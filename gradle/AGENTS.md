# 构建与验收脚本指引

本文件补充[根指引](../AGENTS.md)，作用于本目录；根指引同时要求修改根构建文件、Wrapper、依赖锁、`verify.ps1` 和 CI 时阅读本文件。

## 任务与职责

- 根 `build.gradle` 保留插件、工具链、依赖/source set、标准产物与脚本装配。领域任务放现有职责脚本；复杂报告解析与任务装配分开，不为拆文件预造构建框架。
- 新任务先说明现有入口为何不足、输入输出、成本、是否需要 GPU、是否进入默认构建。场景和质量档优先用受校验参数/数据表达，不复制整套 test、soak、benchmark、release 任务。
- 编译、打包和普通 `check` 不隐式启动真实 GL、性能矩阵或长测。`quickVerification` 当前是完整无桌面门禁，不是最小测试集。
- 配置阶段不运行 GPU/benchmark、不写源码、不执行 Git 提交或下载场景资产。依赖按 Gradle 正常解析；候选身份采集放显式执行任务。
- `dependsOn` 表达前置条件，`mustRunAfter` 只表达顺序。报告读取者只汇总选定范围，不为获取日志拉起所有历史生产任务。
- 保留现有入口的范围与结果语义；去重时复用唯一叶子任务/合同清单。需要兼容的旧入口使用薄别名或明确迁移说明，不静默缩窄它的验证范围。

## 输入、依赖与产物

- 生成输出放 `build/generated`；声明实际输入、输出以及读取的 helper、shader include、模板和参数。修复漏声明的依赖，不以全局 `clean` 或关闭缓存掩盖问题。
- 当前 focused/UI 的部分任务为保证本次证据禁用缓存；在候选身份与复用规则验证前，不直接移除这些保障。依赖缓存命中与验收证据复用是两件事。
- 普通测试目前通过 `testImplementation sourceSets.demo.output` 依赖 Demo 和 shader 生成。调整前盘点真实消费者/fixture；新增纯逻辑测试不继续扩大这种依赖，不把测试参考实现迁入生产包。
- 固定依赖版本，保持 JDK、Wrapper、LWJGL/BOM、`gradle.lockfile` 和相应 guard 一致。更新 lock 使用 Gradle 的受影响依赖解析；同步 `dependencyLockGuard` 中现有硬编码坐标，避免两份版本来源。
- 版本从 `build.gradle` 派生到构建元数据。隔离 JAR 验证使用实际归档与 runtime classpath，不能由工作树 main classes 兜底。
- 资产输出遵循根指引的来源/许可规则；资源集合或打包方式变化说明文件数与字节数影响。当前 VFX 全包进入主 JAR，不把新的按需打包方案当作已实现合同。

## 限时与报告

- 保持默认零自动重试和既有限时策略。`verify.ps1` 有总体时限，直接 Gradle 只有任务级 timeout；不要把两者宣称为同等保障。
- 只终止本次启动的独立进程树，不按 `java` 进程名结束 IDE 或其他任务。失败/超时也要写摘要并保留 stdout/stderr、执行 case 和运行身份。
- 汇总核对必需 case 的执行事件；空选择、意外 skip、未执行、超时或输入身份变化不得复用旧 PASS。未实现的状态分类/自动选测在说明中标明，不伪造执行器能力。
- 任务超时、扩展模式和报告位置以[测试指南](../docs/guides/testing.md)和[验收规范](../docs/guides/focused-acceptance-policy.md)为准。保留正式性能与普通功能结果的区别。
- 修改 CI 时保持无桌面检查与真实 GPU 验收的区别，明确总时限、失败日志归档及取消行为；不能把本地通过写成 Windows/Linux CI 已通过。

## 验证构建改动

1. 用所改入口的 `--dry-run` 比较前后任务图，核对默认路径、GPU/长测依赖和重复 case 来源；同一任务的多条依赖边不等于重复执行。
2. 执行受影响的编译、guard 或代表叶子任务；改了筛选/聚合就核对实际 case 集合。改超时、失败汇总或选择器时验证对应异常路径，不只验证正常退出。
3. 说明旧命令兼容性、实际消除的重复/依赖和未测范围。已通过的无关矩阵不惯例性重跑。

只修改本指引时执行文档检查即可；上述步骤针对构建行为变更。
