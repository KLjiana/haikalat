# v0.10 全 GPU 自动曝光基准（2026-07-15）

## 环境与方法

- GPU：NVIDIA GeForce RTX 3050 Laptop GPU，driver 576.88，OpenGL 4.6。
- 场景：LearnOpenGL ACES + FXAA，Bloom 和实例阴影关闭，默认 100 个实例。
- 分辨率：1920×1080 与 3840×2160 hidden window；VSync off，debug callback on。
- 每项预热 100 帧、正式统计 1000 帧，共 5 轮；奇数轮正序、偶数轮逆序。
- 表中结果为五轮统计值的中位数；性能结论以帧时间为主，不以短时间 FPS 峰值判断。

复现入口：

```powershell
.\gradlew.bat runAutoExposureBenchmarks
```

## 整体结果

| 场景 | present FPS | CPU avg/median ms | GPU avg/median ms | AUTO GPU median 增量 |
|---|---:|---:|---:|---:|
| 1080p MANUAL | 565.4 | 0.222 / 0.207 | 0.226 / 0.224 | — |
| 1080p AUTO | 459.2 | 0.340 / 0.319 | 0.444 / 0.439 | +0.215 ms |
| 4K MANUAL | 263.3 | 0.316 / 0.300 | 0.831 / 0.635 | — |
| 4K AUTO | 222.4 | 0.403 / 0.394 | 1.472 / 1.070 | +0.435 ms |

AUTO 的 CPU median 增量为 1080p `0.112 ms`、4K `0.094 ms`。主要来自额外 pass 的命令录制和
query 管理；亮度、归约、曝光计算与 history 更新没有同步 CPU readback。

## 自动曝光 pass GPU 成本

| 分辨率 | Luminance median | Reduce 合计 median | Adapt median | 分项合计 median |
|---|---:|---:|---:|---:|
| 1080p | 0.0553 ms | 0.1045 ms | 0.0041 ms | 0.1639 ms |
| 4K | 0.1956 ms | 0.2283 ms | 0.0041 ms | 0.4280 ms |

两个分辨率都固定使用 14 个 reduction pass：前 13 级为 `1/2`～`1/8192` 相对尺寸，末级固定 1×1。
归约目标是 `RG32F`，分别累计对数亮度总和与像素权重；小尺寸产生的重复 1×1 pass 保留，以保证 resize
前后拓扑稳定。大部分成本集中在全分辨率 luminance 和第一级 reduction；1×1 adaptation 在两个分辨率下
均约为 `0.0041 ms`。总 GPU 帧时间增量略高于 pass 分项和，
包含额外 framebuffer/query 调度与跨 pass 波动，不应将单轮 query 值简单视为完整墙钟增量。

## 结论

- 自动曝光在 1080p 增加约 `0.215 ms` GPU median，在 4K 增加约 `0.435 ms`。
- 成本随像素量增长，符合全分辨率测光和首级归约的预期；1×1 history 与 adaptation 成本基本固定。
- 当前实现满足全 GPU、无同步 readback、显式 `sum/weight`、奇数尺寸完整覆盖、resize 拓扑稳定和失败帧不发布 history 的约束。
- 若后续需要继续压缩成本，应优先评估降低初始测光分辨率或 compute reduction，而不是改变曝光数学或引入 CPU 回读。
