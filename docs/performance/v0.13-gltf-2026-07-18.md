# v0.13 glTF 静态资产基准（2026-07-18）

> 本页保留首次 OPAQUE 合同副本的历史基线。加入原生 MASK/cutoff 后，
> `runGltfBenchmarks` 已改为直接读取原始 `radio.gltf`；下次正式性能收口将追加新数据，
> 不用本页数值冒充 MASK 路径重测结果。

## 环境与方法

- GPU：NVIDIA GeForce RTX 3050 Laptop GPU（当前 Windows 开发机）。
- 任务：`.\gradlew.bat runGltfBenchmarks`。
- CPU decode：`radio.gltf` 的临时 OPAQUE 副本，3 次预热后测量 5 轮；原资产不改写。
- GPU upload：同一 CPU asset，2 次预热后测量 5 轮；每轮创建 sampler、同一 image 的
  sRGB/linear 两种 texture、material 与 8 个 mesh，使用 `glFinish` 将异步 GPU 创建成本纳入。
- 稳态：主 Demo 的 glTF/OBJ/legacy 共存场景，ACES + FXAA + AUTO exposure + Bloom，
  每个分辨率交错执行 5 轮，每轮预热 100 帧并正式统计 1000 帧，VSync 关闭。

| 阶段 | 中位 | P95 | 输入规模 |
|---|---:|---:|---|
| CPU decode | 3.604 ms | 5.468 ms | 8 nodes / 8 primitives / 0.006 MiB decoded buffer |
| GPU upload | 1.242 ms | 1.685 ms | 8 meshes / 1 encoded image / 2 color-space variants |

| 3840×2160 | 651.7 | 0.463 / 0.435 ms | 1.363 / 1.352 ms | 54.2% | 6 |

## 解读与限制

- glTF 是启动期 decode/upload；静态 world matrix 在 instantiate 时冻结，稳态没有 JSON、accessor
  或 node DTO 遍历。1080p 到 4K 的主要增量位于 GPU 像素阶段，CPU median 只增加 0.045 ms。
- `ordinary draws/pass` 是 scene 中普通 renderer 数量，不包含 1 次 instanced draw，也不把 shadow、
  Bloom、自动曝光和 UI 的各 pass draw/dispatch 合并成一个误导性的总数。
- 这份稳态数据证明当前混合场景没有明显 glTF CPU 回退，但不是“同一内容 OBJ 与 glTF”的严格
  A/B；正式 RC 前仍需使用等价几何和材质补齐该对照。
- `radio.gltf` 的来源与再分发许可尚未归档，因此只用于本机回归和启动期基准，不能作为发布资产。
