## 实际执行

1080p/4K × 雾关闭/开启，各三轮相同输入的 A/B；按轮串行，角色顺序 A/B、B/A、A/B。24 个独立窗口实际执行，每次 120 warmup + 300 measured，合计 7,200 个 measured frames、3,600 个 A/A 配对，覆盖率全部 100%。原始输入是固定 overview、BALANCED、128 个体积灯、8 个局部体积、2 Point + 4 Spot 已分配缓存阴影、NONE、Bloom off，内部尺寸与输出原生尺寸相同。

完整 GPU 链先按同一个提交帧相加，再以同一 measured index 计算 B−A。保持原提交帧身份、去重、完整 pass 配对、有界尾部回收及逐轮等待记录。测量帧没有逐帧 glFinish、HDR/诊断 readback。12 组 A/A 的 profile 全部非注释内容一致；Properties.store 的日期注释单独保留，初次错误的整文件比较与修正说明另存，没有重跑 GPU。

严格日志检查通过，未出现 GL 错误、采样缺失/冲突、query 超时或资源关闭失败。Gradle 调用墙钟 202.979 秒，包含 driver 编译、窗口启动、源/样本归档与等待；分析另计。

## 波动与可比性

下表为三轮中最大的 `p95(abs(B−A))`，是这次实测的经验幅度。它不是置信区间、新的回退阈值或预算豁免。

| 同输入配置 | CPU execute 幅度 ms | 完整 GPU 幅度 ms |
| --- | ---: | ---: |
| 128 灯 1080p，雾关闭 | 1.209500 | 0.307200 |
| 128 灯 1080p，雾开启 | 0.909000 | 0.852992 |
| 128 灯 4K，雾关闭 | 0.495700 | 0.358400 |
| 128 灯 4K，雾开启 | 0.877800 | 0.928768 |

CPU 波动已超过 0.35 ms 产品预算。首个 1080p 关闭雾窗口，warmup 后段 CPU 中位数仍为 0.9597 ms；measured 六个 50 帧块从 0.6458 ms 降到 0.4981 ms，后续轮同输入中位数约 0.24–0.36 ms。因此 120 帧不足以证明 CPU 已稳定，当前不能解释成算法自身的增量。

GPU 同输入后续轮次中位数较接近：1080p 关闭雾约 6.48 ms，开启约 11.35–11.46 ms；4K 关闭约 20.6–20.7 ms，开启约 33.6–34.0 ms。这些是 A/A 各自耗时，不能将它们的中位数差冒充正式对应样本增量 p95。

设备为 RTX 3050 Laptop、驱动 576.88、JDK 21；接交流电，电源方案为平衡。前后 GPU P8/46°C/3.20W → P0/63°C/23.52W，power.limit N/A；内存可用 4914→4605 MiB，提交占用 73→75%；CPU 总使用率快照 0→8%。它们只是前后快照，不证明测量窗口无后台负载或固定功耗上限。

## 已定位的热点与下一步

4K 第三轮 A、雾开启的 `VolumetricOpaqueComposite` 单 pass p50/p95 为 19.079168/19.484672 ms，显著高于 Lighting 的 0.782336/0.795648 ms。仅据此定位热点，不相加 pass p95 推导完整链预算。

源码中 `volumeRefineNativeRay` 对选中 interval 的四个重建列调用 `volumeFineSource`，重新求整簇灯光和介质，然后减去实际存储的 filtered interval contribution。这个替换顺序是此前修复暗部错误的正确性合同，不能撤回修复或降低画质来省时。下一步调查如何复用当前帧 source、同时维持相同数值语义；任何优化先验证独立 ray reference、filtered replacement、透明/MSAA/HDR VFX 和绑定上限，再做必要的代表性能。CPU 在相关配置延长预热并重新校准，保持 2/4 ms GPU、0.35 ms CPU、禁雾 0.05 ms 门槛。
