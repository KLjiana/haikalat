# v0.15 诊断开销基准

日期：2026-07-19  
环境：Windows、Java 21、LWJGL 3.3.3、OpenGL 4.6、RTX 3050 Laptop GPU  
配置：1920×1080、VSync off、debug callback on、主 Demo 100 instances、每项 warmup 100 帧、
正式采样 1000 帧、五轮；DETAILED 保持面板打开。

命令：

```powershell
./gradlew.bat runDiagnosticsBenchmarks \
  -PdiagnosticsBenchmarkRounds=5 \
  -PdiagnosticsBenchmarkWarmup=100 \
  -PdiagnosticsBenchmarkFrames=1000
```

机器在轮次间出现明显的双峰调度/功耗状态，因此采用同轮 paired difference 判断诊断成本。BASIC 相对
OFF 的 CPU median 差值为 `-0.079/-0.001/+0.013/-0.002/-0.002 ms`，中位 `-0.002 ms`，没有可测
回退；allocation 中位从 77.6 增至 78.1 KiB/frame，诊断增量约 0.5 KiB/frame，低于 8 KiB/frame
目标。DETAILED/open 的 paired CPU 增量中位约 0.042 ms；GPU median paired 增量中位 0.009 ms，
query wait 始终为零，没有 GPU stall。DETAILED allocation 中位 90.8 KiB/frame，比 OFF 多约
13.2 KiB/frame，来自面板周期格式化和详细摘要，且受固定 node、240-frame history、256-message ring
与有界资源表约束，不随运行时长增长。

本报告不把 native driver 显存估值当成真实显存。export 的一次性 JSON 分配和 I/O 未计入 render frame，
因为 exporter 只消费 frozen capture。

## 发布时接受的测量限制

以上数据只比较同一 v0.15 构建内的 OFF/BASIC/DETAILED，不能替代规划要求的 v0.14 对照。
本次 `0.15.0` 发布验收接受上述同版本 paired 证据，没有单独签出 v0.14 重跑，因此本报告不声称
已经证明 OFF 相对 v0.14 的精确 1% 数值。后续若需要跨版本归因，应在同一机器、驱动、窗口、
分辨率、场景、VSync/debug 和采样配置下重新测量两个 release commit。
