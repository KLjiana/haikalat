# Stress 矩阵快照修复后基准（2026-07-15）

本次基准用于复测 `88fbbd5` 修复后的性能。该修复让 `CommandExecutor` 将命令缓冲区已经持有的
`Matrix4f` 快照直接交给 `InstancedMeshBatch`，避免 dynamic 路径再次复制 10 万个矩阵对象；同时补全
instance ring 在正常与异常路径上的帧生命周期。

## 环境与统计方法

- GPU：NVIDIA GeForce RTX 3050 Laptop GPU，driver 576.88，OpenGL 4.6。
- 采样结束后 GPU 状态：P0，核心 1935 MHz，显存 6001 MHz，温度 66 °C，功耗约 46.94 W。
- 窗口：1280×720 hidden window；VSync off；debug callback on。
- 每个场景预热 100 帧，随后正式统计 1000 帧；每个场景独立运行 5 轮。
- 奇数轮按空窗口到重负载的顺序执行，偶数轮反向执行，降低固定顺序造成的升频与温度偏差。
- 最终值是 5 个“单轮统计值”的中位数。例如最终 GPU average 是五轮 GPU average 的中位数，
  不是把五轮 FPS 再求算术平均。
- CPU 时间表示引擎 submit；GPU 时间来自 timer query；present FPS 包含 swap、窗口系统和调度成本。

运行前执行 `test demoClasses`，结果通过。所有正式场景保持相同 clear、present、窗口和查询设置。

## 帧时间差

按最终 GPU average 计算：

- indexed 收益：`0.733 - 0.309 = 0.424 ms`，相对展开 Cube 降低约 57.8%。
- SSBO 收益：`0.309 - 0.308 = 0.001 ms`，小于本次测量分辨率，应视为持平。
- 展开 Cube 相对 Triangle 的额外成本：`0.733 - 0.069 = 0.664 ms`。
- indexed Cube 相对 Triangle 的额外成本：`0.309 - 0.069 = 0.240 ms`。
- indexed-ssbo Cube 相对 Triangle 的额外成本：`0.308 - 0.069 = 0.239 ms`。

按最终 GPU median 计算，indexed 收益为 `0.598 - 0.306 = 0.292 ms`；indexed-ssbo
相对 indexed 为 `0.306 - 0.307 = -0.001 ms`，同样说明两条 indexed 路径基本持平。

## 与修复前基线对比

`dynamic` 是本次矩阵快照修复直接影响的路径：

- CPU average：3.801 ms → 3.545 ms，下降 0.256 ms（约 6.7%）。
- CPU median：3.668 ms → 3.398 ms，下降 0.270 ms（约 7.4%）。
- 每帧实例矩阵上传仍为 100,000 × 64 bytes = 6.4 MB；修复减少的是 JVM 端重复对象复制，
  并未改变兼容路径的数据布局。

旧基线只有一轮，本次是五轮中位结果，因此百分比用于判断量级，不应解释为隔离变量的微基准。

## Present 节流与结论

第 4～5 轮出现 hidden-window present 节流：空窗口从 1113 FPS 以上降到约 144–156 FPS，
Triangle 也同步降到约 205–225 FPS；但对应 GPU query 仍分别稳定在约 0.006 ms 和
0.070 ms。该现象表明限制来自 swap、隐藏窗口合成或系统调度，不是 shader/geometry 吞吐。
因此本报告保留全部 present 原始值与范围，不删除异常轮，但性能判断优先使用 CPU/GPU 帧时间。

最终判断：矩阵快照修复使 dynamic 的 CPU 提交时间稳定改善约 7%；indexed 仍将实际 VS invocation
从 360 万降至 90 万并显著降低 Cube GPU 时间；compact SSBO 与纯 indexed 在静态规则场景中性能持平，
其主要价值仍是把实例数据从 64 bytes 降到 16 bytes，并支持任意实例属性与局部更新。
