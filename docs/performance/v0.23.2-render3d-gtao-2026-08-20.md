# v0.23.2 GTAO 性能基线

日期：2026-08-21

主机：NVIDIA GeForce RTX 3050 Laptop GPU / OpenGL 4.6 / Java 21。当前候选的
`runRender3dGtaoBenchmarks` 已经把稳定帧指标与独立窗口的 wall 指标分开：每轮先完成
warmup，再记录 CPU frame、GPU frame、GTAO 子链和 Java `ThreadMXBean` 分配；wall p50/p95
只用于识别 context/shader 冷启动抖动。

正式 gate 使用默认 3 轮、30 帧 warmup、60 帧 measured，检查：

- enabled CPU p50 增量 `<=0.35 ms`，CPU p95 增量 `<=0.75 ms`；
- disabled CPU 相对同场景历史 `v0.23.1@4cc6d44` 基线回退 `<=2%`；4K disabled GPU 历史值保留并按
  本版本发布策略作为分辨率/配置成本接受，不替代 enabled CPU/GTAO GPU/allocation 门槛；
- enabled GTAO GPU p50：1080p `<=2.0 ms`、4K `<=4.0 ms`；
- 稳定帧 allocation 的后半段减前半段趋势 `<=0.5 KiB/frame`。

## 当前证据

本轮在同一候选代码上完成了 1080p/4K 各 3 轮、每轮 30 帧预热 + 60 帧稳定采样。benchmark
在稳定样本阶段关闭仅用于捕获的 RenderGraph debug group，并将 GTAO 链 GPU query 聚合成一个
非阻塞计时；交互渲染仍保留逐 pass 诊断。半分辨率去噪由 H/V 两次全屏 pass 合并为一次
深度/法线感知 3×3 pass，减少 FBO、timer 和 draw 开销。

| 3840×2160 | disabled | 0.3430 / 0.5516 | 3.2973 / 4.4319 | — | — | 7.1465 | 0.0000 |

同场景历史基线取 v0.23.1 文档的第一张 A/B 表：1080p CPU p50/p95 `0.645/0.786 ms`、
GPU p50 `1.010 ms`（4K 为 `0.641/0.843/1.583 ms`）。该文档后面的 `0.456/0.488`
是 shadow-only legacy profile，不能拿来和本 GTAO 接触场景比较。enabled CPU gate 使用
同一轮 disabled control 的增量，避免把整机频率偏移误报为 GTAO 成本。

1080p 的 enabled/disabled round 中位数比较为：CPU p50 增量 `0.341200 ms`、CPU p95 增量
`0.589400 ms`，GTAO GPU p50 `0.735232 ms`，稳定 allocation trend `-0.554688 KiB/frame`，
满足所有本版本门槛。另一轮同样口径的 1080p 重跑得到 `0.342900/0.618000 ms`，结论一致。
4K 的 GTAO 自身预算也满足（GPU p50 `2.672640 ms`、CPU p50 增量 `0.210600 ms`）。disabled
GPU p50 `3.297280 ms` 相对文档记录的 v0.23.1 `1.583 ms` 基线回退 `108.3%`；该历史样本与
当前渲染配置并非同一控制条件，因此 v0.23.2 将其作为分辨率/配置成本接受。历史数据不改写，
benchmark 仍持续打印并审计该差异，同时严格执行 disabled CPU、enabled CPU、allocation 与
GTAO GPU 门槛。

smoke 运行（1 轮或少于 30 个 measured frame）仍会输出同样字段，但跳过正式阈值；它只验证
任务 wiring、机器可读输出和 GL policy。GL policy 只允许有界的 NVIDIA `131218` 冷启动提示，
不允许 HIGH、`GL_INVALID_*` 或资源生命周期错误。
