## 已核实的生产链与所有权

```text
调用方 applyVolumetricFog / applyVisualSettings
  → PipelineTopology.capture
  → createGeneration（拓扑变化）/ 原代保留（数值变化）
  → activateGeneration → retireGeneration
executeFrame
  → RenderFrameContext / SceneFrame / 光照与阴影帧计划
  → VolumetricPassBuilder.prepareFrame
  → RenderGraph.execute → RenderDevice.execute
  → 全部 owner prepareFrameSuccess → frameSucceeded
  → 失败时 frameFailed / 历史失效（GPU 写入不能回滚）
```

| 实际对象 | 基线所有者 | 生命周期/借用 |
|---|---|---|
| `RenderGraph` 附件、shadow atlas framebuffer | Graph 的动态/固定 `RenderTargetManager` | Graph 独占；体积雾仅借用 |
| `CameraUniforms`、`ShadowSamplingBlock` | `PipelineGeneration` | 无雾参数依赖 |
| `ClusteredLightingResources`、`ClusteredLightingBinder` | `PipelineGeneration` | 雾借用 light table/cluster buffers；不释放 |
| `PostProcessPassBuilder` 的 TAA、GTAO、曝光、Bloom、tone mapping | `PipelineGeneration` | 存储与历史有效性分开判断 |
| `SceneSurfacePass`、resolve、reactive、shadow shaders、PBR/sky | `PipelineGeneration` | 仅受各自配置影响；surface 会随雾需求变化 |
| `VolumetricResources`、compute/color/query programs、quad、transparent variants | `VolumetricPassBuilder` | 雾专属；候选失败清理，停用释放 |
| `VolumetricFrameState`、`VolumetricHistoryPlan` | `VolumetricPassBuilder` | 仅成功帧提交，失败失效 |
| `VolumetricFogView` | 帧内借用 | 请求帧号/资源代次受限；不能跨帧使用 |
| 宿主 presentation framebuffer/attachments | Minecraft/宿主 | runtime、pipeline、graph 都不能释放 |

基线问题：启停、quality 或 emission shape 变化重建整代，重建了无关光照/阴影/后处理对象；`VolumetricPassBuilder` 直接依赖 clustered binder 与生产者 Pass 常量；candidate graph 未在激活前显式 compile；管线未统一检查创建时 owner thread/context。

现有 scalar 更新已保留整代，resize 已有跨 owner 候选事务；这些是必须保留的行为。透明 fog variant、VFX reactive replay 和 MSAA depth resolve 已有真实消费者，迁移不能只保留 compute 路径。

## 调度与宿主边界

`HaikalatRuntime.execute` 同步调用并检查线程，不是异步队列。`GlRenderThread` 在 onInit/frameCallback/onCleanup 中持有 Context，`LatestFrameMailbox`/`FrameDriver` 是帧提交链，不可让准备任务阻塞其推进。第一阶段优先保留同步兼容入口；是否需要异步请求由真实需求决定，不预设增加线程。
