# v0.23.4 Render3D 动态阴影性能记录

日期：2026-08-22

## 环境与方法

- GPU：NVIDIA GeForce RTX 3050 Laptop GPU，驱动报告 OpenGL 4.6 / NVIDIA 576.88。
- Java/Gradle：Java 21 toolchain，Gradle 8.10.2；VSync 关闭，隐藏 GLFW 窗口。
- 场景：balanced 1 directional + 2 point + 4 spot，固定 20 shadow view，640×360 集成窗口；
  benchmark 使用 1280×720、60 帧、前 20 帧预热。
- 指标来自 `SHADOW_BUDGET` 与 `SHADOW_CULLING` 行；CPU/GPU 数值是预热后样本，wall time
  只用于诊断，不作为稳定帧门槛。

## v0.23.4 实测

| 入口 | 帧/样本 | CPU p50 | CPU p95 | GPU p50 | shadow GPU p50 | caster refs | culled refs | stable tiles |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: | --- |
| `runRender3dDynamicShadowIntegration` | 18/18 | 1.704 ms | 122.735 ms | 0.565 ms | 0.020 ms | 77 | 3 | 0/20 |
| `runRender3dShadowCullingBenchmarks` | 60/40 | 0.890 ms | 1.608 ms | 1.700 ms | 0.010 ms | 77 | 3 | 0/20 |

稳定帧 planner 输出 `planReused=true`、`dirty=0`、`reusedViews=20`。初始 20 view 完整建立，
移动单个 point 只触发六面，移动 spot 只触发一个 tile；动态入口还验证 revisioned glTF caster
穿过 point face/spot range、old/new membership 清理和一次 partial shadow failure 后的 `FRAME_FAILURE`
恢复；同宽高比 resize 不重建 atlas。当前 glTF proof 中 `candidateCasters=4`、其中 2 个为
degenerate/unknown-bounds volatile caster，`casterViewReferences=77`、`culledReferences=3`；
稀疏有限 bounds 场景仍通过同一 planner 做逐 view 剔除，未知 bounds 按合同保守覆盖全部 active view。

同一 benchmark 还会走真实的 `Scene -> SceneFrameBuilder -> ShadowCasterPlanner` 链路，
并以硬断言检查 changed frontier、共享 shadow queue 复用及离开/重入后的确定性顺序：

```text
SHADOW_PLANNER_BENCHMARK entries=10000 views=20
  staticTests=200000 dynamicTests=20 dynamicFull=false
  forcedTests=200000 forcedFull=true
  sceneChanged=1 shadowQueueReused=true deterministicOrder=true
```

这表示 10k caster 的首次/强制完整重建仍明确计为 10k×20，而单个 revisioned caster
的增量帧只测试 20 个 active view，不再重建全部 slice；该结果不再由 benchmark 手工填入
`changedIndices` 或 `shadowQueueReused`，因此 SceneFrameBuilder 发生全量退化时任务会直接失败。

## 验证命令

```powershell
.\gradlew.bat runRender3dShadowBudgetIntegration --rerun-tasks --console=plain
.\gradlew.bat runRender3dDynamicShadowIntegration --rerun-tasks --console=plain
.\gradlew.bat runRender3dShadowCullingBenchmarks --rerun-tasks --console=plain
```

以上命令均在本机正常退出；GL debug 仅出现已登记的 NVIDIA `131218` MEDIUM shader-state
specialization，无 `GL_INVALID_*`、HIGH、资源生命周期错误或线程悬挂。v0.23.3 的完整五轮
对照数据将在同一硬件/分辨率下的正式 release candidate 复跑并附在发布报告中；本表不把冷启动
P95 误报为稳定帧回退。

## 解读与限制

本版本只做 batch-level instance culling，不做逐实例 compact、BVH、GPU-driven 或 indirect draw。
无可靠 bounds 的 caster 采用保守 membership；因此密集/未知 bounds 场景仍可能接近全量提交。性能
结论必须同时查看 references、dirty views 和最终像素正确性，不能只看 CPU wall time。
