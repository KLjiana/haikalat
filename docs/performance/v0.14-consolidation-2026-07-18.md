# v0.14 收口性能复测（2026-07-18）

## glTF loader 拆分

命令：`runGltfBenchmarks`，CPU decode/upload 各 5 轮，稳态 1080p/4K 各 5 轮。

| 阶段 | v0.13 中位 | v0.14 中位 | 变化 |
| --- | ---: | ---: | ---: |
| CPU decode | 3.604 ms | 3.654 ms | +1.4% |
| GPU upload | 1.242 ms | 1.160 ms | -6.6% |

decode 回退低于 5% 噪声门槛。当前 MASK 原资产稳态为 1080p 369.4 FPS、CPU median
0.534 ms、GPU median 0.686 ms；4K 195.9 FPS、CPU median 0.592 ms、GPU median
1.571 ms。历史 v0.13 稳态使用 OPAQUE 副本且为 6 draws/pass，当前为 9 draws/pass，因此不把
两者 FPS 差异错误归因于 loader 类拆分。

## Stress CommandBuffer 路径

100 万 Cube 使用 100 帧预热、1000 帧统计复测；所有路径保持单 draw、state skip 100%。

| 路径 | FPS | CPU avg/median | GPU avg/median | VS invocations |
| --- | ---: | ---: | ---: | ---: |
| expanded gpu | 115.3 | 0.146 / 0.120 ms | 7.753 / 6.347 ms | 36,000,000 |
| indexed | 214.4 | 0.104 / 0.089 ms | 3.870 / 3.084 ms | 9,000,000 |
| indexed-ssbo | 180.3 | 0.127 / 0.114 ms | 4.541 / 3.907 ms | 9,000,004 |

随后同机连续热运行时 indexed 与 indexed-ssbo 同时下降到约 172 FPS、GPU median
4.13/4.08 ms，说明绝对值受笔记本功耗/温度状态影响；两条路径仍持平。命令流、shader、EBO
和 SSBO 实现未在 v0.14 改动，关键结构指标（1 draw、100% skip、900 万 VS）保持。

## UI allocation 收口

首次 v0.14 复测的 10,000 quads 为约 600 KiB/frame。修复静态树重复 style 解析、命中测试
矩形、paint bounds 与 `children()` 快照分配后，以 30 帧预热、200 帧统计连续运行 3 轮，表中取
中位轮结果：

| 分辨率 | allocation | update | GPU | draws |
| --- | ---: | ---: | ---: | ---: |
| 1080p | 254.5 KiB/frame | 0.948 ms | 0.084 ms | 1 |
| 4K | 254.5 KiB/frame | 0.352 ms | 0.084 ms | 1 |

三轮 allocation 均为 254.5 KiB/frame，低于路线图的 256 KiB/frame 门槛，并保留 layout、shape、
atlas upload 为零。2,000 glyph 场景中位为 5.0/4.6 KiB/frame，低于 128 KiB/frame；virtual list
仍为 51/65 draws，batch break
全部来自 paint-order barrier，不进行全局透明排序。
