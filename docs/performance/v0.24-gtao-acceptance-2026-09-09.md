## 阻塞项

### P1：仍未实现一般情形的 GTAO 切片积分

位置：`src/main/resources/shaders/postprocess/gtao-estimate.frag:177`。

当前最终积分只是两侧 horizon 的平方均值。采样方向在屏幕空间均匀分布，但没有建立视线切片基、投影法线、投影长度权重和有符号法线角。对称、正对视线的 30° 特例得到 0.25，并不能证明倾斜表面和非对称遮挡下积分正确。

修复：实现包含投影法线的两侧解析积分，再用实际 estimate shader 输出对比倾斜平面、墙角、非对称遮挡与相机旋转的独立参考。可核对 [Intel XeGTAO 核心实现](https://github.com/GameTechDev/XeGTAO/blob/master/Source/Rendering/Shaders/XeGTAO.hlsli)，其中 projectedNormalVec、投影长度和 iarc0/iarc1 分别参与积分。

`GtaoAnalyticReferenceTest` 没有调用或读取生产 shader；其方位旋转测试的遮挡条件始终只依赖 z，天然与方位角无关。因此这 4 个测试无法拦截此缺陷。

### P1：跳过下一层 PCF 后，导数仍在非一致控制流内

位置：`src/main/resources/shaders/render3d/pbr/pbr-forward.frag:169`；同样影响 `pbr-forward-shadow-budget.frag:235`。

`weight` 随像素变化，提前返回后调用的 `sampleDirectionalCascade` 内仍会执行 `receiverPlaneGradient` 的 dFdx/dFdy。跨过混合区边界时，一个像素组中可能只有部分像素执行这些导数。函数内部覆盖范围提前返回和动态级联索引也需要一并处理。

这属于可从代码确认的正确性风险，本次没有录制视频来证明每块 GPU 都出现闪烁。[Khronos GLSL 规范](https://registry.khronos.org/OpenGL/specs/gl/GLSLangSpec.4.20.pdf)明确指出非一致控制流中的导数未定义。

修复：在一致控制流中对固定级联坐标计算所需梯度，再在分支中选择梯度并决定是否执行 PCF 采样；不能仅将现有导数调用移到另一个仍使用逐像素级联索引的分支外。验收需补充慢速跨级联边界、斜坡和阴影覆盖边界的画面回归，两个 PBR shader 同步检查。

### P2：法线回归测试没有击中原错误像素

位置：`src/test/java/com/kaleblangley/haikalat/integration/GtaoReconstructionGlTest.java:175`。

深度断层在 x=7/8 之间，断言却只读 x=6/9。即使采用原来的跨边缘中央差分，正确对齐后这两个非边缘像素也可能通过。该测试还使用单位逆投影，并且未像上采样测试一样显式设置 16×16 viewport，不能保证输出像素对应输入断层的位置。

修复：明确设置 viewport，采用真实透视矩阵和 view depth=5/10 的两个平面；至少断言 x=6、7、8、9，验证实际 estimate 法线缓存与 upsample 重建结果。新增奇数尺寸、1 像素尺寸、竖直/水平断层测试；通过临时恢复旧算法确认新测试确实失败。

## 可保留的修复

- 上采样已经采用减 0.5 的像素中心坐标、四邻域双线性权重和 texelFetch AO；本次常量与线性坡度测试通过。
- 法线重建改用视空间深度连续性判断和单侧差分；方向正确，但上述回归证据需要补强。
- estimate 使用 createColors 正确输出 R8 AO 与 RG16F 法线缓存，后续滤波复用缓存，避免为每个邻居重复重建法线。
- temporal 改为保存正视空间深度，并使用上一帧逆投影重建预期深度；近远裁剪面变化也增加了历史失效处理。仍需针对移动、显露区域及投影改变补充像素级历史拒绝测试。
