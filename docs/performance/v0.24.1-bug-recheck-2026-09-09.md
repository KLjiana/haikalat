## 尚存问题

### B1 / P1：天空重投影重复扣除当前 jitter

位置：`src/main/resources/shaders/postprocess/taa-resolve.frag:68`。

`PostProcessPassBuilder` 把当前 inverseJitteredProjection 传给 uInverseProjection；skyHistoryUv 用它从当前 raster UV 重建方向，再投影到 previous stable VP。这一步已经移除了当前 jitter。之后再计算 `previousUv + previousJitter - currentJitter`，会第二次扣当前 jitter。

在相机静止、仅 jitter 变化时，正确坐标是 `rasterUv - currentJitter + previousJitter`，当前实现多出一个 `-currentJitter`。修复为与该矩阵选择一致的 `previousUv + previousJitter`，并用非零 jitter、静止相机和天空高频图案测试 shader 实际输出；零 jitter 测试无法发现它。

### B2 / P1：Reactive 绘制没有跟随实际变形

位置：`SceneReactivePass.java` 的 record；`shaders/render3d/surface/scene-reactive.vert:13`。

Reactive shader 只计算 Model × 原始 aPos，record 没有绑定 skin/Morph 或其他当前变形。声明 reactive 的动画物体可能在实际位置之外写 mask，而真实像素仍使用过多历史。关闭 depth/cull 只能扩大原始网格覆盖，不能保证覆盖变形后的轮廓。

修复：复用当前 surface/color 的 position evaluation 和绑定，或在不支持的对象上使用有证明的保守覆盖降级。加入骨骼/Morph 把网格移出原始轮廓的测试，读取实际 mask 验证覆盖。当前颜色混合测试绑定零 reactive 纹理，不能证明该生产路径正确。

### B3 / P2：退休一个 renderer 会失效仍在使用的共享绑定

位置：`TemporalSceneState.java:112`。

同一 TemporalDrawBinding 可由多个 MeshRenderer 共用，prepare/commit 已按 binding 身份去重。但清理退休 renderer 时无条件调用 invalidatePrevious，没有检查该 binding 是否仍被当前成员使用。删除共享绑定中的一个 renderer，会使剩余对象刚提交的 previous deformation 被清掉。

修复：按活跃 binding 引用集合决定是否退休，最后一个使用者退出后才失效。补“两个 renderer 共用绑定，删除一个”的回归；剩余对象下一帧必须仍有正确 previous palette/velocity。

### B4 / P2：发布阶段仍可因退休清理失败而半提交

位置：`TemporalSceneState.commitSuccessfulFrame()`，特别是创建 retired 列表及 invalidatePrevious 调用。

prepareTemporalCommit 的新协议要求 binding 将可失败操作前移，这个方向正确。但退休列表分配和 public invalidatePrevious 回调仍发生在 TAA、相机、Model 已提交后，且不属于新的 prepareTemporalCommit 协议。回调抛错会进入 frameFailed，discard 不能回滚已发布状态。

修复：预先计算退休集合，并把退休处理放进明确的可失败准备/安全退役协议。补退休失效回调异常测试；不能只测试 prepareTemporalCommit 抛错。
