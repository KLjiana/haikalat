# v0.17.1 RenderGraph 资源预览性能报告

日期：2026-07-20

版本：`0.17.1`

环境：Windows 11、Java 21、LWJGL 3.3.3、OpenGL 4.6、NVIDIA GeForce RTX 3050 Laptop GPU、
VSync off、debug callback on。

## 方法

分别执行：

```powershell
.\gradlew.bat runPreviewBenchmarks
.\gradlew.bat runPreviewBenchmarks -PpreviewBenchmarkSize=3840x2160
```

每种模式预热 100 帧、统计 1,000 帧，共运行五轮。所有 case 使用同一 LearnOpenGlDemo 场景、
MSAA、clear、present、VSync 和 debug 设置。表中 CPU/GPU average 与 median 均先由每轮 1,000 帧
得到，再取五轮结果的中位数，以降低窗口反复创建和系统调度抖动的影响。

`closed` 完全关闭 diagnostics；`direct-hdr` 预览现有 `HdrResolvePass/hdrResolvedColor`；
`msaa-depth` 选择 `GeometryPass/depth`；`cubemap` 选择已注册的 PBR prefiltered cubemap。

## 五轮中位结果

### 1920×1080

| 模式 | CPU avg ms | CPU median ms | GPU avg ms | GPU median ms | GPU median 增量 |
| --- | ---: | ---: | ---: | ---: | ---: |
| closed | 0.786 | 0.793 | 0.625 | 0.423 | 基线 |
| direct-hdr | 0.857 | 0.806 | 0.705 | 0.485 | +0.062 |
| msaa-depth | 0.757 | 0.717 | 0.749 | 0.538 | +0.115 |
| cubemap | 0.658 | 0.624 | 0.666 | 0.454 | +0.031 |

### 3840×2160

| 模式 | CPU avg ms | CPU median ms | GPU avg ms | GPU median ms | GPU median 增量 |
| --- | ---: | ---: | ---: | ---: | ---: |
| closed | 0.648 | 0.549 | 1.293 | 0.921 | 基线 |
| direct-hdr | 0.752 | 0.685 | 1.356 | 0.984 | +0.063 |
| msaa-depth | 0.913 | 0.849 | 1.292 | 0.947 | +0.026 |
| cubemap | 0.676 | 0.640 | 1.304 | 0.953 | +0.032 |

CPU 数据存在明显调度抖动，因此不能用单轮 FPS 推断预览成本；GPU median 在五轮中更稳定。
驱动只报告了 NVIDIA `id=131218` 的 medium performance shader recompile 提示，没有出现 GL error。

## 预算与命令上限

- 关闭态不创建 preview 专用 GPU 资源，也不录制 preview draw/blit。
- direct HDR 复用 RenderGraph 已有的单采样 HDR resolve，避免为 1080p RGBA16F 再申请约
  `15.82 MiB` 的临时纹理；preview 自有 sRGB 输出最长边限制为 512。
- 需要 resolve 时，临时 resolve 与 preview output 的合计预算为 `8 MiB`。1080p depth-stencil
  resolve 会按剩余预算缩小 preview output；4K 完整 depth resolve 超预算时按合同报告不可预览，
  不静默突破显存预算。
- 每个有效预览帧最多增加 1 次 conversion draw；只有 MSAA source 额外增加最多 1 次 typed blit。
- preview conversion 继续作为 `UiOverlayPass` 的前缀命令，不向 RenderGraph 增加 pass，也不执行
  生产 CPU readback。

## 结论

1080p 下最重的已支持路径是 MSAA depth，GPU median 增量 `0.115 ms`；direct HDR 和 cubemap 分别为
`0.062 ms` 与 `0.031 ms`。4K direct HDR 仍仅增加 `0.063 ms`，证明复用现有 resolve 后没有重新引入
全尺寸 HDR 临时目标。关闭态保持 0 preview work；本报告没有把 4K 超预算 depth resolve 误写成支持路径。

## 2026-07-21 静态提交门槛加固

原 fixed-only scene 即使所有 `FixedSource` 已建立缓存，仍会每帧扫描 10,000 个恒定 revision 和 bounds，
导致 `runSceneSubmissionStaticGate` 稳定超过 `0.15 ms`。修复后，membership 全部由不可变模型源组成且
首帧缓存完成时直接复用 model/bounds 统计与 queue；membership 变化会立即退出快路径并完整重建，
TransformSource 和 animated updater 不进入该快路径。

原始门槛连续运行五次，`SceneFrame + queue` 分别落在 `0.003～0.004 ms`，整帧 CPU median 为
`0.078～0.082 ms`，allocation 为 `4.0 KiB/frame`。随后完整 `localGlVerification --rerun-tasks`
执行 55 个任务并通过；在前置 PBR、UI、glTF 和 scene 压力负载后，该门槛仍为 `0.004 ms`，
整帧 CPU median `0.085 ms`。
