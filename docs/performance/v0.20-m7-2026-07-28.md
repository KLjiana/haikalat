# v0.20 M7 热路径性能与回归记录（2026-07-28）

日期：2026-07-28
版本：`0.20.0-SNAPSHOT`
环境：Windows、Java 21、NVIDIA GeForce RTX 3050 Laptop GPU、OpenGL 4.6、
驱动 576.88。

## 结论

- 静态 UI 的测量窗口不再重复 paint 或发布 display-list snapshot；十个容量场景的
  snapshot publication 都是 `0`，layout、shape、paint 和 atlas upload 均为 `0`。
- draw/batch 语义没有改变：普通 HUD、settings、10,000 quad 和 2,000 glyph 场景仍为
  1 draw；virtual list 保留由节点 clip 顺序导致的 51/65 draw。
- 10,000 quad 仍有约 `255 KiB/frame` 分配。它发生在 snapshot publication、layout、
  shape 和 paint 都为零时，因此当前证据将它归入 render/GL submission 剩余预算，
  不把普通路径描述为“完全零分配”。
- 静态场景 all-visible 五轮 CPU 平均值中位数为 `2.984 ms`，相对原始
  `2.977 ms` 基线为 `+0.24%`，不再复现 v0.19.4 独立重跑的 `3.567 ms` 回退。
- UI、resize、async、text、Modern UI 五项真实 GL integration 全部通过；没有 HIGH
  消息，也没有未解释的测量窗口 MEDIUM 消息。

## 方法

UI 容量基准使用：

```text
gradlew.bat --no-daemon runUiBenchmarks --rerun-tasks --console=plain
```

每个分辨率/场景独立创建隐藏窗口并关闭 VSync，执行 1 个 cold frame、30 帧预热和
120 帧测量，共运行五轮并取逐项中位数。CPU p95 使用 120 个完整帧样本的 nearest-rank；
计时覆盖 input snapshot、UI update、RenderGraph record/execute 和 present，不包含
`pollEvents()`。allocation 覆盖同一测量窗口的当前线程。

场景与动画基准分别使用：

```text
gradlew.bat --no-daemon runSceneSubmissionStaticBenchmarks --rerun-tasks
gradlew.bat --no-daemon runSceneSubmissionAllocationBenchmarks --rerun-tasks
gradlew.bat --no-daemon runAnimationPerformanceBaseline --rerun-tasks
```

真实 GL UI 回归使用：

```text
gradlew.bat --no-daemon runUiIntegration runUiResizeIntegration
  runUiAsyncIntegration runUiTextIntegration runModernUiIntegration --rerun-tasks
```

| integration | frames / size | 主要结果 |

| UI | 12 / 720×480 | 75 nodes、898 quads、75 draws、3,931 非清屏采样 |
| resize | 16 / 800×520 | 899 quads、3,684 非清屏采样 |
| async | 12 render frames | published 36、dropped 24、890 glyphs、77 draws |

| Modern UI | 60 / 800×520 | 15 nodes、320 quads、16 draws、3 active effects、3,359 非清屏采样 |

Modern UI 最大可见帧为 `10.94 ms`，`>=25 ms` 的帧为 `0`；UI、paint、record

的 `13.67 ms` 最大帧、`5.09 ms` UI 和 `2.75 ms` paint 有改善；record 与 ring
略高于旧记录，因此不宣称所有子项都下降。

## GL 消息分类

- UI 容量基准在各隔离 context 的冷 shader 初始化期间出现 NVIDIA MEDIUM
  `131218`（vertex shader 根据 GL state 重新编译）。它不发生在预热后的测量语义中，
  没有 HIGH 消息。
- integration 结束的 correctness `glReadPixels` 出现 NVIDIA MEDIUM `131154`
  （pixel transfer 与 3D rendering 同步）。它只属于最终像素证明，不在性能测量窗口。
- 没有 GL error、资源 use-after-close、线程悬挂或未完成 fence。

## M7 边界

本轮证明的是静态 snapshot 增量工作已消除、draw 语义稳定、静态场景回退已恢复，
而不是宣称整个帧循环零分配。10,000 quad 的约 `255 KiB/frame` 和 4K settings 的
约 `130 KiB/frame` 仍需后续 allocation profile 定位；在没有 profile 证据前，
不会通过缩短 lease、共享可变 snapshot 或绕过 ring fence 来追求数字。
