## 仍需处理

### R1 / P1：正式测量入口默认隔离，且实际预算仍未达标

`gradle/demo-tasks.gradle` 的 `runRender3dClusteredBenchmarks` 增加了 `args '--cpu-isolation'`。这会在测量帧前执行 glFinish，改变正常队列行为。其归因结果可单独保留，但不能代替计划要求的正常运行正式性能门禁。

本次通过命令行覆盖 args，以 `--rounds=3 --warmup=120 --frames=300` 执行正常队列矩阵。报告必须明确 `cpuIsolation=false`。不得降低预算或因旧版本存在硬件偏差而自动豁免。

### R2 / P2：counter fence 不携带所属 storage，resize 后可能读错代

`ClusteredLightingBinder.tryCounterSnapshot()` 检查 binder 保存的 fence，然后调用 **当前** `resources.storage().readCounters(selected)`。`PipelineGeneration.ResizeCandidate.commitInto` 更换 ClusterStorage，但没有清理 binder 的旧 counter fence。于是旧 GPU 工作已完成的信号会被用来证明新分配 counter 内容有效。

需要将 storage identity/generation 绑定进 pending counter snapshot；resize 成功时丢弃旧 fence/旧诊断，或完整保留其对应 storage 直到读回完毕。不能只保存 sequence 和 slot，也不能等待旧 fence 后读取新 buffer。frameFailed 与零灯路径同样应覆盖 counter 状态失效。

### R3 / P2：GPU 测量还缺轮次尾部 drain

`Render3dClusteredBenchmarkSuite.measure()` 的循环只有 warmup+measured，没有独立 drain 阶段；读回按当前循环轮次 windowStart/windowEnd 过滤。上一轮尾部查询若在下一轮返回，会被新窗口丢弃，最后一轮未完成查询也无法收集。本次覆盖率达到门槛不代表该生命周期完整。

修复应按提交 sequence 判断其所属任意测量窗口，轮末/配置结束做有界结果 drain，并保留精确 sequence/raw nanos。不要重新引入每帧强制同步。

### R4 / P2：质量入口证明的是确定性，不能替代画质正确性

新 QualitySuite 比较两次相同运行的三帧截图完全相同，能够检测不确定输出，是有效进步；但稳定的错灯和稳定拖影也能通过。保留当前名称说明中的 determinism 边界，继续补透明层、阴影槽迁移、jitter/深度边界、形变及 linear HDR 全灯参考对照。

性能门禁当前实际只覆盖 Assign 的两个预算，不能将其通过（即使未来达到）解释为完成了同灯数全灯 GPU 加速比和零灯 CPU 增量预算。
