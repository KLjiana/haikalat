# v0.12 PBR / IBL 五轮代表基准（2026-07-17）

## 环境与方法

- GPU：NVIDIA GeForce RTX 3050 Laptop GPU，driver 576.88。
- OS：Windows 11，10.0.26200，x64。
- JDK：Oracle JDK 21.0.3 toolchain；Gradle 8.10.2。
- 场景：`PbrDemo` 5×5 sphere、一个五纹理 OBJ、一个 legacy 对照、方向光阴影、两个点光、
  GPU IBL、retained UI。
- 固定模式：隐藏窗口、VSync off、FXAA、AUTO exposure、Bloom on、test-quality environment。
- 每轮预热 100 帧，正式统计 1000 帧；表格取五轮中位数。GPU query 为 RenderGraph 全帧总和。
- environment 预计算发生在正式帧区间外；test/default quality 只改变启动期预计算和固定纹理尺寸，
  不在 steady-state frame 内重新 dispatch。

## 五轮结果

| 分辨率 | Present FPS 中位 | CPU avg / median ms | GPU avg / median ms |
| --- | ---: | ---: | ---: |
| 1920×1080 | 352.8 | 0.608 / 0.562 | 0.937 / 0.797 |
| 3840×2160 | 192.1 | 0.700 / 0.657 | 1.969 / 1.594 |

1080p 五轮 FPS 为 `345.6, 355.8, 352.8, 353.7, 342.2`；4K 为
`191.8, 194.2, 192.1, 191.3, 194.1`。4K 相对 1080p 的主要增量在 GPU，CPU submit
中位只增加约 `0.095 ms`，符合后处理像素量和 PBR fragment/IBL sampling 主导的预期。

## 发布结论

- steady-state 不包含 environment preprocessing、CPU readback 或 `glFinish()`。
- 同一 environment 在 resize 后保持原 GL identity；environment/IBL 重复绑定可由 state cache 跳过。
- 本文作为 `0.12.0` 的同机代表性重负载基线；None/FXAA/MSAA/TAA、manual/auto exposure
  和 Bloom 的正确性由 JVM、真实 GL pixel 与 integration matrix 覆盖，后续版本继续使用
  `runPbrBenchmarks` 观察相对退化。
