## Demo

- NONE/TAA 使用同一套 HDR + ACES 配置，消除色调映射不同造成的伪 A/B 差异。
- 使用带 UV 的棋盘材质、移动前景与移动相机，可观察边缘闪烁和遮挡变化。
- 自定义顶点 shader 显式先计算 `world = model * position`，再计算 `projection * view * world`，与 Surface Pass 保持一致；原来的连乘顺序在共享深度 LEQUAL 下产生可见条纹，不能将其误认为单纯的 TAA 历史拖影。
- 支持 `--aa=NONE/TAA`、`--pause-camera`、`--pause-animation`、`--resize=帧:宽x高`、`--reset=帧`、`--capture=路径`。
- benchmark 的 `--frames` 明确表示实际测量帧数，另加 warmup 和 16 帧 GPU drain；不再混用总帧数与样本数。
- benchmark 拒绝 capture、resize、reset 等会污染稳定计时的选项组合。

## Benchmark

每个分辨率运行三轮，交替 NONE/TAA 顺序。报告保存在 `build/reports/temporal/<源码 SHA-256>/<run UUID>/metrics.json`，失败也保留，且测量后检查源码未改变。

记录每个 pass 的原始 GPU 查询、p50/p95、样本数，以及同一提交帧的完整 GPU pass 总和。只按 query 提交序号计入测量窗口，不把延迟返回的上一帧当作本帧，也不把重复的 latest sample 当成新样本。

原 profiler 只保留最后完成的查询，会覆盖批量完成的中间帧。新增显式启用的完整样本收集模式；正常运行仍使用 8 槽轻量查询环，benchmark 使用 256 槽并定期 drain。收集模式缓存有上限，满时停止取出查询，由既有查询环的 skipped 状态施加背压；不强制等待 GPU。GpuTimerGlTest 验证连续 32 条查询无覆盖且只交付一次。

CPU 指标是 beginFrame 到 endFrame 的录制与提交墙钟耗时，排除 present、截图和 benchmark drain，但可能包含驱动背压；不能解释为纯 Java 算法耗时。GPU 指标独立来自 elapsed query。

显存驱动峰值尚无可信采集，JSON 明确记录 null；图资源布局仅作资源说明，不能代替真实峰值。本 benchmark 目前是同场景 NONE/TAA 对比，不能替代指南要求的 GTAO、体积效果组合全矩阵。
