本地检出的 HEAD 为 `daff1ab1f99d21a85a3280430f72ce95516ae212`（release: 0.24.2），构建版本为 0.24.3。当前可见的是暂存的 0.24.3 实现及未暂存文档，不是已验证的 0.24.3 release commit。本次保留暂存区和原有改动，针对实际工作树验证；不据此否定用户可能在其他位置完成的提交。

## 已复现的启动与汇总问题

| 问题 | 实际证据 | 调整 |
| --- | --- | --- |
| 工作区文档阻断所有发布测试 | 原 `releaseGitGuard` 在测试前拒绝 `docs/README.md`、`testing.md` 的未暂存改动和两份未跟踪规划文档 | 增加独立逻辑入口，允许暂存/未暂存工作树；正式发布仍保留候选冻结要求 |
| PowerShell 参数拆分 | 当前环境执行未加引号的 `-PreleaseVersion=0.24.3` 得到 `Task '.24.3' not found`，任务图未启动 | 文档使用整体加引号的 `'-PreleaseVersion=0.24.3'` |
| 失败没有新汇总，残留旧通过报告 | 修复前 `build/reports/release/readiness.json` 仍为 0.24.0、2026-09-09 的报告；0.24.3 的历史失败未覆盖它 | release 尝试开始写 RUNNING，归档原 JSON；前置任务失败时 finalizer 写失败报告及 attempt 存档 |
| 跳过被视为成功 | 原汇总代码接受所有 `SKIPPED` | 区分任务输出复用与 onlyIf/disabled/NO-SOURCE；新增逻辑入口要求当次必需类有实际通过事件 |
| 局部逻辑依赖完整性能矩阵 | 原 `releaseReadiness` 聚合本版与历史全域、长测和 benchmark | 新入口固定选择相关逻辑/GL，不依赖 benchmark；自动选测仍未实现 |

配置错误/错误参数发生在任务执行前，finalizer 无法覆盖；强制杀进程同样不能保证最终报告。因此必须核对报告 runId、状态与候选，RUNNING 和旧报告都不是成功证据。

## 验证范围

- JVM：GPU 样本归属/配对/覆盖率、视觉 profile 严格解析与冻结 HDR 合同、诊断导出、cluster 数学/shader 同步合同、GTAO 解析参考与设置/Pass、Outdoor 数学和成功帧状态、TAA 状态/jitter、管线 topology、RenderGraph 编译/描述/resize/图合同。
- GL：GTAO 实际 shader 像素与重建、GTAO history resize/失败提交、Outdoor 相机/热更新/IBL/候选回滚、Temporal 成功事务、Clustered 资源生命周期、embedded 宿主 FBO/GL 状态契约。沿用现有 GL debug policy 审计，不扩大警告白名单。
- 附加 guard：架构、公共 API、依赖锁、资产 manifest、现有 release 合同及新增 focused verdict 合同。
- 未测：本次正式性能/4K 容量、全部 AA/场景画质、普通运动的完整残影恢复曲线、长 soak、UI/动画等无关业务、完整发布元数据和 clean tree。

具体类清单以 `gradle/focused-verification.gradle` 为准。这是当前 Render3D 改动的人工固定范围，不能用于无关功能的验收。

## 门禁自身的负向验证

1. `releaseReadiness '-PreleaseVersion=0.24.3'`：仍按设计拒绝未冻结候选，退出非零，但现在执行 `writeReleaseAttempt` 并写明失败位置。
2. 通过仅存在于 `build/` 的 init fixture 为 `focusedRender3dJvmTest` 设置 `onlyIf { false }`：任务 SKIPPED，报告 `NOT_RUN`，整体失败；不会读上次 XML 冒充通过。
3. `releaseReadiness -x writeReleaseReadiness`：即使人为排除核心汇总，finalizer 仍判定证据缺失并退出非零。
4. `focusedVerificationContracts` 检查成功、失败、未执行、跳过、缺类、空集合计数及部分用例失败；固定范围禁止 `--tests` 静默缩小。

这些是验证门禁的预期失败，不是生产功能回归。每次逻辑运行单独归档机器报告和实际测试 XML；最新完整运行可从 `build/reports/logic-verification/latest.json` 找到。

## 约束调整及保留项

普通逻辑签收：输入身份稳定、必需用例实际执行、错误为零、相关 guard 通过。无须 staging、版本稳定声明或 GPU 性能通过后才能开始。新增 Test 只跑固定相关集合；目前每次真实执行以避免不完整缓存合同带来的误判，编译/已有 guard 正常增量执行。

完整发布：仍须冻结候选，并提供适用的功能、质量、性能与偏差证据。旧全量发布入口暂时保留，不将新逻辑入口伪装成发布入口。本次不修改 GTAO 的 0.35 ms CPU 增量预算，不把历史 2%/5% 基线失败改成通过，不新增硬件豁免。

依据 2026-09-23 报告，上一提交和当前候选都不满足过旧的 GTAO disabled 历史基线；这说明对照条件需要重建，不证明当前候选没有性能问题。优化后约 0.5352 ms 的 GTAO CPU 开关增量仍是待解决证据，GPU 0.6021 ms/4K 2.2211 ms 也不能替代完整 CPU 性能结论。GTAO/TAA 的采样归属与正式性仍须按 v2 完善，再按可比条件评估，不通过加大阈值制造通过。

下一阶段再建设自动影响分析、逐用例证据复用和代表配置 PERF-F。当前这次验收不需要为验证上述约束修复而重新跑全部性能矩阵。

## 后续减负调整：总时限与性能检查降级

同日用户反馈检查运行两天未结束，并明确要求降低性能/时间负担。当前进程检查只发现一个 Gradle daemon，没有仍在执行的测试子进程，最近长测日志未持续更新，不能将两天的耗时归因到某个已确认的本地测试。本次没有关闭其他会话或共享 daemon。

- 默认入口改为 `verify.ps1`，运行 `acceptance` → Render3D 定向逻辑与 GL；总时限 300 秒，使用独立单次 daemon。超时只结束本次启动的进程树，生成失败/未完成报告，不自动重试。
- 普通功能验收不强制性能测试，不以旧性能百分比或 GTAO CPU 数值阻断逻辑签收；历史超标保持性能欠账。正式性能承诺与全量发布仍须明确申请并单独验证，不能把短测写成正式通过。
- 旧全量聚合、soak、非 smoke benchmark 要求 `-PextendedVerification=true`；增加任务级 timeout。外层脚本的 Extended 模式最多允许 1800 秒总时限，直接调用 Gradle 不保证总体时限。
- 默认限时入口实测成功：`build/reports/bounded-verification/658ef2a1-e64d-41c0-aa57-d7718c42132e/result.json`，Gradle 27 秒；关联逻辑报告 `9309df79-526f-47f0-b9a5-11236a69fc8d`，116 项全部实际通过、无跳过，`candidateStable=true`。报告中的 `performance=NOT_REQUIRED`、`releaseReady=false` 明确范围。
- 1 秒超时负向试验报告 `build/reports/bounded-verification/098d83bb-57bd-4f63-b9e7-63b1b142e9df/result.json`：约 1.35 秒后终止，`TIMEOUT`、`success=false`、记录码 124；随后进程核对没有残留本次 Java 进程，原共享 daemon 保留。
- 未带 extended 参数的 `releaseReadiness` 在任务执行前明确拒绝，全量矩阵未启动。

以上运行后仅追加本记录，按文档检查处理，不再重复渲染测试。新规则详见验收规范第 0 节；不能让旧的 L2/L3 时间建议再次触发持续多天的重测。
