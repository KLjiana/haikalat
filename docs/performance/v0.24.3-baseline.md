## 测量口径与预算

- GPU 样本键：`(runId, generationId, passName, sampleFrameSequence)`；按提交 ticket 映射 round/phase/measuredIndex。
- 正式顺序：round-major；同一轮按固定顺序交替 zero-light、clustered 与 full-scan，而不是先跑完所有 A 再跑 B。
- 每轮 120 帧 warmup + 300 帧 measured，至少三轮；最后提交后在 10 秒 deadline 内只 flush/drain，不补帧。
- 为避免 300 帧超过每 pass 的 256 槽 query ring，测量期每 32 帧执行一次同样有 10 秒上限的 flush/drain 检查点；不逐帧 `glFinish`，检查点等待不计入单帧 CPU 区间。
- 必需 pass 逐轮覆盖率和完整同帧组合覆盖率均需 `>=95%`。full-scan 只保留 Upload+Geometry，禁止执行 Bounds/Assign/Stats。
- CPU：`executeWall`、`framePreparation`、`lightPackAndRecord`、`graphRecord`、`deviceSubmit`、`unattributedCpu` 分开；隔离任务不替代正常运行。

## 线性 HDR 与视觉对照

- 九张冻结参考在 `config/visual-baselines/reference/`，每场景 60/240/420 帧各一份。读取 tone mapping、Bloom 前的 RGBA16F 颜色并以 4×4 线性平均保存 320×180 RGB float；无 PNG 反推 HDR。
- `runRender3dVisualBaselineQuality` 逐帧与冻结参考比对，RMSE <= 0.015、逐像素 RGB RMSE p95 <= 0.035；误差图在 `build/reports/render3d-v0243/visual/hdr-error/`。同一 GPU/驱动独立重跑九帧均为 RMSE/p95=0。
- 三场景另输出 tone-mapped final、fog-off、Bloom-off、固定曝光灰模；真实像素差异门禁分别确认 fog/Bloom 开关不是空操作。该对照发现并修正了 TAA 外部颜色目标导致 Bloom 首级被跳过的错误。
- Outdoor 晨雾与黄昏另在 60/240/420 帧从体积 RGBA16F 附件直接输出散射 RGB、透射率 alpha 和 temporal shader 的拒绝掩码；小镇末帧输出真实 light-count、overflow、shadow-slot debug shader 图。对应任务为 `runRender3dVisualDiagnosticQuality`，图像在 `visual/diagnostics/`，不在性能测量窗口读回。
- 同路径的 Outdoor `reference` 模式采用 96-step、全分辨率、history-off 体积计算，六帧线性 HDR 与常规冻结基线的 RMSE 为 0.0027–0.0038、p95 为 0.0039–0.0057，低于沿用的 0.015/0.035 门槛；比较误差图在 `visual/hdr-error/highsample-*`。profile 加载后仍应用 reference 质量覆盖，避免误测成常规模式。
- 冻结九帧是同机候选回归参考，Outdoor reference 是较高采样的独立质量模式，不是解析物理真值；跨 GPU/驱动使用时必须审查误差图和阈值。时域残影恢复曲线仍需进一步量化。
