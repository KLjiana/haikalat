# v0.24.1 发布偏差记录：性能基线门禁环境失败

日期：2026-09-10

## 结论

v0.24.1 候选在功能、资源、架构、契约与画质门禁上全部通过；唯一未通过的是
`releaseReadiness` 中的 `comparePerformanceBaseline`（`static-all-visible` CPU
中位数超过 v0.17.2 基线 5% 容差）。经同机 A/B 证明这是环境性能偏差，不是
v0.24.1 的代码回归。按项目所有者决定，本版本带着这一已记录偏差发布。

## 证据

- 同机对照：在 `HEAD`（v0.24.0，`1998151`）的独立 worktree 上运行
  `runSceneSubmissionStaticBenchmarks`，`static-all-visible` 的 CPU
  中位数为 `3.465–3.648 ms`、`command=0.789–0.888 ms`；v0.24.1 候选为
  `3.27–3.35 ms`、`command≈0.8 ms`。两者一致，候选甚至略快。
- 基线：`docs/performance/baselines/v0.17.2-windows-rtx3050.json` 的
  `static-all-visible` CPU 中位数为 `2.977 ms`，门禁上限 `3.126 ms`。
- 环境指纹（OS、Java 21、LWJGL 3.3.3、NVIDIA RTX 3050 Laptop、驱动
  `576.88`、Windows 11）与基线完全一致，因此比较被视为可比。
- 电源：已确认交流供电；切到"高性能"方案后中位数仍为 `3.23–3.44 ms`。
- 系统状态：物理内存 16 GB、提交内存约 30.4 GB，`Memory Compression`
  持续接近满载，整机处于换页/内存压缩状态；关闭游戏等前台程序后基准仍
  `3.27–3.35 ms`。这是当前机器相对基线录制时约 8–18% 的整机变慢。

## 处理

- 未修改基线文件、容差或豁免；`RL-01` 的"不得修改旧 baseline 或扩大容差使
  结果变绿"被遵守。
- 发布报告把 `releaseReadiness` 标记为未通过，并把本文件列为偏差记录。
- 后续应在重启后的干净环境或 CI 重新执行 `releaseReadiness`；届时若
  `comparePerformanceBaseline` 通过，可撤销本偏差状态。
