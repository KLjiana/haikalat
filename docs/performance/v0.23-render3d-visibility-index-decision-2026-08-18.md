# v0.23 Render3D M7 可见性与空间索引结论（2026-08-18）

> 日期：2026-08-18

## 环境与方法

- Windows / NVIDIA GeForce RTX 3050 Laptop GPU / OpenGL 4.6 NVIDIA 576.88。
- `runSceneScalabilityBenchmarks`：640×360，3 paired rounds，20 warmup，100 samples，100/1,000/10,000 objects。
- `runSceneSubmissionStaticBenchmarks`：同尺寸与轮次，10,000 个全静态对象，all-hidden / large / all-visible。

## 结果

| 场景 | 可见 | queue build | CPU median | cache |
|---|---:|---:|---:|---|
| 100 small | 70 | 0.032 ms | 0.326 ms | dynamic baseline |
| 1,000 medium | 250 | 0.132 ms | 0.509 ms | dynamic baseline |
| 10,000 large | 1,000 | 0.940 ms | 1.957 ms | dynamic baseline |

## M8 发布性能修复

首次正式门禁暴露出 M1 revision capture 在稳定场景中每帧两次扫描全部 renderer，
`SceneFrameBuilder.syncMaterialState()` 又扫描一次。其特征是 command record 未回退，但
10,000 all-hidden CPU median 从历史 `0.054 ms` 升到 `0.336 ms`，all-visible 五轮中位数为
`3.334 ms`，超过固定 `3.126 ms` 上限。

修复后，Transform/Material 有效变更推进进程级单调 mutation epoch；稳定场景以 O(1) 读取 epoch，
任意非 revisioned model updater 仍按 frame index 保守失效，material epoch 变化时才扫描本 scene
实例。使用同一 1280x720、100 warmup、1,000 samples、5 rounds 参数复测：

| 场景 | 五轮 CPU median | 五轮中位数 |
| --- | --- | ---: |
| 10,000 static all-hidden | 0.126 / 0.068 / 0.057 / 0.051 / 0.045 ms | 0.057 ms |
| 10,000 static all-visible | 3.034 / 3.062 / 3.128 / 3.118 / 3.001 ms | 3.062 ms |

没有修改 baseline、5% 阈值、warmup、sample、round 或场景规模；`3.062 ms` 低于
`2.977 * 1.05 = 3.126 ms` 发布上限。

## 决策

对象数与静态比例门槛满足，但 O(N) culling + queue scan 没有持续超过 2 ms；静态场景的 revision/queue cache 把 queue 成本压到 0.08 ms 以下。CPU spatial index 的准入条件不成立，v0.23 **不实施 BVH/AABB tree**。保留确定性 arena/queue 接口与指标，未来只有在代表机器上重新满足全部四项门槛时再引入。
