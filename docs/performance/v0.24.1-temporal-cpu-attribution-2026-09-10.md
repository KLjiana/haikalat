# v0.24.1 Temporal CPU 预算归因与口径修正

日期：2026-09-10

候选：HEAD `1998151` 上的 v0.24.1 工作树；基准报告按源码 SHA-256 指纹落盘。

## 问题

4K 下 TAA resolve GPU 为 1.53 ms（预算 3 ms 内），但基准的"CPU 增量"约 2 ms，
超过 0.5 ms CPU 预算。需要确认这是 TAA 的 CPU 成本，还是测量口径问题。

## 归因方法与实测

基准新增逐 pass CPU 时间、`recordP50` 与 `submitP50` 分段，并对比是否在测量帧前
清空驱动队列：

| 尺寸 / 口径 | recordΔ | submitΔ | wallΔ | SceneSurfacePass GPU | TaaPass GPU |
| --- | ---: | ---: | ---: | ---: | ---: |
| 1080p | 0.04 ms | 0.13 ms | 0.18 ms | 0.09 ms | 0.21 ms |
| 4K，未隔离 | 0.07 ms | 1.65 ms | 1.71 ms | 0.27 ms | 1.38 ms |
| 4K，测量帧前 `glFinish` | 0.02 ms | 0.17 ms | 0.19 ms | — | 1.81 ms |

关键等式：4K 未隔离时 `SceneSurfacePass 0.27 ms + TaaPass 1.38 ms ≈ submitΔ 1.65 ms`。
`FrameDriver.beginFrame→endFrame` 的墙钟窗口包含 `device.execute(cmd)`；4K 下新增 GPU
工作填满驱动命令队列，GL 提交被阻塞，GPU 时间因此被计入"CPU 时间"。record 时间在
所有尺寸都约 0.02 ms 且与分辨率无关，证明录制本身没有超预算。

## 修正

- 基准模式在测量帧前调用 `glFinish()` 清空队列（窗口外），使 CPU 窗口只含录制与提交；
  `cpuIsolation` 字段写入报告。
- 门禁按 **CPU 录制增量**（0.5 ms）判定；`submit`/`wall` 单独报告并以 3 ms 作为
  驱动反压 sanity 上界；GPU 预算仍按 TAA resolve p50 判定（1080p 1 ms / 4K 3 ms）。
- 报告新增每 run 的 `recordP50Ms`、`submitP50Ms`、`cpuPasses` 与候选源码 SHA-256。
- 基准模式关闭 debug group，与 GTAO 基准一致。

## 正式门禁结果

`runRender3dTemporalBenchmarks`（3 轮、每轮每模式 30 预热 + 60 实测 + 16 drain）：

| 分辨率 | CPU recordΔ p50 | wallΔ p50 | TAA resolve GPU p50 | 预算 | 结论 |
| --- | ---: | ---: | ---: | --- | --- |
| 1920×1080 | 0.0221 ms | 0.1619 ms | 0.3625 ms | 0.5 ms / 1.0 ms | 通过 |
| 3840×2160 | 0.0157 ms | 0.1890 ms | 1.8053 ms | 0.5 ms / 3.0 ms | 通过 |

画质门禁 `runRender3dTemporalQuality`（480×480、40 帧、第 24 帧硬切镜）：

- 抗锯齿能量 `0.01645 → 0.00690`（ratio 0.420，门限 0.85）；
- 边缘锐度 ratio 0.712（门限 0.65）；
- 切镜残影衰减 0 帧（门限 ≤8），末帧与 NONE 差 0.00000。

## 边界

- 基准场景仅 2 个对象，SurfacePass 录制增量随对象数线性增长；发布候选必须用与
  验收场景相同对象数的基准，不能把 0.02 ms 外推到复杂场景。
- 驱动显存峰值仍无可信采集，报告记录为 null；本基准是同场景 NONE/TAA 对比，
  不覆盖 GTAO/体积效果组合全矩阵。
