## 冻结输入与计量

沿用 `quality.properties` 的原生尺寸、stride=4、全 320×180 ROI、2% 稳定度、暗区绝对阈值及 5% 恢复门槛。
镜头/世界/VFX 使用第 119 帧输入，从 120 帧停止 simulation delta；成功帧的体积与 TAA jitter/history 继续推进。

计量为 ROI 平均亮度的 population STD / reference mean，与既有固定 GL 稳定度合同一致。
逐像素相对/暗区绝对 STD 极值另存，不用 ROI 平均掩盖 TAA 几何边的可见闪动；后者仍须视觉检查。
这不是移动风场验收，也不是独立光学输运参考。

关灯雾增量采用整 ROI 的 `sum(abs(candidate.rgb-baseline.rgb))`；保留负 ghost，不将负差截为 0。
180 帧关闭选定灯的体积 hints，表面照明保持；第 181 帧为关灯后第 2 帧。
无可见增量时 ratio=null 且失败，不能除零登记通过。三个 JVM 回归覆盖负 ghost/不可见灯、
相反像素抖动的 ROI 平均与逐像素诊断区别、暗区绝对阈值及非有限输入。

## 为什么需要受控基线

原 4761977 基线从一开始使用零 hints。候选的光源变化和快速灯会生成局部拒绝域，而该基线不会，
两边背景 q 的滤波和 TAA reactive 因而不同。实验室的无 TAA/有体积历史在第 180 帧表现为候选 2 个脏域、基线 0 个；
关后图像差并非全部来自选定灯的旧雾。原实验室第 2 帧比值 1.3155/1.5943/1.7093 不能据此归因为灯雾残留。

当前 Demo helper 在相同 CPU hints/灯表/阴影/事件下，仅从基线 GPU source 的光源求和中省略选定灯 radiance。
它用 stableId 查当前完整灯索引，不写表面灯表。两边第 180 帧将 hints 置零，因此背景 source 历史策略一致。
每个成功帧直接比较 count/reason/shadow-refit、dirty-domain bytes、时间与三轴相位；有 TAA 时重放候选的 native R8，
最后读回并逐 byte 核对。这是明确标记的 photometric ablation，不是生产零 hints 场景的自然策略。
2316 个成功帧策略配对和 1544 个 R8 重放核对全部通过；它仍不解除实际灯变化的背景/几何边视觉验收。

控制只通过两个 package-private recorder seam 安装，要求显式 readback。helper 的 shader、SSBO 和 quad 均由 Demo 持有，
关闭时移除 seam 并释放；生产路径没有调用者，没有新 public main API 或生产 texture/storage。
基线借用 reference source recorder，其 source 原子诊断关闭，有限保护/限幅仍在；正常 candidate 的数值计数必须为零，
两边最终 float 图像独立检查非有限值。不能用基线零计数声称其 light-visit 路径已被正常计数覆盖。
