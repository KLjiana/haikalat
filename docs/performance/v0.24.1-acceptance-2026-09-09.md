## 必须修复的问题

### F1 / P1：录制失败后会跳过尚未执行的 previous 变形上传

位置：`SkinSceneDrawBinding.java:101`、`:122`；`MorphSceneDrawBinding.java:113`、`:139`。

`recordPrevious()` 把上传加入 CommandBuffer 后立即设置 `previousUploaded=true`。若后续 recorder 抛异常导致命令不执行，`discardTemporalFrame()` 只清 pending，没有清 previousUploaded。下一帧会认为 previous buffer 已更新，跳过上传；实际 GPU 数据可能属于更早一帧，甚至未初始化。

修复：把已录制与已执行状态区分开，或在 abort 时保守使上传缓存无效并允许重传。当前 deformation 上传缓存也应检查同类路径。增加真实失败注入：先完成一帧动画，再在 previous upload 录制之后、GPU 执行之前抛错；重试后读回实际 velocity 与 expected depth，不能只检查 CPU valid 标志。

### F2 / P1：不具备 previous deformation 的绑定仍被当作可信历史

位置：`TemporalSceneState.java:54`。

`previousStateValid()` 在 `temporalBinding()==null` 时直接返回 true，没有区分静态 binding 与 `deformsVertices()==true` 的自定义变形 binding。现有 public 接口允许旧实现没有 temporal capability，因此该路径会把不可信变形标成有效，surface shader 可能按当前骨骼/Morph 类型读取未正确绑定的 previous 数据。

修复：无 temporal capability 只在能够确认静态表面时使用 previous Model；变形对象输出 validity=0，若当前 surface 也不能一致生产则按兼容合同拒绝。增加自定义 skin/morph binding 未实现 temporal 的 GL 测试，不能只验证内建绑定。

### F3 / P1：成功帧提交不是整体事务

位置：`RenderPipeline.java:935`；`TemporalSceneState.java:66`；`TaaHistory.commitSuccessfulFrame()`。

代码先提交 postProcess/TAA history 和相机，再调用 TemporalSceneState，其中先交换 Model，再调用 public `TemporalDrawBinding.commitTemporalFrame()`。该回调可抛异常；一旦失败，catch 中的 discard 不会撤销已交换的 history、相机或 Model。最终得到部分推进的“失败帧”。

修复：增加可失败的 prepare-finalization 阶段与不可失败的统一发布阶段，或者提供能够完整撤销的事务对象。不能仅重新设置 prepared=false。增加在 deformation finalize 中抛错的测试，比较所有 history read ID/内容、camera token、Model 与 palette 是否仍共同指向上一成功帧。

### F4 / P1：Reactive 与天空路径尚未按交付合同完成

位置：`PipelineTopology.java:130` 固定 `taa(false)`；`scene-surface.frag:59` 固定 `outReactive=0`；`taa-resolve.frag:48` 对无效表面直接返回 current。

当前正式图没有依据透明/粒子/材质需求启用 reactive；只有 shader 输入接口不能算 reactive 功能完成。天空没有表面有效性，直接走 current 分支，也没有按相机旋转重投影的独立路径。

修复：接入真实 reactive 生产者和覆盖率统计，为透明/ADD/emissive 提供明确响应协议；天空单独实现方向重投影与背景覆盖校验。验收用移动透明前景、变化 emissive、旋转天空和风动场景序列。当前 surface 实现中未发现风动前后状态求值，亦不能宣称 M4 全部完成。

### F5 / P2：对象快照没有移除，长期切换内容会持续保留旧对象

位置：`TemporalSceneState.java:17`、`:26`、`:93`。

IdentityHashMap 只 computeIfAbsent，commit/discard/invalidate 都没有 remove/clear。被移出 Scene 的 MeshRenderer 仍被强引用，快照和绑定长期保留；同一 renderer 隔若干帧重新加入还可能取得过期 previous Model。

修复：在成功帧提交时按当前 membership 清理退出对象，明确重加入与场景替换规则；失败候选不能提前清理已提交快照。加入对象 churn 长测，验证 cache 数量回落到当前存活对象规模，并检查重加入的首帧无效。

### F6 / P1（发布阻塞）：资源及正式验收产物不完整

assetManifestGuard 实测失败：缺少 scene-surface-resolve.frag、taa-resolve.frag 和 surface 目录下 3 个 shader，共 5 项；gtao-estimate.frag、gtao-temporal.frag 共 2 项 SHA-256 不匹配。

此次变更没有提供 runRender3dTemporalBenchmarks 正式入口及其性能基线、运动序列报告；release-verification 中未发现 temporal 专项的明确接入。M6 不能标记完成。18 项 temporal 测试中，SceneVelocityMathTest 是数学测试，不能替代实际 surface shader 的动态速度、MASK 轮廓和失败重试测试。

修复：补全清单与实际候选 hash；实现并接入 temporal 正式性能/场景验收。保留旧 GTAO/户外门禁，不通过放宽门槛补齐证据。

## 可以确认的进展

- 新增 SceneBufferRequirements、SceneBufferView、SceneSurfacePass/Resolve 和 R32F 支持，已不局限于旧颜色混合。
- TAA resolve 具备 velocity+jitter 重投影、逐 tap 深度验证、邻域 clamp/可选 variance 与 HDR 输出。
- TaaHistory 已有颜色/深度双缓冲与候选读写分离，但跨所有 temporal owner 的事务仍不完整。
- 定向测试证明了基础融合、无效拒绝、越界、HDR 和若干历史生命周期行为，不能外推成全部动态场景覆盖。
