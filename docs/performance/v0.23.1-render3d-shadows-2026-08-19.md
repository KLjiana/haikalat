# v0.23.1 Render3D 阴影性能与缓存记录

> 日期：2026-08-19
>
> 候选版本：`0.23.1`
>
> 对照基线：`67afe3b`（v0.23.0 发布后的稳定 revision fast path）

## 环境与方法

- Windows、Java 21、LWJGL 3.3.3、OpenGL 4.6 Core；NVIDIA GeForce RTX 3050 Laptop GPU，
  驱动 576.88。
- hidden GLFW 窗口、VSync 关闭、test environment、AA/Bloom/auto-exposure 关闭，固定场景和相机。
- v0.23.0 对照与候选都运行 300 帧、预热 180 帧，每个分辨率交替执行五轮。以下 A/B 数字是每轮
  frame median，再对五轮取中位数。两边使用相同运行时 HDR 资源和 JVM/驱动环境。
- v0.23.1 profile 另运行五轮 180 帧、预热 60 帧；每轮保留 120 个样本，并记录 CPU median/P95、
  GPU frame、shadow GPU pass、tile redraw/reuse 与估算 depth memory。

- balanced 1080p CPU median：`0.796 / 0.836 / 0.860 / 0.874 / 0.833`；P95：

  `23.875 / 23.903 / 24.225 / 23.930 / 23.777`。

balanced 的 point atlas 为 1536×2048、spot atlas 为 1024×1024；legacy 分别为 1536×1024 和
512×512。balanced profile 包含 floor、ceiling 与三面 wall 的全屏室内接收面，因而 GPU frame 数据
也包含 1+2+4 阴影对高覆盖率接收面的真实采样成本，不能与 legacy 的不同场景直接比较。静态预热后
连续命中 20 个 directional/point/spot tile，实际 depth draw/clear 归零；shadow pass 节点仍保留在
RenderGraph 中。集成序列另外证明单 point、单 spot、相机和
skin/morph 变形分别精确重画 6、1、4 和 20 个 tile，resize 不更换固定 atlas。

## 结论

legacy 同能力配置满足 CPU/GPU 不超过 5% 的发布阈值；balanced 的额外显存和采样成本与 2+4 能力
相符，静态场景通过缓存避免重复 depth 提交。五轮测试只出现 NVIDIA `API/PERFORMANCE/131218`
shader-state specialization 消息，均由精确、有限额且有到期日的策略覆盖；最终 GL 合规结论以
`releaseReadiness` 生成的同一候选审计为准。
