# v0.24 室外渲染优化复测

本记录覆盖 v0.24.0（577463d）之后的本地工作区优化，日期 2026-09-08。
环境为 Windows、Java 21、NVIDIA GeForce RTX 3050 Laptop GPU、OpenGL 4.6、驱动 576.88。
原发布记录保留为历史证据；本次修改尚未提交或发布。

## 实现与画面

- 修复普通相机移动清空体积历史的问题；保留重投影，突变切镜仍拒绝历史。
- 历史权重和深度拒绝参数传到活动 pass；重建和原地参数更新都使用实际配置。
- 预设同步场景阴影太阳，天空渐变生成漫反射/镜面 IBL，排除太阳圆盘，避免重复计入方向光。
- Demo 用四项有界环境缓存管理 IBL，管线借用资源；图替换后 UI 显式重绑。
- 体积积分输出散射代表位置深度，匹配 TAA 投影抖动；上采样先取离散低分辨率样本，再按深度加权。
- 全局基础密度为零时仍积分局部雾；局部雾使用连续噪声及柔和边界，风按成功帧时间推进。
- CSM 覆盖外抑制直接散射，PCF 使用接收平面深度修正，减轻起伏地形的条纹状自阴影。
- Demo 改为共享程序化网格的低多边形林地，包含起伏地形、小径、树冠、分叉树干、草和岩石。
  固定曝光配合晨雾/晴天/黄昏配色，便于判断照明变化。

## 同场景五轮成本

每组预热 120 帧，测量 600 帧，关闭 VSync；表中为五轮 p95 的中位数。
关闭组保留相同天空、IBL、场景和曝光，只关闭体积链。1080p 使用 32 步、每轴 1/2；
4K 使用 32 步、每轴 1/4。GPU 是管线整体计时，增量由配对开关统计相减，未将各 pass 的 p95 相加。

| 尺寸 | 体积关 CPU/GPU p95 (ms) | 体积开 CPU/GPU p95 (ms) | CPU/GPU 增量 (ms) |
| --- | ---: | ---: | ---: |
| 1920×1080 | 0.4029 / 1.7408 | 0.6064 / 4.4820 | +0.2035 / +2.7412 |
| 3840×2160 | 0.5209 / 5.7580 | 0.7128 / 9.0941 | +0.1919 / +3.3362 |

均满足原计划增量预算：1080p GPU ≤3 ms、4K GPU ≤5 ms、CPU ≤0.3 ms。
开启体积后的线程分配 p95 为约 12.3 KiB/frame。新场景几何、阴影接收和画面覆盖率均改变，
不能将整体帧耗时与旧球体阵列样板直接比较，也不能据此宣称总帧率提高。
