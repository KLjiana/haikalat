# v0.22.2 共享 GLB 动画专项证据

日期：2026-08-18

环境：Windows、Java 21、Gradle 8.10.2、LWJGL 3.3.3、OpenGL 4.6 NVIDIA。专项验证覆盖
共享动画集的 CPU 绑定、GL 上传和运行时姿态驱动；本补丁没有新增 shader 或额外每帧分配
路径，因此 v0.22.1 的文本性能基线仍是本版本的性能基线参考。

## 验证命令

以下命令均在最终候选源码上执行：

```powershell
.\gradlew.bat compileJava demoClasses test --rerun-tasks --no-daemon --console=plain
.\gradlew.bat runGltfSharedAnimationIntegration architectureGuard publicApiGuard --rerun-tasks --no-daemon --console=plain
.\gradlew.bat glSmoke --tests "com.kaleblangley.haikalat.subsystems.render3d.gltf.GltfRuntimeGlTest.sharedGlbAnimationSetUploadsAndDrivesAnotherModel" --rerun-tasks --no-daemon --console=plain
.\gradlew.bat localGltfVerification --rerun-tasks --no-daemon --console=plain
```

## 结果

- `compileJava demoClasses test`：通过；全量 JVM 测试通过。
- `runGltfSharedAnimationIntegration`：通过；覆盖独立 GLB 动画集、同一 Rig 的多模型绑定、
  多 clip 清单选择和旧 JSON sidecar 兼容入口。
- `GltfRuntimeGlTest.sharedGlbAnimationSetUploadsAndDrivesAnotherModel`：通过；真实 OpenGL
  上传共享动画并驱动另一 Mesh，蒙皮 palette 发生预期变化，结束时 `GL_NO_ERROR`。
- `localGltfVerification`：通过；包含 parser/accessor/node/material/skin/animation/Morph、
  resize、player_wild、serialized scene 和共享动画集路径。
- 共享动画集只复用不可变 `AnimationDef`/channel 数据；每个实例继续独立持有时间、PoseBuffer、
  Animation Graph 和蒙皮 palette。严格 Rig 签名拒绝节点顺序、父节点、bind TRS、skin joints
  或 inverse-bind matrix 漂移。

## 性能结论

共享动画集导入发生在 CPU 资产阶段，动画绑定不复制关键帧数组，也不引入新的 GPU shader
分支。运行时仍使用现有动画采样、姿态上传和蒙皮路径，因此没有发现相对 v0.22.1 文本基线
的新增回退信号。完整文本性能数据保留在
`docs/performance/v0.22.1-text-2026-08-09.md`，发布门禁会继续生成本候选的机器可读性能
结果。

## GL 与资源合同

专项真实 GL 测试未报告 `GL_INVALID_*`、未授权 HIGH/MEDIUM、资源泄漏或线程悬挂。动画 GLB
中的 Mesh、材质、图片和 sampler 不进入共享动画集，也不会被绑定目标删除；目标模型仍拥有
自己的 GPU 资源和关闭生命周期。
