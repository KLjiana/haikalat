## 技术卡

| 字段 | 内容 |
|---|---|
| 技术 ID／用户场景 | #34 Temporal Denoising；为 #20 SSR 的单 ray、逐像素噪声提供重投影、历史拒绝、邻域/矩 clamp 与历史累积，降低镜头/物体运动时的闪烁和空间 march 不稳定。首版默认关闭。 |
| 当前基础／差距 | #20 已交付纯空间 SSR：无历史、无重投影、无降噪；TAA/GTAO 已提供 velocity、previous surface depth、validity、历史事务和 candidate-first resize 的既有模式。缺少绑定真实噪声信号的时域 denoiser。 |
| 首版范围 | **一个已有真实信号**：`SsrPass` 输出的 `ssrColor`。每帧一次 MRT fullscreen resolve：重投影 → 深度/法线/亮度突变拒绝 → 深度一致的邻域 AABB + luminance moments σ clamp → 历史混合 → 更新历史颜色/深度/法线/矩。不做光追、不做 GI/云/多信号共享历史、不做逐像素方差预算、不做时域升采样（#35）、不替代 TAA。 |
| 输入 | 当前噪声颜色（RGBA16F，线性 HDR；首版为 `ssrColor`）；单采样设备深度；octahedral 世界几何法线；可选冻结 velocity + previous surface depth（两者必须成对）；当前 TAA UV jitter；当前 inverse raster projection（TAA 开启时为 inverse jittered projection）、当前 inverse view、当前 stable view-projection。 |
| 输出 | 全尺寸 RGBA16F denoise 颜色（下游 HDR 链消费）；同时写入 RGBA16F 历史 state（正 view depth、oct normal、surface flag）与 RG32F luminance moments（mean、mean-square）。历史颜色/深度/法线/矩只在成功帧提交。 |
| 模块与控制 | `subsystems.postprocess.denoise.TemporalDenoisePass`（program + `ScreenQuad` + 私有双缓冲 history）；`TemporalDenoiseSettings`、`TemporalDenoiseInputs` 为 postprocess 域 advanced 合同；`TemporalDenoiseHistory` 为包内 owner。`PostProcessSettings` 追加 `temporalDenoise` 组件，默认 `disabled()`；关闭时不创建 program、history、attachment 或 draw。 |
| 坐标与深度 | UV 为 OpenGL 栅格 UV（原点左下）。深度是当前 raster projection 产生的单采样设备深度；内部用 `inverseProjection` 还原为**正 view-space depth**。颜色为线性 HDR。历史 state 存储正 view depth，而不是设备深度或世界 Z。 |
| 重投影 | 两种合同：① velocity 模式（`velocity` + `previousDepth` 均非零）：`previousUv = currentUv + velocity - currentJitter + previousJitter`，expected previous depth 取 `previousDepth` 当前像素；② previous-view-projection 模式（两者为零）：由当前深度还原世界位置，用 pass 上一次成功帧保存的 stable view-projection 投到上一帧 stable UV，再加 `previousJitter` 落到上一帧 jittered 栅格；expected depth 由上一 inverse projection 从 previous clip 还原。两种模式都限制 `length((previousUv - uv) * extent) <= maxReprojectionPixels`，越界/非有限/非正 w 直接重置。 |
| 拒绝与 clamp | 2×2 history tap 逐 tap 验证 surface flag、深度窗口 `max(1e-4, depthRejectionThreshold * max(expectedDepth, 1))` 与法线 dot ≥ `normalRejectionThreshold`；亮度相对跳变超过 `reactiveThreshold` 触发 reactive/shock reset。接受的历史先 clamp 到当前半径内、深度一致的邻居 AABB；history moments 的 temporal σ 用于 (a) 空间平坦邻域的 AABB 扩张和 (b) luminance clamp 的 `sigma = max(currentSigma, historySigma)`，最后再 AABB clamp。当前邻域采用固定 compile-time 上界，运行时 radius 1–4。 |
| 历史与事务 | 双缓冲，每 slot 三个颜色附件：RGBA16F resolved colour、RGBA16F state、RG32F moments。`beginFrame()` 标记 write slot；`frameSucceeded()` 才交换 read/write；`frameFailed()` 丢弃 candidate；`invalidate()` 清空 valid 与上一帧相机矩阵。`prepareResize` 先分配完整 candidate，`commitResize` 才替换并清空上一帧矩阵；candidate 负责关闭 retired pair。`close()` 幂等，关闭 program、quad 与全部 history 附件。 |
| 独立参考 | JVM double 参考 `TemporalDenoiseReference`：固定矩阵的 world 重建/prev-VP 投影、深度窗口、法线 dot、亮度 shock、3×3 深度一致邻域 AABB 与 moments clamp；另含 TAA jitter 的上一帧世界点对齐与线性 ramp 期望误差复算（0.75 px → 世界位移 0.0541 m → 3.0/m ramp 误差 0.162）；固定输入可复算。GL 合成噪声收敛 case 另用 512 帧高样本平均作参考；真实 SSR case 用“平均 wall radiance 的 SSR 输出”作线性期望参考。 |
| 成本／回退 | 每成功帧 1 次 fullscreen MRT draw；固定 4 次 history tap + 至多 `(2×4+1)^2` 次当前邻域 tap；每 slot 24 B/px，双 slot 约 48 B/px（1920×1080 约 100 MB 历史，不含 TAA）。未做 GPU 计时，性能 `NOT_EVALUATED`。回退：denoise 关闭时精确保持原 HDR 链；SSR 关闭时拒绝启用 denoise。 |
| 验证范围 | JVM：settings 边界/禁用 no-op、double 参考、输入合同、shader 有界结构、surface producer 依赖去重；`PostProcessSettingsTest` 与 SSR JVM 消费者回归。真实 GL：`TemporalDenoisePassGlTest` 首轮 8 case 6 PASS / 2 FAIL；修复后复审轮 8/8 PASS；新增 2 个判别 case 后共 10 个，等待 GPU 串行重跑（新增项 `NOT_EVALUATED`）。 |

## 参数

| 参数 | 默认 | 校验 |
|---|---|---|
| `enabled` | false | 关闭时不创建任何资源或 Pass |
| `historyLengthFrames` | 10 | [2, 64]；`historyWeight = 1 - 1/length`（默认 0.9） |
| `neighborhoodClampRadius` | 2 | [1, 4]，与 shader `TDN_MAX_NEIGHBORHOOD_RADIUS=4` 一致 |
| `depthRejectionThreshold` | 0.02 | [1e-4, 0.5]，相对 view-depth 窗口 + 1 m 绝对 floor |
| `normalRejectionThreshold` | 0.85 | [0, 1]，最小法线 dot |
| `reactiveThreshold` | 0.5 | 有限非负；亮度相对跳变超过则 reset，0 表示任意非零跳变都 reset |
| `maxReprojectionPixels` | 64 | [0, 4096]；0 只接受同像素历史，用于负对照/静态信号 |

`TemporalDenoiseSettings.depthTolerance(expectedDepth)` 与 shader 使用同一公式，便于宿主
报告实际窗口；`historyWeight()`/`currentWeight()` 公开混合值。

## 历史布局与 MRT

| attachment | 格式 | 内容 |
|---|---|---|
| 0 | RGBA16F | 线性 HDR resolved colour（rgb）+ 当前 alpha；下游 HDR 链读取 |
| 1 | RGBA16F | `r` = 正 view-space depth；`gb` = octahedral 几何法线；`a` = surface flag（1 有效，0 背景） |
| 2 | RG32F | `r` = luminance mean；`g` = luminance mean-square；用于下一帧 `mean ± 2σ` clamp |

RGB 颜色不写入 moments（只维护 luminance 矩），因此首版没有逐通道协方差或逐像素方差估计；
这是明确的限制，不是隐藏承诺。

## 与 #20 / #35 的边界

- **#20 SSR**：`SsrPass` 继续只拥有空间 ray march、无历史；#34 消费 `ssrColor`，不修改
  `SsrPass`、SSR 深度/法线/粗糙度合同或 fallback。denoise 开启要求 SSR 已开启且 HDR 链
  已开启；否则 `PostProcessPipeline.assemble` 抛
  `temporal denoising requires an active screen-space reflection signal` /
  `temporal denoising requires HDR tone mapping`。
- **#35 Temporal Upscaling**：本 pass 不改变分辨率、不做低分辨率输入重建、不拥有锐化或
  输出尺寸策略。#35 若需要复用，应按自己的输入分辨率、reactive/exposure/UI 语义创建独立
  owner，不共享本 pass 的历史。
- **不同信号不共享历史**：一个 `TemporalDenoisePass` 只服务一个信号。SSGI/云/体积雾
  等未来信号必须各自创建 pass；颜色、深度、法线、矩和上一帧矩阵的语义没有跨信号通用性。
- **TAA**：TAA 仍负责 jitter/颜色 resolve。denoise 位于 TAA 之后、SSR 之后；输入携带当前
  TAA jitter，pass 保存上一成功帧 jitter，并按 `velocity - currentJitter + previousJitter`
  （velocity 模式）或 `stablePreviousUv + previousJitter`（prev-VP 模式）对齐上一帧 jittered
  栅格；深度重建仍使用当前 raster inverse projection。

## Pass 顺序与配置拒绝

HDR 链：

```
Geometry → [HdrResolve] → [Fog] → [VfxComposite] → [ScreenDistortion] → [TAA]
  → SsrPass → TemporalDenoisePass → [DepthOfField] → [MotionBlur]
  → AutoExposure/Bloom → ToneMapping → ...
```

`PostProcessPipeline` 只在 `effects.temporalDenoise().active()` 时创建 denoise owner；
启用但 SSR 非 active 或 HDR 关闭时在候选装配期拒绝。禁用时 `passNamesFor` 与执行顺序完全
不变。denoise 使用 `writeToExternalTarget()` 写入自有 history slot；pipeline 在
`addFinalPass` 先注册初始外部颜色，并在每帧 `synchronizeTemporalImports(graph)` 中按当前
write slot 刷新导入，避免双缓冲 slot 交替后读到旧纹理。

| `velocityReprojectionFollowsARigidObjectAndRejectsAStaticHistoryControl` | 物体每帧 +1 px；velocity = -1/W；末帧误差 < 0.12，且优于同 UV 负对照 25% 以上。 |

## 明确限制与未验证项

1. 首版只绑定 `SsrPass` 输出；没有第二个信号，也没有 GI/云/体积雾复用。不同信号不共享
   本 pass 的颜色/深度/法线/矩历史。
2. 没有光追、路径追踪或真实多次弹射参考；GL 收敛参考是解析 fixture/高样本 SSR 平均，
   不是物理真值。
3. moments 仅维护 luminance mean/mean-square，用作 temporal σ 与空间平坦邻域的 AABB
   扩张；没有逐通道协方差、逐像素方差估计或按方差调整 ray/采样预算，σ 系数固定 2。
4. previous-view-projection 模式只处理相机运动；刚体运动必须提供 velocity + previous
   depth。若错误地省略 velocity，移动物体可能被深度/法线拒绝或在同深度歧义下留下有限拖影；
   GL case 用 velocity 正路径和同 UV 负对照覆盖。
5. 深度/法线沿用共享**单采样几何**表面，不含 normal map 后着色法线；MSAA 时依赖既有的
   surface resolve 视图。透明 VFX/粒子覆盖没有 coverage mask，与 SSR 的已知限制一致。
