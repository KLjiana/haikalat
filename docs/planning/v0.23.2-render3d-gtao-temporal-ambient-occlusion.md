# v0.23.2 Render3D GTAO 与时域环境遮蔽实施计划

> 状态：已完成（M0～M5 主路径、专项回归与正式发布门禁通过）
>
> 目标版本：`0.23.2`
>
> 实施基线：`0.23.1` 发布提交 `4cc6d44`
>
> 版本主题：复用现有 depth、RenderGraph、frame history 和 PBR 间接光基础，建立深度感知、时域稳定且不错误压暗直接光的 GTAO 主路径

## 1. 版本定位

v0.23.0 完成 Render3D 生命周期、透明队列、MSAA depth resolve 和 CSM 加固；v0.23.1 完成多局部光阴影、确定性预算、稳定 atlas 槽位和逐 tile cache。Render3D 当前拥有正确的直接光、阴影和全局 IBL，但缺少由场景几何关系产生的环境遮蔽。墙角、物体接触处、模型凹槽和相互靠近的表面主要依赖资产自带 occlusion map，动态组合场景因此仍可能显得缺少接触感和空间层次。

v0.23.2 选择 GTAO（Ground-Truth Ambient Occlusion）作为唯一主功能。目标不是增加一个简单的“全屏乘黑”滤镜，而是建立以下纵向闭环：

1. 用与当前相机和 TAA jitter 一致的深度预通道获得 GTAO 所需的稳定场景深度。
2. 在半分辨率执行 horizon-based AO 估计，并用深度/法线感知滤波抑制噪声和 halo。
3. 复用现有 temporal history 的事务式生命周期思想，为 AO 建立独立的重投影、拒绝和成功帧提交合同。
4. 让 GTAO 只调制内置 metallic-roughness PBR 的间接光，不压暗直接光、emissive、天空、透明物、VFX 或 UI。
5. 在 NONE/MSAA/FXAA/TAA、HDR、Fog、Bloom、自动曝光、嵌入式目标和 resize 场景下形成一致、可诊断、可验证的正式能力。

本版本继续保持 Forward renderer，不引入 G-buffer、Deferred renderer 或完整 motion-vector 管线。

## 2. 关键架构决策

### 2.1 不采用最终场景颜色整体乘 AO

当前 PBR shader 在 geometry pass 内直接合成：

```text
direct lighting + indirect IBL + emissive
```

如果 geometry pass 完成后再对 `sceneColor` 整体乘 AO，会同时压暗太阳光、点光、聚光阴影外的直接光和 emissive。这会产生错误的能量关系，并导致火焰、灯牌和 Bloom 源在墙角变暗。

v0.23.2 必须在 PBR shader 内执行：

```text
materialAo = mix(1, occlusionTexture, occlusionStrength)
gtao       = sample(screenSpaceAo)
indirect  *= clamp(materialAo * gtao, 0, 1)

final = direct + indirect + emissive
```

直接光与 emissive 不读取 GTAO。透明 PBR 第一版也不读取 GTAO，避免屏幕空间遮蔽与透明排序、折射或多层 alpha 产生错误关系。

### 2.2 采用专用 depth prepass

GTAO 必须在 PBR geometry shading 之前生成，否则本帧 PBR 无法直接采样 AO。当前 geometry depth 只能在 geometry pass 之后读取，因此 v0.23.2 增加显式 `GtaoDepthPrepass`：

- 输出全分辨率单采样 `DEPTH_COMPONENT24` texture。
- 使用与 geometry pass 相同的 jittered projection，保证屏幕像素对齐。
- culling 继续使用稳定、无 jitter 的 frustum，不改变 v0.16 以来的可见性合同。
- 只绘制 `OPAQUE` 和 `MASKED`；`BLEND/ADDITIVE` 不遮挡 GTAO。
- AO occluder 不依赖 `castShadows`，不能错误复用 shadow caster 策略。
- 普通 mesh、instancing、glTF skin 和 morph 都必须使用与 geometry pass 相同的模型/变形快照。
- MASK 使用与 geometry/shadow 一致的 base-color alpha、UV 和 cutoff。

这会增加一次深度提交，但能保持 Forward/PBR 能量关系正确，并避免增加间接光 MRT、自定义 shader draw-buffer 合同或 G-buffer。后续若 RenderGraph 具备安全的跨 pass depth attachment reuse，可以单独评估让 geometry 复用 prepass depth；不作为 v0.23.2 条件。

### 2.3 GTAO 使用独立 temporal history

现有 TAA history 只保存颜色，而且当前 TAA 尚无 per-object motion vector。GTAO 不能复用 TAA 颜色 history，也不能假设相同 UV 即为同一表面。

新增 `GtaoHistory`：

- 维护两个半分辨率 `RG16F` framebuffer，R 保存 AO，G 保存归一化线性深度。
- temporal pass 从 active history 读取，向本帧 RenderGraph target 写入结果，并复制到 candidate history。
- 只有整个 RenderGraph 成功执行后才交换 active/candidate。
- 任一后续 pass 失败时，candidate 被忽略，上一张 active history 继续有效。
- resize 采用 candidate-first 创建两个新 framebuffer，成功后替换旧 generation 并将 history 标记无效。
- GTAO history 与 TAA history 各自拥有有效性、尺寸、代次和 close 生命周期，禁止共享纹理或有效位。

### 2.4 不在本版本引入完整运动矢量

本版本支持静态几何下的相机重投影，但不伪装成完整动态对象重投影：

- 当前深度通过 inverse view-projection 重建世界位置。
- 世界位置通过上一帧 jittered view-projection 投影到 history UV。
- 使用 history 中的线性深度判断 disocclusion。
- camera 平移、旋转和正常 TAA jitter 可以重投影。
- scene membership、transform/model、skin/morph deformation、MASK material/cutoff 或非 revisioned updater 变化时，第一版保守地令本帧 AO history weight 为 0。
- lighting、shadow selection、exposure、Bloom 和普通颜色参数变化不影响 GTAO history。

这个选择优先保证无拖影。其代价是持续动画场景会更多依赖空间滤波；per-object motion vectors 和局部 history rejection 留给独立时域版本。

## 3. 目标数据流

```text
SceneFrame / camera / frozen model snapshots
                    │
                    ▼
             GtaoDepthPrepass
          full-resolution depth texture
                    │
                    ▼
              GtaoEstimatePass
          half-resolution raw visibility
                    │
                    ▼
              GtaoTemporalPass
     current depth + previous AO/depth history
                    │
                    ▼
        GtaoDenoisePass 3x3 + Upsample
          full-resolution AO visibility
                    │
                    ▼
              GeometryPass / PBR
       direct + indirect * materialAO * GTAO
                    │
                    ▼
       MSAA resolve / TAA / Fog / VFX
                    │
                    ▼
       Exposure / Bloom / Tone Mapping / UI
```

推荐稳定 pass 名称：

- `GtaoDepthPrepass`
- `GtaoEstimatePass`
- `GtaoTemporalPass`
- `GtaoDenoiseHorizontalPass`（兼容名称；实现为一次 3×3 深度/法线感知去噪）
- `GtaoUpsamplePass`

这些 pass 只在 GTAO enabled 时存在。disabled 路径不得加载 shader、创建 target、创建 history、增加 draw 或绑定额外 texture。

## 4. 公共配置

### 4.1 `GtaoSettings`

在 `subsystems.postprocess` 增加不可变公共配置：

```java
public record GtaoSettings(
        boolean enabled,
        GtaoQuality quality,
        float radius,
        float strength,
        float thickness,
        boolean temporal,
        float historyWeight,
        float depthRejectionThreshold
) { }
```

建议默认与约束：

| 字段 | 默认 | 合法范围 | 含义 |
| --- | ---: | ---: | --- |
| `enabled` | `false` | boolean | 默认不改变 v0.23.1 pass 和像素 |
| `quality` | `MEDIUM` | enum | 控制 horizon 方向和每方向步数 |
| `radius` | `1.0` | `(0, 100]` | 世界空间遮蔽半径 |
| `strength` | `1.0` | `[0, 4]` | 最终 visibility 对间接光的影响强度 |
| `thickness` | `0.25` | `[0, radius]` | 减轻薄表面过度遮蔽 |
| `temporal` | `true` | boolean | 是否使用独立 AO history |
| `historyWeight` | `0.90` | `[0, 0.98]` | 通过拒绝测试后的最大历史权重 |
| `depthRejectionThreshold` | `0.02` | `(0, 1]` | 归一化线性深度差阈值 |

所有 float 必须有限。`disabled()`、`defaults()` 和 `quality(GtaoQuality)` 工厂必须存在。

### 4.2 `GtaoQuality`

第一版固定三档，避免公共 API 暴露过多 shader 内部参数：

| 质量 | 分辨率 | Horizon 方向 | 每方向步数 | 目标用途 |
| --- | --- | ---: | ---: | --- |
| `LOW` | 1/2 | 2 | 4 | 低成本或大规模场景 |
| `MEDIUM` | 1/2 | 4 | 4 | 默认正式路径 |
| `HIGH` | 1/2 | 6 | 6 | 高质量静态展示 |

三档都使用同一数据模型、时域拒绝和双边滤波，不维护算法不同的兼容实现。第一版不提供 full-resolution 模式，避免 4K 成本和显存不可控。

### 4.3 接入 `PostProcessSettings`

`PostProcessSettings` 增加 `gtao` component 和 builder 方法：

```java
PostProcessSettings.builder()
        .gtao(GtaoSettings.defaults())
        .fog(...)
        .colorGrading(...)
        .build();
```

兼容要求：

- `PostProcessSettings.defaults()` 返回 disabled GTAO。
- 保留现有两参数构造入口，并委托到 `GtaoSettings.disabled()`，维持源码兼容。
- `RenderPipeline.postProcessSettings(...)` 继续是唯一公共接入面，不新增与之重复的 `pipeline.gtao(...)`。
- 公共 API allowlist 和 migration 文档记录 record component 变化。

## 5. RenderGraph 资源与格式

### 5.1 新增 `R8` typed format

AO visibility 只需要 `[0,1]` 单通道。新增 `RenderFormat.R8`，正式映射 `GL_R8`：

- texture sampling 读取 `.r`；
- framebuffer attachment、清理、blit、preview 和估算显存均有测试；
- 不把 R8 误标为 sRGB；
- 不增加无类型 integer format escape hatch。

### 5.2 逻辑资源

建议资源：

| 资源 | 尺寸 | 格式 | 生命周期 |
| --- | --- | --- | --- |
| `gtaoDepth` | 1× | `DEPTH_COMPONENT24` | RenderGraph generation |
| `gtaoRaw` | 1/2× | `R8` | RenderGraph transient |
| `gtaoTemporal` | 1/2× | `RG16F` | RenderGraph transient |
| `gtaoDenoiseB` | 1/2× | `R8` | RenderGraph transient |
| `gtaoFinal` | 1× | `R8` | RenderGraph generation |
| active/candidate history | 1/2× | `RG16F` ×2 | subsystem-owned persistent |

半分辨率 extent 使用 ceil-divide：`(width + 1) / 2`、`(height + 1) / 2`，奇数尺寸不得遗漏最右列或最下行。

### 5.3 Topology

`PipelineTopology` 增加：

- `gtaoEnabled`
- `gtaoHalfWidth`
- `gtaoHalfHeight`

enabled/disabled、窗口 extent 和未来分辨率档变化属于 topology。radius、strength、thickness、history weight、rejection threshold 和 LOW/MEDIUM/HIGH 的循环预算可作为 frame data 更新；如果 shader 变体要求编译期质量常量，则 quality 必须纳入 topology，不能隐式热换 program。

`PipelineFeaturePolicy` 规定：

- GTAO 只对 HDR metallic-roughness PBR 场景提供正式保证。
- GTAO enabled 但场景无 PBR material 时 fail-fast，避免支付无效果成本。
- GTAO 与 NONE/MSAA/FXAA/TAA 均合法。
- GTAO 不依赖 Fog；Fog 开关不应重置 AO history。
- borrowed embedded target 不需要提供可采样 depth，因为 GTAO 使用 subsystem-owned prepass depth。

## 6. Depth prepass 与绘制合同

### 6.1 队列

增加 package-private `GtaoDepthQueue` 或在 `SceneFrame` 中提供明确的 depth-prepass range：

- 包含当前相机可见的 `OPAQUE` 和 `MASKED`。
- 不使用 `castShadows` 过滤。
- 排序优先复用 mesh/material/deformation 状态，减少 program 与纹理切换。
- 与 forward queue 共享冻结的 renderer、model matrix 和 draw binding，不重新执行 updater。
- 透明 alpha/additive、UI、VFX 和 environment background 不进入。

第一版允许从已有 forward queue 的 opaque/masked 连续区间派生，前提是测试锁定队列分类和稳定顺序；不为了命名新增第二份对象列表。

### 6.2 Shader

新增：

- opaque depth prepass vertex/empty fragment；
- masked depth prepass vertex/alpha-cutoff fragment；
- instanced depth prepass variant；
- skin/morph 继续通过现有 `SceneDrawBinding`/SSBO contract 应用。

禁止只绘制未变形 base mesh。GTAO depth、forward depth 和 shadow depth 在相同姿态上必须一致。

### 6.3 Instancing 生命周期

GTAO 开启后实例化 batch 可能在 shadow、depth prepass、geometry 三阶段复用：

- 一帧 transforms 仍只快照和上传一次。
- prepared batch 的 expected-use count 包含实际存在的 pass。
- 最后一次实际 draw 后才插入 fence。
- depth prepass 或 geometry 抛异常时，执行器仍逆序 finish/abort 未完成 batch。
- GTAO disabled 时命令数量和 fence 时机保持 v0.23.1。

## 7. GTAO Estimate

### 7.1 深度重建

- 使用本帧 inverse jittered projection 重建 view-space position，不硬编码 near/far 或假设固定 FOV。
- depth=1/background 直接输出 visibility 1。
- 非有限矩阵、非有限重建坐标或不可逆投影在 frame freeze 阶段 fail-fast，不能把 NaN 写入 AO history。
- ExternalCamera 与普通 Camera 必须走相同矩阵快照。

### 7.2 法线重建

第一版不增加 normal G-buffer。使用 depth 邻域重建 view-space normal：

- 分别比较左右、上下深度差，选择更连续的一侧构造切线。
- 在 depth discontinuity 处限制跨边缘采样。
- normal 必须 normalize，并为退化邻域提供朝向相机的稳定 fallback。
- mirrored transform 不影响屏幕空间重建法线方向。

normal-map 微表面细节不参与 GTAO，这是有意限制；GTAO 表达几何尺度遮蔽，材质 occlusion map 继续表达烘焙微观细节。

### 7.3 Horizon search

- 每个像素按 quality 选择固定方向数和步数。
- 每帧用确定性的 interleaved gradient rotation 改变采样方向；不引入外部噪声资产。
- temporal disabled 时使用稳定 frame phase，避免无 history 条件下整幅噪声逐帧闪动。
- sample radius 从世界空间 `radius` 转换到屏幕尺度，并随 view depth 衰减。
- thickness 补偿降低薄墙背面和近邻断层造成的过度遮蔽。
- 距离 falloff 使半径边缘连续归零。
- 输出是 visibility：1 表示无遮蔽，0 表示完全遮蔽。
- 所有循环严格有界，不允许由用户输入直接控制任意步数。

## 8. Temporal resolve

### 8.1 重投影

每个 half-resolution 像素：

1. 从当前 GTAO depth 重建世界位置。
2. 使用上一成功帧 jittered view-projection 得到 previous UV。
3. previous UV 越界、w 非正或非有限时拒绝 history。
4. 比较当前表面投影到上一帧的预期线性深度与 history G 通道。
5. 深度差超过阈值时视为 disocclusion，history weight 为 0。
6. 通过后对 current/history visibility 做 bounded blend。
7. 输出新的 AO 和当前归一化线性深度。

history AO 在混合前必须 clamp 到当前 3×3 邻域的 min/max，防止稳定但错误的暗斑长期保留。

### 8.2 History invalidation

以下情况完整失效：

- 第一个有效帧；
- resize、最小化恢复或 half extent 变化；
- pipeline generation 替换；
- scene generation 或 membership 变化；
- camera cut、投影类型/FOV/near/far 的不连续变化；
- transform/model、skin/morph deformation、MASK alpha/cutoff 或非 revisioned updater 变化；
- GTAO radius、thickness、quality 或 temporal 模式变化；
- 上一帧 RenderGraph 执行失败；
- history framebuffer 创建/复制失败。

以下变化不应失效：

- 仅 lighting/shadow selection 变化；
- shadow tile 重画；
- exposure、Bloom、LUT、Fog 参数变化；
- UI/VFX 更新；
- 只有 TAA phase 前进，且当前/上一 jitter matrix 都有效。

### 8.3 Camera cut

除显式 pipeline/scene generation 变化外，内部检测：

- view matrix 平移或旋转超过受控阈值；
- projection matrix 非连续变化；
- previous matrix 不可逆或不有限。

普通相机移动不能被误判为 cut，否则 temporal GTAO 将失去价值。诊断必须区分 `CAMERA_REPROJECTED` 和 `CAMERA_CUT_RESET`。

## 9. 双边去噪与上采样

- 横向和纵向 pass 使用固定小半径 kernel。
- weight 同时考虑像素距离、线性深度差和重建法线夹角。
- 不跨明显 silhouette 混合，避免物体边缘出现黑色 halo。
- full-resolution upsample 从四个 half-resolution 邻居中按 depth/normal 一致性选择或加权。
- background 输出 1，不把天空或 environment background 压暗。
- radius 很小或 strength=0 时仍产生有限输出；strength=0 的最终视觉必须等同 disabled，但允许 diagnostics 显示 pass 仍启用。

## 10. PBR 集成

### 10.1 Texture unit

建议保留 fragment texture unit 13 给 GTAO：

- 0～6：PBR material textures；
- 7：directional shadow；
- 8～10：IBL；
- 11～12：point/spot shadow；
- 13：GTAO visibility。

OpenGL 4.6 contract 下该容量合法，但仍需在 capability 测试和 frame-owned texture-unit guard 中锁定。材质不得覆盖 unit 13。

### 10.2 Shader 变体

- `pbr-forward.frag` 和 `pbr-forward-shadow-budget.frag` 都接入同一 GTAO include/函数合同。
- GTAO disabled 的默认 shader 路径不得额外采样 texture。
- 可以使用 `uGtaoEnabled` 的同一程序，也可以在 generation 中选择明确变体；选择后必须由 benchmark 证明 disabled 路径没有可测回退。
- screen UV 由 `gl_FragCoord` 和冻结的 target extent 得到，不使用 mesh UV。
- `MASK` 正常接收 GTAO。
- `BLEND` 第一版强制 GTAO visibility=1。
- material occlusion map 与 GTAO 相乘后 clamp 到 `[0,1]`。
- direct、emissive 和 alpha 不受 GTAO 影响。
- diffuse/specular IBL 继续沿用当前统一 material AO 行为，v0.23.2 不顺带引入新的 specular-occlusion BRDF 模型。

### 10.3 自定义 shader

正式保证只覆盖内置 metallic-roughness PBR shader contract：

- frame-owned uniform/texture 集合增加 GTAO 名称与 unit 13。
- 遵循内置合同的自定义 PBR shader 可以主动采样 GTAO。
- 未声明 GTAO uniform 的 shader通过 `trySet` 保持可运行，但不会自动获得 AO。
- 不允许 RenderPipeline 猜测任意自定义 shader 中“哪一段是间接光”。

## 11. 与其他功能的组合

### 11.1 Anti-aliasing

- NONE：GTAO 完成后进入普通 geometry 和 present。
- MSAA：GTAO 使用单采样专用 depth prepass；PBR MSAA geometry 的每个 sample读取相同 full-resolution AO。原有 color/depth resolve 合同保持。
- FXAA：GTAO 在 HDR PBR geometry 前完成，FXAA 仍位于 tone mapping 后。
- TAA：AO 自己先完成 temporal resolve；PBR geometry 合成后再进入现有 color TAA。两套 history 分离。

### 11.2 Fog、Bloom 与曝光

- GTAO 在 PBR indirect lighting 阶段生效，Fog 后续覆盖远景，顺序自然。
- Bloom 只看到已经合成 GTAO 的 HDR scene；emissive 未被 GTAO 压暗。
- 自动曝光读取 GTAO 合成后的场景亮度，这是预期行为，因为环境遮蔽改变真实间接亮度。
- UI 位于全部 scene postprocess 之后，不读取 GTAO。
- HDR VFX 保持在现有合成位置，不遮挡也不接收 GTAO。

### 11.3 Embedded rendering

- GTAO 使用 subsystem-owned depth，不要求宿主 depth 可采样。
- presentation target replacement 只影响最终目标和 window-relative resources。
- zero extent 不执行 candidate resize；恢复后重建 GTAO generation 并清空 history。
- borrowed target 仍不由 GTAO close。

## 12. 生命周期与失败恢复

- `GtaoPass` shader、sampler、history 和 graph targets 由当前 `PipelineGeneration` 或明确 owned component 持有。
- build 采用 candidate-first；任一 shader、R8 texture、history framebuffer 或 FBO completeness 失败时释放 candidate，旧 generation 继续可用。
- resize 先创建完整的新 graph/history，再替换；旧 generation 不提前关闭。
- frame 执行失败不交换 GTAO history index，也不更新 previous successful view-projection。
- history copy 失败使 candidate invalid，下一帧 history weight 为 0。
- `RenderPipeline.close()` 重复调用安全；两个 history framebuffer、pass program 和 targets 只释放一次。
- partial construction 按逆序清理，tracked GL resource 回到基线。
- GL debug label 包含 GTAO pass、history index、extent 和 generation。

## 13. 诊断与资源预览

`Render3dDiagnostics` 增加 `AmbientOcclusionSummary`：

- enabled/disabled 和 disabled reason；
- quality、radius、strength、thickness；
- full/half extent；
- temporal enabled、history valid、accepted/rejected sample 计数或估算比例；
- history reset reason；
- depth-prepass opaque/masked/instanced draw 数；
- estimate directions/steps；
- AO GPU pass 总时间与各 pass 时间；
- 当前/峰值估算显存；
- pipeline generation 和 history generation。

history reset 只在原因变化或 debug snapshot 请求时输出，不能逐帧刷日志。

RenderGraph preview 增加：

- GTAO depth；
- raw visibility；
- temporal visibility；
- denoised half-resolution visibility；
- final full-resolution visibility。

R8 以线性灰度显示，1 为白、0 为黑；depth 使用现有深度预览映射。preview 不改变 history、frame plan 或资源生命周期。

## 16. 性能与显存门槛

### 16.1 Disabled 回归

- 相同 v0.23.1 场景下 CPU/GPU 中位数回退不超过 2%。
- pass、draw、texture binding、history、tracked resource 和 per-frame allocation 数量不增加。
- PBR shader 若复用同一 program，必须证明 disabled 分支未产生可测 texture sample 成本；否则使用 generation 变体。

### 16.2 Enabled 预算

先用 M0 同机五轮数据建立基线，再锁定正式 gate。RTX 3050 Laptop 参考目标：

- MEDIUM、1080p：GTAO 全链 GPU 中位数不超过 2.0 ms。
- MEDIUM、4K：GTAO 全链 GPU 中位数不超过 4.0 ms。
- CPU frame 中位数增量不超过 0.35 ms，不包含场景本来已有的动画更新。
- 预热后 GTAO 自身无随帧增长的 Java/native allocation。
- static camera temporal 段不重建 target/history。
- depth prepass 对 instancing 复用同一帧上传，不新增实例矩阵副本。

若代表硬件未满足参考目标，优先调整 sample budget、denoise tap 和 pass 合并；不得用关闭 depth rejection、扩大 history weight 或整体压暗画面伪造质量/性能结果。

### 16.3 显存报告

性能报告必须记录每个 GTAO target 的实际格式、extent、数量和估算字节。4K 不允许悄然创建 full-resolution RGBA16F AO target。资源估值必须进入 diagnostics 和 release report。

## 18. 明确限制与后续接口

v0.23.2 正式声明：

- GTAO 是屏幕空间近似，看不到屏幕外遮挡物。
- 不生成 bent normal，不用于方向性 diffuse IBL。
- 不读取 normal map；几何法线由 depth 重建。
- 透明物不遮挡也不接收 GTAO。
- 动态对象没有 per-object motion vector，发生几何变化时保守 reset 全局 AO history。
- 不做 multi-bounce AO、ray-traced AO、SSGI 或 reflection occlusion。
- 不复用 geometry depth，因此 enabled 时有一次额外 depth prepass。
- 自定义 shader 只有遵循 GTAO texture contract 才能接收 AO。

v0.23.2 完成后，优先根据数据选择后续方向：

1. 若动画场景 temporal reset 过于频繁，v0.24 优先实现 motion vectors 和局部 history rejection。
2. 若 depth prepass 成本成为主要瓶颈，再设计 RenderGraph depth attachment reuse 或 depth-equal geometry 路径。
3. 若 AO 已稳定但室内反射仍不可信，再实现局部 reflection probes。
4. 不因已有 depth/history 就顺带启动 SSR、SSGI 或 Deferred renderer。

## 19. 完成定义

只有同时满足以下条件，才能把 v0.23.2 标记为正式版：

1. GTAO disabled 与 v0.23.1 的 pass、像素、资源和性能保持兼容。
2. GTAO enabled 在墙角、接触和凹陷场景产生稳定、有限、可解释的环境遮蔽。
3. AO 只影响 PBR indirect IBL，不影响 direct、emissive、sky、BLEND、VFX 和 UI。
4. OPAQUE/MASK、instancing、skin 和 morph 的 prepass depth 与 geometry 对齐。
5. 空间滤波和上采样不跨 silhouette 产生明显 halo。
6. 静态几何下相机重投影正确；disocclusion、camera cut、动态几何和失败帧不复用错误 history。
7. NONE/MSAA/FXAA/TAA、Fog、Bloom、曝光、resize 和 embedded 组合全部通过。
8. candidate-first、成功帧 history commit、异常清理和重复 close 合同成立。
9. disabled/1080p/4K 性能与显存门槛通过，预热后无增长型 allocation。
10. GL 日志无未授权 HIGH/MEDIUM 和 error，人工视觉复核通过。
11. capability matrix、guide、testing、performance、changelog、release report 和版本号与实现一致。
