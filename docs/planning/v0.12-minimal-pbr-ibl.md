# v0.12 Minimal PBR / IBL 实施计划

> 已归档：v0.12 历史实施与验收记录，不再作为当前待办。

> 状态：已完成，进入 `0.12.0` 发布提交（2026-07-18）
> 目标版本：`0.12.0`  
> 基线版本：`0.11.0`  
> 方向：方案四——最小现代材质闭环  
> 核心原则：先建立一条可验证、可维护的 metallic-roughness PBR 主路径，不建设完整材质平台。

## 1. 版本目标

### RC 前加固结果

- environment 预计算统一通过调用方 `RenderDevice` 提交，并在删除临时 shader、sampler、texture 后失效活动状态缓存；真实 GL 测试覆盖预热缓存后加载 environment 并继续绘制。
- Demo GPU mesh 按 model reference 与 material model 缓存独立 variant，消除 legacy/PBR 共享模型的 layout 污染和遍历顺序依赖。
- `RenderPipeline.build()` 对每个 PBR renderer 强制校验 canonical POSITION/TEXCOORD_0/NORMAL/TANGENT location、类型和分量数。
- PBR point/spot light 使用 `rangeWindow² / max(distance², epsilon)`，legacy 衰减保持不变。
- environment cube、prefilter mip、BRDF LUT 三阶段故障注入均验证逆序单次清理；cleanup 异常保留为 suppressed，Demo 不再吞掉关闭失败。

v0.12 的目标不是“拥有一个名字叫 PBR 的 shader”，而是把现代材质渲染所需的纵向链路完整接入现有框架：

1. 资产配置能够明确表达 PBR 材质语义；
2. 模型能够提供可靠的 tangent frame；
3. OpenGL backend 能类型化管理 HDR 纹理和 cubemap；
4. 环境贴图能够在 GPU 上预计算为漫反射与镜面 IBL 数据；
5. Forward pipeline 能同时渲染 legacy 材质和 PBR 材质；
6. PBR 输出正确进入现有 HDR、自动曝光、Bloom、抗锯齿和 UI 链路；
7. Demo、自动化测试、资源生命周期测试和性能基线能够证明以上能力。

完成后，项目应具备以下稳定能力：

- opaque metallic-roughness 材质；
- base color、normal、metallic-roughness、occlusion、emissive 纹理；
- Cook–Torrance GGX 直接光照；
- 基于 HDR 环境的 diffuse irradiance、prefiltered specular 和 BRDF LUT；
- 环境背景渲染；
- PBR 与阴影、HDR/ACES、GPU 自动曝光、Bloom 和 v0.11 UI 的协同；
- legacy Blinn–Phong 材质保持兼容。

## 2. 为什么现在适合做

v0.11 之后，PBR 所依赖的外围链路已经足够稳定：

- RenderGraph 已经能够组织多 pass 和重建窗口相关资源；
- HDR/ACES、Bloom 和 GPU 自动曝光已经形成闭环；
- 直接光照、方向光阴影、模型加载和材质实例已经存在；
- UI subsystem 可以承担 PBR 参数调试面板，而不需要临时接入第三方 GUI；
- GL 资源生命周期、command recording 和集成验证已经有明确约束。

当前短板集中在材质输入、切线空间、cubemap 和 IBL 预计算，属于一条可控的纵向能力扩展。此时开始最小 PBR，收益明显且不需要推翻现有 pipeline。

## 3. 当前实现约束

实施必须以当前代码事实为边界：

- `Material` 是通用 shader、texture binding 和 uniform defaults 的运行时对象；
- `MaterialInstance` 提供逐对象覆盖，不应被替换为 PBR 专用对象；
- `MaterialDef` 和 `SceneAssetConfig` 尚无材质模型和 PBR 纹理角色；
- `VertexLayout` 只有 attribute location，没有 position/UV/normal/tangent 语义；
- 现有 mesh attribute `0..2`，实例矩阵从 location `3` 开始；
- tangent 需要占用一个 `vec4` attribute，直接使用 location `3` 会与实例数据冲突；
- backend 只有 `Texture2D`，没有 cubemap、HDR 浮点图片加载和 cube image binding；
- `CommandBuffer` 只有 2D texture binding；
- shadow map 当前固定使用 texture unit `7`；
- geometry target 已经是 `RGBA16F`，ACES、Bloom 和自动曝光能够消费线性 HDR 颜色；
- legacy light intensity 不是物理单位，不能在 v0.12 宣称 photometric lighting。

因此，v0.12 需要扩展现有抽象，但不得用 PBR 名义重写 `Material`、`Scene`、`RenderPipeline` 或 RenderGraph。

## 4. 范围与非目标

### 4.1 正式范围

- metallic-roughness 工作流；
- opaque PBR 材质；
- tangent-space normal mapping；
- directional、point、spot light 的 PBR 直接光照；
- 现有方向光 shadow map；
- 单一全局 HDR environment；
- diffuse irradiance cubemap；
- GGX prefiltered specular cubemap；
- split-sum BRDF LUT；
- 可选环境背景；
- PBR 参数的 retained-mode UI 调试面板；
- OBJ 主路径 tangent 生成；
- dedicated PBR demo 和主 Demo 中的最小证明对象；
- deterministic integration 和 GL smoke 验收。

### 4.2 明确非目标

v0.12 不实现：

- glTF 资产管线；
- specular-glossiness 工作流；
- PBR alpha blend、折射或 transmission；
- clearcoat、sheen、anisotropy、subsurface、iridescence；
- area light、LTC、IES 或真实光度学单位；
- deferred rendering、clustered/forward+ lighting；
- local reflection probe、probe blending 或运行时 probe capture；
- screen-space reflection、ray tracing；
- bindless texture、texture array 材质系统；
- 自动从 Assimp 材质提取完整 PBR 数据；
- shader graph、材质编辑器或通用 AssetRegistry 2.0；
- PBR instancing 的正式承诺。

最后一项尤其重要：v0.12 必须消除 tangent attribute 与 instance matrix 的静默冲突，但可以把“PBR mesh 实例化”留到后续版本。

## 5. 总体设计

```text
HDR equirectangular image
          |
          v
  GPU environment preprocessing
      |          |           |
      v          v           v
 irradiance   prefiltered   BRDF LUT
 cubemap      specular cube Texture2D
      \          |           /
       \         |          /
        +------ PBR binder ------+
                 |
mesh + tangent -> PBR material -> forward geometry
                 |
                 v
          RGBA16F scene color
                 |
       auto exposure / Bloom / ACES
                 |
                 v
             UI overlay
```

主要设计决策如下：

1. 保留 `Material`/`MaterialInstance` 作为统一运行时材质容器；PBR 只增加配置语义和固定 binding contract。
2. PBR 与 legacy shader 可在同一 scene 中共存，由 material model 选择 binder/shader contract。
3. cubemap 是 backend 的真实资源类型，不伪装成六张无关联的 `Texture2D`。
4. IBL 预计算全部在 GPU 完成，生产路径不做 CPU readback。
5. environment 是 pipeline 借用的显式 GL 资源，不塞进 `RenderSettings`。
6. HDR/ACES 是 v0.12 PBR 正式路径的前置条件；不承诺 LDR PBR 的视觉结果。
7. 第一版只有一个 opaque PBR shader variant，避免 shader permutation 提前膨胀。

## 6. 材质模型与配置协议

### 6.1 新增材质模型

新增：

```java
public enum MaterialModel {
    LEGACY,
    METALLIC_ROUGHNESS
}
```

`MaterialDef` 增加 material model 和可选的 PBR properties。旧配置缺少 `model` 时必须默认 `LEGACY`，旧场景不需要迁移。

推荐新增不可变值对象：

```java
public record PbrMaterialProperties(
        Vector4f baseColorFactor,
        float metallicFactor,
        float roughnessFactor,
        float normalScale,
        float occlusionStrength,
        Vector3f emissiveFactor,
        Map<PbrTextureRole, String> textures
) {}
```

对外暴露时，向量必须 defensive copy，map 必须不可变。`MaterialDef` 保留原四参数兼容构造器，并令其产生 `LEGACY` 定义，避免无意义地破坏现有调用点。

### 6.2 固定参数语义

| 参数 | 默认值 | 合法范围 | shader 含义 |
| --- | --- | --- | --- |
| `baseColorFactor` | `(1,1,1,1)` | 每分量 `0..1` | 与 base-color texture 相乘 |
| `metallicFactor` | `0` | `0..1` | 与 metallic channel 相乘 |
| `roughnessFactor` | `1` | `0..1` | 与 roughness channel 相乘 |
| `normalScale` | `1` | `>= 0` | tangent-space XY 强度 |
| `occlusionStrength` | `1` | `0..1` | AO 对间接光的影响强度 |
| `emissiveFactor` | `(0,0,0)` | 每分量 `>= 0` 且有限 | 线性 HDR 自发光倍率 |

配置解析阶段拒绝 NaN、Infinity 和越界值。roughness 允许配置为 `0`，shader 内部对参与分布计算的值 clamp 到安全下限，避免除零和 firefly。

### 6.3 固定纹理角色

新增 `PbrTextureRole`：

- `BASE_COLOR`：sRGB，采样后转线性；
- `NORMAL`：linear，RGB tangent-space normal；
- `METALLIC_ROUGHNESS`：linear，G=roughness、B=metallic；
- `OCCLUSION`：linear，R=occlusion；
- `EMISSIVE`：sRGB，采样后转线性。

颜色空间由角色强制约束：

- base color/emissive 引用 LINEAR texture 配置时解析失败；
- normal/metallic-roughness/occlusion 引用 SRGB texture 配置时解析失败；
- 错误必须包含 material key、texture role、texture name 和实际 color space。

缺省纹理不通过分支处理，而由 subsystem 提供共享 1×1 fallback textures：

- 白色 base color；
- `(0.5, 0.5, 1.0)` flat normal；
- G=1、B=0 的 dielectric rough surface；
- 白色 occlusion；
- 黑色 emissive。

fallback 纹理由一个明确 owner 统一创建和关闭，material 只借用。

### 6.4 manifest 格式

在现有 `.properties` 格式上增加：

```properties
material.rustedIron.model=metallicRoughness
material.rustedIron.shader=pbrForward
material.rustedIron.blend=opaque
material.rustedIron.depthTest=true

material.rustedIron.pbr.baseColorFactor=1.0,1.0,1.0,1.0
material.rustedIron.pbr.metallicFactor=1.0
material.rustedIron.pbr.roughnessFactor=1.0
material.rustedIron.pbr.normalScale=1.0
material.rustedIron.pbr.occlusionStrength=1.0
material.rustedIron.pbr.emissiveFactor=0.0,0.0,0.0

material.rustedIron.pbr.baseColorTexture=rustedIronBaseColor
material.rustedIron.pbr.normalTexture=rustedIronNormal
material.rustedIron.pbr.metallicRoughnessTexture=rustedIronMetalRough
material.rustedIron.pbr.occlusionTexture=rustedIronAo
material.rustedIron.pbr.emissiveTexture=rustedIronEmissive
```

规则：

- `model=metallicRoughness` 只允许 `blend=opaque`；
- PBR material 必须引用 PBR contract shader；
- role texture 字段只能出现在 PBR material；
- 引用缺失 texture 时在配置解析后失败；
- 未配置某个 role 时使用 fallback；
- 不允许同时使用 role key 和通用 sampler key 覆盖 PBR 固定纹理单元；
- unknown `material.*.pbr.*` key 失败，避免拼写错误静默回退。

### 6.5 固定纹理单元合同

| Unit | 用途 |
| ---: | --- |
| 0 | base color |
| 1 | normal |
| 2 | metallic-roughness |
| 3 | occlusion |
| 4 | emissive |
| 7 | 现有 directional shadow map |
| 8 | irradiance cubemap |
| 9 | prefiltered specular cubemap |
| 10 | BRDF LUT |

unit 5、6 保留。environment source texture 只在预计算阶段使用，不占逐帧 contract。

初始化时检查 fragment texture unit 数量是否满足最高使用单元；不足时给出 capability error，不允许得到黑屏后再排查。

## 7. 顶点语义与 tangent 生成

### 7.1 顶点语义

当前 `VertexLayout` 只有 location，纯 JVM 代码无法可靠识别 position、UV 和 normal。v0.12 新增：

```java
public enum VertexSemantic {
    POSITION,
    TEXCOORD_0,
    NORMAL,
    TANGENT,
    COLOR_0,
    CUSTOM
}
```

`VertexAttribute` 增加 semantic，旧 builder 未填写时默认 `CUSTOM`。`VertexLayout` 提供：

- `Optional<VertexAttribute> attribute(VertexSemantic semantic)`；
- 同一非 `CUSTOM` semantic 唯一性验证；
- attribute 范围不超过 stride 的验证；
- location 唯一性验证。

所有内建 layout 和 OBJ 输出 layout 补齐 semantic。backend 仍然只按 location 绑定，semantic 不渗入 GL 调用。

### 7.2 PBR canonical layout

定义 PBR canonical layout：

| Location | Semantic | 类型 |
| ---: | --- | --- |
| 0 | position | `vec3` |
| 1 | texcoord0 | `vec2` |
| 2 | normal | `vec3` |
| 3 | tangent | `vec4` |

tangent.xyz 是单位 tangent，tangent.w 是 bitangent handedness。shader 中：

```glsl
T = normalize(T - N * dot(N, T));
B = cross(N, T) * tangent.w;
```

normal matrix 必须用于 normal/tangent，以支持 non-uniform scale。不得直接用 model matrix 的 `mat3` 代替 inverse-transpose normal matrix。

### 7.3 与 instancing 的冲突处理

现有 instance matrix 从 location `3` 开始，会占用 `3..6`。实施时必须：

1. 将 instance attribute base 从隐含常量升级为 mesh/layout-aware 参数；
2. legacy layout 继续使用 base `3`；
3. tangent layout 若支持 instancing，应使用 base `4`，占用 `4..7`；
4. VAO 配置必须验证 vertex attribute 和 instance attribute 不重叠；
5. 若 v0.12 不实现 PBR instancing，提交 tangent mesh 到 `InstancedMeshBatch` 时必须立即抛出清晰异常。

不得通过移动所有 legacy attribute location 破坏既有 shader，也不得让冲突产生不可预测画面。

### 7.4 TangentGenerator

新增纯 JVM `TangentGenerator`，输入 `MeshData`，输出带 tangent 的新 `MeshData`。算法要求：

1. 通过 semantic 查找 position、UV、normal；
2. 只接受 `GL_FLOAT`、divisor 0 和预期分量数；
3. 按 indexed triangle 累加 tangent/bitangent；非 indexed mesh 按连续三角形处理；
4. 对 tangent 做 Gram–Schmidt 正交化；
5. 从累计 bitangent 计算 handedness；
6. 输出值必须全部 finite；
7. 不修改输入数组；
8. 保留 name 和 indices；
9. 重复处理已有 tangent 的 mesh 时拒绝或显式 no-op，行为固定并有测试。

退化 UV triangle 不能生成 NaN。此时使用由 normal 构造的确定性正交 tangent，并在生成统计中记录 fallback triangle 数。日志按 mesh 汇总，不逐 triangle 打印。

OBJ loader 不应无条件改变旧输出 layout。新增 load option 或 PBR asset assembly step，仅当 mesh 被 PBR material 使用时生成 tangent。

## 8. Backend：HDR texture 与 cubemap

### 8.1 HDR 2D texture

为 environment source 增加 float image loading：

- 使用 STB `stbi_loadf_from_memory`；
- 输入只允许 linear color；
- 明确 flip policy，不依赖全局 STB 状态；
- 上传到 `RGB16F` 或 `RGBA16F`；
- loader 失败时错误包含 resource path 和 STB reason；
- native buffer 在成功和异常路径都释放；
- GL texture 创建失败时清理已分配对象。

可以扩展 `Texture2D` factory，也可以增加职责单一的 HDR loader；不得新增与 `Texture2D` 生命周期重复的平行通用纹理体系。

### 8.2 TextureCube

新增 `TextureCube implements GlResource`，至少支持：

- square size；
- mip level count；
- `RGBA16F` environment/irradiance/prefilter storage；
- immutable storage；
- sampler wrap/filter；
- debug label；
- 幂等 close；
- close 后使用失败；
- owner-thread/context 约束与 `Texture2D` 一致。

构造时验证 size、mip count 和 format。prefilter cubemap 的 mip 数不超过 `floor(log2(size)) + 1`。

### 8.3 RenderFormat

至少补齐 BRDF LUT 所需的 `RG16F`。若 cubemap 使用现有 `RGBA16F`，不为节省一个 channel 提前引入 `RGB16F` render target；只有 storage/API 确有需要时再增加。

每个 format 的 internal format、upload format、type 和 image binding compatibility 必须集中映射，不在多处 switch 复制。

### 8.4 类型化命令

`CommandBuffer` 增加类型化操作：

```java
bindTextureCube(int unit, TextureCube texture, Sampler sampler)
bindImage(TextureCube texture, int unit, int mipLevel,
          ImageAccess access, RenderFormat format)
```

cube image binding 必须以 layered 方式覆盖六个 face。命令录制保持资源引用稳定，执行前进行 close/context 验证。

同时扩展：

- opcode；
- command arena 编码/解码；
- executor；
- state cache；
- debug validation；
- command buffer reset/close 测试。

不得使用 `custom()` 承担生产 cubemap binding 或 preprocessing。现有 profiling allowlist 不扩大。

### 8.5 StateCache

texture cache key 必须包含 unit 和 target。相同 unit 从 2D 切换到 cube 时必须真正 bind；重复 cube bind 应被跳过。

测试至少覆盖：

- 2D → cube；
- cube → 2D；
- 同 cube 重复 bind；
- sampler 改变；
- close 后引用；
- command buffer replay 后 cache reset。

## 9. GPU environment 预计算

### 9.1 资源对象

新增显式资源：

```java
public final class PbrEnvironment implements AutoCloseable {
    TextureCube irradiance();
    TextureCube prefilteredSpecular();
    Texture2D brdfLut();
    float intensity();
    float rotationRadians();
}
```

实际公开面可进一步收窄，但必须满足：

- resource ownership 清晰；
- pipeline 借用，不负责关闭；
- loader/preprocessor 中途失败关闭已创建资源；
- close 逆序、幂等；
- resize 不重建 environment；
- environment replacement 只能在 render thread 安全点发生。

`RenderSettings` 只存纯配置，不拥有 `PbrEnvironment`。

### 9.2 预计算步骤

推荐使用 compute shader，步骤固定为：

1. equirectangular HDR → environment cubemap；
2. environment cubemap → diffuse irradiance cubemap；
3. environment cubemap → GGX prefiltered specular mip chain；
4. 生成 2D split-sum BRDF LUT。

compute dispatch 的 Z 维覆盖六个 cube face。每个阶段之间插入精确的 image access/texture fetch barrier，不使用 `glFinish()`。

prefilter 每个 mip 单独 dispatch：

- mip 0 roughness = 0；
- 最后一个 mip roughness = 1；
- 中间线性映射；
- sample count 使用固定常量并在 shader 注释说明质量/成本；
- mip 尺寸最小为 1；
- 禁止写出 NaN/Infinity。

### 9.3 默认尺寸

首版建议：

| 资源 | 默认尺寸 | Mip |
| --- | ---: | ---: |
| environment cube | 512×512/face | 完整 mip chain |
| irradiance cube | 32×32/face | 1 |
| prefiltered specular | 128×128/face | 5 或完整受控链 |
| BRDF LUT | 256×256 | 1 |

尺寸通过 `PbrEnvironmentSettings` 配置并严格验证。Demo 可提供较低 quality preset 供集成测试使用；生产默认和测试默认不得混淆。

### 9.4 缓存策略

v0.12 不实现磁盘缓存。单次进程中：

- 同一 environment descriptor 可以由 manager 复用；
- 构建必须发生在 GL context/render thread；
- BRDF LUT 可在同一 manager 中共享；
- owner 引用关系必须防止提前释放；
- 没有真实复用需求时，优先单 owner，不引入引用计数框架。

### 9.5 环境资产

仓库必须包含一个可再分发、来源明确的轻量 HDR 基准环境。优先使用项目自行生成的确定性 HDR environment；若采用 CC0 HDRI，必须记录：

- 原始来源 URL；
- 作者/站点；
- license；
- 下载日期；
- 文件 hash；
- 是否缩放或转码。

测试不能依赖网络下载或用户本地路径。

## 10. PBR shader 合同

### 10.1 直接光照 BRDF

opaque PBR shader 使用 Cook–Torrance metallic-roughness：

- GGX/Trowbridge–Reitz normal distribution；
- Smith visibility/masking；
- Schlick Fresnel；
- `F0 = mix(vec3(0.04), baseColor, metallic)`；
- diffuse 为 Lambert；
- metallic 部分不贡献 diffuse；
- 所有中间 denominator 有 epsilon；
- `NdotL`、`NdotV` 等进行安全 clamp。

每盏光的结果结构为：

```text
(diffuseBRDF + specularBRDF) * radiance * NdotL * visibility
```

directional shadow 只衰减直接光，不衰减 IBL 和 emissive。

### 10.2 光强和衰减

v0.12 保留现有 light 数据结构，但 PBR shader 明确把 intensity 当作“框架标量 radiance”，不宣称 lumen/lux/candela。

point/spot light 使用带 range 的稳定 inverse-square falloff：

```text
smooth = clamp(1 - (distance / range)^4, 0, 1)^2
attenuation = smooth / max(distance^2, epsilon)
```

legacy shader 的旧衰减保持不变，避免改变现有 Demo 基线。PBR Demo 的 light intensity 单独调校。

### 10.3 Normal mapping

normal texture 解码为 `[-1, 1]`，XY 乘 `normalScale` 后重新归一化。TBN 必须：

- 使用 world-space normal/tangent；
- normal matrix 处理 non-uniform scaling；
- tangent 对 normal 重新正交化；
- tangent.w 恢复 bitangent handedness；
- backface/degenerate 输入不产生 NaN。

### 10.4 IBL

间接光使用 split-sum approximation：

- diffuse：irradiance × base color；
- specular：prefiltered cubemap 按 roughness 选 LOD，再乘 BRDF LUT；
- Fresnel 使用 roughness-aware 版本；
- AO 影响 indirect diffuse/specular，不影响 direct lighting 和 emissive；
- environment intensity 在线性空间相乘；
- environment rotation 同时影响背景和反射采样方向。

第一版不加入 multi-scattering compensation，除非参考图证明单散射能量损失已严重影响验收；若加入，必须有独立公式测试和文档说明。

### 10.5 Shader uniform/binding contract

推荐统一前缀：

```text
uPbr.baseColorFactor
uPbr.metallicFactor
uPbr.roughnessFactor
uPbr.normalScale
uPbr.occlusionStrength
uPbr.emissiveFactor
uEnvironmentIntensity
uEnvironmentRotation
uPrefilterMaxLod
```

若现有 uniform value 系统不支持 `vec4`，应增加正式 `Vec4UniformValue` 和 builder API，不允许把 base color factor 拆成命名不一致的零散 float。

## 11. Pipeline 集成

### 11.1 与现有材质共存

`RenderPipeline` 保持一条 geometry pass：

- legacy material 继续走现有 binder；
- PBR material 走 `PbrMaterialBinder`；
- lighting 数据继续由现有 `LightingBinder` 提供；
- IBL 资源由单独的 `PbrEnvironmentBinder` 提供；
- material/model 类型不通过 `instanceof` 链扩散到各 pass。

推荐由 material metadata 或预构建的 renderer binding plan 决定 binder，避免每 draw 解析 manifest。

### 11.2 HDR 前置条件

PBR 正式路径要求：

- geometry color target 为 `RGBA16F`；
- tone mapping 为 ACES；
- shader 输出线性 HDR；
- texture color space 按角色正确解码。

scene/pipeline 构建时若存在 PBR material 但 HDR/ACES 未开启，应抛出包含 renderer/material 名称的配置异常。此约束未来可以放宽，但 v0.12 不接受“能画出来但颜色链不确定”的模式。

Bloom 可开关；自动曝光可开关；PBR 两种情况下都必须正确。

### 11.3 环境背景

增加可选 environment background：

- 在 HDR geometry target 中绘制；
- 使用 cubemap 原始环境或其适当 LOD；
- camera translation 不影响背景；
- camera rotation 正确影响视图；
- environment rotation 与 IBL 一致；
- 不写 depth，且不覆盖已有 geometry；
- 输出 linear HDR，由 exposure/Bloom/ACES 统一处理。

实现可以是 fullscreen triangle 重建 view direction，或 cube mesh；首选 fullscreen triangle，减少额外 mesh 生命周期。

### 11.4 后处理和 UI

链路必须保持：

```text
PBR/legacy geometry + environment
  -> HDR scene color
  -> auto exposure metering/adaptation
  -> Bloom
  -> ACES output transform
  -> UI overlay
```

UI 仍在 tone mapping 后绘制，不进入自动曝光统计，也不被 Bloom。PBR 调试面板只修改下一帧 snapshot，不允许在 UI callback 中直接调用 GL。

### 11.5 Resize

窗口 resize 只重建窗口相关 RenderGraph targets。以下资源必须保持 identity 不变：

- environment cubemap；
- irradiance cubemap；
- prefiltered specular cubemap；
- BRDF LUT；
- material textures。

测试应记录 GL object id 或 wrapper identity，证明 resize 没有重新预计算 IBL。

## 12. PBR subsystem 边界

建议包结构：

```text
subsystems/render3d/pbr/
  PbrMaterialBinder
  PbrEnvironment
  PbrEnvironmentLoader
  PbrEnvironmentSettings
  EnvironmentPreprocessor
  PbrFallbackTextures
```

其中：

- public 类型只保留应用真正需要构造/持有的 environment 和 settings；
- shader、preprocess pass、fallback texture owner 尽量 package-private；
- backend 不依赖 pbr subsystem；
- core material 不依赖具体 shader resource path；
- PBR subsystem 可以依赖 core/backend 的稳定能力；
- 不建立 `PbrRenderDevice`、`PbrRenderGraph` 或第二套 mesh/material hierarchy。

架构测试新增守卫：

- backend 不依赖 `subsystems.render3d.pbr`；
- PBR production code 不调用 `CommandBuffer.custom()`；
- environment resource 不进入 `RenderSettings`；
- PBR public API allowlist 固定；
- Demo-specific sphere/UI 不泄漏进 main public API。

## 14. 资源生命周期与失败语义

所有构建器按“创建即登记、成功后移交”的方式管理 GL 资源。

### 14.1 Environment 构建失败

分别注入以下失败：

- HDR decode 失败；
- source texture upload 失败；
- environment cube 创建失败；
- irradiance compute shader 编译失败；
- prefilter 第 N 个 mip dispatch 前失败；
- BRDF LUT 创建失败；
- 最终 environment 组装失败。

每种情况下，之前创建的 shader、texture、cubemap 和 temporary source 必须逆序关闭一次。

### 14.2 正常关闭

- `PbrEnvironment.close()` 幂等；
- pipeline 关闭不关闭 borrowed environment；
- owning resource bundle 最后关闭 environment；
- close 后 bind/replace 明确失败；
- render thread cleanup 即使 frame callback 抛异常也执行；
- context 销毁前完成全部 GL resource cleanup。

### 14.3 替换环境

若 v0.12 暴露运行时 environment replacement：

1. 新 environment 在 render thread 完整构建；
2. 下一帧边界原子替换引用；
3. 旧 environment 在不再被 pending command buffer 引用后关闭；
4. 构建失败保留旧 environment。

如果无法证明第 3 点，v0.12 不开放运行时替换，只允许初始化时设置。

## 20. 风险与控制

### 风险 1：attribute location 冲突

控制：layout-aware instance base；未支持的 PBR instancing fail-fast；架构/GL 测试锁定。

### 风险 2：颜色空间错误导致“看起来像公式错了”

控制：texture role 强制 color space；PBR 要求 HDR/ACES；constant texture/reference pixel 测试。

### 风险 3：IBL preprocessing 过度抽象 RenderGraph

控制：environment 是固定尺寸、跨帧外部资源；首版放在 package-private preprocessor，不把 cubemap 强塞进通用 graph resource model。

### 风险 4：shader permutation 膨胀

控制：一个 opaque PBR shader；缺失纹理使用 fallback；debug contribution toggle 仅 Demo 使用。

### 风险 5：资源 ownership 不清

控制：environment 显式 owner，pipeline borrow；构建失败逐阶段注入；close 顺序测试。

### 风险 6：PBR 名义下扩大为完整资产系统

控制：只扩展现有 manifest；不做 glTF、材质编辑器、AssetRegistry 2.0 或 Assimp 自动材质抽取。

### 风险 7：启动预计算耗时或 driver 差异

控制：可配置 quality；compute capability 检查；分阶段 timing；固定 shader sample count；不以单机绝对毫秒作为跨平台门槛。

9. `test(pbr): add lifecycle pixel and pipeline matrix verification`
10. `docs(release): record v0.12 acceptance and benchmarks`

不要把 backend cubemap、材质配置、shader、Demo 和文档一次性塞入单个提交。

## 22. 后续方向

v0.12 完成后，再依据真实数据选择下一项：

1. PBR instancing 与 material batching；
2. glTF 2.0 metallic-roughness 导入；
3. GPU frustum/Hi-Z culling；
4. local reflection probes；
5. material texture binding 优化。

默认不直接进入高级 PBR extension。优先观察：

- draw/binding 是否成为瓶颈；
- OBJ+manifest 是否已经限制内容生产；
- 单一全局 environment 是否满足当前场景；
- PBR shader 和环境预计算在目标 GPU 上的真实成本。

## 23. 最终完成定义

v0.12 的完成定义可以压缩为一句话：

> 一个带 tangent-space normal、metallic-roughness 材质和 HDR environment 的外部 OBJ，能够在同一 Forward scene 中与 legacy 对象共同接受直接光和阴影，并通过 GPU IBL、自动曝光、Bloom、ACES 与 UI 完整输出；该链路有确定性测试、异常资源清理、resize 证明和性能基线。

如果只有 PBR shader、只有球体截图、只有离线生成的 IBL 文件，或只有 Demo 中的硬编码材质，都不算完成。
