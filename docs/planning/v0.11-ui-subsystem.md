# v0.11 Retained-mode UI Subsystem 实施计划

状态：正式版已完成（2026-07-17）。当前版本为 `0.11.0`；自动化、真实 GL、异步 snapshot、
五轮性能记录和 Microsoft Pinyin 人工矩阵均已完成。Emoji 字形和彩色 Emoji 不属于 v0.11 承诺。

本文是 v0.11 的工程实施合同。它定义 UI subsystem 的职责、依赖方向、公共接口、渲染和输入语义、
Windows IME 路线、资源生命周期、测试矩阵及发布门槛。实现过程中可以调整 package-private 类名和局部算法，
但不得在没有更新本文和架构守卫的情况下改变本文标记为“契约”的行为。

## 1. 结论与范围

当前框架适合开始 UI subsystem。v0.10 已经具备稳定的 RenderGraph、类型化命令流、状态缓存、动态 buffer、
resize、异步渲染线程验证和完整的本机 GL 验证链，可以承载 UI overlay。当前真正缺少的是 UI 所需的纵向基础：

- `GlfwWindow` 只有按键持续状态和鼠标增量，没有逐帧按下/释放、绝对光标、鼠标按钮、滚轮、字符、焦点和 IME composition；
- `CommandBuffer`、`PendingPipelineState` 和 `StateCache` 没有类型化 scissor 状态；
- `RenderPipeline` 没有暴露稳定的最终显示 pass 锚点；
- 没有布局树、字体 shaping、glyph atlas、UI batcher 和 UI 生命周期；
- GLFW 字符回调只能覆盖已提交 Unicode 字符，不能独立完成 Windows IME 预编辑文本和候选框定位。

因此 v0.11 定义为 **UI Foundation + 第一套可用的游戏内控件**。它必须为未来引擎编辑器保留正确结构，
但不在本版本实现完整 docking 编辑器。

### 1.1 本版本目标

- 新增独立的 retained-mode `subsystems.ui`，可以叠加在所有现有 AA/HDR/Bloom/自动曝光组合之后；
- 使用 Yoga 进行 Flexbox 布局，同时把 Yoga 隐藏在内部适配层后；
- 使用 FreeType + HarfBuzz 完成中英文测量、shaping、光栅化和绘制；
- Windows 首发支持文本输入、剪贴板和完整 IME composition/candidate 定位；
- 提供游戏 UI 所需的基础控件、焦点、事件传播、裁剪、滚动和主题；
- UI 逻辑不要求 OpenGL context，真实 GL 只存在于 UI renderer、atlas upload 和 integration 测试；
- 同步 Demo 和现有异步 render-thread 模式都能消费稳定的 UI render snapshot；
- 保留当前 OpenGL 专用定位，不引入第二后端或 Gradle 多模块拆分。

### 1.2 明确非目标

以下内容不进入 v0.11 发布门槛：

- 完整编辑器 docking、可拖拽分屏、原生多窗口 viewport；
- CSS 文件解析、selector、级联、热重载和浏览器兼容样式模型；
- 富文本编辑、语法高亮、Markdown/HTML 排版；
- 完整 Unicode BiDi、阿拉伯文段落算法和复杂脚本编辑器；HarfBuzz shaping 能力保留，但 v0.11 正式承诺 Latin/CJK；
- GPU 矢量路径、SVG renderer、复杂滤镜、模糊和阴影合成器；
- 操作系统 accessibility bridge；v0.11 只保留语义节点和 adapter SPI；
- Linux/macOS IME 原生适配；接口必须跨平台，发布验收先锁定 Windows；
- UI 场景 ECS、脚本语言、XML/JSON UI 标记语言或通用数据绑定框架；
- 任意 paint command 的全局排序。透明 UI 的 paint order 具有可观察语义，只允许合并相邻兼容批次；
- 为 UI 引入 Vulkan 风格 descriptor、通用 2D engine 或新的跨后端抽象层。

## 3. 架构边界

### 3.1 依赖方向

目标依赖关系：

```text
application / demo
    |-- subsystems.render3d ------> runtime/core/backend
    |-- subsystems.ui ------------> core/backend
    |              \-------------> subsystems.windowing.input
    \-- subsystems.windowing -----> GLFW/backend bootstrap

core/runtime/backend/render3d/postprocess -X-> subsystems.ui
```

契约：

- `ui` 是 `render3d` 的兄弟 subsystem，不是 `render3d` 的子包；
- `ui` 不得引用 `Scene`、`Camera`、`Material`、`PostProcessTargets` 或任何具体 3D pass 名称；
- `render3d`、`postprocess` 不得引用 `UiSystem`、控件或 UI renderer；
- `core`、`runtime` 和 `backend` 不得依赖 `subsystems.ui`；
- windowing 可以发布 subsystem-neutral 输入 DTO，但不得持有 UI tree、focus manager 或 widget；
- UI 可以使用 backend 的 OpenGL 资源类型，因为项目明确是单 OpenGL 后端；不得因此新增伪跨后端接口；
- 只有可被其他渲染路径复用的真实 GPU 状态进入 `core.command`，scissor 满足此条件；
- Yoga、FreeType、HarfBuzz、JNA/Win32 细节不得泄漏到游戏层公共接口。

### 3.3 线程所有权

v0.11 固定以下线程语义：

- GLFW callback 与 `WindowInputCollector` 运行在调用 `pollEvents()/waitEvents()` 的窗口线程；
- UI tree mutation、事件分派、布局和 display-list 构建运行在一个指定的 UI/update 线程；
- Shader、VAO/VBO/EBO、texture atlas region upload 和 `CommandBuffer` 录制运行在持有 GL context 的 render thread；
- FreeType/HarfBuzz 对象默认线程封闭；不同线程不得共享同一个可变 native face/font；
- `UiRenderSnapshot` 发布后不可变，在 render thread 完成消费前不得覆写其 primitive arena；
- 同步模式可由同一线程先 update 再 render；异步模式通过内部双缓冲/三缓冲 snapshot exchange 发布 latest-complete frame；
- 当生产速度高于渲染速度时允许丢弃尚未开始消费的中间 UI snapshot，但不得覆写正在消费的 slot；
- 关闭顺序为：停止新 snapshot 发布 → render thread 消费/丢弃剩余 snapshot → GPU ring fence 收尾 → atlas/shader/buffer 关闭 → native font/layout/IME 关闭。

线程策略不得通过给所有节点加锁实现。UI tree 是单线程可变对象，跨线程边界只传不可变 snapshot、资源上传请求和稳定 ID。

## 4. 公共接口合同

以下签名用于锁定职责和数据流。实现时允许进行不改变语义的小幅 Java API 修正。

### 4.1 Window input snapshot

`GlfwWindow` 新增逐帧快照入口：

```java
public WindowInputSnapshot inputSnapshot();
```

`WindowInputSnapshot` 必须是不可变值，至少提供：

```java
public final class WindowInputSnapshot {
    public long sequence();
    public int windowWidth();
    public int windowHeight();
    public int framebufferWidth();
    public int framebufferHeight();
    public float contentScaleX();
    public float contentScaleY();
    public double cursorX();
    public double cursorY();
    public double cursorDeltaX();
    public double cursorDeltaY();
    public double scrollX();
    public double scrollY();
    public boolean focused();
    public boolean cursorInside();
    public boolean keyDown(Key key);
    public boolean keyPressed(Key key);
    public boolean keyReleased(Key key);
    public boolean mouseDown(MouseButton button);
    public boolean mousePressed(MouseButton button);
    public boolean mouseReleased(MouseButton button);
    public KeyModifiers modifiers();
    public IntBuffer committedCodePoints();
    public Optional<ImeComposition> composition();
}
```

契约：

- 光标坐标使用 GLFW 的窗口内容区逻辑坐标，原点为左上；
- framebuffer 尺寸和 content scale 单独记录，不能用 framebuffer 尺寸冒充逻辑布局尺寸；
- `pressed/released` 是自上次快照以来累积的边沿，`down` 是拍摄快照时的稳定状态；
- 同一轮 callback 中 press+release 都发生时，两种边沿都必须保留；
- 滚轮增量、光标增量、字符和边沿在成功生成快照后清空，持续状态不清空；
- snapshot sequence 严格递增；重复读取不得悄悄重复消费一次性事件；
- GLFW key、mouse button 常量不得穿透到 UI widget；windowing 层映射到项目自己的 enum；
- callback 遇到未知 key/scancode 时安全忽略或保留原始诊断值，不越界写数组；
- 窗口失焦时合成所有仍按下键和鼠标按钮的 release，取消 pointer capture，避免 sticky interaction；
- 最小化期间 framebuffer 可以报告 0×0，但 UI 布局保留最后有效逻辑尺寸，渲染跳过；
- 默认 `GlfwWindow.Builder.cursorMode` 仍可服务第一人称 Demo；启用交互 UI 的 Demo 必须显式使用 `NORMAL`。

### 4.2 UI system

建议公共入口：

```java
public final class UiSystem implements AutoCloseable {
    public static UiSystem create(RenderWindow window, UiConfig config);
    public UiDocument document();
    public void update(WindowInputSnapshot input, float deltaSeconds);
    public void attachTo(RenderGraph graph, String dependencyPass);
    public UiFrameStats statistics();
    public void close();
}
```

契约：

- `create` 不得假设 RenderGraph 已经存在；需要 GL 的 renderer 资源可以显式延迟到 `attachTo` 或首次 render-thread 初始化；
- `update` 的 delta 必须有限且非负，并在 subsystem 内设置合理上限，避免暂停恢复后滚动/动画跳跃；
- 每个 `UiSystem` 对应一个窗口和一棵 document tree；v0.11 不跨窗口移动 node；
- 同一个 graph 只能 attach 一次；重复 attach、缺失 dependency pass 和 attach 后修改 pass topology 都要清晰失败；
- `close()` 幂等；部分初始化失败时逆序关闭已经创建的 native/GL 资源；
- close 后所有 mutation、update、attach、render 操作必须以包含资源名称的异常拒绝；
- UI pass 执行失败时 snapshot slot、dynamic ring、atlas upload 状态仍在 `finally` 中完成或中止，不能留下 active frame；
- UI 逻辑异常不能把半成品 snapshot 发布给 render thread。

### 4.3 RenderPipeline output anchor

`RenderPipeline` 新增：

```java
public String finalPassName();
```

它在成功 `build()` 后返回本 pipeline 最终写入 backbuffer 的 pass 名称。调用示例：

```java
pipeline.build();
ui.attachTo(pipeline.graph(), pipeline.finalPassName());
```

契约：

- 调用方不需要判断 NONE/MSAA/FXAA/TAA/HDR 的具体 final pass；
- `finalPassName()` 在 build 前和 close 后清晰失败；
- 它只暴露 graph composition 锚点，不返回 UI 类型，不让 `render3d` 依赖 UI；
- `PostProcessPassBuilder` 内部负责确定实际 final pass，不能在应用层复制 AA/HDR 分支判断；
- UI 也可以 attach 到应用自行建立的非 3D graph，只要 dependency pass 已存在并最终写入同一 backbuffer。

### 4.4 UI tree 与控件

`UiDocument` 拥有普通 root 和 overlay root。普通内容按树布局，popup/menu/modal 放入 overlay root 并保持逻辑 owner 关系。

每个 `UiNode` 至少具有：

- 永不复用的 `UiId`；
- 单一 parent、稳定 children 顺序；
- layout style、visual style、interaction state 和可选 semantic metadata；
- `VISIBLE/HIDDEN/COLLAPSED` 可见性，其中 hidden 占布局但不绘制，collapsed 不参与布局；
- enabled、focusable、hit-test-visible、clip/overflow 属性；
- measure/layout/paint/semantics dirty flags；
- capture 与 bubble event listener；
- optional debug name，但业务逻辑不得依赖 debug name 查找节点。

节点只能属于一个 document。以下情况必须立即失败：重复 parent、形成环、跨 document 插入、删除 root、使用已关闭节点。

第一版公开控件：

- `Panel`：容器、背景、边框、padding、clip；
- `Label`：单行/多行文本、wrap、ellipsis、alignment；
- `Image`：纹理、object-fit、tint；
- `Button`：normal/hover/pressed/disabled/focused 状态和 click；
- `Toggle`：二态值与 change event；
- `Slider`：范围、step、键盘和 pointer drag；
- `ScrollView`：双轴滚动、滚轮、clip、scrollbar；
- `ListView`：垂直列表和最小可用 virtualization，避免编辑器列表为每项常驻绘制节点；
- `TextField`：单行编辑、selection、caret、剪贴板、IME；
- `Popup/Menu`：overlay 定位、outside click、Escape 关闭和焦点恢复。

控件不直接发出 GL 命令，只产生布局、事件状态和 paint primitives。

## 5. Retained tree、布局与失效传播

### 5.1 Yoga adapter

增加 LWJGL `lwjgl-yoga` 模块和对应 native classifier。Yoga 只在 `YogaLayoutEngine` 内出现：

- 公共 style 使用项目自己的 `UiLength`、flex direction、justify、align、position、margin、padding、min/max、grow/shrink；
- adapter 把 computed style 映射到 Yoga node；
- `UiNode` 不公开 native address 或 Yoga enum；
- 每个 UI node 至多拥有一个对应 Yoga node，并由 document 逆序释放；
- text/image intrinsic size 通过 measure callback 提供；容器不得注册无意义 measure callback；
- measure callback 不做 GL 上传、不改变树、不触发事件；
- Yoga 输出使用逻辑像素，paint 阶段才按 content scale 对齐 framebuffer pixel；
- style resolver 将来可以从 typed theme 替换为 CSS-like resolver，而不改变 Yoga adapter、widget 或 renderer API。

### 5.2 布局坐标

- UI 逻辑坐标原点为窗口内容区左上，X 向右、Y 向下；
- root layout size 使用窗口逻辑尺寸，不使用 framebuffer 像素尺寸；
- DPI scale 可以是非整数且 X/Y 不同；
- hit-test 始终使用逻辑坐标，scissor 和 vertex 最终转到 framebuffer 坐标；
- fractional layout 保留到 paint，避免层层取整累积误差；
- 对齐 pixel 时使用统一函数，不允许每个 widget 自行 round；
- resize/content-scale 变化将 root 标记为 layout+paint dirty，并让 glyph cache 按实际 ppem 选择字形；
- 0×0 framebuffer 时仍允许 UI 状态和输入更新，但不产生 GL draw。

### 5.3 Dirty flags

最少区分：

```text
STYLE_DIRTY
MEASURE_DIRTY
LAYOUT_DIRTY
PAINT_DIRTY
HIT_TEST_DIRTY
SEMANTICS_DIRTY
```

传播规则：

- 文本、字体、wrap width 改变：自身 measure/layout/paint dirty，向祖先传播 layout；
- 颜色、透明度、hover 状态改变：只传播 paint；
- width/height/margin/padding/flex 改变：自身及必要祖先 layout；
- children 插入/删除/顺序改变：parent layout、paint、hit-test dirty；
- transform/scroll offset 改变：相关 subtree paint/hit-test dirty，不重新 shape 无关文本；
- invisible subtree 不进入 paint/hit-test；重新显示时使用已有测量缓存，除非依赖的约束或字体版本改变；
- dirty 处理必须迭代完成，禁止在一次 layout 中无限触发自身失效；超过保护轮次时报告 node id 和属性。

### 5.4 Paint order 与 hit-test

- paint 使用稳定的 depth-first 顺序；children 顺序决定同层覆盖；
- overlay root 始终在普通 root 之后；modal barrier 在 modal 内容之前且在普通内容之后；
- hit-test 使用 paint order 的逆序，先命中视觉上最上层节点；
- `pointer-events:none`/hit-test-disabled 节点跳过自身，但按配置决定是否跳过 children；
- clip 必须同时约束绘制与 hit-test；不可见裁剪区域内节点不能响应 pointer；
- opacity 为 0 默认仍可 hit-test，除非显式关闭，避免把视觉属性隐式变成交互属性；
- 删除当前 hovered/focused/captured 节点时必须发送 cancel/focus-lost，并安全寻找新的 focus target。

## 6. 输入、事件、焦点和交互

### 6.1 事件阶段

事件路径固定为：

```text
root capture -> ... -> parent capture -> target -> parent bubble -> ... -> root bubble
```

每个 event 包含稳定 timestamp/sequence、target/currentTarget、phase 和 modifiers。listener 可以：

- `continuePropagation()`；
- `stopPropagation()`；
- `preventDefault()`；
- 请求 keyboard focus；
- 捕获/释放指定 pointer；
- 打开或关闭 popup。

默认控件行为在 target listener 后、未 `preventDefault` 时执行。事件 dispatch 期间的树结构变更进入 mutation queue，当前路径使用开始 dispatch 时的稳定 snapshot，避免 listener 删除 parent 后路径损坏。

### 6.2 Pointer 语义

- v0.11 公开统一 `pointerId`，鼠标固定为 0，为以后触控保留空间；
- hover enter/leave 根据前后 hit path 差集生成，不只对最深 target 生成；
- button press 可以建立 pointer capture；drag 期间事件继续发往 captured node；
- release/cancel/窗口失焦/节点删除都释放 capture；
- click 要求 press 与 release 的默认行为属于同一可点击控件，允许控件配置少量移动阈值；
- double-click 使用时间和距离阈值，但阈值来自 `UiConfig`，不能散落在 widget；
- 滚轮从最深 scrollable target 向祖先传播，边界未消费的 delta 可交给外层 ScrollView；
- disabled 控件不触发业务 click/change，但仍可按主题显示 disabled 状态。

### 6.3 Keyboard focus

- document 同时只有一个 keyboard-focused node；
- Tab/Shift+Tab 按稳定 document order 移动焦点；overlay/modal 激活时 focus traversal 限制在 focus scope；
- popup 打开时记录原 focus，关闭后若原节点仍存在且可聚焦则恢复；
- Escape 先交给最内层 popup/modal，再交给 focused widget，最后冒泡；
- Space/Enter 激活 button，方向键操作 slider/list/menu；
- focus ring 是主题视觉，不改变 layout；
- window focus lost 会清除 pressed visual 和 pointer capture，但可以保留 keyboard focus identity，窗口恢复后不得自动提交旧按键。

### 6.4 剪贴板

新增 subsystem-neutral `ClipboardService`，初版由 GLFW `glfwGetClipboardString/glfwSetClipboardString` 实现。

- `TextField` 支持 Ctrl+A/C/X/V、Home/End、Shift selection、Ctrl+Left/Right；
- 剪贴板只交换 Unicode plain text；
- paste 经过控件的 validation/filter，不能绕过 max length；
- password field 可以复制为空或禁用复制，但仍允许粘贴；password 安全强化不作为 v0.11 密码管理承诺；
- clipboard 失败不得破坏当前 selection/value。

## 7. Windows IME 设计

### 7.1 为什么不能只依赖 GLFW char callback

GLFW char callback 可以得到已经提交的 Unicode code point，但完整 IME 还需要：

- composition/preedit 文本；
- composition 内 selection/caret；
- 开始、更新、提交、取消生命周期；
- 把系统候选窗口定位到当前 TextField caret；
- 在焦点移动、scroll、DPI 或窗口位置变化时更新候选矩形。

因此 v0.11 定义平台 adapter：

```java
public interface TextInputAdapter extends AutoCloseable {
    void activate(TextInputClient client);
    void deactivate(TextInputClient client);
    void setCandidateRect(UiScreenRect rect);
    Optional<ImeComposition> composition();
    void close();
}
```

### 7.2 Windows 实现路线

`Win32TextInputAdapter` 使用成熟的 Win32 binding（优先 JNA/JNA Platform；若最终选用小型 JNI bridge，必须单独评审构建和 native 发布成本）：

- 通过 GLFW Win32 native window handle 找到 HWND；
- 安装可链式调用的 WndProc hook，保存原 WndProc；
- 处理 `WM_IME_STARTCOMPOSITION`、`WM_IME_COMPOSITION`、`WM_IME_ENDCOMPOSITION`；
- 使用 IMM API 读取 composition string、caret/attribute；
- 使用 IMM candidate/composition window API 更新候选窗口位置；
- 所有未消费消息以及 GLFW 依赖的消息必须调用原 WndProc；
- committed text 保持单一来源，不能同时从 GLFW char callback 和 native result string 重复提交；
- close 时先停用 text client，再恢复原 WndProc，最后才允许 GLFW destroy window；
- hook 安装中途失败必须恢复已经修改的 HWND 状态；
- 只在 Windows 加载 Win32 实现，其他平台不得因 class initialization 尝试加载 JNA Win32 类型而失败。

### 7.3 Composition 与 TextField

- composition 文本是临时状态，不立即写入 committed value；
- TextField paint 在 selection/caret 附近显示 preedit 和 underline/selected segment；
- commit 按 grapheme/cluster 边界替换当前 selection，然后清空 composition；
- cancel 只删除 preedit，不还原 composition 开始前之外的编辑；
- composition active 时 Left/Right、Backspace 等由 IME 优先处理；UI 不得重复执行默认编辑命令；
- focus 切换、TextField 删除、document close 和 window focus lost 必须结束或取消 composition；
- candidate rect 使用 caret 的屏幕客户区位置和当前行高，经过逻辑坐标、content scale 和 viewport offset 转换；
- resize、DPI、scroll 和 caret 移动后下一次 UI update 必须刷新 candidate rect；
- 测试 adapter 可以注入 composition 事件，不要求纯 JVM 测试启动真实系统输入法。

### 7.4 v0.11 IME 验收字符集

正式验收至少覆盖：

- Latin ASCII 输入和 Shift/Caps 行为；
- 中文拼音 composition 多次更新后提交；
- 中文候选取消；
- 中英文混排 selection 替换；
- supplementary Unicode code point 不被拆成两个无效字符；
- emoji/组合字符按 grapheme 边界移动和删除的基础行为；
- TextField 在 ScrollView 内移动后候选框跟随 caret；
- 窗口 resize/content-scale 变化后候选框位置正确。

## 8. 文本系统

### 8.1 Native 依赖与所有权

在现有 LWJGL 3.3.3 BOM 中加入：

```groovy
"lwjgl-freetype"
"lwjgl-harfbuzz"
"lwjgl-yoga"
```

这些模块沿用现有 `implementation + runtimeOnly natives` 循环。Windows IME 若采用 JNA，JNA 只作为 windowing Win32 adapter 依赖，不能进入 core。

`FontManager` 初始化一个 FreeType library，`FontFace` 拥有：

- 字体文件的 direct `ByteBuffer`；
- `FT_Face`；
- 对应 HarfBuzz face/font；
- stable face id、family/style metadata 和 coverage cache。

字体 backing buffer 必须活得比 `FT_Face/HB face` 更久。关闭顺序为 HB font → HB face → FT face → backing buffer owner → FT library。重复 close 幂等，失败清理保留 suppressed exception。

### 8.2 字体来源与 fallback

- 应用显式注册 `FontFamily` 和按优先级排列的 fallback chain；
- 不把“当前机器恰好安装某字体”作为可重复 Demo/测试的前提；
- Demo 加入一个许可证明确的 Latin/CJK 测试字体或经过许可的最小子集，并保留原始许可证和 subset glyph manifest；
- fallback 按 code point/cluster 选择可以覆盖完整 cluster 的 face；
- missing glyph 使用明确 tofu glyph，不能静默跳过并改变 advance；
- 字体 fallback 结果进入 shaping cache key；注册/卸载 font 会递增 font generation 并失效相关测量与 glyph cache；
- v0.11 不承诺 variable font axis、彩色 emoji 或 OpenType feature 编辑 UI，但 cache key 为未来 feature set 留字段。

### 8.3 Shaping 与文本布局

流程固定为：

```text
UTF-16 Java String
  -> code point / grapheme boundaries
  -> script/fallback runs
  -> HarfBuzz shaping
  -> glyph ids + advances + offsets + clusters
  -> line breaking / alignment
  -> positioned glyph display list
```

要求：

- 不用 Java `char` 索引直接移动 caret；内部索引明确区分 UTF-16 offset、code point 和 shaping cluster；
- selection/caret 只能落在允许的 grapheme/cluster boundary；
- 中文可在允许的 CJK 边界换行，Latin 优先在 word boundary 换行；
- `TextBoundaryService` 集中封装 `BreakIterator` 或后续 ICU 替代，widget 不自行猜测字符边界；
- shaping cache key 至少包含 font generation、face、ppem、text slice/hash、direction、language、feature set；
- layout cache 额外包含 wrap width、line height、max lines、alignment 和 overflow mode；
- cache 必须有明确上限和 LRU/clock 淘汰，不能因动态聊天文本无限增长；
- label text 改变只失效相关 shaped/layout entry，不清空整个 atlas；
- ellipsis 本身也经过 fallback 与 shaping，max-lines 截断不能切断 cluster；
- line-height 默认来自 font metrics，允许主题覆盖，但必须为有限正值。

### 8.4 Glyph atlas

- glyph atlas 使用动态 `R8` coverage page；shader 从红通道取 coverage；
- glyph key 至少包含 face id、glyph id、ppem、hinting/raster mode；
- atlas page 使用 skyline 或 shelf allocator，算法要有独立纯 JVM 测试；
- 第一次 miss 在 UI/update 阶段完成 FreeType rasterization，生成稳定 upload request；
- GL texture 创建和 region upload 只在 render thread；
- upload 前设置并恢复/通过 DSA 避免污染 pixel unpack 状态；
- glyph padding 至少 1 像素，避免线性采样串色；
- atlas 默认不开 mipmap，使用 clamp-to-edge + linear filtering；
- page 满后新增 page；设置最大 page 数，达到上限时只淘汰不被 in-flight snapshot 引用的 glyph；
- snapshot 持有 atlas generation/page reference，atlas repack 不得使正在渲染的 UV 失效；
- 第一版优先“多 page + 安全淘汰”，不做每帧 repack；
- atlas upload 失败时不发布对应 glyph，下一帧可以重试，已有 page 保持有效；
- UI statistics 暴露 glyph hit/miss、page 数、upload bytes 和 eviction 数。

为支持 atlas，backend 增加最小的 dynamic texture allocation/region upload 能力。不得让 UI 通过 `CommandBuffer.custom()` 调用裸 `glTexSubImage2D`。

## 9. UI 渲染链路

### 9.1 Pass 顺序

UI 永远在场景色彩处理完成后写入 display-space backbuffer：

```text
Geometry
  -> MSAA Resolve / TAA
  -> Bloom + Auto Exposure
  -> Tone Mapping
  -> FXAA / Present
  -> UiOverlayPass
  -> swapBuffers
```

理由：

- UI 不应影响自动曝光或 Bloom；
- UI 不经过 TAA，避免文字 ghosting；
- UI 不经过 FXAA，避免细字变软；
- UI 颜色按主题定义的 linear color 合成到已有 sRGB backbuffer；
- screenshot 如果需要包含 UI，应在 UiOverlayPass 之后采集；只要场景图则在 UI 前采集。

`UiOverlayPass`：

```java
graph.addPass("UiOverlayPass")
    .writeToBackbuffer()
    .noClear()
    .dependsOn(dependencyPass)
    .execute((resources, commandBuffer) -> uiRenderer.record(commandBuffer, currentSnapshot));
```

### 9.2 色彩和混合

UI 使用 premultiplied alpha：

```text
src.rgb 已乘 src.a
blend = ONE, ONE_MINUS_SRC_ALPHA
```

要求：

- UI theme color 在 CPU/API 中表达为 linear RGBA；从十六进制 sRGB token 构造时只转换 RGB，alpha 不做 gamma；
- 普通图片按资源元数据以 sRGB texture 采样并得到 linear shader value；数据纹理显式 linear；
- glyph coverage 乘到 premultiplied text color；
- UI pass 对 sRGB-capable default framebuffer 启用 framebuffer sRGB，使 destination 解码、linear blend、重新编码；
- 不在 fragment shader 再手工 gamma，避免双编码；
- 半透明叠加、文字边缘和图片 tint 必须有真实 GL 像素测试；
- 如果运行环境 default framebuffer 实际不支持 sRGB，初始化时明确报告能力降级，不静默假装 linear blend 正确。

### 9.3 类型化 scissor

新增命令：

```java
CommandBuffer enableScissor(boolean enabled);
CommandBuffer scissor(int x, int y, int width, int height);
```

它必须贯穿：

```text
CommandBuffer
  -> PendingPipelineState primitive packet
  -> PipelineStateSink
  -> StateCache
  -> glEnable/glDisable(GL_SCISSOR_TEST), glScissor
```

契约：

- 参数非负，空 clip 允许编码为 0×0；
- scissor 是 pending raster state，遵循现有“最后写入生效”和 observable boundary flush；
- StateCache 缓存 enable 与 rectangle，并计入 applied/skipped statistics；
- `invalidateState()` 同时失效 scissor cache；
- RenderGraph 每个 pass 的默认状态显式 `enableScissor(false)`，避免上一 UI pass 泄漏到下一帧的场景 pass；
- UI renderer 结束时也显式关闭 scissor，使单独调用 renderer 时安全；
- 生产 UI 路径禁止使用 `custom()` 设置 scissor。

UI top-left clip 转 OpenGL bottom-left scissor：

```text
left   = floor(logicalLeft * scaleX)
right  = ceil((logicalLeft + logicalWidth) * scaleX)
top    = floor(logicalTop * scaleY)
bottom = ceil((logicalTop + logicalHeight) * scaleY)

glX = clamp(left, 0, framebufferWidth)
glY = framebufferHeight - clamp(bottom, 0, framebufferHeight)
glW = max(0, clamp(right, 0, framebufferWidth) - glX)
glH = max(0, clamp(bottom, 0, framebufferHeight) - clamp(top, 0, framebufferHeight))
```

所有 nested clip 先在逻辑空间求交，再统一转换；不得逐层 round 后再求交。

### 9.4 Display list 和 batching

UI update/paint 阶段生成与 GL 无关的 `UiDisplayList`，初版 primitive：

- solid quad；
- textured quad；
- glyph run；
- border/基础圆角矩形；
- push clip / pop clip；
- debug outline（仅诊断模式）。

Display list 保留原 paint order。`UiBatcher` 只合并相邻且以下 key 完全一致的 primitive：

```text
shader variant + texture/atlas page + sampler + clip rectangle + blend mode
```

不能为了减少 draw call 跨越半透明 primitive、clip、popup layer 或用户自定义 paint boundary 排序。

基础 quad vertex 至少包含 framebuffer/display position、UV 和 packed normalized RGBA。圆角/边框参数可以使用独立 shader variant 或扩展 vertex，
但不得让所有普通 glyph/图片 vertex 为罕见效果携带大块无用数据。第一版优先两个明确 variant，而不是一个巨型全功能 shader。

### 9.5 Dynamic buffer ring

- UI VBO/EBO 使用可复用 ring，不逐帧创建/删除 buffer；
- 优先复用现有 persistent-mapped ring 的 fence 经验，但 UI ring 独立于 3D instancing ring；
- 每个 frame slot 有 `IDLE/ACTIVE/SUBMITTED` 状态；
- begin frame 等待或选择安全 slot，upload 后记录 draw ranges；
- 正常完成插入 fence；异常路径在 `finally` 中完成/中止 active slot；
- 清理异常作为 suppressed exception，不覆盖主异常；
- 16-bit index 路径每批最多 16,383 quad，超过时 flush；也可以选择 32-bit index，但选择后必须由 benchmark 证明；
- arena 按高水位增长并设置合理上限；极端 UI 超限时分批 flush，不能 OOM 后留下 active slot；
- steady-state 不为每个 node、glyph 或 quad 创建临时 Java 对象；primitive 写入可复用结构化数组/direct buffer；
- statistics 至少包含 node、primitive、quad、glyph、batch、draw、vertex/index bytes、ring wait 和 atlas upload bytes。

### 9.6 UI pass 固定状态

每次 UI pass 明确提交：

```text
default framebuffer
full framebuffer viewport
framebuffer sRGB = true
blend = enabled
blend func = ONE / ONE_MINUS_SRC_ALPHA
depth test = disabled
depth mask = false
cull face = disabled
scissor = disabled initially, then clip-driven
```

不得依赖前一个 pass 恰好留下的状态。UI pass 完成后 scissor 关闭；下一 pass/frame 仍由 RenderGraph 基线重新提交必要状态。

## 10. Theme、style 与未来 CSS 解耦

### 10.1 v0.11 typed theme

第一版使用不可变的强类型 token：

```text
Theme
  colors
  typography
  spacing
  radii
  borders
  control sizes
  animation durations
  interaction thresholds
```

`Theme` 不直接保存 Yoga node、Texture2D、ShaderProgram 或 native font pointer。字体通过稳定 `FontFamilyId` 引用，图标通过 `UiImageId` 引用。

每个 widget 根据：

```text
widget type + style classes + pseudo states + inherited values + inline overrides
```

得到不可变 `ComputedStyle`。v0.11 不实现 CSS parser，但 `StyleResolver` 是独立边界。未来 CSS-like 实现只替换 token/selector 到 computed style 的解析过程，不改变：

- UI tree ownership；
- Yoga adapter；
- event/focus；
- paint primitives；
- widget value/callback API。

### 10.2 状态和继承

初版 pseudo state：

```text
normal, hover, pressed, focused, disabled, checked, selected, invalid
```

字体、字号、文本颜色可以继承；layout size、margin、padding、background、border 不继承。style state 改变必须通过字段级 diff 决定 layout 或 paint dirty，不能每次 hover 都重建 Yoga tree。

### 10.3 动画

v0.11 只提供有限的属性 transition：opacity、color 和可选 transform。layout 属性动画不是发布门槛。

- 动画使用真实 delta 并限制大暂停；
- prefers-reduced-motion 先作为 config/theme flag；
- UI animation 更新只让受影响节点 paint dirty；
- 关闭/移除节点会取消其 animation handle，不能持有 document 泄漏。

## 11. Widget 行为合同

### 11.1 Button / Toggle / Slider

- Button 在 pointer press 时 capture，release 位于有效区域才 click；Space/Enter 等价激活；
- Toggle 的 value 只在默认 action 未被取消时改变，先更新 value 再发送 change event；
- Slider 对 value 做 finite、range、step 校验；pointer drag 和 keyboard 使用同一 value normalization；
- programmatic value change 是否触发 event 必须通过明确 API 区分，防止数据绑定循环；
- disabled 中途发生时取消 active press/drag；
- focus visual 不改变控件 measured size。

### 11.2 ScrollView / ListView

- scroll offset clamp 到 content extent；content shrink 后立即重新 clamp；
- 滚轮和 scrollbar drag 都建立明确消费语义；
- nested scroll 在内层到达边界后把剩余 delta 交给祖先；
- clip 同时作用于 paint 与 hit-test；
- ListView 通过 item count、key、factory/binder 实现最小 virtualization；
- 可见范围外节点回收前必须释放 focus/capture，并清除旧 listener/value；
- item key 稳定时 selection/focus 不因前方插入项目而错位；
- 10,000 项列表不得创建 10,000 个可绘制 node 作为 steady-state。

### 11.3 TextField

TextField 内部状态至少包括：

```text
committed text
selection anchor/focus
caret affinity
horizontal scroll
composition/preedit
undo/redo history
validation state
```

v0.11 最低编辑能力：

- mouse click/drag selection；
- Left/Right、Ctrl+Left/Right、Home/End；
- Backspace/Delete 按 grapheme boundary；
- Shift 扩选；
- Ctrl+A/C/X/V/Z/Y；
- committed Unicode input；
- Windows IME composition/commit/cancel；
- placeholder、password mode、max length、read-only、disabled；
- caret blink 使用时间而非帧数；
- selection、preedit underline 和 caret 都经过 clip；
- undo 合并连续相邻输入，但 composition 整次提交作为一个 undo unit；
- value/selection change listener 中修改 TextField 不得造成递归损坏。

多行编辑器、语法高亮和大文件 rope 不属于 v0.11；`TextField` 正式承诺单行。`Label` 可以多行只读布局。

### 11.4 Popup / Menu / modal

- popup 在 overlay root 中绘制，但保留 owner 以便定位和焦点恢复；
- popup 自动限制在窗口可见逻辑区域内；
- outside click、Escape 和 owner 删除关闭 popup；
- modal 打开后普通 root 不再接收 pointer/keyboard 默认行为；
- nested popup 按栈关闭，不能一次 Escape 无条件关闭全部；
- popup close listener 中再次打开 popup 通过 mutation queue 处理，不能修改正在迭代的栈。

## 12. 资源与异常生命周期

### 12.1 所有权表

| 资源 | 所有者 | 创建线程 | 关闭线程 |
| --- | --- | --- | --- |
| Window callbacks/input collector | `GlfwWindow` | window | window |
| Win32 WndProc/IME context | `Win32TextInputAdapter` | window | window，且先于 window destroy |
| Yoga config/nodes | `UiDocument/YogaLayoutEngine` | UI | UI |
| FreeType library | `FontManager` | text owner | text owner |
| FT/HB face/font | `FontFace` | text owner | text owner |
| Rasterized glyph bytes | upload request/snapshot slot | UI/text | render consumption 后回收 |
| Glyph atlas textures | `GlyphAtlas` renderer side | render | render |
| UI shader/VAO/VBO/EBO/ring fence | `UiRenderer` | render | render |
| UI tree/widgets/listeners | `UiDocument` | UI | UI |

### 12.2 失败处理

- 构造/attach 采用局部变量建立，全部成功后才发布到字段；
- 资源中途失败按依赖逆序关闭；
- close 聚合异常，第一个为主异常，其余 suppressed；
- snapshot build 失败不替换上一张完整 snapshot；
- render frame 失败不复用 GPU 尚未完成的 ring slot；
- atlas 部分上传失败不发布半有效 atlas generation；
- Yoga measure callback 抛异常时记录 node id/debug name 并中止本次 layout，不能继续使用部分 layout；
- listener 异常默认终止本次 update 并保留文档结构一致性；mutation queue 在 finally 中丢弃未提交 mutation；
- IME hook 失败时普通 committed-char 输入仍可工作，同时报告“composition unavailable”，不得阻止窗口创建；
- duplicate close、close-before-attach、attach-failure close 都有测试。

### 16.7 Pipeline integration

矩阵至少覆盖：

```text
ToneMapping: NONE / ACES
AA: NONE / MSAA / FXAA / TAA
Bloom: off / on
Exposure: manual / auto（合法组合）
UI: off / on
Resize: fixed / scripted resize / minimize-restore

```

`UiPipelineMatrixGlTest` 以真实 OpenGL 上下文执行全部 40 个合法运行项：LDR 的四种 AA 与 UI

## 17. 性能与容量基线

性能结果记录而不设跨机器硬阈值。固定场景：

- 100 nodes HUD；
- 1,000 nodes settings/list；
- 10,000 logical items、仅可见项常驻的 virtualized list；
- 10,000 quads stress；
- 2,000 visible glyph CJK/Latin 混排；
- warm atlas 与 cold atlas 分开；
- 1080p 和 4K，各五轮，报告 median。

报告字段：UI update、layout、shape、paint record、render record、GPU、draw calls、upload bytes、atlas hit rate、ring wait、steady-state allocation。

工程目标而非发布硬阈值：

- 未改变的静态 UI 不重复 layout/shape；
- warm steady-state 不按 node/glyph/quad 分配临时对象；
- 单 atlas page、单 clip、相邻兼容的普通 UI 合并为一个 draw；
- virtualized list 内存和可绘制 node 数与可见项近似相关，不与总 item count 线性相关；
- atlas cold miss 可以增加 raster/upload 成本，但不得同步等待 GPU readback；
- 任何 benchmark 不以关闭正确性检查、跳过 fence 或扩大 `custom()` 使用换取数字。

## 18. 架构守卫

扩展 `ArchitectureBoundaryTest`：

- `core/backend/runtime/render3d/postprocess` 禁止依赖 `subsystems.ui`；
- `subsystems.ui` 禁止依赖 `subsystems.render3d` 和 `subsystems.postprocess`；
- `subsystems.windowing` 禁止依赖 UI；
- Yoga symbols 只允许出现在 `subsystems.ui.layout`；
- FreeType/HarfBuzz symbols 只允许出现在 `subsystems.ui.text`；
- Win32/JNA symbols 只允许出现在 `subsystems.windowing.input.win32`；
- UI 生产代码禁止调用 `CommandBuffer.custom()`；
- widget/event/layout/style package 禁止引用 OpenGL/LWJGL GL symbols；
- UI renderer 不得引用具体 scene/postprocess pass 常量；
- `RenderPipeline.finalPassName()` 是唯一需要的兄弟组合信息；
- 新增白名单必须附设计原因，不得因测试失败直接扩大允许集合。

## 21. v0.12 之后的默认方向

v0.11 稳定后再依次评估：

4. CSS-like stylesheet parser 和热重载，继续复用 `StyleResolver` 边界；

7. rich text/code editor、完整 BiDi/ICU；

## 22. 最终决策摘要

- UI 类型：retained-mode；
- 布局：Yoga，隐藏在 `LayoutEngine` 后；
- 文本：FreeType + HarfBuzz，Latin/CJK 正式支持；
- 输入：windowing 发布不可变逐帧 snapshot；
- IME：平台 adapter，Windows 首发，普通 committed char 与 composition 分离；
- 渲染：RenderGraph 最终 backbuffer overlay，位于 tone mapping/FXAA/TAA 之后；
- 混合：linear-space premultiplied alpha + framebuffer sRGB；
- 裁剪：进入 typed CommandBuffer/StateCache，不使用 `custom()`；
- 样式：typed immutable Theme，保留未来 CSS-like `StyleResolver`；
- 线程：UI tree 单线程，跨线程只发布不可变/slot-owned render snapshot；
- 第一产品：游戏内 HUD/菜单/设置 UI，同时保留编辑器需要的 overlay、virtualization、focus 和 semantics；
- 编辑器 docking：v0.12 候选，不进入 v0.11；
- 定位：继续是稳定的单 OpenGL 后端框架，不拆模块、不做第二后端。
