## 材质与前向语义

- 散射项在 `directionalRadiance`/`localRadiance` 的现有 clearcoat 处理后、`visibility`
  乘法前作为独立加法项加入：`scatterColor * intensity * radiance * clamp(dot(-n,l),0,1) *
  attenuation`。它只读取背光余弦，正面 `dot(n,l) >= 0` 时早退为零，因此不会缩放或替换
  已有 diffuse/specular，正面高光保持逐字节不变。
- 厚度在 `main()` 中每 fragment 解析一次（`gSubsurfaceThickness`），供两盏灯复用；
  厚度源：常量；`(1 - occlusion.r) * thicknessMetres`；`(1 - baseColor.a) * thicknessMetres`。
- 前向 shader 只声明实际消费的 `uSubsurfaceEnabled/ScatterColor/Intensity/Profile/
  ProfileScale/ThicknessSource/Thickness/ScreenSpace/DiffuseSignal`；`uSubsurfaceDiffusionRadius`
  与 `uSubsurfaceMaxDistance` 仍由 `scene-surface.frag` 的 mask 生产者和
  `SubsurfaceScatteringPass` 消费，不在前向 shader 声明或上传。`uSubsurfaceScreenSpace`
  在前向 shader 中实际参与 alpha 份额门控（并由 `PbrMaterials` 上传），
  `uSubsurfaceDiffuseSignal` 由 `RenderPipeline` 每帧按 topology 设置；两者都有引用，
  不会被 GLSL 优化掉。
- 逐通道衰减：`exp(-thickness / max(profileScale * penetration, 0.001))`。`SKIN` 穿透比
  固定为 `(1.0, 0.55, 0.30)`，`UNIFORM` 为 `(1,1,1)`。
- 透射项不乘 `NdotL`（背光时为零），只乘灯辐亮度；阴影/距离/spot cone 仍由原 `visibility`
  和 `radiance` 路径乘入。

## 屏幕空间扩散

`SUBSURFACE` surface 通道（RGBA16F）：

| 通道 | 内容 |
|---|---|
| R | 屏幕空间 coverage：`screenSpaceEnabled * clamp(intensity,0,1) * distanceFade`；零表示不参与 |
| G | 厚度衰减后的有效半径（米）：`diffusionRadiusMetres * mean(attenuation)`，限制在 `[0,2]` |
| B | 解析后的厚度（米） |
| A | 参与位：`screenSpaceEnabled ? 1 : 0` |

生产 mask 接受 SubsurfaceScatteringSettings 的完整 [0, MAXIMUM_INTENSITY] 范围，并在 coverage 上饱和到 1；只有超出设置范围的 uniform 才回退 0。review 修复：早期版本把 >1 误判为非法，导致有效材质静默无 screen-space coverage。

`SubsurfaceScatteringPass` 读取该 mask、颜色、depth、normal：

- 半径从米转像素：用同一 depth 的相邻像素重建 view 位置，得到该深度每像素米数；半径上限
  由全局 `SubsurfaceScatteringSettings.diffusionRadiusMetres` 和 shader 常量 64 px 双重限制。
- 固定 16-tap Poisson 盘（`|r| <= 1.24`），中心权重 1；tap 权重 `exp(-2.5 r²)`。
- 拒绝：tap 越界（不 wrap）；mask 零；背景 depth；世界空间法线 dot < 0.85；tap 到中心
  切平面的距离 > `max(0.01, 0.03 * |viewZ|)`；`maxDistanceMetres` 世界距离。
- 漫反射份额：颜色 alpha 是 `pbr-forward.frag` 写入的 bounded diffuse share（1=全漫反射，
  0=全镜面/自发光）。中心 `centerDiffuse = rgb * alpha`；每个 tap 只累加
  `rgb * alpha`，非漫反射部分永不进入扩散和。
- 最终 `blend = coverage * edgeFade * centerShare`，`scattered = mix(centerDiffuse,
  diffused, blend)`，输出 `rgb - centerDiffuse + scattered`；中心镜面/自发光部分原样加回，
  alpha 0 的中心像素既不扩散也不接收无漫反射反照率支撑的散射光。边缘 8 px fade。
- 非参与像素、零 mask 和背景复制原颜色（逐字节）；无 NaN/Inf。

## Pass 顺序与配置拒绝

HDR 链：

```
Geometry → [HdrResolve] → [Fog] → [VfxComposite] → [ScreenDistortion] → [TAA]
  → SubsurfaceScatteringPass → SsrPass → [TemporalDenoisePass] → [DepthOfField]
  → [MotionBlur] → AutoExposure/Bloom → ToneMapping → ...
```

`PostProcessPipeline` 在 `effects.subsurfaceScattering().screenSpaceActive()` 时创建 owner；
启用但 HDR 关闭时在候选装配期拒绝
（`screen-space subsurface scattering requires HDR tone mapping`）。缺少
`DEPTH`/`NORMAL`/`SUBSURFACE` surface 输入时在 `addFinalPass`/`validateSurfaceInputs`
拒绝。禁用时不创建 pass，`passNamesFor` 与基线顺序不变。

## 明确限制与未验证项

1. 屏幕空间扩散是对已着色 HDR 颜色的有界空间近似；没有真实体积、路径追踪、多次散射、
   折射或透射分离，也没有逐像素 profile 贴图/光谱积分。
2. `SKIN`/`UNIFORM` 只有固定解析穿透比；没有按 RGB 分别积分散射距离的物理 profile。
3. 屏幕空间 pass 只扩散同屏采样；离屏区域直接拒绝，不重建屏幕外颜色；大半径时 16-tap
   Poisson 盘会出现有限采样稀疏，半径受 64 px 上限约束。
4. 深度/法线边界使用固定的平面距离和法线点积阈值；薄几何、掠射表面和法线贴图后的着色
   法线不在该 G-buffer 中（使用共享几何法线），与既有 surface 协议限制一致。
5. 漫反射份额是**单个标量**（HDR alpha），只能表达整像素的漫反射比例，不能逐 RGB
   通道或逐光源分离；它由前向 shader 的实际 direct specular/clearcoat split/specular
   IBL/emissive 亮度从总亮度中减去得到，因此低亮度镜面和同亮度漫反射可以被区分，但
   仍未做逐像素镜面分量缓冲或材质级高光 mask。
6. 屏幕空间 mask 只由 opaque METALLIC_ROUGHNESS 材质写入；透明/粒子/折射不参与。实例
   uniform override 只用于前向 shader 实际声明/消费的字段；`diffusionRadius` 与
   `maxDistance` 仍由材质模板 settings 直接供 mask 生产者读取，不传到前向程序；
   `uSubsurfaceScreenSpace` 现在由前向 shader 实际引用（alpha 份额门控）并由
   `PbrMaterials` 上传，不再被 GLSL 优化掉。每材质仍是单一 mask 值，不支持逐实例多 profile。
   场景阶段（VFX/透明/加法体积合成）在 SSS 表面上的 alpha 覆盖尚未逐一改成
   destination-alpha 保留；这些组合下的份额可能被覆盖为 1.0（退化为全漫反射），列为
   组合限制，需要时由调用方避免叠加。
7. `SubsurfaceScatteringPass` 无历史、无私有目标，因此 resize 由 graph 目标重建承担；
   本包没有独立的 pass resize 事务（stateless pass 无尺寸状态可回滚）。
8. 首版 worker 禁改 `RenderPipeline`/`RenderFeaturesControl` 等文件；后续集成与 S6 阶段已把
   `uSubsurfaceDiffuseSignal` 帧门控、统一 feature control 与 demo 入口接上（见本文开头
   2026-11-16 与 S4/S5 接线记录）；未完成的是 VFX/透明等场景阶段的 alpha 保留组合。
9. 真实 GL 已由 Orchestrator 在唯一 GPU 队列执行：worker `ecba569`/`379c28f` 与集成 `d29cd44`/`2b69d78` 上 Forward 2/2、Pass 2/2、MSAA resolve 2/2 均 PASS，0 skipped、0 failures；设备/驱动身份见 JUnit XML。
   独立 review 结论为 APPROVE_WITH_SCOPE（NONE-AA 已验证路径 + 4x MSAA SUBSURFACE resolve）；POM+SSS、feature-control/demo 仍未验证。
10. `SceneSurfaceLayout` 新增 RGBA16F 通道会改变启用 SSS 时的 surface 存储；未启用时
    layout 与基线一致，但本 worker 未运行 GPU 资源峰值测量，显存/带宽 `NOT_EVALUATED`。
11. 前向散射项对每盏灯求值（方向光与局部光），成本随灯数增长；未做灯光数量/性能测量。
12. **POM + SSS UV 不一致（已记录，未拒绝）**：前向 shader 在视差偏移后的 `materialUv` 采样厚度，mask 生产者用 `vTexCoord`，同一材质同时启用 parallax 与 subsurface 时前向厚度/衰减与 mask 半径/厚度可能不一致。当前 `PbrMaterials.createWithBindings` 不拒绝该组合；首版将其列为已知限制，调用方不应在同一材质上叠加两者。
13. **Raw `Material.builder` 回退差异**：`SceneSurfacePass` 在未绑定 occlusion/base-alpha 贴图时回退为 CONSTANT 厚度，而前向 shader 仍按 OCCLUSION/BASE_ALPHA 语义采样；`PbrMaterials` 总会绑定 fallback 纹理，因此生产 PBR 路径一致，裸 `Material.builder` 调用方需自行保证绑定。
