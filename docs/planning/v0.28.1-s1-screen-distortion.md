# 0.28.1 S1 #4 技术卡：Screen-Space Distortion（屏幕空间冲击波／热浪）

日期：2026-11-11。状态：首版生产实现完成；JVM 合同通过，真实 GL 用例已编写但**未执行**，不能计为 GL PASS。对应 46 项路线图 #4，执行计划见 [multi-agent full delivery](haikalat-multi-agent-full-delivery.md) 与 [realtime rendering roadmap](realtime-rendering-roadmap.md)。

## 适用范围

- 支持：有限层（默认 4，硬上限 8）的屏幕空间 UV 偏移贡献；径向热浪（`ring=0`）与冲击波环带（`ring=1`）；线性/椭圆范围；按场景深度拒绝前景遮挡；UV 越界回退；按深度远到近的重叠合成。
- 不支持：屏幕空间反射/折射（#11/#13/#20）、逐像素屏幕贴图偏移、几何位移、后处理历史/时域累积、MSAA 采样内插（本 Pass 只消费已 resolve 的 VFX composite 单采样颜色与深度）、透明物体的深度遮挡（透明物不在深度图内，只能靠贡献自身的 `effectDepth` 控制）、UI（UI 在 present 之后合成，天然不受影响）。
- 不在本卡交付：`RenderPipeline` 的逐帧 `vfxDistortions` 公共入口。本 Worker 被明确禁止修改 `RenderPipeline`，因此首版通过 `ScreenDistortionSettings.source` 注入 `ScreenDistortionSource`；该接口由应用/战斗 VFX 装配层实现，并在每帧更新有界列表。

## 数据与归属

| 项目 | 内容 |
|---|---|
| 生产者 | VFX/战斗装配层创建 GL-free `subsystems.vfx.VfxDistortion`（世界空间锚点、半径、UV 偏移、mask、厚度、ring/haze/phase，稳定 `(effectId,distortionIndex)`）。 |
| 适配器 | `render3d.vfx.VfxDistortionProjector` 用相机 projection/view 投影为屏幕空间 `postprocess.ScreenDistortion`：UV 中心、椭圆半范围、NDC 深度、深度厚度；相机背后、离屏中心与近远平面外贡献被丢弃而不是 clamp。 |
| 消费者 | `postprocess.PostProcessPipeline` 的 HDR 颜色链；`ScreenDistortionPass` 拥有 shader + `ScreenQuad`，只消费纯数据。 |
| 注入 | `PostProcessSettings.screenDistortion`（`ScreenDistortionSettings`）携带 `ScreenDistortionSource`；source 实例在 pipeline 代次内保持稳定，每帧 `screenDistortions()` 返回有界列表（调用点：record `ScreenDistortionPass` 时，GPU owner 线程，纯 CPU）。 |
| 无新 manager/factory | 仅一个效果 owner 与两个纯数据合同；没有第二套配置系统或通用后处理框架。 |

装配示例（应用侧，不需要修改 `RenderPipeline`）：

```java
List<ScreenDistortion> frameDistortions = new ArrayList<>();
ScreenDistortionSource source = () -> frameDistortions;
pipeline.postProcessSettings(PostProcessSettings.builder()
        .screenDistortion(ScreenDistortionSettings.builder()
                .enabled(true).source(source).build())
        .build());

// 每帧在 pipeline.execute 之前：
frameDistortions.clear();
frameDistortions.addAll(VfxDistortionProjector.project(
        vfxDistortions, projection, view));
```

## 输入输出与空间

| 项目 | 内容 |
|---|---|
| 颜色输入 | `PostProcessTargets.VFX_COMPOSITE_COLOR`（RGBA16F，VFX composite 已写入的 HDR 合成色）。 |
| 深度输入 | `PostProcessTargets.VFX_SCENE_DEPTH`（VFX composite 从 geometry pass blit 的 scene depth 纹理）。 |
| 颜色输出 | `PostProcessTargets.SCREEN_DISTORTION_COLOR`（RGBA16F，独立附件）。读取与写入附件不同，绝不采样正在写的图像。 |
| 坐标 | UV 与 `gl_FragCoord.xy / viewport` 一致（原点左下）；`effectDepth` 为 NDC 深度映射到 `[0,1]`；`extentUv` 由 world radius 经相机 right/up 轴投影。 |
| 颜色空间 | 线性 HDR，位于 tone mapping 之前；只改变采样 UV，不改变 HDR 数值范围。 |
| 分辨率 | 与 graph 颜色附件一致；不做降采样。 |
| 时域语义 | 无历史；热浪相位来自贡献的显式 `phase`，同输入同时间可重复。 |

## Pass 顺序与透明顺序合同

```
Geometry → (MSAA resolve) → Fog → HDR VFX composite
        → ScreenDistortion  (读 vfxCompositeColor + vfxSceneDepth，写 screenDistortionColor)
        → Reactive → TAA → AutoExposure/Bloom → ToneMapping → Vignette → FilmGrain → Chromatic Aberration → FXAA/Present → UI
```

- 透明几何与 VFX primitive 已经合成进 VFX composite 的颜色，因此会被扭曲；不会在透明提交过程中按 primitive 单独扭曲。
- 重叠顺序：贡献先按 `effectDepth` 远到近排序，深度相同按 `(effectId,distortionIndex)` 稳定排序；合成时较近的 mask 覆盖较远的 mask。超过 `maximumContributions` 时保留最近的贡献，丢弃最远的，保证 bounded uniform 载荷。
- 重复 `(effectId,distortionIndex)` 身份在投影与合成前明确拒绝，避免顺序歧义。
- UI 与 `finalPassName` 之后的宿主合成不在扭曲范围内。

## 深度/前景拒绝与 UV 边界

- 前景拒绝：`sceneDepth < effectDepth - depthThickness` 的像素直接跳过该贡献，前景物体不会被后面的冲击波拉动。画面背景（`sceneDepth=1`）比效果平面更远，允许被热浪扭曲。透明遮挡物不在深度图内，属于公开限制。
- UV 边界：`edgeFeatherUv` 在四周用 smoothstep 把 mask 衰减到 0；若 `uv + offset` 仍越出 `[0,1]`，回退到原始 UV（丢弃该像素偏移），而不是 clamp 采样造成边界拖影；范围内采样再 clamp 到半 texel，避免双线性采到图像外。
- 偏移总长度受 `maximumOffsetUv`（默认 0.02，最大 0.1 UV）约束，单轴 authored offset 上限 0.25 在数据层拒绝。

## 资源、事务与失败

| 项目 | 内容 |
|---|---|
| GPU owner | `ScreenDistortionPass`（shader + quad）；`PostProcessPipeline.owned` 随候选代关闭，候选可复用 donor owner。 |
| 准备/发布 | 只有 `ScreenDistortionSettings.active()` 时构造 owner 并添加 Pass；装配失败随 `PostProcessPipeline.assemble` 的 candidate-first 规则关闭已建资源。 |
| 默认关闭 | `ScreenDistortionSettings.disabled()` 不创建 Pass、shader 或附件，Pass 图与颜色链和引入前完全一致（exact no-op）。 |
| 非法组合 | 启用但 LDR（无 HDR tone mapping）或没有 HDR VFX composite 时装配期抛 `IllegalArgumentException`，不静默忽略。 |
| 退役/resize | 无独立历史与自持附件；附件由 RenderGraph 按 Pass 生命周期管理，resize 走既有候选图重建。 |
| 关闭 | `close()` 释放 shader/quad；source 是纯数据合同，不持有 GPU 资源。 |

## 成本与质量档

- 每次启用一次全屏 draw、两次纹理采样（颜色 + 深度）和最多 `maximumContributions`（默认 4、上限 8）次循环；无额外附件历史。
- 无 Low/Medium/High 三档：首版只有一个有界保守配置（默认 0.02 UV、4 层、0.05 边缘羽化），符合"不把全开当默认"的保守范围。
- 未做正式性能测量；不得据本卡宣称 GPU 预算或帧率收益。

## 已知限制与后续

1. 逐帧输入目前必须经 `PostProcessSettings.screenDistortion.source` 注入；`RenderPipeline` 缺少与 `vfxLights(...)` 对称的 `vfxDistortions(...)` 入口（本 Worker 不得修改 `RenderPipeline`）。接入时只需把 controller/source 挂到管线，无需改动本 Pass。
2. `VfxDistortion` 尚未挂到 `EffectSnapshot`/`EffectAsset`；效果资产暂不能声明扭曲图层，需装配层显式提交贡献。
3. 透明遮挡物不进入 scene depth；强透明前景可能被热浪拖动，需后续用独立深度/Stencil 方案扩展。
4. 热浪噪声为无 bandlimit 的屏幕 hash，强参数下可能出现采样带；无时域抖动。
5. MSAA 路径下扭曲发生在 resolve 之后，仅作用于最终一次采样，不参与 per-sample 着色。
