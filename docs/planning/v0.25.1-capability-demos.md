# v0.25.1 最小能力验证 Demo 设计

日期：2026-10-24。状态：实施规格，尚未实现。本文所有新类名、任务名和 CLI 参数均为拟定接口；实现并验证后才能在使用指南中标记为可运行。

配套主规划：[v0.25.1 风格化场景控制](v0.25.1-stylized-scene-control.md)。本文替代原酒馆/森林综合场景 Demo 交付方案，不改变主规划中的区域公式、材质语义和资源所有权合同。

## 1. 交付原则与范围

**每实现一个功能，必须同时写入一个独立、最小、可交互的能力验证 Demo。缺少对应 Demo，功能不算交付完成。** JVM 和 GL 测试仍负责自动判断正确性，Demo 负责让实际能力可见、可操作、可复现；二者不能互相替代。

- 一个入口聚焦一个能力，可以包含该能力的多个边界 case，不要求每个参数各开窗口。
- 默认画面只放必要几何、灯和背景。不引入街道、建筑群、森林等资产前置，也不以建模美化作为验收条件。
- 不要求先运行或完成别的 Demo。已有综合场景保留，但不挂入本版默认验收依赖。
- 小 Demo 必须调用与正式使用相同的生产路径，禁止在 Demo 里重写混合器、BRDF、阴影或历史状态。
- 开发功能时同步添加输入、入口及可见证明；M4 只负责检查交付是否完整。
- 本版核心共五个 Demo。资源修复、风动、DOF 等如果纳入实际交付，另加对应 Demo；不能因本文件给出规格就暗中扩大版本范围。

| ID | 功能及拟定入口类 | 拟定可见任务 | 首次交付阶段 |
| --- | --- | --- | --- |
| D01 | `Render3dVisualScalarsDemo`：显示标量更新 | `runRender3dVisualScalarsDemo` | M2 |
| D02 | `Render3dVisualRegionsDemo`：空间区域混合 | `runRender3dVisualRegionsDemo` | M2 |
| D03 | `Render3dVisualConfigDemo`：配置保存/原子重载 | `runRender3dVisualConfigDemo` | M2 |
| D04 | `Render3dMaskCoverageDemo`：跨 pass 裁剪一致 | `runRender3dMaskCoverageDemo` | M3，先于薄叶 |
| D05 | `Render3dThinLeafDemo`：静态薄叶背光 | `runRender3dThinLeafDemo` | M3 |

M1 可以先只完成纯 CPU 合同和 D02/D03 的输入文件，不为纯算法检查启动 GL。此时记录为“内部检查点完成”，不能写“功能已验收”。

## 2. 共享实现边界

入口类放在现有 `src/demo/java/com/kaleblangley/haikalat/demo/pbr/`，资源放在 `src/demo/resources/config/capabilities/v0251/`；测试放在现有对应 JVM/integration 包。采用小型 case factory，每个 Demo 独立创建和关闭自己的 scene/pipeline。

复用现有窗口、FrameDriver、资源装配、UI、捕获与 diagnostics。可提取小工具共享固定相机、输出目录、截图和关闭流程；不新建通用 Demo 引擎、全局 Scene 单例或第二套成功帧管理器。两个视图必须有各自 pipeline/历史，不能用反复修改一个 pipeline 的相机冒充隔离。

所有入口至少提供：

1. 一句话目标与当前 case；默认启动即能看到目标内容。
2. 效果 ON/OFF 或有效参考模式；每次只改变目标能力，固定相机、曝光和其他资源。
3. 仅暴露该能力需要的参数；重置、暂停、逐帧、固定回放和截图按钮。配置读写功能集中在 D03，其余入口仅在确有作者配置时提供保存/重载。
4. 渲染输入的实际诊断值，不以 UI 滑块缓存值冒充已生效值。UI 不暴露 native texture ID、屏障或内部绑定槽。
5. 可见交互与有限帧 capture 两种运行方式；capture 可以隐藏窗口，但必须使用真实 GL 上下文和生产管线。

拟定公共参数：`--case=<id>`、`--capture`、`--frames=<n>`、`--size=640x360`、`--seed=251`、`--output=<path>`。未识别参数、非法帧数和未支持 case 应明确失败，不静默降级。可见模式默认 960×540，无需自动退出；capture 默认 640×360，所有 case 有固定结束点，不等待人工点击。

自动回放使用固定时间步和成功帧序号。截图明确区分 scene output 与带 UI 的说明图；UI 不进入像素比较 ROI。新 capture 模式不得反向改变正常帧的时间、资源或历史提交语义。

## 3. 五个核心 Demo

### D01：显示标量更新

**只证明：曝光、Bloom 和已支持 LUT intensity 能正确、独立地更新显示输出。**

场景：固定相机、黑/中灰/白三个 HDR 标靶、一个高亮发光小块。使用稳定的自发光或固定环境照明保证无方向光时也有输入；不摆建筑或加入雾。固定 MANUAL 曝光，Bloom 目标预先分配。未支持 LUT 标量时明确标记“不支持”，不能保留无效滑块。

操作：调节全局曝光和 EV 补偿；调 Bloom intensity；如已支持则调同一个 LUT 的 intensity；切换目标参数与基准值。显示基值、补偿、最终曝光、generation ID 和历史失效原因。

固定 case：

- `exposure`：EV 为 -1/0/+1，独立 CPU 期望为基值乘 0.5/1/2；像素检查使用约定输出阶段与 tone mapper，不能要求 tone-mapped PNG 亮度恰好翻倍。
- `bloom`：同一高亮块，intensity=0 与有效值；块外 ROI 出现可解释的光晕差异，黑色远区保持允许误差内。
- `grading`：仅在已实现时运行同 LUT intensity 0/1 对照。
- `no-sun`：场景始终没有方向光，参数可用，未隐式新增灯。

通过：改变了实际输出；标量更新不重建 generation、不每次清历史、不污染全局基值。默认 48 帧含预热与取样；输出每个 case 的参数表及对照图。

### D02：空间区域混合

**只证明：按相机位置解析区域权重并正确应用到各自视图。**

场景：坐标地面、一个固定材质标靶、两个线框区域（球和 AABB）。区域线框为诊断叠层，不写 SceneDepth、不投影、不影响自动指标。提供侧视示意和实际相机位置，避免相机处于区域内部时看不出边界。

操作：相机沿固定直线往返；单独修改 priority、weight、blendDistance 和 override enabled；暂停查看来源。画面旁显示每个 stableId 的有效权重、逐字段基值及最终值。

固定 case：

- `boundary`：外壳外、外壳中、实体内及返回；正 blendDistance 连续，零 blendDistance 按硬边界合同跳变。
- `overlap`：固定 A/B 各 0.5 权重，使用主规划的 EV=0 与 EV=0.75 独立期望；交换优先级不能只改变 UI 文本。
- `missing-override`：B 只覆盖 Bloom，不覆盖 EV；B 不得把 A 的 EV 清零。
- `two-view`：两个独立视图位于不同区域，分别展示最终值；相同全局基准不能被某一视图的 resolved 值改写。
- `history-and-fog`：仅此 case 加入一个小世界雾盒，固定其参数；120 帧边界往返中，区域变化不改物理介质，不无故重建代次或清历史。画面允许随曝光变化，不能要求雾的显示颜色完全不变。

通过：CPU 独立期望、真实输出、代次及历史诊断相互对应。单个 capture 默认 120 帧；在规定取样点截屏，无需保存所有帧。

### D03：配置保存与原子重载

**只证明：作者配置能准确保存、完整校验并在帧边界原子发布。**

场景：一个区域和一个标靶，复用 D02 的简单几何构造工具，但有独立入口。面板分开显示“编辑中”和“已应用”的值、profileId、区域 stableId、配置修订号和错误字段。

操作：保存、修改、重载、恢复初始值；提供明确按钮加载有效配置、重复 stableId、非法数值、未知字段四个 fixture。测试写入本次输出目录的临时副本，禁止改仓库源配置或用户其他文件。

固定序列：基准 → 合法更新 → 保存 → 改动 → 重载恢复 → 非法配置拒绝 → 再次合法更新恢复。每个失败点检查 live region set、全局基值、已用资源及画面保持上一有效状态。错误信息指出具体字段，不能仅显示“失败”。

通过：未填 override 在保存/重载后仍未填写；无部分应用；之后仍可更新。默认 48 帧，输出配置副本、事件结果和前后图。内存 getter 一致不足以单独判定画面正确。

### D04：MASK 跨 pass 一致性

**只证明：颜色、共享表面深度和阴影对同一表面的可见区域一致。**

场景：一块 MASK 卡片、接影平面、卡片后方高对比标靶。准备 texture alpha、factor alpha、vertex alpha 和三者相乘四类 case，包含 cutoff 两侧的确定像素；采用同一张小尺寸自有纹理，几何布局固定。

操作：切换输入因子、cutoff、卡片正反面及镜像变换；切换方向/点/聚光单灯模式；显示最终颜色、SceneDepth、SceneNormal/Validity 和阴影预览。未分配相应阴影资源时必须明确失败或列为未测，不能用无阴影画面判通过。

重点复现：纹理与 factor alpha=1，顶点 alpha 低于 cutoff。后方标靶必须从洞中可见，该处不得留下卡片深度或卡片阴影。先完成这个生产修复，再启用薄叶扩展。

通过：按相机/灯投影分别计算预期覆盖区域，检查洞内、实体内部与边缘；阴影边缘考虑已声明过滤半径，不能直接对不同视角的整张截图逐像素相等。普通 OPAQUE 与没有顶点颜色的材质保持原行为。

默认每个指定 case 24 帧。一次改动选择相关因子和受影响 pass，不自动展开所有 alpha×灯×AA×分辨率组合。新功能收口至少保留四类 alpha 输入及实际受影响阴影路径的证据。

### D05：静态薄叶背光

**只证明：薄叶背光项、双面和有效阴影按既定材质合同工作。**

场景：单张双面 MASK 叶片、一块可移入光路的遮挡板、一个未开启薄叶的普通 PBR 对照物和接影地面。叶片使用自有小 alpha 纹理，不依赖树木或森林模型。默认关闭 Bloom 与体积雾，固定曝光。

操作：旋转灯方向、切正面/背面相机、切方向/点/聚光、调 transmissionColor/strength、启停遮挡板和扩展。每次一种灯，避免无法定位贡献来源。

固定 case：

- `front-back`：正光/背光、前后面分别留图；strength=0 与启用后对照。
- `shadow`：遮挡板进入光路时背光项遵守实际分配的阴影。
- `light-off`：目标灯关闭后，新增背光贡献消失；既有 IBL 可仍存在。
- `material-isolation`：交错提交两种不同薄叶参数和普通材质，包括正式支持的实例路径，不能被第一种材质污染。
- `disabled-baseline`：扩展关闭时普通 PBR 输出回到容差内基准，不改基准掩盖回退。

通过：目标 ROI 与独立背光公式/关闭对照一致，D04 coverage 仍成立。单个 case 默认 48 帧；正反、三种灯及隔离证据按阶段产生，不重复运行无关矩阵。风动不是静态薄叶的必做前置。

## 4. 有限帧验收与证据

每个可见任务配一个有限运行的 `<可见任务名去掉Demo>Capture` 任务，例如 `runRender3dVisualRegionsCapture`。任务名称在实现时核对冲突后统一登记；这里不提供假装已经可执行的命令。

- capture 只负责执行、取样和归档，另由定向断言判断通过；“文件生成成功”不等于正确性通过。
- 默认只跑当前改动涉及的 Demo/case。UI 交互入口不得成为 `acceptance` 的依赖，防止等待关闭窗口。
- 所选编译、定向测试和 capture 共用 300 秒总时限；零自动重试。可见人工操作时间不计作自动验收执行时间。
- 先检查新增任务依赖一次，不能间接拉起全量 GL、历史 benchmark 或长 soak。
- capture 的默认帧数含预热，不以帧数代替截止时间；历史模式切换后使用固定重置/预热协议。首次确认预热足够后冻结，不为单次失败临时增加。
- 必需项未运行、像素检查失败、GL 错误、超时及非预期跳过分别记录。可选未实现项标记 `NOT_IMPLEMENTED`，不能标成 `PASS`。
- 控制渲染态的数字用 CPU 合同断言；像素阈值要注明阶段、单位和 ROI，依据独立期望或冻结参考制定。禁止用“图片有变化”作为唯一条件，禁止失败后临时放宽阈值。
- GPU 读回只在 capture 取样点或显式预览时执行，不引入常态每帧 readback/glFinish。资源计数来自现有诊断，不伪称 GPU 时间测试。

建议产物目录：`build/reports/render3d-v0251/<demo-id>/<run-id>/`，包含：

| 文件 | 内容 |
| --- | --- |
| `report.json` | schema、功能/case、runId、HEAD/工作树指纹、执行起止、实际帧数、设备/尺寸/AA/seed、PASS/FAIL/TIMEOUT/NOT_RUN 等状态及原因 |
| `inputs.properties` | 本次实际使用输入与支持选项，不能只复制未应用的 UI 值 |
| `events.json` | 参数变化、有效区域/权重、代次与历史原因；按 case 需要记录，不造每帧大对象快照 |
| `baseline.png`、`enabled.png`、`roi-*.png` | 明确捕获帧、输出阶段、相机和输入；命名可按 case 扩展 |
| `metrics.json` | 独立期望、观测值、ROI、容差和逐条结论；未测性能明确写明 |

每项新增可见效果至少人工查看一次实际输出及关键 ROI；保存 capture 成功与人工已查看为两个独立事实。重复截图相等只能证明稳定性，不证明算法正确。最终报告可复用代码/输入/合同未变的已完成证据，注明其身份，不为整理文档重跑渲染。

## 5. 可选功能的独立 Demo

以下不计入核心五个必交付 Demo；只有相应功能实际纳入版本时才成为交付要求。

| 功能 | 拟定 Demo | 最小证明 |
| --- | --- | --- |
| 透明变体与资源失败清理修复 | `Render3dVariantLifecycleDemo` | 两个透明 quad，有限次替换材质/场景，显示实际编译次数和当前/峰值资源数；替换后能回收，失败保留旧画面。构造失败注入仅在测试桥接中提供，不扩展生产 API |
| 叶片几何风动 | `Render3dLeafMotionDemo` | 单叶、地面和固定运动；对照颜色/深度/阴影/velocity，暂停逐帧与失败恢复，上一成功变形不提前推进 |
| 景深 | `Render3dDepthOfFieldDemo` | 近中远三个标靶、前景细边；显示焦平面与 CoC，检查漏色和关闭基准；不依赖薄叶或区域开启 |

局部反射、局部环境光、阴影扩容和新的体积细化预算不因本 Demo 重写自动进入 0.25.1。将来实施这些功能时沿用“一功能一最小 Demo”原则。
