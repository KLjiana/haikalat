# v0.18.3 动画运行时、约束与 Morph Target 实施计划

> 状态：已完成（2026-07-27）
>
> 目标版本：`0.18.3`
>
> 基线版本：`0.18.2`
>
> 版本主题：在现有 Clip、Player、双层 Mixer、Bone Mask、Cross-fade、Root Motion、
> Animation Event、Two-bone IK 与 glTF GPU 蒙皮之上，建立可组织完整角色战斗动画的运行时，
> 补齐状态机、Blend Tree、Additive 多层、同步标记、通用约束、Morph Target 和结构化性能门禁。

## 1. 版本定位

v0.18.0～v0.18.2 已经完成动画的基础采样和单角色证明：

- `AnimationClip` 支持 STEP、LINEAR 和 glTF CUBICSPLINE TRS channel；
- `AnimationPlayer` 支持 LOOP/ONCE、pause/resume、seek、playback speed、事件和循环根运动；
- `AnimationMixer` 支持 base + 单 layer、Bone Mask、归一化同步、base cross-fade 和 layer fade；
- `PoseBuffer/PoseBlender` 支持无 GL 的可复用姿态求值；
- `TwoBoneIkSolver` 支持直接 root-middle-tip 链、不可达目标夹取和部分权重；
- glTF skin、inverse bind matrix、joint palette、PBR pass 和 directional shadow pass 已完成 GPU 蒙皮闭环。

当前短板不是“不能播放动画”，而是缺少把这些能力编排成完整角色运行时的结构：

```text
业务代码手动调用 play/transition/fade
        |
        v
AnimationMixer（base + 单 layer）
        |
        v
TwoBone IK（单一直接链）
        |
        v
JointPalette / GPU skinning
```

v0.18.3 将这条链扩展为：

```text
Typed Parameters / Triggers
        |
        v
Animation Graph + State Machine
        |
        +--> Clip Motion
        +--> BlendTree1D
        `--> Explicit-triangle BlendTree2D
        |
        v
Base Pose + Ordered Override/Additive Layers
        |
        v
Sync Markers / Events / Root Motion
        |
        v
Ordered Constraint Stack
  Look-at / Joint Limit / FABRIK / Two-hand / Foot Target
        |
        v
PoseBuffer + Morph Weight Output
        |
        +--> JointPalette / PBR skinning / shadow skinning
        `--> Morph Target GPU deformation
        |
        v
Animation Diagnostics / Performance Gates
```

本版本不建设可视化动画编辑器，不引入 ECS，不让 animation subsystem 查询物理世界，也不做骨架重定向。
目标是形成稳定、可测试、可批量运行的角色动画 runtime。

1. 建立 immutable graph definition 与 per-character mutable controller instance。
2. 支持 bool、float、int、trigger 参数和确定性 transition condition。
3. 支持普通 state、entry state、Any State、exit time、transition easing 和明确的 interruption policy。
4. 支持 `ClipMotion`、`BlendTree1D` 和显式三角形 `BlendTree2D`。
5. 支持最多 8 个有序 animation layer，每层可选 Override 或 Additive。
6. Additive 支持 bind pose 和显式 reference pose 两种参考来源。
7. Bone Mask、layer weight、fade curve 和 transition weight 正确组合。
8. 支持动画 marker、sync group、事件来源信息和无反向依赖的 VFX 桥接证明。

11. Morph 在 vertex shader 中先于 skinning 应用，并同时覆盖 PBR 与 directional shadow。
12. Morph 权重是 per-instance 状态，不允许写入共享 scene asset。
13. 建立 animation diagnostics、批量 benchmark、allocation gate、失败回滚和生命周期验证。
14. 提供独立 Animation Demo、Morph glTF fixture 和 Showcase 综合证明。
15. `AnimationPlayer`、Graph state 和 Blend Tree child 支持负 playback speed，事件、marker 和 root motion
    在倒放及跨循环时保持确定性。

### 3.2 应当完成

- transition destination time offset；
- transition 排队；
- state enter/exit signal；
- playback speed parameter binding；
- sync marker interval 内的 phase matching；
- layer 自动移除和句柄式控制；
- additive root motion 的显式策略；
- constraint warm-start；
- constraint iteration/error diagnostics；
- morph conservative bounds；
- morph zero-weight fast path；
- state/motion/layer/constraint 的稳定整数 runtime index；

### 3.3 明确排除

v0.18.3 不做：

- 骨架重定向、Humanoid avatar、自动 joint-name mapping；
- reference pose 跨骨架转换、身高或肢体比例补偿；
- AnimationGraph 可视化编辑器、节点画布或资源热重载；
- JSON/YAML graph schema；第一版只提供 Java Builder；
- motion matching、机器学习动画、姿态搜索数据库；
- full-body branching IK、物理 ragdoll 或动画物理混合；
- animation subsystem 内部 raycast、导航、碰撞、网络同步或实体查询；
- glTF second joint set、8-weight skinning；
- compute shader morph、GPU animation sampling 或 GPU pose graph；
- Vulkan、第二渲染后端、ECS 或 Gradle 多模块拆分。

## 4. 架构原则

### 4.1 依赖方向

保持：

```text
demo/runtime orchestration
        |
        +--> subsystems.animation
        +--> subsystems.vfx
        +--> subsystems.render3d.gltf
                    |
                    v
                  core
                    |
                    v
                 backend
```

禁止：

```text
animation -> VFX
animation -> render3d
animation -> backend/OpenGL
animation -> scene physics/navigation
```

Animation/VFX 联动由上层读取 animation signal，再调用 VFX API。animation 只输出纯值 signal 和 joint/socket
信息，不持有 `EffectAsset`、`EffectInstance`、`Mesh`、texture 或 RenderGraph handle。

### 4.2 Definition 与 Instance

所有可共享内容属于 immutable definition：

- graph topology；
- state/motion definition；
- transition condition；
- clip；
- blend thresholds/triangles；
- Bone Mask；
- marker/sync metadata；
- constraint definition；
- morph target CPU data。

所有逐角色变化属于 instance：

- 当前 state；
- parameter values 和 trigger bits；
- state time 与 transition cursor；
- layer runtime；
- event/marker cursor；
- constraint targets 和 warm-start 数据；
- PoseBuffer；
- morph weights；
- diagnostics counters。

共享 definition 不得被运行实例修改。

### 4.3 热路径不使用字符串查找

Builder 可以接受名称，但 `build()` 后必须编译为稳定整数 index：

- parameter name → parameter index；
- state name → state index；
- transition source/target → state index；
- motion child → motion index；
- marker name → marker/sync index；
- joint name → joint index。

运行时允许名称只出现在 diagnostics 和错误信息中。每帧 evaluation 不做 Map lookup、正则匹配或反射。

### 4.4 确定性

相同 definition、初始参数、fixed delta 和 signal 输入必须得到：

- 相同 state/transition 序列；
- 相同 PoseBuffer local/global transform；
- 相同 root motion；
- 相同 marker/event 顺序；
- 相同 layer/constraint/morph 权重；
- 相同 diagnostics counter。

不得使用 wall clock、线程调度顺序或无序 Map iteration 决定动画结果。

## 5. Animation Graph 与状态机

### 5.1 公共定位

建议新增：

```java
AnimationGraph
AnimationController
AnimationMotion
ClipMotion
BlendTree1D
BlendTree2D
```

`AnimationGraph` 是 immutable definition；`AnimationController` 是 per-character runtime。
`AnimationMixer` 和 `AnimationPlayer` 保留，不删除、不弃用，继续作为直接控制和简单场景 API。

### 5.2 Parameter

支持四种参数：

```java
enum ParameterType {
    BOOLEAN,
    FLOAT,
    INTEGER,
    TRIGGER
}
```

约束：

- parameter name 非空且唯一；
- float 必须有限；
- trigger 是单次消费 bit，不等价于 boolean；
- transition 未选择时 trigger 不消费；
- 同一 update 只允许实际选中的 transition 消费其 trigger；
- runtime setter 验证类型；
- graph build 后使用整数 slot。

`AnimationController` 至少提供：

```java
setBoolean(String name, boolean value)
setFloat(String name, float value)
setInteger(String name, int value)
fireTrigger(String name)
resetTrigger(String name)
```

可增加 index-based advanced API，但名称 API 只在 setter 边界解析一次，不在每 joint/channel 热路径使用。

### 5.3 State

每个 state 包含：

- 唯一名称；
- `AnimationMotion`；
- playback speed 或 float parameter binding；
- LOOP/ONCE；
- 可选 sync group；
- 可选 enter/exit signal；
- 可选 normalized start offset。

Playback speed 允许有限负值。`0` 表示保持当前采样时间但不推进；负值表示倒放。倒放 ONCE state 到达
`0` 后停止，倒放 LOOP state 从 `0` 包回 duration。

Graph 必须恰好有一个 entry state。无 motion、重复 state、未知 parameter/target、非法 speed 和空图在
`build()` 时失败。

### 5.4 Transition

Transition 至少支持：

- source state；
- destination state；
- Any State；
- condition 列表；
- `all` 语义；
- normalized exit time；
- duration seconds；
- `Curve1f` easing；
- destination normalized offset；
- declaration-order priority；
- interruption policy；
- 可选 queued transition。

建议 interruption：

```java
enum InterruptionPolicy {
    NONE,
    SOURCE,
    DESTINATION,
    ANY
}
```

语义：

- 每次 update 最多启动一次新 transition；
- 同优先级按声明顺序；
- zero-duration transition 在当前 update 立即完成；
- transition 中重定向必须从当前已混合 pose 开始，不能跳回旧 source pose；
- destination state 的事件/marker cursor 从 destination offset 开始；
- outgoing state 仅维持 pose/root motion 连续性，不重复发布离开区间事件；
- queued transition 只能在当前 transition 完成后启动；
- 大 delta 跨越 exit time、loop boundary 和 transition end 时必须确定性处理。

### 5.5 Controller 输出

Controller update 输出至少包括：

- 最终 base pose；
- `RootMotionDelta`；
- 有序 signal；
- 当前/目标 state index；
- transition normalized weight；
- motion child weights；
- diagnostics update。

不得为每次 update 创建完整 immutable `Pose`。生产路径写入调用方或 instance-owned `PoseBuffer`。

## 6. Blend Tree

### 6.1 ClipMotion

`ClipMotion` 包装一个现有 `AnimationClip`，保留：

- LOOP/ONCE；
- playback speed；
- event/root motion；
- clip duration；
- normalized phase。

不得复制 Clip 内部 channel 数组。

### 6.2 BlendTree1D

适用于 Idle/Walk/Run、慢走/快跑和单轴瞄准。

合同：

- 一个 float parameter；
- 至少两个 child；
- threshold 严格递增；
- parameter 低于/高于范围时夹到边界 child；
- 区间内只激活相邻两个 child；
- weight 有限、非负且和为 1；
- child 可以是 ClipMotion 或嵌套 Blend Tree；
- root motion、events、marker phase 和 morph weight 使用同一 child weight。

### 6.3 BlendTree2D

适用于 moveX/moveY 方向移动和二维 aim offset。

第一版不自动做 Delaunay triangulation。Builder 要求调用者显式提供三角形：

```text
child: (x, y, motion)
triangle: (childA, childB, childC)
```

合同：

- child 坐标有限且不重复；
- triangle 面积非零；
- triangle 引用有效 child；
- 参数位于三角形内时使用 barycentric weight；
- 位于 hull 外时投影到最近 hull edge；
- 相同距离按 triangle declaration order；
- 最多三个 active child；
- weight 和为 1；
- graph build 时检查孤立 child 和明显重叠/退化 triangle。

### 6.4 Phase 与速度

Blend Tree child 默认以 normalized time 同步。若配置 sync marker，则以 marker interval phase 同步。

禁止简单地将不同长度 clip 的 seconds time 强行相等。无 marker 时：

```text
childTime = normalizedStatePhase * childDuration
```

root motion 使用各 child 自己区间的 delta，再按最终 motion weight 混合。

## 7. 多层与 Additive Animation

### 7.1 Layer Stack

建议新增 `AnimationLayerStack`，默认上限 4，允许显式配置到 8。

每层包含：

- stable layer index/name；
- motion 或 controller；
- `OVERRIDE`/`ADDITIVE`；
- weight；
- Bone Mask；
- fade state；
- priority/order；
- root motion policy；
- event policy；
- remove-on-complete。

层按稳定 index 从低到高合成。不得按 hash、最近修改时间或对象 identity 排序。

### 7.2 Override

Override 沿用现有 PoseBlender 语义：

```text
effectiveWeight = clamp(layerWeight * boneMaskWeight, 0, 1)
```

translation/scale 使用线性插值，rotation 使用 shortest-path normalized quaternion blend。

### 7.3 Additive

Additive delta 相对 reference pose 计算：

```text
translationDelta = sample.translation - reference.translation
rotationDelta    = sample.rotation * inverse(reference.rotation)
scaleRatio       = safeDivide(sample.scale, reference.scale)
```

应用到当前 pose：

```text
translation += translationDelta * effectiveWeight
rotation     *= slerp(identity, rotationDelta, effectiveWeight)
scale       *= lerp(vec3(1), scaleRatio, effectiveWeight)
```

约束：

- reference scale 分量接近零时 build 失败；
- quaternion 必须有限并归一化；
- weight 和 mask clamp 到 `[0,1]`；
- reference 可以是 bind pose 或同 skeleton 的显式 Pose；
- 不接受其他 Skeleton 的 reference；
- destination 可以与 layer scratch alias，但不能破坏 base pose。

### 7.4 Layer 生命周期

提供：

- immediate play/replace；
- fade in/out；
- pause/resume；
- weight target；
- remove-on-complete；
- cancel；
- diagnostics handle。

同一层中途重定向时从当前合成权重继续，不允许 weight 突跳。

### 7.5 Layer Root Motion

默认只有 base graph 贡献 root motion。Layer 必须显式选择：

```java
enum LayerRootMotionMode {
    IGNORE,
    ADDITIVE,
    OVERRIDE
}
```

`ADDITIVE` 使用 layer effective weight；`OVERRIDE` 仅适用于全身 mask，否则 build 失败。

## 8. Marker、Sync Group 与 VFX 桥

### 8.1 Event 与 Marker 分工

保留现有 `AnimationEvent`：

- 离散业务信号；
- 可以携带 payload；
- 依照时间区间发布。

新增 `AnimationMarker`：

- 用于 gait/attack phase；
- 名称和 time；
- 不承担任意业务对象引用；
- 同名 marker 可在一个 clip 中重复；
- build 后按 `(time, declarationOrder)` 稳定排序。

典型 marker：

```text
foot-left
foot-right
attack-windup
attack-hit
projectile-release
recover
```

### 8.2 Sync Group

Sync group 用于 Walk/Run 等不同长度 clip 的语义相位对齐。

算法：

1. 找到当前 time 前后的 marker interval；
2. 计算 interval 内 phase；
3. 在 destination clip 查找同名 interval；
4. 将 phase 映射到 destination interval；
5. 缺失匹配时回退 normalized clip phase，并记录 diagnostics。

必须覆盖：

- loop boundary；
- 同名 marker 重复；
- source/destination marker 数不同；
- reverse playback；
- seek；
- 大 delta；
- cross-fade 中途重定向。

倒放事件按实际遍历方向从较晚时间到较早时间发布。反向跨 loop 时先发布 `[0, previous)`，再发布
`(current, duration]`；同一 timestamp 继续使用 declaration order。反向 root motion 必须等于对应正向
区间 delta 的逆变换，不能只把 translation 乘以 `-1`。

### 8.3 Signal

Controller 输出统一纯值 signal：

```text
STATE_ENTER
STATE_EXIT
EVENT
MARKER
TRANSITION_START
TRANSITION_COMPLETE
LAYER_COMPLETE
```

每个 signal 至少含：

- sequence；
- graph/layer source；
- state/motion name；
- normalized time；
- event/marker name；
- payload；
- loop index。

signal 队列有界。超过容量时不得静默覆盖 HIGH-priority attack-hit 类信号；应记录 dropped count，并允许
调用方设置容量。

### 8.4 VFX 桥接

VFX 桥放在 demo/runtime orchestration，不放在 animation：

```text
AnimationController.drainSignals()
        |
        v
CharacterEffectBridge
        |
        +--> query PoseBuffer joint/socket transform
        +--> EffectInstance.spawnMesh(...)
        +--> EffectInstance.beam(...)
        +--> spawn particle/decal
        `--> optional camera/UI feedback
```

验收场景：

- `attack-windup` 启动 MeshVfx 能量外壳；
- `attack-hit` 生成 impact particle、Mesh 冲击环和地面 Decal；
- `projectile-release` 从 weapon joint 建立 Beam 起点；
- signal 与 VFX 使用固定 seed，重复运行 snapshot 相同；
- animation/VFX 之间没有反向 package dependency。

## 9. 约束与 IK

### 9.1 求值顺序

固定：

```text
graph/base motion
    -> override/additive layers
    -> root motion extraction/removal
    -> ordered constraints
    -> global matrices
    -> joint palette
```

Constraint 不得在 palette upload 或 render pass 中修改 PoseBuffer。

### 9.2 Constraint Stack

建议新增：

```java
AnimationConstraint
AnimationConstraintStack
ConstraintContext
ConstraintDiagnostics
```

`ConstraintContext` 只包含纯值输入：

- target transform/position；
- pole vector；
- weight；
- delta seconds；
- iteration limit/tolerance；
-可选 previous solution。

不包含 Scene、PhysicsWorld、Window、Camera、Mesh 或 GL handle。

### 9.3 Look-at / Aim

支持：

- 指定 joint；
- local forward/up axis；
- model-space target；
- yaw/pitch limit；
- weight；
- optional parent-space offset；
- degenerate target fallback。

目标与 joint 重合、up 与 direction 平行、非有限 target 必须有明确错误或稳定 fallback。

### 9.4 Joint Limit

第一版支持：

- hinge min/max；
- swing cone；
- twist min/max；
- local reference rotation；
- soft weight。

Joint limit 在每次 solver iteration 后应用。limit 定义属于 immutable constraint definition。

### 9.5 FABRIK

新增多关节 chain solver：

- chain 至少 3 个 joint；
- joint 必须构成真实连续祖先链；
- 固定最大 iteration，默认不超过 16；
- tolerance 必须有限正值；
- unreachable target 使用完全伸展；
- reachable target 使用 forward/backward iteration；
- 支持 pole correction；
- 支持 per-joint limit；
- 支持 partial solve weight；
- 输出 requested/solved distance、iterations、residual 和 clamped 状态。

不支持一个 solver 同时处理分叉全身骨架。

### 9.6 双手武器

双手约束作为组合能力：

1. 主手由动画或角色 transform 决定武器；
2. 上层计算副手 model-space target；
3. 副手 arm chain 使用 Two-bone 或 FABRIK；
4. optional hand orientation constraint；
5. 所有 target 由调用方传入。

animation subsystem 不拥有 weapon entity 或 socket registry。

### 9.7 Foot IK

Foot IK 只接受纯输入：

```text
leftFootTarget(position, normal, weight)
rightFootTarget(position, normal, weight)
pelvisOffset
```

raycast 和地形查询由宿主完成。Animation 负责：

- leg chain solve；
- foot normal orientation；
- pelvis offset 平滑；
- weight fade；
- 最大腿长夹取；
- 左右脚稳定顺序。

### 9.8 TwoBone 兼容

现有 `TwoBoneIkSolver.solve(...)` 保留。新 constraint stack 可以包装它，但不删除静态直接 API。

## 10. Morph Target 与 glTF Weights Animation

### 10.1 支持范围

支持 glTF 2.0：

- primitive `targets[]`；
- mesh-level default `weights`；
- node-level weights override；
- animation target path `weights`；
- STEP、LINEAR、CUBICSPLINE；
- POSITION delta；
- NORMAL delta；
- TANGENT xyz delta，保留 tangent handedness w；
- 非蒙皮 morph；
- morph + skinning；
- PBR color pass；
- directional shadow pass。

### 10.2 限制

第一版：

- 每 primitive 最多 8 个 morph target；
- 上限进入 `GltfAssetLimits`；
- 总 morph vertex/delta byte 数有独立预算；
- 不支持 sparse-only 特殊快路径；沿用 accessor 正确 decode；
- 不支持 morph target texture、compute morph 或 mesh shader；
- 不支持 runtime 新增 target；
- 不支持跨不同 topology 混合。

### 10.3 CPU 数据

建议在 `LoadedGltfScene` 增加纯值：

```text
MorphTargetDef
  positionDeltas
  normalDeltas
  tangentDeltas

MorphTargetSetDef
  targets
  defaultWeights
  conservativeBounds
```

要求：

- accessor 类型为 FLOAT VEC3；
- target vertex count 必须与 base primitive 相同；
- delta 必须有限；
- target 数与 weights 数一致；
- node override 数与 target 数一致；
- CUBICSPLINE weights output 按 targetCount 动态计算，不能继续假设固定 3/4 components；
- 错误信息包含准确 JSON path、accessor 和 primitive index。

### 10.4 Morph Track

Morph weight 不塞入 `PoseBuffer`，避免把 joint TRS 与任意 mesh 属性混为一体。

建议：

```java
MorphWeightTrack
MorphWeightBuffer
```

`GltfAnimationRig` 或相邻 glTF animation bundle 同时保存：

- skeletal `AnimationClip`；
- zero or more `MorphWeightTrack`；
- 共用 duration/interpolation/time cursor。

Graph/Blend Tree 对 morph 输出使用与 pose 相同的 motion weight。Cross-fade、BlendTree 和 layer 合成必须同时
作用于 morph weights。

Morph additive layer：

```text
deltaWeight = sampledWeight - referenceWeight
output += deltaWeight * effectiveLayerWeight
```

最终 weight 只要求有限，不强制 `[0,1]`；glTF 允许超出区间。项目可以设置可配置安全绝对值上限防止
恶意资产产生无界变形。

### 10.5 GPU 数据与所有权

建议 runtime owner：

```text
GltfSceneAsset
  `--> GltfMorphTargetBuffer per primitive

GltfSceneInstance
  `--> mutable MorphWeightBuffer per instance
```

Morph delta 使用 SSBO 或等价受控 buffer，不占用大量 vertex attribute locations。

要求：

- buffer 只在 current GL context 创建；
- asset close 时释放；
- instance close 不重复释放共享 delta buffer；
- weight 是 per-instance uniform/UBO/SSBO 数据；
- resize 不重建 morph buffer；
- context epoch 变化遵守现有 GL resource contract；
- partial upload failure 关闭已经创建的 morph buffer。

### 10.6 Shader 顺序

object-space 顺序固定：

```glsl
position = basePosition + sum(positionDelta[target] * weight[target]);
normal   = normalize(baseNormal + sum(normalDelta[target] * weight[target]));
tangent  = normalize(baseTangent.xyz + sum(tangentDelta[target] * weight[target]));

// morph 后再 skin
position = skinMatrix * position;
normal   = skinNormal(...);
tangent  = skinTangent(...);
```

Directional shadow 至少应用 POSITION morph，再执行 skinning。

PBR color pass 应用 POSITION/NORMAL/TANGENT morph，随后重建 bitangent。

zero-target 或 targetCount=0 路径不得绑定 morph buffer。zero-weight fast path 可跳过读取，但必须避免引入
未审计的大量 NVIDIA shader-state specialization。

### 10.7 Bounds 与可见性

仅使用 base mesh bounds 会错误裁剪 morph 后顶点。

canonicalizer 必须根据：

- default weights；
- node override；
- animation keyframe/CUBICSPLINE 已知 weight envelope；
- optional runtime weight safety range；

计算每 target 的 weight min/max，再按 delta 正负贡献形成 conservative local AABB。

若调用方设置超出已声明 envelope 的手动 weight：

- 更新 conservative envelope 并使 scene bounds cache 失效；或
- 将该 primitive 显式降级为 unbounded。

不得继续使用已知过小 bounds。

## 11. 动画性能与诊断

### 11.1 Evaluation Context

新增 per-controller 可复用 evaluation context：

- PoseBuffer scratch；
- motion child weights；
- transition pose；
- layer scratch；
- marker/event cursor；
- root motion scratch；
- constraint global positions；
- morph weight scratch。

容量只增长不缩小。steady-state 不创建 Pose、List、Map、lambda 或临时数组。

### 11.2 Channel Cursor

当前 Clip 对每 channel 使用 binary search。新增顺序播放 cursor：

- forward playback 顺序推进；
- reverse playback 反向推进；
- seek、loop wrap、clip change 时重置；
- CUBICSPLINE 与 STEP 使用同一 segment index；
- cursor 结果必须与 binary search 基准逐 bit/容差一致；
- random seek 仍可回退 binary search。

### 11.3 Dirty Joint

PoseBuffer 增加受控 dirty tracking：

- local transform 修改标记该 joint；
- global matrix 请求时只重算受影响 subtree；
- reset/load/alias 操作正确清空或扩散 dirty bit；
- 非拓扑 skeleton 仍按 evaluation order；
- constraint 修改后对应 subtree 失效。

不得为了优化破坏 PoseBuffer 的直接 setter 语义。

### 11.4 Diagnostics

建议新增纯值 `AnimationDiagnostics`：

- active controllers；
- evaluated states/motions/clips；
- transition count 和 interruption count；
- sampled channels/joints；
- active layers、override/additive 层数；
- marker/event/signal 数和 dropped 数；
- sync fallback 数；
- constraint count/iterations/residual/clamp；
- morph target/active weight 数；
- pose/global matrix recompute 数；
- scratch capacity/estimated bytes；
- update CPU nanos；
- allocation benchmark 结果。

Diagnostics 不调用 GL，不读取 GPU timer，不持有 mutable PoseBuffer。

### 11.5 Benchmark

新增：

```text
runAnimationRuntimeBenchmark
runAnimationConstraintBenchmark
runMorphTargetBenchmark
localAnimationVerification
```

场景至少包括：

| 场景 | 角色数 | Joint | Graph/Layer | 目标 |
| --- | ---: | ---: | --- | --- |
| clip baseline | 1/100/1000 | 64 | 单 clip | channel cursor 基线 |
| locomotion | 100/1000 | 64 | State + 1D Blend | graph 热路径 |
| combat | 100/1000 | 64 | base + 3 layer | additive/mask |
| constraints | 100 | 64 | look-at + two arm + feet | solver |
| morph | 100 | 32 | 4/8 targets | CPU weight + GPU |

候选门槛在第一轮基线后锁定，最低要求：

- no-event/no-transition steady-state 为 0 B/frame 或审计后的固定极小值；
- 1,000 角色 runtime median 不高于冻结基线 + 10%；
- 单角色 graph 相对直接 Mixer 的额外 CPU 开销有独立记录；
- dirty tracking 不得使 all-joints-dirty 场景回退超过 5%；
- zero-target glTF GPU 路径不回退超过 3%；
- morph 4/8 target GPU 开销单独记录，不与 zero-target 混为一个门槛；
- benchmark 五轮，使用 median-of-medians；
- 不在 preview、GL debug shader warmup 或首次 buffer upload期间采样。

## 18. 风险与控制

| 风险 | 表现 | 控制 |
| --- | --- | --- |
| Graph 抽象膨胀 | 大量 public node class | sealed motion + nested builder；运行节点 internal |
| transition 事件重复 | attack-hit 触发两次 | incoming-only、sequence、loop index 测试 |
| trigger 提前消费 | transition 条件丢失 | 仅选中 transition 提交消费 |
| BlendTree root motion 漂移 | locomotion 滑步 | child delta 同权重混合、sync marker |
| Additive quaternion 错序 | 姿态翻转 | 明确 delta 乘法顺序与 shortest path |
| layer allocation | 多角色 GC | evaluation context、固定容量 layer |
| constraint 抖动 | 手脚跳动 | fixed order、warm-start、weight fade、iteration gate |
| IK 越界 | 非法弯折 | joint limit 每 iteration 应用 |
| Morph 显存膨胀 | 每 target 复制整 mesh | delta-only buffer、target/byte limit |
| Morph 裁剪错误 | 变形顶点消失 | conservative bounds/envelope |
| Morph 与 skin 顺序错误 | 蒙皮变形异常 | morph-before-skin shader/CPU reference test |
| per-instance 串扰 | 两角色表情同步 | shared delta + instance-owned weights |
| zero-target 回退 | 普通 glTF 变慢 | 无 target 不绑定 buffer、独立基准 |
| GL shader warning 增加 | 131218 刷屏 | 固定状态矩阵、预热外零新增、精确 policy |
| 范围过大 | 后期只能删验收 | 里程碑逐项合并，每项独立 gate |

## 19. 降级规则

本版本已明确要求方案一、二、三、五、六、七全部完成，因此不得将缺失能力在 release report 中改写为
“实验完成”后仍发布同一主题。

允许的实现收缩：

- 2D Blend Tree 使用显式 triangle，不做自动 triangulation；
- FABRIK 只支持单一连续 chain，不做 full-body branching；
- Foot IK 只接受外部 target，不做 raycast；
- Morph target 上限固定 8，不做 compute/GPU sampling；
- Graph 第一版只提供 Java Builder，不做序列化和编辑器。

不允许的降级：

- 只添加 public record 而没有 runtime 求值；
- Morph 只 decode 不进入 PBR/shadow；
- Marker 只存在于 Clip 但 transition/loop 会重复；
- Additive 通过普通 override 近似；
- Constraint 直接读取 Scene/Physics；
