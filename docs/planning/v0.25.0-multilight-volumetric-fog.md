## 2. 锁定范围

### 2.1 必须完成

1. 类型化 `Texture3D`、命令绑定、compute 可见性和资源生命周期。
2. 有限视锥 Froxel 网格：透视与标准正交相机，世界单位一致。
3. 高度雾与最多 8 个球/轴对齐盒局部雾体，统一消光、散射、发射语义。
4. 现有方向光、Point、Spot 的体积贡献；主方向光 CSM 和已分配局部阴影联动。
5. 独立体积源项历史、重投影、拒绝、裁剪，以及最终 TAA reactive 联动。
6. 不透明、MASK、标准 ALPHA、ADDITIVE、内置 HDR VFX 的明确合成规则。
7. 四场景 Demo、数值参考、时域序列、性能/资源报告和可执行门禁。
8. 删除被取代的正式 Outdoor 二维体积路径，更新 API、预设、任务和文档。

### 2.2 明确后移

多重散射、介质自阴影/光到采样点的介质积分、体积云、物理大气、IES/Light Function、任意旋转雾盒、透明介质折射、OIT/跨子系统透明排序重构、GI/Reflection Probe、SSR、水、DOF、空间视觉预设混合、通用 RenderFeature 插件系统。

首版采用**单次散射近似：表面阴影遮挡直射光，相机射线计算介质衰减；不计算每盏灯到每个 Froxel 的雾内衰减**。适用于薄雾和美术光束，不把它称为高密度烟云的完整光传输。Emissive 材质也不会自动变成体积光源，窗灯仍需要真实灯实体。

## 4. 代码职责与所有权

### 4.1 新增/调整文件

| 文件或模块 | 职责 | 不承担的职责 |
| --- | --- | --- |
| 新增 `backend/texture/Texture3D` | 尺寸/格式校验、DSA 分配、对象生命周期 | 场景、灯光、时域决策 |
| 调整 `CommandBuffer/CommandExecutor/StateCache` | 3D sampler、分层 image、barrier 的类型化命令 | 临时为体积算法开放裸 GL 回调 |
| 新增 `VolumetricGrid` | 网格、分片边界、投影映射、尺寸签名 | 分配 GL 资源 |
| 新增 `VolumetricResources` | 本代次 3D 纹理、历史双缓冲、参数缓冲、候选 resize | 自己遍历 Scene 或更新模拟 |
| 新增 `VolumetricFrameState` | 上一成功帧相机/网格/介质状态、候选提交、失效原因 | 借用 `TaaHistory` 的内容 |
| 新增 `VolumetricPassBuilder` | 声明介质、注光、temporal、积分、合成依赖；录制命令 | 曝光、Bloom、材质加载 |
| 调整 `ForwardPassBuilder` 和几何 recorder | 明确 opaque、alpha、additive 阶段，保持现有排序 | 每阶段重新遍历可变 Scene |
| 调整 `PostProcessPassBuilder` | 接收已经完成体积/透明合成的 HDR 颜色，继续 reactive/TAA/曝光/Bloom | 再管理一套 Outdoor 历史 |
| 调整 `PipelineGeneration/RenderPipeline` | 唯一所有权、构建/resize 事务、当帧冻结与成功提交 | 公共通用插件容器 |
| 调整现有 diagnostics/质量工具 | pass 时间、切片预览、拒绝原因、线性误差 | 正常帧同步全卷读回 |

上述新增 `Volumetric*` 内部类放在现有 `subsystems/render3d` 包，默认 package-private。公共 API 仅暴露设置和确有必要的场景操作，遵守 [渲染边界](../architecture/render-boundaries.md) 与 [抽象密度约束](../architecture/abstraction-density.md)。

### 4.2 唯一所有权

本版选择：`PipelineGeneration` 直接拥有一个 `VolumetricPassBuilder`，后者唯一拥有 `VolumetricResources` 和 `VolumetricFrameState`。`PostProcessPassBuilder` 不再拥有正式体积模块。这样 Forward 透明阶段和后期都可以借用同一份结果，不需要互相反向调用。

Graph 继续拥有常规 2D/MSAA render target；3D 纹理由 `VolumetricResources` 拥有，graph pass 只声明依赖并借用。若现有 graph 尚不能标记这些外部资源，补最小的借用/诊断合同，不把资源偷偷注册成第二个所有者。内部输出视图至少携带 `generationId`、成功帧身份/当前执行身份、grid、prefix/source 句柄和可用状态；禁止跨帧缓存 raw texture ID。

构建/resize 使用候选资源：全部创建、格式检查与绑定校验成功后一起发布；任一失败关闭候选，保留旧代次。旧资源释放、历史交换、参数发布只有一处负责。测试注入每一类分配/编译/执行失败，验证无双重 close、无半更新。

### 4.3 设置只保留一套真实来源

以下为拟新增 API 的语义合同，具体 Java 构造形式遵循现有 record 风格：

| 设置 | 字段/语义 |
| --- | --- |
| `VolumetricFogSettings` | enabled、fogDistance、quality、globalMedium、localVolumes、anisotropy、history、noiseSeed/风参数 |
| `FogMediumSettings` | extinction、albedo RGB、emission RGB；全局高度基准与衰减尺度 |
| 调整 `LocalFogVolume` | 保留 SPHERE/BOX 和中心/范围；BOX extent 为半尺寸，SPHERE extent.x 为半径；新增 albedo/emission/falloff，统一噪声语义 |
| `LightVolumeHints` | scatteringIntensity ≥ 0、useAllocatedShadow、temporalAccumulation；强度 0 表示不注光 |

`VisualSettings` 增加 `volumetricFog`；`RenderPipeline` 增加对应构建设置及有限热更新入口。天空是否启用和雾是否启用独立：关太阳、关 Outdoor 天空、进入室内都不能顺带关闭局部灯雾。`OutdoorEnvironmentSettings` 最终只保留仍有消费者的天空/室外预设职责，其旧 globalFog、volumetricSun、localFogVolumes、风/噪声运行时来源移入新雾设置。

`LightVolumeHints` 进入现有 `SceneLightEntry` 冻结快照与 revision 路径，经 Scene 的受控 setter 更新；灯的 stableId 和 FrameLightTable 排序不变。GPU 首版使用与 `frameLightIndex` 一一对应的 16-byte 附加记录，包含 float 强度、flags 和保留字段；Java/std430 偏移由测试固定。继续使用已有 80-byte 灯记录，不复用其中仍有用途的分量。

拟定默认值为 scatteringIntensity=1、useAllocatedShadow=true、temporalAccumulation=true；雾系统总开关默认关闭。正式 Demo 按灯逐个配置贡献，强度 0 只关闭体积贡献，不影响表面照明和灯身份。

不保留长期兼容包装：本项目允许直接调整 API，仓库内调用方同次更新。旧 `density/color` 是美术雾语义，尤其 color 可能大于 1，不能直接当作物理 albedo。三份正式预设人工重新标定，升级 `VisualProfile` schema 至 2；旧 schema 1 加载明确报出版本及替代配置路径，不静默猜测。保存/加载继续采用现有严格校验与原子应用。

参数热更新规则：颜色、密度、g、每灯贡献不重建 graph，但更新 revision/历史判断；尺寸、quality、启停引起的资源/拓扑变化走代次事务。曝光/Bloom 改动不清除场景线性体积历史。任意错误配置都不覆盖当前可用配置。

启用雾时，`PipelineFeaturePolicy` 要求 HDR 和可采样深度，`SceneBufferRequirements` 声明 DEPTH；MSAA 同时保留原始多采样深度与已有 resolve 合同。雾本身不要求新增 NORMAL、VELOCITY 或独立 LINEAR_DEPTH 生产；可从共享设备深度还原所需终点。TAA/GTAO 各自的需求仍由原消费者提出。关闭雾的 shader variant 不保留活跃的 3D sampler 依赖，不为绑定空纹理强行分配整套资源。

## 5. M1：3D 资源、绑定与同步合同

### 5.1 资源清单

默认原型：每 `16×16` 个渲染像素一列，`Nz=64` 个区间；`Nx=ceil(width/16)`，`Ny=ceil(height/16)`。以实际 render size 为准，不用窗口逻辑尺寸。所有体积计算中间运算为 float32，首版存储使用下表格式。

| 资源 | 格式/尺寸 | 内容 |
| --- | --- | --- |
| Medium | RGBA16F，Nx×Ny×Nz | RGB = sigma_s，A = sigma_t |
| Emission | RGBA16F，同上，可选 | RGB = 单位路径长度发射源；无发射时不分配 |
| CurrentSource | RGBA16F，同上 | RGB = 当前 q，A = 当前 sigma_t |
| HistoryRead / HistoryWrite | 各 RGBA16F，同上 | RGB = 已过滤 q，A = 对应帧 sigma_t；角色只在成功后交换 |
| IntegratedPrefix | RGBA16F，Nx×Ny×(Nz+1) | 每个区间前边界的累计 S.rgb / T |
| Reject | R8，同网格 | 本帧拒绝/低置信度强度，详细原因用稀疏诊断计数 |
| FogReactive | R8，实际画面大小 | 按可见射线范围归约的体积 reactive |
| OpaqueFogComposite | RGBA16F，画面大小/匹配 MSAA | graph 管理的合成输出，不能与正在采样的颜色附件相同 |

禁止默认生成 mipmap。3D 坐标越界先判无效；`CLAMP_TO_EDGE` 只是合法边界采样方式，不能把越界历史伪装成边缘有效值。不同格式的 image access 必须匹配，layered 写入整个 3D texture 与写入单层的命令语义必须区分。

FP16 的有限范围也属于输入合同：M0 固定 density/emission/源项上界和诊断计数，禁止把 float32 的有限大值直接写成 half Inf。正常验收配置的越界/限幅计数必须为 0；极端压力输入应明确拒绝或显示降级，不能默默夹值后仍报告物理误差通过。

现有 `HostGlState` 已有 `GL_TEXTURE_3D` 和 image binding 的保存逻辑；工作重点是让新增命令与缓存一致，并验证 unit、sampler、level、layered、layer、access、format、SSBO/UBO 恢复。不要把已存在的宿主状态功能再实现一遍。

### 5.2 同步与绑定表

| 写入 → 后继消费 | 必须建立的 GPU 可见性 |
| --- | --- |
| Cluster Assign SSBO → 注光 SSBO read | `GL_SHADER_STORAGE_BARRIER_BIT` |
| compute imageStore → sampler/texelFetch | `GL_TEXTURE_FETCH_BARRIER_BIT` |
| compute imageStore → imageLoad/store | `GL_SHADER_IMAGE_ACCESS_BARRIER_BIT` |
| 诊断 readback/copy | 根据 texture/buffer update 等实际消费补相应 barrier，不沿用 sampler 的假设 |

barrier 根据**后继访问**选择；graph 拓扑有序不能替代可见性，CPU fence、`glFinish` 也不是生产替代方案。跨帧 scratch 重写还必须覆盖上一轮读取到本轮 image 写的访问次序；ping-pong 不允许同一 dispatch 读写同一历史。参见 [Khronos glMemoryBarrier 定义](https://raw.githubusercontent.com/KhronosGroup/OpenGL-Refpages/main/gl4/glMemoryBarrier.xml)。

M0 输出逐 shader 的 sampler/image/SSBO/UBO 绑定表，并查询真实限制；不要跨命名空间混算上限。PBR 已使用 IBL units 8/9/10，另有阴影/GTAO。透明雾查询限定为两张 3D 输入：prefix 与过滤后 source/sigma_t，可优先验证 units 14/15 的可用性；确认全部 variant 后冻结，禁止随意挤占其他 sampler。compute 的更多输入在各 pass 独立安排。

M1 GL 测试：写入带 XYZ 编码的每个 texel，再经 sampler 和 image 分别读取；覆盖非整工作组尺寸、1 像素窗口、非法格式/尺寸、最大资源预算、resize 后首帧、资源关闭后误用。工作组边界必须检查 `gid < gridSize`。

## 6. M2：坐标与介质数学

### 6.1 网格坐标只有一个定义

1. 正视深度 `z=-viewPosition.z`，与既有 LinearDepth 语义一致；设备 depth 先经当前投影正确还原。
2. 网格边界使用 non-jittered projection。TAA 投影 jitter 用于还原表面采样位置；体积采样 jitter 是独立序列，不能重复加偏移。
3. `effectiveFogFar=min(settings.fogDistance,camera.farPlane)`，必须为有限正值并大于 near；诊断同时显示请求值和实际值。天空/背景积分到 effectiveFogFar，几何终点超过它也只积分到此。
4. 透视默认边界：`b0=0`；`bk=near*(effectiveFogFar/near)^((k-1)/(Nz-1))`，k=1…Nz。第一个区间覆盖相机到 near，避免相机进入浓雾时近裁剪段突然无雾；它是特殊区间，不能套 log(0)。
5. 正交相机采用 `[0,effectiveFogFar]` 的线性分片，射线从相机平面上对应 XY 点发出且相互平行。自定义斜裁剪/非标准投影首版明确拒绝。
6. 分片边界、采样中心、积分边界是不同概念。source 用区间内采样点，prefix 用边界。CPU/GLSL 映射共同测试，不能直接把 `z/far` 当三维 texture 的 Z。

对透视射线，若单位视空间方向为 r，区间路径长度为 `ds=(b[k+1]-b[k])/abs(r.z)`；正交 ds 为 Z 差。世界空间变换不得引入未计入的缩放。对数分片下历史插值须按实际中心深度求相邻层和权重，不能假设硬件线性 Z 就是世界距离线性。

首版固定中点采样建立参考；随后加入成功帧驱动的确定性 sub-froxel jitter。积分的区间边界仍固定，不能随采样 jitter 改变整段长度。端点和最后不足一格的像素范围均需测试。

### 6.2 介质合同

- 世界单位沿用场景单位；`sigma_t` 单位为 1/世界单位，必须非负。
- `sigma_s = sigma_t * albedo`，albedo 各分量在 [0,1]；emission 非负且是单位路径长度源项。
- 全局高度分布建议 `sigma_t(y)=densityAtBase*exp(-(y-baseHeight)/heightScale)`，heightScale > 0。指数和最终密度设明确上限以保证有限值；被限幅要可诊断。
- 球/盒使用世界坐标有界支持；边缘 falloff 在边界内衰减到 0。噪声固定 seed、基于世界位置，输出乘子不得为负；动画仅使用冻结的模拟时间。
- 重叠区域分别相加 sigma_t、sigma_s、emission；不直接相加 albedo。全局和局部介质进入同一积分，不再额外执行旧全局 FogPass。
- 本版全局一个 anisotropy g，建议允许范围 [-0.9,0.9]，避免极端相函数峰值；不声称按密度平均多个 g 就等价混合相函数。

### 6.3 分段积分与相函数

对每个采样点，先形成源项：

```text
q = emission + sigma_s * sum(lightRadiance * phase * shadowVisibility * volumeIntensity)

Tseg = exp(-sigma_t * ds)
segmentFactor = (1 - Tseg) / sigma_t
Snext = S + T * q * segmentFactor
Tnext = T * Tseg
Sinitial = 0, Tinitial = 1
```

小光学厚度使用稳定展开 `segmentFactor ≈ ds*(1-tau/2+tau*tau/6)`，tau=sigma_t*ds；不要在 sigma_t=0 时除零，也不要因 density=0 直接跳过非零 emission。吸收和单次散射模型依据 [PBRT 光传输方程](https://pbr-book.org/4ed/Light_Transport_II_Volume_Rendering/The_Equation_of_Transfer)，上式是本项目选定的段内常量近似。

方向约定固定：L 是“采样点指向灯”，透视 V 是“采样点指向相机”，正交 V 是平行观察射线的反方向，`mu=dot(-L,V)`。HG 相函数为 `(1-g*g)/(4*pi*(1+g*g-2*g*mu)^(3/2))`。g=0 必须为 1/(4π)，g>0 应强化看向光源时的前向散射；不要直接搬用其他方向约定的正负号。参见 [PBRT 相函数与方向约定](https://pbr-book.org/4ed/Volume_Scattering/Phase_Functions)。

方向光和 Point/Spot 的强度、距离衰减、range 截断及锥角沿用现有灯表约定，首版不重标所有表面灯的物理单位。体积路径不使用 N·L 或表面 BRDF，也不把 GTAO 乘到空气散射上。可选美术 ambient 源必须显式配置、默认 0，并标为近似，不能暗中把 IBL 强度变成全空间常量照明。

### 6.4 任意深度查询必须处理最后半段

Integration compute 每个 XY 列用一个 invocation 顺序遍历 Z，以 float32 寄存器累计 S/T，写入 Nz+1 个边界。没有跨 workgroup 的前缀依赖；先不引入并行 scan。

查询深度 d 时，找所在区间 k，取得其前边界 prefix，再用该区间 q/sigma_t 和 `partialDs` 完成剩余积分。不要把该区间整段计入，也不要沿 Z 直接线性插值 S/T 来代替指数衰减。d≤0 返回 (0,1)，d≥far 返回末边界。

保留完整雾距的 prefix，不在第一张 opaque depth 处截断三维存储。场景深度只决定各消费者的终点，透明物可以查询自身深度。XY 重建可按四个邻列在同一物理深度分别查询后插值；列间重建属于低分辨率近似，质量测试要覆盖宽视角、轮廓和细光束。不能靠无限放大密度隐藏漏光或块状边界。

## 7. M3：连接灯表、Clustered 和阴影

### 7.1 首版只保留一种生产候选查询

**选择：每个实际体积采样点转换到现有 lighting cluster，读取候选灯列表。** 不新建全套 volumetric light list，不把 froxel index 当 lighting cluster index。

流程：world point → 当前 stable view/projection → lighting cluster XY/Z → header/indices → 用同一 `frameLightIndex` 读取灯和 `LightVolumeHints`。阴影数据也使用这一映射。方向光按既有方向灯区段单独遍历，当前只有主方向光可使用 CSM，其他方向光贡献无阴影。

- Lighting grid 仍可为 64px/24Z，volume 为 16px/64Z；两者独立。
- 候选列表必须覆盖全视锥空气。禁止把后续基于 opaque min/max depth 的 surface-only cluster 裁剪直接供雾消费。
- 原型每 froxel 一个采样点，候选只保证该点，不声称覆盖整格所有灯。若一个 froxel 增加多点采样，每个点重新定位 cluster，或证明候选并集覆盖所有点。
- jitter 后按真实采样点查询；不沿用 jitter 前中心的灯列表。
- `z<lightingNear` 的特殊相机近段不能简单套第 0 个 cluster：其中可能缺少仅影响 near 之前的灯。此段使用体积筛选后的全灯遍历参考逻辑；若实测需优化，再提供有证明的保守候选。
- Overflow 沿用现有正确 fallback，额外统计体积实际受影响的 froxel 比例、候选均值/p95/max、实际访问灯数。禁止直接丢弃超容量灯。

开发参考另有全灯扫描注光 shader/模式，只用于测试和 benchmark A/B，不保留公开生产开关。比较的是同一位置、同一参数下 q 和 S/T，不能拿两张曝光不同的 PNG 判断漏灯。

### 7.2 阴影是已有资源的消费者

沿用 `ShadowFramePlan/ShadowFrameBinder` 的世界坐标、tile、point face、有效槽位和深度比较。`LightVolumeHints.useAllocatedShadow=true` 只请求采样已有有效结果，不向 scheduler 偷加一份预算；没有槽时无阴影注光，并输出诊断计数。

Point/Spot 阴影采样的投影和 atlas PCF 边界可复用；体积点没有表面法线，不能照搬 surface normal offset 或依赖 N·L 的 receiver bias。使用明确的体积深度 bias，按灯类型测试光束贴墙、墙后遮挡和近灯区域。

CSM 的有效范围可能短于雾距：本版范围外 visibility=1，并将末级边界过渡到这一值，显示实际阴影距离。不要采样越界 tile，也不要暗称 far fog 全程受 CSM 遮挡。shadow slot 重排、灯删除/禁用和 shadow 内容更新必须触发对应体积历史失效。

关键用例：保留雾和灯，仅关闭该灯 shadow → 光束仍存在但遮挡消失；切换槽位不串灯；移出相机但仍影响视锥的灯继续注光；opaque 深度后仍需生成空气中的 source，避免相机移动时历史空洞。

## 8. M4：颜色链、透明和 MSAA

### 8.1 目标顺序

```text
RenderFrameContext：一次冻结 scene/camera/lights/volumes/revisions
  ├─ shadow / shared surface / GTAO
  ├─ light upload / cluster assign
  └─ medium injection
             ↓（灯表、cluster 和 shadow 准备完毕）
      volume lighting → temporal resolve → integrate prefix
             ↓
OPAQUE + MASK + background → opaque fog composite
             ↓
ALPHA / ADDITIVE + HDR VFX（按自身深度查询雾，保持既有混合顺序）
             ↓
MSAA color resolve（如启用）→ reactive 合并 → TAA（如启用）
             ↓
auto exposure → Bloom → tone mapping / color grading / output AA → UI
```

这是依赖关系，不要求所有支路串行 CPU 等待。GTAO 仍按现有共享表面在前向着色前准备。SceneColor 仍属于 graph 的颜色链，不往 SceneBufferView 塞一串后期颜色别名。

拆分当前合并 geometry executor：同一份冻结 render queue 分段消费，背景和 OPAQUE/MASK 先完成；ALPHA 保留 back-to-front，ADDITIVE 保留现有确定顺序。renderer updater、蒙皮/morph 和实例快照准备每帧仍只运行一次。跨 pass persistent instancing 的 finish 必须移到最后实际消费者，异常仍统一 abort。

### 8.2 混合公式

| 类型 | shader 输出/合成 |
| --- | --- |
| 不透明/背景 | `Cout = S(d) + T(d)*Cscene` |
| straight alpha 材质 | 先构造 premultiplied `Cp=alpha*Csurface`，再按下一行处理 |
| premultiplied alpha | `CpFog=T(d)*Cp+alpha*S(d)`，alpha 不变；用 ONE / ONE_MINUS_SRC_ALPHA 合成 |
| additive 发光 | `CemitFog=T(d)*Cemit`；不再加 S |
| UI / LDR overlay | 不查询雾 |

透明背景已经带雾；premultiplied 公式中的 alpha*S 配合背景的 (1-alpha) 才恢复正确前景路径散射。alpha=0 必须完全不改背景，alpha=1 应与相同深度的不透明结果一致。透明 shader 不得把已经带 S 的颜色再次当作无雾表面颜色。

内置 HDR VFX 使用同一查询函数：烟尘 alpha、火星 additive 各遵守其公式；soft-particle depth fade 继续只决定粒子的覆盖/alpha。雾场本身不能用表面 velocity 伪装为粒子。

多层折射和吸收型彩色玻璃不在本版保证内。自定义 shader/VFX 若不能接入此合同，在 build 时明确报出不支持的效果组合或要求显式 opt-out；不静默把它塞回最终按 opaque depth 加雾。

本版不解决相交透明 mesh 与粒子的全局排序；沿用现有排序能力并在限制表注明。验收 Demo 将 alpha 层安排成可确定顺序的场景，另保留相交用例展示既有限制，不能把这类混合次序问题归咎于体积积分。

### 8.3 MSAA 不允许先平均深度再统一加雾

目标保留 NONE、FXAA、TAA、MSAA 四种现有 AA 模式；MSAA 与 TAA 是现有互斥选择，不新增混合 AA 模式。

MSAA 路径在 resolve 之前完成 opaque fog 和透明绘制：独立同 sample count 的颜色输出，通过 sampler2DMS 读取对应 sample 的原始 opaque color/depth，以 sample 位置还原射线并查询同一三维雾场。保证 per-sample shader 执行，显式处理并恢复 sample-shading 状态。雾纹理本身不用 MSAA。

Fog composite 的目标不挂载正在被该 shader 采样的深度附件，避免 framebuffer feedback；透明阶段再使用正确的同尺寸/同 sample count depth 做深度测试。共享深度 resolve 继续服务 GTAO、soft particles 等原有消费者，不能被误用为所有 sample 的雾终点。所有透明/VFX 完成后只进行一次最终颜色 resolve。

若实现阶段 MSAA 未完成，应在状态表记为阻断项或明确缩减版本承诺，不能将“build 拒绝启用”记为功能支持通过。测试覆盖 2×/4×、前景细边、不同 sample 深度、透明遮挡和外部目标契约。

## 9. M5：独立体积时域

### 9.1 历史保存什么

保存**局部 source q 与对应帧 sigma_t**，不保存上帧射线积分出的 S 当作本帧局部照明。Temporal 仅过滤 q.rgb；本帧参与积分的 alpha 始终写当前 sigma_t，避免旧密度造成拖尾消光。每帧重新沿本帧射线积分。

步骤：当前采样点世界坐标 → 上一成功相机的 stable volume 坐标 → 按上一 grid/采样 jitter 约定寻找历史 → 校验介质与变化区域 → 对历史 q 做当前邻域裁剪 → resolve → 积分。M2 的坐标测试必须覆盖此映射。

初始 historyWeight=0.9、上限 0.95；先采用当前点及六个轴向邻居的有效 q 范围裁剪，边界只使用有效邻居。后续扩大邻域或做方差裁剪必须以质量/成本数据说明理由。参数写进预设和报告，不成为 shader 隐藏常量。

### 9.2 拒绝条件与动态输入

| 情况 | 处理 |
| --- | --- |
| 第一个成功帧、切镜、场景替换、历史坐标越界 | historyWeight=0 |
| 尺寸/quality/投影类型/near/far/grid 签名变化 | 重建或整卷失效 |
| 失败帧、resize 候选失败 | 不交换历史，不提交相机/帧编号；下一有效帧按失效规则重建 |
| 消光差异 | 使用绝对+相对阈值检验当前 sigma_t 与采样历史 alpha；阈值由解析/运动用例冻结 |
| g、介质 albedo/emission、全局密度模式变化 | 整卷失效；曝光/Bloom 不在此列 |
| 灯光位置/方向/range/颜色/强度、雾体位置/形状变化 | 对上一与当前影响域的并集保守失效，不能只覆盖新位置 |
| 灯灭/删除、shadow 内容或 slot 改变 | 上一影响域也失效；表面遮挡 revision 必须进入判断 |
| 相机移动导致相函数方向变化 | 比较同一世界点的旧/新 V；强各向异性时降低权重或拒绝 |

快速灯 `temporalAccumulation=false` 时，该灯影响的 froxel 总 q 不使用历史；灯熄灭后其旧影响域至少在本帧继续拒绝。先不新增“稳定/动态光各存一卷”的双系统。

M3 可先全卷保守失效验证正确；M5 必须实现有界的局部变化域，避免小镇一盏火把闪烁就让整片雾永远无历史。脏域使用真实范围/锥体的保守包围，移除灯保存上一成功影响域；超过脏域容量可退回全卷失效并计数，禁止漏掉变化。局部阴影可按光影响域失效，主 CSM 变化允许全卷失效并如实报告频率。

区分“遮挡内容改变”和“仅因相机移动而重拟合 shadow 投影/刷新缓存”。前者必须失效受影响区域；后者不能仅凭 pass 被执行就每帧整卷清空。用同一世界位置的当前阴影/源项一致性、覆盖范围变化和邻域裁剪验证历史；只有无法证明一致的区域拒绝。固定场景缓慢移动相机时仍须有有效历史覆盖统计，不能以永久关闭历史通过 M5。

参数 revision 与模拟时间分开。固定世界噪声不应因帧号更新而失效；风动噪声由当前/上一成功时间评估变化并降低置信度，不能未经证明把整个相加介质按单一风速搬移。动态体积先用变化域拒绝，不承诺介质速度场输运。

### 9.3 与 TAA 联动

FogReactive 沿当前可见深度范围归约低置信度和照明变化，并与已有 reactive 按 `max` 合并，保持其 [0,1] 语义。opaque 后不可见的深层变化不应长期让整屏 reactive=1；透明/VFX 另按自身深度贡献 reactive。

体积历史失败不是整帧 TAA 自动清空的理由；快速光束对应区域应及时拒绝最终颜色历史。必须分别跑“体积历史关/TAA 开”“体积历史开/TAA 关”“二者均开”。两个 history 串联仍可能拖尾，成熟引擎也记录了快速变化灯的这种问题，见 [Epic Volumetric Fog 时域说明](https://dev.epicgames.com/documentation/en-us/unreal-engine/volumetric-fog-in-unreal-engine)。

成功提交的语义沿用现有渲染事务：整张 graph 成功后交换 HistoryRead/Write 并提交相机/网格/revisions。失败可以清空历史有效性，但绝不能把已部分写入的 HistoryWrite 当新历史发布。双相机/双 pipeline 不共享这些状态。

## 10. M6：Demo、参数面板与美术验收

### 10.1 一个正式入口、四个场景

拟新增 `Render3dVolumetricFogDemo` 和 `runRender3dVolumetricFogDemo`，组合现有 scene factory、profile codec、capture spec 与面板。复用 [夜间小镇模型](../guides/clustered-night-town.md)，不复制整个旧 Demo 的相机/保存/截图实现。

| 场景 ID | 镜头与目的 | 强制对照 |
| --- | --- | --- |
| `forest_morning` | 保留既有林间路径，低太阳穿树冠，相机跨越局部雾边缘 | fog off、旧 Outdoor 参考、无历史高采样、新路径 |
| `town_night` | 保留全景与沿街路径；暖路灯、窗灯、少量火把与冷色喷泉构成层次 | 固定曝光、Bloom off、局部灯体积 off、局部阴影 off |
| `tavern_threshold` | 复用一栋店门，穿过门口薄雾/alpha 烟，近处 additive 火星；一盏快闪灯 | history off、reactive、S/T、透明物前后两处深度 |
| `medium_lab` | 恒定介质、球盒重叠、遮挡墙、黑背景/天空、旋转/正交相机 | 解析参考、全灯参考、误差图、slice/密度 |

夜间小镇保留既有 128 局部灯的表面照明基线。第一轮只给约 12～20 个有明确构图作用的灯开启体积贡献；其余强度为 0。随后用 all-128 配置做压力验证，不能把“128 表面灯，其中 16 盏注雾”报告成“128 体积灯性能”。沿用 balanced 的最多 2 Point + 4 Spot 局部阴影预算，候选灯数和实际分配数分列记录。

美术调参顺序：固定曝光与 IBL → 检查无雾场景可读性 → 低密度全局高度雾 → 门口/街角局部雾 → 每灯体积强度和 g → 阴影 → 少量 Bloom。夜空保持暗部层次，不用全屏高密度雾把街道抬成灰白；喷泉不应成为照亮整镇的蓝色雾球。路灯光束应随遮挡和观察方向变化，关 Bloom 后仍可辨认。

森林和小镇继续保存旧 60/240/420 帧的无雾回归；新增雾用新的 reference 目录和 scene/config hash，不直接覆盖 0.24.3 参考以让测试变绿。酒馆序列固定时间点，例如 120 帧亮灯、180 帧关灯、240 帧移动雾体，采集事件前后逐帧数据。

### 10.2 面板和诊断

面板只暴露可解释参数：质量档、fog distance、全局密度/高度、albedo、g、雾体范围/falloff、选中灯的体积强度/阴影/历史开关。延续配置加载/保存、固定路径、截图能力，显示 dirty/applied 状态与验证错误。

诊断至少包括：网格尺寸/显存、sigma_t 切片、q 切片、S/T、历史拒绝、FogReactive、体积候选灯数量、overflow 影响比例、shadow 无槽灯数、全卷失效原因/频率、各 pass 与完整链 GPU 时间。3D preview 增加切片查看或显式导出 2D slice；不要向现有只接受 2D 的预览器传一个 3D ID。

## 11. 质量测试和数值门禁

### 11.1 必须独立于生产公式调用的参考

CPU double 参考自己实现公式与坐标推导，不调用生产 packer/helper 得出“期望值”。高采样图像参考采用完整灯遍历、无历史、相同灯单位和阴影定义；至少从 256/512 步做收敛检查，必要时增加步数。旧 Outdoor 只用于单太阳视觉连续性，不能作为多光源物理正确性的 oracle。

所有数值比较在线性 HDR 完成，固定曝光/关闭自动曝光；Bloom、tone mapping 只用于另外的呈现检查。保留原始 float、误差图、配置、相机和代码指纹；PNG 确定性检查不能替代这些证据。

### 11.2 门禁初值

下列是本版**拟定门槛**，M0～M2 用固定解析输入确认量化误差后写入配置。调整必须在正式性能/质量候选之前记录原因和新旧阈值，不得验收失败后只改阈值。

| 测试 | 通过要求 |
| --- | --- |
| sigma_t=0、emission=0 | S=0、T=1；合成结果与 fog off 一致，容许目标格式量化 |
| 均匀介质、常量 q、轴向/斜射线 | T 最大绝对误差 ≤ 0.002；S 归一化最大误差 ≤ 0.005，归一化分母 max(1,abs(reference)) |
| 零密度但 emission 非零 | S=q*d，不出现被 density early-out 吞掉的发射 |
| 多雾体相加 | 与先相加系数再解析积分一致，无负密度/负 T/NaN/Inf |
| 光学厚度递增 | T 单调不增且在 [0,1]；大厚度安全趋近 0 |
| HG 数值积分/方向 | g=0 为常数；CPU 球面积分误差 ≤ 0.001；前向/后向符号正确 |
| Clustered 对全灯参考 | 同采样点 q 归一化最大误差 ≤ 0.002；overflow/近裁剪段不得漏灯 |
| 任意深度、slice 边界 | 连续跨界；最后部分区间满足解析阈值，不能出现整片跳变 |
| 标准 ALPHA/ADDITIVE | alpha=0/1 端点和双层解析混合通过；关雾恢复原混合 |
| 默认质量对收敛图像 | 固定有效 ROI 的 RGB NRMSE ≤ 5%，P95 归一化像素误差 ≤ 10%；黑区使用预设绝对误差阈值 |
| 关灯恢复 | 对“灯雾增量”ROI，关灯后第 2 帧残留能量 ≤ 关灯前的 5%；三种历史组合分别测 |
| 稳定帧时域 | 排除预定闪灯/风动 ROI 后，静止序列亮度标准差/参考均值 ≤ 2%；暗区用绝对阈值 |
| 失败/resize/切镜 | 下一成功帧无旧代次/旧相机历史；GL 错误、泄漏和 NaN 均为 0 |

NRMSE 使用 `sqrt(sum((candidate-reference)^2)/max(sum(reference^2),epsilon))`，ROI、epsilon、亮度阈值和归一化方式写进 capture 配置，不能由本次结果自动选取。薄阴影边、动态遮挡、宽 FOV、各向异性强光束另做人工逐帧复核；平均误差不能掩盖集中漏光。

必测矩阵还包括：0/1/8 个雾体、8/128/256 个体积灯、1 个太阳、2 Point+4 Spot 阴影、无阴影槽、灯删除/重排、正交、非整窗口尺寸、NONE/FXAA/TAA/MSAA、GTAO/Bloom 联合、实例/蒙皮/MASK、双视图、embedded host、连续失败后恢复。

## 12. 性能、显存与优化顺序

### 12.1 计量口径

沿用 0.24.3 的提交 ticket、逐轮覆盖、同帧配对、尾部有界 drain。正式测试至少 3 轮，每轮 120 warmup + 300 measured；A/B 按 round-major 交替运行。正常测量不逐帧 glFinish，CPU isolation 仅用于归因。保存原始样本，报告所有 drain/checkpoint 等待墙钟，不能把它们藏成免费吞吐。

计时分为 `volume-medium`、`volume-lighting`、`volume-temporal`、`volume-integrate`、`volume-composite`、`volume-reactive`。透明/VFX 新增采样成本由同场景 fog on/off 的完整 GPU/CPU 差额反映。**完整链用同一帧相加后再求分位数；不得相加各 pass p95。** 必需 pass/轮次及完整帧组合覆盖率 ≥95%，缺样标失败，不补零。

基线机器优先延用 0.24.3 报告中的 RTX 3050 Laptop，M0 重新记录实际设备、驱动、功耗状态、温度条件和后台负载；不能假定它仍处于相同运行状态。1080p/4K 使用固定 seed、固定灯分布/范围、同样阴影更新策略与 AA，禁止把 4K 输出上的低分辨率内部渲染记为原生 4K。

### 12.2 拟定预算与实际承诺

这是 M0 原型的目标预算，不是当前实测保证。M0/M2 若证明目标与参考硬件不匹配，应在继续投入时调整默认 quality/范围并重冻配置，保留实验记录；最终发布表必须填写真实结果，不能保持“待测”。

| 配置 | 目标 |
| --- | ---: |
| balanced 16px/64Z，1080p，128 个体积灯，8 雾体，6 个已分配局部阴影 | fog on/off 完整 GPU 配对增量 p95 ≤ 2.0 ms |
| 同配置 4K，128 个体积灯 | 完整 GPU 配对增量 p95 ≤ 4.0 ms |
| 同场景 CPU execute 配对增量 p95 | ≤ 0.35 ms |
| fog disabled | 不分配体积资源、不运行体积 pass/上传；相对 0.24.3 同输入额外 CPU ≤ 0.05 ms |
| 4K balanced，3D/历史/附加参数自有资源 | ≤ 128 MiB |
| 4K balanced，含新增单采样合成/Reactive，正常模式 | ≤ 192 MiB；候选 resize 峰值 ≤ 384 MiB |

GPU 2/4 ms 是整帧增加值，包含雾造成的额外透明成本；另报各 pass 帮助归因。阴影图在 on/off 两边保持相同预算与更新，另测变化阴影场景，不利用只在 off 一边重绘阴影降低增量。

256 灯/4K、全 128 灯大范围重叠、overflow、快速动态阴影作为压力项另列，不承诺 1024 灯大覆盖实时帧率。阴影更新成本、已缓存阴影采样成本与无阴影灯分别对照。

显存核算示例：1080p 网格为 120×68×64，4K 为 240×135×64；单张 RGBA16F 分别约 3.98/15.82 MiB。第 5 节全部卷（含可选 emission、双历史、Nz+1 prefix、R8 reject）加 full-resolution R8 reactive 约 26.44/105.06 MiB；再加一张 RGBA16F 合成输出约 42.26/168.34 MiB。还需计参数缓冲、驱动对齐、graph 未复用目标和在途代次，不能只报一张输出。

MSAA 输出按 sample count 另外计量；4K 4× 的一张 RGBA16F 合成目标约 253.13 MiB，不能塞进上述 192 MiB 单采样预算。M0 为 MSAA 单列 ≤384 MiB 稳态/≤768 MiB 事务峰值目标，并核对既有场景资源之后的整体显存余量。质量高档、诊断 readback 和高采样参考也各自报资源，不混入正常低开销声明。

### 12.3 只按实测热点优化

1. 先检查无用 pass、重复分配/上传、错误全灯 fallback、同步读回；修复正确性与资源问题。
2. 检查注光访问量、灯范围、局部阴影 PCF 和 overflow 影响；每灯贡献 0 应快速跳过。
3. 再测试质量档：low 可从 32px/48Z 起步，balanced 16px/64Z，high 8px/96Z 只作质量目标；high 内存约为 balanced 的 6 倍，必须按预算拒绝或明确选择较低档，不能自动申请到失败。
4. 确认 prefix/partial segment 和 XY 重建质量，再考虑 shader 合并或 scratch 复用。
5. 确实由候选访问占优，才另立基准评估独立体积候选列表。没有数据，不把 M3 改成第二套空间系统。

不通过删除历史、关闭阴影、改变灯数/雾距而继续使用原配置名称来“优化通过”。缩减质量是有效产品选择，但必须显示实际配置并重新做质量对照。

不要只创建空的汇总任务。质量配置、固定帧、ROI 和预算进入 `config/` 并参与候选指纹；输出写入 `build/reports/render3d-v0250/<fingerprint>/<runId>/`，含 manifest、原始 CPU/GPU 样本、逐轮结果、线性 HDR、误差图、事件序列、资源表和状态分类。

执行顺序在任务落地后为：普通 `check/publicApiGuard/assetManifestGuard` → 集成 → 质量 → 正式性能 → 全项目 `releaseReadiness`。已有 `localRender3dV0243Verification` 和 `runRender3dVisualBaselineQuality` 中仍适用的用例继续执行；因 API 删除而改名/迁移的用例要记录去向。正式性能串行运行，不与其他 GL benchmark 竞争 GPU。
