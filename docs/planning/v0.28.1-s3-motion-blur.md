日期：2026-11-11。状态：首版生产实现已写入；JVM 合同与真实 GL 用例均已执行通过（功能 PASS，性能 `NOT_EVALUATED`）。对应 46 项路线图 #21，调度范围见 [multi-agent full delivery](haikalat-multi-agent-full-delivery.md) 的 S3 行。

## 技术卡

| 字段 | 内容 |
|---|---|
| 技术 ID／用户场景 | #21 Motion Blur；受控镜头运动与物体运动的方向性模糊，静止画面保持完全清晰。首版不默认开启。 |
| 当前基础／差距 | 已有 `SceneSurfacePass` 产出的共享 velocity/validity、`SurfaceInputs` 借用合同、`TemporalFramePose` 的 jitter/相机事实、HDR RGBA16F 颜色链和各效果独立 owner。缺少曝光控制、半径钳制与 velocity 消费 Pass。 |
| 首版范围 | 单帧、单 Pass、后向屏幕空间 gather：读取已解析 HDR 颜色 + 单采样 velocity/validity，按曝光比例缩放 per-frame velocity，按像素半径钳制后固定 12+1 tap 采样。颜色、velocity、validity 统一按当前 raster 坐标采样；velocity 值本身已由 stable projection 去 jitter，无需再平移坐标。支持 HDR 下的 NONE/MSAA/FXAA/TAA。不支持 tile/邻域 velocity dilation、前向 scatter、逐透明 velocity、深度感知的运动拒绝、per-object motion flag、镜头畸变/旋转模糊卷积。 |
| 模块与控制 | `subsystems.postprocess`：`MotionBlurSettings(enabled,shutterFraction,maxRadiusPixels)` + `motionblur.MotionBlurPass` + 包内 `MotionBlurMath` 参考实现；`PostProcessPipeline` 持有、排序和关闭。不新增 manager/factory/chain。默认 `PostProcessSettings.motionBlur() = disabled()`；`enabled=false`、`shutterFraction=0` 或 `maxRadiusPixels=0` 时 `active()=false`，不创建 Pass、shader 或附件。设置是装配期值，修改后需重新 build/重建候选。 |
| 输入 | 已解析的 HDR 场景颜色（TAA 后；景深后的最终 HDR 合成），单采样 `sceneVelocity`（RG16F，语义为 `previousStableUv - currentStableUv`）与 `sceneValidity`（R8），输出尺寸。颜色为线性 HDR；颜色/velocity/validity 都是当前 raster 索引，velocity 值本身不含 jitter。 |
| 输出 | 独立全尺寸 `motionBlurColor` RGBA16F；不写共享 velocity/validity/depth，不修改输入颜色附件。alpha 沿用中心像素。 |
| 曝光模型 | `shutterFraction ∈ [0, 1]` 表示曝光时间占当前帧间隔的比例（0.5 约等于 180° 快门），`maxRadiusPixels ∈ [0, 64]`。像素位移为 `velocityUv * viewport * shutterFraction`，长度超过上限时按比例钳制。velocity 已是每帧位移，因此不再乘 `deltaSeconds`，避免帧率相关的二次缩放；帧间隔上限仍由既有 `PostProcessPipeline.beginFrame` 的 0.1 s 钳制负责。 |
| Jitter 一致性 | TAA 下颜色、velocity、validity 都由同一 jittered raster 帧索引；velocity 的值是 stable 投影下的 `previousStableUv - currentStableUv`，jitter 已在值中抵消。Pass 不额外减 jitter，也不在 stable 坐标重采样，因此中心像素与 12 个 tap 的坐标原点一致。非 TAA 路径 jitter=0，行为相同。 |
| 重建与方向 | 从当前像素向上一帧位置做 12 个均匀 tap 的盒式 gather（加中心样本共 13 次颜色读取），`sampleUv = rasterUv + motionUv * (i + 0.5) / 12`，tap 始终落在被钳制的线段内。方向由 velocity 定义：`previous - current` 指向上一帧位置；gather 向该方向取样，可见拖影出现在**相反**一侧。 |
| 静止零模糊 | 运动长度小于 0.5 px 时直接输出中心像素，不进入采样循环；静态相机/静态场景是逐字节恒等，而不是“接近不变”。 |
| 相机切镜／无效 velocity | 单帧 gather 不拥有也不采样任何历史，因此不存在跨镜头历史混合。`validity < 0.5`（相机切镜、首帧、resize、形变 previous 数据不可用、非有限/异常 velocity）直接输出中心像素。RenderPipeline 在切镜时失效 temporal/surface 历史，surface Pass 该帧写 `validity=0`、velocity=0，本 Pass 再显式门控，保证切镜不拖尾。 |
| 无 velocity 的 VFX／透明策略 | 共享 surface 只由不透明/写深度表面产生 velocity。透明 VFX 颜色位于 HDR composite，但没有自己的 velocity：它在每个像素使用其身后不透明表面的 velocity。相机整体运动时，位于不透明背景前的 VFX 随背景一起模糊；身后没有不透明表面（天空/clear 区域）时 surface 写 validity=0，该像素保持清晰。静止背景上的独立物体运动不会给 VFX 或背景凭空添加 velocity。该回退是明确合同，不是读取未初始化数据。 |
| 深度不连续 | 首版只用 velocity，不读取 depth；不同深度表面在运动中重叠时，采样可能跨深度混合颜色。单帧后向 gather 在 velocity 场不连续处只软化物体自身轮廓；静止背景不会收到运动物体的 velocity 拖尾。真正的物体 trail 需要 velocity dilation/tile-max 或上一帧颜色，明确不在本包范围。 |
| 参数校验 | 全部要求有限；`shutterFraction ∈ [0,1]`，`maxRadiusPixels ∈ [0,64]`，非法值在构造期 `IllegalArgumentException`。非有限或绝对值超过 `1e4` 的 velocity 在数学参考和 shader 中都回退为零模糊。 |
| 采样与边界 | 抖动后 UV 与每个 tap 都钳制在 `[0.5/viewport, 1-0.5/viewport]`，避免边缘采样越界。固定 12+1 次采样，成本与半径无关地有界；半径只控制线段长度，不增加 tap 数。 |
| Pass 关系 | `GeometryPass → [Surface/Fog/VFX/Distortion] → TAA resolve → DepthOfFieldPass → MotionBlurPass → AutoExposure → Bloom → ToneMapping → Vignette/FilmGrain/ChromaticAberration → FXAA/Present`。运动模糊在 TAA 之后，避免把当帧模糊写入历史；在景深之后，使景深仍读取未被颜色模糊污染的深度对齐输入；在曝光/Bloom/tone mapping 之前，在线性 HDR 中积分。UI 在 Present 之后由宿主合成，不进入本 Pass。 |
| 图依赖 | `PipelineTopology.sceneSurface` 仅在运动模糊 active 时把 `SceneBufferRequirements.motionBlur()`（velocity + 由 `validated()` 补齐的 previous-surface-depth/validity）并入单采样表面请求；与 TAA/GTAO/MSAA resolve 合并时沿用既有通道。`SurfaceInputs.validateDependency` 在提交帧前校验 `MOTION_BLUR_PASS → velocity/validity producer`。缺少 velocity/validity 或非 HDR 时装配期明确拒绝。 |
| 资源与失败 | `MotionBlurPass` 拥有 shader program + `ScreenQuad`，由 `PostProcessPipeline.owned` 关闭；同设置的候选代可借用 donor，`transferResourcesTo` 转移所有权。无历史纹理、无 GPU 读回、无 `glFinish`、无逐帧分配。候选失败时按既有 `PostProcessPipeline` 清理路径释放自有资源；不接管借用 velocity/validity。 |
| 参考与许可 | 算法与 shader 为项目自写，无第三方 shader 或资产。JVM 参考 `MotionBlurMath` 使用独立手算的像素位移/钳制/超限回退数值，`MotionBlurShaderTest` 锁定 raster 采样与无 jitter 平移；GL 用例以独立读回的源颜色缓冲为真值，不把 Pass 自身输出当 oracle。 |
| 成本／回退 | 每像素 1 次 velocity + 1 次 validity + 13 次颜色采样、1 次全屏 draw、1 张全尺寸 RGBA16F 附件。开启会让共享 surface 增加 velocity/previous-depth/validity 通道；无 TAA/GTAO 等既有消费者时新增一个 `SceneSurfacePass`，几何成本另计。未做 GPU 测量，成本状态 `NOT_EVALUATED`。回退是关闭效果（精确 no-op）或降低 `maxRadiusPixels`/`shutterFraction`。 |
| 验证范围 | JVM：`MotionBlurSettingsTest`（边界、no-op、wither）、`MotionBlurMathTest`（零/亚像素恒等、手算曝光缩放、半径钳制与方向、非法/超限 velocity 回退、tap 单调性）、`MotionBlurShaderTest`（raster 坐标采样、无 `uJitter`/`stableUv` 平移）、`PostProcessSettingsTest`（组件兼容构造器/withMotionBlur/null）、`PipelineTopologyTest`（velocity 及其校验通道、MSAA resolve）。GL：`MotionBlurPassGlTest` 单 case 覆盖静态零模糊逐字节恒等、validity=0 切镜恒等、运动方向的有界拖影、物体自身 velocity 软化、2/8 px 半径钳制、disabled 图精确基线、active 图 RGBA16F 且位于 DOF 与 tone mapping 之间、TAA 图把 MotionBlur 放在 TAA resolve 之后，并检查 `glGetError`。 |
| 创作交付 | 通过 `PostProcessSettings.builder().motionBlur(MotionBlurSettings.of(shutterFraction, maxRadius))` 在 build 前配置。曝光/半径是装配期标量；逐帧曝光调节、质量档和 UI 控件不在本包范围。 |

## 明确限制与未验证项

1. 单帧后向 gather 不是时域重建：它不读取上一帧颜色，因此没有跨镜头历史污染，但也无法为“静止背景上的快速物体”生成真实 trail。当前行为是物体自身轮廓在 velocity 方向软化，静止背景保持不动；GL 用例显式断言了该边界。
2. 没有 velocity dilation / tile-max / 前向 scatter，也没有逐透明或粒子的 velocity。VFX 使用身后不透明表面的 velocity；身后没有不透明表面（天空/clear 区域）时保持清晰。与不透明层交错的正确运动模糊未实现。
3. 没有深度感知的跨表面拒绝；强深度不连续和 velocity 不连续处的颜色混合可能不物理。
4. 固定 12+1 tap 在 64 px 最大半径下是稀疏采样，高对比边缘/点光源可能出现离散条纹或阶梯；未实现噪声化 tap 或高光加权。
5. 曝光比例上限为 1.0 帧、半径上限 64 px；高分辨率（4K）下视觉半径相对更小，未做分辨率归一的质量档。
6. 设置是装配期值；逐帧改变曝光比例/半径不会自动重建当前 generation。
7. 仅支持 HDR 链；LDR TAA/FXAA 路径明确拒绝，而非静默忽略。正交相机的 velocity 来自既有 `SceneSurfacePass`，但本 Pass 未单独验证正交/自定义投影组合。
8. 切镜不拖尾依赖既有 `TemporalFrameState.looksLikeCameraCut` 自动失效或显式 `resetTemporalHistory()`。未被这两条路径覆盖的相机跳变仍会向 velocity 提供一个有限但很大的位移；首版只按 `maxRadiusPixels` 钳制，不会单独拒绝该帧，因此极端情况下会出现被上限截断的一次性模糊。这是本包明确的边界，不是“任何相机跳变都自动零模糊”的承诺。
9. TAA 下颜色/velocity/validity 都按当前 raster 坐标采样，velocity 值本身已去 jitter，不做额外坐标平移；GL 只验证 TAA 图顺序，没有做长序列时域稳定性/闪烁测量。非 TAA 路径 jitter=0，行为相同。
10. 未测性能、显存峰值、功耗或多硬件；`NOT_EVALUATED` 保留，不能从功能 PASS 推导性能结论。
