## 技术卡

| 字段 | 内容 |
|---|---|
| 技术 ID／用户场景 | #16 清漆层；车漆、上釉陶瓷、湿润/覆膜表面的第二层高光。首版不默认开启，不引入第二种材质系统。 |
| 当前基础／差距 | 已有唯一 metallic-roughness PBR 材质路径（`PbrMaterials` → `Material` → 唯一 `pbr-forward.frag`）、按粗糙度取 mip 的预过滤 IBL specular、BRDF LUT 与逐帧环境旋转。缺少“在基础层之上叠加一层独立粗糙度介质”的有界材质合同。 |
| 首版范围 | 单层、均匀权重清漆：固定界面反射率 `F0 = 0.04`、独立清漆粗糙度、可选切空间清漆法线贴图与 XY 强度；直接光与现有预过滤 IBL 共用同一个凸组合能量分割。 |
| 不支持 | 逐像素清漆权重/粗糙度贴图（`KHR_materials_clearcoat` 的 `clearcoatTexture`/`clearcoatRoughnessTexture`）、薄膜干涉、多次内反射/多次散射补偿、清漆法线贴图 uv set 1、清漆专属 AO/阴影、第二层透射或折射、glTF 扩展加载（见下）。 |
| 模块与控制 | `core.material.ClearcoatSettings`（GL-free 不可变值对象，公开 advanced）；`Material.clearcoat(...)`/`Material.clearcoat()`（默认 `disabled()`）；`pbr.PbrMaterials.createWithBindings(..., clearcoat, clearcoatNormal)` 与便捷入口 `createWithClearcoat(...)`；唯一 `pbr-forward.frag` 消费端。没有新增 manager、factory、Pass、纹理或 GPU owner。 |
| 材质默认 | 所有既有 `PbrMaterials` 工厂（含 glTF 路径 `GltfSceneAsset`）继续以 `ClearcoatSettings.disabled()` 构建：`uClearcoatEnabled = 0`，清漆法线贴图槽绑定共享扁平 PBR 法线 fallback。基础 PBR 路径不变；GL 用例验证重新禁用后与基础帧逐字节一致，不宣称与引入清漆前的历史 shader 二进制逐位一致。 |
| 纹理单元 | 清漆法线贴图固定 unit **5**（`PbrMaterials.CLEARCOAT_NORMAL_UNIT`）；0–4 为 metallic-roughness 角色，6 未使用，7 为方向光阴影，8–10 由逐帧 IBL binder 借用，11–13 为 point/spot shadow 与 GTAO。提供贴图时必须为 `TextureColorSpace.LINEAR`，与基础法线角色一致，构造期拒绝错误色彩空间。 |
| 界面 Fresnel | `clearcoatFresnel(cos) = F0 + (1 - F0) · (1 - cos)⁵`，`F0 = 0.04`（`CLEARCOAT_F0`，与 glTF clearcoat 模型及本渲染器基色电介质默认值一致）。`ClearcoatSettings.fresnel(...)` 是同一公式的 JVM 参考实现，`ClearcoatSettings.fresnel(1) = 0.04`、`fresnel(0.5) = 0.07`、`fresnel(0) = 1`。 |
| 能量分割（直接光） | 对每个灯：`h = normalize(v + l)`，`F_c = clearcoatFresnel(v·h)`。基础层直接项乘 `(1 - F_c)`；清漆项为同灯辐射度上的 `D_GGX(cn,h,α_c) · G_Smith(cn,v,l,α_c) · F_c / (4·(cn·v)·(cn·l)) · (cn·l)`。分割是凸组合：`base·(1-F_c) + coat·F_c`，不会超过两层中较亮者；`F_c = 0` 精确还原基础项。 |
| 能量分割（IBL） | 基础层 indirect（漫反射 + specular IBL + AO/GTAO/环境强度之前的项）统一乘 `(1 - F_ibl)`，`F_ibl = 0.04 + (max(1 - roughness_c, 0.04) - 0.04)·(1 - cn·v)⁵`，与基础 `fresnelSchlickRoughness` 同形。清漆项复用**现有** `uPrefilteredMap`（`textureLod`，lod = `roughness_c · uPrefilterMaxLod`，反射向量按现有环境旋转）和**现有** `uBrdfLut`：`prefiltered · (F_ibl · brdf.x + brdf.y)`，仅在 `uEnableSpecularIbl != 0` 时加入。清漆不新增 irradiance/漫反射环境项。 |
| 独立粗糙度 | 清漆粗糙度只取 `uClearcoatRoughness`，在 shader 内 `clamp(..., CLEARCOAT_MIN_ROUGHNESS = 0.045, 1.0)`；不读取 `uRoughnessFactor`、不读取 `uNormalScale`。setter 接受 `[0,1]`，0 映射到与基础层相同的安全下限。 |
| 法线空间 | 清漆法线贴图与基础法线贴图使用**同一约定**：采样 XYZ 由 `[0,1]` 解码到 `[-1,1]`，`sampled.xy *= uClearcoatNormalStrength`，再由 `pbr-forward.vert` 输出的切空间帧（`vTangent`、`normalize(cross(n, t)) * vTangentHandedness`、几何法线）构造 `mat3(t, b, n)` 旋转并 `normalize`。绿色为切空间 +Y（glTF `normalTexture` 约定），TEXCOORD_0。清漆层以**几何法线**为基准，而不是基础法线贴图扰动后的法线；因此基础法线贴图不会重复驱动清漆。强度为 0 时精确等于几何法线。 |
| 零值/禁用还原 | `uClearcoatEnabled = 0` 时清漆法线、粗糙度与所有额外项都不参与：`clearcoatNormalValue = n`、`clearcoatRoughness = 0`，直接光只走原 `directBrdf` 路径，IBL 不做 `(1-F)` 缩放也不加清漆项。所有清漆分支都是正向 guard（`if (uClearcoatEnabled != 0)`），禁用路径保持原采样序列与数值。 |
| 参数校验 | `roughness`、`normalStrength` 均为有限且 `[0, 1]`；`enabled` 为布尔。非法值在 `ClearcoatSettings` 构造期 `IllegalArgumentException`。`PbrMaterials` 校验清漆法线贴图色彩空间；`Material.Builder.clearcoat(null)` 抛 NPE。 |
| 装配期/运行期 | 清漆是**材质值**而不是 `RenderFeatureSettings` 拓扑开关：没有清漆时管线图完全相同，不新增 Pass 或附件。材质模板在 `build()` 时进入候选；逐对象差异应使用 `MaterialInstance` 覆盖 `uClearcoatEnabled`/`uClearcoatRoughness`/`uClearcoatNormalStrength`/unit 5，管线每帧重绑材质后生效，无需重建候选。 |
| 资源与失败 | 不新增 GPU owner。清漆法线贴图与 sampler 由调用方拥有（`PbrTextureBinding`），`PbrMaterials` 不拥有、不关闭；未提供时借用 `PbrFallbackTextures` 的 1×1 线性法线。`PbrMaterialBinder` 自身仍要求 ≥ 11 个 fragment 纹理单元（0–10），但完整 PBR forward program 还使用 7、11–13，因此实际需要 14 个单元；这是既有预算，不是清漆新增。禁用不释放任何宿主资源。 |
| 成本／回退 | 启用时每像素增加一次清漆法线采样、每灯一次 GGX/Smith 求值、一次预过滤 cubemap 采样与一次 BRDF LUT 采样；无额外 Pass、无历史、无 GPU 回读、无 `glFinish`。回退是禁用清漆或降低清漆粗糙度/强度。未做正式 GPU 测量，成本状态 `NOT_EVALUATED`。 |
| 参考与许可 | 算法为本项目自写 layered BRDF（GGX + Smith + Schlick 与现有 PBR 共用形式），无第三方 shader 或资产。JVM/GL 参考实现位于 `src/test`，不进入生产包。 |
| glTF 扩展 | **不承诺也不加载 `KHR_materials_clearcoat`**。现有策略不变：`extensionsRequired` 始终拒绝；`extensionsUsed` 仅产生 “ignored optional extensions” 警告；材质级 `extensions` payload 在默认 `strictExtensions = true` 下由 `GltfDocumentValidator` 以 “unsupported extension payload” 拒绝，在显式 lenient 策略下产生警告并被忽略。因此 glTF 资产中的 clearcoat 扩展**不会**自动变成 `ClearcoatSettings`；清漆材质必须通过 `PbrMaterials` 手工构建（本卡与 GL 用例只验证该路径）。若未来实现扩展加载，必须补真实 glTF fixture 的加载断言，而不是仅手建材质。 |

## 已知限制

1. 单层、均匀权重：没有 `clearcoatTexture`/`clearcoatRoughnessTexture` 的逐像素变化，权重恒为 1。
2. 能量分割为单次界面近似：没有多次内反射/多次散射补偿，也没有随粗糙度变化的清漆能量补偿项；
   这与 glTF 清漆模型的首版约定一致，但不等同于完整 microfacet 分层模型。
3. 清漆不参与阴影、GTAO、速度/历史或透明度排序：它只是同一 fragment 的附加 BRDF 项。
4. 清漆法线以几何法线为基准；基础法线贴图与清漆法线贴图分别驱动各自层，不叠加。
5. `KHR_materials_clearcoat` 不支持，glTF 材质仍按 metallic-roughness 解码（见上表）。
6. 逐帧切换清漆参数需要 `MaterialInstance` 覆盖；直接替换场景材质仍需重新 `build()`。
7. 未做正式 GPU 成本测量，也没有清漆专属质量档或诊断计数。
8. **夹具发现（既有渲染器问题，不在本包修复范围）**：`RenderPipeline.FRAME_OWNED_UNIFORMS` 未包含
   `uEnableDirect`/`uEnableDiffuseIbl`/`uEnableSpecularIbl`，而 `PbrMaterials` 模板会写这三个
   “帧门控” uniform。`SceneRenderer` 只在 shader 变化或材质命中帧属 uniform 时重绑 frame state，
   因此同一帧内**第二个及后续** PBR 材质的材质绑定会把门控值覆盖回模板默认的 1：
   `imageBasedLighting(false)` / `directLighting(false)` 对多材质场景只对首个材质生效。
   本用例因此改为单材质 + 实例覆盖；该问题应作为独立的渲染器修复（把三个名字加入帧属集合，
   或让 PBR 模板不再写它们），并补多材质 A/B 用例。
