# v0.24 风格化室外环境与体积阳光计划

状态：`0.24.0` 正式版，M0～M5 自动验收完成。编制日期：2026-09-07，
最近核对：2026-09-09。

目标首版：`v0.24.0`。代码基线：`v0.23.4` 之后的 `add2a30`，包含动态阴影裁剪与
稀疏阴影规划修复。本文件记录已实现的功能、验证证据和发布合同。

## 1. 版本目标

围绕一个可运行的“晨雾林地”样板场景，补齐天空、环境光、空气透视和受遮挡的体积阳光，
让 Render3D 能呈现有远近层次、冷暖关系和稳定光束的风格化室外画面。

当前 PBR、IBL、CSM、GTAO、HDR、曝光和 Bloom 已能作为基础。v0.24 的投入重点是
环境表现、光照一致性和内容质量；完成标准同时包含静态画面、移动镜头和性能证据。

| 首版必须交付 | 可见结果 |
| --- | --- |
| 光照与色彩基线校准 | 阴影区不过度发白，材质粗糙度、环境反射和曝光关系可解释 |
| 风格化天空与统一室外预设 | 天空、太阳方向、环境光和雾色协调，支持晨雾、晴天、黄昏 |
| 深度与 CSM 感知的体积阳光 | 树冠、墙体能遮挡光束，太阳离开屏幕后仍能形成正确光束 |
| 高度雾与局部雾体 | 地面薄雾、林间雾团、远景空气透视，不必把全场景染白 |
| 降采样、重投影与边缘处理 | 镜头移动时光束稳定，树干边缘不出现明显漏光和拖影 |
| 一个完整的室外样板及调试入口 | 能调参数、切预设、复现镜头，并查看效果成本 |

首版聚焦一盏主太阳及 OPAQUE/MASK 场景；树叶可以使用 MASK。透明/VFX 雾化列入
v0.24.1 候选。实时 GI、体积云、完整物理大气、连续昼夜、地形流送、Clustered Lighting、
Shader Graph 和后端重写均不进入 v0.24.0。

### 2.1 先验证 diffuse IBL 的归一化

当前 [irradiance.comp](../../src/main/resources/shaders/render3d/pbr/irradiance.comp)
使用余弦加权半球采样，并输出 `PI * average(L)`；两条 PBR fragment shader 随后直接以
irradiance 乘 base color。按这套储存约定，Lambert 漫反射应使用 `albedo * E / PI`。
代码显示存在缺少 `/ PI` 的嫌疑，必须先用隔离实验确认，而不是直接重调全局环境强度。

M0 增加常量辐亮度环境的数值基准：隔离直接光、specular 和 AO，读取曝光与 tone mapping 前的 HDR 目标，
验证预计算得到 `E = PI * L`，再验证漫反射项符合约定；单独验证完整材质中的 `kd` 权重。
若确认问题，两条 PBR shader 同步修正，并更新受影响的图像基线与默认曝光说明。
环境强度还影响 specular，不能作为掩盖漫反射归一化错误的补偿参数。

## 3. 画面与渲染方案

### 3.1 天空、太阳和环境光统一配置

首版采用可控的风格化天空：天顶/地平线渐变、地平线过渡、太阳圆盘和柔和光晕。
天空基础辐亮度同时用于生成 IBL，复用现有环境预计算；太阳圆盘单独显示，主太阳的
直接照明由方向光提供，防止把高亮太阳同时完整计入 IBL 和直接光。

一个室外预设协调天空参数、主太阳稳定 ID/方向/颜色/强度、雾参数、环境旋转、曝光和调色。
只有被指定的主太阳参与体积散射，其他灯光继续按既有表面照明合同工作。
晨雾、晴天和黄昏使用预生成或缓存的环境资源；参数调整通过显式“应用环境”构建候选，
全部准备成功后在帧边界协调替换。首版不承诺每帧重算 IBL 或连续昼夜插值。

数值进入 shader 前保持线性空间；辐亮度允许大于 1。密度使用场景长度单位的倒数，
样板约定 `1 world unit = 1 m`，避免更换场景比例后雾参数失去意义。

### 3.2 体积阳光的最小正确实现

首版选择屏幕空间降分辨率 ray marching。每条视线从相机积分到首个不透明/MASK 深度或
设定的最大距离；背景深度采用明确的有限积分距离。每个采样点按世界位置选择 CSM cascade，
查询太阳可见性，累计单次散射和视线透射率：

```text
T = exp(-integral(sigma_t * ds))
L_scatter = integral(T_to_sample * sigma_s * incident_light * phase * ds)
C_hdr = C_scene * T + L_scatter
```

`incident_light` 包含受 CSM 遮挡的太阳项及受控的环境散射近似；
`sigma_s = sigma_t * scattering_albedo`。提供密度、散射色、相函数各向异性、距离等艺术参数，
验证相函数的光线方向约定，避免前向散射方向反转。首版不包含多次散射或介质自阴影。

CSM 采样复用当前帧的矩阵、atlas 布局、有效槽和边界保护。体积采样不能使用终点的 cascade
覆盖整条光线，不能读取失效阴影槽。超出阴影有效覆盖区的直射体积贡献应平滑退去，
远景由环境雾接续；不能宣称在未覆盖区域仍有正确的遮挡光束。

先完成高采样、关闭历史的参考模式，再加入优化。屏幕空间径向模糊不作为这条链路的基础。

### 3.3 雾的层次与合成

支持全局指数高度密度，增加球体和盒体局部雾，首版最多 8 个局部体。
局部密度非负、重叠规则明确，支持相机在体内；可用世界坐标噪声、固定种子与风向形成缓慢流动。
先支持均匀局部体，再加入噪声，分别验证密度积分和动画稳定性。

普通解析雾和新体积模式由明确模式选择。体积模式负责近处的消光与散射；如保留远处解析雾，
它只覆盖 ray march 终点之后的全局介质区间，并按透射率正确组合。局部体超出体积距离时
不保证保留细节，需要可见的距离诊断。禁止把原全程 FogPass 再叠到已积分的同一段距离上。

### 3.4 抗噪声与运动稳定

使用确定性蓝噪声或等效低差异抖动，结合深度感知过滤/上采样，保留树干和地面轮廓。
低分辨率深度的选择与重建必须明确，覆盖细枝、MASK 边缘、天空边界和相机贴近几何体的情况。

体积历史单独储存散射/透射率及重投影所需数据，以代表性散射位置重投影，并辅以深度拒绝、
邻域裁剪和受限历史权重。这是屏幕空间近似，不能以不透明终点深度代表所有体积运动。
快速变化时降低历史权重，必要时回退当前帧空间过滤。

相机切换、resize、质量档切换、场景替换、环境/太阳突变及阴影内容改变必须拒绝受影响历史；
首版允许保守清空。连续噪声动画需要控制历史权重，不能每帧清空后仍声称有时域收益。
深度重建与几何 pass 使用相同帧的相机和 jitter；历史只在帧成功后提交。

样板默认使用 FXAA，体积历史独立启用。场景 TAA 的已有运动拖影需要单独记录，
本版本不承诺重写整套场景 TAA；新增体积效果造成的拖影仍必须修复，不能归因于旧链路。

## 4. 管线、所有权与支持边界

### 4.1 正式 HDR 接入

目标顺序如下，具体 pass 名称在实现时确定：

```text
当前帧阴影计划 / CSM → HDR 场景与天空 → 场景 AA 或颜色 resolve
                                 ↘ 当前帧深度 / 必需的 MSAA 深度 resolve
CSM + 相机 + 深度 + 介质快照 → 体积积分 → 独立历史过滤 → 深度感知上采样
HDR 场景 + 散射/透射率 → 环境合成 → 自动曝光统计 → Bloom → Tone Mapping/LUT
                                                       → FXAA（如启用）→ Present → UI
```

体积散射在线性 HDR 内参与曝光与 Bloom，UI 不受雾化。关闭新体积模式时保留现有
HDR VFX 等通路。已有 advanced `VolumetricLightPass` 不自动迁移为这条正式管线。

MSAA 统一复用 typed depth resolve 合同，不因多个深度消费者重复创建同尺寸 resolve 目标。
兼容性策略在 GL 分配前校验；后续场景修改若产生不支持的组合，也应在提交绘制前报告。

### 4.2 首版组合矩阵

| 组合 | v0.24.0 合同 |
| --- | --- |
| HDR + OPAQUE/MASK + 主太阳 CSM | 正式支持，是样板基础 |
| NONE / FXAA / TAA / MSAA 4x | 全部验证；体积历史独立于场景 TAA |
| GTAO 开/关、Bloom 开/关、手动/自动曝光 | 正式支持，曝光不能靠异常增亮掩盖雾错误 |
| UI、窗口与借用外部 FBO、resize、场景替换 | 正式支持，保持宿主目标所有权 |
| 无主太阳或无有效太阳阴影 + 新体积模式 | 明确拒绝；普通解析雾仍可使用 |
| ALPHA/ADDITIVE 材质或 HDR VFX + 新体积模式 | 首版明确拒绝，等待逐层深度/散射合成支持 |
| LDR + 新室外体积链路 | 明确拒绝 |
| 新体积模式关闭 | 不新增以上透明/VFX 限制，也不分配体积目标和历史 |

透明表面不可靠地写入首个场景深度。把合成后的透明颜色统一按后方不透明深度雾化，
会得到错误遮挡；所以首版不把这个组合默认为“已支持”。这一限制只针对新体积模式，
必须在 API、demo 和能力矩阵中说明。

### 4.3 生命周期与变更边界

- 室外参数以不可变快照和 revision 进入 `RenderFrameContext`，不在录制途中读取可变配置。
- 密度、颜色等纯参数修改不重建图；启停、分辨率档和资源布局进入 topology。预设切换的
  天空、IBL、太阳和曝光必须成组提交，失败后旧环境继续可用。
- 环境缓存/加载方拥有 `PbrEnvironment`，pipeline 借用；图内临时目标及体积历史由对应
  `PipelineGeneration` 拥有。缓存有明确容量与释放时机，禁止预设切换无限保留旧纹理。
- 新资源从第一阶段接入 prepare/commit/rollback；resize 失败不破坏旧代次，零尺寸暂停
  不创建无效目标，清理失败保留原始异常，失败帧不污染后续历史。
- 当前 UI attachment 与具体图关联。更换 pipeline generation 时必须定义重绑机制并验证，
  不能假设旧 attachment 自动迁移，也不能通过重复 attach 绕过保护。
- 雾噪声和参数动画本身不触发 CSM caster 重绘；窗口尺寸变化不改变固定阴影分辨率。

新 pass 和历史状态使用独立的小型职责对象，避免继续堆入 `RenderPipeline`。
场景/光照相关代码归 `render3d`，通用过滤才放入 `postprocess`，不把太阳和场景所有权放进
`core` 或 `backend`。新公共配置先按 advanced API 管理，待 demo 与合同稳定后再提升等级。

## 6. 样板与工具交付

“晨雾林地”包含近景岩石/树干、中景林间小径/树冠、远景坡地或山体，使用一致的风格化
色彩和比例。可以采用项目自有程序化低多边形资产，但 base color、normal、roughness、
metallic 和 AO 的含义必须正确；缺少贴图时使用有意义的常量，不继续用演示图片假充法线。

三种预设共用场景：晨雾强调低角度暖阳与冷色阴影；晴天检查材质和清晰度；黄昏检查暖色天空、
长阴影和远景层次。自动曝光单独验证，标准对比截图固定曝光，防止对比结果被曝光漂移干扰。

调试面板提供预设、太阳、密度、高度、局部雾、散射方向性、质量档、历史开关和对比开关，
可查看深度、CSM 有效范围、散射、透射率及历史拒绝情况。配置可以保存/重载；场景时间、
噪声种子、相机路径和参数一起记录，使截图和性能运行可重复。可见入口为
`Render3dOutdoorEnvironmentDemo` 的 `OutdoorEnvironmentOverlay`，隐藏验证不附加 UI。

资源放在 demo 资产目录，补充来源、许可和 manifest；保留现有确定性 PBR 环境夹具。
复用现有调试 UI 和资产机制，不在此版本建设新的编辑器或场景文件格式。

## 7. 性能目标与测量方式

以下为待 M0 校准的预算目标，不是现有实测结果。参考硬件沿用项目已有记录中的
RTX 3050 Laptop GPU；必须同时记录实际驱动、功耗模式、分辨率、CPU 和运行提交。

| 档位 | 内部分辨率 | 采样步数初值 | 使用目的 |
| --- | --- | --- | --- |
| Low | 每轴 1/4 | 16 | 低成本与关闭历史时的退路 |
| Balanced 1080p | 每轴 1/2，即 960×540 | 32 | 默认验收档 |
| Balanced 4K | 每轴 1/4，即 960×540 | 32 | 4K 默认验收档 |
| High | 每轴 1/2 | 64 | 可选画质档，不要求 4K 达到 Balanced 成本 |

Balanced 的初始目标：1080p 体积链 GPU p95 ≤ 3 ms，4K ≤ 5 ms；新增 CPU p95 ≤ 0.3 ms。
这些是增量成本目标，整帧帧率还取决于场景与原有渲染成本。
新增 GPU 资源占用目标分别 ≤ 64 MiB / 128 MiB，包含所需深度 resolve、全分辨率合成目标、
过滤与历史，另列环境缓存及代次切换峰值。显存按实际同时存活资源计数，不只统计低分辨率纹理。

关闭新功能时不分配体积专用目标/历史；配对测试中 CPU/GPU p95 回退目标均不超过
`max(0.1 ms, 原基线的 3%)`。体积链计时覆盖新增深度处理、积分、过滤和合成，不重复计算共享
CSM 成本；同时报告整帧增量和阴影成本，避免掩盖曝光/Bloom 或阴影联动的额外开销。

每组预热至少 120 帧、测量至少 600 帧、五轮，关闭 VSync，使用同一场景/相机/曝光进行
配对开关测试；记录 p50/p95、分配量、GPU 查询有效样本和各 pass。先求逐帧链路总耗时再求
p95，不把各 pass 的 p95 相加。校准后固定预算；若无法满足，记录原因并选择降档或优化，
不能在发布时无说明放宽。

## 8. 验证与发布门禁

### 8.1 必须证明的正确性

- 数值：常量环境 IBL、均匀介质的指数透射率、零密度恒等、非负有限输出、散射方向约定、
  局部体相交/重叠、全局雾分段组合、非法参数与越界预算拒绝。
- 真实 GL：遮挡/无遮挡成对画面，移动遮挡物，太阳出屏，CSM 边界及失效槽，天空深度，
  MASK 细枝，摄像机进入雾体；高采样参考与 Balanced 比较。
- 运动：20–30 秒固定路线含平移、旋转、近物遮挡变化和快速转向；相机切换、预设变化及失败
  帧之后不残留旧光束。人工检查录像，数值通过不能替代运动画质判断。
- 组合：第 4 节矩阵覆盖 1080p/4K；不支持的透明/VFX 组合给出可定位错误，关闭体积后恢复
  现有支持。对原 PBR、阴影、GTAO、UI 和 embedded rendering 做回归。
- 生命周期：初始 soak 目标至少 3,600 帧、100 次预设/尺寸切换、10 次候选构建失败注入，
  覆盖启停、零尺寸恢复、UI 重绑、外部目标替换与 dispose；检查资源稳定及宿主资源未被释放。

### 8.2 拟新增的验证入口

下表是已实现的可运行命令，均复用同一 runner 和样板资源。

| 计划任务 | 职责 |
| --- | --- |
| `runOutdoorEnvironmentDemo` | 样板、预设、参数调节与对比视图 |
| `runOutdoorEnvironmentIntegration` | 数值/图像参考、遮挡、雾体与组合矩阵 |
| `runOutdoorEnvironmentStabilityIntegration` | 历史、resize、代次失败回滚、UI/宿主与 soak |
| `runOutdoorEnvironmentBenchmarks` | 五轮固定镜头 1080p/4K 与效果开关成本 |
| `localOutdoorVerification` | 汇总专项验证，不另造一套结果格式 |

纯 JVM 验证进入现有 `check`；专项 GL 入口接入 `localGlVerification` 和发布证据收集。
Windows/Linux CI 使用可无窗口执行的完整 `check` 与 demo 编译，真实 GL 和人工画面保留
明确的独立验证环境，不能把 skipped 记录成通过。正式候选执行现有 `releaseReadiness`，
并按其规则归档同一候选提交对应的专项性能与人工验收记录。
版本元数据必须在候选冻结前完成；验证后修改代码或版本信息需要重建对应证据。

## 9. v0.24 之后的选择

| 后续候选 | 启动条件 |
| --- | --- |
| v0.24.1：透明/VFX 雾化、薄叶背光与风动 | 晨雾林地已有稳定基础；先解决透明层的透射/散射组合，再扩展特效。顶点风动必须在主 pass/阴影 pass 一致，并更新保守 bounds/失效规则 |
| 后续：轻量云层、云影与连续昼夜 | 明确环境更新预算，避免每帧重建完整 IBL；先让太阳、天空、雾和云影使用一致时间 |
| 后续：更完整的大气或局部环境探针 | 样板证明天际线或局部环境照明已经成为主要画质限制 |
| GI / Clustered / GPU-driven | 分别由间接光需求、多灯需求和提交瓶颈证明，单独立项 |

以上是候选方向，不承诺版本号、工期或在 v0.24.0 内顺带完成。
