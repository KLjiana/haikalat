# Haikalat 实时渲染技术未来计划大纲

日期：2026-11-11。基线：0.27.5。状态：未来任务大纲与优先级建议，尚未冻结后续版本范围。

近期版本更新：A 组首批 #1/#2/#3/#7 已按[0.28 战斗特效材质与动态光照实施计划](v0.28.0-combat-vfx-materials-and-lighting.md)实现，聚焦验收见[0.28 验收](../releases/v0.28.0-review.md)。该计划承接本文原暂标为 0.27.6 的技术方向；其具体范围与验收以版本计划为准，其余分组继续保留为未排期候选。

面向 Java 21 / OpenGL 4.6、RTX 3050 Laptop 级别目标设备及风格化战斗游戏的表现需求。本文编排用户提供的 46 项技术，不表示这 46 项已经实现、全部值得实现，或能同时满足目标帧率。性能评分保留为相对估计；本次没有运行 GPU 测量或重新验收现有功能。

## 1. 文档定位与决策规则

本大纲回答三个问题：哪些技术值得先做、怎样组织为完整功能、以什么证据判定完成。单个版本开工时，再从这里选择一个主目标，形成具体实施计划。

- 当前能力以[能力矩阵](capability-matrix.md)、生产源码和对应候选验收记录为准。
- 依赖与资源遵循[模块合同](../architecture/v0.27.3-render3d-module-contracts.md)、[共享表面合同](../architecture/v0.27.2-shared-scene-surface-contract.md)和[统一控制合同](../architecture/v0.27.4-render3d-feature-control.md)。
- 新技术开工前补齐 [0.27.5 技术提案卡](v0.27.5-agent-and-test-governance.md#8-未来实时渲染技术提案卡)，本文的范围表不能替代具体算法、参考依据及资源规格。
- [0.27.6 候选方案](v0.27.6-candidate-tasks.md)保留原来的 UI／预设／空间混合等选项。战斗特效方向的近期实施范围已单独整理为 0.28 计划，不要求先完成这些工具候选。
- [旧 OpenGL 路线图](haikalat-future-opengl46.md)作为历史候选库；其中旧排期、人月数、目录和已完成能力不直接继承为新承诺。

### 1.1 优先级怎样确定

依次考虑：实际内容是否需要 → 当前基础能复用多少 → 能否形成可组合的创作能力 → 工程与验证成本 → 目标硬件实测成本。视觉回报和 GPU 开销只占其中一部分。

| 维度 | 判断方式 |
|---|---|
| 内容价值 | 是否直接改善技能、角色可读性、战斗空间或经常出现的场景 |
| 组合价值 | 能否由共同时间、参数、材质和资源引用组合，而非只存在独立演示 |
| 工程成本 | 涉及多少真实消费者、输入协议、资源 owner 和资产流程 |
| GPU 成本 | 在明确分辨率、覆盖率、灯数、质量档和硬件状态下测量 |
| 风险 | 是否引入新历史、新场景表示、多视图、透明排序或平台扩展 |
| 维护成本 | 是否扩大 shader 变体、配置组合、公共 API 与回归矩阵 |

不把序数评分直接相除生成精确收益比例；不因为某项 GPU 便宜，就默认其开发和长期维护也便宜。

### 1.2 评分与成熟度

后文“开销／回报”沿用原榜单：1 为低、5 为高；“条件／间接”表示不能按普通画面效果直接比较。原编号只用于追踪，新的实施顺序由分组决定。

后续能力登记使用：候选 → 原型 → 已集成 → 范围内已验收。功能、性能与发布分别记录；阶段完成不自动改变 `performance=NOT_EVALUATED` 或发布状态。本文未做全库 46 项完整审计，未列为现有基础的技术应在立项时再次检索，不据此断言代码中完全没有相关实现。

### 3.1 A：战斗特效表现基础

目标：作者能组合出蓄力、能量护盾、刀光、命中反馈和消散过程。先连通共同时间与参数，再扩展效果数量。

| ID | 技术（开销／回报） | 最小交付范围与归属 | 关键输入／验收重点 |
|---|---|---|---|
| 1 | Fresnel / Rim Lighting（1／5） | 有可靠法线的网格 VFX／角色材质提供颜色、强度、指数和遮罩；所属绘制模块消费材质值 | 明确法线空间、双面语义与观察方向；独立角度算例和旋转镜头对照；不把广告牌平面边缘冒充曲面轮廓光 |
| 2 | UV Flow / Distortion（1／5） | VFX 材质支持 UV 流动及有界噪声扭曲，复用资产与纹理 owner | 明确局部／全局时间、wrap、图集边界和 Flipbook 运算顺序；零幅度恢复基线，无帧率相关漂移 |
| 3 | Dissolve / Erosion（1／4） | VFX 噪声阈值、边缘宽度／颜色／发光与生命周期曲线 | 0/1 端点、单调覆盖率、稳定种子；若推广到场景材质，同步 MASK、shadow、surface 和时域覆盖变化 |
| 5 | Vertex Displacement（2／5） | 先选一个有界网格位移模型；geometry／材质与相关绘制共同消费 | 明确与 skin/morph 的顺序、位移后法线、上一帧形变及 bounds；覆盖可见性、阴影、深度和 velocity，不能只改最终颜色 Pass |
| 7 | VFX Dynamic Lighting（2／5） | 少量无阴影点光／聚光的生命周期桥接；VFX 产出纯数据，装配层接现有 lighting | stable ID、位置、颜色、强度、范围、容量和回收规则；灯满时确定性裁减；停止／取消／重放不残留灯 |

建议先交付 #1/#2/#3/#7，#5 在真实变形消费者明确后接入。#7 不把“每粒子一盏灯”作为默认模型；发光材质本身也不等于已经照亮周围场景。

组级出口：同一效果资产可控制生成、持续、消退；相同种子和时间可重复；材质参数进入真实生产绘制，动态光进入现有灯表；关闭效果后无残留资源或灯实例。

### 3.2 B：特效与场景交互

目标：技能影响屏幕与场景表面，角色和特效获得空间关系。按共同输入合同组织，避免每个效果自行复制深度或颜色。

| ID | 技术（开销／回报） | 最小交付范围与归属 | 关键输入／验收重点 |
|---|---|---|---|
| 4 | Screen-Space Distortion（2／5） | VFX 产生扭曲贡献，颜色合成模块消费；先支持有限层次的冲击波／热浪 | 明确采样的是哪阶段的 HDR 颜色、深度遮挡、UV 越界、重叠和透明顺序；读写附件分离，不能采样正在写的同一图像形成未定义反馈 |
| 6 | Projected Decals（2／5） | 先选择颜色／发光覆盖型投射贴花；如需改粗糙度／法线，另定材质输入方案 | 深度重建、投影体积、接收面过滤、法线来源和重叠顺序；斜坡／墙角／薄墙／移动物体测试；不假定当前 Forward 已有完整 G-buffer |
| 9 | Contact Shadows（2／4） | 首版限定主方向光的短距离屏幕空间遮挡，归属 shadow 并由 lighting 消费 | 深度、步长、厚度、最大距离和已有阴影组合；接触位置对照、屏幕边缘与离屏缺失回退，不能冒充完整阴影 |
| 10 | Cloud Shadows（2／4） | environment 提供云遮罩／变换事实，lighting 决定如何调制指定光源 | 世界空间稳定、太阳方向、滚动速度和衰减；相机移动不使云影粘屏；不依赖先实现体积云，不无差别压暗 emissive／IBL |

组级出口：明确透明物体、天空和 UI 是否受影响；共享附件的 MSAA resolve、分辨率与代次符合合同。选择一个战斗场景覆盖角色遮挡、贴花落点和冲击波，不为每项创建新 Demo 任务。

### 3.3 C：材质与局部光照

目标：提升常见场景与角色材质的辨识度。每个子项可以独立选入版本，不能把整组视为一次小改动。

| ID | 技术（开销／回报） | 最小交付范围与归属 | 关键输入／验收重点 |
|---|---|---|---|
| 8 | Thin Translucency（2／5） | 首版薄叶／薄布背光透射，归属材质与 PBR 光照；承接旧 0.25.1 的相关需求 | 双面法线、厚度／透射参数、MASK 与投影一致；正背侧光对照；区分艺术化透光和有能量约束的模型 |
| 16 | Clearcoat Shading（1／3） | PBR 增加可关闭清漆层，明确参数和资源映射 | 基底与涂层的能量处理、独立粗糙度／法线、IBL 一致性；参数归零恢复基底；若支持 glTF 导入，覆盖实际扩展解析链 |
| 17 | Anisotropic Shading（2／4） | 面向拉丝金属／织物的各向异性高光 | 切线基、方向纹理、镜像 UV、退化切线和 IBL 近似；旋转灯光与物体对照，限制不支持输入 |
| 18 | Local Reflection Probes（3／4） | 优先预计算探针，支持影响区域、选择／混合和全局 IBL 回退 | cubemap 来源、mip／粗糙度、局部校正、加载与 owner；区域边界和资源缺失；实时捕获、预算更新单独扩展 |
| 19 | PCSS（3／4） | 首版选定一类灯，在既有 shadow 图集上实现软阴影采样 | blocker 搜索、滤波预算、光源尺寸、深度单位、图集边界和 bias；软硬变化独立参考，避免跨 tile 采样 |
| 31 | Parallax Occlusion Mapping（3／3） | 先限定有切线空间的近景材质，提供距离／角度衰减 | 高度图、UV、步数和 grazing angle；明确是否改变深度、阴影与轮廓；若不改变，公开该近似边界 |

组级出口：材质参数与全局能力控制分层；不同实例可用不同材质值。资源格式和资产导入不能只在 Demo 中绕开。清漆、各向异性及透射的参数设计可参考 [Khronos PBR 材质说明](https://www.khronos.org/gltf/pbr/)，但采用类似参数不等于实现了对应 glTF 扩展。

### 3.4 D：水体、折射与反射

目标：先交付一个可靠水面，再根据内容扩展玻璃和更多反射来源。不是同时开发六种完整算法。

| ID | 技术（开销／回报） | 最小交付范围与归属 | 关键输入／验收重点 |
|---|---|---|---|
| 14 | Water Surface Rendering（3／5） | 有限水面、法线／波动、吸收色与岸边过渡；按需要设有真实职责的水体包 | 波形时间、bounds、世界尺度、深度厚度；水岸、相交物体和镜头掠射；水下视图和流体模拟首版可明确排除 |
| 11 | Screen-Space Water Refraction（2／4） | 水面作为折射颜色输入合同的首个消费者 | 背景颜色快照、深度厚度、前景泄漏拒绝和边缘回退；不需要先做完整通用折射材质体系 |
| 13 | Refraction（3／5） | 在已有输入合同上扩展单层玻璃／护盾，明确折射率与厚度近似 | 多层透明和离屏信息的限制、粗糙透射、读取时机；不能把简单 UV 偏移宣称为完整物理折射 |
| 30 | Planar Reflections（4／4） | 限定数量的平面反射视图，提供分辨率／更新频率控制 | 镜像相机、裁剪面、绕序、独立视图历史、禁止递归；反射目标 resize／失败回收和额外场景绘制成本 |
| 20 | SSR（3／4） | 有限射线步数、命中置信度与探针／环境回退，明确首版粗糙度支持 | 深度、法线、粗糙度来源、颜色阶段；离屏、遮挡、薄物体和镜头变化；需要降噪时联动 #34 |
| 36 | Caustics（3／3） | 首版可选有明确艺术定位的投射焦散；物理求解另立目标 | 水体／接收面关系、时间与光方向；标明投影近似，避免穿墙照亮和与水外场景无条件混合 |

建议顺序：#14 + #11 → 按需求选择 #30 或 #18 作为反射来源 → #13／#20 → #36。不是要求三种反射方式全部叠加。

参考 [KHR_materials_transmission](https://github.com/KhronosGroup/glTF/blob/main/extensions/2.0/Khronos/KHR_materials_transmission/README.md) 区分材质透射参数与具体屏幕空间实现；导入合同和渲染算法分别验收。

### 3.5 E：镜头与最终画面

目标：支持需要的镜头风格，同时保持战斗目标和 UI 可读性。小效果可以合并开发，但不默认全部开启。

| ID | 技术（开销／回报） | 最小交付范围与归属 | 关键输入／验收重点 |
|---|---|---|---|
| 12 | DOF（3／5） | postprocess 的可控焦距／焦点效果，先用于展示和受控镜头 | 深度与 CoC 约定、前景扩散、透明覆盖；焦内清晰、焦外变化、边缘漏色；UI 合成位置明确 |
| 21 | Motion Blur（3／4） | 基于有效 velocity 的镜头／物体运动模糊 | jitter 去除、曝光时间、最大半径、遮挡；静止不模糊、相机切换不拖尾；无运动向量的 VFX 明确策略 |
| 22 | SMAA（2／3） | 优先 SMAA 1x，作为现有 AA 选项的补充 | 查找纹理许可／指纹、颜色空间、边缘处理；与现有 AA 模式明确选择关系，不任意叠加；参考[作者实现](https://www.iryoku.com/smaa/) |
| 23 | Vignette（1／2） | 最终画面暗角参数，优先复用合适的合成阶段 | 宽高比、中心／边缘、零强度；UI 是否受影响明确 |
| 24 | Film Grain（1／2） | 受控噪声与可重放种子／时间 | 亮度响应、输出分辨率及与 TAA 的顺序；截图对照冻结随机输入，避免噪声污染历史 |
| 25 | Chromatic Aberration（1／2） | 有界色差，用于短时受击或特殊镜头 | 中心保持、UV 边界、强度上限和关闭还原；不影响需要清晰阅读的 UI |

组级出口：固定镜头下独立参数可解释，UI 不被意外后处理；效果开关和预设加载一致。DOF／运动模糊的目标是特定镜头表现，不预设为战斗默认画质提升。

### 3.6 F：粒子规模、性能与重建

这是一条按瓶颈和消费者启动的支线。每项优化必须与原路径比较整体成本；新增 Pass 很快不代表总帧变快。

| ID | 技术（开销／回报） | 最小交付范围与归属 | 关键输入／验收重点 |
|---|---|---|---|
| 27 | GPU Particle Indirect Rendering（条件／间接） | GPU 粒子从实验走向生产：活跃集合、可控发射、间接绘制与资源 owner | 计数上限、空集合、命令 buffer、barrier、寿命与回收；与直接绘制对照，不读取 GPU 计数到 CPU 才决定每帧 draw |
| 15 | Depth-Based Particle Collision（2／4） | 在 GPU 粒子更新中消费受控场景深度 | 深度对应帧、坐标空间、穿透步长与响应；离屏／遮挡信息缺失明确；不为 CPU 粒子引入逐帧同步深度读回，不替代游戏物理 |
| 26 | GPU Particle Sorting（2／3） | 对需要 alpha 混合的粒子按既定深度键排序 | 数量非幂次、稳定键、多个发射器的排序范围；与 CPU 小样本 oracle 对照，说明与网格透明物体的交错限制 |
| 28 | Weighted Blended OIT（3／4） | 为选定烟雾／粒子透明集合提供近似无序合成 | 累积／透射附件、blend 和 resolve；与已排序参考比较；不保证等同精确排序，不直接解决折射与所有透明交错 |
| 34 | Temporal Denoising（2／3） | 绑定 SSR、SSGI 等真实信号的重投影、拒绝和滤波；归属信号模块 | 历史格式、velocity、置信度、反遮挡、亮度突变；独立高样本参考及运动序列，不能用一个滤波器无条件处理所有信号 |
| 35 | Temporal Upscaling（3／间接） | 明确输入／输出分辨率、抖动与重建路径，作为独立技术目标 | 深度、velocity、reactive、曝光、锐化及 UI 输出；与原生分辨率做质量／总耗时对照；OpenGL 移植范围与许可单独确认 |
| 41 | Adaptive Sampling（条件／间接） | 对已确认昂贵的具体采样器进行预算分配 | 误差／方差估计、最小样本、稳定性；不能把质量档切换称为自适应采样，保留固定预算 oracle |
| 42 | Variable Rate Shading（条件／间接） | 检测可用扩展后，对适合的 Pass 选择性降低着色密度 | capability、图像／状态 owner、屏幕区域和宿主恢复；不支持时正常全速率绘制；细线、文字、导数与透明内容重点比较 |

#26 与 #28 是按透明内容选择的路线，不要求按顺序全部实现。Weighted Blended OIT 的原始方案见 [McGuire / Bavoil 论文入口](https://www.jcgt.org/published/0002/02/09/)，具体允许误差需随本项目消费者定义。

OpenGL VRS 的可用性需查询实际实现，例如 [GL_NV_shading_rate_image](https://registry.khronos.org/OpenGL/extensions/NV/NV_shading_rate_image.txt)；OpenGL 4.6 核心版本或 RTX 名称本身不能替代扩展检测。这里的回退是功能关闭／质量回退，不是新增 OpenGL 3.x 后端。

### 3.7 G：按内容立项的专项能力

只有美术资源、镜头和使用频率足以证明需求时才立项；不因视觉评分高自动排在战斗基础之前。

| ID | 技术（开销／回报） | 最小交付范围与归属 | 关键输入／验收重点 |
|---|---|---|---|
| 29 | Atmospheric Scattering（3／4） | environment 的天空／大气模型，明确与现有风格化天空的选择关系 | 天体方向、大气参数、LUT／计算成本、地平线与曝光；与体积雾边界衔接，避免重复积分同一介质 |
| 32 | SSS（4／4） | 先确定皮肤／蜡等目标材质与散射模型，再选择实现 | 单位尺度、厚度／轮廓、散射 profile、光照分离；是技术目标，不预设必须另做一套全场景系统 |
| 33 | Screen-Space SSS（3／3） | #32 的一种候选实现，作用于标记材质的散射分量 | 材质 mask、深度／法线边缘、世界尺度到像素尺度；不模糊高光或串色到背景；离屏限制明确 |
| 38 | Volumetric Particles（4／4） | 有限局部烟团／尘团的密度表现，先选解析体或局部网格 | 密度、光照、步数、重叠与深度合成；与已有体积雾如何组合先定义，不能简单重复叠加介质 |
| 40 | Volumetric Clouds（5／5） | 有限云层／天气范围和分辨率预算 | 密度资产、空域、光照、步进、历史、云影；高速镜头、地平线、曝光和显存测试；#10 可独立先行 |
| 46 | Hair Strand Rendering（5／2） | 仅在发丝资产与近景镜头明确时研究；卡片发束仍可作为内容方案 | strand 数据、宽度、LOD、各向异性、透明与阴影；模拟是否需要另定，不自动建设完整毛发工具链 |

#32/#33 属于目标与实现路线关系，不能按两个互不相关的功能累计完成度。#38 是渲染表现，不自动包含 #43 的流体模拟。

### 3.8 H：高成本研究候选

研究出口可以是“暂不采用”。先证明输入可得、结果可信和预算可承受，再决定生产化；避免原型直接成为默认管线依赖。

| ID | 技术（开销／回报） | 最小研究问题 | 进入生产计划的条件 |
|---|---|---|---|
| 37 | Stochastic Transparency（3／3） | 目标透明内容能否在可接受样本数下稳定 | 覆盖概率、时域收敛和运动噪声有参考；证明相对排序／OIT 的实际收益 |
| 39 | SSGI（4／4） | 屏幕可见信息能否给目标室内场景带来稳定间接光 | 深度／法线／材质／radiance 输入可信；与直接光、IBL、AO 的组合无明显重复；联动 #34 和离屏回退 |
| 43 | Volumetric Smoke Simulation（5／4） | 有界网格烟雾模拟是否比预制／解析烟雾更符合内容需求 | 时间步、边界、注入／消散、稳定性与显存可控；模拟 owner 和体积渲染 owner 清楚 |

| 45 | Voxel Cone Tracing（5／4） | 场景体素化及辐射更新是否适合目标场景尺度 | 体素占用／radiance、mip、动态更新、漏光、越界和显存可测；不要与 DDGI 同时建设两套场景表示 |

DDGI、VCT、SSGI 不是必经的升级链。正式立项时选一种能服务当前内容的路线，其余保留对照或候选。

## 4. 横向协作与模块归属

### 4.1 功能数量不等于模块数量

```text
subsystems.vfx
  资产、材质值、时间曲线、实例状态、纯 CPU 模拟／输出数据
        │
        ├── render3d.vfx：特效 GPU 绘制、相关资源、GPU 粒子
        └── 装配／桥接 → render3d.lighting：特效灯消费

render3d.geometry / pbr / gltf
  几何与材质消费、资产参数导入、形变协议

render3d.surface
  按消费者需求提供共享深度／法线／运动等通道

render3d.shadow / lighting / environment
  阴影、光照与环境各自的数据、算法和 owner

postprocess 各效果包
  镜头与颜色链效果，通过自身输入合同接收数据

render3d.pipeline
  模块装配、输入适配、候选发布和所有权转交
```

以上是职责映射，不是提前批准新增类名。水体／反射等确有独立生命周期时可新增职责包；同时更新架构门禁和公共 API 清单。现有模块依赖检查包含显式包名单，新包不能因为不在名单中就绕过边界。

### 4.2 控制粒度

- 管线能力层：需要新 Pass、共享输入或 GPU owner 的正式能力接 `RenderFeaturesControl` 及依赖策略。
- 材质／实例层：UV 速度、溶解阈值、轮廓颜色等留在材质／实例参数；不为每个数值添加全局开关。
- 时间层：显式区分游戏时间、效果局部时间、暂停和重放；不能让 shader 墙钟时间绕过作者控制。
- 工具层：UI 编辑草稿，提交有效配置，展示 requested／effective 和失败原因；不直接修改 GPU 资源。

### 4.3 新技术的共同输入合同

每项至少声明：格式、线性／非线性颜色空间、深度与坐标约定、采样数、分辨率、jitter、velocity、帧序和代次。不能仅用“拿一张深度图”描述输入。

新增输入只由真实消费者驱动；需要粗糙度／材质 ID 的技术先盘点来源，再决定是否扩展 surface，不能预先建立没有消费者的全量 G-buffer。

### 4.4 生命周期与性能约束

1. 纯 CPU 准备与 GPU owner 操作分开；GL 创建／销毁保持正确线程和 context。
2. 候选完整准备后在帧边界发布；发布前失败保留旧生效代并释放候选自有资源。
3. 发布后退役失败保留新代和正确 revision，报告退役问题；不能伪报已回滚。
4. borrowed 资源不由效果销毁；共享输入仍有其他消费者时继续保留。
5. 总暂停保留配置与资源；功能关闭移除自身执行，按 owner 合同处理不再需要的专属资源。
6. 标量变化不无故重建图；资源规格／拓扑变化走事务；跨代帧租约不得复用。
7. 历史只在成功帧提交；失败后的状态恢复不等于 GPU 像素已回滚。
8. 不新增逐帧同步读回、全局 `glFinish` 或无界诊断；优化以整个消费者路径的证据为准。

### 5.3 建议验收合同

以下 ID 是本大纲的验收条目，不是当前已有 JUnit 方法或构建任务；正式计划按现有合同索引映射测试。

| ID | 必须观察到的行为 |
|---|---|
| RT-A01 | 所有新增参数关闭／归零后，在约定容差内恢复既有材质基线 |

| RT-A10 | 多效果同时运行的实例数、灯数、纹理与诊断有界；记录代表负载，不把“可运行”写成性能达标 |

## 6. 性能预算、画质档与证据

### 6.1 目标设备记录

RTX 3050 Laptop 是目标档位，正式测量需要记录具体设备、驱动、可用显存、功耗／电源模式、分辨率、AA、场景和质量档。本纲要不由设备名称推断固定毫秒或帧率。

可先用 1920×1080 建立代表负载，并在有低分辨率目标时补 1280×720；这只是测量建议，正式预算和目标帧率在技术立项时冻结。显示分辨率与内部渲染分辨率分开记录。

### 6.2 每组预算应该关注什么

| 技术组 | 主要控制变量 | 可选降级方式 |
|---|---|---|
| A 战斗特效 | 覆盖像素、透明层数、实例数、灯数、shader 变体 | 限制灯数／可见实例、关闭某类艺术效果；不只统计粒子总数 |
| B 屏幕交互 | 颜色副本、深度采样、投射体数量、射线步数 | 限定屏幕覆盖／距离、降低步数、降低适用效果分辨率 |
| C 材质光照 | 材质覆盖率、探针数量／分辨率、阴影采样与更新 | 降低探针预算、限制复杂材质或软阴影采样 |
| D 水体反射 | 反射视图数量、额外几何绘制、折射／SSR 带宽 | 降低反射更新率／尺寸、回退环境反射 |
| E 后处理 | 采样半径、内部尺寸、附件数量与合成次数 | 限制半径、选择质量档、关闭非必要镜头效果 |
| F 性能重建 | 整帧 CPU/GPU、调度／排序开销、历史资源与画质损失 | 选择原路径或较简单方案，确认低负载不会无条件变慢 |
| G/H 专项研究 | 3D 存储、历史、更新体积、额外场景表示 | 限定区域与更新预算；无法达标则不进入默认路径 |

关闭前后的内存比较同时记录活动资源、候选峰值、待退役资源及仍被其他消费者使用的共享资源。不能以“没有执行 Pass”推断显存已经释放。

### 6.3 功能验证与正式性能分开

- 普通功能签收：按风险选择定向 JVM、必要真实 GL／消费者和一个组合场景，遵循[有侧重验收规范](../guides/focused-acceptance-policy.md)。
- 正式性能：只有承诺预算／加速时，选择相应测量入口，固定输入、预热和统计方法；比较整体路径及资源峰值。长测／扩展任务按现有规则启用。
- 画质比较：使用独立公式、可信实现、高样本参考或冻结的分析场景；不能直接将本次输出设为真值。
- 运行证据：保留候选身份、case、日志与资源／像素数据；超时、全跳过、空选择、缺失报告不能记 PASS。
- 历史复用、增量跳过与新执行分别说明；隐藏 GL 不能替代人工视觉、游戏手感或真实 Minecraft 接入。

| 输入／输出 | 格式、颜色空间、坐标、深度、采样数、分辨率和时域 |
| Pass 关系 | 读取哪个阶段的结果、写入什么、透明／AA／雾／UI 的先后 |
| 资源与失败 | owner／borrowed、线程、候选峰值、resize、发布、退役、关闭 |
| 参考与许可 | 独立算法依据、参考实现／资产许可和指纹；算法可读不等于资产可随意分发 |
| 正确性证明 | 最小算例、真实消费者、必要像素／历史事件及容差依据 |
| 成本／回退 | 代表设备与负载、预算或 NOT_EVALUATED、回退质量与诊断 |
| 验证范围 | 复用哪些合同、哪些新风险需要补例、何时扩大组合矩阵 |
| 创作交付 | 作者如何设置、保存、组合、暂停、重放和定位未生效原因 |

## 8. 后续维护与完成标准

1. 每次只冻结一个主目标和必要配套；大纲条目进入版本后链接到正式计划与验收，不提前写“已完成”。
2. 一个技术可服务多个模块，一个模块也可容纳多个技术；不要按榜单项复制 Controller、Demo 或 Gradle 任务。
3. 新功能应让通常的改动集中在所属模块及必要装配；若反复修改不相关模块内部状态，先调整输入合同，再继续扩展。
4. 组合验证优先覆盖深度、时域、HDR、透明、资源借用和多视图的真实交互，不枚举所有开关排列。
5. UI 改进随真实技术消费推进；空间区域混合、完整编辑器与宿主整合保留各自范围，不隐式混入技术版本。
6. 成熟度、性能、宿主验证、发布状态分别记录。研究原型只有进入正式生产路径并完成相应合同，才可升级为已集成／已验收。
