# 0.28.1 F6 / #2 验收卡：UV Flow / Distortion 的采样器与缩小过滤合同

日期：2026-11-12。分支 `codex/render-f6-sampler`，基线 `801f8850`（integration HEAD）。
本卡冻结既有生产实现的实际 sampler/minification 合同，并补独立参考与真实 GL 证据；本轮不改变生产过滤行为。
对应 46 项矩阵 #2（UV Flow / Distortion）的独立验收 F6 缺口：
“filtered/minified sampler evidence incomplete; atlas LOD0 policy is not the full filtered/minified evidence”。

## 1. 范围与结论

- 覆盖：VFX sprite 纹理从 `VfxTextureCache` 导入到 `VfxRenderer` 的 `vfx.frag` 采样这一整条链，包括
  颜色纹理的 sRGB 解码、mip 链、min/mag filter、wrap S/T、UV Flow/cell 内缩、Flipbook 的 LOD 选择。
- 已验证：线性放大双折中点、sRGB 解码、clamp-to-edge、完整 mip 链的线性光缩小平均、Flipbook cell 隔离，
  以及生产纹理对象上的实际 GL 参数；资源跟踪归零、无 GL 错误。
- 明确限制：Flipbook 固定 LOD0，缩小粒子不参与 mip 过滤（抗锯齿不保证）；非 Flipbook 但手工设置
  `uvRegion` 的子区域在高缩小率下仍可能被粗 mip 跨过 cell 边界。本卡以证据记录这些限制，不做生产修复。
- 不支持/不承诺：VFX 路径不使用 NEAREST 过滤、REPEAT wrap、anisotropic filtering、LOD bias 或显式
  min/mag 覆盖；`Texture2D` 的通用 setter 可以改这些参数，但一旦改动就不再满足本冻结合同。

## 2. 生产 sampler 状态（冻结值）

| 项 | RGBA 颜色 sprite | Mask sprite | White 占位 |
|---|---|---|---|
| 导入入口 | `Texture2D.fromEncoded(encoded, true, SRGB)` → `setWrap(CLAMP_TO_EDGE, CLAMP_TO_EDGE)` | `VfxTextureCache.decodeMask` → `Texture2D.fromR8` | `Texture2D.fromR8(1,1)` |
| internal format | `GL_SRGB8_ALPHA8` | `GL_R8`（线性） | `GL_R8` |
| 采样颜色空间 | sRGB 解码为线性后过滤 | 线性 | 线性 |
| mip levels | `1 + floor(log2(max(width, height)))`，immutable storage 全链 | 同左 | 1 |
| mip 生成 | `glGenerateTextureMipmap`；GL 4.6 在**线性光**中生成 sRGB mip | 线性空间 box filter | 无 |
| `TEXTURE_MIN_FILTER` | `GL_LINEAR_MIPMAP_LINEAR` | 同左 | 同左（仅 1 级） |
| `TEXTURE_MAG_FILTER` | `GL_LINEAR` | 同左 | 同左 |
| `TEXTURE_WRAP_S/T` | `GL_CLAMP_TO_EDGE`（cache 显式设置） | `GL_CLAMP_TO_EDGE`（`fromR8` 默认） | 同左 |
| `TEXTURE_BASE_LEVEL` | 0 | 0 | 0 |
| LOD bias / min LOD / max LOD | 默认 0 / 无额外限制 | 同左 | 同左 |
| anisotropic filtering | 未启用，`TEXTURE_MAX_ANISOTROPY == 1.0` | 同左 | 同左 |

补充：

- `VfxTextureCache` 的缓存键为 `(AssetRef, maskMode)`，最多 32 项；RGBA_COLOR 的 projected-decal 路径
  (`get(AssetRef)`) 复用同一导入合同。
- `vfx.vert` 只负责把局部 UV/世界位置传给 fragment；`vfx.frag` 在 unit 0 采样 `uTexture`。
- 最终颜色写入线性 HDR 目标；测试与 VFX 路径均关闭 framebuffer sRGB 编码，因此测试读回的是线性值
  （默认帧缓冲 RGBA8 读回时按 8 bit 量化）。
- `uNoise` 是 renderer 自有的 128×128 线性 R8 噪声纹理，`REPEAT` + base level；它不属于材质 sprite
  纹理合同，本卡只记录其存在，不把它和 `uTexture` 混为一谈。

## 3. UV Flow / Atlas / Flipbook 与过滤的交互

生产 shader 的固定顺序（与 [战斗 VFX 指南](../guides/render3d-combat-vfx.md#2-材质参数)一致）：

```
局部 UV
  → 速度 × 显式效果时间（uUvFlow.xy × uTime）
  → 线性噪声扭曲（textureLod(uNoise, ..., 0)）
  → 当前 cell 内的 half-texel 内缩/夹取
  → 当前/下一 cell 的 region 映射
  → Flipbook：两次 textureLod(..., 0.0) 混合；非 Flipbook：两次 texture(...) 混合
```

- **cell 内缩**：`texel = 1/textureSize(uTexture, 0)`，`cellSize = region.max - region.min`，
  `inset = clamp(0.5 * texel / cellSize, 0, 0.5)`，然后 `local = clamp(local, inset, 1 - inset)`。
  对整图 region，inset 为 half texel；对 12×4 双 cell 图集，U 方向 inset = 1/12（正好半个 texel 的
  cell-local 长度）。因此 LOD0 的双线性 footprint 不会越过 cell 边界。
- **clamp-to-edge 的边界**：wrap 只保护整张 texture 的外边界，不保护 atlas 内部 cell 边界。cell 边界靠
  上述 inset 保护，而不是靠 `GL_CLAMP_TO_EDGE`。
- **UV Flow 不 wrap**：流动量在 cell-local 空间先相加，再被 inset 夹取；流出 cell 的 UV 会停在边缘，
  不会平铺到相邻 cell，也不会回绕。这是设计行为。
- **Flipbook 固定 LOD0**：`uFlipbook != 0` 时当前/下一帧都用 `textureLod(..., 0.0)`。非 padded atlas
  的粗 mip 可能把相邻 cell 平均进来，LOD0 是当前明确的规避方式；代价是缩小粒子完全没有 mip 过滤，
  可能出现闪烁/锯齿，且不使用 anisotropic filtering。
- **非 Flipbook 的隐式 LOD**：`texture()` 按屏幕导数选择 mip；整图 sprite 的 UV 只覆盖自身图像，
  clamp 只发生在图像外边界，因此没有“相邻 cell”问题。手工 `uvRegion` 的子区域则没有额外保护：
  一旦缩小率选到粗 mip，粗 mip 可以在内部边界两侧平均。
- **sRGB 与 mip**：颜色纹理按 sRGB 解码后过滤；GL 4.6 的 sRGB mip 生成在线性光中完成，本卡用
  数值断言冻结该行为（见 §5）。

## 5. 参考数学、容差与判别力

1. **sRGB 解码**：`128/255 = 0.50196078` 按 sRGB 传输函数解码为 `0.21586050`。
   GL 断言容差 `±0.002`（RGBA32F probe 读回）。线性上传或编码空间采样会得到 ≈0.502。
2. **放大双折中点**：2×1 黑(0)/白(1)，`u = 0.5` 的 texel 坐标是 `0.5×2 − 0.5 = 0.5`，
   bilinear 权重 50/50，线性结果为 `0.5`。容差 `±0.01`。
   NEAREST 会返回 `1.0`；若在 sRGB 编码空间过滤，会得到 `decode(0.5) = 0.2159`。
3. **clamp-to-edge**：2×1 纹理 `u = 2.0` 被夹到右边界，返回白色 texel `1.0`；REPEAT 会 wrap 到
   `u = 0` 的黑色 texel `0.0`。容差 `±0.01`。
4. **缩小 / mipmap 平均**：8×8 纹理只有一行（8 个 texel）为白，其余 56 个为黑/0。
   `8×8 → 4×4 → 2×2 → 1×1` 的 2×2 box 链精确得到 `8/64 = 0.125`：
   - R8：各级 8 bit 量化后 level3 存 `32/255 = 0.1254902`，GL probe 期望 `32/255`，容差 `±0.01`。
   - sRGB：level3 存 `99/255`，解码为 `0.1247718`，容差 `±0.02`。
   - probe 用 `uStepPerPixel = 1.0 UV/pixel`，8×8 的导数为 8 texel/pixel，LOD = `log2(8) = 3`；
     中心 UV `(0.5, 0.5)` 的 base level 和 NEAREST 都是 `0`，因此缩小采样与未过滤采样相差
     ≥0.125，测试会区分 mip 链是否真的生效。
5. **Atlas cell 边界**：`u = 0.5 − 0.5/12 = 0.458333` 是 cell 0 的 inset 右边界。
   - LOD0：texel 坐标 `0.458333×12 − 0.5 = 5.0`，正好是 cell 0 的最后一个红 texel，green = 0。
   - LOD2（`uStepPerPixel = 4/12`，4 texel/pixel）：3×1 mip 的 texel 坐标 `0.458333×3 − 0.5 = 0.875`
     落在“红 texel”和“红绿各半 texel”之间，green ≈ `0.875 × 0.5 = 0.4375`。
   GL 用例断言 LOD0 green ≤ `1e-4`，LOD2 green > `0.2`。
   - 生产 Flipbook：放大（size 32，覆盖 32×32 目标）与缩小（size 0.6，约 3 px sprite）两种情况下
     全帧 green 最大值均为 0；说明 LOD0 + inset 生效，粗 mip 不会串 cell。
6. **生产 sprite 缩小**：8×8 颜色纹理（一行白）以约 3 px sprite 渲染时，中心像素落在 mip 平均区间
   `(20, 160)`（8 bit）；同一纹理放大到覆盖目标时中心为 0。该开区间同时排除“未过滤的黑色 base
   texel”和“边缘白 texel”。

## 6. 明确限制

1. **Flipbook 缩小无非 mip 过滤**：LOD0 是防止未 padding atlas 串 cell 的冻结策略；代价是缩小的
   Flipbook sprite 不参与 mip/aniso 过滤，可能出现闪烁或锯齿。若需要缩小抗锯齿，应使用 padded
   atlas（让相邻 cell 之间有透明 padding）并重新评估 LOD 策略；本卡不实施。
2. **手工 `uvRegion` 子区域可能跨边界**：非 Flipbook 的 `uvRegion` 材质走正常隐式 LOD；clamp-to-edge
   只保护整张纹理外边界，不保护子区域边界。缩小到足以选择粗 mip 时，粗 mip 可能平均进相邻内容。
   本卡的 12×4 图集在 3×1 mip 上就可复现该结构（green ≈0.4375）。缓解方式：使用 padded atlas、
   让子区域 sprite 保持放大、或改用 Flipbook 的 LOD0 路径。
3. **无 NEAREST / REPEAT / anisotropic / LOD bias 合同**：这些模式不被 VFX 路径使用；`Texture2D`
   的通用 setter 可以覆盖，但覆盖后不再满足本卡冻结合同，GL 参数断言会失败。
4. **sRGB mip 线性生成是驱动/规范行为**：本卡在当前 GL 4.6 / NVIDIA 576.88 上以数值冻结
   （level3 = 99/255 → 0.124772）；若未来后端改变 mip 生成空间，`VfxSamplerContractGlTest`
   的 sRGB mip 断言会先失败，而不是静默改变画面。
5. **未覆盖**：人工视觉、性能、连续相机运动/TAA 下的闪烁评估、非 4.6 上下文、其他厂商驱动。
   GL 断言只在本机 RTX 3050 / NVIDIA 576.88 / OpenGL 4.6 上执行。
