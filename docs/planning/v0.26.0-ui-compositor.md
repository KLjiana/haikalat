# 26.0 完善ui compositor

日期：2026-11-04。状态：实施中；当前提交为内部功能检查点，尚未完成整版验收。

本文标题沿用任务名称“26.0”，仓库版本规划按现有序列记为 `v0.26.0`。当前构建仍为 `0.25.0`；本阶段不修改版本、不创建发布标签。下文保留原始交付合同，实际落地范围见第 11 节；未在该节确认的入口仍属规划。

## 1. 目标与交付边界

把已有的 UI 图层描述、资源预算和空合成 pass 补成可复用的实际渲染能力，使调用方通过 `UiSystem` 与节点图层配置完成子树离屏绘制、整体透明度、内容模糊、背景模糊和静态内容缓存。

本版完成的生产链路应为：

```text
UiNode / 图层配置
  → 布局、动画、输入与不可变 UI snapshot
  → 图层校验、绘制范围与资源计划
  → 子树离屏绘制 / 有效缓存复用
  → 内容模糊或背景模糊
  → 按原有绘制顺序合成到父图层 / PresentationTarget
  → 成功后提交缓存有效性，失败释放候选并保留可恢复状态
```

版本重点是让已有接口产生正确画面，并降低实际接入成本。每项功能必须同时有最小可交互 Demo 和直接生产链路的自动断言。描述对象、拓扑测试或截图文件存在均不足以证明功能完成。

| 优先级 | 必交付范围 | 出口 |
| --- | --- | --- |
| P0 | 图层与 snapshot 一致性、子树离屏、嵌套与顺序、预乘 Alpha、整体透明度 | 单层和嵌套层真实像素正确，不重复绘制子树 |
| P0 | 内容模糊、显式背景来源、背景模糊、矩形裁剪与变换/输入一致 | 模糊来源可解释，文字保持清晰，点击位置正确 |
| P0 | resize、宿主目标替换、预算与失败降级、资源释放 | 无失效附件引用、无反馈采样、无资源泄漏 |
| P1 | 静态内容缓存、完整失效原因、运行时诊断 | 静态层实际跳过绘制；变化后画面及时更新 |
| P1 | 最小 Demo、VLS 公共能力迁移、接入指南与能力矩阵修正 | Demo 不再维护同类通用合成算法 |
| 延后 | 通用阴影/Glow、颜色滤镜、任意遮罩、任意混合模式、编辑器 | 明确未支持，不能接受参数后静默忽略 |

不扩展 Render3D 光照、体积雾、动画图、玩法或资产编辑器。不把手柄导航、拖拽和新业务控件作为本版前置；现有输入与控件只修复被合成链路影响的行为。0.25.1 的场景控制规划独立保留，本版不依赖其新功能。

## 3. 架构与 API 原则

- 继续沿用 `subsystems/runtime → core → backend`。合成策略留在 UI，RenderGraph 负责通用资源和 pass，不感知控件、节点或背景模糊业务。
- 保留 `UiSystem` 接入门面及默认 direct 路径。关闭 Compositor 时不分配图层 target、不增加空模糊 pass。
- 优先扩展已有 `UiCompositorPlan`、`UiCompositor` 和 renderer 内部实现；必要的新计划/缓存类型默认包内可见。不新建通用 RenderFeature、第二套 RenderGraph 或 UI 专用 GL 资源后端。
- 应用提供逻辑资源引用与图层设置，不需要持有 native texture/FBO ID，不得直接操纵内部缓存。
- 复用现有 typed command 和资源所有权协议。GPU 读回只用于验证或显式诊断；常态路径不引入 `glFinish` 或每帧读回。
- 新公共入口按仓库公共 API 清单与架构门禁登记；默认行为兼容普通 quad/image/glyph/SDF UI。

### 3.1 图层配置与 snapshot 的唯一性

节点上的 layer 标记决定实际子树范围，attachment 声明负责可分配拓扑与预算。两者不能成为互相独立的 live 配置源。

首版采用显式注册的有界图层集合：稳定 ID 唯一；父子关系必须与 snapshot 的实际嵌套一致。缺失、重复、交叉区间或不匹配的描述在提交前拒绝，并指出 layerId。一个成功帧只能使用同一配置 revision 的计划与 snapshot，不能读取正在修改的 `UiNode`。

普通矩形/颜色/内容更新不重建拓扑；新增或移除注册层、改变父子关系或效果链结构走显式 reconfigure。隐藏/显示已有层复用注册资源，不每帧建图。首版不能支持的动态变化必须明确拒绝，不能悄悄忽略。

### 3.2 固定拓扑与事务

现有 `attach()` 会 seal graph，不能向已封闭 graph 随意插入 pass。实施时先提供完整校验后的候选计划，再接入宿主的 graph 候选构建流程。

`UiAttachmentController.rebind()` 的“旧 graph 已关闭”要求不能作为事务保证：应准备候选 attachment/graph，全部资源可用后在帧边界切换，再退役旧 attachment。若调用方不能提供候选 graph，本版支持固定注册层及数值变化，并对结构变更返回明确错误；不得先销毁旧画面再声称可以回滚。

准备新配置失败时保留旧有效配置；执行中 GPU 写入失败时不能假定已写纹理未变，应失效受影响缓存并在下一帧重绘。所有成功标记仅在对应命令执行成功后提交。

## 4. 渲染语义

### 4.1 子树、顺序与整体透明度

1. 由不可变 display list 建立平衡的层级和绘制区间；跨图层边界不能合批。
2. 离屏子树从 direct 列表中移除，只在原来的绘制位置合成一次。父层采样子层结果，不能再次绘制子层 primitive。
3. 以已有 paint order 为基准；若 `zOrder` 参与排序，必须由同一上游顺序同时驱动绘制与 hit test。不得按全局 layerId 排序改变重叠控件的视觉/输入关系。
4. 首版保证普通预乘 Alpha 图层，嵌套至少支持父/子两级。最大层数和深度均有明确边界，超限在提交前诊断。
5. 原有节点 opacity 语义保持；图层 opacity 是独立组属性，先合成子树内部遮挡，再在父目标上乘一次。禁止在子节点和最终合成重复乘图层透明度。

线性预乘 Alpha 的 source-over 公式为 `Cout = Cs + Cd * (1 - As)`，`Aout = As + Ad * (1 - As)`。组 opacity `o` 同时乘预乘 RGB 与 Alpha。用两个重叠不透明色块组成的半透明组验证，不能仅用一张半透明图片证明组语义。

### 4.2 颜色、坐标与裁剪

- 首版离屏颜色统一采用明确的线性预乘 RGBA 工作空间，建议 `RGBA16F`；最终目标按实际 `RenderFormat` 编码一次。不得沿用未核对的默认 `RGBA8` 目标冒充 sRGB。
- UI 位于 tone mapping 后的显示阶段，不进入场景 Bloom。显示阶段背景输入只做必要的 sRGB 解码，不再次曝光或 tone map。
- 定义 logical UI 坐标 → framebuffer 像素 → layer-local 像素的转换；包含 HiDPI、Y 方向、离屏原点、采样中心与奇数宽高。
- 实际 layer target 应匹配裁剪后的边界和滤波 padding，不能给每个小面板隐式分配整屏纹理。padding、降采样后的向上取整和边界采样规则必须参与预算。
- P0 保证轴对齐矩形裁剪及图层移动/缩放。既有旋转 clip 的保守 AABB 限制应明示；不得宣称已支持精确任意旋转遮罩。圆角/路径/任意 Alpha mask 延后或作为独立追加范围。
- 视觉变换使用现有 snapshot 矩阵；输入继续消费同一帧几何及逆变换。模糊扩展区域不扩展可点击范围。隐藏、detach、pointer capture 和焦点不能因新增离屏层失效。

### 4.3 内容模糊与背景模糊

| 效果 | 输入 | 输出语义 |
| --- | --- | --- |
| 内容模糊 | 本层子树离屏颜色 | 子树内容一起模糊，包括其中的文字 |
| 背景模糊 | 显式指定的 UI 前背景颜色快照 | 模糊结果限定在面板区域，再绘制清晰的本层内容 |

首版背景固定为 **本帧 UI 开始之前、完成场景后处理的颜色源**，所有玻璃面板使用同一来源；不递归采样已经画好的其他 UI，不承诺“模糊任意下层窗口”。面板重叠时按正常 source-over 合成。

- `UiBackdropSource.available()` 不代表纹理一定可读。构建时验证逻辑资源存在、producer 在前、可采样、尺寸及编码明确。只在必要时复制/resolve；禁止读取当前正在写入的同一颜色附件。
- 背景源不可用时，只允许明确报告后退回无背景模糊的普通 UI；内容与输入必须保留。调用方要求严格效果时可选择失败，不伪装成功。
- 复用现有 Gaussian kernel 的数学定义，采用可分离两遍滤波。半径用逻辑像素表达，换算到 framebuffer 和降采样空间后保持视觉尺度；支持的倍率与范围写入 API 文档。
- radius=0 为明确旁路；核归一化、透明边缘、padding、边缘 clamp 与采样位置均由独立 CPU 参考或解析输入验证。
- 嵌套层的内容模糊在子层合成后作用于整个父内容；本版不承诺同一层同时开启内容模糊与背景模糊，收到该组合时明确拒绝。

### 4.4 已有但未实现的选项

M0 列出 `UiLayerDescription` 中每个 effect、mask、blend、cache 枚举的支持状态。P0/P1 之外的 Glow、颜色变换、任意遮罩等选项不得继续被诊断为“active 且生效”。

保留已有类型以减少 API 破坏；未支持的非默认选项应在构建前报错或产生明确 `UNSUPPORTED_EFFECT` 降级记录。升级指南说明这属于修正原先静默无效的行为。任何效果转为支持时必须同时补像素与实际消费者。

## 5. 缓存、资源与生命周期

### 5.1 缓存合同

首版缓存静态子树颜色及其内容模糊结果；背景模糊默认每帧更新，避免在没有可靠背景 revision 时冻结动态场景。不能用 UI 未变推断背景未变。

缓存 key 至少覆盖：稳定 layerId、图层实例/配置代次、子树 paint revision、子层 revision、布局/有效像素尺寸、clip、内容缩放、图片资源 generation、文字/字形依赖、效果参数及目标编码。调用方的 `dirtyRevision` 只能补充失效，不能成为唯一依据。

本层 opacity 和纯平移在尺寸/clip/像素映射允许复用时只触发合成，不重绘本层；子层 opacity/位置变化必须失效缓存它的父层。缩放先按重新栅格化处理，不提前承诺任意缩放缓存复用。

动画、文本输入、图片热重载和 UI VFX 会产生内容变化。无法证明静态的层默认每帧绘制；宁可不缓存，也不能用缓存隐藏更新。若缓存依赖 GPU glyph atlas，要验证 atlas 淘汰/重建后的重绘；无需无理由持有失效 native handle。

### 5.2 所有权与预算

- 图层 target 由现有 RenderGraph/generation 所有；UI 计划和缓存只持有带代次引用。不要让两个 owner 各自删除同一附件。
- 宿主借用的 FBO/color/depth 继续遵守 `BORROWED`：不释放、不修改 storage，成功和异常出口恢复必要 GL 状态。
- 预算覆盖实际 target 数、格式字节数、两遍模糊、padding、缓存保留及候选/旧代次同时存在的峰值；现有像素预算不能仅由请求 bounds 推断。
- 受限分配应优先关闭可选模糊/缓存，保留能够正确执行的组透明度。若无法保留组透明度，应整层 direct fallback 并报告视觉语义降级，不能把逐 primitive opacity 冒充正确组效果。
- 候选创建失败不发布半套图层；不可继续使用旧尺寸附件绘制到新目标。尺寸为零时跳过绘制，恢复后重新校验。
- 跨 pass 复用 vertex ring/glyph 资源必须保证 fence 在最后消费者之后；失败路径也要释放未完成提交，不提前复用 GPU 正在读取的内容。
- detach/rebind/重复 close、隐藏/显示、目标更换后旧引用失效；长期缓存首次交付执行一次定向长测，后续只在风险变化时复测。

## 7. 最小能力验证 Demo

拟新增一个 `UiCompositorDemo` 入口，提供下列独立 `--case`。每个 case 可直接启动，不依赖其他 case 或 VLS；实现阶段可拆为小 factory，不创建通用 Demo 框架。

| ID / case | 画面与操作 | 必须证明 |
| --- | --- | --- |
| D01 / `layers` | 两个重叠色块、文字、父子层；调整组 opacity、移动/缩放、切 direct/offscreen | 组透明度与解析结果一致；嵌套顺序正确；按钮点击与画面一致 |
| D02 / `content-blur` | 脉冲/条纹/透明色块及文字；调半径和倍率 | 核与参考一致；无暗边/越界；radius=0 回到基准 |
| D03 / `backdrop-blur` | 移动棋盘背景、两张玻璃面板和清晰文字；切换源可用性 | 使用 UI 前背景；背景变化及时；面板不采样自己；文字不被模糊 |
| D04 / `cache-lifecycle` | 静态面板、一个动态文本/图片、嵌套层；缓存开关、resize、热更新与失败注入 | 静态层跳过重绘但画面不丢；各失效原因真实发生；恢复和资源释放正确 |

可见入口拟为 `runUiCompositorDemo`；有限帧验证拟为 `runUiCompositorIntegration`，均登记到现有 UI Gradle 脚本。这些名字当前不可执行。

各 case 提供效果切换、重置、暂停、固定回放与截图；正常用户界面不暴露 native ID、绑定槽和屏障。开发诊断单独显示 layerId、缓存命中/失效原因、实际 draw/blur/composite 数、资源字节数与 fallback。

自动回放使用固定时间步和固定输入，默认以 640×360 的小场景验证像素，额外一个奇数尺寸及 HiDPI case。窗口演示默认约 960×540；验收画质范围只覆盖实际测试尺寸，不能推导成 4K 已验证。

## 8. 验收合同与执行策略

遵循[有侧重验收规范](../guides/focused-acceptance-policy.md)及[测试指南](../guides/testing.md)。普通签收默认总时限 300 秒，包含 Gradle 启动，零自动重试；超时列已完成与未完成项，不把缺项计为通过。

当前 `verify.ps1` 只有 `Focused/Jvm/Extended` 固定模式，`acceptance` 主要覆盖已有 Render3D 范围。**M0 必须补一个 UI 定向叶子任务及受总体时限控制的调用方式**，例如向脚本增加显式 UI 模式；不得假定现有默认入口已经覆盖新 Compositor，也不得把新任务串入全量 GL/性能矩阵。

常规验证只编译受影响源码，执行定向 JVM、实际 GL 和当前阶段必要 case。共享命令、资源、状态恢复或字体生命周期有变动时，增加直接消费者的短验证。长期缓存首次落地需要一次单独安排的定向长测；不在每轮修复重复，不自动执行完整 benchmark。

| 验收域 | 最小关键证据 | 不接受的替代证明 |
| --- | --- | --- |
| 区间与顺序 | 平衡/错配/重复拒绝，嵌套与 direct 交错的像素；同位置输入命中 | 仅 layer 数量或 pass 名称存在 |
| Alpha 与色彩 | 解析重叠色块、组 opacity=0/0.5/1、透明边缘、sRGB/linear 对照 | 仅截图看起来变淡 |
| 模糊 | 固定核的独立 CPU 对照、常量保持、脉冲响应、边界与旁路 | 只验证“图片发生变化” |
| 背景 | producer 顺序、动态源、缺失源、非零宿主 FBO、MSAA 来源显式 resolve | UI 文本没有模糊就宣称来源正确 |
| 缓存 | 输出不变且实际重绘计数下降；文字/图片/动画/父子变化后更新 | getter 显示 cacheHit=true |
| 输入 | `WindowInputCollector → UiSystem → hit test/focus → Button`，移动/缩放/滚动/隐藏后操作 | 直接调用按钮 handler |
| 生命周期 | resize 往返、失败注入后恢复、zero extent、target replacement、重复 close、资源回基线 | 单次启动成功 |
| 兼容 | Compositor disabled 的 direct 基准；UI+3D；embedded 成功/异常状态恢复 | 全部 JVM 通过代替 GL |

像素容差在 M0/M1 首次建立独立参考时确定并记录：比较阶段、单位、ROI、色彩编码、允许误差和依据。不得失败后通过更新金图或放宽阈值获得通过。滤波测试优先比较线性中间结果；最终呈现另测编码与目标接入。像素 readback 不进入常态产品路径。

既有 `UiCompositorFoundationTest`、`UiRendererGlTest`、`UiPipelineMatrixGlTest` 与 `EmbeddedPresentationGlTest` 按变更选择扩展，不机械复制实现断言。新测试须至少能捕获空执行体、子树双绘、重复 opacity、缓存不失效和源/目标反馈中的对应错误。

性能不设置未经测量的 FPS 承诺。必需结构证据为：关闭零图层资源、固定配置暖机后不反复分配 target、静态缓存实际跳过子树/滤波、预算与诊断匹配。可选短测记录设备、尺寸、层数、半径和 cache 模式，只报告观察；正式性能矩阵另行安排。

建议产物目录：`build/reports/ui-compositor-v0260/<run-id>/`。包含输入指纹（含未跟踪文件）、环境、选测清单、实际执行与 skip、参考/输出图、断言结果、资源与 fallback 记录。人工可见交互单独记是否实际执行；隐藏 GL 不等于人工视觉签收或 Minecraft 客户端验收。

## 9. 完成条件与风险

- [ ] 支持矩阵清楚，已支持效果无空执行体，未支持选项明确报错/降级。
- [ ] 正常与离屏路径共享绘制协议，子树只绘制一次，组 opacity 与颜色编码正确。
- [ ] 四个最小 case 可独立运行，并有生产链路像素/输入/资源证据。
- [ ] 背景只来自明确的 UI 前颜色源，文字保持清晰，无纹理反馈采样。
- [ ] 静态缓存实际减少工作，内容、资源与父子变化不会被旧缓存覆盖。
- [ ] 资源峰值预算、resize/reconfigure、执行失败、borrowed 目标和关闭均有可解释行为。
- [ ] VLS 使用公共能力，现有任务/行囊/键鼠操作未被视觉迁移破坏。
- [ ] 使用指南及能力矩阵分别标明完成、降级、未支持和未测；历史报告不改写。
- [ ] 本版功能结论与正式性能、人工体验、发布就绪状态分列，不继承或抹去 0.25 的性能欠账。

主要风险是现有 direct renderer 对“整张 snapshot 一次提交”的假设、封闭 graph 的配置变化、预乘 Alpha 的重复处理、背景颜色空间不明，以及父子缓存失效遗漏。先完成 M1 的最小闭环，再推进模糊和缓存；发现需要大范围改写 core 时先缩小到真实消费者必需的能力，不用新增抽象掩盖未闭环行为。
