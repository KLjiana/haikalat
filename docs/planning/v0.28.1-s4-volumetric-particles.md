## 技术卡

| 字段 | 内容 |
|---|---|
| 技术 ID／用户场景 | #38 Volumetric Particles。让有限局部烟团/尘团以**解析密度体**形式进入 HDR 场景颜色：在声明包围盒内做有界 ray march，按主光方向产生单次散射与透射率，深度遮挡后与已有体积雾颜色合成。默认关闭；不是完整烟雾模拟，也不是粒子 billboard 排序/OIT 的替代。 |
| 当前基础／差距 | 已有 `VolumetricFogSettings`/`FogMediumSettings`/`LocalFogVolume`/`VolumetricPassBuilder`（froxel 体积雾，含全局/局部介质、光照、历史、反应式）与 `GpuParticleSystem`（#27 GPU 粒子 active set）。差距：没有“局部体积粒子”这一独立生产 Pass；没有单像素有界步数/步长合同、没有对雾颜色的单次合成合同、没有覆盖率上限、没有可复算的解析单次散射参考。本包**复用既有雾 owner** 作为上游颜色来源，不改动它，也不复制粒子系统。 |
| 真实生产消费者 | `VolumetricParticlePass.record(CommandBuffer, Framebuffer, int, ExternalCamera)`：消费调用方（Integrator）提供的已解析单采样 HDR 颜色（应已包含体积雾合成）与同帧单采样不透明深度，输出到 Pass 自有 RGBA16F 颜色目标；`colorTarget()` 供下一个颜色消费者（后处理/色调映射前）读取。GL 验收 `VolumetricParticleGlTest` 用真实 `VolumetricPassBuilder` 的雾输出、真实深度 FBO、真实 draw 与 `glReadPixels` 证明合成/遮挡/边界。当前生产 `RenderPipeline` 尚未接线（本包不改 `RenderPipeline`），因此本包是 **bounded Pass + 真实 GL 消费者验收**，不是端到端场景接线。 |
| 输入 | 既有 `ExternalCamera`（view/projection 及逆矩阵；不要求 jitter 稳定，但必须与颜色/深度同帧）＋ 新的 `VolumetricParticleSettings`：enabled、density、absorption/scattering（每米、密度 1）、局部椭球中心/半轴、maximumSteps、stepSizeMetres、主光 direction/color、anisotropy、`FogBlend`、fogWeight、maximumScreenCoverage。另借用：RGBA16F 单采样颜色 Framebuffer（同尺寸）、单采样不透明深度纹理 id。不读回、不 map、不下载。 |
| 输出 | Pass 自有 RGBA16F 颜色目标：`OCCLUDING` 为 `S + (1 − coverage)·dst`，`ADDITIVE` 为 `S + dst`；`S` 是预乘单次散射，`coverage = 1 − T`。不写调用方颜色、不写深度、不写雾 froxel、不写粒子的 SSBO/计数器。 |
| IO 与空间 | 世界空间：椭球中心/半轴、主光方向（光传播方向，构造期归一化）、每米系数。深度重建：`inverseProjection` 把像素 NDC + device depth 变为视图空间，`inverseView` 变为世界空间；射线原点取**近平面点**（透视/正交一致），方向为 `normalize(far − near)`。透射率/散射在双精度参考中可复算；GPU 侧为 float 与中点求积。 |
| Pass 顺序 | 在体积雾颜色合成（`VolumetricOpaqueComposite`，以及若启用的透明雾颜色 Pass）**之后**、后处理/色调映射之前记录；调用方把雾合成后的 HDR 颜色作为 `colorSource`。Pass 先 blit 该颜色到自有目标（避免读写同一附件），再在目标上做加法/遮挡合成。与雾同时启用时**只合成一次**：本 Pass 不采样雾密度、不读取雾 UBO、不重新积分雾介质；雾只由 `VolumetricFogSettings` 的 owner 积分一次，粒子介质只由本 Pass 积分一次。 |
| GPU owner | `VolumetricParticlePass` 拥有 1 个 RGBA16F 目标、1 个 shader program（2 stage）、1 个 `ScreenQuad`；无 SSBO、无 3D 纹理、无历史、无 FBO 读回。颜色源与深度纹理均为调用方借用，Pass 不销毁、不 resize。 |
| 生命周期 | 构造：校验 enabled/设置；完整创建 shader → quad → target，任一失败逆序关闭已创建资源。`resize(w,h)`：先完整分配候选 target 再发布，失败保留旧 target（GL 用例 f 断言旧 id/尺寸不变）。`close()` 幂等；关闭后 `record/resize/colorTarget` 抛 `GlException`，`id()/colorTexture()/width()/height()` 归零。 |

| 质量档 | 不内置 Low/Medium/High 预设，成本旋钮是 `maximumSteps`（1–64）、`stepSizeMetres`、包围盒、`density/absorption/scattering`、`maximumScreenCoverage`。建议档位见下表；默认 `disabled()`，未做 GPU 性能/显存测量，`NOT_EVALUATED`。 |

## 介质与合成合同

1. **单介质所有权**：粒子介质是椭球解析体，只由 `VolumetricParticlePass` 积分一次；体积雾介质
   （全局/局部）只由 `VolumetricFogSettings` 的 owner 积分一次。本 Pass 不接受
   `VolumetricFogSettings`，shader 不声明任何雾密度/source sampler，也不 include 雾实现；
   因此不存在同一介质被两个 Pass 同时累积的路径。
2. **合成顺序**：调用方先得到雾合成后的 HDR 颜色，再记录本 Pass；Pass 把该颜色复制到自有目标，
   再以 `OCCLUDING`（`ONE, ONE_MINUS_SRC_ALPHA`，保留目标 alpha）或 `ADDITIVE`（`ONE, ONE`）
   叠加。雾在颜色输入中已恰好出现一次；粒子只出现一次。这是**顺序分层近似**，不是把两种介质
   放进同一条射线联合积分；雾的消光会作用在粒子上、粒子的消光会作用在雾颜色上，但两者的
   前后交错顺序未建模（见限制）。
3. **去重守卫**：`VolumetricParticleSettings.validateFogComposition(fog)` 拒绝“同一形体同时被
   声明为正消光 `LocalFogVolume`”的复制粘贴重复（中心/半轴在 `1e-4` 相对容差内且消光 > 0）。
   不同或仅重叠的介质不会被拒绝：它们是不同介质，各自由自己的 owner 积分一次；艺术取舍由调用方
   负责。GL 用例 c 用**全局均匀雾**证明粒子 Pass 不会把雾再积分一次。
4. **雾权重**：`fogWeight ∈ [0,1]` 乘在粒子光深上（`τ' = w·τ`），散射随透射率
   `S = L·phase·albedo·(1−exp(−τ'))`，因此 `w=0` 是粒子介质的精确 no-op，`w=1` 为全强度。
   权重只应用一次；GL 用例 d 断言 `w=0` 时中心像素与源像素逐字节一致。
5. **光深与散射**：`σ_e = density·(absorption + scattering)`，`albedo = scattering/(absorption+scattering)`，
   `σ_s = density·scattering`；单次散射对常量主光精确为 `L·phase·albedo·(1−T)`，能量有界
   `S ≤ L·phase`（albedo ≤ 1）。相位与体积雾共用归一化 Henyey–Greenstein 及 `max(0.01, …)`
   分母下限；`μ = dot(lightDirection, −rayDirection)` 与雾的“光传播方向/朝向相机”约定一致。
6. **步数与步长**：区间为射线与椭球的相交段再按不透明深度截断；`stepLength = max(span/maxSteps,
   stepSizeMetres)`，`steps = clamp(ceil(span/stepLength), 1, maxSteps)`，中点采样。因此
   `stepSizeMetres` 是质量旋钮，`maximumSteps` 是每像素硬上限；区间变长只会加粗步长，不会突破预算。
7. **深度遮挡**：只接受单采样不透明深度；`rawDepth ≥ 1` 视为无遮挡物（不截断局部体）；表面在
   局部体之前 → 区间为空 → 输出 0（OCCLUDING 下 `alpha=0`，背景逐字节不变）；表面穿过局部体 →
   只积分到表面。深度纹理必须与颜色/相机同帧同视口；Pass 不做 GPU 同步、不读回深度。
8. **覆盖率与离屏**：以局部体 AABB 的 8 个角投影得到屏幕矩形；Pass 只在该矩形内开 scissor，
   矩形外像素不运行 fragment。局部体完全在眼后/离屏时不记录 draw，但仍把源颜色 blit 到自有目标，
   保证 `colorTarget()` 始终是当前帧颜色；跨越眼平面时保守取全屏矩形。
   若矩形面积占比超过 `maximumScreenCoverage`，record 在写任何命令前抛
   `IllegalStateException`（fail-closed），不静默裁剪出半帧。
9. **单采样/解析**：颜色源必须是已解析的单采样 Framebuffer；MSAA 原始颜色/深度不支持，需由
   Integrator 在 resolve 之后接线。无历史、无 jitter、无反应式 mask；不与 TAA 共享历史。
10. **无读回**：生产 Pass 不调用 `glGetTexImage`/`glReadPixels`/`glMapBuffer`/fence；GL 用例中的
    读回仅为测试证据。

## GL 验收用例（待 Orchestrator 执行）

`VolumetricParticleGlTest`（6 case，64×64 隐藏窗口 + 透视相机）：

1. `boundedScatteringInsideTheBodyLeavesOutsidePixelsUnchanged`：均匀地板深度 12 m，局部椭球在
   `z∈[−1.5,1.5]`；对全部 4096 像素用独立参考计算求积/解析光深（求积误差 ≤ 2e-3），命中的像素
   与 `S + T·bg` 比对（4e-3），未命中的像素与 blit 后的源像素**逐字节**相等；断言命中 ≥ 200、
   拒绝 ≥ 1500。另用一个完全离屏的局部体验证“不记录 draw 但源颜色逐字节复制”，并用
   `maximumScreenCoverage=0.02` 的局部体断言 record 在写入命令前抛 `IllegalStateException`。
2. `foregroundDepthOccludesParticlesAndInsideDepthTruncatesThem`：真实栅格化 5 m 前景小 quad 写入
   深度；局部体在其后时中心像素逐字节不变，地板深度像素与参考一致；把局部体移到遮挡物前后
   交叉位置，中心像素与“截断到 5 m”的参考一致且可见，证明 A-B 前后遮挡。
3. `volumetricFogAndParticlesApplyEachMediumExactlyOnce`：真实 `VolumetricPassBuilder`（均匀
   0.2/m 雾，`history=false`）执行 medium/source/temporal/integrate；用 `volumeQuery` 查询逐像素
   `(S_fog,T_fog)`（查询 compute 与合成 fragment 都显式上传同一 12 m 深度）并按真实
   `composite.frag` 公式写入雾颜色。fixture 先自检 `T_fog ≈ exp(−0.2·12)`、`S_fog ≈ 0`、
   `fogColor ≈ T_fog·bg`，再断言粒子实际 = `S_p + T_p·fogColor`，且与“雾再合成一次”的模型
   相差 > 0.01；粒子权重与介质各应用一次。
4. `stepBudgetAndDensityChangesAreMonotoneAndBounded`：`1 vs 48` 步的中心像素分别匹配各自求积参考，
   48 步更接近解析参考且 1 步误差 > 3e-3；密度 0.5/1.5/4 的加色输出严格递增、逐档匹配参考且
   不超过光能量上界；`fogWeight=0` 的中心像素逐字节回到源像素。
5. `disabledSettingsCreateNoPassAndLeaveTheBaselineByteIdentical`：`disabled()` 构造
   `VolumetricParticlePass` 抛 `IllegalArgumentException` 且不新增任何追踪资源；基线像素重复读回
   逐字节一致；资源跟踪回到空。
6. `resizeAndCloseAreTransactionalAndReleaseTrackedResources`：64×64 → 48×32 事务发布并真实渲染；
   同尺寸 resize 为 no-op；非法 resize 保留旧 target id/尺寸；close 幂等、句柄归零、关闭后
   `record` 抛 `GlException`；全部追踪资源释放。

## 生产接线（Integrator，`codex/render-pipeline-wiring`）

生产入口（均默认 `VolumetricParticleSettings.disabled()`，禁用时不创建 pass、目标或 draw，
拓扑 key 与基线逐字节一致）：

| 名称 | 语义 |
|---|---|
| `RenderPipeline.volumetricParticles(settings)` | build 前配置；已有代次时抛 `IllegalStateException`。 |
| `RenderPipeline.volumetricParticles()` | 当前请求值；不暴露 GPU 句柄。 |
| `RenderPipeline.applyVolumetricParticles(settings)` | 帧边界事务：设置相等时直接返回；否则构建完整候选代（pass 在构造期烘焙 settings），成功后退役旧代；失败保留旧代与旧设置。 |
| `RenderFeatureSettings.volumetricParticles(...)` / `volumetricParticles()` | builder、`defaults()`、`toBuilder()` 与统一批量入口。 |
| `RenderFeature.VOLUMETRIC_PARTICLES` | `RenderFeaturesControl.activities()` 的有效/不可用原因（`ACTIVE`、`DISABLED`、`PAUSED_BY_MASTER`、`UNAVAILABLE`）。 |
| `PipelineTopology.volumetricParticles` | 只在“settings active + 体积雾 active + 单采样”时进入拓扑 key；否则请求保持 `UNAVAILABLE` 且不改变图。 |

图顺序与颜色/深度合同：

```text
GeometryPass -> VolumetricOpaqueComposite (fog HDR colour + opaque depth)
             -> VolumetricParticlePass     (copy fog colour, composite own medium)
             -> VolumetricTransparency     (transparent replay + HDR VFX share the particle colour)
             -> post-process HDR chain
```

- 粒子图节点由 `RenderPipeline.addVolumetricParticlePass(...)` 声明，消费
  `VolumetricPassBuilder.COMPOSITE_COLOR` 与共享单采样不透明深度（`scene.depth` 生产者）；
  `VolumetricPassBuilder.addColorPrePasses(...)` / `addTransparentPass(..., colorSourcePass)`
  把透明 replay 的颜色源改为 `VolumetricParticlePass.PASS_NAME`。
- 粒子 pass 拥有自有 RGBA16F 目标（`VolumetricParticlePass.COLOR_TEXTURE`，`volume.particleColor`），
  记录后由图节点 blit 回共享颜色链；这是接线适配的**一次额外全屏颜色拷贝**。
- 相机使用 `fogRasterCamera()`：TAA 帧下与雾合成所用 jittered 投影一致；MSAA 帧不进入该拓扑。
- `PipelineFeaturePolicy` 在装配期拒绝“粒子 active 但无体积雾 / 非单采样 / 无单采样深度”的
  外来拓扑；`RenderFeaturePolicy` 对批量请求做同样的软不可用判定，并调用
  `validateFogComposition` 拒绝重复 `LocalFogVolume` 介质。
- resize 在候选代装配期创建新的 pass owner；旧代退役失败保留新代并报告退役失败，不伪报回滚。

122 个 case，实际执行 80、0 失败、0 错误，42 个 GL case 按 `haikalat.glSmoke=true` 守卫 skip
（不计 PASS）。新增 `RenderPipelineWiringTest` 9 个 JVM case（禁用 no-op、顺序/依赖、特性原因、
装配期拒绝、设置事务与候选构建失败回滚）。新增真实 GL `VolumetricParticlePipelineGlTest` 2 个 case 为
**NOT_EVALUATED**（GPU 队列负责执行）：

剩余限制：只支持单采样；粒子必须与体积雾同帧启用；透明 replay 在粒子之后绘制，跨层交错仍为

## 明确限制与未验证项

1. **局部解析体，不是完整烟雾模拟**：只有单个椭球解析密度（`(1−r²)²` 衰减），没有局部密度
   网格、没有注入/消散/平流/浮力/温度、没有粒子 buffer 驱动的密度、没有时间演化。动画、寿命与
   多烟团交互属于 #43 或 #27/#15 的后续扩展，不在本包冒充。
2. **单次散射/常量主光**：只按一个方向光做 HG 单次散射，无阴影/自阴影/透射阴影、无多次散射、
   无环境光/IBL 耦合、无自发光、无逐点光源。相位在强前向（g→0.9）时依靠 `0.01` 分母下限保持有界，
   这是与体积雾一致的艺术近似，不是精确相函数。
3. **顺序分层合成**：雾与粒子是“雾先、粒子后”的两次顺序合成，不是联合积分；雾对粒子的消光与
   粒子对雾颜色的消光都被各应用一次，但介质前后交错顺序未建模。对厚雾+厚粒子重叠区域，误差
   可能可见；需要严格顺序时应将粒子介质并入体积雾 froxel 介质（本包未做，避免复制雾 owner）。
4. **单采样/不透明深度**：只接受已解析单采样颜色与深度；MSAA 原始颜色/深度、透明表面深度、
   粒子自身深度不支持。清空深度（≥1）当作无遮挡物。无屏幕外几何、无背面/薄壁特殊处理。
5. **覆盖率上限是硬失败**：投影 AABB 超过 `maximumScreenCoverage` 时 record 抛异常而不是裁剪或
   降级；调用方必须调大上限或缩小局部体。默认 1.0 表示只受目标面积约束。
6. **无时域/无 AA 集成**：没有历史、jitter、reactive mask 或 TAA 重投影；接入 TAA 时需要 Integrator
   评估是否要求 reactive/无效化，本包未声明该合同。与 #28 OIT、#26 排序、#37 随机透明、#11/#13
   折射、#12 DOF、#20 SSR、#34 降噪、#35 升采样、#40 云、#43 烟雾的组合均未验证。
7. **未接线/未测**：真实 `RenderPipeline` 端到端场景、透明队列顺序、多相机/离屏、暂停/重放、
   动态分辨率、GPU 性能/显存/帧时间、多硬件与 1920×1080 预算全部 `NOT_EVALUATED`；GL 6 case 由
   Orchestrator 串行执行，本 Worker 未运行。
