日期：2026-11-11；GL fixture 修复 2026-11-12。状态：首版实现；JVM 已执行；真实 GL
`ThinTranslucencyGlTest` 1/1 PASS，focused verification `dfb658b6`（HEAD `37ab4f9e`，
1259 tests / 0 skipped）。对应 46 项路线图 #8，执行计划见 [multi-agent full delivery](haikalat-multi-agent-full-delivery.md)。

## 范围与承诺

- 目标：双面薄叶／薄布在背光方向获得可控的透射颜色，进入现有 PBR 直接光结果。
- 支持：`PbrMaterialProperties` 的显式标量 `thicknessFactor`、`transmissionFactor`、`backlightFactor`，均为 `[0,1]`、默认 `0`；geometry 仍为普通 opaque/MASK 网格。
- 不支持：厚度贴图、屏幕空间折射、multiply 混合、glTF `KHR_materials_transmission` 自动导入；不宣称能量守恒的薄介质散射，也不自动把双面 glTF 材质识别为薄叶。

## 输入/输出与公式

| 项目 | 内容 |
|---|---|
| 输入 | 三个归一化浮点材质值（线性、无时间语义）；场景 properties 键为 `material.<name>.pbr.thicknessFactor/transmissionFactor/backlightFactor` |
| 输出 | 现有 HDR 表面颜色增加背光项；不改变 alpha、shadow map、surface 通道或 Pass 拓扑 |
| 法线 | 沿用现有 `uDoubleSided` + `gl_FrontFacing` 翻转后的 shading normal（含 normal map），与 PBR 反射项使用同一 `Nf` |
| 公式 | `B=max(dot(-Nf,L),0)`，`F=max(dot(V,-L),0)`，`lobe=F^(1+7*thickness)`，`absorb=exp(-2*thickness)`；`Ctrans=baseColor*radiance*transmission*backlight*B*lobe*absorb` |
| 灯循环 | 方向光与 clustered 本地光复用同一 radiance、距离/锥角衰减和 shadow visibility；不新增灯扫描或第二套阴影采样 |
| 零值 | 两个控制任一为 `0` 时函数立即返回 `vec3(0)`，反射路径与加法顺序不变，默认输出与改动前逐像素一致 |
| 能量 | 艺术近似：`transmission*backlight ≤ 1`；未从反射项扣除透射能量，技术卡明确公开该限制 |

## 集成、生命周期与阴影

- 归属 `core.assets` 的不可变材质定义与 `subsystems.render3d.pbr` 的装配/着色；没有新增 manager、Pass、纹理或 GPU owner。
- `PbrMaterials` 两条创建路径都写入 `uThicknessFactor`／`uTransmissionFactor`／`uBacklightFactor`；旧七参数构造器保留并补 `0`，现有调用点不改语义。
- 阴影 path 仍是 depth-only 且显式关闭 cull；MASK 的 alpha cutoff、双面 raster 与主 pass 保持同一值。背光项只消费既有 visibility，不改变 shadow-caster 约定。
- 已知限制：若薄叶自身作为 shadow caster 且使用已启用阴影的方向光，正面 bias 可能把自身计入遮挡，背光项被 self-shadow；首版不新增 transmission shadow pass，作者可用非投影薄叶或非阴影灯验证效果。

## 正确性 oracle 与验证

- JVM：旧构造器/`defaults()` 三值为零；显式值可读写；场景 properties 解析往返；NaN、负数、`>1` 在构造与解析层拒绝。

- shader 字节已变化，`docs/licenses/assets.tsv` 的 `pbr-forward.frag` SHA-256 已同步。

## 成本与回退

- 每个直接光增加三个标量 uniform 与一次分支；控制为零时提前返回，不执行 pow/exp，不改变原有分支预算。
- 关闭：材质三值归零（或旧构造器）即回到原 PBR；无资源需要回收。
- 正式性能未测量，状态 `NOT_EVALUATED`；不把可运行写成达到帧率预算。

## 第二次验收：边界行为证据（2026-11-13）

日期：2026-11-13。代码提交 `ccfa06c0`（基于集成 HEAD `4b1f3e62`）。首次验收只有
背光/正面光/零值 1 个 case；MASK alpha-cutout、back-face 相机、`thickness > 0` 的
吸收/波瓣方向、cascade shadow 的可见性一致性都没有行为覆盖。生产 shader 未修改。

### 新增 case 与断言

1. `maskCutoutBackFaceAndSideLightKeepThinTransmissionBounded`
   - 2×1 base-colour 纹理：左 texel alpha 0.2（< cutoff 0.5），右 texel alpha 1.0。
     `alphaCutoff=0.5` 的 MASK 材质下，左探针被 discard 到背景（与矩形外背景
     能量差 ≤2），右探针保留背光透射（>30）；同一纹理 `alphaCutoff=0` 时左探针
     被着色且显著高于 MASK 值（差 >30），证明 cutoff 真正生效而非 fixture 变空。
   - back-face 相机：相机在 -Z、yaw 90° 看双面 quad 的背面，背光方向
     `(0,0,-1)`；薄材质中心能量比零值高 **>30**。
   - front-lit 负对照：同一双面材质正面受光时，薄与零值中心能量差 **≤2**，
     证明正面 PBR 路径未变。
   - side-lit 拒绝边界：光方向 `(1,0,0)` 时 `back = dot(-N,L) = 0`，薄材质与零值
     中心能量都为 0（差 ≤2），对应 shader 的 `back <= 0` 提前返回。
2. `thicknessChangesAbsorptionAndLobeInTheAssertedDirection`
   - 背光、正对相机：`thickness=1` 的中心线性 HDR 亮度 / `thickness=0` 的比值
     **< 0.5**（`absorb=exp(-2)=0.1353`，正对时 `lobe=1`）。
   - 斜视相机（front ≈ `(-0.496,0,-0.868)`）：同一比值**再小于正对值的 0.9 倍**，
     对应 `lobe = forward^mix(1,8,thickness)` 的收紧。
3. `cascadeShadowAttenuatesTheThinReceiverExactlyOnce`
   - 两个镜像的 shadow 配置测量同一可见性 profile：front light（travel -Z）+
     caster 在 +Z 时用零值材质测 direct 可见性；back light（travel +Z）+ caster
     在 -Z 时用薄材质测 thin 可见性。caster 均为 1.6×1.6、接收面 3×3、
     `ShadowSettings(32, 4.0, 0.1, 20.0, 0.01)`，在 penumbra 内找
     `0.15 < visibility < 0.9` 的像素。
   - 薄材质的 shadowed/lit 比值与 direct 测得的 visibility 差 **≤0.1**：既不是 1
     （阴影消失），也不是 visibility²（双重变暗）；阴影确实使薄接收面变暗。
   - 该 case 也验证了文档中的限制：只有既有 visibility 被消费，没有新增
     transmission shadow pass；接收面仍显式 `castShadows=false`。

### 仍明确不支持的边界

## 第三次验收：薄背光的传播阴影容差（2026-11-16）

日期：2026-11-16。分支 `codex/render-thin-transmission`，基于集成提交 `ec27fb0c`。
本节关闭首版记录的「薄叶自身作为 shadow caster 时背光项被 self-shadow」限制；它是
**一次有界的逐片元深度容差**，不是通用 transmission shadow 功能，也不新增 pass、
framebuffer 或纹理。

### 改了什么

- `pbr-forward.frag` 与测试参考 `full-scan-reference.frag` 同步新增：
  - `const float THIN_MAX_THICKNESS_METRES = 0.05;`：5 cm 世界空间板厚上限；
  - `thinTransmissionWorldThickness()`：先拒绝 NaN/Inf，再返回
    `clamp(uThicknessFactor, 0.0, 1.0) * THIN_MAX_THICKNESS_METRES`；
  - `directionalCascadeDepthTolerance(cascade, l, worldThickness)`：用
    `directionalCascadeMatrix(cascade)` 投影 `vWorldPosition` 与
    `vWorldPosition + l * worldThickness`，取 NDC 深度差
    `abs(a.z/a.w - b.z/b.w) * 0.25`，clamp 到 `[0, 0.02]` 归一化 window 深度并拒绝
    非有限结果；`receiver.z/receiver.w` 是 [-1,1] NDC，比较使用 [0,1] window 深度，
    因此 0.5 做 NDC→window 映射、另一个 0.5 才取半板厚，有效放行深度为板厚的一半；
  - `directionalShadowFactorTransmissive(n, l)`：仅在 `uHasDirectionalShadow != 0`、
    `uDirectionalCascadeCount > 0` 且板厚 > 0 时，把世界板厚写入 invocation 全局
    `gThinTransmissionShadowLookup`，让**每一个被采样的 cascade**用自己的矩阵换算
    tolerance 后交给**同一组 PCF/PCSS taps**；循环上界不变，tile guard 不变，退出时
    恢复旧值；
  - `directionalRadiance` 将 `thin` 从 `base` 中拆出：`thin` 恰为零、非阴影灯或
    板厚为零时仍返回原 `visibility * base`（逐位一致的旧表达式）；只有阴影灯且板厚
    > 0 时返回 `visibility * (base - thin) + thinVisibility * thin`，其中
    `thinVisibility = (1 - directionalShadowFactorTransmissive(n, l)) *
    (1 - directionalContactShadow(-n, l)) * cloudShadowVisibility(-n, l)`。
- 透射光从薄板**朝光一侧**穿过到达相机，因此薄背光份额用 `-n` 重新求值同一套云影与
  材质接触影；相机侧 `n` 在背光面上点积为负，这两个函数按设计返回中性值（0 和 1），
  直接沿用会让薄份额完全绕过云影/接触影。精确 `visibility` 的运算顺序、接触影采样
  位置和云影乘法保持不变，直接漫反射/高光、SSS 与不透明表面仍只消费精确
  `visibility`；局部光（点/聚光）路径未改，也没有透射阴影容差。

### 容差公式与近似边界

- 容差 = `clamp(0.25 * |z_ndc(vWorldPosition + l * thickness) - z_ndc(vWorldPosition)|,
  0, 0.02)`，其中 `thickness = clamp(uThicknessFactor, 0, 1) * 0.05 m`。方向光正交投影下
  window 深度对世界距离仿射；`receiver.z/receiver.w` 是 NDC，比较使用 window 深度，
  所以 0.5 先把 NDC 映射到 [0,1]，再乘 0.5 取半板厚。有效放行深度因此是
  `thickness * 0.5`：5 cm 材料上限对应 **约 2.5 cm** 的实际 pass-through，3–4 cm 的
  独立 caster 必须完全遮挡。每个被采样的 cascade 用自己的正交半径/深度比例换算，
  blend band 的两个 cascade 不会复用同一个归一化容差。
- 近似是 **caster-agnostic** 的：任何落在半板厚内的 caster 都会被同样放宽，因为逐片元
  无法区分「自身背面」与「同样薄的其它遮挡物」。它**只**作用于薄背光项的那一次可见性
  查找，且同时受 5 cm 世界板厚（半板厚 2.5 cm）与 0.02 归一化深度两个上界约束；直接光、
  不透明接收面仍使用精确查找，薄背光份额另乘朝光侧的材质接触影与云影。
- 三控制全零、板厚为零或灯不是当前阴影方向光时走原来的 `visibility * base`，不新增
  阴影采样；GL 中板厚为零的帧实测仍为 0.0（pre-fix self-shadow 行为）。

## 第四次验收：复核 P1 修复（2026-11-16）

日期：2026-11-16。分支 `codex/render-thin-shadow-fix`，基于集成提交 `9b8b160d`。
独立复核发现的两项 P1 均在本节修复；生产 shader 与测试参考同步更新。

### 修复 1：薄背光份额消费云影与材质接触影

- `pbr-forward.frag` 的 `directionalRadiance` 中，精确 `visibility` 的算术、接触影采样位置
  （`directionalContactShadow(n, l) * visibility`）和云影乘法顺序保持不变；零薄值/零板厚/
  非阴影灯仍走 `visibility * base`。
- 复核建议的「在精确块里捕获 `contactRaw`/`cloud` 再乘到 `thinVisibility`」经实测是
  **无效的**：背光面上 `dot(n, l) < 0`，`directionalContactShadow` 与
  `cloudShadowVisibility` 都按设计提前返回中性值（0 和 1），捕获值恒为中性。真实 GL
  反例：预修复 shader 在云覆盖世界位置 cloud-on 仍为 **0.328613**（与 cloud-off 相同）；
  接触影 on/off 也同为 **0.328613**。
- 实际修复：仅在非零薄份额分支内，用朝光侧法线 `-n` 重新求值同一套材质接触影与云影：
  `thinVisibility = (1 - transmissive(n,l)) * (1 - directionalContactShadow(-n,l))
  * cloudShadowVisibility(-n,l)`。精确 `visibility` 路径不变；直接/SSS/不透明表面仍只
  消费精确 visibility。
- 真实 GL：云生产参数（coverage 0.55 / softness 0.35 / scale 0.12 / strength 0.65 /
  speed 0）在世界坐标 (-4.5, 2, 0) 处，cloud-off **0.328613** → cloud-on **0.173218**
  （比值约 0.527）；同一 shader 在无云世界位置（原点）cloud-on/off 差 < 1e-4，证明是
  世界云场而非全局开关。MSAA 下仅材质接触影生效（`PipelineTopology` 断言屏幕空间 pass
  不活动），2.2 cm 隐藏 caster（在半板厚容差内、透射查找放行）：
  contact-off **0.328613** → contact-on **0.087097**；无 caster 时 contact-on 仍为
  **0.328613**（无自遮挡）。

### 修复 2：每个 cascade 使用自己的容差

- 用 invocation 全局 `gThinTransmissionShadowLookup` 保存「朝光世界板厚」；wrapper
  保存旧值、置为板厚、调用同一 `directionalShadowFactor`，退出时恢复旧值（不是硬清零）。
- `sampleDirectionalCascade` 与 `sampleDirectionalCascadePcss` 在采样时用**自己的
  `cascade` 参数**调用 `directionalCascadeDepthTolerance(cascade, l, worldThickness)`；
  blend band 的两个 cascade 各自换算。精确直接光查找在 flag 为 0 时仍加 0，循环上界、
  tap 数和 tile guard 不变。
- 真实 GL 反例：4-cascade、lambda=0、blend 0.25、shadowDistance=10，相机 2.25 m
  （cascade 0 的 blend band 内，权重约 0.5），4 cm caster 在预修复 shader 下漏光
  **0.161987**（约半个 0.328613 基线）；修复后 **0.0**。1.5 cm caster（半板厚内）
  仍为 **0.328613**，10 cm caster 为 **0.0**。
- 为什么不用 2 cascade：当前 2-cascade atlas 把 tile 写成 256×256（`tileSize =
  atlasSize / max(columns, rows)`），而 forward shader 按 `rows=1` 读取半宽全高区域，
  2-cascade fixture 采不到自己的 shadow map；这是既有的 atlas 布局问题，不在本次 P1
  范围，故用 4 cascade（2×2、512 高 tile）覆盖同一 blend-band 合同。

### 修复 3：有效板厚边界（0.5 的语义）

- 第三次验收把 `abs(a.z/a.w - b.z/b.w) * 0.5` 当成「半板厚」，但 `a.z/a.w` 是 NDC，而
  比较使用 [0,1] window 深度：0.5 先做 NDC→window 映射，实际放行的是**完整板厚**
  （5 cm）。本次改为 `* 0.25`（NDC→window 0.5 × 半板厚 0.5），有效 pass-through 为
  `thickness * 0.5`，即 5 cm 材料上限对应 **约 2.5 cm**。注释、技术卡和 manifest 描述
  同步改正。
- 真实 GL：thicknessFactor=1 时，2.5 cm caster 仍透射 **0.328613**；3 cm、3.2 cm、
  4 cm caster 均为 **0.0**；0.5 m caster 仍为 **0.0**。2 cm 双层板自阴影 fixture 的
  0.328613 基线不变。

### 仍明确不支持的边界

- 材质接触影对薄份额的求值仍基于 shadow map，不是屏幕空间接触影；当 ContactShadowSettings
  的 start offset 落在板内时，薄板自身的朝光面可能作为接触遮挡物再次压暗薄份额。生产默认
  （屏幕空间 pass 活动）不使用该材质项；本次 fixture 使用 0.1 m distance / 0.05 m
  thickness，未出现无 caster 自遮挡。
- PCSS 路径已按 per-cascade 修复，但真实 GL 反例覆盖的是 hard PCF；PCSS/multi-cascade
  的数值覆盖仍沿用既有 PcssGlTest。
- 无 transmission shadow map、无 caster 颜色/材质区分；点/聚光仍无透射容差；不透明
  接收面仍被完全遮挡。
- 2-cascade atlas 布局不匹配（见上）仍是既有独立缺陷，本次未修。
