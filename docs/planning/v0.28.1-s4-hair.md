## 生成与几何

`HairStrandGenerator` 使用 SplitMix64 finalizer：

```text
hash(seed, strand, point) = mix(seed + 0x9E3779B97F4A7C15*(strand+1)
                                     + 0xD1B54A32D192ED03*(point+1))
unit(bits) = (bits >>> 11) * 2^-53
```

对每根 `s`：

```text
phase   = 2π * unit(hash(seed, s, 0x101))
radius  = rootSpread * sqrt((s + 0.5) / strandCount)
root    = right*cos(phase)*radius + up*sin(phase)*radius
point_i = root + flow*length*t
        + (right*cos(1.7*phase) + up*sin(1.7*phase)) * curl*length*0.25*sin(π t)
        + jitter(hash(seed, s, 0x1000 + 3i + k)) * curl*length*0.04*sin(π t)
```

`right/up` 是 `flow` 的确定性正交基（`|flow.y| < 0.9` 时 hint=`+Y`，否则 hint=`+X`）。
同一 seed 逐位可复现；无外部资产、无贴图、无随机运行时状态，许可为 project license。

每根 strand 的 ribbon 顶点布局（stride 36 B，5 个 attribute）：

| location | 分量 | 语义 |
|---|---|---|
| 0 | 3 | 中心线位置（局部） |
| 1 | 3 | 归一化切向 |
| 2 | 1 | 沿发丝参数 `[0,1]` |
| 3 | 1 | ribbon 边符号 `-1/+1` |
| 4 | 1 | 每根随机值 `[0,1)` |

每个 segment 生成两个三角形（6 个非索引顶点）；每根 strand 的 `segments*6` 顶点在缓冲中连续，
因此排序 alpha 可按 strand 使用 `drawArrays(first,count)` 而不重传。顶点着色器把中心点和法向偏移
探测点投影到屏幕，得到每世界单位的像素数，再以
`aCorner * widthPixels / viewport` 的 NDC 偏移展开；因此宽度是**像素**语义，且受
`uMinimumWidthPixels/uMaximumWidthPixels` 双重 clamp。该展开沿生成切向的屏幕法向进行，
不是相机朝向的根卡片。

## LOD

`selectLod(distance, projectedRadiusPixels)`：

```text
distance <= near && pixels >= lodMinimumPixels                  -> HIGH
distance <= far  && pixels >= 0.5 * lodMinimumPixels            -> MEDIUM
otherwise                                                       -> LOW
```

阈值含等号；近但投影半径过小的发束不会使用 HIGH。级别预算：

| LOD | strands | segments |
|---|---|---|
| HIGH | `strandCount` | `segmentsPerStrand` |
| MEDIUM | `max(1, (strandCount+1)/2)` | `max(2, segments-2)` |
| LOW | `max(1, (strandCount+3)/4)` | `max(1, segments/2)` |

`widthScaleFor(distance)` 在 `[near, far]` 内从 `1` 线性降到 `lodWidthScale`，窗口外保持端点值；
shader 再 clamp 到像素上下界。

## 着色（Kajiya-Kay）

方向光 `l = normalize(-travelDirection)`，视角 `v`，半向量 `h = normalize(l+v)`，切向 `t`：

```text
diffuse  = baseColor * (ambient + radiance * diffuseStrength * sqrt(1 - (t·l)^2))
primary  = pow(sqrt(1 - (t·h)^2), primaryExponent)
secondary= pow(sqrt(1 - (t·h)^2), secondaryExponent) * secondaryWeight
specular = radiance * (primary + secondary) * specularStrength
baseColor= mix(rootColor, tipColor, t_parameter) * (1 + (random*2-1)*colorVariation)
```

`t ⟂ h` 是正控制（高光最大），`t ∥ h` 是负控制（高光为零）。`radiance = lightColor * intensity *
shadowFactor`，其中 shadowFactor 是既有方向光 depth map 的 3×3 PCF：

```text
projected = lightSpacePosition.xyz / w * 0.5 + 0.5
if outside [0,1]^3 -> 1.0 (fully lit)
lit taps = projected.z - bias <= storedDepth
```

`bias` 由调用方传入，`texelSize = 1/shadowResolution` 显式传入（默认重载为 2048 方向图）。
无 shadow texture 时 `uHasDirectionalShadow=0`，完全受光。仅方向光；点/聚光 shadow 首版不接收。

### Shadow caster 的世界宽度

forward ribbon 的像素宽度在 shadow 深度图中没有意义，因此 `recordShadow` 用独立的
`strandRadiusMetres` 世界半径，沿 `side = normalize(cross(tangent, normalize(lightTravelDirection)))`
把中心线偏移 `±radius` 后再乘 `uLightSpace * uModel`。这保证 caster 不是零面积三角形；半径过小时
（细于 shadow texel）可能欠采样，需按 shadow 分辨率/场景尺度调大。shadow caster 仍使用 HIGH LOD，
每 dirty directional tile 一次 draw。

## 透明

| 模式 | 深度写 | 混合 | 排序 |
|---|---|---|---|
| `CUTOUT` | 是 | 关闭；`alpha < alphaCutoff` discard | 不需要，写深度 |
| `SORTED_ALPHA` | 否 | `SRC_ALPHA / ONE_MINUS_SRC_ALPHA` | 每根按 view-space z 升序（远的先画），同深度按 strand index 稳定 |

`alpha = settings.alpha * mix(0.55, 1.0, smoothstep(0, 0.3, parameter))`；forward 与 shadow fragment
共享同一 profile。`SORTED_ALPHA` 与既有透明队列的排序语义一致，但不是 OIT：不与 OIT 双重合成同一
发束，调用方需把 hair 放在同一 HDR 透明阶段、OIT resolve 之后或明确选择其一。

## Pass 顺序与接线

目标顺序（调用方负责）：

```text
Opaque/MASKED -> sorted transparent queue -> HairStrandPass.record (CUTOUT or SORTED_ALPHA)
  -> HdrResolve -> Fog/VFX -> TAA -> postprocess -> present
```

shadow caster 应插在既有 `ShadowCasterRecorder` 的 dirty-tile 循环内：

```text
... recordAllCasters(...) -> hair.recordShadow(cmd, model, lightSpace, settings, lightTravelDirection)
```

`recordShadow` 使用同一 `uLightSpace * uModel`、写当前绑定的 shadow FBO/tile，不创建第二套 shadow map。

  像素变化读 `captureLinearHdrRgbaFloat()`（receiver inset 内变暗像素计数、+X 质心位移）。

### 事件序列（实测）

| 帧 | 动作 | tilesRendered | tilesReused | receiver 阴影像素 | 像素结论 |
|---|---|---:|---:|---:|---|
| baseline | hair disabled | 1 | 0 | 0 | receiver 全亮 |
| 1 | 启用 hair（固定模型） | 1 | 0 | 3236 | 首次 miss |
| 2 | 不动 | 0 | 1 | 3236 | 与帧 1 逐位相等 |
| 3 | 只移动 hair +1.2m（X） | 1 | 0 | 3242 | 阴影像素区改变；质心 +X 移约 32px |
| 4 | 不动 | 0 | 1 | 3242 | 与帧 3 逐位相等 |
| baseline | 禁用 hair | 1 | 0 | 0 | 与 pre-hair baseline 逐位相等 |

声明断言：帧 3 必须 `tilesRendered == 1` 且 `tilesReused == 0`，receiver 阴影区 changed pixels
与 +X 质心位移均超阈值；帧 2/4 必须 `tilesRendered == 0`、`tilesReused == 1` 且像素逐位不变；
最后 `GlDebug.assertNoError`、fixture 关闭后 `GlDebug.resources().liveResources()` 为空。

### 回归暴露的第二处缓存洞（同根因，已修）

`applyHairStrands` 在 shadow shape 不变时会继承（borrow）上一代的 `ShadowCacheState`。
因此从 disabled 启用 caster 时第一帧仍是 hit：tile 里没有发束，影子不出现；反过来禁用后旧影子会
一直保留。hair 是 cache key 之外的动态 caster，这与 F5 同根因。修复：`applyHairStrandsInternal`
在 `activateGeneration` 之后，若 previous/replacement 任一侧 `active && castsShadow`，对继承的
cache 调用 `invalidateAll()`；启用、禁用和重建发束几何都会强制下一帧重绘。

回归判别力验证：临时把 `hairStrandModel` 的 `invalidateAll()` 关掉后重跑该 case，在帧 3 的
`tilesRendered == 1` 断言处失败（`expected 1 but was 0`），确认该真实 GL 事件序列确实能抓住
F5 原缺陷，而不是只依赖 JVM 状态。

## Hair + TAA 历史失效（2026-11-16，`codex/render-boundary-2`）

接线 review 的遗留项「hair+TAA 的 TAA 历史失效」在本轮关闭。发束是共享 surface 之外的
动态前向覆盖：不写 velocity，`SORTED_ALPHA` 也不写深度，所以 TAA resolve 会把上一帧的
发束图像当作有效历史；移动 lock、改变参与状态或重新烘焙几何后，旧发束会以 ghosting 残留。

### 失效点与原因

`TaaInvalidationReason` 末尾追加两个常量（既有常量与序号不变）：

| 常量 | 触发点 | 边界 |
|---|---|---|
| `HAIR_STRANDS_SETTINGS` | `RenderPipeline.applyHairStrandsInternal(...)` 成功激活候选代之后；`RenderPipeline.applyPendingFeatureRequest()` 中 `hairStrands` 请求发生变化并在帧边界接受之后（含 candidate 已激活、退役失败的恢复分支） | 仅当 previous/replacement 至少一侧 `active()`；启用、禁用、重新烘焙几何都失效；构建失败的候选保留旧历史 |
| `HAIR_STRAND_MODEL` | `RenderPipeline.hairStrandModel(...)` | 仅当矩阵真实变化且当前 hair `active()`；相同矩阵是 no-op，不再每帧清空 shadow cache 或历史 |

`PostProcessPipeline.invalidateTemporalHistory(reason)` 仍会一并清 SSGI/时域降噪/时域放大
历史（既有语义）。本轮没有为 hair 新增 velocity/历史通道，也没有改变相机、世界或拓扑既有的
失效路径。

## 发丝 velocity 通道 v1（2026-11-17）

本轮只补共享 surface 的 velocity 通道，范围是 velocity 的生产 + 接线 + 测试；不新增 validity /
previous-surface-depth / reactive，不改 RenderGraph core，不删除既有 TAA 失效策略。

### 设计

- `HairStrandPass` 新增 internal `VELOCITY_PASS_NAME = "HairStrandVelocityPass"`、
  `recordVelocity(CommandBuffer, ExternalCamera current, ExternalCamera previous, Matrix4fc model,
  Matrix4fc previousModel, boolean previousValid, HairStrandSettings requested)` 与第三个
  program（`hair-velocity.vert/.frag`）。pass 仍不拥有任何目标：调用方绑定 framebuffer，pass 只
  绑定 program/mesh 并按一次 draw 画出全部 strand（velocity 不需要逐 strand 排序）。
- 顶点阶段复制 `hair-forward.vert` 的 ribbon 展开（同一 camera-facing side probe、像素宽度
  clamp 与 `aCorner * widthPixels / viewport` 偏移），因此覆盖与 forward 完全一致；中心线-only
  变体会光栅化零面积 ribbon，零输出。
- motion vector 取**未展开中心线**的稳定视图投影：`vCurrentClip = uCurrentStableViewProjection *
  world`、`vPreviousClip = uPreviousStableViewProjection * previousWorld`，fragment 输出
  `previousUv - currentUv`，`w > 0` 与 `|velocity| < 4` 保护与 `scene-surface.frag` 相同。展开偏移
  不进入 velocity（它是像素宽度约定而非世界运动），所以静态 lock + 静态相机逐位精确 0。
- CUTOUT 复用 forward 的 alpha profile 与 `uAlphaCutoff` discard：forward 丢掉的像素保留 opaque
  receiver 的 velocity，避免把 receiver 的运动覆盖成发丝运动。SORTED_ALPHA 无混合、按 draw 顺序
  覆盖（velocity 没有逐像素 validity）。
- 图声明：仅当 `topology.sampleCount() == 1` 且 surface layout 有 raw VELOCITY 通道时，
  `shareColorAttachments(sceneVelocity, SCENE_SURFACE_PASS, [velocity.colorSlot()], 1)` +
  共享 raster depth + `noClear()`；绝不 `createColor(SCENE_VELOCITY)`（会 shadow surface 输出）。
  NORMAL 存在时 source slot = 1，否则 0。声明紧邻两个 hair forward 声明点之后、post-process
  （TAA 在 `finishAssembly` 才声明）之前，并显式 `dependsOn(HairStrandPass.PASS_NAME)`：既保留
  declaration-order tie-break，又避免 forward 因 decal/volumetric 分支尚未 ready 时 velocity 提前
  执行；JVM 与真实 GL 都固定顺序。
- `RenderPipeline`（不是 pass，pass 会在 resize 重建）保存上一成功帧的 hair model/camera/LOD 与
  validity：成功帧在所有 fallible finalizer 之后提交，失败帧、`invalidateSurfaceHistory()`、
  resize、camera cut、hair enable/settings 变更（含统一 feature 请求）清空；previous 无效时整帧
  跳过（不写 0 覆盖 receiver velocity）；`HairStrandPass.activeLod()` 变化时跳一帧（局部几何已
  变）。`TaaInvalidationReason.HAIR_STRAND_MODEL` / `HAIR_STRANDS_SETTINGS` 的 reset 原样保留。

| disabled settings | 0 条命令，目标逐位不变 |

每 case 结束 `glGetError == GL_NO_ERROR`。`HairTaaInvalidationGlTest` 2/2：hair+TAA 声明
velocity pass；静态帧全图 velocity 精确 0；移动 lock 后新 placement 上 >100 像素非零、两个
placement 之外的 receiver 像素保持 0（不制造运动）；`TAA_HAIR_STRAND_MODEL` reset 仍触发，
`completedTaaInvalidationReason()` 与 `invalidationReasons()` 都断言。

### 诚实限制（scout memo）

- 只有 velocity；hair 像素没有自己的 validity / previous-surface-depth。TAA 与运动模糊读取的
  validity / previous-depth 来自 hair 背后的 opaque receiver（hair 不参与 surface pass），所以局部
  disocclusion 不能靠 validity 标记；lock 移动仍依赖全局 `HAIR_STRAND_MODEL` reset。
- TAA 的 sky 分支（`deviceDepth >= 0.999999`）用相机旋转重投影，从不读 velocity；发丝覆盖天空
  时该像素的 velocity 不被 TAA 消费。
- hair 不参与 TAA jitter；velocity 用 stable view-projection，与 surface pass 的约定一致。
- `HAIR_STRAND_MODEL` 的 TAA history reset 保留，仍是 lock 移动不 ghost 的主策略；velocity 只是
  让相机运动/连续移动获得正确 reprojection 数据，不替代 reset。
- hair + MSAA 仍被 policy 拒绝；velocity pass 只在 `sampleCount() == 1` 声明。
- SORTED_ALPHA 多层重叠在同一像素按 draw 顺序覆盖 velocity（无混合、无 validity）；同一 lock
  变换下差异是透视/旋转量级。
- velocity 是中心线重投影：ribbon 边缘像素沿用中心线值；纯平移/静止精确，强旋转时是近似。
- 性能、显存与人体视觉 `NOT_EVALUATED`；本轮没有新增 benchmark 或截图基线。
