## 技术卡

| 字段 | 内容 |
|---|---|
| 技术 ID／用户场景 | #41 Adaptive Sampling；在真实昂贵采样器 #20 SSR 的逐像素 ray march 上，按实测误差分配有界 step 预算，降低“所有像素都付固定最大步数”的成本，同时保持薄几何/掠射处的采样质量。首版默认关闭。 |
| 当前基础／差距 | #20 已交付纯空间 SSR：每像素固定 `maxSteps` 步、命中置信度、环境/IBL 回退；#34 已消费其噪声信号。缺少“按实测误差决定步数”的机制；质量档切换或固定步数不算自适应。 |
| 首版范围 | **一个已实现真实消费者**：`SsrPass` 的反射 march。新增 `ssr-adaptive.frag` 变体，按（a）tile 级 normal/roughness 方差与（b）该像素 coarse march 实测残差分配 `[minimumSteps, maximumSteps]` 预算；先付最小样本 floor，再按实测误差决定是否做第二次更细 march。不做新采样器、不做云/ GI 复用、不做 VRS（#42）、不做逐像素方差历史。 |
| 输入 | 与 `ssr.frag` 相同：resolved 线性 HDR 颜色、单采样设备深度、octahedral 世界几何法线、材质 roughness；`inverseProjection`（TAA 时为 jittered inverse）、`inverseView`、`view`、stable `viewProjection`、borrowed 环境 cubemap。新增 uniform：`uMinimumSteps`、`uMaximumSteps`、`uErrorThreshold`、`uTileSizePixels`、`uScreenStepScalePixels`、`uDepthJumpScale`、默认关闭的 `uBudgetDebug`。 |
| 输出 | 与 `ssr.frag` 完全相同的全尺寸 RGBA16F 反射颜色；生产 alpha 恒为 1.0（与基线一致）。`uBudgetDebug=1` 时 alpha 写 `budget/maximumSteps`，仅供 GL 验收读回分配结果，生产路径永不启用。 |
| 模块与控制 | `AdaptiveSamplingSettings`（postprocess advanced 合同）、`SsrPass` 的 adaptive 程序变体、`ssr-adaptive.frag`；`PostProcessSettings` 追加 `adaptiveSampling` 组件，默认 `disabled()`。关闭时不加载 adaptive 程序、不改变任何 uniform/Pass/target。`PostProcessPipeline.validateAdaptiveSampling` 做 fail-closed 依赖校验。 |
| 坐标与深度 | 与 `ssr.frag` 相同：OpenGL 栅格 UV（原点左下），像素中心 → UV；正 view-space 深度；march 样本用 stable view-projection 投影；深度/法线点采样不滤波。tile 由 `gl_FragCoord.xy / tileSize` 量化。 |
| 分配合同 | `budget = max(tileBudget, pixelBudget)`，其中 `normalized = clamp((error - threshold) / (1 - threshold), 0, 1)`、`steps = minimum + floor(normalized * (maximum - minimum) + 0.5)`。`tileBudget` 来自 tile 四角 probe 的 normal/roughness 方差（同一 tile 内所有像素相同）；`pixelBudget` 来自该像素最小样本 coarse march 的最大正深度跳变（以 `thickness * depthJumpScale` 归一）与穿越步的屏幕空间长度（以 `screenStepScalePixels` 归一）。深度不进入 tile 项：后退地板的平滑深度梯度不代表 silhouette。 |
| 最小样本／稳定性 | 每个 eligible 像素先无条件走 `minimumSteps` 步；只有实测误差超过 `errorThreshold` 才追加到 `budget`。更细 march 找不到命中时保留 coarse 命中（`refinedHitT > 0 || coarseHitT <= 0`），因此追加预算不会丢掉已找到的命中；分配是确定性、单调的，不是质量档枚举。 |
| 独立参考 | JVM 测试侧 `AdaptiveSamplingReference` 用 double 独立重写分配公式与成本模型：固定输入表（8/10/13/20/27/32 步）可手算复算；稀疏难例 fixture（56 easy + 8 hard cell）在**总样本成本完全相等**下比较 adaptive 与 fixed 的剩余误差模型，adaptive 更低。该模型不是 GPU 实测。 |
| 成本／回退 | 每 eligible 像素：4×3 次 tile probe fetch + `minimumSteps` 步 coarse march + 可选 `budget` 步 final march + 命中时 ≤4 次二分。最坏 `minimumSteps + maximumSteps + 4`（默认 8+32+4 = 44 次采样；固定基线 32+4 = 36），每个 march 仍被 compile-time `SSR_MAX_STEPS=64` 截断；实测残差为 0 的像素只付 floor。未做 GPU 计时，性能 `NOT_EVALUATED`。回退：adaptive 关闭时 `ssr.frag` 路径逐字节不变；adaptive 启用但 SSR/HDR 关闭或 `maximumSteps > ssr.maxSteps` 时装配期拒绝。 |
| 验证范围 | JVM：settings 7、独立参考 5、shader 合同 4、消费者接线 6，共 22 PASS；`publicApiGuard` / `architectureGuard` / `assetManifestGuard` PASS。真实 GL：`SsrAdaptiveSamplingGlTest` 9 case，本 worker 未执行，`NOT_EVALUATED`。 |

## 参数

| 参数 | 默认 | 校验 |
|---|---|---|
| `enabled` | false | 关闭时不加载 adaptive 程序、不改 uniform/Pass |
| `minimumSteps` | 8 | `[1, 64]` 且 ≤ `maximumSteps` |
| `maximumSteps` | 32 | `[minimumSteps, 64]`，并须 ≤ `SsrSettings.maxSteps()`（配置的 SSR 硬上限仍是天花板） |
| `tileSizePixels` | 8 | `[1, 64]`；最后不足一格的 tile 用 clamp 覆盖 |
| `errorThreshold` | 0.10 | `[0, 0.9]`；低于/等于阈值只付 floor |
| `screenStepScalePixels` | 4.0 | `(0, 64]`；穿越步屏幕长度达到该值即饱和 |
| `depthJumpScale` | 1.0 | `(0, 8]`；深度跳变达到 `thickness * scale` 即饱和 |

`AdaptiveSamplingSettings.budgetFor(double)` 与 shader `budgetForError(float)` 使用同一公式；
`budgetSpanSteps()`、`worstCaseSteps()`、`tileCount(width,height)` 公开供宿主报告与测试复算。

## 消费者合同与 Pass 顺序

`PostProcessPipeline` 在 `effects.ssr().active()` 时创建
`new SsrPass(effects.ssr(), effects.adaptiveSampling())`；adaptive 只改变该 pass 使用的
fragment 程序，**不新增 Pass、不新增附件、不改变 HDR 链顺序**：

```
Geometry → [HdrResolve] → [Fog] → [VfxComposite] → [ScreenDistortion] → [TAA]
  → SsrPass(fixed | adaptive) → [TemporalDenoise] → [DepthOfField] → [MotionBlur]
  → AutoExposure/Bloom → ToneMapping → ...
```

装配期校验（`PostProcessPipeline.validateAdaptiveSampling`）：

1. `active()` 必须有 active `SsrSettings`，否则
   `adaptive sampling requires an active screen-space reflection sampler`；
2. 必须有 HDR tone mapping，否则 `adaptive sampling requires HDR tone mapping`；
3. `maximumSteps()` 不得大于 `ssr.maxSteps()`，否则
   `adaptive sampling maximumSteps must not exceed the screen-space reflection maxSteps`；
4. `disabled()` 直接返回，不改变任何状态。

`SsrPass` 的公开录制入口签名不变；adaptive 由 `adaptiveSettings()` 选择。真实 GL 测试通过
同包 package-private 的 `recordIntoCurrentTarget(..., boolean exposeBudgetInAlpha)` 读取
分配结果，生产代码始终传 `false`。

**resize 语义**：本特性不拥有持久 target，SSR 颜色附件由既有 `RenderGraph` 管理，adaptive
只在现有 `SsrPass` 内选择 fragment 程序，因此没有 pass-owned resize 事务可做；resize 走
既有 pipeline/RenderGraph 代路径。`SsrPass` 自身只拥有两个 program 与 quad，`close()`
幂等；GL case 8 用第二个尺寸代（61×97）验证新代可渲染且资源回到 baseline。若后续把
adaptive 扩展为拥有 per-tile 预算纹理的独立 owner，则必须按候选代规则实现
`prepareResize`/`commitResize`，不能沿用本首版的“无持久 target”假设。

  `AdaptiveSamplingSettings.budgetFor` 及参考实现同时断言，可手算复算。

  画质或耗时。

## 明确限制与未验证项

1. **GL 未执行**：本 worker 禁止运行 GPU/GL 测试；9 个 GL case 的真实结果由串行执行者归档。
   JVM PASS 与 guard PASS 只证明合同、参考和接线，不证明 shader 像素。
2. **tile 项是 per-fragment 重复计算**，不是共享内存/缩减；4 个 probe × 3 次 fetch 在每个
   eligible 像素上重复。tile 项只覆盖 normal/roughness 不连续，不覆盖“同法线的薄遮挡物”；
   后者依赖逐像素残差。没有独立的 per-tile 预算纹理或 GPU 归约。
3. **残差只测 coarse march 的穿越 gap**：当粗样本两端都落在背景（没有 surface present）
   时无法识别被跳过的薄表面；也不会测量 final 命中的置信度误差。它是有界的误差代理，
   不是真值。
4. **两阶段成本最坏高于固定基线**（默认 8+32+4 vs 32+4）；收益取决于场景中“零残差像素”
   的比例。未做 GPU 毫秒/带宽测量，性能与收益 `NOT_EVALUATED`；不能据此宣称更快。
5. **`ssr-adaptive.frag` 复制了 `ssr.frag` 的 march/回退/置信度代码**。这是为了让禁用路径
   在源码级保持逐字节不变（精确 no-op）；代价是共享合同变更时必须同步两个文件。合同测试
   固定了 `SSR_MAX_STEPS`、`SSR_REFINE_STEPS`、回退输出与公式标记，但不能替代像素级同步。
6. **`maximumSteps ≤ ssr.maxSteps`**：adaptive 不能超过配置的 SSR 硬上限；想提高 ceiling
   必须同时提高 `SsrSettings.maxSteps`，否则装配期拒绝。
7. **无时域预算稳定性**：没有跨帧 tile 预算历史或 hysteresis；稳定性来自确定性的 floor、
   单调分配和 coarse-hit 保留。快速变化的画面可能逐帧改变预算，但不改变输出语义。
8. **`uBudgetDebug` 是测试诊断**：生产恒为 0，alpha 恒 1.0；若未来下游读取 SSR alpha，
   与基线一致。诊断只对 adaptive 启用时可用，且只对未 early-out 的像素有意义。
9. **未接入统一控制面**：`RenderFeaturesControl` / `RenderFeatureSettings` /
   `RenderFeaturePolicy` / `PipelineFeaturePolicy` / `RenderPipeline` 为本 worker 禁改文件；
   请求入口、effective/不可用原因、demo 开关与固定镜头由 Integrator 接线。由于本特性不新增
   Pass，接线只需要把 `PostProcessSettings.adaptiveSampling` 透传并纳入候选代指纹。
10. **未更新** `docs/architecture/public-api/README.md`、`docs/planning/haikalat-multi-agent-status.json`、
    `config/gl-debug-policy.tsv`（禁改文件）。若 GL 执行出现新的 debug 消息，由执行者按策略
    授权，不得放宽断言。
