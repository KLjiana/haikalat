# v0.20.1 可嵌入渲染与外部宿主契约实施计划

> 目标版本：`0.20.1-SNAPSHOT` → `0.20.1`
>
> 基线版本：`0.20.0`
>
> 状态：`0.20.1` 已完成；引擎侧与宿主侧发布验收均已确认
>
> 首个目标宿主：HaikalatHost / Minecraft 1.21.1 / NeoForge 21.1.x

## 1. 目标

v0.20.1 补齐 Haikalat 的“可嵌入渲染”能力，使引擎不再默认拥有窗口、
OpenGL context、渲染线程、默认 framebuffer 或最终 present 操作。

最终职责边界固定为：

> Haikalat 负责“如何渲染”，HaikalatHost 负责“何时渲染、渲染到哪里、
> 资源从哪里来”。

这组接口必须保持宿主无关。Haikalat 主工程不得依赖 Minecraft、NeoForge、
Blaze3D、`RenderTarget` 或 `ResourceLocation`；对应转换和事件编排全部留在
HaikalatHost。

v0.20.1 必须同时保留现有独立窗口 Demo 和 framebuffer `0` 路径。嵌入能力是新增的
显式路径，不以破坏现有 `RenderWindow`、`FrameDriver` 和 Demo 为代价。

## 2. 当前阻塞

v0.20.0 已有可复用的 `RenderDevice`、typed `CommandBuffer`、`RenderGraph`、
`RenderPipeline`、后处理、VFX 和 UI，但完整宿主接入仍被以下事实阻塞：

1. `RenderPipeline` 的最终 pass 以默认 framebuffer 为 backbuffer；
2. `PostProcessPassBuilder` 的部分 present 路径仍明确 blit 到 framebuffer `0`；
3. `UiRenderer` 每次录制都会重新绑定默认 framebuffer；
4. `RenderGraph.importTexture` 只接收 Haikalat `Texture2D`，没有 raw 外部附件和
   `BORROWED` 生命周期契约；
5. `RenderPipeline` 的尺寸和相机仍从 `RenderWindow` / `Scene.camera()` 取得；
6. `GlRenderThread` 和 Demo 可以 present，但没有一个明确保证“不创建窗口、不启线程、
   不 swap”的嵌入 runtime；
7. 外部 OpenGL 状态恢复尚未成为 Haikalat 嵌入入口的强制契约。

这些问题必须在 Haikalat 内部解决，不能由 HaikalatHost 通过强制绑定 framebuffer `0`、
复制宿主纹理或维护私有 fork 绕过。

## 3. 公共数据契约

### 3.1 资源所有权

新增通用所有权枚举：

```java
public enum ResourceOwnership {
    OWNED,
    BORROWED
}
```

- `OWNED`：资源由 Haikalat 创建，且只由对应 Haikalat owner 在渲染线程销毁一次；
- `BORROWED`：资源由宿主创建，Haikalat 只能在声明用途内使用；
- `BORROWED` framebuffer/texture 不得被删除、重新分配、改变 storage 或修改采样参数；
- RenderGraph 导入资源固定按 `BORROWED` 处理，不能进入 deferred deletion 或 generation
  退休队列；
- 所有权必须由类型或构造参数显式给出，不根据 ID、framebuffer `0` 或调用路径猜测。

现有 `core.material.ResourceOwnership` 只描述 Material 对 shader/texture/sampler 的关闭
职责。实现阶段应评估迁移到通用枚举，或保留兼容适配；不得长期维护两个语义不同但同名的
所有权协议。

### 3.2 外部附件

新增不可变外部附件描述，至少包含：

```java
ExternalAttachment {
    int textureId;
    AttachmentRole role;       // COLOR / DEPTH / STENCIL / DEPTH_STENCIL
    RenderFormat format;
    int width;
    int height;
    int samples;
    ResourceOwnership ownership;
}
```

要求：

- native ID 必须非负；`0` 只表示附件不存在或 API 明确允许的默认对象；
- width/height 允许同时为零，表示宿主当前不可渲染；
- 非零尺寸必须与 `PresentationTarget` 一致；
- multisample 数、格式和 role 在导入时验证；
- `STENCIL` 可以独立，也可以与 depth 共用 `DEPTH_STENCIL` texture；
- 导入操作不修改 texture parameter，不创建 texture view，不接管 bindless residency。

### 3.3 PresentationTarget

新增宿主无关的 `PresentationTarget`，至少描述：

```java
PresentationTarget {
    int drawFramebufferId;
    int readFramebufferId;
    ExternalAttachment color;
    ExternalAttachment depth;     // optional
    ExternalAttachment stencil;   // optional，可与 depth 为同一 attachment
    int width;
    int height;
    int samples;
    ResourceOwnership framebufferOwnership;
}
```

必须提供：

- framebuffer `0` 的兼容工厂；
- 单一非零 FBO 的常用 borrowed 工厂；
- draw/read FBO 分离的高级构造；
- `hasDepth()`、`hasStencil()`、`isRenderable()` 等只读查询；
- 确定性的结构校验和清晰错误消息；
- 目标 identity/revision，使 Host 在 FBO 重建后可直接提交新值，不重建整个引擎。

`PresentationTarget` 是目标描述，不负责调用 `swapBuffers`。即使它描述 framebuffer `0`，
Haikalat 的 pipeline 也只写入目标，不自行 present。

### 3.4 ExternalCamera

新增不可变外部相机快照：

```java
ExternalCamera {
    Matrix4f view;
    Matrix4f projection;
    Matrix4f viewProjection;
    Vector3f position;
    float partialTick;
}
```

实现还应提供或预计算：

- inverse view；
- inverse projection；
- inverse view-projection；
- 可选 near/far 与 depth convention；
- 单调 frame/revision 标识，供 visibility cache 正确失效。

构造时复制调用方矩阵和向量，避免宿主在命令执行前修改同一对象。`viewProjection` 必须与
`projection * view` 约定一致；如果允许宿主显式传入，应提供可选的一致性校验。

同一份 `ExternalCamera` 必须贯穿：

- 几何与可见性；
- PBR 光照相机位置；
- 环境背景；
- 方向光、点光和聚光阴影选择所需相机数据；
- 雾、景深、TAA/抖动与其他后处理；
- VFX billboard、soft particle 与世界空间效果；
- UI 的世界空间节点。

任何 pass 都不得在嵌入路径中重新读取 Haikalat 的窗口相机。

## 4. RenderGraph 外部资源导入

### 4.1 导入接口

RenderGraph 新增显式导入：

```java
graph.importExternalColor("hostColor", target.color());
graph.importExternalDepth("hostDepth", target.depth());
graph.importExternalStencil("hostStencil", target.stencil());
graph.importPresentationTarget("hostTarget", target);
```

同一逻辑名允许在帧边界替换为新的 borrowed handle，支持宿主 resize、世界切换和
`RenderTarget` 重建。替换要求：

- 不改变 pass topology；
- 不关闭旧 borrowed handle；
- 在下一次 execute 前原子可见；
- 尺寸/格式/采样不兼容时确定性拒绝；
- replacement 失败时保留上一份有效导入；
- graph close 只清理自身 managed/owned target，不清理任何 external import。

### 4.2 Pass 输出

PassBuilder 增加命名外部目标：

```java
graph.addPass("Present")
        .writeToPresentationTarget("hostTarget")
        .noClear()
        .dependsOn("ToneMapping")
        .execute(...);
```

现有 `writeToBackbuffer()` 保留，并等价使用当前执行上下文的 presentation target：

- 独立窗口路径传入 framebuffer `0` target；
- 嵌入路径传入宿主 target；
- 不允许 pass 自己猜测或重新绑定 framebuffer `0`；
- pass resources 可以读取当前 target 的尺寸与附件 ID，但不能取得可关闭 owner。

目标尺寸为 `0 × 0` 时，整个 frame 应在创建临时 target、上传 frame-only 数据和执行 draw
之前返回 `SKIPPED_ZERO_EXTENT`。它不是 fatal error，也不能污染上一帧 profile。

## 5. RenderPipeline

### 5.1 新渲染入口

新增明确的嵌入入口，具体参数顺序可在实现阶段按现有 `RenderDevice` 归属收敛：

```java
pipeline.render(scene, externalCamera, presentationTarget);
```

或：

```java
pipeline.execute(renderDevice, externalCamera, presentationTarget, deltaSeconds);
```

要求：

- target 和 camera 是每帧显式输入；
- 不固定绑定默认 FBO；
- 不调用 `swapBuffers` / present；
- 不使用 GLFW 窗口尺寸；
- target resize 触发 Haikalat managed relative target 的 candidate-first resize，
  绝不重分配 borrowed attachment；
- FBO/texture ID 变化但尺寸和格式相同时只更新 external import；
- zero extent 直接跳过；
- 同一 pipeline 可以连续接收多个 target generation；
- render 返回结构化结果，至少区分 rendered、zero-extent skip 和 validation failure。

### 5.2 兼容路径

已有入口继续工作：

```java
pipeline.execute(device, deltaSeconds);
```

兼容入口只负责从现有 `RenderWindow` 和 `Scene.camera()` 生成一份 framebuffer `0`
presentation target 与 camera snapshot，然后复用同一内部实现。不能长期维护两套 pass
执行逻辑。

### 5.3 帧结束语义

嵌入路径结束时：

- 不 present；
- 不把 FBO、viewport 或 program 重置成 Haikalat 认为的默认值；
- 不留下绑定到已退休 Haikalat resource 的状态；
- 无论成功或异常，都在 `finally` 中恢复进入前捕获的宿主 GL 状态；
- 恢复后使 Haikalat `RenderDevice` 状态缓存失效，使下一帧重新建立事实；
- 不尝试同步 Minecraft/Blaze3D 的 Java 状态缓存，该步骤由 HaikalatHost 在外层完成。

## 6. UI、VFX 与后处理

### 6.1 UI

UI renderer 增加外部目标入口：

```java
uiRenderer.render(uiScene, presentationTarget, width, height);
```

或与现有 snapshot/command 模型一致的等价 `record` 入口。

要求：

- UI overlay 使用与 scene 最终输出相同的 target；
- logical window size 与 framebuffer pixel size 分开传递；
- scissor 和 content scale 使用显式目标尺寸；
- UI 不绑定默认 framebuffer；
- UI 不调用 present/swap；
- zero extent 时不初始化或更新 frame-only GPU ring；
- glyph atlas、image resolver 和 borrowed UI image 继续遵守现有所有权合同。

### 6.2 VFX

- HDR VFX recorder 消费当前 `ExternalCamera`；
- billboard、stretch、soft particle 和 depth sampling 使用同一 camera/target depth；
- 不允许 VFX 从全局窗口或 Demo singleton 获取尺寸；
- borrowed depth 不得被 resolve/重建，必要的 Haikalat 中间 resolve 必须写入自有 target。

### 6.3 后处理

- LDR blit、HDR tone mapping、FXAA、TAA、Bloom、雾和 color grading 最终写入显式 target；
- `FxaaPostProcessor.record`、`TemporalAccumulationPass.record` 等旧默认 FBO 入口应迁移到
  `recordIntoCurrentTarget`，旧方法保留兼容并标记迁移方向；
- 后处理需要宿主 depth 时，从 RenderGraph external depth import 读取；
- target format/sRGB policy 必须显式，不能根据 framebuffer `0` 猜测；
- 宿主 multisample target 与 Haikalat pipeline AA 组合必须验证，不允许静默使用错误 blit filter。

## 7. 无窗口嵌入 Runtime

新增不创建任何平台对象的入口：

```java
HaikalatRuntime runtime = HaikalatRuntime.createEmbedded(renderDevice);
```

嵌入模式下由 Host 提供：

- 当前且满足能力契约的 OpenGL context；
- 唯一渲染线程；
- `RenderDevice`；
- 每帧 `PresentationTarget`；
- 每帧 `ExternalCamera`；
- delta time / partial tick / frame sequence；
- 资源重载、世界切换和 shutdown 的调用时机。

Haikalat embedded runtime：

- 不创建 `GlfwWindow`；
- 不创建或切换 OpenGL context；
- 不启动 `GlRenderThread`；
- 不控制宿主主循环；
- 不调用 `glfwSwapBuffers`；
- 记录创建线程并拒绝其他线程上的 GL 操作；
- 将调用分为 `READY`、`CLOSED`，初始化失败不得留下半初始化 owner；
- `close()` 幂等，只关闭 Haikalat `OWNED` 资源，不关闭 borrowed `RenderDevice` 或宿主资源；
- 多次 create/close 不得重复释放。

## 8. OpenGL 状态隔离

嵌入 render scope 进入时捕获、退出时恢复至少以下状态：

- draw/read framebuffer；
- viewport、scissor box 与 scissor enable；
- current program、VAO；
- active texture，以及 Haikalat 可能触及 texture unit 的 texture/sampler binding；
- array、element、uniform、shader-storage、image、pixel pack/unpack、indirect 等实际触及的
  buffer binding；
- blend enable、function、equation；
- depth enable、function、write mask；
- cull enable、mode、front face；
- stencil enable、front/back function、operation、read/write mask；
- polygon offset；
- color mask；
- framebuffer sRGB。

实现必须：

1. 在执行前使 Haikalat 状态缓存失效；
2. 使用同一作用域执行完整 graph；
3. 在异常路径也恢复；
4. 恢复后再次使状态缓存失效；
5. 提供 debug diff，能够报告未恢复的具体 binding，而不是只返回 boolean。

状态捕获范围应由 Haikalat 实际可能修改的集合驱动。若新增 command opcode 会修改新的 GL
状态，必须同步扩展 state-scope 测试。

## 9. 实施顺序

### M0：基线与失败证明

- 固定 v0.20.0 的 public API、RenderGraph 描述、最终 pass 和资源计数基线；
- 新增测试证明当前 final pass 会写 framebuffer `0`、UI 会重新绑定默认 FBO；
- 记录 Host 非零 FBO 和 camera snapshot 的最小输入样例；
- 所有新增 public 类型先进入 API allowlist 分类。

### M1：不可变值对象与所有权

- 落地 `ResourceOwnership`、`ExternalAttachment`、`PresentationTarget`；
- 落地 `ExternalCamera`；
- 完成纯 JVM validation、defensive-copy、zero extent、identity/revision 测试；
- 明确旧 material ownership 的兼容方案。

### M2：RenderGraph external import

- 导入 color/depth/stencil/presentation target；
- 支持帧边界 replacement；
- pass 可写命名 target；
- close/resize/失败回滚不触及 borrowed resource；
- description/diagnostics 标记 `EXTERNAL` 与 `BORROWED`。

### M3：RenderPipeline 显式 target

- 最终 LDR/HDR/FXAA/TAA pass 全部使用当前 target；
- 兼容 framebuffer `0` 入口委托到新路径；
- target resize 和 FBO generation replacement；
- zero extent 跳过；
- pipeline 不 present。

### M4：ExternalCamera 全链路

- geometry/culling/uniform；
- PBR lighting/environment；
- shadows；
- fog/postprocess；
- VFX；
- 世界空间 UI；
- 删除嵌入路径上的窗口相机回读。

### M5：UI/VFX/后处理目标统一

- UI snapshot 和 scissor 使用外部尺寸；
- UI overlay 不绑定默认 FBO；
- VFX 和 postprocess 共享 target attachments；
- sRGB、depth、stencil 和 sample compatibility 验证。

### M6：Embedded Runtime 与状态恢复

- `HaikalatRuntime.createEmbedded(renderDevice)`；
- render-thread guard；
- borrowed device/target lifecycle；
- 完整 GL state scope 和异常恢复；
- 多次初始化/关闭与 Host generation 切换。

### M7：端到端验证与 0.20.1 发布

- 独立隐藏窗口创建非零宿主 FBO；
- scene + postprocess + VFX + UI 写入宿主 color texture；
- 真实 depth occlusion；
- resize 后替换 FBO/texture；
- borrowed deletion sentinel；
- GL state before/after diff；
- HaikalatHost 客户端烟雾测试；
- 更新 changelog、能力矩阵、接入指南和正式 release report；
- 完整 `releaseReadiness -PreleaseVersion=0.20.1`。

## 10. 必须补的自动化测试

| 测试 | 最低证明 |
| --- | --- |
| 非零 FBO | 最终 draw framebuffer 为宿主给出的非零 ID，framebuffer `0` 像素不变 |
| Color 输出 | readback 宿主 color texture，像素与清屏值不同且符合场景/UI 预期 |
| Depth 输入 | 宿主 depth texture 参与遮挡、soft particle 或后处理，A/B 像素可区分 |
| Stencil 输入 | 声明 stencil 时 role/format 正确；缺少或不匹配时确定性拒绝 |
| Resize replacement | 旧 target 保持有效，新 target 从下一帧接收输出，不重建整个 runtime |
| Borrowed 生命周期 | graph/pipeline/runtime close 后 `glIsFramebuffer/glIsTexture` 仍为 true |
| Zero extent | 不执行 pass、不上传 frame-only 数据、不抛 fatal error、不 present |
| 重复 create/close | owner 只释放一次，borrowed resource 从不释放 |
| GL 状态恢复 | 成功和故意抛异常两条路径的进入/退出 snapshot 完全一致 |
| Camera 一致性 | geometry、lighting、shadow、fog、VFX 和 world UI 读取同一 revision/matrix |
| UI 目标 | UI 命令没有 bind framebuffer `0`，像素写入宿主 color texture |
| VFX/后处理目标 | HDR VFX、Bloom、tone mapping/FXAA 输出最终进入同一宿主 target |
| 无 swap | 嵌入路径没有 GLFW 依赖或 swap callback，静态架构测试可证明 |
| 线程契约 | 非创建线程调用 GPU 入口确定性失败，且不执行部分命令 |

真实 GL 测试应独立创建“宿主资源”，再把 raw ID 交给 Haikalat。不能使用 Haikalat
Framebuffer owner 创建后又把同一 owner 传回，以免遗漏 borrowed 删除问题。

## 11. 发布门禁

`0.20.1` 不得发布，直到同时满足：

1. 新 public API 已分类并有 JavaDoc；
2. framebuffer `0` 兼容路径通过原有全部测试；
3. 非零 FBO scene/UI/VFX/postprocess 真实像素测试通过；
4. borrowed color/depth/FBO 在所有 close/failure 路径后仍有效；
5. zero extent、resize、世界 target replacement 通过；
6. 外部相机在所有相关 pass 中没有窗口相机回读；
7. 宿主 GL 状态在成功和异常路径完整恢复；
8. embedded runtime 没有 GLFW、Minecraft、NeoForge 或 `ResourceLocation` 依赖；
9. Windows/Linux CI 与本地 OpenGL 4.6 集成门禁通过；
10. HaikalatHost 使用发布候选完成一次真实 Minecraft 客户端烟雾测试。

## 12. 明确不进入 v0.20.1

- 不直接在 Haikalat 中加入 Minecraft/NeoForge API；
- 不让 Haikalat 接管 Minecraft 主循环、世界 renderer 或窗口；
- 不创建第二个窗口、context 或 render thread；
- 不替 Host 恢复 Blaze3D 的 Java 状态缓存；
- 不为嵌入能力引入新的渲染后端；
- 不借机重写完整 RenderGraph 或 UI subsystem；
- 不通过未声明的隐式复制掩盖外部附件契约；需要 HDR/后处理 owned intermediate 时，
  source transfer 必须以已验证的 imported attachment 为来源，且不得修改宿主 storage；
- 不移动或重新分配 borrowed texture storage；
- 不把 `swapBuffers` 隐藏在 pipeline、UI 或 runtime close 中。

## 13. 与 HaikalatHost 的对接边界

HaikalatHost 负责把 Minecraft 当前帧数据转换为本计划的通用值对象：

```text
Minecraft RenderTarget/FBO
        → PresentationTarget(BORROWED)

Minecraft camera matrices/partial tick
        → ExternalCamera

Minecraft render event + Render Thread
        → HaikalatRuntime embedded frame call

Minecraft resource reload/world switch/resize
        → target generation replacement + Haikalat asset generation
```

Haikalat 只验证并消费这些值，不认识它们来自 Minecraft。Host 在 Haikalat 状态恢复后，
仍负责通过 Blaze3D API 恢复/同步 Minecraft 自己的状态缓存。

更完整的宿主实施顺序见外部工程：
`D:/project/Java/Project-Crystal-Fracture/HaikalatHost/docs/haikalathost-0.20.md`。

## 14. 当前实现证据

- 公共契约：`AttachmentRole`、`ExternalAttachment`、`PresentationTarget`、
  `PresentationResult`、`OwnedPresentationTarget`、`ExternalCamera` 和
  `HaikalatRuntime.createEmbedded(RenderDevice)`；
- RenderGraph：borrowed color/depth/stencil/target 导入、命名 presentation target、
  同逻辑名 replacement、zero-extent skip，close 不接管导入资源；
- Pipeline：显式 `ExternalCamera + PresentationTarget` 入口，LDR/HDR、Bloom、tone mapping、
  FXAA 和 camera-aware HDR VFX 使用同一帧目标；旧 framebuffer `0` 入口保持兼容；
- UI：`UiRenderer.record(..., PresentationTarget)` 使用显式 FBO、像素尺寸与 sRGB 策略；
- 状态隔离：嵌入帧在成功和异常路径都恢复宿主 FBO、viewport/scissor、program、VAO、
  buffer/texture/sampler/image binding 及 blend/depth/cull/stencil 等状态；
- 门禁：`embeddedJvmVerification` 与 `embeddedGlVerification`。后者使用宿主直接创建的
  raw 非零 FBO/color/depth-stencil，验证真实像素、深度遮挡、target replacement、
  borrowed deletion sentinel、zero extent、UI/VFX/postprocess 同目标和状态恢复。

Haikalat 主工程依赖。
