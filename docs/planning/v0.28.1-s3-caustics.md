## 技术卡

|---|---|
| 技术 ID／用户场景 | #36 Caustics；为有限水体场景提供“水下地面/池底被水面聚焦光斑照亮”的艺术化光照贡献。首版默认关闭，配置/Pass 不进入图时零成本。 |
| 当前基础／差距 | 已有共享 `scene.depth`（raster 深度的单采样纹理或 MSAA 深度）、HDR `SceneColor`、`TemporalFrameState` 帧矩阵、`Framebuffer`/`CommandBuffer`、候选代/借用资源协议，以及 `WaterSurfacePass`、`SsrPass` 的 Pass 生命周期风格。缺少“从水体沿主光投射到接收面”的受控设置、程序化图样、共享深度拒绝和独立参考。 |
| 首版范围 | 一个有限水平水矩形（`y == waterLevel`）沿一个主方向光投射到水下接收面；程序化三列正弦干涉脊线图样（可选 alpha 纹理调制）；确定性时间相位；世界尺度/动画速度/强度/颜色；最大光路距离、接收面高度带、水体投影区域、depth bias、指数距离衰减、区域/高度边缘淡出、接收面坡度拒绝。**明确不是**光子映射、物理焦散求解、折射/反射求解或水下体积渲染。 |
| 不支持输入／拒绝 | 水矩形必须有限且宽/深 `∈ [0.05, 20000]` 米；`waterLevel` 与接收面高度必须在 `±10000` 米内；接收面高度带至少 `0.01` 米厚；`intensity ∈ [0,8]`；颜色分量 `∈ [0,16]`；`worldScaleMetres ∈ [0.05,1000]`；`animationSpeed ∈ [-4,4]` 周/秒；`maximumProjectionDistance ∈ [0.05,1000]` 米；`depthBias ∈ [0,10]` 米；`distanceFalloff ∈ [0,8]` 1/米；`edgeFadeDistance ∈ [0,100]` 米；`maximumReceiverSlopeDegrees ∈ [0,89]`；`patternTexture` 只能为空或 `/` 开头的 classpath 路径（≤256 字符）。所有值在设置构造期拒绝，不静默夹取。主光方向在 `record` 期要求有限、非零、归一化后 `y < -1e-3`（必须向下），否则拒绝该帧。 |
| 模块与控制 | 新职责包 `subsystems.render3d.caustics`：advanced `CausticsSettings`（纯值，唯一配置）、internal `CausticsPass`（`GlResource`，拥有 shader、全屏 quad、可选纹理和 RGBA16F 目标）。`RenderPipeline`/`RenderFeatureSettings`/`RenderFeaturePolicy`/`PipelineFeaturePolicy` **本包未接线**（文件 owner 限制），由 Integrator 按下方接线点完成。`CausticsSettings.disabled()` 是唯一 no-op 值；关闭时零 Pass、零 shader、零附件、零 draw。 |
| 真实生产消费者 | Pass 的直接消费者是调用方提供的 `Framebuffer colorSource` 与共享场景深度纹理：Pass 复制场景颜色并把焦散加法贡献写入自己的 `causticsColor` 目标。当前**真实读回消费者**是 `CausticsPassGlTest`（生产 Pass + 真实 GL framebuffer/深度纹理）；`RenderPipeline` 生产帧路径的接线待 Integrator。因此本项是 bounded Pass 交付，而非已经进入默认生产帧路径的完整特性。 |
| 输入 | `Framebuffer colorSource`（不透明/已解析 HDR 场景颜色，RGBA16F；尺寸必须等于 Pass 目标）、共享场景深度纹理 id（单采样 `sceneDepth` 或与 Pass `samples` 一致的 `sceneDepthMS`）、`TemporalFrameState.FrameParameters`（宽高、`inverseJitteredProjection`、`view`）、归一化世界空间主光方向（光传播方向，`y<0`）、非负累积时间秒。Pass 不读取相机对象、不读取阴影图、不读取历史。 |
| 输出 | Pass 私有全尺寸单采样 `RGBA16F` 颜色目标，内容 = 复制的场景颜色 + 焦散颜色（加法混合，alpha 保持 `colorSource` 的 alpha）；不写共享颜色、不写共享深度、不写 mip。下游通过 `colorTexture()` 读取，关闭后返回 0。 |
| 空间与坐标 | 世界空间右手系，1 单位按米解释，Y 向上；主光方向为“光传播方向”，接收面沿该方向回溯到水面的入水点。世界位置由 `gl_FragCoord` 像素中心 + 共享设备深度经 `inverseJitteredProjection` / `inverseView` 反投影得到，和 SsrPass 的深度重建约定一致；屏外/背景（`depth >= 1`）直接拒绝。 |
| 水体／接收面／主光／时间关系 | 对每个像素重建世界点 `P`；垂直厚度 `h = waterLevel - P.y`，必须 `h > depthBias`；光路距离 `travel = h / max(-light.y, 1e-4)` 必须 `≤ maximumProjectionDistance`；入水点 `W = P - light * travel` 必须位于有限水矩形内；接收面高度 `P.y` 必须位于 `[receiverMinimumHeight, receiverMaximumHeight]`；由深度导数重建的几何法线必须满足 `|n.y| >= cos(maximumReceiverSlopeDegrees)`（排除墙/立面）。时间只进入确定性图样相位 `2π · animationSpeed · timeSeconds`，同一输入序列得到同一图样，无随机数、无帧计数噪声、无时域累积。 |
| 图样 | 三层确定性正弦干涉，取“波峰相消处”的脊线：`q = W.xz / worldScaleMetres`；`sum = (sin(2π(0.83qx+0.37qz)+φ) + sin(2π(-0.44qx+0.79qz)·1.21-0.73φ+1.7) + sin(2π(0.17qx-0.91qz)·0.87+1.31φ+3.1))/3`；`ridge = clamp(1 - 1.8|sum|, 0, 1)`；`pattern = ridge³ ∈ [0,1]`。可选纹理按 `patternCoordinates` 采样 alpha 通道（线性数据，重复平铺）并乘到程序化图样上；空路径保持纯程序化。 |
| 衰减／边缘 | `attenuation = exp(-distanceFalloff · travel) · rangeFade · regionFade · heightFade`；`rangeFade = 1 - smoothstep(0.8·maxDistance, maxDistance, travel)`；水矩形边缘距离经 `smoothstep(0, min(edgeFade, 0.5·min(width,depth)), edgeDistance)`；接收面高度带上下各 `min(edgeFade, 0.5·bandThickness)` 的 smoothstep 淡出。边缘淡出为 0 时为硬边界。最终颜色为 `color · intensity · pattern · attenuation`，alpha 为 0（加法混合不改变目标 alpha）。 |
| 深度拒绝与厚度限制 | 每像素从共享深度重建接收面，不使用固定平面假设；前景遮挡物（深度更近）会按它自己的世界位置参与坡度/高度/距离/区域判定，而不是按被遮挡地面的位置被照亮。水体区域、最大光路距离、depth bias、接收面高度带与坡度门共同避免穿墙/投射到错误表面。**限制**：这是屏幕空间深度拒绝，不能发现“只存在于水面与接收面之间、但对相机不可见”的独立遮挡物；没有阴影图/光线步进可见性测试，也没有水面掩码。 |
| Pass 顺序（建议接线） | 推荐 `SceneSurfacePass → GeometryPass → CausticsPass → WaterSurfacePass → [Transparent/Volumetric/TAA/Fog/…] → PostProcess`。**当前 `WaterSurfacePass` 不写深度**：若把焦散放在水面之后，共享深度仍是水下地面，焦散会被加到已经合成的水面颜色上，看起来像水面自发光。因此首版应在水面之前把焦散加到不透明场景颜色上，再由水面 Pass 用自己的吸收/Fresnel 合成。若 Integrator 坚持“水面之后”，必须额外提供水面覆盖掩码或把焦散改为 PBR 接收面着色项；本版不提供该掩码，不能直接后置。焦散目标可作为水面 Pass 的 `sceneColorSource`；水面关闭时焦散输出直接进入后续 HDR 链。 |
| GPU owner | 与现有 Render3D 一致：构造函数、`record`、`resize`、`close` 必须在同一 GPU owner 线程/current context 内执行。Pass 不创建线程、不做异步 PBO、不做逐帧 GPU 读回、不使用 `glFinish`；GL 测试的 `glReadPixels` 仅存在于测试。 |
| 准备／提交／退役／失败 | 构造：先校验 settings/extent，再依次创建 shader、quad、可选纹理、目标 FBO；任一步失败按相反顺序关闭已创建资源并抛出，不发布半成品。`resize`：先完整创建候选 FBO，成功后才替换字段并关闭旧 FBO；候选失败保留旧目标。发布后旧 FBO 关闭失败时新目标保持活动并向上报告（不伪报回滚）。`close`：幂等，关闭目标、可选纹理、quad、shader，聚合关闭异常；关闭后 `width/height/colorTexture/id` 返回 0，`record/resize` 抛 `GlException`。不写深度、不采样自己写入的附件，因此无反馈。 |
| 所有权与借用 | Pass 拥有自己的 shader、全屏 quad、可选 pattern 纹理和 RGBA16F 目标；`colorSource`、共享深度纹理、调用方帧参数均为借用，不关闭。可选纹理从 classpath 加载并归 Pass 所有；缺失/解码失败使构造失败，不静默回退到程序化图样（避免“配置了资产却悄悄没生效”）。 |

## 接线点（Integrator 必读）

1. **配置入口**：在 `RenderPipeline`/`RenderFeatureSettings`（本包禁止修改）增加 `CausticsSettings` 字段，默认 `CausticsSettings.disabled()`；build 前配置、帧边界 apply；`enabled=false` 时不构造 Pass、不创建附件。若使用统一 `RenderFeature`/`RenderFeaturePolicy`，需新增 `CAUSTICS` 项与 HDR/水面依赖校验（本包未改这些文件）。
2. **Pass owner**：在 `PipelineGeneration` 增加 `CausticsPass` 字段与 `assembleCaustics(...)`：`settings.active()` 时以 `topology.sampleCount()`、场景宽高创建；兼容候选代可借用/转交，`close()` 负责退役；关闭时不创建任何附件。
3. **Pass 顺序**：`GeometryPass → CausticsPass → WaterSurfacePass`（见上方“Pass 顺序”）。焦散 Pass 输出 `causticsColor`；Integrator 可用 `pass.colorTarget()`（借用的目标视图，禁止关闭/改绑）作为水面 Pass 的 `sceneColorSource`；水面关闭时由后续 HDR 链消费。**不要**在未提供水面掩码时把焦散放到水面之后。
4. **深度与样本数**：`samples` 必须与共享深度一致；单采样用 `sceneDepth` 的纹理 id，MSAA 用 `sceneDepthMS` 并让 Pass 以 `samples>1` 构造（shader 用 `texelFetch(...,0)` 取 sample 0，逐样本焦散不在本版承诺内）。不要把 `GeometryPass` 颜色附件与 Pass 目标混为同一附件。
5. **resize**：帧/窗口尺寸变化时先调用 `pass.resize(width,height)`，再 `record`；`record` 会校验 `colorSource`、`frame` 与目标尺寸一致，尺寸不匹配直接失败而不是隐式分配。
6. **时间**：使用与水面 Pass 相同的成功帧累积时间；暂停时不推进。不要传帧计数器或随机数，否则破坏可复现性。
7. **公共 API 文档**：`docs/architecture/public-api/render3d.allowlist` 已登记 `CausticsSettings`（advanced）与 `CausticsPass`（internal）；`docs/architecture/public-api/README.md` 叙述条目按文件 owner 限制未修改，属集成期文档缺口。

## GPU 首轮失败与修复（2026-11-12）

Orchestrator 首轮真实 GPU 执行先发现 shader 编译/链路失败：`caustics.frag` 使用了 `uMaximumProjectionDistance`，但既没有 `uniform float` 声明，`CausticsPass` 也没有上传。修复：fragment shader 增加声明，`record()` 增加对应 `setUniformFloat`。修复后 6 个 case 中 3 个失败，逐项结论如下。

### 1. RGBA16F 量化导致的背景精确相等（2 个 case）

`outsideRegionBandAndMaximumDistanceStayUnchanged` 和 `disabledAndZeroIntensityAreNoOps` 用 `1e-6` 比较未变化的背景，但目标附件是 RGBA16F：清除色 red `0.05` 读回为 `0.049987793`，差约 `1.22e-5`，属于半浮点存储量化。修复：新增 `BACKGROUND_TOLERANCE = 1e-3`，只用于“背景未被修改”的断言；该容差同时覆盖平滑边缘处 float/double 分类的亚阈值差异，真实错位焦散量级约 `0.1–1.0`，仍会被检出。焦散数值仍用 `5e-3` 与独立参考比较。没有放宽到会掩盖真实焦散的量级。

### 2. 前景遮挡区域被照亮（1 个 case）

失败读数：B 侧 covered 像素 red `0.37231445`，恰好等于 A 侧地面焦散（amount ≈ 0.585，`0.55·0.585 + 0.05`），说明 B 侧仍在使用**地面深度**，而不是 fixture 写入的前景深度。

几何/深度推导（测试相机 `(0,6,10)`、pitch `-50°`、`forward.y=-0.766`，恒定视空间距离平面）：

- 地面深度：view distance `10 m`，covered 像素反投影约 `(-1.359, -3.616, 5.902)`；`thickness = 0 - (-3.616) = 3.616 m > depthBias`，是合法接收面。
- 前景深度：view distance `3 m`，同一像素反投影约 `(-0.408, +3.115, 8.771)`；`thickness = 0 - 3.115 = -3.115 m < depthBias`，必须拒绝，B 侧应为背景。
- 因此 B 侧被照亮只能意味着深度纹理没有被改成前景深度。

根因是 fixture 的 GL 状态假设错误，不是 shader 的深度门错误：`CommandBuffer` 的 pending pipeline state 在下一个可观察 GPU 边界才提交；`CausticsPass.record` 在 draw 之后记录的 `depthMask(true)` 恢复状态在 `execute` 结束时仍是 pending，实际深度写掩码仍为 `false`。fixture 随后用 raw `glClear(GL_DEPTH_BUFFER_BIT)` 清前景深度（以及 B 侧重置地面深度）时被静默忽略，于是 B 侧继续读地面深度。

修复（两层）：

1. `CausticsPass.record` 在恢复 `enableBlend(false)/depthMask(true)/enableDepthTest(true)` 后调用一次 `blendEquation(GL_FUNC_ADD)` 作为 state-flush 边界，保证 pass 声明的恢复状态在 `execute` 返回前真正生效；混合已关闭，额外调用无视觉影响。
2. GL fixture 的 `clearScene`/`clearDepthRegion` 在 raw clear 前显式 `glDisable(GL_SCISSOR_TEST)` + `glDepthMask(true)`，不依赖 pass 之后的外部状态；这样即使未来 pass 恢复策略变化，A-B fixture 仍然可信。

修复后 JVM `*Caustics*` 重新执行通过；GPU 由 Orchestrator 串行重跑。修复后的 A-B 预期仍是：A 侧地面被照亮，B 侧同一像素（前景深度）保持背景，前景区域外的可见地面继续被照亮。

## 明确限制与未验证项

1. **艺术近似**：图样是解析正弦干涉脊线 + 可选 alpha 纹理，不是 photon mapping / 物理焦散求解；没有真实光路聚焦、焦散面亮度积分、波长色散或光强守恒证明。
2. **无水下体积/色散**：不渲染水下雾、吸收散射分层、蓝绿偏色、体积光束或色散；焦散只是表面加法光照，水下颜色交给既有水面/雾/后处理。
3. **屏幕空间深度限制**：只拒绝共享深度中可见的表面；水面与接收面之间对相机不可见的独立遮挡物无法被检测。没有阴影图、光线步进可见性或“水面掩码”，因此不能承诺穿墙完全正确。
4. **与水面边界**：`WaterSurfacePass` 当前不写深度，所以推荐顺序是“焦散在水面之前”；若后置会叠加到水面颜色上。水面吸收会把先加的焦散一起衰减，这是首版接受的近似，不是解析水下辐射传输。
5. **与雾边界**：焦散是表面颜色贡献，不参与体积雾积分；雾/体积合成在其后按既有顺序处理，可能出现“雾把焦散一起压暗”的观感，未提供单独的体积焦散。
6. **单水体/单主光**：首版只有一个水矩形和一个主光方向；不支持多水体混合、聚光灯/点光焦散、动态水面顶点位移后的焦散重投影。
7. **MSAA 未验证**：`CAUSTICS_MSAA` 分支取 sample 0，逐样本正确性、MSAA 边缘稳定性和与 TAA 的组合均 `NOT_EVALUATED`。
8. **资源失败注入未验证**：代码路径保留“候选失败保留旧目标、发布后旧 FBO 关闭失败上报”，但没有注入真实 GL 分配失败；该分支 `NOT_EVALUATED`。
9. **GL 修复后未重跑**：`CausticsPassGlTest` 6 个 case 已编写；首轮 GPU 在修复前 2 个精度断言失败 + 1 个 A-B fixture 深度状态失败，修复后由 Orchestrator 串行重跑。本文不把 JVM 通过当作 GL 通过，GL 状态 `NOT_EVALUATED`。
10. **性能/显存未测量**：每帧全尺寸 blit + 全屏 draw + 一张 RGBA16F 附件；未测 1080p/4K、Low/Medium/High 档或与其他效果的组合成本，成本 `NOT_EVALUATED`。
11. **未测组合**：与水面、体积雾、透明度、TAA/MSAA、Bloom/DOF、实际场景几何和不同 GPU/驱动的组合均未验证；GL 测试夹具使用合成深度而非真实场景栅格化。
