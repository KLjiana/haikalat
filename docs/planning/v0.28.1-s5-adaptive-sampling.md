## 背景与两个证据缺口

S4 卡和独立验收 F7 记录：

1. **GL oracle 不是成本匹配**：旧 case 取 debug alpha 的最终预算均值
   `meanBudget = round(mean(b))`，再用 `fixed(meanBudget)` 作 control。adaptive 实际是
   “每个 eligible 像素先无条件付 `minimumSteps`，只有 `b > minimumSteps` 的像素再付一次
   完整 `b` 步 march”。固定均值 control 的 total 是 `Σb`，比 adaptive 的精确 total 少
   `minimumSteps × extraPixels`，所以它并不花同样的成本。
2. **residual 用例被 tile 混淆**：旧 floor+wall fixture 的 tile 同时有 normal/roughness
   差异，tile-only 规则也可能给出额外预算；缺少“tile 统计均匀、只有 coarse-march
   residual 变化”的判别 fixture。

本卡只修测试证据与 JVM 参考成本模型，不改生产分配公式；第 3 条要求已由现有逐像素
`coarseResidual` 实现满足，并由新 fixture 证明。

## 精确成本核算

`ssr-adaptive.frag` 的两阶段结构（`src/main/resources/shaders/postprocess/ssr-adaptive.frag`）：

```glsl
marchReflection(worldPosition, reflected, floorSteps, ...);   // 总是执行
int budget = clamp(max(tileBudget, pixelBudget), floorSteps, ceilingSteps);
if (budget > floorSteps) {
    marchReflection(worldPosition, reflected, budget, ...);   // 仅 extra 像素
}
```

debug alpha 只暴露最终预算 `b`（`alpha = b / maximumSteps`），不暴露两次 march 的总和。
因此对每个 eligible 像素，精确 march 采样数是

```
spent(i) = floor + (b(i) > floor ? b(i) : 0)
```

对全帧求和：

```
totalSpent = Σ b(i) + floor × E
E = #{i : b(i) > floor}
```

`mean(b) × N = Σ b`，所以固定均值 control 的缺口正好是 `floor × E`：每个 extra 像素少算
一次 floor。两个 control 都不使用这个均值：

- **Control 1（两层精确混合）**：固定 floor pass 与固定 worst-case pass
  `fixed(floor + ceiling)` 按权重

  ```
  w = (totalSpent - floor × N) / (ceiling × N)
    = extraSum / (ceiling × N)
  ```

  混合。混合成本

  ```
  (1 - w) × floor × N + w × (floor + ceiling) × N
      = floor × N + extraSum = totalSpent
  ```

  精确相等。混合图是两个真实固定 pass 的线性组合，不是第三次 shader 采样。
- **Control 2（等均值固定预算）**：`B = round(totalSpent / N)`，并显式断言
  `|B × N - totalSpent| <= N / 2`；这是“同样平均成本”的固定 pass，预算差被单独记录，
  不用它冒充精确匹配。

**二分 refine**：命中后 `SSR_REFINE_STEPS = 4` 次二分在 adaptive 与所有 fixed control 中
都存在，且每次命中最多 4 个 tap；它是对称、有界的项，不进入 debug march 预算。成本匹配
针对两次 march 的采样数，refine 项两边同阶，因此不改变 control 的公平性。

**early-out**：背景/天空、roughness 超阈值、`nDotV <= 0.05` 的像素在 debug 模式下 alpha
仍写 1.0，但实际 0 步。测试用 CPU eligibility mask（depth、roughness、oct normal、
nDotV）只统计真正进入 march 的 eligible 像素。

### 实测成本（floor+wall fixture，96×96，默认 8/32/8）

| 量 | 值 |
|---|---:|
| eligible N | 4384 |
| extra E（`b > 8`） | 1370 |
| `Σ b`（debug final budgets） | 67952 |
| `floor × E` | 10960 |
| 精确 `totalSpent` | **78912** |
| worst case `(8+32) × N` | 175360 |
| 混合权重 `w` | 0.3125 |
| 等均值固定预算 `B` | 18 |
| `B × N - totalSpent` | **0** |

恒等式断言：`78912 - 67952 = 10960 = 8 × 1370`；旧均值 control 会少花这 10960 个样本。

### 质量结果（oracle = fixed(64)）

| 区域 | adaptive | floor(8) | 两层混合 control | 等均值 fixed(18) |
|---|---:|---:|---:|---:|
| 反射区（752 px） | **0.035359** | 0.415163 | 0.293014 | 0.084528 |
| hard 区（688 px，`b = 32`） | **0.032809** | 0.447943 | 0.315923 | 0.090291 |

断言：反射区 adaptive `<= floor`、`<= 两层混合`、`<= 等均值`；hard 区 adaptive 严格低于
三者。`extra = 1370 < 3N/4`，`0 < w < 1`，因此：

- **全 floor 的 no-op**：`extra = 0`，`w = 0`，hard 区为空；`extra >= 20`、`w > 0` 和
  hard 严格增益都会失败。
- **全 ceiling 的 overspend**：`extra = N`，`w = 1`；`extra < 3N/4`、`w < 1` 失败，且
  `fixed(40)` 混合 control 的 hard 质量高于 adaptive 的 32 步，严格增益失败。
- **预算与误差无关的分配**：hard 区不再由 `b = 32` 的像素组成，hard 严格增益失败。

## Residual-only fixture

### 为什么不能使用“全屏 normal/roughness 完全相同”

SSR 的命中权重含 `facing = clamp(-dot(hitNormal, reflected), 0, 1)`。对可见接收面
`N·toCamera > 0`，反射方向 `R = reflect(-toCamera, N)` 满足

```
dot(N, R) = -dot(N, -toCamera) = dot(N, toCamera) > 0
```

若命中面与接收面使用同一个 `N`，则 `facing < 0`，命中权重恒为 0，oracle 不会产生任何
反射颜色。**字面意义上的全屏 uniform normal 不可能同时产生可测的反射质量差异**。因此
fixture 必须有一个 normal 不连续面；为了让 tile-only 规则仍停在 floor，这个面必须让
production tile term 的四个 probe 全部看不到。

### Fixture：probe-blind 薄遮挡条

`thinOccluderFixture`（96×96，`SsrAdaptiveSamplingGlTest`）：

- 解析式地板：`normal = (0,1,0)`，`roughness = 0.05`，深色；天空 depth = 1。
- 三像素宽、camera-facing 的遮挡条：屏幕列 **71..73**，view depth **7.0**，
  `normal = (0,0,1)`，`roughness = 0.05`，亮红色。它是唯一的 depth/normal 不连续面。
- tile probe 列是全局 `x % 8 == 2` 或 `6`；71/72/73 的余数是 7/0/1，**四个 probe 永远
  不采样遮挡条**。遮挡条偏离屏幕中心，使更浅、未被遮挡条替换的地板像素仍能把反射射线
  送进它。
- 结果：production `tileErrorEstimate()` 在每个 tile 都只看到 uniform 地板
  normal/roughness，tile 预算恒为 floor；只有逐像素 coarse-march residual 能给出额外预算。

### (a) tile-only 策略停在 floor

- 144 个 tile 全部 `tileErrorEstimate() == 0`（CPU 独立复算，容差 `1e-6`）；84 个 tile
  有 ≥2 个 foreground probe。
- 每个 tile 的四个 foreground probe 的 normal/roughness 完全一致；`assertOccluderIsProbeBlind`
  证明遮挡条列不与 probe 列重合，且遮挡条本身是 eligible、facing 的表面。
- 独立公式 `referenceBudgetFor(0) = minimumSteps`；因此只使用 tile term 的策略在整帧
  分配 floor，不可能解释任何额外采样。

### (b) 只有高 residual 像素升预算

CPU 独立复算 `marchReflection()` 的 8 步 coarse residual（最大正 depth jump +
crossing screen step）：

| 分类 | 像素数 | 实测分配 |
|---|---:|---|
| residual `<= 0.09`（明显低于 0.10 ramp） | 4520 | 全部 floor，0 例外 |
| residual `>= 0.15`（明显高于第一个 extra 步） | 511 | 全部 `> floor`，0 例外 |
| eligible 合计 | 5031 | extra = 511（10.2%） |

两处 margin 避开 CPU double 与 GPU float 的边界差异；分类不是用 GPU 预算反推，而是独立
coarse-march 参考。

### (c) adaptive 比 floor 更接近高样本 oracle

- oracle：`fixed(64)`；floor：`fixed(8)`。
- oracle 反射区 29 px；residual-high ∩ 反射区 = **26 px**。
- 平均 RGB 误差（相对 oracle）：adaptive **0.007466**，floor **0.193292**；adaptive 约低
  25.9 倍。断言 `adaptiveError < floorError - 1e-6`。

## JVM 参考的成本模型修正

`AdaptiveSamplingReference` 也有同类成本核算缺陷：旧 `totalCost` 对每个像素都加
`minimumSteps + budget`（floor-only 像素多算一次 floor），`fixedBudgetForSameCost` 又返回
`meanCost - minimumSteps`，把 fixed pass 的 `uStepCount` 当成“floor 之上的 extra”。现改为：

- `totalCost` = `minimumSteps + (budget > minimumSteps ? budget : 0)`，与 shader 两阶段一致；
- `fixedBudgetForSameCost` = `round(mean exact cost)`，直接是 fixed pass 的单次 march
  `uStepCount`，不再减 floor。

稀疏难例 fixture（64 cell：56 easy 预算 8、8 hard 预算 56）：

| 量 | 修正前 | 修正后 |
|---|---:|---:|
| 总成本 | 1408 | **960** |
| 固定 control 预算 | 14（实际只花 896） | **15（实际花 960）** |
| adaptive 模型误差 | 5.25 | **5.25** |
| fixed 模型误差 | 6.14 | **5.91** |
| adaptive/fixed | — | **≈ 0.889** |

新增 `floorOnlyAllocationPaysTheFloorOnce`：全 floor 的 64 像素总成本是 `64 × 8 = 512`
（旧模型会算成 1024），cost-matched fixed 预算为 8。`AdaptiveSamplingReferenceTest` 现为
**6 tests**；`Adaptive*` JVM 合计 **23 PASS**。该模型仍是误差曲线模型，不是 GPU 实测。

## 剩余限制

1. **GL 只在一个设备上执行**：RTX 3050 Laptop / 576.88；其他驱动/GPU 的 float 边界未覆盖。
2. **refine 未计入精确成本**：每命中最多 4 个 tap，adaptive 与 fixed 对称；它不是 debug
   march 预算的一部分，因此成本匹配是 march 采样数意义下的精确匹配，不是总指令数/耗时。
3. **两层混合 control 是图像线性组合**：它对应“floor 与 worst-case 两个真实 fixed pass 的
   成本加权”，不是第三个已实现的采样策略；等均值 fixed pass 是第二个真实 control，但其
   预算被显式记录为 `round(total/N)`，差值为 0（本 fixture）。
4. **residual-only fixture 的遮挡条是受控的 depth-only billboard**：它在物理上不是一致的
   几何（屏幕列固定 depth），目的是构造“tile probe 看不到、coarse march 能看到”的最小
   facing 不连续面；不能当作真实场景的材质/几何样本。
5. **tile 项仍是 per-fragment 重复计算**：没有 GPU 归约或共享预算纹理；本卡只证明分配与
   质量，不证明性能。
6. **未做 GPU 计时**：性能与“adaptive 更快”仍为 `NOT_EVALUATED`；两阶段最坏成本
   `8+32+4` 高于固定 `32+4`。
7. **JVM 参考是模型**：5.25 vs 5.91 是确定性误差曲线，不是像素实测；像素证据以 GL case 为准。
8. **`uBudgetDebug` 仍是测试诊断**：生产 alpha 恒 1.0；early-out 像素在 debug 下 alpha
   也是 1.0，测试用 CPU eligibility 排除。
9. **状态/交付文档未在本 worker 更新**：`docs/planning/haikalat-multi-agent-status.json`
   里 “adaptive model error 5.25 vs fixed 6.14 / 1408-sample” 是修正前模型的证据，已被
   本卡的 960-sample / 15-step 结果取代；`v0.28.1-delivery-matrix.md` 的 #41 `PARTIAL`
   与 per-feature 的 22/31、9/9 计数也需由 Integrator 在本卡合入后重算。
10. **旧 mean control 不再保留为 case**：它已被成本匹配 case 取代；均值缺口的数学关系由
    `totalSpent - Σb = floor × E` 的精确断言记录，而不是继续保留一个有缺陷的对照。
