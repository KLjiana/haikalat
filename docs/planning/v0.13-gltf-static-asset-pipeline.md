# v0.13 glTF 2.0 静态资产管线实施计划

> 已归档：v0.13 历史实施与验收记录，不再作为当前待办。

> 状态：已完成并通过人工验收（2026-07-18）
> 目标版本：`0.13.0`  
> 基线版本：`0.12.0`  
> 版本主题：把已经完成的 metallic-roughness PBR 接入现代静态资产主路径  
> 核心原则：完整支持一条可验证的 `.gltf/.glb → CPU scene asset → GPU resources → SceneObject → PBR pipeline` 链路，不在本版本引入动画系统。

## 1. 版本目标

v0.12 已经完成 opaque metallic-roughness、tangent、HDR cubemap、GPU IBL、阴影和后处理闭环，但内容仍主要由 OBJ、`.properties` 和手工纹理角色装配。v0.13 的目标是让框架能够直接加载一个符合约定的 glTF 2.0 静态场景，并保留它的节点层级、mesh primitive、PBR 材质、纹理、sampler 和共享关系。

完成后，用户应能够：

1. 从 classpath 或显式资源根目录加载 `.gltf` 和 `.glb`；
2. 使用外部 buffer/image、data URI 和 GLB embedded BIN/image；
3. 加载默认 scene、node hierarchy、TRS/matrix 和多 primitive mesh；
4. 将 glTF metallic-roughness 材质映射到 v0.12 PBR contract；
5. 自动处理缺失 normal/tangent 的静态三角网格；
6. 复用同一 mesh/material/image/sampler，而不是按 node 重复上传；
7. 把加载结果实例化为现有 `SceneObject`，继续使用阴影、IBL、HDR、Bloom、曝光、AA 和 UI；
8. 在加载失败时获得包含 JSON path、对象索引和资源 URI 的明确错误；
9. 通过纯 JVM、真实 GL、deterministic integration 和性能基线证明整条链路。

版本完成定义：

> 一个同时包含 node hierarchy、多 mesh primitive、共享 mesh、embedded/external image、metallic-roughness 材质和缺失 tangent 的静态 glTF/GLB 资产，可以从 classpath 加载并在现有 PBR pipeline 中正确受光、投射阴影、响应 IBL 和后处理；加载、上传、失败清理和重复关闭均有自动化证明。

只有“Assimp 能打开 glTF”或“Demo 中手工提取一个 mesh”不算完成。

## 2. 当前架构事实与设计约束

实施必须尊重当前边界：

- `ModelAssetLoader` 和 `LoadedModel` 只表示 `List<MeshData>`；
- OBJ 是 geometry-only 主路径，不能表达 glTF node、material、image 和 sampler；
- `SceneAssetConfig.object.*` 使用一个外部 model 加一个外部 material，也不能表达 glTF 内部材质分配；
- `MeshData` 是纯 JVM 几何，`Mesh` 是显式拥有的 OpenGL 资源；
- `MaterialDef` 是无 GL 配置，`Material`/`MaterialInstance` 是 OpenGL runtime material；
- PBR shader contract 已经冻结 texture unit、factor、tangent layout 和 HDR/ACES 前置条件；
- `SceneObject.ModelUpdater` 可以输出任意 `Matrix4f`，足以承载静态 glTF world transform；
- `RenderPipeline` 已经验证 PBR mesh canonical layout；
- glTF asset loading 不应进入 RenderGraph，RenderGraph 只处理逐帧 pass 和 render target；
- backend 不得依赖 glTF/core/subsystem；
- OpenGL 资源创建和上传必须发生在拥有当前 context 的 render thread；
- CPU 解析必须能够在无 GL context 的 JVM 测试或后台准备线程执行。

因此本版本不修改 `LoadedModel` 的含义，也不把 glTF 场景强行伪装为 OBJ。新增一条 richer scene-asset 路径，并让两条路径在 `MeshData`、`Material` 和 `SceneObject` 处汇合。

## 5. 总体数据流

```text
ResourceLocator + AssetRef
          |
          v
   GltfDocumentReader
   (.gltf / .glb)
          |
          v
 JSON schema DTO + raw chunks
          |
          v
  GltfSceneDecoder (pure JVM)
   | buffers/accessors/images
   | nodes/materials/primitives
   | normal/tangent generation
          |
          v
      LoadedGltfScene
   (no OpenGL resources)
          |
          v render thread/current context
   GltfSceneUploader
   | Texture2D / Sampler
   | Material / MaterialInstance
   | Mesh
          |
          v
      GltfSceneAsset
   (owns runtime resources)
          |
          v
 instantiate(root transform, castShadows)
          |
          v
   List<SceneObject> -> Scene -> RenderPipeline
```

解析和上传是两个明确阶段。纯 JVM 阶段不得调用 LWJGL OpenGL API；上传阶段不得重新解析 JSON 或重复解码 accessor。

## 6. 公共类型与兼容性

### 6.1 保留现有接口

以下定位不变：

- `ModelAssetLoader`：geometry-only loader；
- `LoadedModel`：一个或多个 `MeshData`；
- `ObjModelLoader`：OBJ 主路径；
- `AssimpModelLoader`：实验入口；
- `SceneAssetConfig.model.*`/`object.*`：外部 geometry + manifest material 的简单场景便利格式。

不把 `.gltf/.glb` 注册到现有 `ModelAssetManager`，因为这会丢失 node 和 material 语义。

### 6.2 CPU 资产 API

新增 package `core.assets.gltf`，稳定入口：

```java
public final class GltfAssetLoader {
    public GltfAssetLoader(ResourceLocator locator);
    public LoadedGltfScene load(AssetRef ref);
    public LoadedGltfScene load(AssetRef ref, GltfLoadOptions options);
}
```

```java
public record GltfLoadOptions(
        SceneSelection scene,
        boolean strictExtensions,
        GltfAssetLimits limits
) {
    public static GltfLoadOptions defaults();
}
```

```java
public sealed interface SceneSelection {
    record Default() implements SceneSelection {}
    record ByIndex(int index) implements SceneSelection {}
    record ByName(String name) implements SceneSelection {}
}
```

`LoadedGltfScene` 是纯 JVM immutable owner，至少暴露：

- source `AssetRef`；
- selected scene index/name；
- root node indices；
- immutable nodes；
- immutable mesh primitives；
- immutable material definitions；
- decoded image payloads；
- sampler definitions；
- warnings；
- aggregate statistics。

内部 JSON DTO 不公开。buffer/accessor 原始结构只在 decoder 内部存在，不进入稳定 API。

### 6.3 Runtime 资产 API

新增 package `subsystems.render3d.gltf`：

```java
public final class GltfRuntimeLibrary implements AutoCloseable {
    public static GltfRuntimeLibrary create();
}
```

library 拥有并共享：

- built-in PBR shader；
- PBR fallback textures；
- default samplers；
- glTF shader contract metadata。

```java
public final class GltfSceneAsset implements AutoCloseable {
    public static GltfSceneAsset upload(
            LoadedGltfScene source,
            GltfRuntimeLibrary library);

    public List<SceneObject> instantiate(
            Matrix4fc rootTransform,
            boolean castShadows);

    public GltfSceneStatistics statistics();
}
```

ownership 固定为：

- `GltfRuntimeLibrary` 由应用拥有；
- `GltfSceneAsset` 借用 library，拥有自身 mesh、material、image texture variant 和非默认 sampler；
- `SceneObject` 借用 `GltfSceneAsset` 的 mesh/material；
- 关闭顺序为 pipeline → scene asset → runtime library；
- pipeline 不关闭任何 glTF 资源；
- scene asset 关闭后由它创建的 `SceneObject` 不得继续渲染；
- runtime library 在仍有 scene asset 存活时 close 必须失败，而不是提前删除共享 shader/fallback。

第一版使用 library 的显式 active-asset 计数保护生命周期，但不建设通用引用计数资源框架。

### 6.4 PBR texture binding 扩展

glTF sampler 属于 texture binding，而不是 image。扩展 `PbrMaterials`，保留现有 overload，并新增：

```java
public record PbrTextureBinding(Texture2D texture, Sampler sampler) {}

public static Material create(
        ShaderProgram shader,
        PbrMaterialProperties properties,
        Map<PbrTextureRole, PbrTextureBinding> bindings,
        PbrFallbackTextures fallbacks);
```

旧 `Map<PbrTextureRole, Texture2D>` API 继续使用 fallback/default sampler，保持源码兼容。

### 6.5 Vertex color contract

PBR vertex shader新增可选 location `4`：

```text
location 0 POSITION vec3
location 1 TEXCOORD_0 vec2
location 2 NORMAL vec3
location 3 TANGENT vec4
location 4 COLOR_0 vec4（可选）
```

glTF material instance 使用 `uHasVertexColor`。有 COLOR_0 时 base color 乘 vertex color；没有时不读取 location 4。现有 OBJ PBR layout 保持 `0..3`，不用追加白色 attribute。

PBR instancing 仍非目标。若后续支持带 vertex color 的 PBR instancing，instance base 至少为 5，本版本只锁定冲突检测。

## 7. JSON 与 GLB 解析

### 7.1 JSON 实现

引入 Jackson `jackson-core`，固定使用 streaming parser，并启用 strict duplicate detection。不得手写字符串拆分 JSON，也不引入/暴露 Jackson tree node。

只增加满足 glTF 解析的最小依赖；不引入完整外部 game asset framework。

### 7.2 GLB 验证

GLB reader 必须验证：

- magic 为 `0x46546C67`；
- version 为 `2`；
- header length 与实际字节长度一致；
- chunk header 不越界且使用 little-endian；
- 第一个 chunk 为 JSON；
- 最多一个 BIN chunk；
- JSON/BIN chunk 4-byte aligned；
- JSON padding 只允许 space/NUL；
- unknown chunk 按规范跳过并记录 warning；
- declared buffer byteLength 不超过 BIN payload；
- 所有长度计算使用 `long` 和 overflow-safe 检查。

错误包含 source path、chunk index/type 和 byte offset。

### 7.3 `.gltf` JSON

验证 `asset.version` 的 major 为 2。`minVersion > 2.0` 时失败。顶层缺失 required array 时根据实际引用报错，不要求存在未使用的可选字段。

JSON duplicate key 默认失败，防止不同 parser 行为导致资产解释不一致。

## 8. URI 与 ResourceLocator

### 8.1 相对资源解析

扩展 `ResourceLocator`：

```java
public AssetRef resolveRelative(AssetRef owner, String uri);
```

规则：

- URI 使用 `/` 分隔；
- percent decode 只执行一次；
- query/fragment 不参与本地资源寻址，出现时失败；
- `.` 正常归一化；
- `..` 不得逃出 owner 所在资源根；
- absolute filesystem path 只有显式 root policy 允许时可用；
- 禁止 `http`、`https`、`file` 和其他 scheme；
- classpath owner 的相对资源继续从 owner 目录解析；
- filesystem owner 必须保持在匹配的 configured root 内；
- Windows drive/UNC 不得通过 URI 文本绕过 root 检查。

### 8.2 Data URI

支持：

- `data:application/octet-stream;base64,...`；
- `data:application/gltf-buffer;base64,...`；
- `data:image/png;base64,...`；
- `data:image/jpeg;base64,...`。

只支持 base64 payload。错误的 padding、非法字符、mime 与 image signature 不一致均失败。decode 前根据 limits 检查预计大小，避免先分配超大数组。

## 9. 安全与容量限制

`GltfAssetLimits.defaults()` 固定默认值：

| 项目 | 默认上限 |
| --- | ---: |
| JSON/GLB 文件 | 64 MiB |
| 所有 decoded buffer 总计 | 512 MiB |
| 单 image encoded payload | 64 MiB |
| node | 100,000 |
| mesh | 50,000 |
| primitive | 100,000 |
| material | 16,384 |
| texture/image/sampler 各自 | 16,384 |
| accessor | 200,000 |
| 单 primitive vertex | 16,777,216 |
| 单 primitive index | 50,000,000 |
| node hierarchy depth | 256 |
| data URI decoded 总计 | 256 MiB |

所有 count、offset、stride、element size、总字节数使用 overflow-safe 算术。越界错误包含 limit 名、实际值和 JSON path。

## 10. Buffer、bufferView 与 accessor

### 10.1 Buffer

- `.gltf` buffer 必须有 URI；
- GLB 第一个无 URI buffer 使用 BIN chunk；
- URI buffer 实际大小至少为 declared `byteLength`；
- 多出的 padding 可以忽略；
- 同 URI 只读取一次；
- buffer payload 在 `LoadedGltfScene` 完成解码后不保留无用副本。

### 10.2 BufferView

验证：

- buffer index 合法；
- byteOffset/byteLength 非负；
- range 不越界；
- byteStride 为 4～252 且 4-byte multiple；
- accessor element 不跨 stride；
- image bufferView 不与 accessor解释混淆；
- target 仅作为 hint，不决定数据是否可读。

### 10.3 Accessor

支持 component type：

- `BYTE`；
- `UNSIGNED_BYTE`；
- `SHORT`；
- `UNSIGNED_SHORT`；
- `UNSIGNED_INT`；
- `FLOAT`。

支持 type：`SCALAR`、`VEC2`、`VEC3`、`VEC4`、`MAT4`。本版本只在实际语义允许的位置消费这些类型。

decoder 统一输出 framework canonical float/int arrays，不把 quantized/interleaved storage 原样上传。normalized integer 按 glTF 规则转换；signed minimum 必须 clamp 到 `-1`。

验证：

- accessor/bufferView offset alignment；
- component/type 与 semantic 匹配；
- count 合法；
- range 不越界；
- indices 必须 SCALAR unsigned integer；
- index 小于 vertex count；
- finite POSITION/NORMAL/TANGENT/UV/COLOR/matrix；
- POSITION accessor min/max 若提供必须 finite、维度正确并包围实际数据；
- sparse count 不超过 accessor count；
- sparse index strictly increasing、无重复、无越界；
- sparse values 范围合法；
- accessor 无 base bufferView 时先以零初始化再应用 sparse。

## 11. Mesh 解码与 canonical layout

### 11.1 Primitive 模式

只接受 `mode=4 TRIANGLES` 或缺省 mode。POINTS、LINES、LINE_LOOP、LINE_STRIP、TRIANGLE_STRIP、TRIANGLE_FAN 明确失败，不在 importer 中隐式拓扑转换。

每个 primitive 独立生成一个 `MeshData`。name 使用稳定格式：

```text
<assetName>/mesh[<meshIndex>]:<meshName>/primitive[<primitiveIndex>]
```

错误和 debug label 使用同一名称。

### 11.2 POSITION

POSITION 必须存在、为 `FLOAT VEC3`、finite。空 primitive 失败。不同 attribute accessor count 必须一致。

### 11.3 NORMAL

如果存在 NORMAL：

- 转换为 float vec3；
- 拒绝零长度和 non-finite；
- normalize 后写入 canonical buffer。

如果缺失 NORMAL，使用新增纯 JVM `NormalGenerator`：

- indexed/non-indexed triangles；
- 按 triangle area-weighted 累加；
- 退化 triangle 不贡献；
- 无任何有效贡献的 vertex 使用确定性 `(0,0,1)` fallback 并计数；
- 输出 finite unit normal；
- 不修改输入 POSITION/indices；
- hard edge 由资产通过顶点拆分表达，loader 不猜测 smoothing group。

### 11.4 TEXCOORD_0

支持 float 或 normalized unsigned integer `VEC2`。如果 material 引用任何 texture，TEXCOORD_0 必须存在；如果 factor-only material 没有 TEXCOORD_0，loader 填充 `(0,0)`。

任何 textureInfo 的 `texCoord != 0` 明确失败。

### 11.5 TANGENT

如果存在 TANGENT：

- 必须可转换为 float `VEC4`；
- xyz finite nonzero；
- w 只能为接近 `-1/+1` 的 finite 值，归一为符号；
- tangent 对 normal Gram–Schmidt 正交化。

如果缺失：

- 有 UV 时复用 `TangentGenerator`；
- factor-only 且缺 UV 时先填零 UV，再由退化 fallback 生成确定性 tangent；
- mirrored UV handedness 保留；
- fallback 数量进入 asset warnings/statistics。

### 11.6 COLOR_0

支持 `VEC3/VEC4` float 或 normalized unsigned byte/short。VEC3 alpha 补 1。值 clamp 到 `0..1`，non-finite 失败。

glTF 定义 vertex color 为线性值，不做 sRGB decode。primitive 记录 `hasVertexColor`，runtime material instance 设置 `uHasVertexColor`。

### 11.7 Indices

- indexed primitive 保留 `UNSIGNED_BYTE/SHORT/INT` 的值语义，但转换为当前 `MeshData int[]`；
- non-indexed primitive 允许直接 draw；
- triangle index count 必须为 3 的倍数；
- winding 保留 glTF CCW；
- index 越界立即失败。

## 12. Node hierarchy 与 transform

### 12.1 结构验证

- scene/node/child index 必须合法；
- selected scene 内 node 不得形成 cycle；
- 同 node 在 selected scene 内不得有多个 parent；
- duplicate child 失败；
- depth 超过 limit 失败；
- selected scene 不可达的 node 不上传 mesh，但仍可在 CPU statistics 中记录；
- 一个 node 可以没有 mesh；
- node 引用 skin、camera 或 morph weights 时按非目标规则失败或警告。

### 12.2 Local matrix

node 提供 `matrix` 时不得同时提供 TRS。TRS 顺序固定为：

```text
local = Translation * RotationQuaternion * Scale
```

缺省 translation `(0,0,0)`、rotation `(0,0,0,1)`、scale `(1,1,1)`。quaternion finite 且长度非零，normalize 后使用。matrix/TRS 结果必须 finite。

world matrix：

```text
world(node) = world(parent) * local(node)
```

实例化 root transform：

```text
model = rootTransform * world(node)
```

每个 mesh primitive 生成一个 `SceneObject`，同 node 的 primitives 共享 model updater 中的 immutable matrix snapshot。

### 12.3 Mirrored transform

负 determinant node 必须保持正确正面和 tangent handedness：

- PBR vertex shader 的 bitangent handedness 乘 `sign(determinant(mat3(uModel)))`；
- single-sided material 的 front-face orientation 随 determinant 切换；
- double-sided material 禁用 culling；
- normal matrix 继续使用 inverse-transpose；
- singular transform 在 scene upload/instantiate 阶段失败，错误包含 node path。

为此补齐 typed raster state：

- `CullMode.NONE/BACK`；
- `FrontFace.CCW/CW`；
- `CommandBuffer.frontFace(...)`；
- `StateCache` 缓存 `glFrontFace`；
- `Material.Builder.cullMode(...)`，现有 material 默认 `NONE` 以保持 v0.12 视觉兼容；
- glTF single-sided material 显式使用 `BACK`，double-sided 使用 `NONE`；
- `RenderPipeline` 在得到每次 draw 的 model matrix 后计算 determinant：非负为 CCW、负数为 CW；
- PBR material 增加 `uDoubleSided`，只在该值为 1 且 `!gl_FrontFacing` 时翻转 shading normal；
- material/draw binding plan 能提交 double-sided 与 mirrored front face。

不通过 `custom()` 修改 front face。

## 13. glTF Material 映射

### 13.1 Default material

primitive 没有 material 时使用 glTF default：

- base color `(1,1,1,1)`；
- metallic `1`；
- roughness `1`；
- emissive `(0,0,0)`；
- opaque；
- single-sided；
- fallback textures。

注意 glTF default metallic 为 1，与框架 `PbrMaterialProperties.defaults()` 当前 metallic 0 不同。importer 必须显式创建 glTF default，不能直接复用 framework defaults。

### 13.2 Factor 与纹理

映射：

| glTF | Haikalat |
| --- | --- |
| `baseColorFactor` | `uBaseColorFactor` |
| base color image | `BASE_COLOR`，sRGB |
| `metallicFactor` | `uMetallicFactor` |
| `roughnessFactor` | `uRoughnessFactor` |
| metallicRoughness image | `METALLIC_ROUGHNESS`，linear，G/B |
| normal image + scale | `NORMAL` + `uNormalScale` |
| occlusion image + strength | `OCCLUSION` + `uOcclusionStrength` |
| emissive image/factor | `EMISSIVE` + `uEmissiveFactor` |

factor validation与 v0.12 一致。baseColor alpha 在 OPAQUE 路径中保留但不启用 blending。

### 13.3 Alpha

接受 `alphaMode=OPAQUE`（含缺省）和 `MASK`。MASK 保留 `alphaCutoff`，颜色 pass 在 PBR
base-color 与 vertex-color 相乘后执行 alpha test。由于 directional shadow depth shader 尚未
绑定 base-color texture，含 MASK 的资产只允许 `castShadows=false`，否则 instantiate fail-fast。
`BLEND` 仍明确失败；本版本不引入透明排序或混合材质路径。

### 13.4 Double-sided

`doubleSided=false` 使用 back-face culling；`true` 禁用 culling。double-sided fragment 的 normal 在 back face 使用 `gl_FrontFacing` 翻转，使直接光和 IBL 方向一致。

### 13.5 Unsupported extensions

material 中出现以下扩展默认失败：

- unlit；
- clearcoat；
- transmission/volume；
- sheen；
- specular/ior；
- emissive strength；
- iridescence；
- anisotropy；
- texture transform。

错误必须指出 extension 名、material 和后续支持版本未承诺，不能静默丢弃后继续宣称材质正确。

## 14. Image、texture 与 sampler

### 14.1 Image decode

扩展 `Texture2D` 或新增 backend image upload factory，支持从 encoded `byte[]/ByteBuffer` 解码 PNG/JPEG。要求：

- 使用 STB memory decode；
- 不依赖全局 flip 状态；glTF image 不垂直翻转；
- mime 与 signature 交叉验证；
- 强制 RGBA8 upload 可接受，原 channel count 只用于统计；
- sRGB role 使用 `SRGB8_ALPHA8`；
- linear role 使用 `RGBA8`；
- mip chain 完整生成；
- decode/upload 中途失败释放 native/GL 资源；
- 错误包含 image index/name/source URI。

### 14.2 Texture variant cache

cache key：

```text
(imageIndex, TextureColorSpace)
```

同一 image 同时作为 base color 和 metallic-roughness 使用时必须生成两份不同 internal format 的 texture。相同 image+colorSpace 被多个 glTF texture 使用时共享 GPU texture。

### 14.3 Sampler

完整映射 glTF：

- mag：NEAREST/LINEAR；
- min：NEAREST、LINEAR 和四种 mip filter；
- wrapS/wrapT：CLAMP_TO_EDGE、MIRRORED_REPEAT、REPEAT；
- 缺省 sampler 使用 LINEAR + mip linear + REPEAT；
- wrapR 对 2D texture 固定为 wrapT；
- 相同 descriptor 共享一个 `Sampler`；
- 非法 enum 失败；
- 需要 mip filter 的 image 必须有完整 mip chain。

sampler cache 属于 `GltfSceneAsset`；library 只拥有默认 sampler。

## 15. Runtime upload 与资源所有权

### 15.1 上传顺序

固定顺序：

1. 验证 runtime library/context；
2. 创建 sampler cache；
3. decode/upload image color-space variants；
4. 创建 materials；
5. 上传 unique primitives 为 `Mesh`；
6. 组装 node primitive references；
7. 构造 `GltfSceneAsset` 并移交 ownership。

创建任何资源后立即登记到 local owner；失败时逆序关闭。不得等全部成功后才登记。

### 15.2 去重

- 一个 glTF primitive 上传一次；
- 多 node 引用同 mesh 时共享 primitive `Mesh`；
- 一个 material 定义创建一个 `Material` template；
- 每个 node primitive 创建独立 `MaterialInstance`，用于 `uHasVertexColor` 等 primitive override；
- image variant 和 sampler 按 key 共享；
- default material 共享；
- `SceneObject` 不拥有资源。

### 15.3 Close

`GltfSceneAsset.close()`：

1. 标记 closed，阻止新 instantiate；
2. 逆序关闭 meshes；
3. 关闭 materials；
4. 关闭 non-default samplers；
5. 关闭 image textures；
6. 通知 runtime library active asset 减一；
7. 聚合 cleanup exception，后续异常 suppressed；
8. repeated close no-op。

即使某一 close 失败，也继续关闭剩余资源。上传失败遵循相同规则。

## 16. SceneAssetConfig 集成

现有 `model.*`/`object.*` 不改变。新增独立 glTF scene instance 字段：

```properties
gltf.showcase.path=/gltf/showcase.glb
gltf.showcase.scene=default
gltf.showcase.position=0,0,-3
gltf.showcase.rotation=0,0,0
gltf.showcase.scale=1
gltf.showcase.castShadows=true
```

规则：

- `path` 必填且 extension 为 gltf/glb；
- `scene` 可省略或为 `default`、非负 index、唯一 scene name；
- position/rotation 缺省为零；
- scale 缺省 1，必须 finite 且非零；允许负数用于显式镜像；
- castShadows 缺省 true；
- `gltf.*` 不引用外部 `material.*`，内部 material 由 glTF 决定；
- unknown `gltf.<name>.*` key 失败；
- glTF 实例名不得与 object 名冲突，避免调试 UI 歧义；
- config 解析只验证字段和 path extension，不读取或上传 glTF；
- Demo 资源装配阶段执行 CPU load 和 runtime upload。

新增 `SceneAssetConfig.GltfSceneDef`，但不把 glTF nodes 展开进 `.properties`。

## 22. 故障语义

统一异常 `GltfAssetException`，包含：

- source asset path；
- phase：READ/PARSE/RESOLVE/DECODE/UPLOAD/INSTANTIATE；
- JSON path 或 byte offset；
- node/mesh/primitive/material/accessor/image index；
- dependent URI；
- 原始 cause。

错误示例：

```text
Failed to decode glTF /gltf/showcase.glb at meshes[2].primitives[1].attributes.NORMAL:
accessor[17] range 4096..8192 exceeds bufferView[8] length 6144
```

不得把所有错误包装成“Failed to load model”。

故障注入点只在 test-visible package-private boundary 暴露，不进入 stable public API。

## 26. 风险与控制

### 风险 1：把 geometry loader 扩大成万能场景系统

控制：保留 OBJ/LoadedModel；glTF 使用独立 scene-asset DTO，最终只映射到现有 `SceneObject`，不引入 ECS。

### 风险 2：支持矩阵不断扩大

控制：本文件的正式范围即冻结合同；遇到 animation/compression/高级材质明确失败，不在实现中临时加半套支持。

### 风险 3：资源共享导致 ownership 不清

控制：library、scene asset、SceneObject 三层 ownership 固定；active-asset close guard 和 failure injection 覆盖。

### 风险 4：颜色空间和 sampler 造成“模型能画但材质不对”

控制：role-driven sRGB/linear variant、glTF sampler 映射、参考像素和同 image 双 color-space 测试。

### 风险 5：恶意或损坏资产触发越界/巨量分配

控制：统一 limits、long overflow-safe range、root-confined URI、decode 前大小验证。

### 风险 6：node 负缩放破坏 winding/TBN

控制：typed front-face state、determinant handedness、negative-scale pixel tests。

### 风险 7：Demo-only importer

控制：CPU loader/runtime asset 位于 main source set，Demo 只消费 public entrypoint；架构测试禁止 Demo 解析 JSON/accessor。
