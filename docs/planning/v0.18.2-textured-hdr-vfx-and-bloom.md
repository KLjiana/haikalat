# v0.18.2 纹理化 HDR VFX 与 Bloom 合成实施计划

> 状态：功能验收完成；正式发布被 `static-all-visible` 性能门禁阻塞
>
> 目标版本：`0.18.2`
>
> 基线版本：`0.18.1`
>
> 版本主题：在 v0.18.1 曲线与过渡能力之上，为 CPU VFX 建立正式的纹理材质、HDR 透明合成、场景深度交互和 Bloom 链路，并以经过筛选和审计的 VFX 贴图形成可见证明。

## 1. 版本定位

v0.18.1 已完成 `core.curve`、particle/Ribbon/Decal over-life、`BezierPath3f`、动画 cross-fade 和 layer fade。VFX 模拟层能够稳定、确定性地生成 size、color、rotation、width 和 scale，但 render3d adapter 仍只使用纯色 quad/cube：shader 没有 UV，不采样纹理，所有 primitive 使用同一 alpha blend 状态，并且 Showcase 当前在 tone mapping 之后的 overlay 阶段绘制 CPU VFX。

因此现有 VFX 即使输出大于 1 的 RGB，也不会进入 HDR Bloom 提取；新增的 fire、smoke、spark、flare、ring、slash 等贴图也没有正式的资源、颜色空间、遮罩通道和 GPU owner 合同。

v0.18.2 的主题是补齐这一条纵向路径：

```text
VFX 纯值材质与确定性 snapshot
        |
        v
render3d VFX texture/cache/shader adapter
        |
        v
HDR transparent composition
        |
        v
Bloom extraction/downsample/upsample
        |
        v
Tone mapping -> UI -> Present
```

本版本不是完整 VFX 编辑器，也不重写 GPU 粒子。目标是让少量经过许可审计的纹理真正进入项目现有资源生命周期、RenderGraph、HDR、Bloom、diagnostics 和自动验证合同。

## 2. 开工前置条件

### 2.1 v0.18.1 发布边界

实施开始时仓库为 `0.18.1-SNAPSHOT`，功能和本地 GL 验收已经完成，但 `static-all-visible` 结构化性能门禁尚未通过。原计划要求 v0.18.2 实施前二选一：

1. 解决或以可审计证据重新建立 v0.18.1 性能基线，完成正式 release commit/tag；
2. 明确取消独立 v0.18.1 发布，并将其完整候选作为 v0.18.2 的单一版本基线。

维护者于 2026-07-26 审批采用第二项：取消独立 v0.18.1 release commit/tag，将其完整候选作为
v0.18.2 的内部验收基线并最终一次提交。`build.gradle` 在完整 v0.18.2 `releaseReadiness`
完整候选形成前保持 `0.18.1-SNAPSHOT`；执行最终 `releaseReadiness` 时按门禁合同切换候选元数据为
`0.18.2`。两部分通过计划、测试和发布报告分别保留可审计边界；门禁失败时不得创建 release commit/tag。

### 2.2 功能基线

开始实现前必须确认：

- `compileJava demoClasses test` 通过；
- `publicApiGuard architectureGuard` 通过；
- `localGlVerification` 在有桌面的本机通过；
- v0.18.1 的固定 seed VFX snapshot、曲线、动画过渡和资源归零测试保持通过；
- 当前不带纹理的 `EffectAsset` 和 `VfxRenderer.record(...)` 行为作为 legacy 基线保留；
- Bloom 的 threshold、soft-knee、intensity 和 level 行为具有现有测试保护；
- RenderGraph attachment、resize、failure rollback 和 GL context epoch 合同不回退。

## 3. 总体目标

### 3.1 必须完成

1. 从当前 VFX 原始素材中筛选一个体积可控、许可证完整、用途明确的 runtime texture pack，禁止把全部原始素材直接打入 runtime JAR。
2. 建立无 GL 依赖的 `VfxMaterial` 纯值合同，至少支持纹理引用、遮罩来源、alpha/additive blend、emissive intensity、billboard 模式和 soft-particle 距离。
3. particle、Ribbon 和平面 Decal 支持纹理与 UV；未配置纹理时继续使用 legacy 白色 mask。
4. 正确处理两类现有素材：opaque grayscale PNG 使用 luminance/red mask，带透明通道的 light mask 使用 alpha mask。
5. 建立受控的 HDR transparent composition pass，使 VFX 在 tone mapping 之前写入 `RGBA16F`，并进入现有 Bloom 提取链路。
6. 自动曝光默认只观察基础场景，不因短生命周期高亮 VFX 产生明显 exposure pumping；Bloom 必须观察合成后的 VFX HDR 结果。
7. VFX 能依据场景深度完成遮挡和 soft-particle fade；MSAA 路径使用现有 typed depth blit 形成单采样深度，不使用 CPU readback 或 `CommandBuffer.custom()`。
8. 保持 UI 在 tone mapping/Bloom 之后绘制，VFX 泛光不能污染 UI 像素。
9. VfxDemo 和 HaikalatShowcaseDemo 至少提供 fire/smoke、magic impact 和 trail/slash 三类确定性证明。
10. 新纹理、shader、许可说明和转换记录全部通过 `assetManifestGuard`。

### 3.2 应当完成

- `VfxUvRegion` 与规则 sprite-sheet/flipbook 描述；
- camera-facing、Y-axis locked 和 velocity-aligned 三种 sprite orientation；
- 可限制的 velocity stretch；
- Ribbon 的 textured camera-facing segment 和 stretch/repeat UV；
- Bloom scatter 与高亮 clamp 设置；
- VFX material/texture switch、mask mode、HDR draw 和 soft-particle rejection 统计；
- 连续相同材质 primitive 的状态复用；
- grayscale/alpha mask 在 GPU 侧使用单通道 `R8`，避免每张遮罩固定占用 RGBA8；
- VFX fog influence，确保非纯发光 smoke 能与现有距离/高度雾协调。

### 3.3 明确非目标

v0.18.2 不做：

- VFX 节点编辑器、曲线编辑器、时间轴编辑器或 shader graph；
- JSON VFX 资产 schema、热重载或项目级资源数据库；
- GPU 粒子系统重写、GPU Ribbon tessellation 或 indirect VFX submission；
- Mesh particle、流体、碰撞、布料或物理驱动粒子；
- 真正的 deferred/projected decal；现有 Decal 继续是有方向的表面平面 quad；
- 屏幕空间 distortion、heat haze、lens dirt 或 anamorphic flare；
- 完整 Bloom 重构或独立 per-object bloom buffer；
- 将全部 207 MB 原始纹理打包发布；
- 使用缺少明确再分发许可证的 Luos/WrizFX 素材；
- AnimationGraph、状态机或新的骨骼动画功能；
- Vulkan、第二后端、ECS 或 Gradle 多模块拆分。

## 4. 当前实现与资源审计

### 4.1 Renderer 现状

当前 `VfxRenderer`：

- particle 与 Decal 使用 `BuiltinMeshData.coloredQuad(...)`；
- Ribbon 使用 colored cube，只能表达平均宽度；
- vertex shader 只有 position 和 `uMvp`；
- fragment shader 只输出 `uColor`；
- 全部 primitive 使用 `BlendMode.ALPHA`；
- 每个 primitive 单独提交 model matrix 和 color；
- 不持有 texture、sampler 或 texture cache；
- `EffectSnapshot` 只包含几何/颜色值，不包含 visual material identity。

这一实现适合作为 v0.18.0/0.18.1 的验证 adapter，但不足以承载贴图、HDR emissive、soft particle 或材质状态切换。

### 4.2 Bloom 现状

项目已有正式 Bloom 管线：

- HDR threshold extraction；
- soft-knee；
- 1～8 级 downsample；
- 多级 upsample；
- tone mapping 阶段 intensity 合成；
- RenderGraph pass timing 与真实 GL 测试。

因此 v0.18.2 不新增“VFX 专用模糊器”。正确做法是让 VFX 在 Bloom extraction 前进入 HDR scene color，并通过 material emissive intensity 控制是否超过 threshold。

### 4.3 新增素材盘点

当前 `src/main/resources/vfx` 约包含：

| 目录 | 文件数 | PNG | 约占用 | 当前结论 |
| --- | ---: | ---: | ---: | --- |
| `dev` | 476 | 474 | 15.68 MiB | Kenney CC0，可筛选使用 |
| `paricle` | 97 | 96 | 4.05 MiB | Kenney Particle Pack CC0，可筛选使用；正式路径需修正拼写 |
| `Luos_FreeGiveAway` | 56 | 56 | 83.11 MiB | 未随仓库提供明确许可证，禁止进入正式候选 |
| `Luos_Noise_V2` | 47 | 45 | 60.76 MiB | 未随仓库提供明确许可证，禁止进入正式候选 |
| `WrizFX` | 36 | 35 | 33.88 MiB | 只有来源 URL，不构成再分发许可，禁止进入正式候选 |

合计约 712 个文件、207 MB。它们目前位于 main resource root，若不处理会直接扩大 runtime JAR，并使逐文件资产 manifest 失控。

已确认可用的许可来源：

- Kenney Development Essentials 1.1：CC0；
- Kenney Light Masks 1.0：CC0；
- Kenney Particle Pack：CC0。

来源 URL 不是许可证。Luos/WrizFX 只有在补齐原始许可文本、版本/日期、再分发判断和用途后才能重新评估。

### 4.4 素材通道事实

`paricle` 中检查过的 fire、smoke、spark、flare、scorch 和 slash PNG 均为 512x512、alpha 固定为 255，视觉遮罩保存在灰度 RGB 中。它们必须使用 `LUMINANCE` 或明确的 `RED` mask，不能按 alpha 采样，否则整张 quad 都会不透明。

`dev/Light-Masks/transparent` 中的纹理则含有实际 alpha，应使用 `ALPHA` mask。`gradient-radial.png` 是 opaque grayscale，可作为 `LUMINANCE` mask。所有 mask 都是数据纹理，采样时不执行 sRGB decode。

## 6. 纯值材质合同

### 6.1 VfxMaterial

建议在 `subsystems.vfx` 增加无 GL 依赖的不可变类型：

```java
VfxMaterial fire = VfxMaterial.builder("fire")
        .texture(AssetRef.of("/vfx/particles/kenney/particle_pack/fire_01.png"))
        .maskMode(VfxMaskMode.LUMINANCE)
        .blendMode(BlendMode.ADDITIVE)
        .emissiveIntensity(5.0f)
        .billboardMode(VfxBillboardMode.CAMERA_FACING)
        .softParticleDistance(0.08f)
        .build();
```

第一版字段建议为：

- `name`：非空逻辑名；
- `texture`：可选 `AssetRef`；
- `maskMode`：`WHITE`、`ALPHA`、`RED`、`LUMINANCE`、`RGBA_COLOR`；
- `blendMode`：只允许 `ALPHA` 或 `ADDITIVE`；
- `emissiveIntensity`：有限、非负；
- `billboardMode`：`CAMERA_FACING`、`Y_AXIS_LOCKED`、`VELOCITY_ALIGNED`；
- `softParticleDistance`：0 表示关闭，大于 0 时使用世界/视图空间距离淡出；
- `alphaCutoff`：范围 `[0,1]`，默认 0；
- `velocityStretch` 与 `maximumStretch`：有限、有界；
- `fogInfluence`：范围 `[0,1]`，0 表示不受雾影响；
- `uvRegion` 或 sprite-sheet 描述。

材质只包含纯值和逻辑资源引用，不包含 `Texture2D`、`Sampler`、shader、OpenGL id、lambda 或 close callback。

### 6.2 遮罩语义

固定 mask 规则：

| 模式 | mask | RGB 语义 | 典型用途 |
| --- | --- | --- | --- |
| `WHITE` | 1 | tint | legacy 无纹理 |
| `ALPHA` | sampled alpha | tint | transparent light mask |
| `RED` | sampled red | tint | 单通道数据纹理 |
| `LUMINANCE` | grayscale/luminance | tint | opaque Kenney particle PNG |
| `RGBA_COLOR` | sampled alpha | sRGB decode 后的 sampled RGB × tint | 真正彩色 sprite |

mask 模式必须显式配置，不根据文件名或 alpha 是否全 255 在运行时猜测。资源导入测试可以给出建议，但正式 asset 是事实来源。

### 6.3 EffectAsset 与 snapshot

`EffectAsset.Builder` 增加按 primitive kind 的 visual 配置：

```java
builder.particleMaterial(fire)
       .ribbonMaterial(trail)
       .decalMaterial(scorch);
```

建议新增 `VfxVisualSet`，由 `EffectAsset` 持有并复制到 `EffectSnapshot`。同一个 snapshot 在 asset/instance 关闭后仍是完整纯值，不依赖 owner 的可变状态。

兼容要求：

- 未配置 material 时使用 `VfxMaterial.legacyAlpha()`；
- 保留现有 `EffectSnapshot` 四参数 convenience constructor；
- 保留现有 `ParticleEmitter`、`RibbonEmitter`、`Decal` record component；
- 保留现有 `VfxRenderer.record(commands, snapshot, projection, view)` overload，按 LDR legacy 模式执行；
- public 新类型默认登记为 `advanced`，不提前承诺 stable 二进制合同。

### 6.4 每实例数据

为支持 velocity aligned、stretch 和 flipbook，`ParticleSprite` 需要携带最小额外纯值：

- 当前 velocity；
- frame index 或归一化 flipbook progress；
- 可选 per-particle UV rotation/offset。

旧 constructor 继续存在并填入零 velocity、frame 0。新增字段必须防御性复制并验证有限值。第一版不增加每粒子随机 material、任意 shader parameter map 或脚本属性。

## 7. GPU 资源与纹理上传

### 7.1 VfxTextureCache

`VfxRenderer` 在 GL/render thread 创建并拥有内部 texture cache。cache key 至少包含：

- `AssetRef`；
- mask/color import profile；
- flip vertically；
- mipmap policy；
- wrap/filter policy。

同一路径以 `ALPHA`、`LUMINANCE` 或 `RGBA_COLOR` 导入时不能错误复用同一个 storage。关闭 renderer 时关闭全部 texture/sampler，失败时继续尽力关闭并聚合 suppressed exception。

`subsystems.vfx` 不得依赖该 cache；它只存在于 `subsystems.render3d.vfx` 或已有正式 texture asset adapter 边界。

### 7.2 单通道 mask

mask 上传路径建议：

1. 使用 STB 解码源 RGBA；
2. 按 material import profile 提取 alpha、red 或 luminance；
3. 上传为 `R8`；
4. 生成 mipmap；
5. sampler 使用 clamp-to-edge；
6. shader 统一从 `.r` 采样 mask。

`LUMINANCE` 对当前 grayscale 素材可直接使用任一相等 RGB 通道；对非灰度素材使用文档化的固定权重。mask 是线性数据，不执行 sRGB decode。`RGBA_COLOR` 才使用 sRGB storage。

缺失资源、零尺寸、超出尺寸上限、解码失败或不支持的通道必须在 renderer build/load 阶段明确失败，不静默替换为白色。只有 material 显式 `WHITE` 时才使用内部 1x1 white mask。

### 7.3 线程与 generation

- texture decode 可在未来异步执行，但 GPU 创建/替换只发生在 GL thread；
- v0.18.2 第一版可以同步 classpath decode，优先保证 owner 与失败语义；
- renderer close 后任何 record/load 调用失败；
- resize 不重新解码纹理；
- pipeline rebuild 不复制或泄漏 renderer-owned texture；
- 若后续接入资源 generation，过期 decode 结果必须在上传前拒绝。

## 8. Textured VFX Renderer

### 8.1 Shader 输入

新的 sprite shader 至少支持：

- position 与 UV；
- projection/view/model 或 billboard basis；
- tint 与 emissive intensity；
- mask mode；
- blend mode 所需输出语义；
- scene depth texture、viewport 与 inverse projection；
- soft-particle distance；
- alpha cutoff；
- sprite-sheet UV region；
- 可选 fog 参数。

legacy pure-color path 可以复用同一 shader 的 `WHITE` mask，但必须通过像素测试证明输出一致。

### 8.2 Alpha 与 additive 输出

两种 blend 不能共用错误的颜色预乘规则：

- `ALPHA` 使用 straight-alpha，pipeline state 继续为 `SRC_ALPHA / ONE_MINUS_SRC_ALPHA`；
- `ADDITIVE` 使用 `ONE / ONE`，shader 输出 RGB 必须显式乘以 mask、tint alpha 和 emissive intensity；
- 两种模式都关闭 depth write；
- soft fade 与 alpha cutoff 在 blend 前完成；
- 任何 shader 输出必须有限，HDR RGB 允许大于 1。

不在本版本新增 premultiplied alpha blend。若真实彩色素材出现明显边缘污染，再以独立像素证据评估。

### 8.3 Billboard

- `CAMERA_FACING`：使用 view inverse rotation，保持现有 particle 行为；
- `Y_AXIS_LOCKED`：仅绕世界 Y 轴面向相机，适合火焰和竖直烟柱；
- `VELOCITY_ALIGNED`：长轴沿屏幕投影速度方向，零速度时回退 camera-facing；
- `velocityStretch` 结果限制在 `[1, maximumStretch]`，不能因极端速度产生 NaN 或超大 quad；
- rotation over-life 在 billboard basis 之后应用，语义在三种模式中一致。

### 8.4 Ribbon

Ribbon 不再使用 colored cube 伪装为平均宽度线段。第一版使用 textured quad segment：

- 顶点在 start/end 之间插值；
- 两端分别使用 startWidth/endWidth；
- side vector 根据 segment direction 与 camera direction 计算；
- 退化方向使用稳定 fallback，不产生零矩阵；
- `STRETCH` UV 每段使用 `[0,1]`；
- `REPEAT` UV 根据累计路径长度和 repeat scale 计算；
- segment 仍按 snapshot sequence 和距离稳定排序。

本版本不进行 Catmull-Rom/Bezier GPU tessellation。平滑度继续由 CPU emitter point density 和 v0.18.1 路径控制。

### 8.5 平面 Decal

Decal 使用 textured quad、spawn normal、rotation 和 size，适合 scorch、magic circle 和 impact mask。它仍不读取 G-buffer，也不投影到任意曲面；文档和 UI 文案必须称为 surface quad decal，而不是 deferred decal。

soft depth 可以减少 z-fighting，但不能假装解决复杂曲面贴合。现有 0.004 normal offset 继续受测试保护。

### 8.6 排序与状态复用

现有 `transparentDrawOrder` 继续作为正确性事实来源：

- alpha primitive 保持远到近；
- additive 与 alpha 混排时不为减少 texture bind 任意重排；
- renderer 只合并或复用连续相同 material/texture/blend 的状态；
- 相同距离继续按 sequence/kind 稳定；
- 后续只有在独立 additive layer 明确不影响 alpha 结果时，才能评估材质分组或 instancing。

统计至少包含 draw calls、texture binds、material switches、alpha draws、additive draws、soft-particle draws 和 uniform/object payload bytes。

## 9. HDR Transparent Composition

### 9.1 当前问题

Showcase 当前通过 UI overlay recorder 在最终 backbuffer 上绘制 VFX。此时 tone mapping 和 Bloom 已经结束，造成：

- emissive RGB 大于 1 被 backbuffer 截断；
- Bloom 看不到 VFX；
- VFX 与自动曝光、fog、scene depth 没有正式关系；
- UI 和 VFX 共用 overlay 阶段，边界含糊。

### 9.2 目标 pass 顺序

建议固定顺序：

```text
Geometry
  -> MSAA Resolve / TAA
  -> Fog
  -> Base HDR color
       +-> Auto Exposure（只读取基础场景）
       +-> VfxHdrPass（复制基础 HDR，再叠加 VFX）
              -> Bloom Extract/Down/Up
              -> Tone Mapping
              -> FXAA/Present
              -> UI Overlay
```

VFX 放在 TAA 之后，避免短生命周期 sprite 被 TAA history 拖影。VFX 放在 tone mapping 之前，确保 HDR 与 Bloom 正确。默认 auto exposure 在 VFX 合成之前取样，避免 muzzle flash 或爆炸让整个画面短时间变暗。

### 9.3 Ping-pong 合成

当前 RenderGraph 不支持后续 pass 原地复用前一 pass attachment。`VfxHdrPass` 必须：

1. 创建新的 `VFX_HDR_COLOR`，格式 `RGBA16F`；
2. 依赖当前基础 HDR producer；
3. 用 typed color blit 将基础 HDR 复制到当前 target；
4. 在同一 target 上以 alpha/additive 绘制 VFX；
5. 将 Bloom 和 tone mapping 的输入切换为 `VFX_HDR_COLOR`；
6. 没有注册 VFX recorder 时完全不创建该 pass 和 attachment。

不能使用 `glCopyTexImage*`、CPU readback、默认 framebuffer 往返或 `CommandBuffer.custom()`。blit 后的 framebuffer/state 必须由 typed command 和 state cache 正确恢复。

### 9.4 受控扩展入口

RenderPipeline 增加一个构建前注册的 HDR transparent recorder 集合，或由 `subsystems.render3d.vfx` 提供等价 attach API。合同必须满足：

- 注册发生在 `pipeline.build()` 前；
- 名称唯一，数量有上限；
- recorder 只在 render thread 执行；
- recorder 不拥有 graph attachment；
- graph rebuild/close 后旧 recorder 不可继续调用；
- 没有 recorder 时现有 pass 列表与像素不变；
- API 第一版分类为 `advanced`，不暴露 raw framebuffer owner 给 `subsystems.vfx`。

不建议在 `PostProcessPassBuilder` 中直接硬编码 `EffectSnapshot` 或 `VfxRenderer`。HDR transparent 是 render3d 兄弟 subsystem 的组合锚点，VFX 只是首个正式调用者。

## 10. 场景深度与 Soft Particle

### 10.1 非 MSAA

NONE、FXAA 和 TAA geometry 已提供单采样 `SCENE_DEPTH` texture。VFX shader 使用 screen UV 采样 scene depth，与当前 fragment depth 比较：

- primitive 在场景表面之后时 discard；
- 接近交界时按 view-space 距离渐隐；
- `softParticleDistance=0` 时仍执行硬遮挡，但关闭软淡出；
- inverse projection 用于把非线性 depth 转换到一致的 view-space 距离。

禁止直接用非线性 depth 差冒充世界单位 soft distance。

### 10.2 MSAA

MSAA geometry 当前使用 multisampled depth renderbuffer，不能直接由普通 sampler2D 采样。新增受控 `VfxDepthResolvePass`：

1. 创建单采样 depth texture；
2. 依赖 GeometryPass；
3. 使用现有 `CommandBuffer.blitDepth(source, target)`；
4. 强制尺寸、format 和 sample compatibility；
5. VfxHdrPass 依赖该 pass 并采样 resolved depth；
6. 没有 VFX/soft depth 消费者时不创建 resolve pass。

不得引入 `glReadPixels`、`glGetTexImage` 或隐藏同步点。resize 后 resolve target 跟随 graph 尺寸重建。

### 10.3 VFX 互相遮挡

第一版 VFX 不写 depth，primitive 之间继续依靠透明稳定排序。scene-depth sampling 只解决 VFX 与不透明场景的遮挡/交界，不解决透明 VFX 之间的 order-independent transparency。OIT 明确不属于 v0.18.2。

### 10.4 Fog

由于 VFX 合成位于现有 FogPass 之后，第一版可增加 `fogInfluence`：

- 0：纯发光 fire/flare 不受雾影响；
- 1：smoke 按与正式 FogSettings 一致的距离/高度模型衰减；
- 中间值在无雾和完全受雾颜色之间插值；
- 不复制或修改 FogPass 资源所有权；
- shader 数学必须通过共享 helper/测试与现有 fog 结果保持可解释一致。

若实现阶段无法避免不必要的 shader 复制，`fogInfluence` 可以降为 v0.18.2 的 should 项，但必须在限制文档中明确 VFX 当前不受雾影响。

## 11. Bloom 增强

### 11.1 复用现有参数

VFX glow 的主要控制方式是：

```text
sampled mask × tint RGB × tint alpha × emissiveIntensity
```

结果进入 `RGBA16F` 后由现有 Bloom threshold/soft-knee 提取。推荐初始范围：

- smoke：emissive `0～0.4`，通常不触发 Bloom；
- fire：emissive `3～6`；
- magic ring：emissive `2～5`；
- flare/muzzle flash：emissive `8～12`，生命周期很短；
- slash/trail：emissive `1.5～4`。

这些是 Demo 预设，不是公共硬限制。public material 只要求有限、非负，并由 diagnostics 报告异常高值。

### 11.2 新增参数

在真实 VFX 像素证明需要的前提下，为 `BloomSettings` 增加：

- `scatter`：控制低分辨率 mip 回灌比例与视觉扩散半径；默认值保持 v0.18.1 画面；
- `maxBrightness` 或等价 highlight clamp：限制极亮 flare 在半精度链路中产生 firefly；0 或明确 sentinel 表示关闭。

保留现有五参数 constructor 作为 convenience overload，旧 builder 默认结果必须逐像素兼容。scatter 与 clamp 必须有边界验证、shader 测试和 1080p/4K A/B 数据。

### 11.3 不做独立 Bloom mask

v0.18.2 不增加 MRT bloom mask 或 per-object bloom flag。材质通过 emissive intensity 与最终 HDR 亮度决定贡献，这与现有 PBR emissive/scene Bloom 语义一致。只有真实内容证明“可见亮度和 Bloom 强度必须分离”时，才评估额外 attachment。

### 12.1 Fire and smoke

## 14. 性能与分配预算

### 14.1 基准场景

至少记录：

- 256 sprites：典型效果；
- 1,000 sprites：较重效果；
- 10,000 sprites：压力路径；
- 256 sprites + 128 Ribbon segments + 32 Decals：混合材质场景；
- Bloom off/on；
- 1080p 与 4K；
- NONE/FXAA 代表组合，MSAA 单独记录 depth resolve。

### 14.2 指标

- CPU simulation/snapshot；
- VFX command record；
- texture bind、material switch 与 draw count；
- VfxHdrPass color blit GPU 时间；
- depth resolve GPU 时间；
- VFX draw GPU 时间；
- Bloom 各级 GPU 时间；
- 每帧线程分配；
- runtime JAR 增量与 GPU texture bytes。

### 14.3 预算

- legacy 无纹理模式相对 v0.18.1 CPU record 中位数回归不超过 5%；
- 相同 primitive count 的 textured 模式 CPU record 回归目标不超过 15%；
- 1,000 同材质 sprites 不得产生 1,000 次 texture bind；
- texture/material 状态只在实际变化时提交；
- VfxHdrPass 固定只增加一次全分辨率 color copy；
- MSAA depth resolve 只在存在 VFX depth 消费者时启用；
- diagnostics OFF 不创建字符串、JSON 或额外 per-primitive snapshot；
- 10,000 sprite 路径若每 primitive draw 成为主要瓶颈，只记录证据并规划后续 instancing，不在本版本未经设计重写 submission。

预算失败不能通过降低粒子数、提高历史基线或关闭纹理/Bloom 门禁来掩盖。若 pass 成本超出预算，应先区分全屏 copy、透明 overdraw、draw submission 和 Bloom 层级成本。

## 18. 风险与回退策略

| 风险 | 影响 | 控制措施 |
| --- | --- | --- |
| 原始素材全量打包 | JAR 增加约 207 MB，manifest 失控 | runtime 白名单、体积守卫、原包移出 resource root |
| 缺少许可证 | 无法合法交付 | Luos/WrizFX 默认拒绝，只有完整许可后重审 |
| opaque PNG 错用 alpha | 整张黑色方块可见 | 显式 mask mode、通道测试、禁止运行时猜测 |
| VFX 仍画在 LDR overlay | emissive 被截断、无 Bloom | HDR pass 像素测试、Showcase 移除旧 overlay 路径 |
| VFX 进入 auto exposure | 爆炸导致画面突然变暗 | exposure 读取 base HDR，Bloom 读取 VFX composite |
| MSAA depth 不可采样 | soft particle/遮挡失效 | typed depth resolve，只有消费者存在时启用 |
| 透明排序被材质分组破坏 | 跨帧闪烁与颜色错误 | 保留全局稳定顺序，只复用连续相同状态 |
| 大面积贴图 overdraw | GPU 成本显著上升 | alpha cutoff、尺寸预算、1080p/4K overdraw 基准 |
| emissive 极高 | half-float firefly 或 Bloom 爆炸 | 有限值验证、diagnostics、可选 highlight clamp |
| 新材质破坏 legacy API | v0.18.1 Demo/测试失败 | legacy constructors/default material/record overload |

若 HDR pass 或深度路径无法满足资源生命周期门禁，允许 v0.18.2 候选退回到“纹理化 LDR VFX 实验”，但不能以正式“Bloom VFX”发布。版本主题只有在 HDR、Bloom 和深度证明全部闭环后才能保留。
