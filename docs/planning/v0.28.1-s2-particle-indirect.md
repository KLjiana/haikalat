## 技术卡

| 字段 | 内容 |
|---|---|
| 技术 ID／用户场景 | #27 GPU Particle Indirect Rendering。为粒子 owner 提供真正的 GPU 活跃集合、受控发射、生灭与 indirect draw，使每帧绘制数量由 GPU 计数决定，CPU 不读回。 |
| 当前基础／差距 | 已有 `GpuParticleExperiment` 的真实 compute + SSBO + 全量 `glDrawArrays(GL_POINTS, 0, capacity)` 路径，以及 `CommandBuffer`/`StateCache` 的 typed compute/storage/barrier 命令。差距：没有活跃索引压缩、没有原子计数、没有 indirect draw 命令、没有显式 reset/replay、没有生产 owner 与生命周期。本包沿用同一 Particle ABI（2×vec4，32 B）和 billboard 拓扑，但把实验的恒定 NDC 尺寸修正为世界空间尺寸，并演进出活跃集合与 indirect 路径；实验类保留给既有 demo，不改其 shader 指纹。 |
| 真实生产消费者 | `subsystems.render3d.vfx.GpuParticleSystem.record(CommandBuffer, dt, viewProjection, aspect)` 直接写入调用方的命令流，由 Integrator 在 VFX/透明阶段执行。`GpuParticleSystemGlTest` 是真实 GL 消费者：compute 写存活的 N 个粒子并 `glDrawArraysIndirect` 到 FBO，读回像素/计数/索引。 |
| 输入 | `GpuParticleSettings`（capacity、世界空间 spawn AABB、lifetime、重力、初速度范围、billboard 世界尺寸、线性颜色、强度）；每帧 `deltaSeconds`、`viewProjection`、`viewportAspect`；显式 `emit(count)` 队列与 `reset()`。设置、容量和时间在 CPU 侧校验；shader 不吃纹理、深度或灯光。 |
| 输出 | 3 个 GPU buffer：particle SSBO（capacity × 32 B）、counter SSBO（16 B，前 4 个 uint 同时是 `DrawArraysIndirectCommand`）、active-index SSBO（capacity × 4 B）。渲染输出是加色、预乘、无深度写入的 billboard 颜色到调用方目标；GPU 侧命令为 `glDrawArraysIndirect(GL_POINTS)`。 |
| IO 与空间 | 粒子位置是世界空间，vertex 阶段乘调用方 `uViewProjection`；`particleSize` 是世界空间 billboard 半宽，geometry 阶段的 clip 偏移为 `corner * particleSize * uViewProjection[1][1]`，透视除法后屏幕半宽为 `particleSize * projectionScale / clip.w`，因此尺寸随距离衰减。active index 是粒子 storage 下标，不是 draw 顺序；draw count 来自 counter 的首个 uint。std430 布局固定：`Particle{vec4 positionLife; vec4 velocitySeed;}`（32 B），counter/indirect 4×uint（16 B）。 |
| Pass 顺序 | 每个 record 固定为：① `glDispatchCompute(1,1,1)` reset 命令（activeCount=0、instanceCount=1、first=0、baseInstance=0）→ `GL_SHADER_STORAGE_BARRIER_BIT`；② update dispatch（GROUP=ceil(capacity/64)）清空 replay 槽、按环形窗口发射、积分寿命/重力并原子追加活跃索引 → `GL_SHADER_STORAGE_BARRIER_BIT \| GL_COMMAND_BARRIER_BIT`；③ 加色/无深度写状态 → 绑定 draw program/VAO → `glDrawArraysIndirect(GL_POINTS, 0)`。空集合不特判：count=0，draw 不产生图元。 |
| GPU owner | `GpuParticleSystem` 拥有 3 个 program（reset/update/draw）、3 个 SSBO、1 个空 VAO，全部在 GPU owner 线程与 current context 内创建/关闭。`CommandBuffer` 只承载 typed 命令；`GpuParticleSystem` 不在 render3d 业务类里写 raw GL。它不依赖 `RenderPipeline`、`ForwardPassBuilder` 或 `pipeline` 包。 |
| 生命周期 | 构造：按 `[1, 1,048,576]` 校验容量并一次性分配 buffer/program/VAO；任一创建失败按逆序关闭已创建资源后抛出。录制：`record` 先校验参数，再消费发射队列并写命令。发射队列上限为 capacity，跨帧保留；`emit(count)` 在 `pending + count > capacity` 时拒绝而不是静默丢弃。`updateSettings` 只允许同容量热更新（lifetime/speed/gravity/size/color）。容量变化用 `resized(newCapacity)` 准备完整候选，调用方发布后关闭旧 owner。`reset()` 同时承担取消/重放语义：丢弃未提交发射、游标与 seed 帧归零、下一帧从空集合重建。`close()` 幂等，关闭后 `record/emit/settings/statistics/reset/resized` 抛 `GlException`。 |
| 失败 | 非法 settings/容量/时间/aspect 在进入命令流前抛 `IllegalArgumentException`；关闭的 buffer 在录制期被拒绝，执行期再次校验。replay reset 是显式 `reset()`，不是每帧回读：清空队列、游标和 seed 帧归零、下一次 update 逐槽清零后再发射。失败帧不做像素回滚，也不伪造成功：统计只记录已录制的请求发射量。 |
| 独立 oracle | 测试树内 `GpuParticleReferenceModel` 用独立 Java 实现重算发射窗口、寿命和活跃集合；JVM 用例断言手工序列（0.375 s / 0.125 s 等二进制精确值）。GL 用例把 GPU counter、active-index 集合和像素与该模型比较：wrapped case 读回 counter 前 4 个 uint 作为 `DrawArraysIndirectCommand`（count/instanceCount/first/baseInstance）、读回实际 active-index 顺序并用同一 draw program 重绘，还显式提交 dead prefix 证明其不可见；active-vs-full case 用相同 draw program + identity index SSBO 做全量对照。生产类不读回；GL 测试通过包内 `verificationHandles()` 做诊断读回，每个 case 会多次读 counter/index/像素，不是每 case 一次。 |
| 质量档 | 本版没有内部 Low/Medium/High 预设：有意暴露 `capacity`、每帧 `emit` 预算和 `particleSize` 作为唯一质量/成本旋钮，默认值保守且有界（`GpuParticleSettings.defaults`）；下文给出可选建议表供 Integrator 映射。未做 GPU 性能测量，收益与预算状态 `NOT_EVALUATED`；不以容量全开作为默认。 |
| 验证范围 | JVM：settings/容量/防御性拷贝、发射队列/环形游标/replay、独立寿命模型、shader 绑定与原子追加契约、indirect draw 命令编码（19 个 case，已执行 PASS）。GL：`GpuParticleSystemGlTest` 的 7 个 case 覆盖活跃数 < capacity 时只画活跃集合并与全量直接绘制对照、wrapped/non-prefix 活跃集合的 indirect command/active-index/像素 oracle、空集合零像素、容量上限/队列溢出、寿命跨越与运行时寿命变化、reset/replay 像素逐字节一致、容量替换/resize/close 资源回收与 `GL_NO_ERROR`。`f667621` 上前 6 个 case 已由 Orchestrator 重跑 6/6 PASS；新增 wrapped case 与 frag/状态修复后的 GL 尚未重跑，记为 `NOT_EVALUATED`。 |

## 建议质量档（调用方配置，不是内部预设）

本版只有一组有界旋钮，没有隐藏的 Low/Medium/High 分支。下表是可直接由 Integrator 映射到
`GpuParticleSettings` / 每帧 `emit` 预算的建议值；均为作者配置，未做性能或视觉签收，
`NOT_EVALUATED`。

| 档位 | capacity | 每帧 emit 预算 | particleSize | 备注 |
|---|---|---|---|---|
| Low | 4,096 | 256 | 0.04 | 保守显存与填充率，适合远景/低端设备 |
| Medium | 16,384 | 1,024 | 0.06 | 默认候选，约 512 KiB particle + 64 KiB index |
| High | 65,536 | 4,096 | 0.08 | 近景/高密度，显存与 overdraw 需单独测量 |

任何档位都保持 `capacity ≤ 1,048,576`、每帧发射 ≤ capacity、活跃计数 ≤ capacity；超过
`emit` 容量的请求在 CPU 侧被拒绝，活槽被重新命中时该次发射被丢弃而不是覆盖。

## 与 #15 / #26 / #28 的接线点

- **#15 Depth-based collision**：当前 update shader 不绑定深度纹理，也不做碰撞；扩展点是在
  `GpuParticleSystem` 内部增加深度输入与 update 采样，保持活跃集合/indirect 命令合同不变。
  禁止为碰撞在 CPU 逐帧读深度。
- **#26 Sorting**：`activeIndices` 是已压缩的活跃集合。排序应在 update 之后、draw 之前对
  `[0, activeCount)` 的索引 dispatch 重排，count 不变；不需要 CPU 读计数。当前未实现排序。
- **#28 Weighted Blended OIT**：本版 draw 为 `GL_ONE/GL_ONE` 加色且不写深度。OIT 集成应把同一
  indirect draw 路由到累积/透射附件并替换 blend/resolve，仍消费 GPU 计数与活跃索引。
- Integrator 需要接线：在 `RenderFeatureSettings`/pipeline 生成期加入粒子字段（capacity、
  settings、enabled），在 GPU owner 线程构造 `GpuParticleSystem`；每帧在 VFX/透明阶段调用
  `emit` 与 `record`；容量变化用 `resized` 候选替换并在代次发布后关闭旧 owner；关闭 feature
  时关闭 owner 而非保留资源。`RenderPipeline.java`、`RenderFeaturesControl.java`、
  `RenderFeaturePolicy.java`、`PipelineFeaturePolicy.java` 本包未修改。

## 明确限制与未验证项

1. 生产路径没有 CPU 同步读回，也不提供“读活跃数”API；统计中的 `requestedEmission` 是提交给
   update 的请求量，不是 GPU 确认的 spawn 数。
2. 本版不做排序；加色混合在 8-bit 量化后仍可能对重叠粒子的绘制顺序产生 ±1 级差异。
   replay fixture 用同位置/同寿命粒子避免该差异；wrapped oracle 则用读回的实际 active-index
   顺序重绘，不假设顺序。真实 alpha 排序/稳定相同键仍待 #26。
3. 不承诺透明正确性：不写深度、不做 OIT/背到前合成、不与场景透明网格交错；这些属于 #26/#28。
4. 粒子物理范围仅“初速度 + 重力 + 线性位置积分”，无碰撞、无流体、无纹理驱动、无逐粒子寿命
   分布/颜色分布；发射是显式调用，没有内部 rate 时钟。
5. 空集合仍会记录一次 indirect draw（GPU count=0），由 GL 语义保证不产生图元；这不是 CPU
   读取后跳过 draw。
6. 未测性能、显存峰值、多硬件、MSAA 交互或 1920×1080 预算；`NOT_EVALUATED` 保留。
7. 世界尺寸使用 `uViewProjection[1][1]` 作为投影 Y 缩放；标准透视/正交矩阵成立，带 skew 或
   非对角缩放的自定义投影不保证比例。
8. 本 Worker 未运行真实 GL。历史：首轮 4/6；`f667621` 上 6/6 PASS。复审修复新增第 7 个
   wrapped case 并改动 fragment 与 draw 状态，必须在 GPU 串行阶段重跑并核对 7 个 case、0 skip、
   command/index/像素读回、投影 centroid 与 `GL_NO_ERROR`，之前新增项记为 `NOT_EVALUATED`。

## 首轮 GL 诊断与修复（2026-11-12）

首轮真实 GL：`GpuParticleSystemGlTest` 6 个 case 中 4 PASS、2 FAIL。失败均不是活跃集合、
reset/replay 或原子顺序错误：

1. `activeSetIndirectDrawMatchesTheFullRangeDrawAndStaysBelowCapacity`：GPU counter 读回为
   32（活跃集合与间接 count 正确），但像素覆盖只有 16 px，未通过 `>32` 断言。
2. `resetReplaysTheSameEmissionToIdenticalPixelsAndTheSameActiveSet`：像素逐字节比较和
   active-index 集合比较都已通过；失败的是同一个 `nonBlackPixels(replay) > 32` 断言（同样
   16 px）。

根因是 geometry 阶段把 clip 偏移写成 `corner * particleSize * center.w`。由于
`gl_Position.w` 保持不变，透视除法会把这个 `w` 约掉：

```text
NDC offset = (corner * size * w) / w = corner * size
```

因此 `particleSize` 实际是**恒定 NDC 尺寸**，不是世界尺寸；64×64、size 0.08、w=3 时半宽只有
2.56 px，32 个同位置 billboard 合计约 16 个非黑像素。replay 失败只是同一 fixture 敏感度问题，
reset 语义本身没有差异。

修复：

- geometry shader 改为 `corner * particleSize * uViewProjection[1][1]`（标准透视/正交投影的
  Y 缩放）。clip 偏移现在与深度无关，透视除法后 `NDC size = particleSize * projectionScale / w`，
  即真正的世界空间 half-width，屏幕尺寸随距离衰减。
- 64×64 fixture 的 `particleSize` 从 0.08 提高到 0.35（世界空间半宽），预期覆盖约 250 px；
  覆盖断言从 32 提高到 `>100`，不是降低阈值。
- 新增 CPU 投影 centroid oracle：32 个粒子放在已知世界点 (0.5, 0.25, 0)，把非黑像素质心与
  CPU 用同一 `viewProjection` 投影出的像素中心比较（±1 px）。若 `uViewProjection` 未上传或为
  identity，质心会落在原始 NDC 位置并明显偏离。
- replay case 增加“两次覆盖像素数相等”断言（在逐字节相等之外），并保留 active-index 集合断言。
- shader 契约测试锁定 `uParticleSize * uViewProjection[1][1]` 且禁止旧的 `* center.w` 形式。

修复后 Orchestrator 在 `f667621` 上重跑：**6/6 PASS**。首轮 4/6 记录保留，不改写。

## 复审修复（2026-11-12，第二版）

复审指出三个需要修复的点，均已处理：

1. **active-vs-full 的测试缺口**：原先所有 GL fixture 的活跃集合都是前缀 `[0,N)`、粒子同点、
   死粒子 alpha=0，因此把 draw 换成 `glDrawArrays(0, capacity)` 仍会通过。新增
   `wrappedActiveSetDrawsOnlyTheLiveIndicesAndTheirExactOrder`：
   capacity 8，先 emit 4 个前缀槽并让它们全部死亡，再推进环形游标逐帧 emit 到 slots 4..7；
   活跃集合是 `{4,5,6,7}`（非前缀、wrapped），每槽位置由 spawn AABB 的 hash 决定且因错峰
   生成而有不同剩余寿命（可见 alpha 不同）。断言：
   - 读回 counter 前 4 个 uint 作为 `DrawArraysIndirectCommand`，要求
     `count=4 < capacity`、`instanceCount=1`、`first=0`、`baseInstance=0`；
   - 读回实际 active-index 顺序，并用同一 draw program 重绘同一顺序，像素误差 ≤1；
   - 显式提交 dead prefix `{0,1,2,3}`，要求零非黑像素；
   - 保留空集合、寿命、replay、容量、resize/close 断言。
2. **fragment 可移植性**：`smoothstep(1.0, 0.65, r2)` 的 `edge0 > edge1` 在 GLSL 4.60 未定义，
   改为等价的 `1.0 - smoothstep(0.65, 1.0, r2)`；shader 契约测试禁止降序形式。
3. **状态自足**：`record` 在加色 draw 前显式 `blendEquation(GL_FUNC_ADD)`，draw 后恢复
   `materialState(OPAQUE, true)` 与 `enableCullFace(true)`，不再依赖调用方遗留的 blend
   equation/cull 状态；粒子的 draw 状态不会泄漏到后续 pass。

GL 读回政策：每个 case 会多次读回（counter/indirect command、active indices、像素），
**不是每 case 一次**；读回都在命令执行完成后由测试 oracle 触发，生产 `record` 路径没有
`glGetBufferSubData`/`glReadPixels`/`glMap`。若 `config/gl-debug-policy.tsv` 需要为本类登记
驱动消息，描述应与这条一致，而不是 “one readback per case”。
