# v0.25.1 风格化场景控制执行规划

日期：2026-10-08。状态：待实施；本文件不表示下述新渲染功能已完成。

## 1. 版本目标与开工基线

把 0.25 的多光源体积雾、灯光、PBR 和视觉配置转化为易调、可重复的场景画面。必做两条主线：**空间视觉参数混合、薄叶材质最小扩展**。先完成酒馆门口的平滑视觉过渡和森林逆光叶片；不以新增后处理数量衡量版本完成度。

开工基线为 `1e681517cb3287eff72996ba56885355200f37fd`，构建版本 `0.25.0`，已确认推送到 `origin/new-engine`。相对 `0602550` 的合并增量只有限时验收脚本及相关记录，运行时源码未变。依据 [0.25 功能签收](../releases/v0.25.0-functional-acceptance-2026-10-08.md) 和 [版本身份核对](../releases/v0.25.0-version-identity-2026-10-08.md)，允许开始本版；性能欠账和 `releaseReady=false` 保留各自含义。

本次开工收尾修复了 `build.gradle` 未加载固定验收脚本的问题，并将固定范围补到 0.25 生产消费者；最终 145 项测试通过，入口耗时约 28 秒，见 [收尾验证记录](../releases/v0.25.0-merge-cleanup-2026-10-08.md)。实现过程中不要求重做全部 0.25 验收，也不把旧体积性能失败改写成通过。本文编写阶段不提前修改构建版本、创建标签或推送代码。

## 2. 现有架构与落点

路径均相对于仓库根目录；下表新增名为拟定设计，不是现有可调用 API。

| 现有文件/模块 | 保留职责 | 本版修改边界 |
| --- | --- | --- |
| `src/demo/java/.../demo/pbr/VisualProfile.java`、`VisualProfileCodec.java` | schema 2 作者配置、严格解析、原子保存 | 增加独立区域配置文件；不能让 main 依赖 demo profile 类型 |
| `src/main/java/.../subsystems/render3d/VisualSettings.java` | 不可变渲染参数快照 | 复用已有曝光/Bloom 字段；区域解析结果只合并允许字段 |
| `RenderPipeline.java` 的 `applyVisualSettings` | 帧边界设置与候选代次事务 | 增加小型桥接逻辑，不在这里实现区域距离/优先级算法 |
| `PostProcessPassBuilder.updateVisualScalars` | 不改变资源形状的曝光/Bloom 更新 | 需要 grading intensity 热更新时扩展这一内部路径 |
| `subsystems/postprocess/ColorGradingSettings.java` | tone mapping 后、显示编码前的 LUT 与 intensity | 首版只混合同一 LUT 的 intensity，不插值纹理 ID |
| `PipelineGeneration`、`TemporalFrameState`、`VolumetricHistoryPlan` | 所有权、成功帧及独立历史 | 保留协议，视觉区域不拥有纹理或新增私有时钟 |
| `VolumetricFogSettings`、`LocalFogVolume` | 世界介质、局部雾体及其时域变化 | 保留世界坐标物理语义，不由相机区域替换 |
| `core/assets/PbrMaterialProperties`、`render3d/pbr/PbrMaterials`、`PbrMaterialBinder` | 材质定义、装配和绑定 | 增加显式、默认关闭的叶片扩展；保留金属粗糙度 PBR |
| Forward、SceneSurface、shadow shader | 表面着色、共享表面、阴影 | 保持 MASK coverage 和变形一致；共享必要的 shader helper |

拟新增的 CPU 类型放在 `subsystems/render3d/visual/`，包内类型优先；只有场景作者必须调用的入口进入 public API allowlist：

- `VisualOverrides`：每个字段单独记录 override 与值，未填写不能等价为零或默认值。
- `VisualRegion`：stableId、priority、enabled、球/轴对齐盒边界、blendDistance、weight、overrides。
- `VisualSettingsResolver`：纯 CPU，无 GL，无 Scene 全局静态状态，输入全局基值/区域快照/当前相机位置。
- `ResolvedVisualSettings`：该视图当帧不可变结果及有效区域诊断；不包含 GPU 原生 ID。

区域配置与 Demo codec 放在 demo 作者层，解析成上述 main 数据类型。首版最多 32 个区域，简单遍历；超过上限显式报错，不静默裁剪。没有测出瓶颈前不接入 lighting cluster 或建立空间树。

## 4. M1：空间视觉参数混合

### 4.1 字段白名单

| 字段 | v0.25.1 核心行为 | 禁止的隐式行为 |
| --- | --- | --- |
| 曝光补偿 EV | 区域以绝对补偿值覆盖并混合，最终乘子为 `2^EV` | 把线性曝光当 EV；每帧用上次结果再次乘基值 |
| Bloom intensity | 在定义的线性强度空间混合，有限且非负 | 在边界切 enabled/maxLevels 或分配新目标 |
| 同一 LUT 的 intensity | 在 `[0,1]` 内混合；基准 LUT 与资源开关固定 | 插值 LUT/cubemap ID；暗中加载第二套 LUT |
| 雾密度/颜色/局部体积 | 仍用现有世界介质与 LocalFogVolume 作者设置 | 相机跨门口就修改整个世界雾密度，或令门外看到的室内烟雾消失 |
| AA、tone mapper、采样/分辨率/质量、IBL 资源、光源表 | 不进入连续解析输出 | 经过区域边缘重建 topology、换阴影槽或清空全局历史 |

核心阶段固定 MANUAL 曝光以隔离效果；AUTO 模式可接入，但补偿必须作用于适应后曝光，不重置适应历史。若还未支持 AUTO 补偿，配置明确拒绝并在支持矩阵标记，不能忽略用户字段。当前 `VisualSettings.manualExposure` 是正线性乘子；最终手动曝光为 `globalManualExposure * exp2(resolvedEV)`。

现有 grading 配置只提供 LUT/intensity，没有现成 saturation/contrast 标量。本版不靠新增一套隐藏着色参数假装已支持。第一版允许只完成 EV/Bloom，再通过小型内部标量更新补齐同 LUT intensity；发布清单应准确记录实际支持字段。

所有写入值必须 finite；EV 限定 `[-8,8]`，区域 weight `[0,1]`，blendDistance 非负，Bloom intensity `[0,8]`，LUT intensity `[0,1]`。这些是首版作者输入合同，不是 GPU 性能阈值。越界/重复 stableId/未知字段/非法形状在解析阶段拒绝，保持旧配置有效。

### 4.2 距离、优先级与缺省值

1. 每帧从全局基值开始解析，不能以上一帧 resolved 值作为基值；在一个视图内先读取一份不可变区域快照。
2. 球：`d=max(length(camera-center)-radius,0)`；轴对齐盒：`d=length(max(abs(camera-center)-halfExtent,0))`。首版不支持任意缩放/旋转盒；非法尺寸拒绝。
3. `blendDistance>0` 时，`t=clamp(1-d/blendDistance,0,1)`，`w=weight*t*t*(3-2*t)`。实体内部权重为 weight，外壳平滑衰减到零；`blendDistance=0` 时，内部/边界为 weight，外部为零。半径/半尺寸必须严格为正。
4. 按 `(priority 升序, stableId 字典序升序)` 排序；每个启用 override 的字段执行 `value=lerp(value,regionValue,w)`。高优先级后处理，同级较大 stableId 后处理；这是有序覆盖，不是所有区域归一化平均。
5. 未 override 的字段不参与任何覆盖。disabled、零权重与外壳外区域不改变结果。禁止依赖 HashMap 遍历顺序。

必须有独立例子：全局 EV=0，A 的 EV=2、权重=0.5，B 的 EV=-1、权重=0.5，A 后 B 得到 EV=0；交换优先级得到 EV=0.75。测试从公式给出期望，不复制 resolver 的实现当 oracle。

首版不增加随时间追赶的平滑器：空间 smoothstep 已定义边界行为。需要额外时间平滑时另立成功帧状态合同，不能混入 resolver 产生帧率依赖。固定相机路径 + 固定输入必须给出相同输出。

### 4.3 配置格式与事务

新增独立 `VisualRegionSetCodec`（拟名），使用项目已有 properties 风格：`regions.schema=1`、区域数量、逐区域 stableId/shape/priority/center/extent 或 radius、blendDistance/weight，以及显式 overrides。

- 全局 VisualProfile 保持 schema 2；区域文件引用 profileId，不复制光源表索引或灯 override 到 region。
- 加载顺序：完整解析 → 检查有限性/容量/唯一性/引用 → 建立不可变 region set → 下一个帧边界原子替换。解析失败不修改 live set、profile 或 IBL。
- 保存使用临时文件加原子替换的既有模式；加载保存往返保留 override 是否存在，未填字段不能生成隐含覆盖。
- UI 的手动预览值与已保存配置分开；重载时不让旧 UI 指针指向已替换数据。离散资源切换继续走原有候选代次事务。
- 不要求自动迁移旧作者文件；没有 region 文件时直接使用全局 profile，画面应与 0.25 相同。

M1 出口：边界/重叠/稳定排序/缺省字段/非法输入/往返/双视图 CPU 合同通过。此阶段不启动 GL。

## 5. M2：帧边界接入与历史语义

调用顺序必须清楚：场景更新及区域快照 → 视图相机位置 → CPU resolve → 合并允许字段 → 原子发布视觉参数 → 冻结 SceneFrame/FrameLightTable → 正常渲染 → 成功后提交已有历史。

默认宿主可在帧开始调用解析器再调用 pipeline 的小型参数入口；引擎不强依赖某个 Demo。两个 pipeline 使用各自的相机、resolved 值与缓存，不互相改共享 Scene 的灯或物理介质。

注意现有实现的两个实际约束：

- `applyVisualSettings` 会检查已有方向光，并在 IBL/方向光变化时失效 TAA。区域只有曝光/Bloom/grading 的更新应走只影响显示参数的小入口，或者把既有方法拆出共享私有核心；不要为了无太阳场景虚构方向光。
- `updateVisualScalars` 会校验 Bloom 的资源形状。区域必须保留 enabled/maxLevels；如果作者基准没启用某效果，首版拒绝对它作有效 override，或在加载时显式准备所需资源。不能靠边界穿越按帧分配。

曝光/Bloom/LUT 位于历史颜色链后的显示处理时，其连续变化不应使体积或 TAA 历史失效。依据实际 pass 顺序核实；不为保历史而移动 tone mapping 到错误阶段。若以后加入真正修改入射光或介质的参数，继续由 VolumetricHistoryPlan 按变化类别拒绝/更新历史，本版不顺手修改该协议。

发布事务分两类：

1. 合法纯标量：不新建 Generation；先校验整组值再应用，失败保留上一组。
2. 显式 profile/资源切换：构建完整候选，成功后替换；失败保留旧 profile、region set 与借用 IBL。临时 resolved 值不是已保存的全局基值。

需要的诊断：当前 active region IDs/实际权重、各字段来源、基值与 resolved EV、最终曝光、generation ID、历史失效原因。沿用现有面板/diagnostics，不每帧 readback GPU 纹理。

M2 最小 GL 场景：区域往返 120 帧确认 generation 未增长、物理雾参数未变、TAA/体积历史持续有效；一次非法配置热重载保留旧画面；无方向光场景可调曝光；双视图不同区域互不污染。包括调参变化真实影响像素的 ON/OFF 对照，不能仅检查 getter。

## 6. M3：薄叶材质最小扩展

### 6.1 数据与着色

拟新增不可变 `ThinLeafSettings`：enabled、transmissionColor（线性 RGB `[0,1]`）、strength `[0,1]`，默认 disabled/strength=0。首版只支持刚体/instanced、双面、MASK 非金属叶片，不新增厚度贴图或 Skin/Water 渲染路径。通过 PbrMaterials 的显式配置入口装配；现有 glTF 双面标志不自动解释为薄叶。

PbrMaterialProperties 原 Metallic-Roughness 语义保持。若定义扩展 holder，让其独立于 BlendMode/CullMode；启用薄叶不把 MASK 变成 ALPHA。材质实例的参数必须进入实例兼容/批次分组与 revision，不能让同一批次第一片叶子的设置污染其他材质。

首版定一个可测试的风格化背光项，而不是直接调 Bloom：

```text
Nf = 当前面的朝外几何法线（背面按双面约定翻转）
back = max(dot(-Nf, L), 0)
Cback = baseColorLinear * transmissionColor * strength * back
        * incidentLightRadiance * shadowVisibility
Csurface = 原 PBR 表面结果 + Cback
```

`L` 指向灯。这里是明确的艺术项，不声称薄介质物理散射或能量守恒；strength 范围和有限性约束避免随意倍增。先用几何法线决定前/后受光，PBR 仍按现有 normal map；不得把 normal-map 扰动直接当成叶片翻面判断。默认参数关闭时原 PBR 数值不变。

方向/Point/Spot 都复用 FrameLightTable 与当前有效 shadow slot，局部光使用同一距离/锥角衰减，点灯不能绕过 clustered 列表再次全表遍历。full-scan 测试参考必须实现同样的薄叶项，以验证候选裁剪而非比较两种材质模型。

空气散射依旧由体积链计算。叶片项进入表面 HDR，在既有深度处接受体积 S/T 合成，禁止重复添加空气散射。UI、普通金属/石墙与未启用材质不受影响。

### 6.2 法线、coverage 与阴影

- 双面只改变受光/剔除约定，不篡改 SceneNormal 的坐标系或将 shading normal 静默替换为几何通道。
- Forward、SceneSurface、CSM、Point/Spot shadow 的 UV/alpha texture/factor/cutoff 一致；必要时提取最小共享 MASK helper，避免四份阈值。
- 单叶正反面、背光/正光、灯关闭、遮挡投影、strength=0、两种材质同批实例必须分别有像素检查。alpha cutoff 边界另测，不用大图平均掩盖漏光。
- glTF 缺少切线或没有 transmission 配置继续走原有 fallback；不用猜测文件名给某些模型隐式套效果。

### 6.3 风动范围

0.25 的物理雾风场不是叶片几何风动。第一阶段允许静态叶片交付；若加入几何风动，必须同时完成 Forward/SceneSurface/Shadow 当前变形以及 velocity 的上一成功帧变形，不能只修改 Forward vertex shader。

拟用单个共享 `leaf-deformation.glsl`，输入对象/实例稳定参数、当前成功时间与上一成功时间；确定性 seed，不读 wall clock。上一帧参数在失败帧不得前进。实例化先明确 per-instance seed 与前后矩阵来源；未支持蒙皮/形变网格风动时拒绝组合或在支持矩阵列为不支持。

没有有效上一帧时标记 velocity invalid/reactive，不能输出假零速度。改变 wind 参数、切镜、resize 和失败恢复用短事件序列确认；不增加与本改动无关的整套动画系统测试。

M3 出口：静态薄叶主体可单独签收；只有跨 pass 变形/历史齐全才宣布支持风动。关闭扩展应回到原材质画面，不通过更新普通 PBR 基线隐藏变化。

## 7. M4：Demo 与美术交付

复用 `Render3dVolumetricFogDemo` 的现有场景/模型/配置，优先添加场景选择与区域面板。确需独立入口时，仅建薄 wrapper，复用 factory、profile codec、捕获器与资源关闭协议，不复制第二个引擎状态管理器。

| 场景 | 实施内容 | 固定证据 |
| --- | --- | --- |
| 酒馆门口 | 暖室内/冷街道视觉区域，边缘有过渡；室内雾保持世界定位 | 门外、边界、门内 3 帧，region on/off；同路径进出 120 帧参数/代次记录 |
| 森林林缘 | 逆光薄叶与普通石木参照物；Bloom-off 仍能分辨背光效果 | 正光/背光/透射关闭 3 帧；静态叶片必要，风动完成才加短时域序列 |
| 小型实验台 | 两重叠区域、单叶正反、alpha 检查图、双视图 | CPU/小分辨率 GL 的独立数值测试，不新增大型资产场景 |

默认固定手动曝光。面板显示当前 override、有效区域权重、最终参数和效果开关；支持暂停相机、一次保存/重载、恢复基准。调参界面不暴露内部 texture ID 或让使用者选择 query/屏障模式。

每个正式镜头至少看一次原生截图；颜色/曝光判断用实际输出，细叶边缘使用原生 ROI。数值测试使用线性 HDR 或明确的显示阶段，不能混用 tone-mapped PNG 和线性参考的阈值。重复截图相等只能证明稳定性，独立公式/关闭效果对照才验证新功能。

## 8. P2：DOF 的启动条件

M1～M4 完成且指定镜头确需突出主体时再立项；否则 0.25.1 以区域与薄叶收口。首版可限定单相机、透视、手动焦点/孔径、有限 CoC 半径；不默认把全场景变模糊作为美化结果。

开工前单独明确：CoC 的单位与正负号、前景扩张/背景漏色、透明深度、天空、AA/宿主目标兼容、与 TAA/Bloom/tone mapping 的顺序。使用现有 LinearDepth 的正视空间语义；没有合适透明深度时声明限制，不把 opaque depth 当作透明物距离。

DOF 如果引入新历史或大分辨率临时目标，应追加对应生命周期与深度边缘测试；不沿用“只改参数”的验收范围。其实现与性能目标另写补充单，不挤占核心两条主线。

## 9. 代码整理与旧代码处理

1. M0 只修验收入口与测试选取，保留测试目录中的旧 Outdoor 数学/状态参考；它们不再作为新体积生产链唯一覆盖。
2. 核心引擎不能引入 `demo.pbr.VisualProfile` 依赖。profile/region IO 留在作者层，resolver 和只读数据留在 main；禁止新增 nullable 资源大容器。
3. 把 Demo 内手工插值统一到 resolver，确认无消费者后删除重复函数与死参数；不要保留“旧区域/新区域”两个正式选择器。
4. 删除功能前用引用搜索核对主代码、shader include、demo、测试、公共 API allowlist、资源 manifest、配置 codec 与文档入口。变更资源 hash 通过现有流程更新，不删除 guard 或放宽日志规则。
5. 保留 0.25 物理雾、FogMediumSettings/LocalFogVolume、灯与阴影源。旧历史报告不改成新版本通过；新报告引用原 runId。
6. 本版不做大规模 RenderPipeline 清理。只提取新增重复逻辑，保持成功帧事务、资源所有权与调用顺序可追踪。

## 10. 按阶段验收，默认不跑性能矩阵

遵循 [减负验收规范第 0 节](../guides/focused-acceptance-policy.md)。默认总时限 5 分钟、零自动重试，超时列出未完成项再诊断；不不断加时或重复执行相同失败。

| 改动 | 必测 | 不默认执行 |
| --- | --- | --- |
| 规划/文字/索引 | 链接、文件名、命令、差异 | JVM、GL、benchmark |
| resolver/codec | 排序/边界/缺省/独立期望/原子重载 JVM | 任何 GL、旧容量矩阵 |
| 参数接入 | 上述 JVM + 标量像素变化/120 帧稳定/失败/双视图短 GL | 全灯数、4K、长 soak |
| 薄叶 shader/MASK | 目标 shader 编译、正反/遮挡像素、SceneSurface/Shadow 一致、一个森林镜头 | 全部材质/所有场景/独立性能承诺 |
| 可选风动 | 变形共享、velocity、失败帧、一个 TAA 运动序列 | 无关动画 Graph、IME/native soak |
| 本版功能收口 | 当前必需合同 + 两场景最终图，复用未变证据 | 为写版本号重新跑完整 0.25 性能/质量矩阵 |

当前 `.\verify.ps1` 是 0.25 的固定基础范围，不会自动包含未来新类。新增 resolver/codec/薄叶测试时，必须同时更新清单；可按域增设短叶子入口，保留每个必需类的实际执行/零跳过校验。**下列是拟新增任务名，实施前不可作为现有命令使用：**

- `visualRegionJvmVerification`：仅区域 CPU 与 codec 合同。
- `visualRegionGlVerification`：仅帧边界/像素/事务。
- `thinLeafGlVerification`：材质与跨 pass 合同。

每次任务先 `--dry-run` 检查实际依赖一次；任务结构未变不反复 dry-run。GL 串行执行，禁止与性能探针并行。只有确需性能结论才独立安排代表场景；旧 2%/5%、0.35 ms 或 4K 预算不作为本版普通功能签收前置。

仍保留结构性成本要求：连续参数变化 generation 不增长、同一场景资源数不逐帧增长、没有新增每帧纹理 readback/glFinish、没有重复全灯扫描。这里只验证可观察行为/计数，不伪称毫秒性能已达标。

## 11. 实施顺序与停止条件

| 阶段 | 工程师提交内容 | 进入下一阶段前确认 |
| --- | --- | --- |
| M0 | 入口修复、基线/欠账、支持字段和案例清单 | 限时检查能执行；旧范围不会替代新用例 |
| M1 | 数据类型、resolver、region codec、JVM 合同 | 确定性、无累乘漂移、未填字段不覆盖 |
| M2 | 帧边界标量入口、UI 诊断、区域 GL | 无代次抖动、历史无误清、双视图/失败隔离 |
| M3 | ThinLeafSettings、绑定、共享 shader 与像素检查 | MASK/阴影一致；关闭时原 PBR 不变 |
| M4 | 酒馆/森林固定镜头、面板与配置、按需风动 | 改善来自目标效果；不依赖过曝/Bloom 掩盖问题 |
| M5 | 文档/API/资产索引、版本身份、当前范围报告 | 功能通过/未测性能/可选项未做分别列明 |

连续参数更新导致代次重建、物理雾随相机消失、失败帧推进历史、GL 错误/NaN、薄叶导致非叶片材质变化，是本版必须修复的正确性阻断项。单次旧性能超标、未做 DOF、未跑无关长测不阻止核心功能签收。

若 M3 风动合同明显扩大范围，先交静态薄叶；若 grading 需要重写资源链，先完成 EV/Bloom 并将 grading 明确后移。不得通过删除测试、修改基线或把未执行标记为 PASS 缩短时间。
