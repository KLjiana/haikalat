# 0.28.1 S2 #5 技术卡：Vertex Displacement（有界局部正弦位移）

日期：2026-11-11。状态：首版生产实现完成；JVM 合同通过，真实 GL 用例已编写但**未执行**，不能计为 GL PASS。对应 46 项路线图 #5，执行计划见 [multi-agent full delivery](haikalat-multi-agent-full-delivery.md) 与 [realtime rendering roadmap](realtime-rendering-roadmap.md)。

## 适用范围

- 支持：单个显式局部空间正弦位移模型；`axis`（位移方向）与 `waveDirection`（相位推进方向）可分别配置；幅度、频率、速度、相位和调用方提供的时间；位移后解析法线；与既有 skin/morph draw binding 组合；current/previous 时间用于 surface velocity 与 previous depth；保守 bounds padding 与 revision；forward、共享 surface、GTAO depth 和 directional shadow 深度阶段共用同一数学。
- 不支持：纹理驱动位移、世界空间位移、模型空间法线贴图叠加、instanced renderer 批量位移、VFX 自定义 shader 自动位移、glTF 位移扩展、形态目标/蒙皮顺序的运行时选择、双面法线特殊语义、位移后的 CPU 侧逐顶点 bounds 精确重算。
- 透明/加色材质：如果作者把 binding 挂到透明对象，颜色阶段会位移，但透明对象不进入当前 opaque shadow/surface 深度集合；该组合不属于本首版支持范围，需调用方避免或另行立项。
- 不在本卡交付：`RenderPipeline` 的逐帧 displacement 公共入口（本 Worker 被明确禁止修改 `RenderPipeline`）。接入使用现有 `SceneObject`/`MeshRenderer` 的 `SceneDrawBinding`。

## 数据与归属

| 项目 | 内容 |
|---|---|
| 模型值 | `VertexDisplacementSettings`（GL-free record）：`enabled`、`amplitude`、`frequency`、`speed`、`phase`、`axis`、`waveDirection`。`disabled()` 为默认关闭值。 |
| 每对象绑定 | `VertexDisplacementDrawBinding` 实现 `SceneDrawBinding` + `TemporalDrawBinding`，可包装既有 skin/morph binding；持有 current/previous time 与设置 revision，不持有 GPU 资源。 |
| 真实消费者 | `SceneRenderer`（forward/transparent）、`SceneSurfacePass`（surface/velocity）、`GtaoDepthPass`、`ShadowCasterRecorder`、`SceneReactivePass` 在每次 draw 前调用 `SceneDrawBinding.recordVertexDisplacement`；默认实现写入关闭 gate。 |
| 无新 manager/factory | 只有模型值、绑定和现有 draw protocol 的默认方法；没有新增 Pass、附件、GPU owner 或配置系统。 |
| 应用侧更新 | 每帧在 `RenderPipeline.execute` 之前调用 `binding.update(settings, elapsedSeconds)`；时间由应用时钟提供，暂停时保持不变。 |

装配示例：

```java
VertexDisplacementDrawBinding displacement = new VertexDisplacementDrawBinding(
        VertexDisplacementSettings.localSinusoidal(0.08f, 1.5f, 0.5f, 0.0f),
        existingSkinOrMorphBinding); // 或省略为 SceneDrawBinding.NONE
SceneObject.fixed(mesh, material, modelMatrix, true, displacement);

// 每帧、execute 之前：
displacement.update(settings, elapsedSeconds);
```

## 数学、空间与法线

```text
phase  = 2*pi * (frequency * dot(localPosition, waveDirection) + speed * time) + phase0
offset = axis * amplitude * sin(phase)
normal = normalize(localNormal - waveDirection * slope * dot(axis, localNormal))
slope  = 2*pi * frequency * amplitude * cos(phase)
```

- 位置与法线均在 mesh local/rest space 求值，之后才进入 skinning 与 `uModel`；`axis`/`waveDirection` 会被归一化。
- `amplitude ∈ [0, 0.25]`，`frequency ∈ [0, 4]` cycles/local-unit，`|speed| ≤ 4` cycles/second，`phase` 归一化到 `[0, 2π)`；非法或非有限值在构造期拒绝，不做静默夹取。
- 法线是同一高度场的一阶解析梯度，不是有限差分；`|offset| ≤ amplitude`，斜率上界 `2π·frequency·amplitude`，因此 visibility padding 可以保守使用 `amplitude`。
- 位移方向与波方向都是局部的；若 `axis == waveDirection`，位移只沿自身传播方向移动，法线不变，这是模型的明确退化行为。
- 时间/相位是唯一“种子”：无随机数、无帧率累加；相同设置、位置、时间产生相同结果。

## 与 skin/morph 的顺序

固定顺序为 **morph → vertex displacement → skinning → model transform**：

1. `applyMorph`/`morphPosition` 先产生 local rest 位移；
2. 位移模型读取 morph 后的 local position，写入 position 与解析 normal；
3. `skinMatrix()` 与 `uModel` 最后应用。

因此蒙皮角色的波动绑定在 rest space，并随骨骼动画一起变换；不是在世界空间按屏幕/相机相位摆动。`VertexDisplacementDrawBinding` 通过委托保留 base binding 的 `skinningEnabled()`、`morphTargetCount()`、storage 绑定和 temporal 数据。

## 默认关闭 exact no-op

- 默认 `SceneDrawBinding` 不携带位移；`recordVertexDisplacement` 默认只写入 `uDisplacementEnabled = 0`，不会残留上一个启用对象的 uniform。
- 六个生产 vertex stage 的三个入口函数（offset/position/normal）在 `uDisplacementEnabled == 0 || uDisplacementAmplitude <= 0.0` 时立即返回输入值，位移 gate 位于任何 `sin`/`dot`/归一化之前。
- 关闭时不创建额外 Pass、纹理或缓冲；`boundsPadding() == 0`、`deformsVertices()` 回到 base 值、alpha 与 shadow/depth/velocity 路径与引入前相同。
- 设置变更（幅度/频率/速度/相位/方向/启用）会使 `boundsRevision()` 增加并失效 previous deformation；仅时间推进不会失效 previous。

## 可见性、bounds 与 previous frame

| 项目 | 内容 |
|---|---|
| Bounds | `VertexDisplacementDrawBinding.boundsPadding()` 返回当前 `amplitude`；`BoundsTransforms.world` 在 local AABB 三轴各加该 padding，再变换到 world。SceneFrameBuilder 的缓存 key 已包含 `boundsRevision()`，因此幅度变更会重算可见性/阴影队列。 |
| Previous deformation | `TemporalDrawBinding` 在成功帧提交 current time 为 previous time；`scene-surface.vert` 用 `uDisplacementPreviousTime` 计算 previous local position，再乘 `uPreviousModel * previousSkinMatrix` 得到 previous clip/depth。 |
| 失败/丢弃 | `discardTemporalFrame` 保留已提交 previous；`invalidatePrevious` 清空。设置变更、场景重建、resize 走既有 temporal 失效路径，不伪造回滚。 |
| 阴影/深度/velocity | forward、surface、GTAO depth、directional shadow 的 vertex stage 使用同一 position 函数；surface 额外写当前/previous clip、previous view depth 和解析法线，因此颜色、深度、阴影、velocity 消费同一形变。 |

## 资源、失败与成本

- 无 GPU 资源、无新 Pass/附件；每个启用对象每次 draw 约 9 个 uniform 写入（默认关闭对象仅 1 个 gate 写入），顶点阶段约十余条 ALU，无纹理采样。
- 成本随启用对象数和顶点数增长；未做正式 GPU 性能测量，不得据此宣称预算或帧率。
- 非法设置值在构造期抛 `IllegalArgumentException`；绑定不可嵌套（防止双重位移）；`update` 的非有限时间被拒绝。

## 已知限制与后续

1. 只支持 local sinusoidal 一个模型；纹理驱动/世界空间模型需另立技术卡。
2. 逐对象时间由应用维护；`RenderPipeline` 尚无统一场景时间入口（本 Worker 不得修改）。
3. 透明对象、instanced renderer 和 VFX 自定义 shader 不自动参与 shadow/depth 位移，需明确扩展。
4. Bounds padding 使用 `amplitude` 的保守 AABB，足够覆盖位移但会略微放大 culling 范围。
5. 未做正式性能、长测、GL/视觉或多硬件验证。
