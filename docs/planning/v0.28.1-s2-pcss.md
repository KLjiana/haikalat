## 范围与归属

- 归属：`render3d.shadow.PcssSettings` / `PcssMath` 的配置与 CPU 数学合同、
  `render3d.lighting.FrameLightBinder` 的标量与级联 texel 尺寸上传，以及现有唯一
  `pbr-forward.frag` 的消费端。
- 首版只处理一个主方向光，即现有 `uDirectionalShadowFrameLightIndex` 指向的已选阴影灯，并
  沿用现有方向光 shadow map / cascade atlas。点光、聚光、未进入方向光阴影选择的其他方向光
  以及非 PBR 材质明确不消费；启用但没有方向光阴影或 PBR 消费者时由 `RenderFeaturePolicy`
  在候选准备前拒绝，而不是静默忽略。
- 默认关闭。`ShadowSettings` 原四/五/六参数构造器保留，v0.28.1 S1 的七参数（带
  `contactShadows`、`cloudShadows`）构造器也保留，并填入 `PcssSettings.disabled()`；
  既有场景和默认输出不变。不新增 manager、factory、Pass 或第二套阴影图集。

## 显式控制

| 控制 | 默认 | 合法范围 | 说明 |
|---|---|---|---|
| `enabled` | `false` | — | 总开关；`active() = enabled && lightWorldSize > 0` |
| `lightWorldSize` | `1.0` | `[0, 16]` 世界单位 | 光源世界直径；0 为精确 no-op |
| `blockerRadiusTexels` | `4` | `[1, 16]` shadow texel | blocker 搜索圆盘半径 |
| `blockerTaps` | `16` | `[1, 32]` | blocker 搜索采样数 |
| `filterRadiusTexels` | `8` | `[1, 16]` shadow texel | 变半径 PCF 的半径上限 |
| `filterTaps` | `16` | `[1, 32]` | 变半径 PCF 采样数 |
| `depthBias` | `0.001` | `[0, 0.05]` 归一化深度 | 叠加在现有 `uShadowBias` 斜率修正上的额外 bias |

`PcssSettings` 校验有限性、范围和 `blockerTaps + filterTaps <= 48` 的总 tap 预算；
`blockerRadiusTexels`、`filterRadiusTexels` 和每个 tap 数在 shader 内再次用
`PCSS_MAX_*` 常量 `clamp`，即使宿主上传异常值也不会突破 32+32 次采样。GLSL 的编译期上限与
Java 常量由 `PcssShaderTest` 锁定一致。

## 深度单位与换算

- 深度比较沿用现有方向光路径的 **归一化 light-space window depth `[0,1]`**：shadow map 的
  `.r` 就是该值，现有 hard/PCF 也用 `projected.z + gradient - bias > sampledDepth` 比较。
  `depthBias` 与 `uShadowBias` 使用同一单位，blocker 判定为
  `sampledDepth < receiverDepth - bias`。
- 方向光级联使用正交投影，因此 window depth 与离光源平面的世界距离是线性的：
  `world = near + windowDepth * (far - near)`。shader 从级联矩阵的
  `m22` / `m32` 恢复这两个常量，不额外上传近远平面。
- `uDirectionalCascadeTexelWorld[cascade]` 由 `FrameLightBinder` 从同一份不可变
  `ShadowFramePlan.DirectionalPlan.texelWorldSizes()` 上传（culling 也使用该值）。legacy
  单图路径的 plan 存的是 culling 占位值 `1.0`，因此该路径按对称正交半径推导
  `2 * sceneRadius / resolution` 后上传，避免 penumbra 缩小约两个数量级；该分支由
  `FrameLightBinderTexelWorldTest` 锁定。
- penumbra 半径：
  `receiverWorld = near + receiverDepth * range`，
  `blockerWorld = near + blockerDepth * range`，
  `penumbraWorld = max(receiverWorld - blockerWorld, 0) * lightWorldSize / max(blockerWorld, ε)`，
  `penumbraTexels = penumbraWorld / texelWorld`，再 `clamp` 到
  `[0, filterRadiusTexels]`。`lightWorldSize` 是世界单位，不是 UV 或像素单位。

## 算法与 tile 边界

对当前级联执行：

1. 按现有 normal-offset 与接收面梯度 bias 投影接收面；越出级联 tile / 深度范围时返回
   0（回退到无阴影，与现有 PCF 的越界语义一致）。
2. Blocker search：在半径 `blockerRadiusTexels` 的确定性 golden-angle 圆盘上采样
   `blockerTaps` 次，只把 `sampledDepth < receiverDepth - bias` 的样本计入平均值。无 blocker
   时返回 0（完全受光），不进入 filter。
3. Penumbra：用上节公式和平均 blocker 深度计算，并 clamp 到 `filterRadiusTexels`。
4. 变半径 PCF：同一 golden-angle 圆盘按 penumbra 半径缩放到 `filterTaps` 个 tap，统计被遮挡
   比例作为 shadow factor；半径趋近 0 时退化为近似硬阴影，不会超过配置上限。

tile 边界：

- `directionalCascadeTile` 增加显式 `tapRadiusTexels` 参数；PCSS 传入
  `max(blockerRadius, filterRadius)`，因此 tile 的 guard 覆盖 blocker 搜索和 PCF 两个圆盘。
- 每个 blocker / filter tap 的 UV 都显式 `clamp(..., tileMinimum, tileMaximum)`；接收面本身
  若距 tile 边界不足 guard 距离则提前返回 0，所以任何 tap 都不会读取相邻级联 tile。
- 现有 hard/PCF 调用方传入 `shadowKernelRadius()`，guard 和采样序列保持原语义。

## 合成与禁用等价

- PCSS 只替换 `directionalShadowFactor` 内部的单个级联采样函数；级联选择、级联混合、
  contact shadow、cloud shadow、IBL、emissive 和其他灯保持不变。
- 选择器 `sampleDirectionalShadow` 在 `uPcssEnabled == 0` 时直接调用原
  `sampleDirectionalCascade`，PCSS 函数和任何 PCSS 采样都不会执行，因此禁用默认是精确
  no-op。`FrameLightBinder` 每次绑定仍上传 7 个 PCSS 标量和 4 个级联 texel 尺寸（与
  cloud shadow 的已记录行为一致）；禁用时 shader 不消费它们，像素路径不变。
- 设置仍通过现有 `RenderFeaturesControl.submit` / 候选代发布，不提供逐帧 setter。

## 资源生命周期与成本

- 无新纹理、FBO、shader、Pass、manager 或 GPU owner；`PcssSettings` 是纯值对象，随
  `ShadowSettings` / `RenderFeatureSettings` 发布，关闭时不释放任何他人共享资源。
- 最坏成本：每条被主方向光照亮且未被现有 shadow 完全遮蔽的 PBR 片元
  `blockerTaps + filterTaps <= 48` 次 shadow-map 采样；默认 32 次。没有 blocker 时只做
  blocker search。级联混合区间最多 2 个级联，因此单像素最坏 2 × 48 次。
- 循环边界是编译期常量 + 运行时 `break`，不存在无界循环或逐帧集合。

## 独立参考与限制

- JVM 期望来自显式参数边界、手算样本、测试内独立参考公式，不调用生产 helper 计算唯一期望；
  生产 `PcssMath` 仅是 shader 公式的 CPU 契约镜像，由测试钉住，不构成第二渲染路径。
- GL 测试的 shadow/penumbra band 来自墙平面几何与光方向，不把先前帧输出当真值；hard 基线只
  用作“相对变宽”对照，不是正确性 oracle。
- 首版限制：只支持一个主方向光；假定方向光级联为正交投影（现有实现如此）；侧边/前向
  遮挡边界仍由同一解析带覆盖，极薄 blocker、透明 caster、MSAA/TAA 组合、驱动差异和多方向光
  独立 PCSS 未验证；PCSS 不替代 contact shadow 或 cloud shadow，也不改变级联划分。
- 未执行真实 GL 前不宣称 shader 编译、半影宽度上限或 tile 无泄漏在硬件上通过。
