## 技术卡

| 字段 | 内容 |
|---|---|
| 技术 ID／用户场景 | #22 SMAA；为不需要时域历史的画面提供比 FXAA 更保边、比 TAA 更稳定的单帧 AA 选项。首版不默认开启。 |
| 当前基础／差距 | 已有 `AntiAliasingMode` 单值选择、`PostProcessPipeline` 的 HDR/LDR 颜色链、TAA resolve、FXAA、屏幕效果与 UI 后合成。缺少正式的 SMAA 1x 模式、面积/搜索查找表、三 Pass 拓扑与 HDR-only 配置拒绝。 |
| 作者参考实现 | Jorge Jimenez 等，SMAA 仓库 https://github.com/iryoku/smaa，提交 `71c806a838bdd7d517df19192a20f0c61b3ca29d`。GLSL 移植自 `SMAA.hlsl` 的 `SMAALumaEdgeDetectionPS`、`SMAABlendingWeightCalculationPS`、`SMAANeighborhoodBlendingPS`；使用 HIGH preset（threshold 0.1、16 线性搜索步、8 对角搜索步、25% 圆角）。未改算法，只补 GLSL 330 uniform 与注释。 |
| 查找纹理来源／许可／指纹 | `SmaaLookupTables` 是上游 `Scripts/AreaTex.py` 与 `Scripts/SearchTex.py` 的逐行 Java 移植（MIT）。area：160x560 RG8，SHA-256 `35065cef2a02cabcad711d6bf430239ae64e27d71c4e4fa06f29cce2c992f0d2`；search：64x16 R8，SHA-256 `3694eae5e9d44b8ebb4415a13f8c7b94dc08a2fc86658434d771c4610fe5744d`。指纹由 CPython + Pillow 独立执行上游生成器得到；JVM 测试校验指纹和固定采样值。完整许可与 provenance 见 [SMAA licence](../../licenses/smaa.md)。不提交二进制查找纹理。 |
| 模块与控制 | `subsystems.postprocess.smaa.SmaaPass`（3 个 program + `ScreenQuad` + 2 张查找纹理）；`PostProcessPipeline` 持有并排序。`AntiAliasingMode.SMAA` 是唯一模式选择，天然与 NONE/MSAA/FXAA/TAA 互斥；不新增 manager/factory/chain。 |
| 输入 | HDR 链 tone mapping 之后的 display-referred RGBA8 颜色（`TONE_MAPPED_COLOR`，已做 1/2.2 编码），并在 Vignette/Film Grain/Chromatic Aberration 之后读取；全尺寸屏幕坐标与 `uInvResolution`。区域/搜索表是线性过滤 + clamp-to-edge 的内部资源。 |
| 输出 | 三个全尺寸 RGBA8 中间/最终目标：`smaaEdgeColor`（R/G 边掩码）、`smaaBlendColor`（RGBA 混合权重）、`SmaaNeighborhoodBlendingPass` 直接写 backbuffer（embedded 路径同样走 `writeToBackbuffer`）。输出保持 display-referred gamma 编码，不做二次 sRGB 编解码。 |
| 颜色空间与顺序 | SMAA 的 luma 阈值和混合按参考实现要求工作在 gamma-corrected、非 sRGB 的显示空间；因此 **不进入 LDR `SRGB8_ALPHA8` 路径**，只允许 HDR tone mapping 之后的 RGBA8。Pass 顺序：`Geometry → … → ToneMapping → [Vignette → FilmGrain → ChromaticAberration] → SmaaEdgeDetection → SmaaBlendingWeight → SmaaNeighborhoodBlending → backbuffer`。UI 由宿主在 Present/backbuffer 之后追加 `UiOverlayPass`，不进入 SMAA。 |
| 模式互斥与拒绝 | `RenderSettings.Builder.build()` 在 `antiAliasingMode==SMAA && toneMappingMode==NONE` 时抛 `IllegalStateException("SMAA requires HDR tone mapping")`；`PostProcessPipeline.assemble` 同样拒绝；`passNamesFor/finalPassNameFor(SMAA, NONE)` 抛 `IllegalArgumentException`；`PipelineFeaturePolicy` 对 SMAA+非 HDR topology 拒绝。SMAA 不叠加 MSAA（topology `sampleCount==1`）、不产生 TAA history/velocity/jitter、不与 FXAA 同时出现。 |
| 斜线／细边 | 边检测覆盖对角线 pattern；blending weight 使用 8 步对角搜索与 16 步水平/垂直搜索；单像素斜线在 GL 用例中与二值 baseline 对照，要求出现中间覆盖、能量扩散且峰值不被抹除。 |
| 资源与失败 | `SmaaPass` 拥有 3 个 shader、quad、area/search 纹理，加入 `PostProcessPipeline.owned`；候选代可借用 donor（无状态，直接复用），`transferResourcesTo` 转移所有权。构造失败按 `PostProcessPipeline` 既有路径关闭已创建资源。无历史、无 GPU 读回、无 `glFinish`。关闭 `SMAA` 时不创建任何 SMAA program/纹理/Pass。 |
| 成本／回退 | 每帧 3 次全屏 draw、2 张全尺寸 RGBA8 附件、1 次一次性表生成（约 5.4 万 pattern 单元，JVM 内）与 2 张常驻查找纹理（area 179,200 B + search 1,024 B）。搜索成本随 HIGH preset 有界（≤16 线性/8 对角步）。未做 GPU 性能测量，成本状态 `NOT_EVALUATED`；回退是切回 NONE（精确基线路径）或 FXAA/TAA。 |
| 验证范围 | JVM：查找表 author-reference 指纹/固定采样/确定性、luma 边检测数学 fixture、HDR-only 与互斥/配置拒绝、HDR pass 顺序、禁用精确基线与 topology。GL：`SmaaPassGlTest` 在真实 shader 上覆盖斜线/细边的 GPU 边掩码对 CPU 参考、AA 指标、bounded neighbourhood、禁用/恢复；**尚未执行**。 |

## 明确限制与未验证项

1. 只实现 SMAA 1x（HIGH preset）；不提供 T2x/S2x/4x、时域重投影、predication、运动模糊联合、
   可配置 threshold/搜索步/圆角的质量档。参数是固定的，不在装配后热调。
2. 仅支持 HDR tone mapping 之后的 display-referred RGBA8；LDR `SRGB8_ALPHA8` 链明确拒绝，
   因为参考 luma 边检测要求 gamma-corrected 非 sRGB 输入。不承诺 sRGB 纹理采样下的行为。
3. 与 MSAA/TAA/FXAA 不共存；SMAA 不做 jitter，也不写入或消费 TAA history。切换模式会重建
   整个 generation（`PipelineTopology` 含 AA mode）。
4. 真实 GL 用例与 shader 编译尚未执行；GPU 上的斜线/细边阈值、GL debug 消息和任何驱动差异
   仍需 slot 后确认。当前证据不能记 PASS。
5. 未测性能、显存峰值或多硬件；`NOT_EVALUATED` 保留。查找表在 JVM 内一次生成并常驻，
   生成耗时未作为性能结论。
6. 透明/VFX 的颜色与深度合同沿用既有 HDR composite；SMAA 只处理最终 display-referred 颜色，
   不做逐物体/透明层单独 AA，也不进入 UI 合成。
