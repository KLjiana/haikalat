## 范围与归属

- 归属：`render3d.vfx`。`VfxRenderer` 是既有 VFX 绘制 owner，新增投射贴花记录入口、惰性

## 显式控制

| 控制 | 默认 | 合法范围 | 说明 |
|---|---|---|---|
| `enabled` | `false` | — | 总开关；`active() = enabled && maximumDecals > 0` |
| `thickness` | `0.5` | `(0, 10]` | 沿贴花法线进入接收面的世界单位深度 |
| `surfaceOffset` | `0.02` | `[0, thickness]` | 贴花平面朝观察侧的前向容差 |
| `facingCosine` | `0.5` | `[0, 1]` | 接收面法线与贴花法线的最小对齐余弦 |
| `receiveBackFaces` | `false` | — | 为 true 时使用 `abs(dot)`，接受法线相反的面 |
| `alphaMask` | `true` | — | 覆盖率乘以贴花纹理 alpha；关闭则只使用 `ProjectedDecal.color` 的 alpha |
| `maximumDecals` | `32` | `[1, 64]` | 每帧有序绘制上限；超出时保留最近的一批 |

`ProjectedDecal` 的 `normal` 与 `up` 在构造时归一化并正交化；平行、零向量、非有限值、
非正尺寸、越界颜色或 `emissiveScale` 越界在 CPU 侧直接拒绝。`emissiveScale` 合法范围为
`[0, 8]`，大于 1 时写入 HDR 场景颜色，供 Bloom 等后续阶段消费。

## 接收面、面朝向与深度合同

单个贴花的局部基：

```text
right = normalize(up × normal)
volume(local) = center + right * local.x * size.x
                       + up    * local.y * size.y
                       + normal * (surfaceOffset - local.z * (thickness + surfaceOffset))
local.x, local.y ∈ [-0.5, 0.5]     // 接收矩形
local.z ∈ [0, 1]                   // 深度区间
```

等价地，接收点沿法线的有符号距离必须满足
`d = dot(receiver - center, normal) ∈ [-thickness, +surfaceOffset]`。
`+surfaceOffset` 允许贴花浮在表面上方，`-thickness` 限定穿透深度；两侧之外都拒绝。

像素处理顺序：

1. 采样 scene depth；`depth >= 1` 视为天空/背景，直接丢弃。
2. 用 `uInverseProjection`、`uInverseView` 从窗口深度重建世界位置。深度约定为 OpenGL
   窗口深度 `[0,1]`（近 0、远 1），NDC `z = 2 * depth - 1`；不读取 `gl_FragCoord.z` 作为
   接收面深度。
3. 用 `uInverseModel` 把接收点变换到贴花局部空间，做上面的体积测试。
4. 用 `cross(dFdx(receiver), dFdy(receiver))` 重建接收面法线并归一化；只有面向相机的面
   能在深度缓冲中可见，因此再按相机方向定向。没有 G-buffer 法线，这是本版明确公开的
   法线来源。
5. 面朝向过滤：默认要求 `dot(receiverNormal, decalNormal) >= facingCosine`；
   `receiveBackFaces=true` 时改用 `abs(dot) >= facingCosine`。垂直墙面因此被拒绝；
   薄墙背面的可见面法线与贴花法线相反，也会被拒绝。
6. 可选 alpha 掩码：`alphaMask=true` 时覆盖率乘纹理 alpha；否则只使用 `ProjectedDecal.color` 的
   alpha。覆盖率为 0 时不写像素。
7. 输出线性 RGB `texture.rgb * color.rgb * emissiveScale` 与覆盖率，按现有 ALPHA blend
   合成到当前场景颜色；不写深度。

深度量化、屏幕空间导数在轮廓处的不稳定以及深度重建误差都是公开的首版近似；被拒绝的
接收面不会产生未定义写入，测试用固定相机与世界点做独立断言。

## 重叠顺序与边界

每帧先构造 `ProjectedDecalPlan`：过滤零 alpha，按相机中心距离保留最近的
`maximumDecals` 个，再按距离远→近排序；距离相等时按 `sequence` 升序。这样重叠贴花
由近到远最后合成，alpha 结果确定；超出上限时丢弃最远的一批，而不是截断到剩余容量。
排序使用有界优先队列（容量即 `maximumDecals`），不会保留无界的逐帧绘制集合。

已知首版限制：排序键是贴花中心到相机的欧氏距离，不足以表达大尺寸贴花与非共面接收面的
逐像素深度关系；本版不承诺与场景透明物、其他批次或后期透明效果的全局排序，只保证同一
批次内的确定性。调用方应把投射贴花记录在不透明场景之后、需要覆盖的透明效果之前。

保守回退：

- 视图空间 `z >= 0` 的贴花锚点在相机后方，计划阶段直接丢弃且不记录绘制；即使巨大体积
  仍可能部分可见，也宁可缺失而不伪造覆盖。
- 屏幕外体积交给 GPU 光栅裁剪，不做可能误删大贴花的 CPU 包围盒剔除。
- 深度为清空值（天空/背景）或无有效接收面时丢弃；不退回平面屏幕 quad，也不在无深度
  目标时偷偷使用 `gl_FragCoord.z`。

## 集成入口与精确 no-op

```java
renderer.recordProjectedDecals(commands, settings, decals,
        projection, view, sceneDepthTexture, viewportWidth, viewportHeight);
```

- 调用方绑定颜色目标与 viewport，拥有 framebuffer 和深度纹理；渲染器只借用它们。
- 深度纹理绑定在 unit 1，贴花纹理绑定在 unit 0；每次绘制上传模型/逆模型、颜色、发光和
  法线，每批上传投影、逆投影、逆视图、相机位置、viewport、朝向阈值、背面/掩码开关。
- 关闭、空批次或全零 alpha 时在任何 `bindShader`/`bindTexture`/`drawMesh` 之前返回
  `ProjectedDecalStatistics(submitted, 0, submitted, 0)`；首次真正启用时才编译
  `projected-decal.vert/frag` 并创建内置立方体。
- 体积以 `frontFace(CW)` + back-face culling 绘制其远侧面；面片只覆盖体积的屏幕投影，
  片元再用重建接收点做体积测试，因此不是相机朝向的平面 quad。记录结束恢复
  `frontFace(CCW)` 与关闭 cull，不改变调用方后续的深度/混合语义。

## 资源生命周期与失效

- `VfxRenderer` 拥有惰性 shader 与体积网格，`close()` 统一关闭；构造失败时只关闭本次候选。
- 贴花纹理与既有 VFX 纹理共用 `VfxTextureCache`（LRU 32）；新增
  `prepare(EffectSnapshot, Collection<ProjectedDecal>)` 同时保留两套引用，避免快照预取把
  贴花纹理逐出。未调用 prepare 时仍保持既有惰性解析。
- 深度纹理、framebuffer、viewport 均为借用；resize 后调用方传入新的深度 id 与新尺寸即可。
  没有历史、上一帧状态或跨代缓存；失败帧没有可回滚的像素历史承诺。
- 不做逐帧资源重建；关闭总开关不会释放其他消费者共享的纹理。

## BLOCKED 根因与修复（2026-11-12）

- 现象：GL 运行记录 `drawn=1/drawCalls=1`，但贴花前后图像无变化；调试输出证明贴花几何
  覆盖像素，而片元全部因 `sceneDepth >= 1` 丢弃。
- 根因（fixture，不是生产投影矩阵/UV/alpha/blend）：`renderScene()` 记录
  `.drawMesh(quad)` 时没有 `bindMesh(quad)`。`CommandExecutor` 的 `DRAW_MESH` 调用
  `Mesh.drawBound()`，后者**不绑定 VAO**，依赖调用方先 `bindMesh`；无 VAO 的绘制在 core
  profile 下无效，接收面颜色/深度都没有写入。深度被清为 1.0 后，贴花 fragment 的
  `sceneDepth >= 1` 分支必然丢弃全部像素。之前记录的“直接读回深度 1.0”正是这个 fixture
  缺陷，而不是深度重建或贴花合同错误。
- 次要 fixture 缺陷：贴花 pass 把 `target`（其深度纹理正被采样）绑定为 draw framebuffer，
  形成纹理反馈环。现在改为绑定共享同一颜色纹理、无深度附件的 color-only FBO；深度纹理
  只作为采样输入。
- 新增判别用例：贴花绘制前在投影中心直接 `glReadPixels(GL_DEPTH_COMPONENT)`，断言
  `0 < depth < 0.999`；同时读回中心颜色，断言接收面 shader 写入的
  `(0.22,0.24,0.28)` 而不是清屏色 `(0.05,0.06,0.08)`；并在接收面矩形外（体积内但
  `local.x > 0.5`）断言逐字节不变。缺少 VAO 绑定时深度/颜色两个断言都会失败，不再让
  “无变化”被误判为贴花合同或集成 PBR 路径问题。
- 生产代码未发现需要修改的投影/UV/alpha/blend 缺陷；体积模型与 sorting 由
  `ProjectedDecalTest` 的 JVM 合同独立覆盖。

### 新增 case 与断言

1. `thinWallBackFaceIsRejectedOrAcceptedByReceiveBackFaces`
   - 相机在 -Z 侧看一块 4×4×0.5 的薄墙（`z ∈ [-0.4, +0.1]`）。贴花在原点、法线 +Z，
     体积沿 +Z 为 `[-0.6, +0.02]`；可见面 `z = -0.4` 在体积内，背面 `z = +0.1`
     在体积远端之外。
   - 可见面法线为 -Z，与贴花法线 +Z 点积为 **-1**。`receiveBackFaces=false` 时
     图像与基线**逐字节相等**（`assertExact`），深度逐位不变；`true` 时同一墙面
     产生可见变化，深度仍逐位不变，且矩形外探针不变。
2. `movingAndResizedReceiversKeepProbedDepthColourAndWorldPlacement`
   - 移动接收面到 `x = 1.6`：绘制前在**新中心**断言真实接收面深度
     （`0 < depth < 0.999`）与接收面颜色 `(0.22,0.24,0.28)`；在**旧屏幕位置**
     断言 `depth == 1.0` 且为清屏色——因此“旧位置不变”不是空基线。
   - 贴花仍锚定世界空间：新中心有变化、旧中心逐字节不变、深度不变。
   - 48×36 resize：resize 后中心与矩形外探针都重新做深度/颜色断言；中心有变化、
     深度不变、矩形外 3×3 不变。decal 尺寸降为 0.8 以让矩形外探针留出 ≥2 px 余量。
3. `transparentQueueCompositesOverTheDecalWithoutDepthWrites`
   - 场景特征使用同一 target 上的 **transparent queue** 覆盖层
     （`color=(0.1,0.8,0.2,0.5)`，ALPHA blend，关闭深度测试/写入）。
   - 四种顺序分别读回：接收面、decal、overlay、decal→overlay、overlay→decal。
     `overlay over decal` 必须等于用 decal-only 字节和 overlay 颜色独立算出的
     `0.5*src + 0.5*dst`（容差 1/255）；它与 overlay-only 不同（decal 在透明层
     下仍可见）；两种顺序结果不同（顺序确实生效）。
   - 每一步 `glReadPixels(GL_DEPTH_COMPONENT)` 都与接收面深度逐位相等：decal 和
     transparent queue 都不写深度。

### Alpha mask 像素覆盖

此前 `ProjectedDecalGlTest` 使用 bundled `scorch_01.png`（alpha 全 255），`alphaMask`
分支在像素层是 no-op。新增**测试专用**
`src/test/resources/vfx/test/decal-alpha-columns-8x8.png`：8×8、RGB 常量 240/160/64、
alpha 列 `[0, 0, 64, 128, 192, 255, 255, 255]`。它只在 test classpath 可见，不进入
`src/main/resources`，因此 `docs/licenses/assets.tsv` 无需新增行（`assetManifestGuard`
只校验 main/demo 资源）。

`alphaMaskCoverageKeepsMaskedTexelsAndTheUnmaskedComparison` 在同一 receiver/相机/贴花上
分别以 `alphaMask=true/false` 绘制，探针取 texel 列中心：

- `true`：alpha=0 的 texel 区域与基线**逐字节相等**；不透明列有可见变化；50% alpha 列的
  变化量严格小于不透明列且大于 0（覆盖率跟随纹理 alpha）；矩形外不变；深度不变。
- `false`：同一 alpha=0 区域出现变化，且不同 alpha 列在常量 RGB 下颜色**完全相等**
  （覆盖与纹理 alpha 无关）。
- 判别力：把生产 fragment 的 `if (uAlphaMask != 0)` 改成恒真后重跑，`false` 分支在
  「alphaMask=false must apply the decal where the texture alpha is zero」失败；恢复后 PASS。

### MSAA：documented rejection

`multisampledDepthHasNoSampleableTextureSoTheDecalFailsClosed` 在真实 4× MSAA
color+depth renderbuffer framebuffer 上完成 receiver 绘制后断言：

- `depthAttachmentIsTexture()` 为 false：MSAA 只能提供 depth renderbuffer，不能作为
  `sampler2D` 的 scene depth；
- `FramebufferDescriptor` 明确拒绝 multisampled depth texture（"multisampled depth
  textures are not supported yet"），因此后端不可能提供 decal 需要的单采样 window depth；
- 没有 depth texture 时 `recordProjectedDecals(..., 0, ...)` 按文档 fail-closed 抛
  `IllegalArgumentException`（"projected decals require a scene depth texture …"），
  不录制任何命令且无 GL error。

结论：MSAA 下投射贴花**按合同不可用**，不是静默错误；本版没有 MSAA depth resolve。

### TAA：decal 在 resolve 之前合成

`decalCompositesIntoTheTaaResolveInputWithoutDepthFeedback`：单采样 colour+depth 目标上
先绘制 receiver，再以该 depth 记录 decal，最后用生产 `TemporalAccumulationPass` +
`TaaHistory` 执行一次无历史 resolve：

- decal 改变目标像素，目标深度逐位不变（decal 不写深度）；
- resolve 写入自己的 history FBO，被采样的 scene depth 不附着在 draw framebuffer 上，
  因此没有 depth feedback loop；
- 无历史时 resolve 输出**逐位等于** decal 合成后的当前颜色：decal 位于 TAA 输入内，
  而不是在 resolve 之后追加；
- resolve 后 target 深度仍逐位不变；`glGetError == GL_NO_ERROR`，所有 fixture 资源关闭。

这是 resolve 顺序/兼容性 fixture；decal 仍未进入 `RenderPipeline` feature 图（本卡既有
限制不变），也没有证明宿主 TAA 合成路径的完整顺序。

### 阴影接收与遮挡

`shadowedReceiverKeepsContrastAndTheCasterDoesNotLeakTheDecal`：

- 测试 shader 绘制 -X shadow band / +X lit band 的 receiver。decal 不读 shadow map，因此
  darkening 来源不影响被测的混合合同；两侧都必须满足
  `after = (1 - coverage) * under + coverage * decalLinear`（独立 sRGB→linear oracle，
  容差 2/255），且 `afterContrast ≈ (1 - coverage) * beforeContrast`，shadow band 仍显著
  暗于 lit band——没有 double-darkening 或 bleaching。
- 真实不透明 caster quad 位于 decal 体积前方并遮挡部分接收面：caster 像素**逐字节不变**、
  深度逐位不变（体积测试拒绝，不泄漏）；未遮挡的 shadow band 仍按上述混合收到 decal。
