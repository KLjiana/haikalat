| 字段 | 内容 |
|---|---|
| 技术 ID／用户场景 | #35 Temporal Upscaling；低分辨率场景渲染到独立尺寸，再时域重建到目标显示尺寸并做可控锐化。首版默认关闭，关闭时颜色链与原生全分辨率路径逐字节一致。 |
| 当前基础／差距 | 已有 TAA resolve（jitter、velocity、previous surface depth、reactive、历史事务）与 #34 时域降噪，但两者都要求输入/输出同分辨率，没有独立低分辨率输入、重投影到稳定输出栅格、曝光/UI 语义或重建后的锐化。 |
| 首版范围 | **一个低分辨率 HDR 颜色输入**（线性 `RGBA16F`）+ 低分辨率单采样设备深度；可选 velocity/previous-depth 对、reactive mask、UI mask；输出为独立目标尺寸的线性 HDR 颜色。每帧一次 resolve MRT 写入历史，锐化开启时再加一次有界 unsharp。不做 ML/DLSS/FSR 集成、不做 UI 重绘/合成、不做多帧超采样控制器、不做输出深度重建。 |
| 输入 | 低分辨率颜色（线性 HDR）；低分辨率设备深度；可选稳定栅格 velocity（UV 位移）与前一帧稳定栅格正 view depth；可选低分辨率 reactive/UI `R8` mask；当前 jittered inverse projection、inverse view、stable view-projection；当前低分辨率 jitter（UV）；曝光标量（正数）；输入/输出 extent。 |
| 输出 | 目标尺寸 `RGBA16F` resolved 颜色（锐化关闭时直接作为下游输入，开启时为锐化源）+ 可选单缓冲 `RGBA16F` 锐化输出 + 双 slot 历史 state（正 view depth、曝光、valid flag）。历史颜色/state 只在整帧成功后提交。 |
| 模块与控制 | `subsystems.postprocess.upscale.TemporalUpscalingPass`（resolve/sharpen program + `ScreenQuad` + 私有历史/锐化目标）；`TemporalUpscalingInputs` 为 postprocess 域 advanced 合同；`TemporalUpscalingHistory` 为包内 owner。`TemporalUpscalingSettings` 与 `TemporalUpscalingSource` 位于 `subsystems.postprocess` 根包（与既有 effect settings 一致）。`PostProcessSettings` 追加 `temporalUpscaling` 组件，默认 `disabled()`；关闭时不创建 program、history、锐化目标或 draw。GPU owner：`GlResource`，所有 GL 资源操作与录制要求同一 GPU owner 线程/current context，入口 `ensureOpen` 校验；`PostProcessPipeline` 在候选装配期创建、按帧 begin/commit/fail、随 generation 退役。 |
| 坐标与深度 | UV 为 OpenGL 栅格 UV（原点左下）。输出栅格是**稳定显示栅格**；当前低分辨率颜色/depth 可能以 TAA jitter 光栅化，因此当前样本取 `outputUv + jitter`，世界重建用 jittered inverse projection，重投影后的 UV 直接落在稳定输出栅格（不需要再叠加前一帧 jitter）。设备深度经 inverse projection 还原为**正 view-space depth**；历史 state 存正 view depth，不存设备深度。颜色为线性 HDR；曝光不在此 pass 应用。 |
| 重投影 | 稳定输出位置（output UV）是唯一重投影原点；低分辨率纹素中心只用于取 depth/velocity/mask 与空间邻域。两种合同：① velocity 模式（velocity + previous depth 成对）：`previousStableUv = outputUv + velocity`，expected previous depth 取 previous depth 纹理在 `previousUv` 的低分辨率纹素；② prev-VP 模式（两者为零）：由当前设备深度与 **jittered inverse projection 在 `outputUv + jitter`** 还原 view/world 位置，用 pass 上一次成功帧保存的 stable view-projection 投影到上一帧稳定 UV，expected depth 由上一 inverse projection 从 previous clip 还原。两种模式都用 `length((previousStableUv - outputUv) * outputExtent)` 限制在 `maxReprojectionPixels` 内；越界/非有限/非正 w 直接拒绝。**首轮 GPU 证据显示曾把低分辨率纹素中心当作重投影原点，造成最多半个低分辨率纹素的系统性偏移；已修正并以 case b/c 的收敛与同 UV 对照覆盖。** |
| 拒绝与 clamp | 背景（设备深度 ≥ 0.999999）与非法深度不写 valid state；2×2 history tap 逐 tap 验证 valid、深度窗口 `max(1e-4, 0.02 * max(expectedDepth, 1))` 与相对曝光窗口；per-pixel reactive mask 或相对亮度跳变超过 `reactiveThreshold` 触发 reactive reset；UI mask 覆盖像素完全绕过历史与锐化。接受的历史 clamp 到当前低分辨率、深度一致邻域的 AABB（quality 控制半径 1/2/3），再按 `historyBlend` 与当前样本混合。 |
| 历史与事务 | 双缓冲（每 slot：RGBA16F resolved 颜色 + RGBA16F state）；锐化开启时另有一个单缓冲 RGBA16F 锐化目标。`beginFrame()` 标记 candidate；只有 `frameSucceeded()` 才交换 read/write；未记录帧的 commit 只丢弃 candidate；`frameFailed()` 丢弃 candidate 保留旧 read slot；`invalidate()` 清空 valid 与上一帧相机矩阵。`prepareResize` 先分配完整 candidate（历史对 + 锐化目标），`commitResize` 才替换并清空上一帧矩阵；candidate 关闭 retired 资源。`close()` 幂等。 |
| 独立参考 | JVM double 参考 `TemporalUpscalingReference`：row-major 前次 VP 投影、previous UV/预期 view depth、输出像素重投影距离、深度/曝光/相对亮度窗口、manual bilinear 重采样、bounded unsharp；固定输入有手算常数用例。GL case 的原生参考由解析场景在输出分辨率上用独立 CPU 超采样生成，空间双线性对照由 CPU 参考实现生成，不复用 pass 输出。 |
| 成本／回退 | 每成功帧 1 次 resolve MRT fullscreen draw；锐化开启时 +1 次 5-tap fullscreen draw。resolve 固定 ≤4 次当前颜色双线性 tap + 4 次 history tap + `(2r+1)^2` 次邻域 tap（LOW 9 / MEDIUM 25 / HIGH 49）。历史内存每输出像素 2 slot × 16 B = 32 B，1920×1080 约 66 MB；锐化目标另 8 B/px（约 17 MB）。未做 GPU 计时，性能 `NOT_EVALUATED`。回退：关闭时精确保持原颜色链；active 但缺少 source、HDR、AA 或 effect 组合非法时在候选装配期拒绝。 |

## 参数

| 参数 | 默认 | 校验 |
|---|---|---|
| `enabled` | false | 关闭时不创建任何资源或 Pass |
| `renderScale` | 0.5 | 有限且 [0.1, 1.0]；用于 `inputWidth/inputHeight` 的单一四舍五入规则，结果至少 1 px |
| `historyBlend` | 0.9 | 有限且 [0, 0.99]；`currentWeight = 1 - historyBlend` |
| `sharpness` | 0.25 | 有限且 [0, 1]；0 时完全不创建/记录锐化 program 与目标 |
| `reactiveThreshold` | 0.5 | 有限非负；相对亮度跳变超过则 reset，0 表示任意变化都 reset |
| `exposureThreshold` | 0.1 | 有限且 [0, 1]；相对曝光变化超过则拒绝历史，1 表示接受任意正曝光 |
| `maxReprojectionPixels` | 64 | 有限且 [0, 4096]；按输出像素计的稳定栅格位移；0 只接受零位移历史 |
| `quality` | MEDIUM | LOW=1 / MEDIUM=2 / HIGH=3，均为低分辨率纹素；shader 编译期上界 `TUS_MAX_NEIGHBORHOOD_RADIUS=3` |

`TemporalUpscalingSettings.depthTolerance(expectedDepth)` 与 shader 使用同一固定窗口；
`exposureRelativeChange`/`exposureAccepted`/`reactiveReset` 与 shader 使用同一相对公式，
便于宿主报告实际判定。

## 历史布局与双缓冲

| attachment | 格式 | 内容 |
|---|---|---|
| resolve slot 0 | RGBA16F | 线性 HDR resolved 颜色（rgb）+ 当前 alpha |
| resolve slot 1 | RGBA16F | `r` = 正 view-space depth；`g` = 帧曝光标量；`a` = surface valid flag |
| sharpen target | RGBA16F | 可选单缓冲锐化输出（仅 `sharpness > 0`） |

颜色只在历史 slot 中保存，没有额外的法线/矩附件：本 pass 的拒绝只依赖深度、曝光、
亮度跳变、reactive/UI mask 与邻域 AABB。与 #34 不同，这里没有法线输入，因此不含
法线拒绝；这是有意的首版限制，不是隐藏承诺。

## 锐化

`temporal-upscale-sharpen.frag` 为有界局部对比度 unsharp：取 resolved 结果的 3×3
十字邻域，`sharpened = center + (center - average) * sharpness`，再逐通道 clamp 到
`[min(local, center), max(local, center)]`，因此不会在既有对比度之外产生 halo。
UI mask 覆盖像素直接复制中心值。该实现是自写的 RCAS 风格对比度限制，不是
FidelityFX RCAS 的逐像素复制或移植；没有引入 SDK 代码或第三方资产。

## 与 TAA / #34 的边界

- **TAA**：TAA 仍负责全分辨率 jitter/颜色 resolve。开启 temporal upscaling 时，颜色链
  拒绝全分辨率 TAA/MSAA；低分辨率场景自己的 jitter/TAA 由宿主在低分辨率目标上完成，
  其 jitter 通过 frame pose 传入本 pass。
- **#34 Temporal Denoising**：现有 `TemporalDenoisePass` 绑定 SSR 噪声信号且输入/输出同
  分辨率；本 pass 不消费、不共享其历史，也不改变它的程序/附件。两者同时开启会被组合
  校验拒绝（denoise 需要全分辨率 surface 输入）。
- **不共享历史**：本 pass 只服务低分辨率颜色重建；其他信号（SSR/GI/云）不得共享其
  output/history。不同放大倍数或新 input target 必须新建 generation。

## Pass 顺序与组合拒绝

HDR 链（active 时）：

```
TemporalUpscalingPass（低分辨率颜色/depth/velocity → 输出尺寸）
  → ToneMapping
  → [Vignette] → [FilmGrain] → [ChromaticAberration] → [FXAA|SMAA] → Present
```

**首版不支持** `AutoExposure` 与 `Bloom`：upscale pass 是 pass-owned external target
producer，`BloomChain` 无法从 managed color target 取尺寸（只对 TAA 有既有特例），
`AutoExposureChain` 则没有可读的 managed luminance source。二者在 active upscaling 时
装配期拒绝，不是静默跳过。若后续需要，应泛化这两个 chain 对外部 target 的支持，而不是
在本包内复制一套 pipeline。

`PostProcessPipeline` 在候选装配期（创建任何 GPU owner 之前）拒绝：

- active 但没有 `TemporalUpscalingSource`；disabled 但提供了 source；
- 非 HDR（本 pass 的混合/钳制在预曝光线性 HDR 中定义）；
- 全分辨率 `TAA`/`MSAA`（重复时域解析或绕过单采样低分辨率源）；
- 非空 HDR VFX composite（低分辨率场景必须自己拥有 VFX 合成）；
- active 的 `fog`、`screenDistortion`、`depthOfField`、`motionBlur`、`ssr`、
  `temporalDenoise`（这些效果需要全分辨率 surface 输入）；
- active 的 `lateSurface`/reactive producer（低分辨率场景必须自己产生 reactive mask
  并通过 `TemporalUpscalingSource.reactiveTexture` 提供；全分辨率 late pass 不支持）；
- `settings.bloomSettings().enabled()` 与 `ExposureMode.AUTO`（见上，首版仅支持
  manual exposure + 无 Bloom）；#34 denoise 同属 external-target producer，同一校验
  也拒绝它的 Bloom/自动曝光组合；
- source 的宽/高超过输出 extent。

`lateSurface`、低分辨率 jitter 与低分辨率 source 是接线硬前提：宿主必须让低分辨率场景
自己完成 reactive 输出，并把该帧的低分辨率 jitter 写入 `TemporalFramePose.jitterUvX/Y`
（active upscaling 拒绝全分辨率 TAA/MSAA）。缺少这些前提时装配期拒绝或按零 jitter
解释，不能假定 production 会自动推断。

禁用时 `passNamesFor`、执行顺序、external import 与每帧 draw 完全不变（GL case e 以
逐字节比较覆盖）。`passNamesFor`/`finalPassNameFor` 是**基线**预测器，active upscaling
时不再包含 upscale pass；实际顺序必须读取 `RenderGraph.description()` 与
`finalPassName()`。

`PostProcessPipeline.prepareResize` 在 upscaling active 时明确拒绝：低分辨率 source 是
generation 稳定的借用资源，原地 resize 会把旧 source 配到新输出尺寸；宿主必须构建
candidate generation。pass 本身的 `prepareResize`/commit 事务仍完整可用（GL case d）。

## 两轮 GPU 证据与修复（2026-11-12）

Orchestrator 的串行 GPU 首轮执行了 `TemporalUpscalingPassGlTest`：**4 PASS / 2 FAIL**，
失败只出现在时域收益断言上（不是 shader 编译或资源错误）：

1. case b：`temporal 0.057814753 vs spatial 0.052018884`（时域比单帧双线性更差约 11%）。
2. case c：`tracking 0.053644927 vs zero-budget control 0.028904305`（有历史比重投影错误的
   对照更差）。

诊断（CPU double 独立复算，结果与 GPU 读数在 1e-5 内一致）：

- **实现缺陷**：prev-VP 路径把低分辨率纹素中心 `inputUv` 作为世界重建/重投影原点。
  一个输出像素落在低分辨率纹素内部时，历史会被系统性地查询到相邻输出像素（最多半个
  低分辨率纹素），相当于每次重投影多一次模糊。改为稳定输出位置 `outputUv`（世界重建
  使用 `outputUv + jitter`）后，case b 从 0.0578 降到 0.0429，case c 从 0.0536 降到
  0.0453。
- **度量缺陷（case c）**：`maxReprojectionPixels=0` 会拒绝全部历史，输出退化成每帧空间
  结果；在移动的高频内容上，空间结果天然比任何时域累积更锐，因此它不是“无重投影”对照。
  现改为 **same-UV 速度模式对照**（velocity=0 + 合法 previous depth），历史被接受但不
  重投影；实测 tracking 0.0453 vs same-UV 0.0596，重投影仍带来 24% 改善，并新增“相机
  停止后 24 帧收敛回当前帧（0.030）”的 ghost 回归。
- **误差下界校准（case b）**：在 18/10 cycles（超过低分辨率 Nyquist）的固定 fixture 上，
  8 相位双线性均匀平均的 MAE 是 0.0422；这是“同核相位平均”的最优可达误差（下界），
  任何同核实现都不可能把误差压到它以下。原“< 单帧 ×0.7 = 0.0364”的阈值低于 oracle，
  属于不可达断言。现改为：时域严格优于单帧、优于单帧 15%（实测 17.5%）、接近 oracle
  （≤ oracle×1.10，实测 1.017），并单列 oracle 优于单帧 15% 的证据。这不是放松收益
  断言，而是用可计算的独立误差下界替换了不可达阈值。

修复 commit 及其 JVM 结果见文末；修复后的 GL 由 Orchestrator 串行重跑。

### 第二轮 GPU 证据与修复（2026-11-12）

重跑：**5 PASS / 1 FAIL**，失败推进到 oracle 自身：
`the phase-averaged reference itself must improve on one frame: 0.05354056 vs 0.05201888`。
CPU 复算确认：

- oracle 采集了全部 8 个相位并等权平均，但 `bilinearUpsample` 在采样时**漏加了 jitter
  偏移**：它用输出 UV 去采样“内容位于纹素中心 − jitter”的每帧 fixture，等于把 8 个平移
  副本平均，结果反而比单帧更差（CPU 复现 0.05354056，与 GPU 完全一致）。
- 修正：oracle 按 production 的 `outputUv + jitter` 采样（`bilinearUpsample(input, jitterUv,
  jitterUv)`），CPU 复算回到 0.04216472；单帧仍为 0.05201888。
- 新增 JVM 独立覆盖 `jitteredReconstructionMustIncludeTheSampleOffset`：固定 2×2 线性
  ramp 上，带 jitter 偏移采样恢复稳定值 0.25，不带偏移得到 0.0；防止 oracle/参考再次
  漏掉采样偏移。
- 断言不变：时域 < 单帧、< 单帧 ×0.85、≤ oracle ×1.10、<0.045；oracle < 单帧 ×0.9。

## 明确限制与未验证项

1. 首版是**时域重建近似**，不是超采样控制器：没有自适应采样数、没有动态分辨率控制器、
   没有每像素置信度或方差估计；quality 只控制邻域 clamp 半径。
2. 没有 ML/DLSS/FSR/帧生成，也没有光流或神经网络推理；`historyBlend` 是固定指数混合。
3. 不做 UI 重绘或 UI 合成。UI mask 仅用于让已经包含在低分辨率颜色里的 UI/覆盖层绕过
   历史与锐化；真正清晰的 UI 仍应在 tone mapping 之后以目标分辨率合成。
4. 背景/天空（设备深度 ≥ 0.999999）不累积历史，只做空间放大与锐化；因此无限远背景在
   相机旋转时不会有本 pass 的时域收益。这是保守选择，避免无深度对应的错误重投影。
5. 低分辨率颜色/depth 的双线性/最近采样没有深度感知 upsample；强深度边缘可能在
   邻域 clamp 与深度拒绝作用下保持有界，但会出现有限的边缘混合。
6. 时域累积对**快速移动的高频内容**本身是低通：0.9 历史权重在 1.4 输出像素/帧的运动下
   仍会产生有限运动拖尾。有效诊断是“正确重投影 vs 同 UV 历史”的相对改善与停止后收敛，
   而不是要求时域结果在任何运动 fixture 上都优于每帧空间结果；后者在信息上不等价。
7. 2× 放大且低分辨率信号含超过自身 Nyquist 的高频时，8 相位双线性平均给出的误差下界
   （最优可达误差）约为单帧双线性的 0.81×（本 fixture 实测 0.0422 vs 0.0520）。本 pass
   目标接近该下界（实测 0.0429），不做频率域/迭代反投影式超分辨率，也不会宣称突破该
   下界。
8. velocity 合同采用稳定栅格 UV 位移 + 前一帧稳定栅格正 view depth；若生产者提供的是
   其他空间或 jittered 栅格的前一深度，深度拒绝会偏保守或错误，必须按合同适配。
9. 曝光只是拒绝信号，不在此 pass 应用；首版组合只支持 manual exposure（自动曝光在
   装配期拒绝，见“Pass 顺序与组合拒绝”）；自动曝光快速变化时由相对亮度阈值兜底属于
   未来接线，不宣称当前可用。
10. 本 pass 不重建输出深度；下游任何需要全分辨率深度的效果都被组合校验拒绝。低分辨率
    场景必须自己完成 fog/VFX/扭曲/透明等与深度相关的合成。
11. 历史内存固定：双 slot 32 B/输出像素，1920×1080 约 66 MB；锐化目标另约 17 MB。
    未做 GPU 毫秒/带宽测量，性能与显存峰值 `NOT_EVALUATED`。
12. 生成代切换（设置/候选重建）会新建 upscaler 并从 invalid history 开始，不跨代转交
    历史；resize 走 candidate 事务并清空上一帧矩阵。切换后短时重新收敛是预期行为。
13. `PostProcessPipeline.prepareResize` 在本特性 active 时明确失败，宿主必须重建
    generation；这是外部 source 所有权的保守选择，不是遗漏。
14. JVM PASS 不等于 GL PASS。Orchestrator 串行 GL 已在 runId `9e46cd77`（gitHead

    未自行执行 GPU 测试，后续只改测试/文档不重写该历史 PASS。
