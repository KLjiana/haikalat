## 已知性能回退

正式 release readiness 的唯一失败项是历史静态场景基线：

| 场景 | v0.17.2 基线 | 0.19.4 首次候选 | 独立重跑 |
| --- | ---: | ---: | ---: |
| `static-all-visible` CPU median | 2.977 ms | 3.301 ms | 约 3.567 ms |

独立重跑仍超过基线 5% 上限，因此 v0.20 M7 必须重新测量并解释或消除该回退。
其他静态场景没有同等级回退：`static-all-hidden` 为 0.044 ms，
`static-mostly-hidden` 为 0.324 ms。

## 四类行为基线清单

- 公共 API：以 `docs/architecture/public-api/*.allowlist`、`publicApiGuard` 和
  `architectureGuard` 为准；v0.20 不得产生未记录的 public 类型或删除。
- Demo 输出：Modern UI 的上述节点、quad、draw、像素和帧耗时保持不回退；
  旧 `UiDemo`、场景 Demo 和 glTF Demo 仍以现有 integration 结果为准。
- GL 日志：HIGH=0，MEDIUM 必须有 policy 分类；不得新增 `GL_INVALID_*`。
- 资源生命周期：关闭、resize、scene reload、UI attach/detach 之后 owner 数量回到基线，
  不得出现 use-after-close、跨 context 销毁或悬挂线程。
