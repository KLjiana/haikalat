## 估计器与统计性质

对一个像素、一个样本，每层独立接受（概率 `p_i`），并只保留最近接受层。于是：

```text
P(最终显示层 = i) = p_i · Π_{j 比 i 更近} (1 - p_j)
E[颜色]           = Σ_i p_i c_i Π_{j 更近}(1 - p_j) + T · background
T                 = Π_i (1 - p_i)
E[覆盖率]         = 1 - T
```

这与 back-to-front alpha 合成在 `p_i = alpha_i` 时完全一致；因此本 Pass 在**不启用时域 clamp/拒绝**时是排序 over 的无偏 Monte Carlo 估计。与 #28 不同，它不是单一加权平均，颜色误差来自采样方差而非层间颜色平均；与 #26 不同，它不需要预先排序，逐样本私有深度决定最近者。

每帧 `N` 个独立样本的覆盖率估计方差为 `p(1-p)/N`（`p` 为单层覆盖或合成覆盖率）。时域运行平均在 `n` 帧后的有效记忆约 `(1+w)/(1-w)`；`w = n/(n+1)` 时等价于等权平均前 `n+1` 帧。固定种子/帧序/样本序/像素/实例的阈值是确定的；换种子或换样本数只改变采样序列，不改变期望。

**误差界**：GL case d 用独立排序 over 参考，断言随机估计的 256 像素区域均值在 `0.05` 内；相邻 WBOIT 用两层解析界 `a_near²·a_far/(a_near+a_far)·|c_near-c_far|` 断言。对多层/多颜色集合，随机估计的偏差只在时域 clamp/拒绝边界出现，不承诺逐像素精确排序。

## 帧与事务合同

1. `record(cmd, surfaces, inputs, settings)`：绑定并清除私有样本/帧和附件，执行 N 个样本与帧和，再把时域 resolve 写入私有 write history slot。它不绑定、不读取也不写入调用方目标或共享深度。
2. 调用方绑定自己的 HDR 目标与视口，调用 `resolve(cmd, settings)` 做预乘合成；它不绑定 framebuffer。
3. 调用方执行命令缓冲区，然后 `frameSucceeded()` 或 `frameFailed()`。只有成功提交才交换历史 read/write slot、推进 `historyLength` 与上一帧 stable view-projection。
4. `invalidate()` 显式丢弃历史并重置帧序列；大相机位移在 `record` 内自动触发同一路径。`resize` 只允许在无 pending 帧时调用（否则拒绝），先建候选再替换。
5. `record` 与 `resolve` 在 `settings.active() == false` 时是精确 no-op：零 GPU work，不推进历史；`frameSucceeded` 对没有 record 的帧同样是 no-op。

## 与 OIT / 排序的边界

- #26 排序：需要精确前后顺序的 alpha 粒子走深度键排序；本 Pass 不排序、不交换几何，最近接受层由逐样本深度决定。同一集合只能选一条路线。
- #28 WBOIT：解析使用单一加权平均色；本 Pass 每样本只保留最近层，颜色期望是排序 over，因此多层异色时**没有** WBOIT 的加权平均误差，但有采样噪声。两者的共同点是都只处理显式集合、都不写共享深度、都不承诺折射/介质。
- #37 不是“精确透明解”：它是无偏估计（在 `gamma=1/threshold=0` 且无时域 clamp 时），有可见噪声；时域平均降低噪声但引入有界拖影可能；同深度共面层由绘制顺序决定（`GL_LESS`），本版不承诺处理。
- 不透明遮挡：本 Pass 的私有深度只包含所选透明集合，**不做不透明深度测试**；被不透明体遮挡的表面如果进入集合仍会贡献。调用方必须预先裁剪可见集合，或后续另立任务把共享深度复制进私有深度。

## 接线合同（Integrator）

1. `RenderFeatureSettings`/`RenderFeaturesControl` 增加 `StochasticTransparencySettings` 字段与
   `stochasticTransparency(...)`/`applyStochasticTransparency(...)`，默认 `disabled()`；只在
   `active()` 时构造 `StochasticTransparencyPass(width,height,settings)`。`maximumSurfaces` 改动需新 Pass。

   `record`（自有附件）与 `resolve`（调用方已绑定 HDR 目标）；`record`/`resolve` 必须同帧同序执行。
3. 集合：使用与 #28 相同的 `OitSurface` 展开；同一集合在同帧只能选排序 / WBOIT / 随机透明之一。
   调用方负责不透明遮挡裁剪、可见性与容量上限（`maximumSurfaces`）。

   stable 场景深度；相机切镜/场景不连续时调用 `invalidate()`（大位移会自动触发）。本版不支持 TAA
   jitter 光栅；若宿主的共享深度是 jittered，必须改为 stable 深度或另行适配。
5. 生命周期：`resize` 在候选 generation 装配期调用；每帧 `frameSucceeded`/`frameFailed`；总开关
   关闭时停止构造/录制并交回原队列。
6. `docs/architecture/public-api/README.md`、`RenderPipeline`、`RenderFeaturesControl`、
   `RenderFeaturePolicy`、`PipelineFeaturePolicy`、聚焦任务筛选、`config/gl-debug-policy.tsv`、
   `docs/planning/haikalat-multi-agent-status.json` 均按任务约束未修改；README 叙述由 Integrator 补。

## 明确限制与未验证项

1. 有噪声：单帧 N 样本的覆盖率方差 `p(1-p)/N`；低 alpha/低样本数需要更多帧或更多样本。时域积累降低噪声但有界滞后。
2. 时域拖影/延迟：重投影使用借用的**不透明场景深度**，不是透明表面自身的每对象 velocity；透明表面与场景深度不同深、快速对象运动或隐藏/显露时只靠邻域 clamp、覆盖率冲击与位移预算把误差限制在有界范围，不承诺零拖影。新进入集合的像素从零历史开始，16/17 权重的残余为 `0.941^n`（24 帧后 23%），需要约 40+ 帧才能完全收敛；这是积累延迟，不是永久 ghost。相机切镜必须 `invalidate()`（大位移自动兜底）。
3. 不是精确排序：逐样本最近接受层由私有深度决定，但同深度共面层由绘制顺序决定；不承诺任意透明交错、折射/透射或逐像素正确前后关系。
4. 不做不透明遮挡：不采样/不写共享深度；被不透明体遮挡的表面若进入集合仍贡献。调用方必须预裁剪。
5. 稳定栅格：本版不处理 TAA jitter；共享深度/矩阵必须是 stable 栅格。若宿主使用 jittered 深度，重投影/深度拒绝会偏保守或错误。
6. 单采样：不做 MSAA 逐样本累积；目标必须是单采样 HDR（或在 MSAA resolve 之后）。
7. `coverageGamma != 1` 与 `alphaThreshold > 0` 改变能量，不是无偏估计；文档把期望改为以 `p_i` 为层 alpha 的 over 合成。
8. 反应性窗口是覆盖率冲击，不是颜色冲击：颜色变化由当前邻域颜色 clamp 兜底；颜色窗口会在随机混合色上误触发，故不提供。
9. 时域支持输出颜色/覆盖率/覆盖率矩（mean + second moment），但不做自适应采样预算；#41 若消费这些矩需另立接线。
10. 成本未测：N 次表面 + N 次全屏帧和 + resolve + composite；内存约 76 B/px（1080p ~158 MB）。性能、显存峰值、真实粒子集合成本均 `NOT_EVALUATED`。
11. `RenderPipeline`/`RenderFeaturesControl`/`RenderFeaturePolicy`/`PipelineFeaturePolicy` 未改（禁改文件）；统一请求入口、effective/不可用原因、Demo、公共 API README 与状态 JSON 由 Integrator 接线。
12. 真实 GL 未执行；9 个 GL case 的编译、驱动行为、读回数值与设备/驱动身份等待 GPU 队列。JVM 通过不等于 GL 通过。
