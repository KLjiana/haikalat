## 精确扩展与入口点逻辑

`VariableRateShadingCapability.inspectCurrent()` 在**当前 context** 上执行，绝不从
GPU 名称、RTX 标签、驱动版本或 OpenGL 4.6 核心版本推导支持：

1. `glGetIntegerv(GL_NUM_EXTENSIONS)` + 逐项 `glGetStringi(GL_EXTENSIONS, i)` 枚举
   **精确字符串**：
   - `GL_NV_shading_rate_image`：已实现路径；
   - `GL_EXT_fragment_shading_rate`：检测并报告，不实现；
   - `GL_NV_primitive_shading_rate`：仅诊断。
2. NV 入口点：`GLCapabilities.GL_NV_shading_rate_image` 为真，且 LWJGL 解析的
   `glBindShadingRateImageNV`、`glShadingRateImagePaletteNV`、
   `glGetShadingRateImagePaletteNV`、`glShadingRateImageBarrierNV` 四个函数地址非 0。
3. 仅当 NV 字符串 + 三个入口点都成立时才查询
   `GL_SHADING_RATE_IMAGE_TEXEL_WIDTH_NV`、`..._TEXEL_HEIGHT_NV`、
   `..._PALETTE_SIZE_NV`、`GL_MAX_COARSE_FRAGMENT_SAMPLES_NV`；
   `texelWidth>0 && texelHeight>0 && paletteSize>=2` 才判 `SUPPORTED_NV_IMAGE`。
4. EXT 入口点：通过 `GL.getFunctionProvider().getFunctionAddress` 查询
   `glShadingRateEXT`、`glFramebufferShadingRateEXT`；两者存在只判
   `EXT_DETECTED_NOT_IMPLEMENTED`。原因：LWJGL 3.3.3 没有
   `EXT_fragment_shading_rate` 生成绑定，若强行用未封装的 native 函数指针调用会
   绕过项目受控 GL 层；NV image 路径在目标 NVIDIA 驱动上提供真实 per-tile 选择性路径。
5. `unsupportedReason()` 对无 context、NV 缺入口点、NV limits 非法、仅 EXT、完全不同
   分别给出明确文本；`summary()` 输出 extensions/entryPoints/limits 与
   `active=`/`fallback=` 结果。

能力状态（纯函数 `evaluate(...)`，可无 GL context 测试）：

| 条件 | status | 有效路径 |
|---|---|---|
| 无 context | `UNAVAILABLE` | 无；调用方不得报告活跃 VRS |
| NV 字符串 + 4 入口点 + 合法 limits | `SUPPORTED_NV_IMAGE` | 创建 `R8UI` rate image 并包住 SSS draw |
| 仅 EXT 字符串 + 2 入口点 | `EXT_DETECTED_NOT_IMPLEMENTED` | 回退：consumer 全速率；状态明确 |
| 其余（含只广告 NV、入口点缺失、limits 非法） | `UNAVAILABLE` | 回退：consumer 全速率；状态明确 |

## 实现路径

### rate image 与 tile map

- `VariableRateShadingPlan.create(width, height, settings, texelW, texelH, paletteSize)`：
  - `tilesX = ceil(width/texelW)`，`tilesY = ceil(height/texelH)`；
  - 中心 fine 比例为 `fineRegionFraction`，每轴至少 1 个 fine tile；`Math.round(tiles * fraction)`
    后 `clamp(1, tiles)`，起始位置二分居中；
  - 其余 tile 为 coarse；必须同时存在 fine 与 coarse，否则拒绝（目标小于 2×2 个 rate
    texel 时 fail-closed，而不是静默全 fine）；
  - palette 固定为 `[fineRate.glValue(), coarseRate.glValue()]`；
  - `MAX_TILES = 1_048_576` 防御性上限。
- `VariableRateShadingPass` 用 `Texture2D.createR8ui(tilesX, tilesY)` 创建不可变
  `R8UI` 单 mip 纹理（整数纹理按 GL 完整性规则使用 `NEAREST`），通过
  `uploadRegion` 以 `GL_RED_INTEGER/GL_UNSIGNED_BYTE` 上传 index map。
- `R8UI` 纹理的 texel 值是 **viewport-0 palette 的下标**；rate image 绑定到当前 draw
  framebuffer，覆盖 framebuffer 的 tile 网格。

### 真实消费者与配置

`PostProcessPipeline` 在装配期：

1. `effects.variableRateShading().active()` 且顶层 `settings.hdrEnabled()` 且
   `effects.subsurfaceScattering().screenSpaceActive()`；否则抛
   `variable rate shading requires the declared screen-space subsurface scattering consumer`
   或 `... requires HDR tone mapping`。
2. 查询 capability；`ACTIVE_NV_IMAGE` → 创建 `VariableRateShadingPass` 并加入 owned；
   `FALLBACK_UNSUPPORTED` → **不创建任何 VRS 资源/命令**，只设置
   `variableRateShadingStatus = "fallback:..."`。
3. `SUBSURFACE_SCATTERING_PASS` executor 中：
   `recordBegin(cmd)` → `SubsurfaceScatteringPass.recordIntoCurrentTarget(...)` →
   `recordEnd(cmd)`。作用域在同一 FBO bind 之后、SSS draw 之前/之后执行。

`variableRateShadingStatus`：

| 请求/能力 | 状态前缀 | 资源与命令 |
|---|---|---|
| `enabled=false` | `disabled` | 无 capability 查询、无 texture、无 begin/end |
| enabled + NV 完整 | `active:fine=1x1 coarse=2x2 centre=50%:...` | 一个 rate image；每帧 begin/end |
| enabled + 无 NV 路径 | `fallback:<request>:<reason>` | 无 rate image；SSS 全速率；不得记作 VRS 验收 |

### 宿主状态保存/恢复契约

因为命令流先录制后执行，rate image binding 和 palette 不能在录制时安全读取；实现把
保存/恢复放进执行期：

- `CommandBuffer.beginVariableRateShading(rateImage, palette)` /
  `endVariableRateShading()` 是 typed 命令；同一 command buffer 内必须成对。
- `CommandExecutor` 在执行到 begin 时调用 `VariableRateShadingState.begin`：
  1. 捕获当前 `GL_SHADING_RATE_IMAGE_BINDING_NV`；
  2. 用 `glGetShadingRateImagePaletteNV(0, 0, n)` 捕获将被覆盖的 viewport-0 palette 项；
  3. 写入新 palette（`glShadingRateImagePaletteNV`）并
     `glBindShadingRateImageNV(rateImage.id())`。
- end 时 `Snapshot.restore()` 恢复原 image 和原 palette 项；`Snapshot` 幂等。
- 执行异常/缺少 end 时，`CommandExecutor.finally` 逆序恢复所有未结束作用域，并把清理
  失败作为 suppressed 保留；缺少 end 的正常流在 loop 结束后抛
  `unbalanced beginVariableRateShading`。
- 不修改 sample order、viewport 数量、scissor、混合或 texture unit 状态；bind 的
  rate image 不占用普通 texture unit。
- rate image 由普通 texture upload 产生；NV 的 raster 读取要求显式排序点，因此 bind 后调用
  `glShadingRateImageBarrierNV(true)`（同步形式，首版正确性优先；image 创建后静态，通常
  没有待完成上传）。若未来改用 image store/GPU 生成，需按写路径重新确认同步语义。
- resize 是 candidate-first：新 image 完整分配+上传后，`commitResize` 才替换 active
  image 并关闭旧 image；uncommitted candidate 的 `close()` 只释放 candidate image。
- `VariableRateShadingPass.close()` 幂等删除自有 texture；`PostProcessPipeline.close()`
  通过既有 owned 列表释放。

## 导数 / gl_FragCoord / 细线 / 透明 caveat

- 粗 rate 下一次片元着色调用覆盖整个 footprint，输出被写入该 footprint 内的像素。
  因此：
  - 依赖 `gl_FragCoord` 的逐像素细节会在 footprint 内变为常量；
  - 1 像素细线、发丝、细边框可能被**加宽或丢失**；
  - 透明/alpha 边缘的 alpha 也按 footprint 复制，透明渐变的分辨率下降；
  - `dFdx/dFdy/fwidth` 与隐式 LOD 只对应这次调用的区域，不能假定仍是逐像素导数。
- 声明的 SSS 消费者已把颜色/深度采样改为显式 `textureLod(..., 0.0)`（surface mask/normal
  本来就是 `texelFetch`）；所有输入只有 1 个 mip level，故 1x1 路径行为不变，但 coarse
  footprint 不再依赖隐式导数选择 LOD。
- UI/文本在颜色链之后合成，本实现不把 VRS 作用到 UI/文本；若未来把 VRS 扩到文本，
  必须单独比较粗 rate 下的文字可读性，不能沿用本卡片结论。
- 首版消费者是**单采样全屏 Pass**；MSAA、alpha-to-coverage、逐 sample shading、几何
  细线覆盖不在本实现/验证范围。

## 与 #33 / #41 / HDR 场景的边界

- **#33 SSS**：VRS 只包住其全屏 draw，不改变 SSS 的 mask、深度/法线拒绝、半径或
  pass 顺序；SSS 关闭时 VRS 请求被拒绝，而不是退化成无消费者的全局开关。
- **#41 Adaptive Sampling**：本实现是屏幕区域的静态 rate map，不是误差/方差驱动或
  采样预算分配；两者不共享状态，也不把质量档切换称为自适应。
- **HDR 场景**：本 worker 禁改 `RenderPipeline`，没有把 VRS 包到 PBR 几何 pass；若要
  覆盖几何细线/透明，应由 Integrator 在场景 pass 增加同型作用域并单独验收，不能引用
  本卡片的 SSS 结果。
- **EXT 路径**：只检测、报告，不实现，不把 EXT 广告当作支持。

## Pass 顺序

```
Geometry → [HdrResolve] → [Fog] → [VfxComposite] → [ScreenDistortion] → [TAA]
  → [SubsurfaceScatteringPass wrapped by VRS begin/end] → [SSR]
  → [TemporalDenoise] → ... → ToneMapping → ... → Present
```

VRS 不新增 graph pass；`passNamesFor`/执行顺序在 disabled/fallback 下与基线完全一致。

  必须明确打印 `NOT_EVALUATED: implemented NV shading-rate path unavailable: ...` 并
  abort（JUnit skipped）；真实路径 case 不得通过。`pipelineReportsActiveOrFallback...`
  仍会验证 fallback/disabled 分支，但该分支只是回退证据，不是 VRS PASS；
- `coarseTilesAreBlockwiseAndTheFineCentreStaysFullRate` 的 begin/end 恢复断言与
  `assertCoarseBlocksAreUniform` 必须真实通过，才能说明 NV 路径生效；
- `thinLineDerivativeAndTransparencyCaveatsAreVisible` 是负对照，只证明粗 rate 的可见
  代价，不能作为生产画质通过；
- `realSubsurfaceFullScreenConsumerIsShadedAtTheTileRate` 用真实 `SubsurfaceScatteringPass`
  输出验证消费者，不是仅 synthetic probe；
- `pipelineReportsActiveOrFallbackAndDisabledIsANoOp` 的 active/fallback 分支与
  `PostProcessPipeline` 关闭资源计数。

JVM PASS 不等于 GL PASS；在 GPU 队列实际执行前，本功能保持 `NOT_EVALUATED`。

## GL case 设计

| case | 断言 |
|---|---|
| `capabilityIsQueriedAndUnsupportedIsReportedAsNotEvaluated` | 打印精确 `capability.summary()`、`GlDebug.contextInfo()`；断言 context/状态/原因自洽；不支持时明确 `NOT_EVALUATED` 并 abort（skipped），不返回 active。 |
| `coarseTilesAreBlockwiseAndTheFineCentreStaysFullRate` | `GL_RGBA8` 128×128 probe；2×2 coarse 区域每 2×2 block 四字节相等，中心 fine 区域至少一个 block 有差异；begin 前/end 后 `GL_SHADING_RATE_IMAGE_BINDING_NV` 与 palette 相等；关闭作用域后的下一次全速率 draw 与 baseline 逐字节相等；`GL_NO_ERROR`。 |
| `thinLineDerivativeAndTransparencyCaveatsAreVisible` | 1 像素竖线：fine 每行恰 1 个线像素，coarse 数量不同（加宽/丢失）；导数通道在 coarse 区域与 fine 至少有可见差异；alpha 渐变 + blend 下 coarse block 仍均匀、fine 保留变化；`GL_NO_ERROR`。 |
| `realSubsurfaceFullScreenConsumerIsShadedAtTheTileRate` | 真实 `SubsurfaceScatteringPass` + 合成颜色/深度/法线/mask，VRS 包住其 draw；输出 finite；coarse 区域 2×2 block 浮点逐位相等，fine 区域保留逐像素差异；`GL_NO_ERROR`。 |
| `pipelineReportsActiveOrFallbackAndDisabledIsANoOp` | 支持时 `active:true`，否则 `active:false` + `fallback:`；disabled 为 `"disabled"` 且不创建 VRS 资源；无 SSS 消费者时装配期 `IllegalArgumentException`；支持时 `pipeline.resize` 走 candidate-first rate-image 替换并保持 active；close 后 `GlDebug.resources()` 回到 baseline；`GL_NO_ERROR`。 |

## 明确限制与未验证项

1. **仅实现 NV image 路径**；`GL_EXT_fragment_shading_rate` 只检测/报告，不实现，也不
   手写 native 函数指针。目标驱动若不广告 NV，功能保持 fail-closed 回退，不能声称 VRS。
2. **没有逐 draw / 逐 primitive rate**，也没有 combiner ops、rate image 的 GPU 写入或
   内容/误差驱动选择；tile map 是静态屏幕中心矩形。
3. 消费者是 **SSS 全屏 post-process**，不是 HDR 几何场景；不覆盖几何细线、透明网格、
   MSAA sample shading、alpha-to-coverage 或 UI/文本。
4. 细线/导数/透明 case 是**负对照**，证明粗 rate 的可见代价；它们不是画质通过结论。
5. `GL_NV_shading_rate_image` 没有像 EXT 那样查询逐 rate 支持集合的入口；plan 假定扩展
   定义的 palette rate 可用，默认 2x2，4x4 为可选项。真实驱动对具体 rate 的行为未验证。
6. 未做 GPU 毫秒/带宽/显存测量；1920×1080 的 rate image 约 8 KB 只是解析估算。性能与
   “更快”结论 `NOT_EVALUATED`，不得把局部 pass 的 VRS 开关归因为全局 FPS 提升。
7. GPU 首轮 5 个 case 为 3 FAIL（probe dead uniform ×2、SSS 帧相同 ×1）；修复后的 shader
   编译、驱动是否实际生效、像素读回、设备/驱动身份仍待 Orchestrator 复跑。JVM PASS 不能替代 GL PASS。
8. `RenderFeaturesControl`/`RenderFeatureSettings`/`RenderFeaturePolicy`/
   `PipelineFeaturePolicy`/`RenderPipeline` 未改（禁改文件）；统一请求入口、effective/
   unavailable reason、demo 入口和聚焦过滤登记由 Integrator 完成。
9. 目标最小 extent 为每个轴 2 个 rate texel（默认 16×16 → 32×32）；更小的目标会拒绝
   创建而不是静默全 fine。
