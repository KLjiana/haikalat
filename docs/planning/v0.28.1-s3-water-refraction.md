日期：2026-11-12。状态：生产实现、JVM 合同与真实 GL 用例均已完成；Orchestrator 首轮 5/5 在 fixture 的 window-depth 校验阶段失败（不是水面 pass/shader 失败），修复 `deviceDepth` 列主序编码后 `WaterRefractionGlTest` **5/5 PASS、0 skipped**，水面回归 6/6 PASS。本分支已补齐 `RenderPipeline` companion pass 主路径（`codex/render-wiring-s4s5`）：启用时图声明 `WaterSurfaceRefractionCopy → WaterSurfacePass`，关闭时无额外 pass/附件/绘制且主视图逐字节恢复；新增 `WaterRefractionPipelineWiringTest` 与 `WaterRefractionPipelineGlTest`。

## 技术卡

| 字段 | 内容 |
|---|---|
| 技术 ID／用户场景 | #11 屏幕空间水面折射；让 #14 有限水面在已有背景颜色与共享不透明深度上产生受控的屏幕空间折射偏移，作为水面着色的一部分，而不是独立的玻璃/护盾材质。默认关闭，关闭时水面行为与 #14 逐字节一致。 |
| 当前基础／差距 | 已有 #14 `WaterSurfaceSettings`、`WaterSurfacePass`（复制场景颜色、采样共享深度、吸收/岸边/Fresnel 反射）与 `water-surface.frag`；已有 HDR `sceneColor`、`sceneDepth`/`sceneDepthMS`、`TemporalFrameState` 矩阵、`PbrEnvironment` 和 RenderGraph 颜色/深度租约。差距是水面没有背景颜色采样、没有基于法线/视角/厚度的屏幕偏移、没有前景拒绝和离屏回退。 |
| 首版范围 | 在 `WaterSurfacePass` 内新增可选的折射 shader 变体：以水面波法线对相机→水面方向做 Snell 折射，按垂直水厚（深度重建）推进，投影到屏幕 UV 后采样**独立单采样背景拷贝**。提供 IOR、强度、最大 UV 偏移、厚度缩放、前景拒绝 bias、离屏回退模式/颜色；构造期校验；默认关闭。 |
| 不支持输入 | 实时水下体积/光线步进、真实折射率色散、多层水体、焦散（#36 独立）、泡沫、屏幕空间反射（#20）、平面反射（#30）、流体模拟、玻璃/护盾材质（#13 独立）、透明 VFX/粒子的折射或遮挡、正交相机专门调参、逐样本 MSAA 折射。 |
| 模块与控制 | 新公开值对象 `render3d.water.WaterRefractionSettings`（独立 record，不修改 #14 的 `WaterSurfaceSettings` 公开形状）；`WaterSurfacePass` 增加 `WaterSurfacePass(int samples, boolean refractionSupport)` 构造、折射 `record` 重载与 `recordBackgroundCopy` 静态合同；shader 增加 `WATER_REFRACTION` 变体。没有新增 manager/factory/interface。默认 `WaterRefractionSettings.disabled()`。 |
| 真实消费者 | `WaterSurfacePass.record(cmd, sceneColorSource, backgroundCopy, target, sceneDepthTexture, frame, waterSettings, refractionSettings, environment, intensity, rotation, time)`；背景拷贝由 `WaterSurfacePass.recordBackgroundCopy(cmd, source, target)` 在 companion pass 中记录。GL 测试直接驱动该生产 pass（不是 Demo shader）。 |
| 输入：背景颜色 | `waterSurfaceRefractionBackground`：单采样、全尺寸 RGBA16F 线性 HDR 颜色纹理，由 companion pass `WaterSurfaceRefractionCopy` 从最后一个写 `sceneColor` 的 pass blit/resolve 得到。采样合同同 RenderGraph 颜色附件：`GL_LINEAR`、`CLAMP_TO_EDGE`。shader 只采样该拷贝，绝不采样自己写的 `waterSurfaceColor`。 |
| 输入：深度 | 共享 `sceneDepth`/`sceneDepthMS`（与几何样本数一致）；设备深度，单采样路径 `texelFetch(..., 0)`，MSAA 路径 `texelFetch(..., 0)` 取 sample 0。用于当前像素水厚和折射 lookup 的前景拒绝。 |
| 输入：相机/时间 | `TemporalFrameState.FrameParameters` 的 jittered projection、view、inverse jittered projection、相机位置、far plane；本帧累积水波时间。所有距离按世界单位/米解释；UV 为左下原点 `[0,1]`；输出为线性 HDR。 |
| 输出 | `waterSurfaceColor`（RGBA16F，MSAA 时多采样），折射路径对水面覆盖像素输出 `alpha = 1` 的替换色 `mix(refractedBackground, waterColorShade, alpha)`；矩形外像素保持已复制背景。不写深度、不写速度、不读回。 |
| 偏移公式 | `I = normalize(world - camera)`；`N` 为解析波法线，必要时翻转使 `dot(N, I) < 0`；`R = refract(I, N, 1/ior)`；`downward = max(-R.y, 0.05)`；`travel = max(thickness,0) * thicknessScale / downward`；`refractedWorld = world + R * travel`；`offset = (project(refractedWorld) - pixelCentreUv) * strength`；总 UV 偏移长度 clamp 到 `maximumScreenOffset`。`pixelCentreUv = (gl_FragCoord.xy) / extent`（与 `ivec2(gl_FragCoord.xy)` 的像素中心一致）。 |
| 厚度与薄水 | `thickness = waterLevel - sceneWorldY`，由共享设备深度反投影得到；深度为远平面（`>= 1`）时沿用 #14 的 `sceneY = level - farPlane` 深水处理。偏移随 `thickness` 线性缩小，水厚趋近 0 时折射自然消失；岸边仍由 #14 的 `shoreFadeDistance` alpha 过渡控制，不重复实现吸收/岸边。 |
| 前景拒绝 | 在偏移后的像素取共享深度：若 `deviceDepth >= 1`（无背景几何）回退；否则反投影采样点，沿该像素相机射线求水面距离 `waterDistance`，采样点视图距离 `sceneDistance = length(viewSpace(sample))`；当 `waterDistance - sceneDistance > foregroundRejectionBias` 时判定为前景（背景比水面更近），不折射。bias 是世界米，用于容纳深度量化/水面近似误差。 |
| 离屏／边缘回退 | 偏移 clamp 后若 shifted UV 任一轴离开 `[0,1]` 或出现非有限值，按 `OffscreenFallback` 处理：`UNREFRACTED`（默认）保留当前像素背景，只叠加水面着色；`TINT` 使用显式线性 `offscreenFallbackColor`。正常路径的 shifted UV 保证在 `[0,1]` 内，不依赖 clamp-to-edge 读取错误边缘；屏幕边缘不会越界或产生 NaN。 |
| 反馈禁止 | companion copy pass 写 `waterSurfaceRefractionBackground`；水面 pass 读该纹理并写 `waterSurfaceColor`，两者是不同颜色附件。水面 pass 也不读自己写的 `target`。图依赖必须为 `GeometryPass → WaterSurfaceRefractionCopy → WaterSurfacePass → 后续 HDR 链`。 |
| 参数校验 | `ior ∈ [1.0, 2.5]`；`strength ∈ [0, 2]`；`maximumScreenOffset ∈ [0, 0.5]` UV；`thicknessScale ∈ [0, 8]`；`foregroundRejectionBias ∈ [0, 10]` 米；fallback 颜色分量 `∈ [0, 16]`；全部有限，fallback 模式非 null。非法值在 `WaterRefractionSettings` 构造期拒绝，不静默夹取。 |
| GPU owner／生命周期 | GPU owner 与 `RenderPipeline.execute` 相同；`WaterSurfacePass` 拥有 base/refraction 两个 program、单位 mesh 和 cubemap sampler，`close()` 统一释放；背景拷贝附件由 RenderGraph 拥有。同样的候选代可按 sample count 借用 pass；折射支持在构造期固定，运行期切换折射参数需重建候选代（与既有 water 设置一致）。无历史、无 GPU 读回、无 `glFinish`。 |
| 失败语义 | 构造期 shader link 失败关闭已创建资源并抛出；record 在触碰 GL 状态前校验背景拷贝（非空、非 target、extent 一致、单采样、颜色纹理），缺 copy pass 或构造时未启用折射支持时抛出可诊断异常；候选失败沿用既有 generation 清理，不把失败帧写成像素回滚。 |
| 成本／回退 | 启用折射时每帧新增 1 个全尺寸 RGBA16F 单采样附件 + 1 次全尺寸颜色 blit/resolve；每个水面覆盖像素最多 2 次背景颜色采样（中心 + 偏移）和 1 次额外深度 fetch。关闭折射时零额外附件、零额外采样，水面 shader 与 #14 相同。未做 GPU 性能测量，成本 `NOT_EVALUATED`；回退是 `WaterRefractionSettings.disabled()` 或关闭水面。 |
| 质量档 | 参数建议（非性能结论）：Low `ior=1.333, strength=0.75, maxOffset=0.01, thicknessScale=1.0, bias=0.10, UNREFRACTED`；Medium `1.333, 1.0, 0.02, 1.0, 0.05, UNREFRACTED`；High `1.333, 1.25, 0.04, 1.25, 0.02, UNREFRACTED`。Low→High 增加可见偏移与更严格的 foreground bias，像素采样次数不随档位增加；实际性能必须实测。 |
| 独立 oracle | `src/test` 中的 `WaterRefractionReferenceMath` 用 double 独立实现 Snell、双列波法线、厚度/斜率先验、投影、前景判定、离屏回退与双线性采样；固定输入可复算（法线入射零偏移、固定斜入射手算样例 `(0, -0.11139303)`、厚度/强度单调、0.02 UV clamp、bias 边界）。GL 期望值从独立渲染的背景读回采样，不以 GPU 自身输出当真值。 |
| 验证范围 | JVM 已执行：`.\gradlew.bat test --tests "*WaterRefraction*" --tests "*WaterSurface*"` = 22 passed / 11 skipped（GL-guarded）/ 0 failed；覆盖设置边界、独立 double oracle、window depth 编码回归、shader 基线源文本逐字节等价、既有 water 设置回归。GL **未得到 PASS**：GPU 首轮 5/5 在 fixture 深度校验阶段失败（测试编码错误，已修复并加 JVM 回归），修复后尚未重跑；`WaterRefractionGlTest` 5 cases + 既有 `WaterSurfacePassGlTest` 3 cases + `WaterSurfacePipelineGlTest` 3 cases 待 GPU 队列；命令 `.\gradlew.bat glSmoke --tests "*WaterRefractionGlTest" --tests "*WaterSurfacePassGlTest" --tests "*WaterSurfacePipelineGlTest"`。 | 真实 GL：`WaterRefractionGlTest` 5/5 + `WaterSurfacePassGlTest`/`WaterSurfacePipelineGlTest` 6/6，集成 `verify.ps1` runId `6bf14b8c`（650 tests、0 skipped）。

## 生产接线（已完成）

本分支（`codex/render-wiring-s4s5`）补齐了主 RenderPipeline 路径：

1. **配置字段**：`RenderFeatureSettings` 末尾追加 `waterRefraction`（默认 `WaterRefractionSettings.disabled()`），builder/`toBuilder()`/`defaults()`/访问器保持源码兼容；`RenderFeature` 追加 `WATER_REFRACTION` 活动项。
2. **管线字段**：`RenderPipeline` 新增 `waterRefraction(...)`、`waterRefraction()`、`applyWaterRefraction(...)`。build 前只暂存值；帧边界 apply 在启用/禁用切换时构建完整候选代，标量参数变化只更新字段（executor 每帧读取）。`PipelineTopology` 末尾追加 internal `waterRefraction` 组件并保留旧构造器/`capture(...)` 重载。
3. **Pass 构造**：`PipelineGeneration.assembleWaterSurface` 用 `new WaterSurfacePass(topology.sampleCount(), topology.waterRefraction())`，donor 复用同时匹配 sample count 与折射支持。
4. **拷贝 pass**：启用时图声明
   `graph.addPass(WaterSurfacePass.REFRACTION_BACKGROUND_PASS).createColor(REFRACTION_BACKGROUND, RGBA16F).noClear().dependsOn(sceneColorProducer)`，
   executor 调用 `WaterSurfacePass.recordBackgroundCopy(cmd, res.framebufferOfPass(sceneColorProducer), res.currentTarget())`；`WaterSurfacePass.PASS_NAME` 依赖该 pass。MSAA 的 geometry colour 由 blit resolve 到单采样 copy。
5. **记录调用**：`waterExecutor` 在 `generation.waterRefraction()` 时取 `res.framebufferOfPass(REFRACTION_BACKGROUND_PASS)` 作为 `backgroundCopy`，调用带 planar 反射的折射重载；关闭时继续使用旧的 planar/base 重载，路径与 #14 完全一致。
6. **失败语义**：启用折射但没有活动水面、没有 HDR、或场景存在玻璃 `RefractionPass` 时，在 `validateCompositionDependencies`/`createGeneration` 的候选准备之前抛 `IllegalArgumentException`；禁用折射与水面停用互斥也在 `applyWaterSurface` 前拒绝。无 source/pass 的静默降级不存在。
7. **与 #14/#13 关系**：#14 的 `WaterSurfaceSettings` 与旧 `record` 重载保持不变；`disabled()` 走 base shader，与 #14 源文本逐字节相同。#11 不新增 `RefractionPass`，`PipelineFeaturePolicy.validateRefractionWater` 对“玻璃 + 水面”的互斥仍然有效。SSR + 水面、体积雾 + 水面的既有拒绝同样保持不变。
8. **公共 API/资产/聚焦清单**：没有新增 public 顶层类型，`render3d.allowlist` 无需新增条目；生产 shader 未修改，`assets.tsv` 无需更新。新增 JVM `WaterRefractionPipelineWiringTest` 与 GL `WaterRefractionPipelineGlTest` 已注册到 `gradle/focused-verification.gradle`。

## 限制与未验证项

1. **屏幕空间近似**：折射只改写屏幕采样位置，不建立真实水下光路、体积吸收分层或场景底部几何求交；`travel` 由垂直水厚与折射方向斜率近似，不保证折射点与真实几何一致。
2. **无法看见真实水下体积**：背景是单张不透明颜色拷贝；水下物体、折射后的遮挡关系、折射率色散、多层水体、泡沫、真实焦散均不在本版范围。
3. **前景拒绝依赖共享不透明深度**：透明 VFX/粒子不写场景深度，因此不会被识别为前景；前景 bias 是世界米近似，深度量化、水面平面近似和掠射角会造成边界误差。前景拒绝不改变 #14 原有“当前像素场景更近则丢弃水面”的遮挡逻辑。
4. **有限水面边缘**：只对 shifted UV 做屏幕范围检查，没有对折射采样点的水平位置做有限矩形包含测试；靠近水面矩形边缘时可能采到水面矩形之外、但仍在屏幕内的地面像素。这是首版明确接受的近似。
5. **天空/无背景回退**：偏移像素 `deviceDepth >= 1` 时按回退处理，避免把天空颜色当成水下背景；该规则使地平线附近更频繁回退。
6. **MSAA**：背景拷贝固定 resolve 为单采样；水面输出仍按 fragment 写入多采样目标，深度比较取 sample 0，未实现逐样本折射。MSAA 路径有生产代码但本工作包**未执行 GL**，标 `NOT_EVALUATED`。
7. **TAA**：水面设置变化不会自动失效 TAA history；没有 velocity/reactive 通道，移动折射波纹在 TAA 下可能拖影。未验证。
8. **与 #13 玻璃**：两者仍是互斥的 scene-color producer；本包不实现水+玻璃双层折射，也不复用 `RefractionPass` 的快照。
9. **与 #20 SSR/#30 平面反射/#36 焦散**：未接入；SSR+水面、体积雾+水面的现有策略拒绝保持不变。焦散仍是独立 #36 路径。
10. **性能**：新增全尺寸背景拷贝和最多 2 次颜色采样；未做 GPU 性能/显存测量，成本 `NOT_EVALUATED`。质量档只是参数建议，不是预算结论。
11. **正交相机**：投影数学可运行，但没有专门测试或承诺。
12. **主路径接线后的边界**：折射只在有限水面启用时存在；玻璃折射、SSR 与体积雾的既有互斥不变。`applyWaterRefraction` 的标量变化不重建候选代，启用/禁用切换才重建；主路径 GL 用例覆盖单采样 NONE 路径，MSAA 主路径与真实场景透明交错仍未在本分支 GL 覆盖内。

## 水下体积（#11/#30 扩展，2026-11-17）

状态：生产实现、JVM 合同与真实 GL 用例完成。新增 `render3d.water.UnderwaterVolumeSettings`
（advanced，默认 `disabled()`）与 `render3d.water.UnderwaterVolumePass`（internal），
`RenderPipeline.underwaterVolume(...)`/`applyUnderwaterVolume(...)` 接入主颜色链；没有新增
`RenderFeatureSettings` 组件，也不改 #14 的 `WaterSurfaceSettings` 公开形状。

### 输入、输出与公式

| 字段 | 内容 |
|---|---|
| 输入：场景颜色 | 单采样链直接采样当前 `sceneColorTexture`；MSAA 链由 `UnderwaterVolumeColorCopy` 把当前颜色 blit/resolve 到 pass 自有单采样 RGBA16F 拷贝后采样。 |
| 输入：深度 | `UnderwaterVolumeDepthResolve` 把光栅深度 blit 到 pass 自有单采样深度纹理；单采样链直接采样共享 `sceneDepth`。任何路径都不会用普通 `sampler2D` 读取多采样深度。 |
| 输入：相机/水面 | `TemporalFrameState.FrameParameters` 的 jittered projection、view、相机位置；水面高度来自当前启用的 `WaterSurfaceSettings.level()`。 |
| 输出 | pass 自有 RGBA16F 目标 `underwaterVolumeColor`（MSAA 时保持拓扑样本数）；下游 `sceneColorInput`/`hdrResolveSource` 指向该 pass。不写深度、不写速度、不读回。 |
| 公式 | `path = min(length(world - camera), maximumDistanceMetres)`；`attenuation = exp(-absorptionDensity * path)`；`rgb = scene.rgb * attenuation + scatterColor * (1 - attenuation)`；alpha 沿用场景 alpha。`world` 由 `uv = gl_FragCoord.xy / viewport`、设备深度和 `inverse(jitteredProjection * view)` 重建。 |
| 有限性 | 密度 clamp 到 `[0,8]`、路径 clamp 到 `[0.1,500] m`、指数下限 `-80`（`exp(-80) ≈ 1.8e-35`）、散射色 clamp 到 `[0,16]`；`w`、深度、`path`、结果为 NaN/Inf 时整像素回退到场景颜色。设置构造期拒绝非法/非有限值。 |
| 相机在水面以上 | `camera.y >= level` 时 executor 只把当前颜色生产者 blit 到目标，不记录 draw；输出与禁用基线逐字节一致，图拓扑不因相机高度改变。 |
| 参数校验 | `absorptionDensity ∈ [0,8]`；`maximumDistanceMetres ∈ [0.1,500]`（默认 60）；`scatterColor` 分量 `∈ [0,16]`；全部有限；颜色防御性拷贝；`with...` 返回新值。 |

### Pass 位置、颜色链与 MSAA

- 图位置：`WaterSurfacePass`（以及互斥的 `RefractionPass`，若未来组合放开）之后、
  `HdrResolvePass`/`ToneMappingPass` 与分析雾/体积云消费者之前。启用后 `postProcess.sceneColorInput`
  与 MSAA 的 `hdrResolveSource` 都更新为 `UnderwaterVolumePass`，`sceneColorTexture`/`sceneColorProducer`
  继续向后传递；相机高度不参与 `PipelineTopology`。
- 单采样：pass 目标 `createColor`，直接采样 `sceneColorTexture` 与共享 `sceneDepth`；没有额外拷贝附件。
- MSAA：`UnderwaterVolumeColorCopy`（单采样颜色拷贝）与 `UnderwaterVolumeDepthResolve`（单采样深度）
  两个 companion pass 先执行，主 pass 目标保持拓扑样本数；HDR resolve 从主 pass 目标 blit 到单采样
  HDR 链。这样普通 sampler 永远不读多采样深度/颜色。
- 生命周期：pass 只拥有 program 与全屏三角形 mesh；颜色/深度附件由 RenderGraph 代际拥有，
  resize 由 graph 事务重建；兼容 donor 只按无状态 program 借用。disabled 时无 pass、附件或 draw，
  帧与当前基线逐字节一致。

### MSAA 连续水面帧缺陷修复（2026-11-17）

- 现象：`AntiAliasingMode.MSAA`、4 样本下，首帧 MSAA 水面正常；在首帧 capture 后立即再渲染
  一帧，第二帧水面 draw 产生 `GL_INVALID_OPERATION 1282`（NVIDIA 消息
  `program texture usage`）。只渲染一帧的既有 MSAA 用例因此没有暴露。
- 根因（`WaterSurfacePass`，不是共享深度/拓扑）：`uSceneDepth` 固定绑定
  `DEPTH_UNIT = 0`；`uPlanarReflection` 只在存在平面反射目标时写 uniform，否则保持链接后的
  默认 texture unit 0。MSAA 变体的 `uSceneDepth` 是 `sampler2DMS`、`uPlanarReflection` 是
  `sampler2D`，于是同一 program 的 unit 0 同时出现两种 sampler 类型。首帧 unit 0 的
  `GL_TEXTURE_2D` 绑定仍为 0，驱动没有可校验的 2D 纹理；帧末 HDR/后处理链在 unit 0 留下
  一个完整 2D 纹理后，第二帧水面 draw 触发驱动校验并报 1282。`uEnvironment` 同样默认
  unit 0，但 `samplerCube` 使用独立绑定点，不参与该冲突。
- 执行期证据（临时诊断，未提交）：frame 1 水面 draw 前 unit0 为
  `2D=0, 2DMS=2, cube=0`，`uSceneDepth=0, uEnvironment=0, uPlanarReflection=0`；
  frame 2 同一位置为 `2D=3, 2DMS=2, cube=0`，uniform 不变，draw 后
  `glGetError()=1282`，debug 消息阶段为 `RenderGraph/WaterSurfacePass`。共享深度纹理两帧
  都是同一个 MS texture（id 2），样本数与内容未变。
- 修复：`WaterSurfacePass.recordInternal` 每帧无条件把 `uEnvironment`、`uPlanarReflection`
  写到各自专用 unit（`WaterSurfacePass.java:357-358`；`ENVIRONMENT_UNIT=1`、
  `PLANAR_REFLECTION_UNIT=3`），可选纹理只在存在时绑定（`:364-366`）；`uSceneDepth` 保持
  unit 0。可选输入仍由 `uHasEnvironment`/`uHasPlanarReflection` 守卫。未改 shader 源、
  资产或 GL policy 行（1282 不是被豁免，而是不再产生）。
- 回归：`WaterSurfacePipelineGlTest.consecutiveMsaaWaterFramesStayErrorFreeAndByteStable`
  以 MSAA 4、静态波（`frame(0.0f)` 连续 3 帧）逐帧断言 `glGetError() == GL_NO_ERROR`、
  全部像素有限、三帧读回逐 bit 相等，并在关闭水面后要求有限矩形内 >32 像素变化（证明不是
  常量图）。把修复临时回退后该用例在第二帧失败 `expected: <0> but was: <1282>`，恢复修复
  后通过；既有单帧 MSAA 用例与 NONE/TAA 水面用例保持通过。

### 限制

1. **屏幕空间近似**：只按可见深度重建路径，不能衰减被遮挡或不在深度缓冲中的介质；没有真实
   光线步进、色散、多层水体、泡沫或逐波长吸收。
2. **有限距离**：路径被 `maximumDistanceMetres` 钳制，最远只到 60 m 默认值；深度为远平面时
   按远平面点计算并钳制，不是无限水体。
3. **波形不参与入口平面**：入口平面始终是 `WaterSurfaceSettings.level()` 的水平面，波高/法线
   不影响水下体积路径；相机穿越平面只看相机 y 与 level。
4. **云/雾顺序**：pass 位于分析雾与体积云消费者之前，这些消费者看到的是被染色的颜色；体积雾
   与水面本身仍互斥，玻璃折射与水面仍互斥。
5. **MSAA 多帧（已修复）**：`WaterSurfacePass` 连续 MSAA 帧的 1282 已按上一小节修复并有 3 帧
   回归；仍不覆盖 MSAA + 折射/平面反射/IBL/水下体积的多帧组合，逐样本水面真值仍未建立。
6. **TAA**：未接入 TAA 特定处理；没有 velocity/reactive 通道，快速相机移动在 TAA 下可能拖影。
7. **性能与视觉**：没有 GPU 性能测量、显存测量或人工视觉验收，成本与视觉质量 `NOT_EVALUATED`。
8. **组合边界**：本包只在有限水面 + HDR 下启用；水面禁用时 `underwaterVolume` 明确拒绝。与
   #13 玻璃、#20 SSR、体积雾的既有互斥不变。
