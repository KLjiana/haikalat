## 技术卡

| 字段 | 内容 |
|---|---|
| 技术 ID／用户场景 | #12 DOF；受控镜头与展示中区分焦内/焦外，保持战斗目标与 UI 可读性。首版不默认开启。 |
| 当前基础／差距 | 已有 `PostProcessPipeline` 颜色链、TAA resolve、共享 `SurfaceInputs.Channel.DEPTH`、HDR RGBA16F 中间附件与各效果独立 owner。缺少景深设置、深度线性化、CoC 与有界 gather。 |
| 首版范围 | 单层深度驱动的 gather 景深；可配置焦点距离、光圈 f-number、最大 CoC 半径。支持 NONE/MSAA/FXAA/TAA 的 HDR 路径。不支持自定义 bokeh 形状、高光加权、分层/逐透明深度、自动对焦、镜头呼吸、物理相机焦距/FOV 匹配。 |
| 模块与控制 | `subsystems.postprocess`：`DepthOfFieldSettings` + `depthoffield.DepthOfFieldPass`；`PostProcessPipeline` 持有并排序。不新增 manager/factory/chain。默认 `PostProcessSettings.depthOfField() = disabled()`；`enabled=false` 或 `maxCocPixels=0` 时 `active()=false`，不创建 pass、shader 或附件。 |
| 输入 | 已解析的 HDR 场景颜色（TAA 后；含透明/VFX/雾/屏幕扭曲的最终 HDR 合成），单采样 device depth（D24 或 MSAA resolve 后的 R32F），帧的 inverse projection（取 `TemporalFramePose.inverseJitteredProjection()`；jitter 不影响 z），输出尺寸。颜色为线性 HDR，深度为 OpenGL `[0,1]` device depth。 |
| 输出 | 独立全尺寸 `depthOfFieldColor` RGBA16F；不写共享深度，不修改输入颜色附件。 |
| CoC 公式 | 固定 50 mm 焦距、36 mm 传感器宽度的薄透镜近似：`diameter = f²·|d-S| / (N·d·(S-f))`，`radiusPixels = 0.5·diameter·(viewportWidth/0.036)`，最后 `min(radius, maxCocPixels)`。`S` 为焦点距离（世界单位按米解释），`N` 为光圈 f-number，`d` 为逆投影得到的相机空间深度。JVM 参考实现位于包内 `DepthOfFieldMath`，与 shader 使用同一常数。 |
| 参数校验 | `focusDistance ∈ [0.1, 1000]`，`aperture ∈ [1, 22]`，`maxCocPixels ∈ [0, 16]`；全部要求有限。非法值在设置构造期拒绝。 |
| 采样与边界 | 固定 16 tap 黄金角圆盘，tap 半径始终不超过 `maxCocPixels`，因此成本与模糊半径有界。UV 在 `[0.5/viewport, 1-0.5/viewport]` 截断，避免屏幕边缘采样到黑边。 |
| 焦内清晰 | 中心 CoC `< 0.5 px` 时只接受“更近且自身失焦”的样本；同深度平面与同深度边缘保留中心原值，不因邻域同 CoC 采样而软化。 |
| 前景扩散／漏色控制 | 中心已失焦时，若样本更远且其 CoC 明显大于中心 CoC（`> centerCoC + 0.25`），拒绝该样本，防止失焦背景颜色盖到更清晰的前景；更近的失焦样本仍可扩散到背景，形成前景 bokeh。中心焦内时，更近的失焦前景也可覆盖该像素。 |
| 透明／VFX 覆盖策略 | DOF 读取的是共享表面深度，只有不透明/写深度的表面提供 CoC；透明 VFX 位于 VFX composite 颜色中，但通常不写共享深度，因此其颜色按**其身后不透明表面的深度**取 CoC：焦点在背景时前景透明特效会跟随模糊，焦点在前景物体时透明特效保持清晰。首版没有逐透明深度、premultiplied-alpha 感知或 VFX 深度层；不承诺透明物体与不透明物体之间的正确遮挡式 DOF。 |
| Pass 关系 | `GeometryPass → [Surface/Fog/VFX/Distortion] → TAA resolve → DepthOfFieldPass → AutoExposure → Bloom → ToneMapping → Vignette/FilmGrain/ChromaticAberration → FXAA/Present`。DOF 在 TAA **之后**，避免 CoC/模糊进入 TAA history 造成拖影；在曝光/Bloom/tone mapping **之前**，在线性 HDR 中模糊。UI 由宿主在最终 backbuffer/Present 之后追加 `UiOverlayPass`，因此不进入 DOF、曝光、Bloom 或 TAA。 |
| 资源与失败 | `DepthOfFieldPass` 拥有 shader + `ScreenQuad`，由 `PostProcessPipeline.owned` 关闭；同设置的候选代可借用 donor，`transferResourcesTo` 转移所有权。无历史、无 GPU 读回、无 `glFinish`。候选失败时按既有 `PostProcessPipeline` 清理路径释放自有资源；不接管借用深度。 |
| 装配依赖 | `PipelineTopology.sceneSurface` 在 DOF active 时把既有 depth 通道并入请求（与解析雾共用 `SceneBufferRequirements.fog()` 的 depth-only 语义），因此 `SurfaceInputs.single(DEPTH)` 有真实 producer。装配/`validateSurfaceInputs()` 在缺深度或非 HDR 时明确拒绝。未修改 `RenderPipeline` 公共入口。 |
| 参考与许可 | 算法为项目自写薄透镜/黄金角 gather，无第三方 shader 或资产；shader 为 project source，指纹见下。独立 JVM 参考用固定常数与手算数值，不以当前 GPU 输出当真值。 |
| 成本／回退 | 每像素 1 次中心颜色 + 16 次颜色/depth tap（命中时为 2 次纹理读取），1 次全屏 draw，1 张全尺寸 RGBA16F 附件。启用 DOF 会让共享 depth 成为 surface 消费者：无 TAA/雾等既有消费者时新增一个 depth-only `SceneSurfacePass`（与解析雾相同机制），该几何开销另计。未做 GPU 测量，成本状态 `NOT_EVALUATED`；回退是关闭效果（精确 no-op）或降低 `maxCocPixels`。 |
| 验证范围 | JVM：设置边界/默认关闭/no-op、CoC 解析值/单调性/夹取/分辨率缩放、`PostProcessSettings` 兼容构造器、`PipelineTopology` depth 请求。GL：`DepthOfFieldPassGlTest` 覆盖焦内 vs 焦外、最大半径、前景漏色和 disabled/active 图合同；真实 GL 已执行 PASS。 |
| 创作交付 | 通过 `PostProcessSettings.builder().depthOfField(DepthOfFieldSettings.of(focus, aperture, maxCoc))` 在 build 前配置；焦点等标量是装配期值，修改后需重新 build/重建候选。逐帧自动对焦与 UI 控件不在本包范围。 |

## 明确限制与未验证项

1. 首版没有真实相机焦距/FOV/sensor 数据，50 mm/36 mm 是固定的艺术近似；不同 FOV 镜头的散景强度不自动匹配。深度线性化按透视逆投影工作，正交相机未验证/未承诺。
2. 最大 CoC 以输出像素为单位且上限 16 px；高分辨率下视觉半径相对更小，未做分辨率归一的质量档。
3. 固定 16 tap 在最大半径下是稀疏采样，强边缘/高对比点光源可能出现采样纹；未实现高光加权或可分离预滤波。
4. 透明/VFX 只按共享不透明深度取 CoC，未解决透明层与不透明层交错的正确景深；体积雾与透明排序保持既有合同。
5. 景深设置为装配期值；改变焦点/光圈/最大 CoC 不会自动重建当前 generation，需要重新 build。
6. 真实 GL 已执行 PASS（2026-11-11，`DepthOfFieldPassGlTest`，fresh run）；shader 编译、16 tap 像素结果、`glGetError` 和 pass 图执行均有证据。GPU 调试策略对 `131218` 的豁免仅限该测试类、最多 2 条冷 shader 特化消息，并带负向超量断言。
7. 未测性能、显存峰值或多硬件；`NOT_EVALUATED` 保留。
