# v0.18.1 VFX 曲线动画、缓动与过渡实施计划

> 状态：内部功能验收完成；经审批不独立发布，完整候选合并进入 v0.18.2
>
> 目标版本：`0.18.1`
>
> 基线版本：`0.18.0`
>
> 版本主题：在不改变 glTF 动画语义和现有 VFX 默认画面的前提下，建立可复用、确定性、无 OpenGL 依赖的曲线能力，并将其用于 VFX 生命周期表现和骨骼动画过渡。

## 1. 版本定位

v0.18.0 已完成骨骼动画、glTF skin/animation、UI Tween/Transition、CPU VFX、局部阴影和受控 GPU 特效实验。当前 `subsystems.animation` 已支持 `STEP`、`LINEAR`、glTF `CUBICSPLINE`、双层混合、Bone Mask、动作事件、根运动和 Two-bone IK；`subsystems.vfx` 已提供有界、确定性的粒子、Ribbon 与 Decal 模拟。

现有能力仍存在一个明显缺口：动画和 VFX 能正确推进生命周期，但大多数表现参数只能在线性端点之间变化。粒子尺寸与颜色、Ribbon 宽度与颜色、Decal 颜色目前均按归一化年龄直接线性插值；`AnimationMixer` 的 layer weight 只能由调用者立即设置，缺少正式的 cross-fade 和权重过渡协议。UI 已有一套局部 easing，但它属于 `subsystems.ui`，不能成为 VFX 与骨骼动画共同依赖的基础合同。

v0.18.1 的目标是补齐这层基础能力，而不是建设完整动画编辑器、特效编辑器或通用 AnimationGraph。版本必须保持项目当前的分层、确定性、资源所有权和公共 API 分类策略。

## 2. 开工前置条件

开始实现前必须确认：

- `compileJava demoClasses test` 通过；
- `localGlVerification` 在有桌面的本机通过；
- v0.18.0 的 VFX 固定种子快照、动画事件、根运动和 glTF `CUBICSPLINE` 测试保持通过；
- 当前 `ParticleEmitter`、`RibbonEmitter`、`Decal` 的默认输出作为兼容基线保留；
- 新增 public 类型在实现时同步登记到对应 allowlist，默认分类为 `advanced`；
- 曲线基础不依赖 LWJGL、GLFW、OpenGL、UI、render3d 或 demo；
- 本版本不混入 Gradle 任务拆分、发布脚本整理或其他无关重构。

若基线测试已经失败，应先修复基线，不能通过放宽曲线误差、改变快照比较或重写测试来掩盖历史问题。

## 3. 总体目标

### 3.1 必须完成

1. 建立一套无 GL 依赖、不可变、可验证的标量曲线合同，支持 linear、常用 cubic easing、spring 和自定义 cubic-bezier easing。
2. 明确区分“时间缓动曲线”和“三维空间路径”，避免使用同一个含糊的 Bezier 类型承载两种语义。
3. VFX 支持粒子 size/color、Ribbon width/color、Decal scale/color 的 over-life 曲线。
4. 未配置新曲线的旧 `EffectAsset` 保持 v0.18.0 行为；旧构造方式继续可编译，默认快照不发生可见变化。
5. `AnimationMixer` 支持按 duration 与 easing 执行 base clip cross-fade，以及 layer weight fade-in/fade-out。
6. glTF `STEP`、`LINEAR`、`CUBICSPLINE` 解码和采样语义完全不变；通用 cubic-bezier 不进入 glTF sampler 映射。
7. 所有曲线边界、无效输入、确定性、事件、根运动和大 `deltaSeconds` 行为具有单元测试。
8. `VfxDemo` 或 `HaikalatShowcaseDemo` 提供一个可重复的真实画面证明，展示非线性粒子生命周期、平滑 Ribbon 和动画过渡。

### 3.2 应当完成

- 多关键帧 `FloatTrack`，支持 `STEP`、`LINEAR` 和 cubic Hermite segment；
- 在线性颜色空间采样的多 stop `ColorGradient`；
- 三次 `BezierPath3f` 的位置、切线与近似弧长重参数化；
- VFX 曲线采样统计进入现有 diagnostics，但 diagnostics OFF 时不创建额外快照；
- CPU 曲线可烘焙为固定长度 LUT，为未来 GPU 粒子复用同一数据语义；
- 曲线采样热路径不产生临时集合、装箱值或 lambda 捕获分配。

### 3.3 明确非目标

v0.18.1 不做：

- 通用 AnimationGraph、行为树、动画状态机或 Motion Matching；
- 完整 N 层动画图、全身 IK、关节角限制或物理布料；
- VFX 节点编辑器、时间轴编辑器、曲线可视化编辑器或 shader graph；
- JSON VFX 资产格式、热重载或项目级资源数据库；
- 每粒子独立脚本、表达式解释器或任意回调；
- GPU 粒子系统重写、GPU Ribbon tessellation 或新的 compute pipeline；
- 修改 glTF `CUBICSPLINE` 为 Bezier、Catmull-Rom 或自定义 easing；
- 为曲线功能引入新的第三方数学或动画依赖；
- Vulkan、第二后端、ECS 或 Gradle 多模块拆分。

## 4. 现有架构判断

当前存在三套相关但语义不同的行为：

1. `AnimationClip.Interpolation.CUBIC_SPLINE` 是 glTF 定义的三次 Hermite 关键帧采样，输入包含 key value、in tangent 和 out tangent；
2. `UiEasing` 是 `[0, 1]` 时间到进度的预设映射，包含 linear、cubic 和 spring；
3. VFX 在 `EffectInstance.snapshot()` 中根据 primitive age 直接计算线性进度并执行 `lerp`。

不能让 VFX 直接依赖 `UiEasing`，也不能把 glTF Hermite sampler 替换为 CSS 风格 cubic-bezier。建议新增中立的纯 CPU 包：

```text
core.curve
  Curve1f                 归一化时间到标量值
  Curves                  预设曲线和工厂
  CubicBezierEasing       时间缓动，求解 x(u)=time 后返回 y(u)
  FloatTrack              多关键帧标量轨道
  ColorGradient           多 stop 线性颜色渐变
  BezierPath3f            三维空间三次贝塞尔路径
  CurveLut                固定长度采样结果，可供诊断和未来 GPU 上传
```

依赖方向保持为：

```text
subsystems.ui -----------+
subsystems.animation ----+--> core.curve --> JOML / Java math
subsystems.vfx ----------+
```

`core.curve` 不知道 UI node、Skeleton、EffectAsset、OpenGL texture 或 shader。各 subsystem 只负责把曲线结果应用到自己的属性合同。

## 5. 曲线核心合同

### 5.1 Curve1f

建议第一版合同：

```java
public interface Curve1f {
    float sample(float normalizedTime);
}
```

固定规则：

- 输入必须是有限值且位于 `[0, 1]`，非法输入立即抛出 `IllegalArgumentException`；
- 返回值必须有限，但不强制位于 `[0, 1]`，从而允许 spring 或 overshoot；
- 是否 clamp 由属性消费方决定，例如 alpha clamp 到 `[0, 1]`，size 必须保持非负；
- `sample(0)` 与 `sample(1)` 对预设 easing 必须精确返回端点；
- 实现必须不可变、线程安全，并且单次采样不得分配；
- 不接受隐式时间单位，所有输入均是归一化进度。

不建议把 `java.util.function.Function<Float, Float>` 作为公共合同，因为它会引入装箱、任意捕获状态和无法序列化/审计的行为。

### 5.2 预设缓动

`Curves` 至少提供：

- `LINEAR`；
- `EASE_IN_CUBIC`；
- `EASE_OUT_CUBIC`；
- `EASE_IN_OUT_CUBIC`；
- 参数化 `spring(damping, frequency)`；
- `cubicBezier(x1, y1, x2, y2)`。

UI 现有 `UiEasing` 暂时保留公共名称，内部委托给 `core.curve.Curves`，避免 v0.18.1 顺手破坏 UI API。UI 的确定性像素测试必须继续通过。

### 5.3 CubicBezierEasing

时间缓动采用固定端点 `P0=(0,0)`、`P3=(1,1)` 和两个控制点。采样不能直接计算 `y(time)`，必须：

1. 求解 `x(u)=normalizedTime`；
2. 以同一个 `u` 计算 `y(u)`；
3. 对接近端点的输入返回精确 `0` 或 `1`；
4. Newton-Raphson 导数过小或不收敛时退回固定轮数二分；
5. `x1`、`x2` 限制在 `[0,1]`，保证时间轴单调；
6. `y1`、`y2` 只要求有限，允许可控 overshoot；
7. 求解轮数固定，不根据机器速度或 epsilon 无限循环。

必须使用已知曲线样本验证，例如 `linear(0,0,1,1)`、`ease(0.25,0.1,0.25,1)` 和对称 ease-in-out。

### 5.4 FloatTrack

`FloatTrack` 用于表达实际属性值，而不是只表达 0 到 1 的 easing。关键帧至少包含：

- `time`：严格递增且位于 `[0,1]`；
- `value`：有限标量；
- segment interpolation；
- cubic Hermite 所需的 in/out tangent。

第一版支持 `STEP`、`LINEAR`、`CUBIC_HERMITE`。查找 segment 使用二分或带上次索引的内部 sampler；公共不可变 track 本身不保存跨调用可变游标。

`FloatTrack` 与 `AnimationClip.CUBIC_SPLINE` 可以共享经过验证的 Hermite 数学 helper，但不共享骨骼 channel、JOML quaternion 或 glTF DTO。

### 5.5 ColorGradient

`ColorGradient` 使用严格递增的 stop 和不可变颜色副本。固定规则：

- RGB 按项目现有线性颜色空间插值；
- alpha 在 `[0,1]`；
- RGB 必须有限且非负，第一版不强制上限为 1，以允许 HDR/emissive 颜色；
- stop 之外返回首尾颜色；
- 采样提供写入 caller destination 的无分配入口；
- 不在此类中隐式执行 sRGB decode、tone mapping 或 gamma 编码。

### 5.6 BezierPath3f

空间路径采用四个三维控制点 `P0..P3`，与时间 easing 分开。至少提供：

```java
void sample(float parameter, Vector3f destination);
void tangent(float parameter, Vector3f destination);
float parameterAtNormalizedDistance(float distance);
```

`parameterAtNormalizedDistance` 使用构建时生成的固定长度弧长表做近似反查，使 Demo 中的 emitter 能近似匀速移动。弧长表分辨率固定并可测试，不在每帧重新生成。零长度路径、非有限控制点和退化切线必须有明确行为。

## 6. VFX 生命周期曲线

### 6.1 兼容策略

`ParticleEmitter`、`RibbonEmitter` 和 `Decal` 当前是公开 record。v0.18.1 不直接增加或删除 record component，避免改变 canonical constructor 和现有源码调用。

曲线配置放入 `EffectAsset.Builder`：

```java
EffectAsset.builder("fire")
        .particles(existingEmitter)
        .particleSizeOverLife(sizeTrack)
        .particleColorOverLife(fireGradient)
        .ribbonWidthOverLife(widthTrack)
        .ribbonColorOverLife(ribbonGradient)
        .decalScaleOverLife(decalScaleTrack)
        .decalColorOverLife(decalGradient)
        .build();
```

未配置对应 track 时继续执行 v0.18.0 的 start/end 线性插值路径。为保证旧固定种子测试稳定，默认分支优先保留原计算顺序，不强制把旧线性行为转换为新 track 后再采样。

曲线对象由 `EffectAsset` 以不可变引用持有，不拥有 native/GPU 资源，不参与 `close()` 顺序。`EffectInstance` 只借用所属 asset 的曲线，并继续遵守 asset 不能早于 instance 关闭的现有合同。

### 6.2 粒子

粒子 over-life 支持：

- actual size track；
- linear RGBA color gradient；
- 可选 rotation offset track。

归一化年龄继续使用：

```text
age01 = clamp(ageSeconds / lifetimeSeconds, 0, 1)
```

size 结果必须有限且大于零。若 track 在合法输入上产生零或负值，asset build 阶段无法证明时应在 snapshot 阶段以明确异常拒绝，不能静默生成非法 primitive。若需要完全消失，应通过 alpha 归零，而不是负尺寸。

rotation 由出生时随机初始旋转加 track offset 组成；不在本版本加入角速度积分、湍流或每粒子随机曲线变体。

### 6.3 Ribbon

Ribbon 的 width 与 color 按每个控制点自己的 `pointAge01` 采样，segment 两端分别获得 width，颜色可使用两端平均进度或扩展 snapshot 为两端颜色。第一版优先保持现有 `RibbonSegment` 合同，使用两端平均颜色，避免扩大 renderer 改动。

空间平滑采用以下有限方案：

- 模拟层继续保存有界控制点，不保存展开后的每帧顶点；
- Demo 可使用 `BezierPath3f` 驱动 emitter origin，Ribbon 自动采样该运动路径；
- v0.18.1 不强制把每组 Ribbon 点拟合成新的 spline primitive；
- 若直线 segment 的折角仍明显，可在后续版本增加 Catmull-Rom 到 Bezier 的受控 tessellation，不混入当前曲线基础提交。

### 6.4 Decal

Decal over-life 支持：

- uniform scale track，乘以 spawn 时提供的二维 size；
- linear RGBA color gradient。

scale 必须有限且大于零，normal、rotation 和透明排序合同保持不变。本版本不加入 Decal 投影深度、法线混合或 surface attachment 跟随。

### 6.5 属性范围策略

不同属性不能共享一个无条件 clamp：

| 属性 | 输入 | 曲线输出策略 |
| --- | --- | --- |
| alpha | age01 | clamp 到 `[0,1]` |
| RGB | age01 | 有限且非负，允许大于 1 |
| size/width/scale | age01 | 必须有限且大于 0 |
| rotation offset | age01 | 任意有限弧度 |
| animation blend weight | transition01 | clamp 到 `[0,1]` |
| path position/tangent | path parameter | 验证有限，不做颜色/权重 clamp |

spring 允许数学输出 overshoot，但最终属性仍必须遵守自己的范围合同。禁止为了让异常曲线“看起来能用”而在所有通道统一 `clamp01`。

## 7. AnimationMixer 过渡

### 7.1 Base clip cross-fade

在保留现有 `playBase()` 立即切换语义的同时增加显式过渡入口：

```java
mixer.transitionBase(
        runClip,
        AnimationPlayer.LoopMode.LOOP,
        0.25f,
        Curves.EASE_IN_OUT_CUBIC);
```

内部维护 outgoing player、incoming player、两个可复用 pose buffer、elapsed、duration 和 curve。每次 update：

1. 推进 outgoing 和 incoming cursor；
2. 计算 `transition01`；
3. 用 easing 得到 blend weight，并 clamp 到 `[0,1]`；
4. 使用现有 `PoseBlender` 混合两张 pose；
5. 完成时释放 outgoing 状态，将 incoming 设为正式 base player；
6. duration 为 0 时立即切换，与 `playBase()` 一致。

过渡期间再次调用 `transitionBase()` 时，从当前已混合 pose 开始新的过渡，不能突然退回旧 clip 的原始 pose。第一版可以保存一张 transition-start pose 作为 source，避免无限叠加 player。

### 7.2 Layer weight fade

增加：

```java
mixer.fadeLayerTo(targetWeight, durationSeconds, curve);
mixer.fadeOutLayer(durationSeconds, curve);
```

同一 layer 同时只允许一个 weight transition。新 transition 替换旧 transition，并从当前实际权重开始；`clearLayer()` 仍立即停止并清除。目标权重与采样后权重均限制在 `[0,1]`。

### 7.3 事件语义

cross-fade 期间固定采用以下规则：

- incoming clip 从过渡开始立即推进并发布事件；
- outgoing clip 继续推进以维持视觉连续，但其新事件不再对外发布；
- transition 完成帧只发布一次 incoming 事件；
- seek、stop、重新 transition 会清理被废弃 player 的 pending events；
- 相同 update 跨越多个 incoming loop 时继续服从现有最大事件循环保护。

该策略避免脚步、攻击命中或 VFX spawn 在 cross-fade 期间由两个 clip 重复触发。若未来需要双源事件，必须引入带 clip identity 的新事件合同，不能改变本版本行为。

### 7.4 根运动

过渡期间 `updateWithRootMotion()` 使用与 pose 相同的 eased weight 混合 outgoing/incoming delta：

- translation 使用 lerp；
- rotation 使用 normalized slerp；
- duration 为 0 时只使用 incoming delta；
- remove-from-pose 继续只作用于最终混合结果；
- loop 边界、一次性 clip 结束和大 delta 必须有确定性测试。

如果实现阶段无法在不改变现有根运动合同的情况下正确混合，则 `transitionBase()` 第一版必须在调用 root-motion update 时明确失败，而不能静默选用某一侧产生错误位移。正式发布前应优先完成正确混合。

### 7.5 glTF 动画边界

以下规则不可改变：

- glTF `STEP` 仍保持阶跃；
- glTF `LINEAR` translation/scale 使用 lerp，rotation 使用规范化 slerp；
- glTF `CUBICSPLINE` 继续使用规范定义的 tangent 与 segment duration；
- quaternion cubic 采样后继续 normalize；
- cubic-bezier easing 只用于 transition weight、程序化 track 和 VFX 属性，不映射为 glTF interpolation；
- `GltfAnimationRig` 不依赖 VFX、UI 或 `EffectAsset`。

## 8. Demo 与集成证明

### 8.1 VfxDemo

在现有 VFX Demo 中增加一个固定种子、固定路径的证明场景：

- 粒子 size 使用“快速长大、缓慢缩小”的三关键帧 track；
- 颜色由高亮黄过渡到橙红并将 alpha 降到 0；
- Ribbon width 使用 ease-out，颜色末端透明；
- Decal scale 先轻微 overshoot 再稳定衰减；
- emitter origin 沿 `BezierPath3f` 近似匀速运动；
- 相同 seed、delta 序列和 origin 序列产生相同 snapshot。

Demo 不增加交互式曲线编辑器。现有开关只需允许比较 `linear` 与 `curved` 两种预设，并在画面或 diagnostics 中显示当前模式。

### 8.2 HaikalatShowcaseDemo

Showcase 中选择一处已有动画切换使用 `transitionBase()`，并由 incoming clip 的正式 `AnimationEvent` 触发 VFX。证明链路为：

```text
AnimationPlayer incoming event
        |
        v
Demo/application event handling
        |
        v
EffectAsset.instantiate(seed)
        |
        v
EffectInstance deterministic update/snapshot
```

Animation subsystem 不直接创建 VFX instance，VFX subsystem 也不依赖 Skeleton 或 AnimationEvent；组合只发生在 Demo/application 层。

## 9. 测试计划

### 9.1 曲线单元测试

至少覆盖：

- 每个 preset 的精确端点和代表性中点；
- 非有限、越界 normalized time；
- cubic-bezier linear identity；
- Newton 求解退化时的二分回退；
- 非法 x control point 和非有限 y control point；
- spring 输出有限且端点精确；
- FloatTrack key time 严格递增、重复 key、空 track、单 key；
- STEP/LINEAR/CUBIC_HERMITE 已知样本；
- ColorGradient 的 stop、alpha、HDR RGB 和防御性复制；
- BezierPath3f 端点、切线、退化路径和弧长反查单调性；
- 同一输入在重复采样和不同实例间结果一致。

### 9.2 VFX 单元测试

扩展 `EffectInstanceTest`：

- 未配置曲线时旧固定种子快照保持相同；
- size、color、width、scale 在 0%、50%、100% 生命周期符合已知值；
- spring overshoot 在 alpha、blend weight 等受限属性上正确 clamp；
- 非法 size/width/scale 曲线输出明确失败；
- 大 delta 导致 primitive 过期时不采样无效年龄；
- close、asset/instance owner、透明稳定排序和统计不回退；
- curved 与 linear 模式均保持有界集合和确定性。

### 9.3 Animation 单元测试

至少覆盖：

- 0 duration 立即切换；
- 过渡起点、中点和终点 pose；
- ease-in-out 与 linear 权重差异；
- transition 中途被替换时无 pose 跳变；
- layer fade 替换、取消和 clear；
- outgoing event 不再发布，incoming event 只发布一次；
- loop、once、pause、resume、seek 和大 delta；
- root motion translation/rotation 混合；
- Bone Mask 与 layer fade 同时工作；
- 现有 glTF cubic、动作事件和 IK 测试不变。

### 9.4 架构与真实 GL 测试

- `core.curve` 不包含 `org.lwjgl` 或 `subsystems` import；
- `subsystems.animation` 和 `subsystems.vfx` 继续无 OpenGL 调用；
- 新 public 类型完成 allowlist 分类；
- VFX renderer 能消费曲线生成的 snapshot，真实像素非空且资源关闭归零；
- Showcase cross-fade 与 VFX 事件在固定帧数运行后状态稳定；
- resize 不改变曲线时间，也不重置正在执行的 transition；
- diagnostics OFF/ON 不改变模拟结果。

## 10. 性能与分配预算

曲线是每 primitive、每帧可能执行的热路径，必须满足：

- preset easing 单次采样零分配；
- cubic-bezier 单次采样零分配，固定最大迭代次数；
- FloatTrack segment 查找为 `O(log n)`，常见 2 到 4 key 不创建临时数组；
- ColorGradient 写入 caller destination，不额外创建颜色对象；
- BezierPath3f 的弧长表仅构建一次；
- 未启用自定义曲线的旧 VFX 路径不增加 track 查找；
- 10,000 active particle 的 CPU snapshot 时间不得相对 v0.18.0 线性基线回归超过 10%；
- diagnostics OFF 不新增每帧集合、字符串或 JSON 对象；
- 性能结论使用相同 seed、粒子数、帧数、warmup 和硬件环境比较。

若 cubic-bezier 求解成为热点，可以在 `EffectAsset` build 时烘焙固定 64 或 128 sample LUT，并使用线性查表；但必须先保留直接求解作为正确性参考，并量化误差与性能收益，不能凭假设替换。
