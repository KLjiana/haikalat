# v0.23.1 Render3D 光源与阴影深化计划

> 状态：已完成（2026-08-19）
>
> 目标版本：`0.23.1-SNAPSHOT` → `0.23.1`
>
> 实施基线：`v0.23.0` 发布提交 `c904283`，并包含后续稳定 revision fast path 修复 `67afe3b`
>
> 版本主题：在不更换 Forward/PBR 主架构的前提下，补齐多局部光阴影、确定性预算调度、稳定 atlas 槽位、按需更新与阴影质量控制

## 1. 版本定位

v0.23.0 已经把 Render3D 的 revision、frame context、render queue、透明材质、MASK shadow、MSAA depth resolve、级联方向光阴影、可见性和诊断合同收拢到一条稳定主路径。v0.23.1 不再继续铺设新的顶层渲染架构，而是沿光源与阴影链路做一次有边界的纵向深化。

当前光照着色器可以接收 2 盏方向光、8 盏点光和 4 盏聚光，但阴影阶段每帧只选择第一盏可用方向光、第一盏点光和第一盏聚光。点光固定使用一个 3×2 六面 atlas，聚光固定使用一张 depth map；只要存在阴影光源，对应深度内容原则上每帧重画。这个实现适合能力闭环和小型 Demo，却还不能稳定承载多光源室内场景，也无法解释预算不足时为什么某盏灯没有阴影。

因此，本版本把目标收敛为四件事：

1. 在已有着色器光源上限内，同时支持有界数量的多点光和多聚光阴影。
2. 用确定、可诊断且不会随轻微相机抖动频繁换槽的调度器分配阴影预算。
3. 让固定阴影 atlas 能复用未变化的 tile，只更新真正失效的方向级联、点光六面组或聚光 tile。
4. 统一阴影采样质量、bias 和 atlas 边界合同，避免 acne、peter-panning 与跨 tile 污染。

这仍是一次补丁版本增强：默认场景的视觉结果和资源预算必须兼容 v0.23.0，新增容量通过显式高级设置开启。

## 2. 当前基线与缺口

### 2.1 已有能力

- `LightingBinder` 最多上传 2 盏方向光、8 盏点光和 4 盏聚光。
- 一盏方向光可使用 1～4 级 CSM，具备 practical split、world-texel snapping、tile PCF 和级联过渡。
- 一盏点光使用 `PointShadowAtlas` 的 3×2 六面 depth atlas。
- 一盏聚光使用 `SpotShadowMap` 的单张透视 depth map。
- 普通 mesh、实例化 mesh、glTF 静态 mesh、skin、morph 和 `MASK` 材质已经进入统一 shadow caster 路径。
- `Scene.lightingRevision()`、transform/model revision、material/render-state revision 和 pipeline generation 已能表达主要失效原因。
- `LocalShadowMathTest`、`LocalShadowsGlTest`、`DirectionalCascadeSettingsTest`、`RenderPipelineGlTest` 与 `runLocalShadowsIntegration` 已覆盖单灯闭环。

### 2.2 主要限制

| 领域 | v0.23.0 状态 | v0.23.1 目标 |
| --- | --- | --- |
| 方向光阴影 | 第一盏满足条件的方向光；最多 4 级 CSM | 保持一盏方向光预算，但选择可解释、更新可缓存、采样质量统一 |
| 点光阴影 | 每帧最多一盏，固定 3×2 atlas | 高级模式最多两盏，每盏独占稳定的 3×2 block |
| 聚光阴影 | 每帧最多一盏，单张 depth map | 高级模式最多四盏，使用固定 2×2 spot atlas |
| 选择策略 | 同类型中取第一个 | 明确优先级、相机影响、稳定 ID、迟滞和拒绝原因 |
| atlas 生命周期 | 固定目标，但内容通常每帧重画 | generation 首次清理，之后仅清理和重画 dirty tile/block |
| 采样质量 | 各类阴影分别持有 bias/PCF 逻辑 | 统一 quality preset、slope/normal bias 与 tile guard band |
| 诊断 | 只报告 selected/none | 报告候选、入选、拒绝、槽位、cache hit/miss 和重画 tile 数 |
| 配置 | `LocalShadowSettings` 只有分辨率、near、bias | 保留旧记录构造器，新增组合式 pipeline settings，不破坏旧调用 |

## 3. 范围与非目标

### 3.1 必须完成

- 一帧同时渲染最多 1 盏方向光、2 盏点光和 4 盏聚光的阴影。
- 新增不可变 `ShadowFramePlan`，让 pass 构建、深度绘制、PBR 绑定和诊断消费同一份选择结果。
- 为场景内灯光分配稳定的进程内 ID；`setLight()` 替换参数时保留 ID。
- 新增有界、确定性的阴影调度器；超出预算时输出具体拒绝原因。
- 点光与聚光使用各自的固定 atlas；不把两类投影强行塞入一个通用纹理抽象。
- atlas 槽位跨帧稳定，支持 dirty block/tile 的局部清理和重画。
- 静态帧复用上一帧有效阴影内容；移动一盏局部光时只重画它自己的槽位。
- 全部 shadow caster 类型继续遵守 `OPAQUE / MASK / BLEND` 与 skin/morph 合同。
- GL 测试、集成 Demo、诊断、性能基线、能力矩阵和发布报告形成闭环。

### 3.2 明确不做

- 不引入 Deferred、Forward+、Clustered Lighting 或新的 G-buffer 主路径。
- 不提高普通照明的 2/8/4 shader 上限，不承诺无限动态光源。
- 不实现 Virtual Shadow Maps、ray-traced shadows、contact shadows 或 screen-space shadows。
- 不实现 VSM/EVSM、半透明彩色阴影、软阴影面积光或 PCSS。
- 不支持两盏方向光同时拥有完整 CSM；太阳/月亮切换仍由预算调度选择一盏。
- 不在本版本引入 GPU-driven shadow culling、indirect shadow submission 或通用空间索引。
- 不为了共享代码合并方向、点光和聚光投影数学；共享数据合同，不抹平投影差异。
- 不删除现有 `LocalShadowSettings`、`PointShadowAtlas`、`SpotShadowMap` 或旧构造方式。

## 4. 目标架构

### 4.1 单一帧计划

每帧只允许执行一次阴影选择。`ForwardPassBuilder`、shadow pass、PBR shader 绑定和 diagnostics 不得分别调用“寻找第一盏阴影灯”的方法。

```text
Scene lights + stable IDs + camera + revisions + settings
                           │
                           ▼
                  ShadowLightScheduler
                           │
                           ▼
                    ShadowFramePlan
       ┌───────────────────┼───────────────────┐
       ▼                   ▼                   ▼
 Directional plan     Point slot plans     Spot slot plans
       │                   │                   │
       └──────────┬────────┴─────────┬─────────┘
                  ▼                  ▼
          dirty tile rendering   PBR sampling block
                  │                  │
                  └────────┬─────────┘
                           ▼
                  Render3dDiagnostics
```

建议新增以下 package-private 类型：

| 类型 | 职责 |
| --- | --- |
| `SceneLightEntry` | 稳定 light ID、当前 `SceneLight`、shader index、shadow hints |
| `ShadowLightScheduler` | 收集候选、评分、迟滞、预算和槽位分配；不调用 GL |
| `ShadowFramePlan` | 本帧不可变的方向/点光/聚光选择、矩阵、槽位、dirty 状态与原因 |
| `PointShadowSlotPlan` | point light ID、shader index、3×2 block、六个矩阵和 dirty 原因 |
| `SpotShadowSlotPlan` | spot light ID、shader index、tile、矩阵和 dirty 原因 |
| `ShadowAtlasAllocator` | 持有稳定 ID 到 slot 的小型有界映射；不拥有纹理 |
| `ShadowCacheKey` | light、caster、material、animation、camera/cascade 与 settings revision 的显式快照 |
| `ShadowSamplingBlock` | 将槽位映射、矩阵、UV rect 和质量参数一次打包给内置 PBR shader |

这些类型先留在 `subsystems.render3d` 包内。没有第二个消费者前，不建立公共 ShadowManager 或通用 light ECS。

### 4.2 稳定灯光身份

`SceneLight` 是值对象，不能把对象地址、`identityHashCode` 或当前数组下标当作长期 cache key。`Scene` 内部应像 renderer 一样给灯光分配单调递增的 process-local ID：

- `addLight()` 创建新 ID。
- `setLight(index, replacement)` 保留原 ID，只增加 lighting revision。
- 删除/重排能力未来加入时不得复用已释放 ID。
- shader index 仍表示本帧上传数组位置，只用于 shader 映射，不用于 cache 身份。
- 序列化场景无需持久化 runtime light ID；重新加载场景自然产生新 generation 和新 ID。

如果需要内容侧控制，新增非破坏性重载：

```java
scene.addLight(light, ShadowLightHints.priority(100));
scene.setShadowLightHints(index, hints);
```

旧的 `addLight(SceneLight)` 等价于默认优先级 0。不要给 `SceneLight` record 增加字段，以免破坏现有构造器和反序列化代码。

## 5. 公共设置与兼容性

### 5.1 新增组合式设置

建议新增公共不可变配置 `LocalShadowPipelineSettings`，由 `RenderPipeline.localShadows(...)` 在 `build()` 前设置。它组合而不是替换现有 `LocalShadowSettings`：

```java
public record LocalShadowPipelineSettings(
        LocalShadowSettings point,
        LocalShadowSettings spot,
        int maxPointLights,
        int maxSpotLights,
        ShadowSelectionMode selectionMode,
        ShadowFilterMode filterMode,
        float normalBias,
        float replacementThreshold,
        boolean cacheStaticTiles
) { }
```

约束：

- `maxPointLights` 必须在 `[0, 2]`。
- `maxSpotLights` 必须在 `[0, 4]`。
- `replacementThreshold` 必须有限且 `>= 1.0`；建议默认 `1.15`。
- `normalBias` 必须有限且非负。
- point/spot 的 `nearPlane` 必须小于每个入选灯光的 `range`；不合法候选应被明确拒绝，而不是在 pass 中途抛出。
- 设置在 generation 创建前冻结；容量、分辨率变化属于 topology change，评分和 bias 变化只属于 frame-data change。

提供两组工厂：

- `legacyDefaults()`：1 点光、1 聚光、512 px、当前 bias 和 PCF 行为，视觉及资源预算兼容 v0.23.0。
- `balanced()`：2 点光、4 聚光、512 px、稳定调度、PCF 3×3、缓存开启，用于 v0.23.1 Demo 与完整验收。

### 5.2 选择模式

`ShadowSelectionMode` 第一版只提供：

- `SCENE_ORDER`：优先级高者在前，同优先级按稳定 light ID；这是兼容模式。
- `CAMERA_IMPORTANCE`：优先级优先，再按相机可见性和屏幕影响评分，最后按稳定 light ID 打破平局。

不要暴露任意回调作为排序器，避免渲染线程执行不受控用户代码。未来确有需求时再设计策略扩展点。

### 5.3 阴影采样模式

`ShadowFilterMode` 第一版限定为：

- `HARD`：单采样，用于诊断和低端模式。
- `PCF_3X3`：默认质量档。
- `PCF_5X5`：可选高质量档，只作为显式设置，不作为默认值。

三个模式共用 tile guard、slope bias 和 normal bias 规则，不复制三套互不一致的 shader 函数。

## 6. 阴影预算与调度

### 6.1 候选范围

- 只从实际会上传到 PBR shader 的 2/8/4 有界灯光数组中选择阴影候选。
- `castShadows=false`、强度为 0、range 不合法、超出 shader 光源上限或配置容量为 0 的灯光均不进入分配。
- 方向光、点光和聚光分别有预算，不允许一盏点光挤占聚光 tile。
- 方向光仍只选择一盏；高级模式只扩展局部光数量。

### 6.2 相机影响评分

`CAMERA_IMPORTANCE` 必须使用简单、可重复测试的评分，不引入遮挡查询或 GPU readback：

1. 内容侧 `ShadowLightHints.priority` 为第一排序键。
2. 与相机 frustum 无交集的局部光降级，但不因边界浮点误差直接抖动出槽。
3. 可见局部光按投影影响近似评分，可使用 `range / max(distance, nearPlane)` 的有界函数；聚光额外考虑视锥朝向。
4. 当前槽位拥有者获得保留加成。挑战者评分只有达到 `occupantScore * replacementThreshold` 才能替换。
5. 全部相等时按稳定 light ID 升序，结果不得依赖 `HashMap` 遍历顺序。

评分只决定有限预算的归属，不改变实际光照数组顺序。

### 6.3 拒绝原因

每个 shadow-capable 候选最多拥有一个终态：

- `SELECTED`
- `DISABLED_BY_SETTINGS`
- `OUTSIDE_SHADER_LIMIT`
- `INVALID_NEAR_FAR_RANGE`
- `OUTSIDE_CAMERA_INFLUENCE`
- `LOWER_PRIORITY`
- `BUDGET_EXHAUSTED`
- `HELD_BY_HYSTERESIS`

原因进入结构化 diagnostics；日志默认不逐帧刷屏，只在选择结果变化或 debug snapshot 请求时输出。

## 7. Atlas 布局与资源预算

### 7.1 保持两类局部 atlas

点光和聚光继续使用两个 sampler，避免为了“统一”引入复杂的可变 tile 投影协议。

点光 atlas：

- 每盏点光占一个连续 3×2 block。
- `maxPointLights=2` 时布局为 3 列 × 4 行。
- slot 0 使用行 0～1，slot 1 使用行 2～3。
- `viewportX(slot, face)` 与 `viewportY(slot, face)` 必须同时验证 slot 和 face。
- 每个 slot 向 shader 提供六个矩阵、shader light index 和 block/face UV rect。

聚光 atlas：

- 新增 `SpotShadowAtlas`，高级容量 4 时使用 2×2 tile。
- 每个 slot 提供一个 light-space matrix、shader light index 和 tile UV rect。
- 现有 `SpotShadowMap` 保留；旧构造方式可映射为容量 1 的 atlas，不能直接删除公共类型。

### 7.2 容量上限理由

按 512 px、32-bit depth 粗略估算：

- 两盏点光：`1536 × 2048`，约 12 MiB。
- 四盏聚光：`1024 × 1024`，约 4 MiB。
- 高级局部阴影合计约 16 MiB，不含 framebuffer 对象的少量开销。

这是有意设置的硬上限。更高容量应等待 Forward+/Clustered 或独立的阴影预算项目，不在本补丁版本通过继续扩大静态数组解决。

### 7.3 Tile 隔离

- PCF 采样坐标必须 clamp 到当前 face/tile 的半 texel 内边界。
- 5×5 kernel 的 guard 范围按 2 texel 计算，不能沿用 3×3 的 1 texel 边界。
- point face 选择发生在采样前；kernel 不得跨入相邻 cube face。
- 所有 viewport、scissor 和 UV rect 由同一 atlas layout 对象生成，禁止 CPU 绘制布局和 shader 采样布局分别维护常量。
- resize 不重建固定 atlas；只有分辨率、容量或 depth format 改变才创建新 generation。

## 8. 缓存与局部更新

### 8.1 Cache key

每个方向级联、point block 和 spot tile 至少比较：

- scene generation；
- stable light ID 与灯光参数 revision；
- shadow caster membership revision；
- caster transform/model revision；
- material/render-state 与 alpha-cutoff revision；
- skin/morph/deformation revision；
- shadow settings/topology revision；
- 对方向级联，额外包含稳定化后的 cascade matrix/split key；
- 对局部光，不把无关 camera jitter 计入深度内容 key。

不能只比较 `Scene.lightingRevision()` 后重画全部槽位。需要从本帧 light entry 判断是哪一盏灯变化；第一版可对 caster 变化保守地标记所有已分配槽位 dirty，但灯光自身变化必须做到单槽失效。

### 8.2 保留深度内容

RenderGraph 若在 pass 开始时无条件清理 depth attachment，缓存将失去意义。实现必须显式采用以下合同：

1. 新 atlas generation 创建后执行一次全图 depth=1 清理。
2. 后续 shadow pass 不执行自动全图 clear。
3. dirty point block 按六个 face 分别设置 viewport/scissor、清理该 face、提交 caster。
4. dirty spot tile 设置 viewport/scissor、清理该 tile、提交 caster。
5. clean slot 完全不清理、不绘制，继续采样上一有效内容。
6. slot 被释放时无需立即清理；分配给新 light 时必须先清理再绘制。
7. pass 抛异常时该 slot 不得标记 valid；下一帧必须重新清理和绘制。

如果现有 RenderGraph clear 策略不能表达这一点，只增加 package-private 的 shadow pass preserve/explicit-clear 路径，不把条件 pass 扩展成未经验证的公共 RenderGraph API。

### 8.3 更新粒度

- 方向光：以 cascade tile 为最小诊断单位；第一版可以在任一 caster 变化时重画全部 cascade，但静止相机、静止灯光、静止 caster 时必须整图命中缓存。
- 点光：一盏灯的 6 个 face 作为一个一致性 block。第一版不做逐 face caster culling，任一 face 失效时重画整个 block。
- 聚光：一个 tile 为最小更新单位。
- shader 选择变化但 atlas 内容未变化时，只更新 sampling block，不重画深度。

### 8.4 动态内容

- skin/morph 动画对象每帧发生 deformation revision 时，包含它的阴影槽位必须失效。
- 非 revisioned model updater 继续按每帧动态处理，不能错误命中静态缓存。
- `castShadows=false` 和 `BLEND` 对象不得参与 cache key；`MASK` 的纹理、cutoff 或 UV 变化必须参与。
- 实例化批次中任一投影实例发生变化时，第一版允许使相关槽位整体失效，不强求实例级 tile 更新。

## 9. Shader 与绑定合同

### 9.1 从单索引改为槽位映射

内置 PBR shader 不再只接收：

- 一个 `uPointShadowLightIndex`；
- 一组六面 `uPointShadowMatrices[6]`；
- 一个 `uSpotShadowLightIndex`；
- 一个 `uSpotShadowMatrix`。

新合同使用固定上限的槽位映射：

- 每个 point shadow slot：shader light index、六个矩阵、atlas block/face rect、valid flag。
- 每个 spot shadow slot：shader light index、矩阵、tile rect、valid flag。
- shader 根据当前 lighting array index 查找 shadow slot；未映射返回 0 shadow。
- 数组容量必须与 Java 常量和 shader `#define` 通过测试锁定。

### 9.2 数据上传

不应在每个 draw 上逐个录制几十个矩阵 uniform。建议新增 subsystem-owned 的 `ShadowSamplingBlock` UBO：

- frame plan 冻结后只打包一次。
- 每次 PBR draw 只绑定同一 buffer range。
- 使用现有 `GlBuffer.uniformBuffer()` 和 `CommandBuffer.bindUniformBuffer()`，不新增 core buffer 抽象。
- buffer 由当前 `PipelineGeneration` 持有并释放。
- std140 layout、binding point、容量和字节大小必须由 Java/GL 合同测试验证。

普通 light 数组是否一起迁移到 UBO 不作为 v0.23.1 发布条件。只有独立 profile 证明能降低录制成本且不会破坏自定义 shader 兼容时才顺带迁移；否则本版本只迁移新增 shadow sampling 数据。

### 9.3 Bias 合同

- `LocalShadowSettings.bias()` 继续作为 base depth bias，保持旧 API 语义。
- slope bias 由 `max(baseBias * slopeFactor, baseBias * minimumFactor)` 计算，三个光型共享公式。
- normal bias 沿接收面法线偏移采样位置；其世界空间含义必须记录，不能随 atlas 分辨率无意变化。
- directional cascade 可按 texel world size 缩放 bias，远级不应与近级使用完全相同的世界偏移。
- 默认值必须以现有 PBR Demo 为视觉基线，先解决 acne，再限制 peter-panning；不得以大幅提高 bias 掩盖 atlas 或矩阵错误。

## 10. Pass 与生命周期合同

### 10.1 Pass 规划

- `ForwardPassBuilder` 只根据 `ShadowFramePlan` 决定 pass 是否存在，不再自行扫描 `Scene.lights()`。
- 一个 point shadow pass 可以循环多个 dirty block，不为每盏点光创建不同名字的 RenderGraph pass。
- 一个 spot shadow pass可以循环多个 dirty tile。
- directions、point 和 spot pass 名称继续稳定，保证 profiler、preview 和测试不因容量变化产生动态 pass 名。
- 无任何入选光源时不得创建或绑定对应 atlas；容量为 0 时不分配资源。

### 10.2 事务化 generation

- atlas 容量、分辨率、format 或 CSM topology 变化必须走 candidate-first generation 替换。
- candidate atlas 创建、framebuffer 完整性检查或 sampling block 创建失败时，旧 generation 保持可用。
- candidate 失败创建的 texture/framebuffer/buffer 全部关闭。
- `RenderPipeline.close()` 重复调用安全，sampling UBO 与所有 atlas 只释放一次。
- 嵌入式 borrowed target 与固定 shadow atlas 的所有权继续分离。

### 10.3 状态恢复

- 每个 tile 绘制都显式设置 viewport 和 scissor；结束后通过现有状态缓存恢复或使后续 pass 显式覆盖。
- scissor clear 必须经过受控命令路径，不能在 pass callback 中散落裸 GL 调用。
- shadow pass 异常不得把错误状态写入 cache，也不得遗留错误 framebuffer/viewport 给下一 pass。
- GL debug policy 对新增 pass 和 Demo 使用稳定 context label。

## 11. 诊断与可观察性

`Render3dDiagnostics` 至少新增：

- `directionalShadowCandidates / selected`
- `pointShadowCandidates / selected / capacity`
- `spotShadowCandidates / selected / capacity`
- 每个 selected light 的 stable ID、shader index、slot 和评分摘要
- 每个 rejected light 的 stable ID 与拒绝原因
- `shadowTilesRendered`
- `shadowTilesReused`
- `shadowCacheHits / shadowCacheMisses`
- miss reason：light、caster membership、transform/model、material、deformation、camera/cascade、settings、new allocation
- 当前 filter mode、point/spot resolution、atlas dimensions 和估算 depth memory

日志策略：

- release 默认不逐帧输出选择详情。
- 选择集合、slot ownership 或 cache miss 原因发生变化时可输出一次 debug 事件。
- frame diagnostics history 保存结构化摘要，UI/日志只消费它，不在渲染线程重复扫描场景。
- GL integration 验收不能只看进程退出码；必须同时扫描 HIGH/MEDIUM debug 消息和 `glGetError` 结果。

## 12. 实施里程碑

### M0：基线冻结与合同测试

- 将 Gradle 版本从 `0.23.0` 调整为 `0.23.1-SNAPSHOT`。
- 记录 legacy 1 point + 1 spot 场景的 pass、像素、CPU/GPU 时间、atlas 尺寸和 GL 日志基线。
- 为当前单索引 shader 合同、3×2 point atlas 和单 spot map 补齐锁定测试。
- 写明哪些设置属于 topology，哪些只使 frame plan/cache 失效。

验收：默认 `compileJava demoClasses test` 通过；`runLocalShadowsIntegration` 通过；GL 日志无 HIGH/MEDIUM 和 error。

### M1：稳定 light ID、配置与纯 CPU 调度器

- `Scene` 内部引入 stable light ID，`setLight()` 保留身份。
- 新增 `ShadowLightHints`、`LocalShadowPipelineSettings`、选择与 filter 枚举。
- 新增纯 CPU `ShadowLightScheduler` 和不可变 `ShadowFramePlan`。
- `LightingBinder`、`ForwardPassBuilder` 与 diagnostics 改为消费同一帧计划。
- 先保持实际 GPU 容量 1+1，证明架构切换不改变 legacy 像素。

验收：顺序、优先级、shader 上限、迟滞、非法 near/range、预算拒绝和稳定 tie-breaker 的纯 JVM 测试全部通过。

### M2：多点光与多聚光 atlas

- 扩展 point atlas 为最多两个 3×2 block。
- 新增最多四槽的 `SpotShadowAtlas`，保留 `SpotShadowMap` 兼容入口。
- 完成 viewport/scissor/UV rect 单源布局。
- shadow pass 循环入选 slot，内置 PBR shader 按 light index 映射 slot。
- 引入 `ShadowSamplingBlock` UBO，frame plan 每帧只打包一次。

验收：2 point + 4 spot 同帧产生六组彼此独立的局部阴影；关闭任一灯只影响对应像素和 slot。

### M3：稳定分配与 atlas 局部缓存

- 引入稳定 slot allocator 和 replacement hysteresis。
- 新 generation 首次全清，之后显式 scissor clear dirty tile。
- point 按 block、spot 按 tile、directional 按 cascade 记录 valid/cache key。
- 移动单个局部光只使其 slot 失效；静态帧完全复用局部阴影。
- 异常、资源替换和 slot reassignment 正确回退为 dirty。

验收：连续静态帧 `shadowTilesRendered=0` 且最终像素不变；移动一盏 point 只重画 6 faces，移动一盏 spot 只重画 1 tile。

### M4：质量、bias 与 CSM 深化

- 统一 HARD/PCF 3×3/PCF 5×5 采样路径。
- 根据 kernel 半径正确 clamp face/tile 边界。
- 接入 slope bias、normal bias 和 cascade texel-scaled bias。
- 静止相机与稳定化矩阵命中方向级联缓存；跨 split blend 继续正确。
- 建立 acne、peter-panning、tile bleed、cascade seam 的固定图像/像素断言场景。

验收：三个 filter 档均无跨 tile 采样；默认档相对 v0.23.0 不出现明显阴影漂移或断层。

### M5：Demo、诊断、性能与发布收口

- 扩展 Render3D/PBR 阴影 Demo，固定展示 1 directional + 2 point + 4 spot、MASK caster、skin/morph caster 与静态 cache。
- 新增确定性 `runRender3dShadowBudgetIntegration`，限定帧数并在指定帧移动一盏灯。
- 将任务加入 `localGlVerification`，但不挂入无桌面默认 `check`。
- 更新 capability matrix、Render3D 阴影指南、测试指南、changelog 和 release report。
- 完整验收后将版本从 `0.23.1-SNAPSHOT` 改为 `0.23.1`。

验收：全部发布门禁、GL 日志、视觉样例、缓存计数与性能阈值通过，工作区只含预期发布修改。

## 13. 测试矩阵

### 13.1 纯 JVM

- stable light ID：add 分配、set 保留、scene generation 隔离。
- settings：容量、分辨率、near、bias、normal bias、threshold 和枚举验证。
- scheduler：类型预算、优先级、相机影响、稳定平局、迟滞、槽位复用和拒绝原因。
- atlas math：全部 point face/slot 与 spot tile 的 viewport、scissor、UV rect 不重叠且不越界。
- matrix：point 六面方向、spot 外锥、directional cascade split/stabilization 保持有限且可逆。
- cache key：每种 revision 只失效应失效的内容；无关 resize 不失效固定 atlas 内容。
- frame plan：pass、binding 和 diagnostics 消费同一 selection snapshot。
- UBO layout：Java offset/size 与 std140 shader contract 一致。

### 13.2 GL smoke

- 单方向光、单点光、单聚光的 legacy 像素基线不回退。
- 2 point + 4 spot 同帧可见并各自产生非空阴影差异。
- HARD、PCF 3×3、PCF 5×5 产生预期采样差异且无 atlas bleed。
- `MASK` caster 在所有光型下按 cutoff 投影；`BLEND` 不进入 shadow pass。
- skin/morph 动画使缓存失效并更新阴影。
- 静态帧复用 depth；单灯更新只清理对应 scissor 区域。
- atlas generation 创建失败后旧 generation 继续渲染，candidate 资源全部释放。
- close 幂等，无 use-after-close、framebuffer incomplete、非法纹理单元或 UBO 越界。
- 每项 GL 测试扫描 debug callback：不允许未授权 HIGH/MEDIUM，不允许 GL error。

### 13.3 Integration

- 默认 Demo 保持 legacy 设置和既有视觉结果。
- shadow budget Demo 使用 balanced 设置，在有限帧正常退出。
- 指定帧移动 point、spot、camera 和 caster，诊断中的 dirty/reused tile 数与预期一致。
- resize 前后窗口目标重建，固定 shadow atlas ID/尺寸保持不变。
- 嵌入式目标、隐藏窗口和 deterministic 模式均无线程悬挂或资源泄漏。
- `localGlVerification` 包含原有 local-shadow 测试和新增 budget/cache 测试。

### 13.4 性能

必须比较相同能力配置，不能拿 2+4 阴影与旧 1+1 直接宣称回退：

- legacy 1+1 默认配置：CPU frame、GPU frame 和命令数相对 v0.23.0 中位数回退不超过 5%。
- shadow disabled：不创建局部 atlas，不上传 shadow block，不产生 shadow draw。
- balanced 静态场景：预热后 shadow depth draw 数归零，cache hit 稳定。
- 单点光移动：只增加 6 face 对应的 shadow draw；其他槽位保持 reuse。
- 单聚光移动：只增加 1 tile 对应的 shadow draw。
- frame plan/scheduler 在固定 2/8/4 灯光上不产生随帧增长的集合分配。
- 记录 1080p 与 4K 至少五轮中位数、P95、shadow GPU pass 时间、tile redraw 数和估算显存。

## 16. 完成定义

只有同时满足以下条件，才可把 v0.23.1 标记为正式版：

1. 默认设置保持 v0.23.0 的 1 point + 1 spot 行为和性能基线。

9. GL 日志无未授权 HIGH/MEDIUM，不能仅凭测试进程退出码判断成功。
10. 文档、版本号、release report 与实际实现一致。

完成本版本后，再根据真实场景指标选择 v0.24：如果主要瓶颈是可见动态灯数量，再评估 Forward+/Clustered；如果主要瓶颈是阴影 caster 提交，再评估 GPU-driven shadow culling。两者都不应提前塞入 v0.23.1。
