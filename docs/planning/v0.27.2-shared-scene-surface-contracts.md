# 0.27.2 共享场景表面与输入合同收敛计划

> 计划日期为 2026-11-07，定向功能验收于 2026-11-08 完成。[验收记录](../releases/v0.27.2-review.md)
>
> 承接体积雾与 GTAO 两个已验收试点，收敛深度、法线、运动数据和 reactive 的需求声明、分配、生产顺序与借用合同。本文不表示实现、构建版本升级或发布完成。

## 1. 目标与范围

GTAO、TAA、体积雾已经共同使用场景表面。它们各自管理私有资源后，公共装配仍需了解多个消费者的通道需求、采样数、固定附件位置和实际生产者。本版本集中表达这些共享事实，让消费者声明需求并取得经过验证的输入，减少中心类与各消费者之间重复的条件判断。

```text
0.27.2
├── 必须交付
│   ├── 消费者需求 → 合并／补齐依赖 → 实际表面布局
│   ├── 单采样与 MSAA 原始／resolved 输入合同
│   ├── 通道格式、坐标、producer、代次和所有权
│   ├── GTAO、TAA、体积雾使用共享事实完成装配
│   ├── 附件复用、退役与历史有效性
│   └── 组合状态、原生像素与资源事务验收
├── 保留独立职责
│   ├── Graph 拥有自己创建的附件
│   ├── GTAO／TAA／体积雾各自拥有私有历史
│   └── reactive 保持实际生产时机，不强塞入表面预通道
└── 不做
    ├── 通用 FeatureModule／资源注册中心／自动调度框架
    ├── 全面拆分光照和阴影、新增渲染算法
    ├── Minecraft 地形／光照统一整合
    └── 为枚举中每个通道补造没有消费者的新功能
```

验收重点：修改一个现有消费者的需求时，通常只改变其声明、必要消费代码与实际新生产能力；不需要在 Pipeline、Forward builder、resolve 和多个输入类中同步复制功能开关判断。仅移动代码或更换管理器名字不算完成。

## 3. 当前实现与迁移入口

以下代码位于 `src/main/java/com/kaleblangley/haikalat/subsystems/render3d/`，开工时刷新观察。

| 现有类型 | 已有基础／切口 | 本版本动作 |
|---|---|---|
| `SceneBufferRequirements` | 需求集合、merge、samples、velocity 同伴补齐及 fog/GTAO/TAA 辅助构造已经存在 | 复用并规范化；区分消费需求与生产样本数，明确冲突行为 |
| `SceneBufferChannel` | 七种逻辑通道与基本语义 | 保留含义；没有生产者的通道不能因为枚举存在就标记可用 |
| `SceneBufferView` | 不可变借用句柄，带代次／帧号和单一 samples，缺失通道可返回 0 | 明确公开兼容性及内部执行验证，避免混淆不同采样类型和生产阶段 |
| `PipelineTopology` | 集中拼接各功能需求 | 从消费者声明合并需求，保留拓扑快照，不掌握附件实现细节 |
| `ForwardPassBuilder` | 表面主要分为 depth-only 或固定 normal/velocity/previous-depth/validity 四通道；同时装配阴影和 Geometry | 收敛共享布局／producer 连接，保留必要 Geometry／阴影装配 |
| `SceneSurfacePass`、`SceneSurfaceResolvePass` | 真实绘制与 resolve，完整路径依赖固定附件索引 | 依据同一布局获取槽位与采样信息，保持光栅和 resolve 结果 |
| `SceneReactivePass` | 较晚阶段生成或补充 reactive | 明确实际生产／合并时机，不声称预通道已提供最终 reactive |
| `GtaoSurfaceInputs`、`VolumetricSurfaceInputs` | 已有真实消费者验证，各自编码 producer／格式约定 | 共享通道事实，保留模块专属限制 |
| `PostProcessPassBuilder`、`RenderPipeline`、`PipelineGeneration` | TAA 输入、view 构造、表面资源和候选连接分散 | 统一事实来源，保留帧提交和候选事务的既有责任 |

M0 追踪每个 view／输入类型的实际生产与消费点；不能因为字段有 generationId 就认定已经实现失效检查。

## 4. 需求、布局与借用合同

```text
消费者需求：语义、采样视图、读取阶段（纯 CPU）
  ↓ 合并与依赖补齐
候选私有布局：附件、格式、槽位、样本数、producer
  ├── surface → 必要 resolve
  └── 较晚 reactive producer／合并
  ↓ 完整校验与帧边界发布
借用输入：Graph／代次／帧／读取阶段受限
  ├── GTAO：单采样深度、法线、可选运动数据
  ├── TAA：深度、运动、有效性、实际可用 reactive
  └── 体积雾：当前算法所需原始或 resolved 深度
```

这是职责模型，不要求每层新建接口。优先扩展现有值对象与包内装配；新增抽象必须有真实调用点、隔离收益、失败合同与测试，不建立任意获取所有资源的全局服务。

### 4.1 通道语义与生产时机

| 通道 | 冻结语义／当前典型格式 | 验证重点 |
|---|---|---|
| DEPTH | device depth；原始深度纹理，MSAA resolved 为 R32F | 原始与 resolved 区分，深度约定一致，实际 producer 正确 |
| NORMAL | 世界几何法线，shared signed-oct RG16F | 不与 GTAO 私有 unsigned-oct 缓存混用；与深度样本对应 |
| VELOCITY | 当前表面到上一成功帧表面的 UV 偏移，不含 jitter；RG16F | 相机、实例、skin/morph 与静态表面的意义一致 |
| PREVIOUS_SURFACE_DEPTH | 当前可见表面在上一帧视空间的线性深度；R32F | 不混用当前线性深度或上一帧屏幕深度 |
| VALIDITY | 可靠前帧对应标志；R8 | 新对象／失败／切世界时不伪造有效历史 |
| REACTIVE | 降低或拒绝历史的强度；R8 | 透明／VFX／雾贡献的写入、合并及 TAA 读取顺序 |
| LINEAR_DEPTH | 当前表面的正视空间深度 | 核对实际消费者和生产者；未实现则拒绝必需请求，不返回假句柄 |

velocity 的伴随需求继续补齐 previous-depth 和 validity。布局必须区分 requested 与 produced；实现需要成组生成其他通道时应记录理由，不能把所有组合都分配全套附件描述为按需。

**最少验证三类实体布局：**仅深度、深度＋法线、运动数据组（按消费者可含法线），另独立处理 reactive。允许 Shader 存在未映射输出，但不能仅为固定索引方便而常驻无用附件；M1/M2 明确 draw-buffer 映射与实现方式，不预先要求大量 Shader 变体。

场景光栅样本数来自有效 AA 配置；同时满足原始 MSAA 和单采样消费需求。不能简单取请求最大 samples 后把所有消费者都当多采样。重复需求应幂等、合并顺序无关；不支持的采样要求和缺失 producer 在发布前失败。

### 4.2 MSAA 与执行顺序

- 保持现有最近覆盖样本规则；normal、velocity、previous-depth、validity 与所选深度来自同一样本，不能独立选样或平均。
- M0 固定无覆盖像素、相同深度的确定性行为，不在重构中顺便改变。
- 仅为实际单采样消费者创建必要 resolve；原生 MSAA 消费者仍读取原始样本。
- 按实际 producer 建立显式 `dependsOn`，不依赖注册顺序，不把 reactive 的最终 producer 误接到 surface pass。
- 缺失必需输入应报错；对原有返回空／静默跳过逐项区分合法关闭与非法装配，禁止用旧像素或黑图替代失败。

### 4.3 所有权与有效期

Graph 拥有自己创建的附件；表面组件拥有程序和必要私有绘制资源；消费者仅借用。GTAO／TAA／雾历史仍各有唯一 owner，宿主附件始终归宿主。

借用输入应能核对通道、格式、尺寸、采样类型、producer 和 Graph／代次。帧内数据还需检查帧号与可消费阶段。旧 view 在 resize、切世界、关闭或发布新代后，不能通过生产绑定入口继续使用；裸 GL ID 可能复用，不能单独证明有效。

现有公开 `SceneBufferView` 构造器和单一 samples 的兼容方案需在 M1 明确。内部可分离 raw/resolved 视图或增加每通道描述，但不能静默改变旧字段含义。保留可选通道查询，必需通道显式验证；本版本不要求补造未有消费者的 LINEAR_DEPTH 算法。

### 4.4 事务、资源复用与历史

候选布局和输入记录必须私有，不能修改活动回调、历史或 donor。编译、输入和预算校验成功后帧边界一次发布；兼容附件沿用 descriptor＋共享源身份的借用转交机制。最后消费者退出时才回收无用附件和 Pass，其他消费者仍依赖的资源不得释放。

发布前失败保留旧图、旧设置和可绘制像素；发布后退役失败保持新状态并保留可重试 owner；部分 GPU 写入不宣称回滚，恢复必要历史。峰值覆盖活动、候选、待退役资源，共享附件只按真实所有者计一次，不分别记到 GTAO 和雾后重复宣称节省。

存储复用与历史有效性分别判断。纯布局变化而输入语义不变，不应无故清空所有历史；尺寸、世界或输入语义变化按消费者依赖失效并记录原因。最终颜色变化可使 TAA 内容失效，但不要求重建其存储。

## 5. 实施阶段

| 阶段 | 交付内容 | 退出条件 |
|---|---|---|
| M0 身份与生产图 | 固定完整候选；逐消费者记录需求、实际附件、producer、借用和历史；保存 NONE/TAA/MSAA 参考 | requested 与分配差异可解释，已知缺陷与未实现通道单列 |
| M1 合同与纯布局 | 复用 Requirements，定义规范化、raw/resolved、槽位、代次、公开兼容和预算 | 合并幂等／顺序无关；非法请求确定失败；不建设平行资源系统 |
| M2 生产者收敛 | 统一表面分配和 resolve，支持三类最小布局；整理阴影／Geometry 连接 | 原生 GL 写入符合布局，不依赖固定四附件索引；保留冷启动／变形修复 |
| M3 消费者迁移 | GTAO、TAA、雾采用共享通道事实，reactive 连接实际 producer | 无重复 producer／格式猜测，不泄漏模块私有实现 |
| M4 事务与组合 | 需求增减、失败、resize、退役、视图过期与历史隔离 | 共享资源只释放一次，单侧切换不破坏另一模块，无无理由全局重建 |
| M5 定向验收 | 原生像素、布局组合、故障／冷启动／嵌入式验证与职责审查 | 必需项闭合；功能、资源、性能、宿主、发布分别记录 |

每阶段形成可审查的小步变更。发现旧算法缺陷时独立修复并更新正确基线，避免将结构迁移和算法调优混在不可解释的变化中。

## 6. 验收矩阵

| ID | 场景 | 必须证明 |
|---|---|---|
| S01 | 需求规范化与冲突 | 空需求、重复／顺序变化、velocity 同伴、缺失 producer／不支持模式的确定结果 |
| S02 | 三类布局 | 实际附件数、格式、draw-buffer 映射与需求一致；仅深度不常驻无用 normal/motion 附件 |
| S03 | MSAA 细边缘／无覆盖／同深度 | resolve 各同伴通道选样一致；首帧、移动和 resize 的原生读回正确 |
| S04 | producer 顺序 | GTAO/TAA/雾依赖实际生产者；交换无关 Pass 注册顺序不改变正确结果 |
| S05 | GTAO × 雾 × AA | NONE/TAA/MSAA4 下四种开关组合，覆盖 GTAO temporal 变化、样本视图及需求增减 |
| S06 | reactive、透明／VFX | 最终 producer 在 TAA 前完成；原生雾采样、透明自身深度、reactive alias 与缺省回退正确 |
| S07 | 单侧变化和复用 | 参数不重建布局；开关只替换必要附件；最后消费者退出释放，其他 owner/history 合理复用 |
| S08 | 非法／过期输入 | 错误格式／尺寸／samples／Graph／世界／帧阶段被拒绝，旧 view 不因 ID 复用而复活 |
| S09 | 候选／执行／退役失败 | CPU、附件、Shader、编译失败旧图可绘制；部分写入不提交错误历史；fence 故障可重试 |
| S10 | 奇数尺寸／双视图／世界 | 尺寸和代次一致，互不污染；失败 resize 保留旧输入与像素，零尺寸沿用宿主策略 |
| S11 | MASK／实例／skin/morph／污染状态 | 保留 0.27.1 基线；原生法线有限、通用属性污染控制和有效 SSBO 范围通过 |
| S12 | 小尺寸循环及关闭 | 至少 50 次需求拓扑切换穿插 resize／失败；创建释放对账，固定组合无增长，最终 live=0 |
| S13 | 嵌入式目标与状态 | 借用附件存活，FBO／viewport／texture/sampler／SSBO 恢复；错误线程／Context 在 GL 前拒绝 |
| S14 | 责任与消费审查 | GTAO/TAA/雾三条生产链使用同一通道事实；中心与消费者没有第二套有效分配／producer 决策 |

S05 的 12 种核心组合使用小尺寸定向 GL，不要求每种再跑全画质或性能矩阵。纯拓扑／附件组合可以便宜验证，像素、故障与历史合同必须真实执行 GPU。

迁移前冻结输入和像素比较方式。确定性且算法未变的路径优先逐字节比较；非确定性先解释并冻结容差，不在看到失败后放宽。冷启动复用 0.27.1 定向循环及污染控制，不能用单次暖运行替代。

## 7. 选测和证据预算

优先扩展 `SceneBufferRequirementsTest`、`PipelineTopologyTest`、`SceneVelocityMathTest`、`SceneVelocityGlTest`、`SceneReactiveGlTest`、`TemporalTransactionGlTest`、`GtaoModularityGlTest`、`VolumetricModularityGlTest`、`VolumetricCompositeGlTest` 和 `EmbeddedPresentationGlTest`。Graph／共享附件所有权改变时补对应 RenderGraph／RenderTargetManager 测试。

每轮按实际差异选择叶子任务，核对 glSmoke／glReadback 等属性、实际执行数和退出码。跳过、UP-TO-DATE 和旧报告不算新鲜通过；复用保留原指纹和理由。

普通功能签收默认总时限 5 分钟：相关 JVM＋GL＋一个必要主场景；超时列未完成项，不无限重试。明确性能承诺或有效回退迹象才另排测量，不默认运行 4K、完整体积雾质量矩阵和全部历史长测。

新鲜嵌入式 GL 是必需项。宿主协议未变时可复用原 Minecraft 协议证据；若改变实际借用／复制语义，则补真实客户端对应操作。没有世界深度／光照输入，不宣称 Minecraft 统一视觉完成。

性能未测写 `NOT_EVALUATED`；对象和格式估算可证明按需分配，不能代替驱动显存或 FPS 测量。历史性能欠账不因布局收敛自动关闭。
