## 技术卡

| 字段 | 内容 |
|---|---|
| 技术 ID／用户场景 | #30 Planar Reflections；为水面、镜面地板等需要屏幕空间对齐镜像视图的真实表面提供限定的平面反射颜色与深度。首版默认关闭，最多 1 个平面。 |
| 当前基础／差距 | 已有 `Camera`/`ExternalCamera`、`CameraProjection`、共享 `CommandBuffer`、`Framebuffer`/`FramebufferDescriptor`、`FrontFace` 与 `PipelineGeneration` 的候选代/借用资源协议；`WaterSurfacePass` 和 `SsrPass` 展示了 Pass 与资源生命周期风格。缺少独立的镜像相机/斜裁剪数学、反射 FBO、更新节流和递归防护。 |
| 首版范围 | 1 个世界空间平面（点 + 单位法线；`planeY(level)` 为水平面快捷方式）；镜像视图由 `V * R` 构造；Lengyel 斜近平面裁剪；正面绕序翻转为 `CW`；独立 RGBA16F 颜色 + `DEPTH_COMPONENT24` 深度 FBO；分辨率缩放/上限、更新间隔、近平面偏移；显式递归防护。**排除**多平面混合、反射内再反射、屏幕空间射线、时域累积、MSAA、透明排序、深度重建/近远平面语义、动态移动平面和完整水下渲染。 |
| 不支持输入／拒绝 | `enabled=false` 时构造函数拒绝创建 Pass；`planeNormal` 为零/非有限、resolutionScale 不在 `(0,1]`、maxResolution 不在 `[1,16384]`、updateIntervalFrames 不在 `[1,1000]`、nearPlaneOffset 负数/非有限、平面点超出 ±1e6 米均在设置构造期拒绝。平面在运行期不可移动；移动平面必须替换 settings/Pass（候选代语义）。相机位于平面保留侧或平面上（符号距离 ≤ 1e-4 米）时跳过更新并保留上一次成功内容。 |
| 模块与控制 | 新职责包 `subsystems.render3d.planar`：advanced `PlanarReflectionSettings`、advanced `PlanarReflectionMath`（GL-free）、internal `PlanarReflectionPass`（`GlResource`）。`RenderPipeline`/`RenderFeaturesControl`/`PipelineFeaturePolicy` **本包未接线**（文件 owner 限制），由 Integrator 按下方接线点完成。`PlanarReflectionSettings.disabled()` 是唯一 no-op 值；关闭时零 Pass、shader、FBO、附件或 draw。 |
| 真实生产消费者 | Pass 的消费者合同是 `PlanarReflectionPass.SceneRecorder`：调用方在 Pass 已绑定/清理好的反射目标内，用镜像视图与斜投影绘制真实场景。当前真实消费者是 GL 测试中的场景 recorder；生产 `SceneRenderer` 适配器尚未接线，因此尚不能宣称 RenderPipeline 生产帧路径已消费本 Pass。下游水面/SSR 读取 `colorTexture()`/`depthTexture()` 的接线同样待 Integrator。 |
| 输入 | 主相机 `Camera`（`ExternalCamera` 支持其显式 view/projection）、场景/输出尺寸、调用方提供的 `SceneRecorder`、可选恢复目标 `Framebuffer`（null = 默认 framebuffer）。Pass 自己拥有 settings 中固定的平面、分辨率和节流参数；不读取共享 depth/color、不采样主场景历史。 |
| 输出 | 独立单采样 `RGBA16F` 颜色纹理（线性 HDR，alpha 由场景 recorder 决定）与 `DEPTH_COMPONENT24` 深度纹理/FBO。目标尺寸 = `round(sceneExtent * resolutionScale)`，最长边再按 `maxResolution` 等比缩小，且每轴至少 1 像素。目标不写共享 `SceneColor`/`sceneDepth`，不产生 mip，不做 resolve。 |
| 坐标系与空间 | 世界空间右手系，1 单位按米解释；平面方程 `normal · p + w = 0`，法线指向保留/场景侧；view/projection 为 OpenGL 列主序 NDC（近平面 `-1`、远平面 `+1`）。镜像相机位置、朝向、view、projection、viewProjection、逆矩阵和裁剪平面同时暴露给 recorder。 |
| 镜像相机与绕序 | 世界反射矩阵 `R = I - 2nnᵀ/(n·n) - 2d n/(n·n)`；`mirroredView = V * R`，位置为平面镜像点，基向量取自 view 矩阵行（right/up/-forward）。不能用反射后的 up 向量重新 `lookAt`：反射翻转 handedness，lookAt 会再次翻转水平轴。镜像 view 的行列式为负，Pass 在自己的目标内设置 `glFrontFace(GL_CW)`，结束后恢复 `CCW`。 |
| 斜近平面裁剪 | Lengyel 形式：把 view 空间裁剪平面变换到裁剪空间，取远平面反向角点 `q`，计算缩放平面 `c = plane * 2/(plane·q)`，只替换投影第三行（`m02,m12,m22,m32`）。平面映射到近平面 `z_ndc = -1`，位于镜像相机与平面之间的几何被裁掉。`nearPlaneOffset` 沿法线把裁剪平面向镜像相机移动（正数裁剪更多），避免贴水面几何泄漏；镜像本身仍使用未偏移平面。 |
| 更新频率 | `updateIntervalFrames = N` 表示每 N 次 `record` 最多成功更新一次：首次更新后计数为 `N-1`，随后 N-1 次调用返回 `false` 且不绑定/不清空目标；下一次调用再更新。`N=1` 为每帧更新；`requestUpdate()` 强制下一次更新；目标 resize 也强制下一次更新。被跳过调用保持上一份成功内容。 |
| 分辨率控制 | `resolutionScale ∈ (0,1]` 控制线性缩放；`maxResolution` 是目标最长边上限（`[1,16384]`），按宽高比等比缩小，避免非等比拉伸。尺寸变化时先完整分配候选 FBO，再发布新目标并退役旧目标。 |
| 独立历史 | 反射颜色/深度是 Pass 私有的独立附件，不复用主场景颜色、深度或 TAA/GTAO 历史。首版**不做**时域累积、velocity、reactive 或 jitter；跳过节流/相机在平面背面时保留上一份成功反射，消费者必须通过 `updateCount()`/`record` 返回值判断是否已有有效内容。 |
| 递归防护 | `record` 在调用 `SceneRecorder` 期间置内部 `recording` 标志；同一 Pass 在回调内再次 `record`、`resize` 或 `close` 抛 `IllegalStateException`。调用方合同还要求：recorder 不得采样本 Pass 正在写入的 `colorTexture()`（反馈），不得在其中调用其他反射 Pass。首版明确禁止反射内再反射。 |
| Pass 顺序（建议接线） | `SceneSurfacePass → GeometryPass → PlanarReflectionPass → WaterSurfacePass → Transparent/Volumetric → PostProcess`。反射是独立子视图，必须在消费它的水面/镜面合成之前完成，且不能进入自身；首版建议只绘制不透明场景，不重跑 shadow/GTAO/IBL 生产。 |
| GPU owner | 与现有 Render3D 相同：所有 `record`、FBO 创建/删除、resize 必须在同一 GPU owner 线程/current context 内执行。Pass 不创建线程、不做异步 PBO、不逐帧 `glFinish`/GPU 读回。GL 测试的 `glReadPixels` 只在测试内使用，生产代码没有读回。 |
| 准备/提交/退役/失败 | 构造：先校验 settings 再分配 FBO，分配失败由 `Framebuffer` 自行清理候选、构造函数抛出不发布半成品。resize：先创建候选 FBO，成功后才替换字段并关闭旧 FBO；候选分配失败保留旧目标。发布后旧 FBO 关闭失败时新目标保持活动并向上报告（不伪报回滚）。关闭：幂等；关闭中若正在 recording 则拒绝。相机无效/在平面背面：`prepareFrame` 在任何绑定前返回 null，目标不动。recorder 抛异常：`finally` 仍记录恢复目标/viewport/状态，异常向上传播，该帧不增加 `updateCount`。 |
| 所有权与借用 | Pass 拥有自己的 FBO、颜色/深度纹理；`restoreTarget` 是借用，不关闭。场景 recorder 的 shader/mesh/纹理由调用方拥有；Pass 不关闭。关闭后 `colorTexture()`/`depthTexture()`/`width()`/`height()` 返回 0，`id()` 返回 0。 |
| 额外场景绘制成本（单列） | 每次实际更新都会让调用方**再绘制一遍被选中的场景集合**（首版建议不透明集合），额外 draw/顶点/填充成本与场景规模和 `resolutionScale²` 成正比；节流 N 帧只降低频率，不降低单次成本。不重跑 shadow map、GTAO、IBL 预滤波或体积生产；这些被借用/复用。无 GPU profiling，成本状态 `NOT_EVALUATED`；关闭或跳过更新时无场景绘制。 |
| 质量档（有界建议） | Low：`resolutionScale=0.35, maxResolution=512, updateIntervalFrames=4, nearPlaneOffset=0.05`；Medium：`0.5, 1024, 2, 0.02`；High：`1.0, 2048, 1, 0.005`。默认仍是 `disabled()`，不把 High 作为默认。档位未做性能测量。 |
| 独立 oracle | JVM：手算 double 平面反射/Householder 矩阵、显式 `V*R` 行主序乘法、手写透视矩阵和斜裁剪几何不等式；测试不调用生产 helper 计算唯一期望。GL：用**未镜像主相机**投影镜像世界点得到期望屏幕位置；用“剔除关闭两片都可见 / 剔除开启仅正面可见”的 A-B 对照验证绕序；用“平面下方几何点位于屏幕内但绿色像素必须为 0”验证裁剪，而不是只看 Pass 内部矩阵。 |
| Shader 与资产 | 纯 Pass：生产路径没有新增 shader、纹理或模型，场景绘制由调用方提供。GL 测试内联最小 vertex/fragment shader，不作为 production/demo 资产，不写入 `docs/licenses/assets.tsv`。因此没有新 SHA-256 需要登记。 |
| 验证范围 | JVM：设置边界/禁用 no-op/防御性拷贝/平面方程与偏移/分辨率缩放与上限；GL-free 数学的镜像点/方向/矩阵、`V*R`、平面变换、Lengyel 投影和镜像+斜裁剪集成。GL：`PlanarReflectionPassGlTest` 6 个 case，覆盖镜像位置、斜裁剪、绕序 A-B、节流、resize、禁用/关闭生命周期。 |

## 与水面、SSR 的关系

- **水面（#14）**：当前 `WaterSurfacePass` 的反射来自预滤波 IBL/固定回退色，不消费本 Pass。接入 #30 后，建议由 `WaterSurfacePass` 的 Fresnel 反射项改为采样 `PlanarReflectionPass.colorTexture()`（同帧、屏幕空间对齐），并保留 IBL 作为无更新/离屏回退。本包未修改水面，避免抢占 #14 的 owner；两者的 scene-colour producer/顺序需在集成期明确，不能让两个 Pass 同时成为最终颜色生产者。
- **SSR（#20）**：SSR 是屏幕空间有界射线，能反射屏幕外不可见内容的部分退化；平面反射是完整几何再投影，但只有一个平面且成本高。首版不自动混合两者，也不共享历史。建议水面在“平面反射可用且相机在保留侧”时优先平面反射，否则回退 SSR/IBL；具体选择与权重留给 #11/#20 的集成合同。
- **#34 时域**：本 Pass 没有独立时域历史，不消费 jitter/velocity，因此不能被 #34 当作带历史的信号。未来如需时域反射，需要单独的信号/历史设计。

## 接线点（Integrator 必读）

1. **配置入口**：在 `RenderPipeline`/`RenderFeatureSettings`（这些文件本包禁止修改）增加 `PlanarReflectionSettings` 字段，默认 `PlanarReflectionSettings.disabled()`；build 前配置、帧边界 apply；启用前校验依赖（建议仅 HDR 管线，且与需要同一 scene-colour producer 的效果协调）。
2. **Pass owner**：在 `PipelineGeneration` 增加 `PlanarReflectionPass` 字段与 `assemblePlanarReflection(...)`：`settings.active()` 时创建；尺寸取 topology 宽高；兼容候选代可借用，不兼容则新建；`close()` 负责退役。关闭设置时不创建任何附件。
3. **Pass 顺序/目标恢复**：在 graph 中增加一个在 `GeometryPass` 之后的 Pass；executor 内调用 `pass.record(cmd, frameCamera(), width, height, res.currentTarget(), recorder)`。`res.currentTarget()` 用于恢复 graph 当前目标；若该 graph pass 没有目标，需要改用默认 framebuffer，或改为有目标/外部目标的接线，不能假设 graph 会自动重新绑定。反射 Pass 自身拥有 FBO，不需要 graph 再创建同尺寸颜色附件。
4. **SceneRecorder 适配器**：用 `Frame.view/projection/viewProjection/position` 构造一个 `ExternalCamera`（或等价 host），让现有 `SceneRenderer` 以镜像相机绘制；**不要**在 TAA 模式下再叠加 jitter（斜投影不能承受额外 jitter），并明确该子视图只输出颜色/深度，不重跑 shadow/GTAO/IBL 生产。`SceneRenderer.Host` 需要能返回镜像 camera/frame，或新增最小 adapter。
5. **下游采样**：水面/镜面 Pass 通过 `colorTexture()` 采样；采样坐标需按主相机屏幕 UV（与主相机同投影的 x/y），不要用反射目标尺寸做世界重建。首帧/跳过更新时用 `updateCount()>0` 或 `record` 返回值决定是否已有有效反射。
6. **公共 API 文档**：`docs/architecture/public-api/render3d.allowlist` 已登记 3 个新类型；`docs/architecture/public-api/README.md` 的叙述条目因文件 owner 禁止修改，需 Integrator 补记。focused 验证列表（`gradle/focused-verification.gradle`）也未修改；新 GL 类需要加入 GPU 串行队列。

## 明确限制与未验证项

1. **单平面**：首版 `MAXIMUM_PLANES = 1`；没有多平面、混合权重、每平面独立历史或动态平面移动。settings 是不可变值，运行期移动平面会重建 Pass/候选代。
2. **非递归**：反射内再反射被 Pass 的 `recording` 标志拒绝；recorder 合同同时禁止采样自身颜色附件。没有“反射中的水面/SSR”合成。
3. **额外场景绘制成本**：每次更新重绘一遍调用方选择的场景集合；成本与场景规模、分辨率和更新间隔相关，当前**没有 GPU 测量**，不能给出毫秒/显存预算结论。阴影、GTAO、IBL 若在 recorder 内被重新生产，成本会额外增加且不在本 Pass 控制内。
4. **透明/材质范围**：首版只提供颜色/深度子视图，不定义透明排序、alpha 混合、MSAA、OIT 或材质筛选；recorder 画什么由调用方决定。没有透明物体与水面交错的正确性承诺。
5. **斜投影与深度语义**：斜近平面会改变深度分布，原来用 near/far 反投影深度的 shader 在该子视图中不再成立；首版不提供恢复/重建合同。Pass 输出深度纹理但未承诺其与主场景深度的可比较性。
6. **无时域**：没有历史累积、velocity、reactive、jitter 或 TAA 集成；节流保留的是上一份成功颜色，不是可解释的时域滤波结果。切镜/相机突变若命中节流，可能短暂显示旧反射。
7. **相机在平面背面**：跳过更新并保留旧内容，消费者必须自行 gate；首次分配后若从未成功更新，纹理内容是未定义的，不应被采样。
8. **resize 失败注入**：代码路径保留旧目标，但没有测试注入了真实的 GL 分配失败；该分支 `NOT_EVALUATED`。发布后旧 FBO 关闭失败同样没有 GL 注入证据。
9. **GL 未执行**：`PlanarReflectionPassGlTest` 的 6 个 case 尚未在桌面 OpenGL 4.6 上运行；本文件不把 JVM 通过当作 GL 通过，GL 状态 `NOT_EVALUATED`。GPU 由 Orchestrator 串行执行。
10. **未测组合**：与水面/SSR/透明/TAA/MSAA/体积雾的实际组合、其他 GPU/驱动、显存峰值和性能均未验证。
11. **公共 API 叙述**：allowlist 已同步，`README.md` 叙述未同步（禁止修改）；这是集成期文档缺口，不是 API 缺口。

## Shader 说明

本 Pass 是纯 Java 资源/状态 Pass，不拥有 shader。场景 recorder 负责自己的 shader、顶点格式、材质和 draw 顺序；Pass 只提供：

- 已绑定的反射 FBO 与 viewport；
- 清空后的颜色/深度；
- `glFrontFace(GL_CW)` 与恢复；
- `Frame` 的镜像 view/projection/viewProjection、位置、基向量、世界/view 裁剪平面和逆矩阵。

因此不需要新增 `docs/licenses/assets.tsv` 条目，也没有新的生产 shader SHA-256。GL 测试中的内联 shader 仅用于测试夹具。
