## 技术卡

| 字段 | 内容 |
|---|---|
| 技术 ID／用户场景 | #30 Planar Reflections；为水面、镜面地板等需要屏幕空间对齐镜像视图的真实表面提供限定的平面反射颜色与深度。首版默认关闭，最多 1 个平面。 |
| 当前基础／差距 | 已有 `Camera`/`ExternalCamera`、`CameraProjection`、共享 `CommandBuffer`、`Framebuffer`/`FramebufferDescriptor`、`FrontFace` 与 `PipelineGeneration` 的候选代/借用资源协议；`WaterSurfacePass` 和 `SsrPass` 展示了 Pass 与资源生命周期风格。缺少独立的镜像相机/斜裁剪数学、反射 FBO、更新节流和递归防护。 |
| 首版范围 | 1 个世界空间平面（点 + 单位法线；`planeY(level)` 为水平面快捷方式）；镜像视图由 `V * R` 构造；仅支持标准 OpenGL 透视投影的 Lengyel 斜近平面裁剪；正面绕序翻转为 `CW`；独立 RGBA16F 颜色 + `DEPTH_COMPONENT24` 深度 FBO；分辨率缩放/上限、更新间隔、近平面偏移；显式递归防护。**排除**正交/自定义投影相机、多平面混合、反射内再反射、屏幕空间射线、时域累积、MSAA、透明排序、深度重建/近远平面语义、动态移动平面和完整水下渲染。 |
| 不支持输入／拒绝 | `enabled=false` 时构造函数拒绝创建 Pass；`planeNormal` 为零/非有限、resolutionScale 不在 `(0,1]`、maxResolution 不在 `[1,16384]`、updateIntervalFrames 不在 `[1,1000]`、nearPlaneOffset 负数/非有限、平面点超出 ±1e6 米均在设置构造期拒绝。平面在运行期不可移动；移动平面必须替换 settings/Pass（候选代语义）。相机位于平面保留侧或平面上（符号距离 ≤ 1e-4 米）时跳过更新并保留上一次成功内容。**正交或非标准 OpenGL 透视投影在 `obliqueProjection` 前置校验中抛 `IllegalArgumentException`，在分配/清空任何反射目标之前拒绝。** |
| 模块与控制 | 新职责包 `subsystems.render3d.planar`：advanced `PlanarReflectionSettings`、advanced `PlanarReflectionMath`（GL-free）、internal `PlanarReflectionPass`（`GlResource`）。`RenderPipeline`/`RenderFeaturesControl`/`PipelineFeaturePolicy` **本包未接线**（文件 owner 限制），由 Integrator 按下方接线点完成。`PlanarReflectionSettings.disabled()` 是唯一 no-op 值；关闭时零 Pass、shader、FBO、附件或 draw。 |
| 真实生产消费者 | Pass 的消费者合同是 `PlanarReflectionPass.SceneRecorder`：调用方在 Pass 已绑定/清理好的反射目标内，用镜像视图与斜投影绘制真实场景。当前真实消费者是 GL 测试中的场景 recorder；生产 `SceneRenderer` 适配器尚未接线，因此尚不能宣称 RenderPipeline 生产帧路径已消费本 Pass。下游水面/SSR 读取 `colorTexture()`/`depthTexture()` 的接线同样待 Integrator。 |
| 输入 | 主相机 `Camera`（`ExternalCamera` 支持其显式 view/projection）、场景/输出尺寸、调用方提供的 `SceneRecorder`、可选恢复目标 `Framebuffer`（null = 默认 framebuffer）。Pass 自己拥有 settings 中固定的平面、分辨率和节流参数；不读取共享 depth/color、不采样主场景历史。 |
| 输出 | 独立单采样 `RGBA16F` 颜色纹理（线性 HDR，alpha 由场景 recorder 决定）与 `DEPTH_COMPONENT24` 深度纹理/FBO。目标尺寸 = `round(sceneExtent * resolutionScale)`，最长边再按 `maxResolution` 等比缩小，且每轴至少 1 像素。目标不写共享 `SceneColor`/`sceneDepth`，不产生 mip，不做 resolve。 |
| 坐标系与空间 | 世界空间右手系，1 单位按米解释；平面方程 `normal · p + w = 0`，法线指向保留/场景侧；view/projection 为 OpenGL 列主序 NDC（近平面 `-1`、远平面 `+1`）。镜像相机位置、朝向、view、projection、viewProjection、逆矩阵和裁剪平面同时暴露给 recorder。 |
| 镜像相机与绕序 | 世界反射矩阵 `R = I - 2nnᵀ/(n·n) - 2d n/(n·n)`；`mirroredView = V * R`，位置为平面镜像点，基向量取自 view 矩阵行（right/up/-forward）。不能用反射后的 up 向量重新 `lookAt`：反射翻转 handedness，lookAt 会再次翻转水平轴。镜像 view 的行列式为负，Pass 在自己的目标内设置 `glFrontFace(GL_CW)`，结束后恢复 `CCW`。 |
| 斜近平面裁剪 | Lengyel 形式：把 view 空间裁剪平面变换到裁剪空间，取远平面反向角点 `q`，计算缩放平面 `c = plane * 2/(plane·q)`，只替换投影第三行（`m02,m12,m22,m32`）。平面映射到近平面 `z_ndc = -1`，位于镜像相机与平面之间的几何被裁掉。`nearPlaneOffset` 沿法线把裁剪平面向镜像相机移动（正数裁剪更多），避免贴水面几何泄漏；镜像本身仍使用未偏移平面。**仅接受标准 OpenGL 透视投影（`m00>0`、`m11>0`、`m32<0`、`m23=-1`、`m33=0`、无 x/y/w 交叉项）；正交、reversed-Z/zZeroToOne、轴向翻转在修改矩阵前拒绝，不再静默产生错误 NDC。** |
| 更新频率 | `updateIntervalFrames = N` 表示每 N 次 `record` 最多成功更新一次：首次更新后计数为 `N-1`，随后 N-1 次调用返回 `false` 且不绑定/不清空目标；下一次调用再更新。`N=1` 为每帧更新；`requestUpdate()` 强制下一次更新；目标尺寸变化会强制下一次**尝试**更新（但相机/投影校验失败时仍不会分配或发布）。被跳过调用保持上一份成功内容。 |
| 分辨率控制 | `resolutionScale ∈ (0,1]` 控制线性缩放；`maxResolution` 是目标最长边上限（`[1,16384]`），按宽高比等比缩小，避免非等比拉伸。自动尺寸变化采用事务：先校验相机/投影，再分配候选并绘制，recorder 成功后才发布候选、关闭旧 FBO；任何前置失败都保留旧 FBO/像素/valid 状态。显式 `resize` 先分配候选再发布，但发布的是无效存储（valid=false），等待下一次成功 record。 |
| 独立历史 | 反射颜色/深度是 Pass 私有的独立附件，不复用主场景颜色、深度或 TAA/GTAO 历史。首版**不做**时域累积、velocity、reactive 或 jitter；跳过节流/相机在平面背面时保留上一份成功反射。消费者必须用 `hasValidContent()`（或 `updateCount()>0`，其在新目标发布时重置为 0）判断是否已有有效内容；首次分配/显式 resize 后、成功录制前纹理不可采样。valid 表示命令已成功录制到当前目标，调用方仍须提交该 command buffer。 |
| 递归防护 | `record` 在调用 `SceneRecorder` 期间置内部 `recording` 标志；同一 Pass 在回调内再次 `record`、`resize` 或 `close` 抛 `IllegalStateException`。调用方合同还要求：recorder 不得采样本 Pass 正在写入的 `colorTexture()`（反馈），不得在其中调用其他反射 Pass。首版明确禁止反射内再反射。 |
| Pass 顺序（建议接线） | `SceneSurfacePass → GeometryPass → PlanarReflectionPass → WaterSurfacePass → Transparent/Volumetric → PostProcess`。反射是独立子视图，必须在消费它的水面/镜面合成之前完成，且不能进入自身；首版建议只绘制不透明场景，不重跑 shadow/GTAO/IBL 生产。 |
| GPU owner | 与现有 Render3D 相同：所有 `record`、FBO 创建/删除、resize 必须在同一 GPU owner 线程/current context 内执行。Pass 不创建线程、不做异步 PBO、不逐帧 `glFinish`/GPU 读回。GL 测试的 `glReadPixels` 只在测试内使用，生产代码没有读回。 |
| 准备/提交/退役/失败 | 构造：先校验 settings 再分配 FBO，分配失败由 `Framebuffer` 自行清理候选、构造函数抛出不发布半成品。自动 resize：先校验相机侧与投影，再分配候选并录制；recorder 成功后才把候选发布为当前 FBO、关闭旧 FBO；候选分配失败、相机在背面或投影被拒绝时旧 FBO/像素/有效标志全部保持。显式 `resize`：候选分配成功后发布，但 `contentValid=false`、`updateCount=0`，等待下一次成功录制；候选分配失败保留旧目标。发布后旧 FBO 关闭失败时新目标保持活动但 `contentValid=false`、`updateCount=0`，并向上报告（不伪报回滚）。关闭：幂等；关闭中若正在 recording 则拒绝。recorder 抛异常时：当前目标路径保持旧 GPU 内容（命令不应提交），自动 resize 候选被关闭、旧目标仍活动；异常向上传播，该次不增加 `updateCount`/不发布候选。 |
| 所有权与借用 | Pass 拥有自己的 FBO、颜色/深度纹理；`restoreTarget` 是借用，不关闭。场景 recorder 的 shader/mesh/纹理由调用方拥有；Pass 不关闭。关闭后 `colorTexture()`/`depthTexture()`/`width()`/`height()` 返回 0，`id()` 返回 0，`hasValidContent()` 返回 false。 |
| Host 状态合同 | 恢复的是文档化默认值而非完整 host 快照：caller framebuffer、viewport、front face `CCW`、depth test/write on、cull/blend/sRGB/scissor off、clear colour `(0,0,0,1)`。Pass **不修改** `depthFunc`、colour write mask、cull-face mode；调用方须提供 Render3D 默认 `GL_LESS`/全通道写入/`GL_BACK`（当 culling 开启时）。非默认 depthFunc 若拒绝清空后的深度，会合法地导致反射为空。GL 新增 `preservesDepthFunctionAndCullModeWhileRestoringDrawDefaults` 覆盖 depthFunc/cull mode 不被修改且 cull 被关闭。 |
| 额外场景绘制成本（单列） | 每次实际更新都会让调用方**再绘制一遍被选中的场景集合**（首版建议不透明集合），额外 draw/顶点/填充成本与场景规模和 `resolutionScale²` 成正比；节流 N 帧只降低频率，不降低单次成本。不重跑 shadow map、GTAO、IBL 预滤波或体积生产；这些被借用/复用。无 GPU profiling，成本状态 `NOT_EVALUATED`；关闭或跳过更新时无场景绘制。 |
| 质量档（有界建议） | Low：`resolutionScale=0.35, maxResolution=512, updateIntervalFrames=4, nearPlaneOffset=0.05`；Medium：`0.5, 1024, 2, 0.02`；High：`1.0, 2048, 1, 0.005`。默认仍是 `disabled()`，不把 High 作为默认。档位未做性能测量。 |
| 独立 oracle | JVM：手算 double 平面反射/Householder 矩阵、显式 `V*R` 行主序乘法、手写透视矩阵和斜裁剪几何不等式；测试不调用生产 helper 计算唯一期望。GL：用**未镜像主相机**投影镜像世界点得到期望屏幕位置；用“剔除关闭两片都可见 / 剔除开启仅正面可见”的 A-B 对照验证绕序；用“平面下方几何点位于屏幕内但绿色像素必须为 0”验证裁剪，而不是只看 Pass 内部矩阵。 |
| Shader 与资产 | 纯 Pass：生产路径没有新增 shader、纹理或模型，场景绘制由调用方提供。GL 测试内联最小 vertex/fragment shader，不作为 production/demo 资产，不写入 `docs/licenses/assets.tsv`。因此没有新 SHA-256 需要登记。 |
| 验证范围 | JVM：设置边界/禁用 no-op/防御性拷贝/平面方程与偏移/分辨率缩放与上限；GL-free 数学的镜像点/方向/矩阵、`V*R`、平面变换、Lengyel 投影、镜像+斜裁剪集成，以及正交/reversed-Z/负 m00 拒绝（destination 保持 identity）。GL：`PlanarReflectionPassGlTest` 10 case 覆盖镜像位置、斜裁剪、绕序 A-B、节流、resize、禁用/关闭生命周期、正交 ExternalCamera 无副作用拒绝、自动 resize 遇相机背面不发布、非 null `restoreTarget`、depthFunc/cull mode 状态合同。 |

## 与水面、SSR 的关系

- **水面（#14）**：`WaterSurfacePass` 的 Fresnel 反射项已改为采样 `PlanarReflectionPass.colorTexture()`（同帧、屏幕空间 UV），并保留 IBL 作为无有效内容/离屏回退（`e5cde50f`）。水面是当前唯一的平面反射消费者；SSR 保持自身屏幕空间射线，不消费该目标，避免双重反射。2026-11-16 修复：平面目标用 stable projection 录制，水面因此改用 `FrameParameters.stableViewProjection()`（`uStableViewProjection`）采样，不再用 jittered `uProjection * uView`，见文末。
- **SSR（#20）**：SSR 是屏幕空间有界射线，能反射屏幕外不可见内容的部分退化；平面反射是完整几何再投影，但只有一个平面且成本高。首版不自动混合两者，也不共享历史。建议水面在“平面反射可用且相机在保留侧”时优先平面反射，否则回退 SSR/IBL；具体选择与权重留给 #11/#20 的集成合同。
- **#34 时域**：本 Pass 没有独立时域历史，不消费 jitter/velocity，因此不能被 #34 当作带历史的信号。未来如需时域反射，需要单独的信号/历史设计。

## 接线点（Integrator 必读）

1. **配置入口**：在 `RenderPipeline`/`RenderFeatureSettings`（这些文件本包禁止修改）增加 `PlanarReflectionSettings` 字段，默认 `PlanarReflectionSettings.disabled()`；build 前配置、帧边界 apply；启用前校验依赖（建议仅 HDR 管线，且与需要同一 scene-colour producer 的效果协调）。
2. **Pass owner**：在 `PipelineGeneration` 增加 `PlanarReflectionPass` 字段与 `assemblePlanarReflection(...)`：`settings.active()` 时创建；尺寸取 topology 宽高；兼容候选代可借用，不兼容则新建；`close()` 负责退役。关闭设置时不创建任何附件。
3. **Pass 顺序/目标恢复**：在 graph 中增加一个在 `GeometryPass` 之后的 Pass；executor 内调用 `pass.record(cmd, frameCamera(), width, height, res.currentTarget(), recorder)`。`res.currentTarget()` 用于恢复 graph 当前目标；若该 graph pass 没有目标，需要改用默认 framebuffer，或改为有目标/外部目标的接线，不能假设 graph 会自动重新绑定。反射 Pass 自身拥有 FBO，不需要 graph 再创建同尺寸颜色附件。
4. **SceneRecorder 适配器**：用 `Frame.view/projection/viewProjection/position` 构造一个 `ExternalCamera`（或等价 host），让现有 `SceneRenderer` 以镜像相机绘制；**不要**在 TAA 模式下再叠加 jitter（斜投影不能承受额外 jitter），并明确该子视图只输出颜色/深度，不重跑 shadow/GTAO/IBL 生产。`SceneRenderer.Host` 需要能返回镜像 camera/frame，或新增最小 adapter。
5. **下游采样**：水面/镜面 Pass 通过 `colorTexture()` 采样；采样坐标需按主相机屏幕 UV（与主相机同投影的 x/y），不要用反射目标尺寸做世界重建。首帧/跳过更新/显式 resize 后用 `hasValidContent()`（或 `updateCount()>0`）gate；只有成功录制的目标才可采样。
6. **公共 API 文档**：`docs/architecture/public-api/render3d.allowlist` 已登记 3 个新类型；`docs/architecture/public-api/README.md` 的叙述条目因文件 owner 禁止修改，需 Integrator 补记。focused 验证列表（`gradle/focused-verification.gradle`）也未修改；新 GL 类需要加入 GPU 串行队列。

  `active()` 时进入拓扑。渲染期间平面移动需要新的 settings 并重建候选代。

## 明确限制与未验证项

1. **单平面**：首版 `MAXIMUM_PLANES = 1`；没有多平面、混合权重、每平面独立历史或动态平面移动。settings 是不可变值，运行期移动平面会重建 Pass/候选代。
2. **非递归**：反射内再反射被 Pass 的 `recording` 标志拒绝；recorder 合同同时禁止采样自身颜色附件。没有“反射中的水面/SSR”合成。
3. **额外场景绘制成本**：每次更新重绘一遍调用方选择的场景集合；成本与场景规模、分辨率和更新间隔相关，当前**没有 GPU 测量**，不能给出毫秒/显存预算结论。阴影、GTAO、IBL 若在 recorder 内被重新生产，成本会额外增加且不在本 Pass 控制内。
4. **透明/材质范围**：首版只提供颜色/深度子视图，不定义透明排序、alpha 混合、MSAA、OIT 或材质筛选；recorder 画什么由调用方决定。没有透明物体与水面交错的正确性承诺。
5. **斜投影与深度语义**：斜近平面会改变深度分布，原来用 near/far 反投影深度的 shader 在该子视图中不再成立；首版不提供恢复/重建合同。Pass 输出深度纹理但未承诺其与主场景深度的可比较性。
6. **无时域**：没有历史累积、velocity、reactive、jitter 或 TAA 集成；节流保留的是上一份成功颜色，不是可解释的时域滤波结果。切镜/相机突变若命中节流，可能短暂显示旧反射。
7. **相机在平面背面**：跳过更新并保留旧内容；自动 resize 也在分配之前返回，因此旧 FBO/像素/valid 状态不动。显式 `resize` 会发布无效存储，消费者必须用 `hasValidContent()` gate；首次分配后若从未成功更新，纹理不可采样。
8. **仅标准透视**：Lengyel 公式只对标准 OpenGL 透视投影成立；正交/自定义 `ExternalCamera` 投影在修改投影前抛 `IllegalArgumentException`，不会被静默接受。首版不提供正交平面反射。
9. **状态恢复是默认值而非快照**：depthFunc、colour write mask、cull-face mode 未被 Pass 修改，也不做逐项回读恢复；调用方必须提供 `GL_LESS`、全通道写入和 `GL_BACK`。若宿主在调用前有非默认这些状态，Pass 结束后仍保留它们，但反射结果可能为空或错误，这是调用方合同违规。
10. **resize/失败注入**：自动 resize 的分配失败会保留旧目标；显式 resize 发布后 valid=false。但没有注入真实 GL 分配失败或旧 FBO 关闭失败；这些分支 `NOT_EVALUATED`。
11. **GL 证据**：集成 HEAD 上 `PlanarReflectionPassGlTest` 10/10 PASS、0 skipped；provenance 为 glSmoke XML 早于 `901b9b2`，但集成 HEAD 的 planar 内容 diff 为空。本轮追加 `m00>0/m11>0/m32<0` 的拒绝路径校验，不改变标准透视的绘制路径；最终 GL 由 Orchestrator 串行重跑，文档不把 sign 后的代码冒充为已执行新 XML。
12. **未测组合**：与 SSR/透明/MSAA/体积雾的实际组合、其他 GPU/驱动、显存峰值和性能均未验证；
    水面消费的 UV 对齐/翻转与 TAA jitter 已由 2026-11-16 的稳定 VP 用例覆盖（见文末），
    MSAA 下水面的真实帧仍未覆盖。
13. **生产 SceneRecorder 适配器**：`ExternalCamera` 需要 near/far；`Frame` 只提供斜投影矩阵/逆矩阵，**不提供可用的 near/far 深度反投影语义**。适配器必须自己决定是否使用原 near/far 或放弃深度重建，该缺口仍未证明。

## Shader 说明

本 Pass 是纯 Java 资源/状态 Pass，不拥有 shader。场景 recorder 负责自己的 shader、顶点格式、材质和 draw 顺序；Pass 只提供：

- 已绑定的反射 FBO 与 viewport；
- 清空后的颜色/深度；
- `glFrontFace(GL_CW)` 与恢复；

## 平面 UV 对齐与 TAA jitter 收口（2026-11-16）

基线为集成 HEAD `f549c545`（分支 `codex/render-high-1`）。此前水面消费只有
“像素变化 + 禁用逐位恢复”证据，没有 UV 对齐/翻转 oracle，也没有证明
“水面使用 jittered VP、平面目标使用非 jitter 相机块”这一组合是否正确。

### 结论与修复

- 平面反射目标由 `PlanarReflectionPass` 用 `CameraProjection.stable(camera, ...)`
  **无 jitter** 录制；水面顶点仍用 `jitteredProjection` 栅格化（当前 TAA 采样）。
  对 jittered 栅格中的像素 `p`，其水面世界点 `W` 在 stable 投影下落在
  `p + jitter`，所以正确的屏幕空间平面地址是 `stableViewProjection * W`，
  而不是 `jitteredProjection * view * W`（后者等于 `p`，偏移一个 jitter）。
- `WaterSurfacePass` 改为上传
  `TemporalFrameState.FrameParameters.stableViewProjection()`，shader uniform 由
  `uViewProjection` 更名为 `uStableViewProjection` 并注明“仅用于 planar lookup 的
  stable 投影”。这是 jitter 补偿，不是对平面目标再加 jitter。
- `uProjection`/`uInverseProjection` 仍是 jittered 矩阵（水面/折射栅格化与深度
  重建继续使用），没有改变水面顶点或深度语义。

### 新增真实 GL 用例（`PlanarReflectionPassGlTest`）

公共 fixture：64/128 px 窗口、world-locked 红色 ramp quad 由
`PlanarReflectionPass` 用 mirror camera 录制；水面平面 `y=0`、近掠射相机
`(0, 0.05, 5)`、yaw -90、pitch -2，探针为已知屏幕像素
`(width/3, height/2 - 4)`；water settings 关闭波浪、吸收、岸线淡出和颜色项，
因此合成可独立还原为 `planarSample * fresnel²`。

1. `waterPlanarLookupUsesTheStableScreenSpaceUv`：CPU 用未 jitter 的
   `stableViewProjection` 投影水面世界点，读取 planar 目标在该 stable UV 的 texel；
   水面输出逐通道匹配 `texel * fresnel²`（容差 0.15）。同时断言 `1-u` 翻转
   texel 与期望 texel 的 RGB 距离 > 0.5，且翻转预测与 GPU 输出距离 > 0.15，
   即翻转 UV 必须失败。
2. `waterPlanarLookupCompensatesTaaJitterInsteadOfUsingTheJitteredAddress`：
   `jittered = T(-2 * 0.75 / width) * stable`（测试放大到 0.75 px，生产为
   ±0.25 px），`FrameParameters` 同时携带 stable/jittered 矩阵；CPU 用
   `inverse(jittered)` 求像素对应的水面世界点 `W`。断言 stable 与 jittered
   地址落在不同 texel（RGB 距离 > 0.3），GPU 输出匹配 stable texel 的
   `texel * fresnel²`（容差 0.15），而 jittered 地址预测与 GPU 输出距离 > 0.15。
   这直接证明 current mapping 在修复前是错的，并且修复方向是 stable VP。
