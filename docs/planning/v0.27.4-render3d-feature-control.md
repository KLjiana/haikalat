## 1. 目标与范围

0.27.0–0.27.3 已建立模块 owner、共享表面需求、代次候选、帧边界替换及失败回滚机制。
0.27.4 将这些局部机制接到统一配置合同上，让应用代码、调试工具和未来 UI 都能通过
同一个入口请求一组相互一致的功能状态。

```text
RenderFeaturesControl
├── enabled                         Render3D 输出总暂停／恢复
├── lighting                        direct lighting、IBL
├── shadow                          directional、point、spot
├── ao                              GTAO、时域历史
├── volumetric                      体积雾、历史累积
├── environment                     天空显示
├── postprocess                     Bloom、曝光、解析雾、AA、色调映射、调色
├── vfx                             HDR VFX 绘制
└── preview                         RenderGraph 调试预览
```

必须完成：

- 一个不可变的完整配置快照和统一批量提交入口；单次请求可以同时改多个模块。
- 总开关暂停／恢复 Render3D 帧输出，不清空用户的子配置，不重建或释放仍保留的资源。
- 子开关实际影响 Pass、资源准备和生产者调用；关闭的功能不能只改 UI 状态。
- 跨模块依赖在准备候选前统一校验；无效请求保留当前已生效配置并报告原因。
- 候选在渲染 owner 的帧边界一次提交；候选失败时旧代继续可用。
- 对外提供 requested、effective、revision、状态和失败原因，区分请求值与实际运行值。
- 共享表面按所有仍启用消费者的需求并集合并；某一消费者关闭不得误释放其他消费者使用的附件。

不包含：

- 通用插件发现、动态模块注册表或第二套生命周期调度器。
- 预设持久化、配置文件格式、图形化设置面板或通用编辑器。
- 新渲染算法、自动性能调优和本版本之外的后端扩展。
- 把基础 `scene`、`geometry`、`pipeline` 或共享 `surface` 做成可任意关闭的功能模块。
- 在总暂停语义中自动释放资源；显式 `close` 仍负责销毁管线和资源。

## 2. 当前基线与能力映射

统一控制器是新增的控制面，不是已有 API 的改名。现有局部更新入口和配置先继续作为
模块适配基础；M0 需确认当前候选中的真实调用链、所有权以及兼容 API 使用者。

| 功能 | 当前配置／入口 | 0.27.4 控制语义与必要工作 |
|---|---|---|
| 总开关 | 暂无管线级 pause 设置 | 新增 `enabled`。关闭时跳过 Render3D 输出与专属帧执行，保留有效代和子配置；不触碰嵌入宿主借用附件。 |
| 直接光 | `SceneLight`、`FrameLightTable`、`FrameLightBinder` 和 Clustered lighting | 新增渲染贡献开关；通过灯表／绑定与材质消费路径生效，不修改 Scene 中的灯定义。还需定义体积雾作为光照消费者时的语义。 |
| IBL | `PbrEnvironment` 借用对象、强度与旋转参数 | 新增 IBL 贡献开关。关闭只停用采样贡献；借用环境由调用方所有，不能由 Render3D 销毁。天空绘制与 IBL 必须分别控制。 |
| 三类阴影 | `PipelineTopology` 从场景投影灯和容量推导方向光、点光、聚光拓扑 | 新增每类请求开关并纳入拓扑。不得改写 `SceneLight.castShadows`；关闭后停止对应阴影 Pass 和专属资源使用。 |
| GTAO | `GtaoSettings.enabled/temporal`、`applyGtao` | 接入 AO 子设置。关闭 GTAO 后仍由 TAA、雾等消费者请求的 SceneSurface 附件保持分配。 |
| 体积雾 | `VolumetricFogSettings.enabled/history`、`applyVolumetricFog` | 接入体积雾设置；时域字段现名为 `history`。关闭时回收专属雾 owner，其他消费者共享的场景附件保留。 |
| 天空 | `OutdoorEnvironmentSettings.enabled`、`applyOutdoorEnvironment` | 接入天空显示开关；该值不替代 IBL 环境配置或光照贡献开关。 |
| 后处理 | `RenderSettings`、`PostProcessSettings`、`applyVisualSettings` | 聚合 Bloom、自动曝光、解析雾、颜色分级、AA 与色调映射。AA 使用 `AntiAliasingMode`（NONE／MSAA／FXAA／TAA），色调映射使用 `ToneMappingMode`（NONE／ACES）。 |
| HDR VFX | `RenderPipeline.hdrVfx*` recorder 接口 | 新增独立执行门控；recorders 属于调用方，开关不能释放调用方资源。体积雾开启时保留 `hdrVfxWithFog` 或显式 opt-out 合同。 |
| 调试预览 | `GraphPreviewController` 和预览 renderer | 新增预览绘制／资源门控；预览关闭不应改变生产 RenderGraph 的输出和附件所有权。 |

配置模型优先复用已验证的 `RenderSettings`、`PostProcessSettings`、`GtaoSettings`、
`VolumetricFogSettings` 和 `OutdoorEnvironmentSettings`。新的类型只表达现有配置无法
表达的跨模块开关，以及统一提交和状态查询。对 direct lighting、IBL 和 shadow 新增的
有效开关是新增能力，不得在文档或兼容层中伪装成当前已有字段。

## 3. 控制 API 与状态合同

建议新增一个稳定入口 `RenderFeaturesControl`，由 `RenderPipeline` 持有并暴露；配置值以
不可变 `RenderFeatureSettings`（最终命名在 M0 API 审查时确定）表示。控制对象只负责接收
请求、提交完整快照、读取状态，不持有 GL 资源、构造 Pass 或决定资源借用关系。

一次请求包含完整配置快照和递增 revision。渲染 owner 在帧开始时读取最新快照，执行：

1. 纯配置校验与依赖解析，不分配 GPU 资源。
2. 计算有效拓扑及各消费者的共享输入需求。
3. 创建私有候选并让各模块 owner 准备、复用或借用资源。
4. 所有准备步骤成功后，在同一帧边界发布配置和候选代。
5. 发布后更新 effective revision 并退役旧代。发布前失败保留旧配置／代并报告 FAILED；发布后退役失败保留已发布配置／代与 APPLIED，另报退役诊断，不回滚成状态分裂。

若控制入口支持非 GL 线程提交，使用现有 `LatestFrameMailbox<T>` 交接完整不可变快照；
它的 latest-wins 语义表示尚未处理的中间完整快照可以被更新值替代。调用方不能提交
基于过期快照的零散 patch 并假设无丢失合并。GL 构建、Pass 录制、资源释放和代次替换
仍只在现有 GPU owner 线程执行。若本版本确认所有调用者都在 owner 线程，仍保留一个统一
批量入口和帧边界提交合同，不为跨线程能力额外引入队列抽象。

状态至少包含：

| 字段 | 语义 |
|---|---|
| `requested`／`requestedRevision` | 最近一次完整提交的配置及其序号；即使总开关关闭也保留子配置值。 |
| `effective`／`effectiveRevision` | 最后一次成功发布的配置；候选失败不能提前更新。 |
| `status` | `PENDING`、`PREPARING`、`APPLIED` 或 `FAILED`；无效的静态组合在候选分配前以失败状态报告。 |
| `failureReason` | 稳定、可读的校验或准备失败原因；新请求创建新状态，成功后清除旧失败。 |
| `activeFeatures` | 当前真正参与输出的能力和受依赖抑制的原因；总暂停时明确显示 `PAUSED_BY_MASTER`。 |

`enabled=false` 是输出暂停，不把子模块配置改写为 false，也不把“已配置但没有合格
消费者”误报为已运行。恢复后从保留配置继续；TAA、GTAO 和体积雾的历史必须按暂停期间
是否跳帧、相机／场景是否变化及现有失效规则重新验证，不能直接消费过期历史。

现有局部 `apply*` API 在兼容期继续工作，但内部应转成同一候选路径，或明确标记为兼容
包装，避免出现统一入口和局部入口并行维护两套提交语义。稳定公共 API 清单和迁移说明
同步更新；不公开模块私有 owner、Pass builder 或资源句柄。

## 4. 依赖、互斥与有效状态

规则在一处纯策略边界校验，并输出配置值与有效拓扑；非法组合不得静默忽略或被悄悄
改写。拓扑应基于有效消费者而不是“所有开关字段的简单或值”。

| 关系 | 处理规则 |
|---|---|
| TAA／FXAA／MSAA | 由单值 `AntiAliasingMode` 选择其一。MSAA sample count 只在 MSAA 模式有效；雾与 MSAA 的深度 resolve 继续经过 `DepthResolveDescriptor` 合同。 |
| Tone mapping／HDR | 继续使用 `ToneMappingMode` 选择 NONE 或 ACES；Bloom、自动曝光、调色、解析雾、体积雾与 HDR VFX 的现有限制由统一策略校验。 |
| GTAO | 保留现有“至少一个 metallic-roughness PBR 材质”前置条件；AO 关闭不应关闭其他 PBR、TAA 或雾所需资源。 |
| 阴影 | 各类型开关与场景中实际投影灯、容量和消费者共同决定有效阴影拓扑；场景无对应投影灯时报告 `NO_ELIGIBLE_LIGHT`，不分配空图集。 |
| 光照与阴影 | 阴影只有在至少一个消费者会采样时才需要录制／存储；direct lighting 关闭时仍需明确体积光等消费者是否保持灯光贡献，不能由管线猜测。 |
| IBL 与天空 | IBL 负责材质环境反射／漫反射输入；天空开关只控制背景绘制。关闭天空不自动关闭 IBL，关闭 IBL 也不销毁借用的环境。 |
| 雾与 VFX | 当前 `RenderPipeline` 明确拒绝解析雾与体积雾同时启用；统一策略必须保留该互斥并在分配候选前拒绝整份请求。体积雾消费者启用时，自定义 HDR VFX 必须满足现有 fog-aware 或显式 opt-out 合同。 |
| SceneSurface | depth、velocity、reactive、GTAO 和雾输入按活跃消费者需求并集计算；最后一个消费者退出后才释放共享附件。 |
| 总开关 | 只影响帧输出，不改变子功能合法性，不等同于 close，也不丢弃有效配置。嵌入模式暂停不得绑定、清除或释放宿主借用目标。 |

请求值但当前无消费者时，状态可以说明该模块已请求、当前未生效及原因；依赖冲突则拒绝
整份候选，禁止只应用其中“看起来没问题”的字段。请求状态与已生效状态均以 revision
关联，防止 UI 或脚本把较早候选的结果覆盖到新请求上。

## 5. 资源与线程生命周期

- 模块 owner 继续拥有专属 program、target、buffer 和 history。控制器只传递配置及候选
  协作信息，不能越权创建或关闭资源。
- 关闭 Bloom、GTAO、体积雾、阴影或预览时，移除对应专属 Pass 并使对应 owner 停用；按
  现有退休/fence 合同安全释放专属资源。其他 Pass 仍读取的公共附件保持有效。
- 总开关暂停时停止更新 Render3D 帧状态和绘制；保持代次、配置及资源。恢复帧前按现有
  历史失效 API 使必要的累积重置，并处理相机与场景变更。
- 代次切换的候选峰值预算需计入旧代、活动候选和待退役 owner；同一共享附件只计一次。
  预算失败必须发生在不可恢复地改变有效状态之前。
- 整体 close 与 master pause 是两种明确操作。close 完成后状态为关闭，不允许下一帧通过
  隐式恢复重新创建资源。
- embedded 路径遵守 `HostGlState` 与借用附件合同；测试暂停、恢复及候选失败后宿主绑定、
  framebuffer 内容和 GL 状态仍由宿主掌控。
