# v0.18.2 资源目录整理与打包规范

> 状态：已实施（2026-07-26）
>
> 适用版本：`0.18.2`
>
> 目标：统一项目资源目录、Shader 路径和 VFX 素材分包规则，同时保持来源可追溯、资源引用稳定。

## 1. 总体原则

项目资源分为两类，采用不同的组织规则：

1. 项目自有资源按“领域 / 子系统 / 用途”组织，例如 Shader、场景配置和测试 fixture。
2. 第三方美术资源按“类型 / 作者 / 具体资源”组织，例如 VFX 粒子、遮罩、噪声和拖尾纹理。

不强制所有资源都增加作者层级。项目自己编写的 Shader 不需要放入 `haikalat` 作者目录；第三方图片需要保留作者维度，防止来源丢失。

所有正式 classpath 路径必须满足：

- 使用 ASCII；
- 全部小写；
- 分包目录及其内部子目录使用全小写 snake_case，单词使用下划线 `_`；
- Shader 等项目自有正式资源文件名使用全小写 kebab-case，单词使用连字符 `-`；
- VFX 素材包内的图片文件名使用全小写 snake_case，数字尺寸可写成 `1x1`、`4x4`；
- 不含空格、中文和乘号等特殊字符；
- 目录名使用复数：`shaders`、`textures`、`models`、`fonts`；
- 路径描述资源职责，不继承素材包中的拼写错误或临时目录名；
- Java 代码直接引用 `vfx` 下的素材包文件。

## 3. Shader 统一规范

所有运行时 Shader 统一放入：

```text
src/main/resources/shaders/<subsystem>/...
```

现有路径迁移如下：

| 旧路径 | 新路径 |
| --- | --- |
| `/postprocess/*.vert`、`/postprocess/*.frag` | `/shaders/postprocess/*` |
| `/render3d/pbr/*` | `/shaders/render3d/pbr/*` |
| `/render3d/preview/*` | `/shaders/render3d/preview/*` |
| `/render3d/vfx/*` | `/shaders/render3d/vfx/*` |
| `/shadows/*` | `/shaders/shadows/*` |
| `/ui/ui.vert`、`/ui/ui.frag` | `/shaders/ui/ui.vert`、`/shaders/ui/ui.frag` |

示例：

```text
/postprocess/fxaa.frag
-> /shaders/postprocess/fxaa.frag

/render3d/pbr/pbr_forward.vert
-> /shaders/render3d/pbr/pbr-forward.vert

/shadows/directional_depth.vert
-> /shaders/shadows/directional-depth.vert

/ui/ui.vert
-> /shaders/ui/ui.vert
```

Shader 文件名统一使用 kebab-case。迁移时必须同步更新：

- Java 中的资源字符串；
- Shader loader 默认路径；
- Demo 中的资源字符串；
- GL 集成测试；
- 读取源码文件的合同测试；
- `docs/licenses/assets.tsv`；
- 发布资源 allowlist 和 hash。

不保留重复的旧 Shader 副本。迁移提交必须完成全仓搜索，确保旧路径没有残留引用。

## 4. VFX 资源规范

### 4.1 资源路径

VFX 正式资源路径统一为：

```text
/vfx/<type>/<author>/<package>/<resource>.<ext>
```

示例：

```text
/vfx/particles/kenney/particle_pack/fire_01.png
/vfx/particles/kenney/particle_pack/smoke_03.png
/vfx/decals/kenney/particle_pack/scorch_01.png
/vfx/masks/kenney/light_masks/transparent/ring_a_streaks.png
/vfx/noise/luos/free_giveaway/noise_01.png
/vfx/noise/wrizfx/personal_noise/noise_01.png
/vfx/normals/luos/noise_v2/noise_normal_01.png
```

作者标识固定为小写稳定名称：

- `kenney`；
- `luos`；
- `wrizfx`。

素材包名称保留在路径中，Java 和配置直接引用包内文件。

### 4.2 类型判定

| 类型 | 内容 |
| --- | --- |
| `particles` | 火焰、烟雾、火花、闪光、魔法符号等 billboard sprite |
| `trails` | 刀光、轨迹、方向条纹和 Ribbon 纹理 |
| `decals` | scorch、scratch 等表面痕迹 |
| `masks` | 圆形、环形、渐变、light mask 等通用遮罩 |
| `noise` | 灰度噪声、合并通道噪声和扰动数据 |
| `normals` | 法线噪声和其他 normal-map 数据 |
| `utilities` | 棋盘格、UV 图、纯色像素和默认法线等开发辅助图 |

资源按主要运行时用途归类，不为同一文件复制多个类型副本。一个通用 noise 被多个效果复用时仍只保留一份。

### 4.3 原始素材映射

| 当前目录 | 目标 VFX 分类 |
| --- | --- |
| `vfx/paricle` | 按文件用途拆到 `particles/kenney/particle_pack`、`trails/kenney/particle_pack` 和 `decals/kenney/particle_pack` |
| `vfx/dev/Light-Masks` | `masks/kenney/light_masks` |
| `vfx/dev/Noise` | `noise/kenney/development_essentials` |
| `vfx/dev/Gradient` | `masks/kenney/development_essentials` |
| `vfx/dev/Normal map` | `utilities/kenney/development_essentials/normal_map` |
| `vfx/dev/1x1 Pixels` | `utilities/kenney/development_essentials/1x1_pixels` |
| `vfx/dev/4x4 Pixels` | `utilities/kenney/development_essentials/4x4_pixels` |
| `vfx/dev/Checkerboard` | `utilities/kenney/development_essentials/checkerboard` |
| `vfx/dev/UV texture` | `utilities/kenney/development_essentials/uv_texture` |
| `vfx/Luos_FreeGiveAway/Noise_Gradients` | `noise/luos/free_giveaway` |

## 5. 授权与来源记录

### 5.1 Kenney

Kenney Particle Pack、Development Essentials 和 Light Masks 按其随包许可记录为 CC0。VFX 使用素材包级来源记录，不在 `docs/licenses/assets.tsv` 中逐文件重复登记。

### 5.2 Luos

作者说明允许这些文件用于商业或非商业项目，署名非强制；不允许将图片作为素材出售、编辑后出售或单独转送。

项目使用边界：

- 可以作为实际 VFX 效果的一部分进入项目；
- 不提供原始素材包下载入口；
- 不把仓库包装成素材分发包；
- 原图尽量保持不变，颜色、UV、混合和扰动在 Shader 中完成；
- 内部保留作者说明、获取 URL 和获取日期作为审计证据。

### 5.3 WrizFX

作者允许这些个人噪声纹理供使用和学习，并要求不要冒充自己的素材重新分发。

项目使用边界：

- 纹理必须服务于项目中的实际效果；
- 不作为独立素材或完整纹理包再分发；
- 不宣称素材由 Haikalat 项目创作；
- 内部保存 Gumroad 页面说明、URL 和获取日期；
- 对外署名不是当前条款的强制要求，但内部 provenance 不得删除。

### 5.4 许可文件位置

```text
src/main/resources/vfx/licenses/kenney/
src/main/resources/vfx/licenses/luos/
src/main/resources/vfx/licenses/wrizfx/
docs/licenses/vfx-textures.md
docs/licenses/assets.tsv
```

完整页面原文、截图或文本存档放入 `vfx/licenses`，并随正式 JAR 一起保留。

## 7. 打包规则

正式 JAR 允许包含：

- `shaders/**`；
- `ui/fonts/**`；
- `vfx/**` 完整素材目录及许可存档；
- 生成的 build metadata。

正式 JAR 禁止包含：

- VFX 目录之外的临时下载文件和原始素材压缩包；
- Demo 专用资源；
- Test fixture；
- Shader generator 模板。

当前不限制 VFX 的 JAR 压缩体积和完整素材数量。后续如需优化约两百 MiB
的发布包，另行设计压缩、拆包或按需下载方案，不在本次目录合同中处理。

## 8. Manifest 规则

`docs/licenses/assets.tsv` 继续记录普通 main/Demo 发布资源。VFX 完整素材采用
`docs/licenses/vfx-textures.md` 和 `vfx/licenses/**` 的素材包级来源记录，不逐项
生成数百条 manifest 记录。

每个普通第三方资源至少记录：

- 最终路径；
- 资源用途；
- 作者与来源 URL；
- 授权标识或作者授权说明；
- 素材包/页面版本和获取日期；
- SHA-256；
- 是否进行裁剪、缩放、压缩、合图或通道转换；
- 是否允许随项目再分发。

目录变更后必须重新生成 hash。仅移动或重命名不会改变文件 hash，但 manifest 中的最终路径必须更新。

- 所有代码直接引用的 VFX 路径都能映射到真实文件；

- glTF 外部 URI 在迁移后仍可解析；
- Shader 编译错误能显示新资源路径。
