# v0.21 序列化游戏场景与角色内容管线

> 状态：执行中（M0–M3 已完成，M4 核心路径与 M5 embedded 交接已完成，M6/M7 验收中）
> 目标版本：`0.21.0-SNAPSHOT` → `0.21.0`
> 主题：让场景、角色、外部动画库、Animation Graph、UI 和嵌入渲染形成一条可加载、可热重载、可诊断的正式主路径
> 前置版本：`0.20.2` 已验收并标记为 `v0.20.2`；当前从该基线执行 `0.21.0-SNAPSHOT`

## 1. 版本定位

v0.20 已经完成 UI、动画和渲染核心的内部收敛；v0.20.1 又完成了宿主无关的嵌入渲染边界。当前项目的主要短板不再是缺少单项渲染能力，而是这些能力仍然需要 Demo 或业务代码手工装配。

v0.21 的目标是完成一条“内容驱动”的纵向闭环：

```text
场景文件
  → 资源身份与依赖图
  → glTF / 外部动画库 / Animation Graph 解析
  → 后台 CPU 解码与 generation
  → GL 线程分阶段上传
  → 角色实例与动画状态机激活
  → PBR / 阴影 / VFX / UI / embedded target 渲染
  → 运行时诊断、失败保留旧版本、热重载
```

本版本不追求完整编辑器或通用游戏引擎，而是要让工程师可以用一份受约束的场景定义启动一个真实角色场景，并在资源变化时安全替换它。

## 2. 版本身份前置门禁

`0.20.2` 已验收并创建本地 `v0.20.2` tag，本计划不再重新定义其范围，也不把其功能重复计入 v0.21。v0.21 已从该正式基线切出 `0.21.0-SNAPSHOT`。

在切出 v0.21 前必须记录：

- 基线提交哈希；
- 当前资源清单和许可证状态；
- 外部动画库支持的 schema 与明确限制；
- Modern UI 和 `player_wild` 的真实集成入口；
- 最后一次完整 GL 日志的 policy 结果。

## 3. 目标与非目标

### 3.1 本版本目标

1. `haikalat.scene/1` 可以可选描述角色、动画库和 Animation Graph 引用。
2. 场景加载可以解析 glTF、`haikalat.gltf-animation-library/1` 和 `haikalat.animation-clip/1` 之间的依赖。
3. Animation Graph 可以从 JSON sidecar 加载，并绑定到同一 `GltfSceneInstance` 的 skeleton 与 clip 集合。
4. 场景首次加载、失败恢复、手动 reload、directory watcher 和 embedded target 使用同一 generation 合同。
5. 同拓扑 reload 不重新编译完整 RenderGraph；只有拓扑或资源描述变化时才创建 candidate generation。
6. `player_wild` 角色成为正式的 SerializedSceneDemo，而不是只在 GltfDemo 中手工组装。
7. Modern UI 可以读取场景/角色诊断，显示当前状态、clip、transition、marker window 和资源 generation。
8. 形成可交付的资产错误报告，使内容作者不需要阅读 GL 日志才能定位绑定失败。

### 3.2 明确不做

- 不引入 ECS、全局 AssetRegistry、Model runtime 或 Service Locator；
- 不把 `SceneAssetService` 改造成通用网络资产系统；
- 不直接解析 GeckoLib 原始 Molang、声音、粒子和 Minecraft 事件；
- 不实现可视化动画编辑器、曲线编辑器或完整场景编辑器；
- 不新增第二渲染后端；
- 不在本版本同时实现 PBR transmission、BLEND、GPU animation sampling、motion matching；
- 不启动 GPU-driven scene、全量 MDI、Hi-Z occlusion 或大规模 crowd runtime；
- 不让动画 Graph 查询 Scene、Physics 或宿主 SDK。

## 4. 架构边界

### 4.1 继续沿用的所有权关系

```text
CPU 内容线程
  ├─ SceneJsonParser / AnimationGraphParser
  ├─ GltfAssetLoader / AnimationLibraryImporter
  └─ SceneBuildPlan / CharacterBuildPlan
          │ 只产生不可变 CPU 数据和依赖身份
          ▼
SceneAssetService / ResourceGenerationTracker
          │ generation ticket + upload budget
          ▼
GL owner thread
  ├─ GltfGpuAssetCache
  ├─ GltfSceneInstance
  ├─ AnimationController / AnimationGraphRuntime
  ├─ RenderPipeline / RenderGraph
  └─ UiSystem / PresentationTarget
```

约束：

- CPU 解码器不能引用 backend 或直接调用 OpenGL；
- Animation Graph 保持 GL-free，不直接持有 Mesh、Texture、Shader 或 FBO；
- SceneAssetService 只发布 CPU plan 和 generation，不在后台线程创建 GL 资源；
- GL 资源必须由 owner/render thread 创建和销毁；
- candidate 失败时 active scene、active graph 和 active UI snapshot 都保持可用；
- embedded 模式只替换 presentation target 和 external camera，不创建额外窗口、context 或线程；
- UI 继续作为 sibling subsystem，不依赖 render3d 的具体实现。

### 4.2 Facade 与内部实现

保留现有入口：

- `SceneAssetService`；
- `SceneDefinition`；
- `GltfAssetLoader`；
- `GltfSceneInstance`；
- `AnimationGraph` / `AnimationController`；
- `RenderPipeline`；
- `HaikalatRuntime`。

新增实现优先为 package-private：

- `SceneCharacterDefinition`；
- `CharacterBuildPlan`；
- `AnimationGraphDocument`；
- `AnimationGraphParser`；
- `CharacterActivation`；
- `SceneReloadTransaction`；
- `SceneDependencyDiagnostics`；
- `SceneGenerationLease`；
- `EmbeddedScenePresenter`。

除非宿主或内容工具确实需要，不新增 stable public API。必要的加载器入口标记为 advanced，并进入 API allowlist、迁移说明和测试合同。

## 5. 内容格式设计

### 5.1 场景格式保持 `haikalat.scene/1`

不修改既有 `objects`、`models`、`materials`、`textures` 和资源目录语义。新增的 `characters` 为可选字段，旧场景文件必须完全保持兼容。

示例：

```json
{
  "format": "haikalat.scene/1",
  "catalog": "scenes/player/catalog.json",
  "models": {
    "playerModel": "./model/player_wild.gltf",
    "environment": "./environment.glb"
  },
  "objects": [
    {
      "id": "player",
      "model": "playerModel",
      "material": "playerMaterial",
      "transform": { "position": [0, 0, 0] }
    }
  ],
  "characters": [
    {
      "id": "playerCharacter",
      "object": "player",
      "animationLibrary": "./animation-library.json",
      "animationGraph": "./player.animation-graph.json",
      "initialState": "idle",
      "parameters": {
        "grounded": true,
        "speed": 0.0
      }
    }
  ]
}
```

解析规则：

- `characters` 缺失表示普通静态场景，不创建角色运行时；
- `object` 必须引用同一场景中的 object；
- `animationLibrary`、`animationGraph` 和模型依赖必须进入同一 dependency graph；
- 同一个 object 只能绑定一个 active character descriptor；
- `initialState` 必须在 Graph 中存在；
- 参数类型、默认值和 Graph 声明必须一致；
- 所有相对路径先规范化，再执行 archive root、字节数和条目数限制；
- 未知字段、重复 ID、循环引用和多次声明必须在 CPU 阶段失败；
- 旧场景没有 `characters` 时，现有静态渲染行为不能变化。

### 5.2 Animation Graph 使用独立 sidecar

Animation Graph 不直接嵌入场景 JSON，避免 SceneJsonParser 变成动画编辑器格式解析器。sidecar 使用独立 schema：

```json
{
  "format": "haikalat.animation-graph/1",
  "skeleton": "player",
  "parameters": [
    { "name": "grounded", "type": "BOOLEAN", "default": true },
    { "name": "speed", "type": "FLOAT", "default": 0.0 },
    { "name": "attack", "type": "TRIGGER" }
  ],
  "states": [
    {
      "id": "idle",
      "clip": "idle_default",
      "loop": "LOOP"
    },
    {
      "id": "run",
      "clip": "run_default",
      "loop": "LOOP"
    },
    {
      "id": "attack",
      "clip": "attack_light",
      "loop": "ONCE"
    }
  ],
  "entry": "idle",
  "transitions": [
    {
      "from": "idle",
      "to": "run",
      "duration": 0.12,
      "when": { "float": "speed", "greaterThan": 0.1 }
    },
    {
      "from": "idle",
      "to": "attack",
      "duration": 0.08,
      "interrupt": "ANY",
      "when": { "trigger": "attack" }
    }
  ]
}
```

第一版只序列化当前已有运行时语义：

- typed boolean/float/int/trigger 参数；
- clip motion、loop mode、transition duration；
- exit time、destination offset 和 interruption policy；
- 1D blend tree；
- 显式 triangle 2D blend tree；
- Marker/Signal 只引用 clip 中已有事件，不在 Graph 中重新定义时间轴。

第一版不加入表达式脚本。条件使用 typed predicate，避免把宿主逻辑、脚本语言和场景查询引入渲染框架。

### 5.3 资产身份与依赖

所有文件继续使用 `AssetId` / `ResourceSource` / `ResourceCatalog` 表示身份。依赖节点至少包含：

```text
scene
 ├─ model.gltf / model.glb
 │   ├─ buffer / image / material
 │   └─ skeleton / clip
 ├─ animation-library.json
 │   └─ external animation clips
 └─ animation-graph.json
     └─ named clip / skeleton references
```

失效传播必须覆盖：

- 主模型文件变化；
- embedded 或 external buffer/image 变化；
- animation-library manifest 变化；
- 任意外部 clip 变化；
- Animation Graph sidecar 变化；
- Scene 定义、catalog 或引用路径变化。

依赖变化只使受影响的 generation 失效，不得让无关 texture、environment 或 host target 全部重建。

## 6. 运行时激活模型

### 6.1 角色构建阶段

`CharacterBuildPlan` 只保存 CPU 数据：

- object identity；
- glTF scene identity；
- skeleton identity；
- animation library identity；
- graph document；
- initial parameters；
- transform 和 material binding；
- generation ticket。

它不持有 GL handle，也不在 parse 阶段创建 `GltfSceneInstance`。

### 6.2 GL 线程激活顺序

```text
validate SceneBuildPlan
    ↓
resolve CPU glTF + animation clips
    ↓
upload mesh / skin / morph / texture by budget
    ↓
create GltfSceneInstance
    ↓
bind skeleton + named clips
    ↓
compile AnimationGraphRuntime
    ↓
set initial state and parameters
    ↓
attach to SceneFrameBuilder / RenderPipeline
    ↓
publish active SceneVersion
```

任何阶段失败：

1. 关闭本次已经创建的 GPU 资源；
2. 释放本次 graph runtime 和 lease；
3. 保留旧 active scene；
4. 写入结构化 failure report；
5. 通过 UI diagnostics 显示失败资源和阶段；
6. 不让渲染线程进入半激活状态。

### 6.3 运行时播放入口

场景激活后，业务代码只通过角色实例的统一入口操作：

```java
CharacterInstance player = scene.character("playerCharacter");
player.setBoolean("grounded", grounded);
player.setFloat("speed", speed);
player.fireTrigger("attack");
player.update(deltaSeconds);

for (AnimationSignal signal : player.drainEvents()) {
    effectBridge.dispatch(signal);
}
```

直接 `play(...)` 仍保留，用于兼容简单 glTF 资源，但通过 Graph 激活的角色必须明确退出 Graph 模式后才能使用立即播放入口。

### M3：Animation Graph sidecar 与运行时绑定

目标：把现有 Java Builder 能力转换为受约束的资产格式。

工作项：

- 新增 `AnimationGraphParser` 和 `AnimationGraphDocument`；
- parser 输出 immutable document，不直接创建 runtime；
- `AnimationGraphCompiler` 将 document 转为当前 `AnimationGraph` builder 或内部 compiled graph；
- clip name 解析必须绑定到当前 `GltfSceneInstance`；
- 参数表、entry state、transition、condition、loop 和 interruption 全部预验证；
- Graph 编译失败时不影响已激活的旧角色；
- Graph sidecar 变化只重建 Graph runtime，不重新上传 mesh/texture。

暂不支持的内容必须显式列在报告中：

- motion matching；
- 脚本表达式；
- full-body IK；
- physics/scene query；
- runtime 动态新增骨骼或 morph target；
- 跨 topology clip 混合。

当前状态：parser、immutable document、compiler 和 `GltfSceneInstance.attachAnimationGraph` 已完成；真实 `player_wild` Graph sidecar 已在 SerializedSceneDemo 中绑定并运行。Graph attach 现在先构造/初始化 candidate controller，再原子替换旧 controller；初始化或 morph/skeleton 校验失败时旧 pose、参数窗口和 runtime 保持不变。Graph-only generation 的外围发布仍由 M4 reload transaction 负责。

### M4：事务式热重载与同拓扑快速路径

目标：让内容修改可恢复、可预测并且不造成不必要的整管线重建。

变更分类：

| 变更 | 期望动作 |
|---|---|
| Graph 参数默认值 | 只更新 active Graph runtime |
| Graph transition/condition | 编译 candidate Graph，成功后原子替换 |
| animation clip JSON | 重新解码 clip，并替换受影响角色 generation |
| animation-library manifest | 重建依赖集合和受影响 clip |
| material/texture | 只重建受影响资源和材质绑定 |
| object transform | 更新 scene instance，不重建 Graph topology |
| object 数量或 pass topology | 创建 candidate pipeline/graph generation |

当前状态：`SceneAssetService` 已提供 generation ticket、dependency invalidation、candidate
失败保留 active、directory watcher 和 exact-generation GPU lease；`SceneReloadTransaction`
与 `SceneDependencyDiagnostics` 已补上 Graph/scene candidate 的 CPU 事务与 UI 可读错误边界。
新增 `SceneReloadCoordinator` 和 `invalidateAll(...)`，把 watcher 同一批次的重复变更合并为
一次确定性决策；参数更新/Graph 重编译/角色资源重建/管线重建和 presentation target 替换
现在有明确动作边界，Graph-only 变更不会被误报为完整 RenderGraph 重建。
`RenderPipeline.replaceScene(...)` 也已实现 shadow-pass topology signature：同拓扑只替换
scene/lighting binding 并复用现有 RenderGraph，方向光/点光/聚光阴影拓扑改变时才构建候选
graph；focused real-GL gate 同时验证了复用与重建两条路径。剩余的 Graph-only runtime
原子替换、generation lease 和完整 reload/close soak 仍在后续验收中。
同拓扑不重建完整 RenderGraph 的 fast path、Graph-only runtime replacement 和 reload soak
仍在继续实现。
| presentation target resize | 只替换 window/relative target |
| fixed shadow target | 保持原 native resource 不变 |

事务流程：

```text
watcher event
  → debounce/coalesce
  → resolve dependency graph
  → build CPU candidate
  → validate all references
  → upload candidate with budget
  → compile Graph/runtime candidate
  → validate candidate diagnostics
  → atomically activate
  → retire old leases after fence
```

失败规则：

- 新文件语法错误：保留旧 scene；
- 依赖缺失：保留旧 scene，并显示全部缺失项；
- GPU 上传失败：关闭部分资源，保留旧 generation；
- Graph 编译失败：旧角色继续播放，scene 其余部分不受影响；
- watcher 重复事件：同一 generation 只处理一次；
- close/reload 并发：close 进入 retiring，禁止新 activation。

### M5：嵌入宿主与 UI 诊断接入

目标：证明内容驱动路径不依赖 GLFW Demo。

工作项：

1. `HaikalatRuntime.createEmbedded(...)` 加载同一 SerializedSceneDemo 的 scene plan。
2. 宿主只提供 `RenderDevice`、`PresentationTarget` 和 `ExternalCamera`。
3. UI overlay 使用同一 target 的尺寸、scissor 和 sRGB 策略。
4. 宿主触发资源 reload 时不创建新窗口、context 或线程。
5. borrowed FBO、color、depth/stencil 资源继续由宿主所有；Haikalat 只持有 lease。
6. host failure、target replacement 和 zero extent 继续保持 v0.20.1 合同。

不把 Minecraft、NeoForge、Blaze3D 或 `ResourceLocation` 引入主仓库。真实客户端状态同步仍属于 HaikalatHost。

当前状态：`EmbeddedPresentationGlTest` 已新增 serialized-scene 路径：同一个
`SceneAssetService -> SceneBuildPlan -> SceneVersion` 交接值由
`HaikalatRuntime.createEmbedded(...)` 渲染进非零 borrowed FBO，并验证 host color 写入、
资源存活和外部相机/渲染线程契约。窗口 Demo 与 embedded host 因此共用 CPU scene plan；
角色动态 diagnostics overlay 仍在 M6 继续接入。

### M6：诊断、资产报告与新人路径

目标：让内容作者能够定位错误，而不是依赖源码和 GL 日志。

新增结构化 section：

- `scene`：scene ID、version、generation、active/candidate 状态；
- `assets`：模型、clip、graph、texture 的 source、size、generation；
- `characters`：object、skeleton、state、clip、blend weight；
- `dependencies`：依赖图、失效原因、过期 generation；
- `failures`：阶段、字段、资源、fallback、保留旧版本原因；
- `reload`：事件时间、coalesce 次数、candidate 构建时间、激活结果。

新人指南增加一条最短路径：

```text
scene.json → animation-library.json → animation-graph.json
→ SerializedSceneDemo → F2 diagnostics → embedded runtime
```

当前状态：`SerializedSceneDiagnostics` 已提供 scene generation、character descriptor、Graph
state count、参数名和 `SceneAssetSnapshot`；`SceneCharacterRuntimeDiagnostics` 可逐帧捕获
state、time、normalized time、transition target/weight/reason 与 active marker windows。
`SerializedSceneDemo` 已输出两类结构化快照，验证真实 `player_wild` transition 原因与权重；
剩余工作是把相同记录绑定到 Modern UI/F2 panel，而不是再从 GL 日志反推状态。

### M7：性能、稳定性与正式发布

目标：证明内容管线增加了便利性，没有破坏 v0.20.1 的稳定基线。

性能门槛：

- 静态 scene 无资源变化时不重复 parse、shape、paint 或 upload；
- 同拓扑 reload 不触发完整 RenderGraph compile；
- Graph 参数更新不分配新的 clip、mesh 或 texture；
- 100 个角色运行时性能相对 v0.20.1 基线不回退超过 5%；
- 1,000 个角色 benchmark 只记录能力上限，不作为稳定承诺；
- 10,000 quad UI 的约 `255 KiB/frame` 不得回退；
- reload 期间不得出现 ring overwrite、use-after-close 或跨 context 销毁；
- active scene 失败恢复时间和 candidate upload 字节数进入 diagnostics。

当前状态：已加入 `SerializedSceneStabilityTest` 以及
`serializedSceneStabilityIntegration`，覆盖 3,600 帧 CPU 控制路径和 100 次事务式 reload；
这项证据不替代真实 GL soak，GPU 生命周期、借用 target 替换和正式性能门禁仍需在 M5/M7
集成阶段完成。

稳定性门槛：

- 连续 3,600 帧运行；
- 至少 100 次 scene/clip/Graph reload；
- 至少 20 次故意损坏文件、缺失依赖和 GPU upload failure；
- 每次失败后旧 scene 仍可渲染；
- close、重复 close 和 reload/close 竞争均无泄漏；
- embedded target 替换后宿主 GL 状态完全恢复。

## 11. v0.21 之后的候选顺序

完成本版本后，再从以下方向选择下一阶段：

1. glTF `BLEND`、transmission 和材质扩展；
2. MSAA depth resolve，使 fog + MSAA 正式兼容；
3. world-space UI 和场景 UI anchor；
4. UI offscreen subtree replay/cache；
5. VFX distortion、fog、动态光和 GPU indirect compact；
6. 多驱动 GL 验证和远端真实 GL CI；
7. 只有在性能门槛满足时再评估 GPU-driven scene。

在 v0.21 完成前，不启动完整编辑器、第二后端或 ECS 重写。

## 12. 总结

v0.21 的核心不是再增加一个渲染特效，而是把当前已经存在的：

- glTF 与外部动画库；
- Animation Graph 与 Marker；
- PBR、阴影、HDR 和 VFX；
- Modern UI；
- SceneAssetService 与热重载；
- embedded `PresentationTarget`；

收敛成一条真正由内容文件驱动的角色场景路径。

完成后，项目将从“功能齐全且可嵌入的 OpenGL 框架”进一步变成“可以承载一个可维护游戏角色场景的渲染运行时”，同时仍保持单后端、边界清晰、资源可验证和不提前膨胀为完整游戏引擎的定位。
