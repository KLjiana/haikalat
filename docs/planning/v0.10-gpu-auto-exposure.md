# v0.10 全 GPU 自动曝光实施计划

状态：已完成（2026-07-15）。基线版本为 `0.9.0`，当前版本进入 `0.10.0-rc.1`。

完成结果：全 GPU 对数亮度、`RG32F sum/weight` 固定 14 级 reduction、双 1×1 `R16F` history、帧率无关适应和
Tone Mapping 纹理采样均已落地。生产路径没有 CPU readback 或 `CommandBuffer.custom()`；
NONE/MSAA/FXAA/TAA、Bloom 开关、奇数尺寸、resize 拓扑、失败帧 history 和重复关闭均有自动化验证。
1080p/4K 五轮正式数据记录在 `docs/performance/v0.10-auto-exposure-2026-07-15.md`。

## 目标

在现有线性 HDR、Bloom 和 ACES 链路上增加可选的全 GPU 自动曝光。亮度统计、曝光计算和跨帧适应
全部留在 GPU；生产路径禁止逐帧 CPU readback。手动 exposure 继续作为默认模式，关闭自动曝光时不得
改变 v0.9 的 pass 计划、最终像素和资源成本。

本阶段不包含 PBR、GPU culling、直方图测光、局部曝光、眼适应曲线编辑器、第二渲染后端或通用
RenderGraph buffer-resource 抽象。

## 最终链路

```text
Geometry ── MSAA Resolve / TAA ── Linear HDR source
                                      ├── Log luminance ── Reduction to 1x1 ── Temporal adaptation ─┐
                                      └── Bloom ────────────────────────────────────────────────────┤
                                                                                                   ▼
                                                                                         ACES Tone Mapping
                                                                                                   │
                                                                                             FXAA / Present
```

- 自动曝光读取 resolve/TAA 后、Bloom 前的线性 HDR 颜色，避免 Bloom 扩散反向影响测光。
- Bloom 与曝光统计从同一个 HDR producer 分支，Tone Mapping 同时依赖 Bloom 输出和本帧 exposure。
- LDR 路径完全不创建自动曝光 pass 或资源。

## 里程碑 1：公共契约与兼容性

- 新增 `ExposureMode { MANUAL, AUTO }`，默认 `MANUAL`。
- 新增不可变 `AutoExposureSettings`，至少包含：
  - `minExposure`、`maxExposure`；
  - `keyValue`，默认以 18% 中灰为目标；
  - `brightenSpeed`、`darkenSpeed`，分别控制暗场增曝光和亮场降曝光的速度。
- `RenderSettings` 增加 `exposureMode` 和 `autoExposureSettings`；现有 `exposure` 保留为手动值，
  同时作为自动曝光历史的初始值。
- `AUTO` 只允许与 HDR tone mapping 一起使用；所有数值必须有限、为正，且
  `minExposure <= maxExposure`。
- `RenderPipeline` 增加 `execute(RenderDevice, float deltaSeconds)`。现有 `execute(RenderDevice)`
  保留并使用确定性的 `1/60 s`，避免破坏已有调用方；主 Demo 传入 `FrameClock.Tick.deltaSeconds()`。
- pipeline 内部再次限制异常大的 delta，避免窗口挂起或调试暂停后曝光瞬间跳变。

## 里程碑 2：GPU 测光与时间适应

- backend 增加 `RenderFormat.R16F` 与 `RenderFormat.RG32F` 及 framebuffer/texture 格式映射；R16F 用于
  原始对数亮度和 exposure history，RG32F 用于归约总和与权重。
- 新增 `AutoExposurePass`，职责仅包括亮度提取、GPU reduction、1×1 历史和命令录制。
- 亮度采用 Rec.709 权重，并在 GPU 上写入对数亮度：

```text
luminance      = dot(linearRgb, vec3(0.2126, 0.7152, 0.0722))
logLuminance   = log(max(luminance, 1e-4))
averageLum     = exp(average(logLuminance))
targetExposure = clamp(keyValue / max(averageLum, 1e-4), minExposure, maxExposure)
```

- reduction 使用 RenderGraph 管理的 `RG32F` 纹理 pass：R 累计 `logLuminance` 总和，G 累计像素权重。
  第一级把每个 R16F texel 作为 `(value, 1)`，后续级直接累加 RG；adaptation 使用
  `sum / max(weight, 1)`。每一级按整数 begin/end 覆盖全部 texel，奇数尺寸不得遗漏边缘。
- 固定创建 14 个 reduction pass：前 13 级使用 `1/2`～`1/8192` 相对尺寸，最后一级固定 1×1。
  小尺寸重复 1×1 pass 保留，正式支持最大 16384 像素边长，拓扑不再依赖 build 时窗口尺寸。
- reduction 层数和采样布局属于内部实现，不进入公共设置；不得为了自动曝光增加通用场景 ECS、
  AssetRegistry 或公共 GPU reduction 框架。
- 时间适应使用帧率无关的指数形式：

```text
weight   = 1 - exp(-speed * deltaSeconds)
exposure = mix(previousExposure, targetExposure, weight)
```

- 使用两个 `1×1 R16F` 目标保存 exposure history 并逐帧 ping-pong。历史由后处理子系统持有，
  因为它跨 RenderGraph frame 存活；中间 reduction target 继续由 RenderGraph 管理。
- history 只在 `RenderGraph.execute` 成功后交换。命令执行失败时保留上一张有效 history，下一帧覆盖
  同一个 write target，不能把部分写入结果发布为当前曝光。
- Tone Mapping 在 `MANUAL` 模式继续读取 `uExposure`；在 `AUTO` 模式直接采样 1×1 exposure texture。
  禁止 `glReadPixels`、`glGetTexImage`、同步 map 或其他逐帧 CPU 回读。

## 里程碑 3：生命周期、Demo 与可观测性

- 自动曝光关闭时不加载 shader、不创建 history、不增加 pass，手动路径保持逐像素一致。
- resize 时重建窗口相关 reduction target，但保留 1×1 exposure history，防止只因调整窗口尺寸产生闪烁。
- 最小化产生的 0×0 resize 不改变 graph 或 history；恢复到正尺寸后继续收敛。
- build 中途失败时逆序释放已创建的 shader、framebuffer 和 texture；`close()` 保持幂等。
- Main Demo 增加 `--auto-exposure`，默认仍为手动 exposure；标题或基准摘要显示当前模式，但不得
  为显示数值而从 GPU 每帧回读曝光。
- 新增 `runAutoExposureIntegration`：隐藏窗口、关闭 VSync、运行有限帧，并在确定帧切换暗场/亮场。
- `localGlVerification` 纳入该任务；跨机器 CI 仍只执行无桌面安全测试。
- RenderGraph profiling 记录每个 luminance/reduction/adaptation pass 的 GPU 时间，并在正式基准中报告
  自动曝光总成本；不设置跨机器硬性能阈值。
- `Scene.setLight()` 只允许颜色、强度、方向、位置、范围和锥角等不改变拓扑的更新；改变 `LightType`
  或 `castShadows` 会报告 index 与字段并失败，调用方必须重新 build pipeline。

## 测试与验收

### 纯 JVM

- 默认设置仍为 `MANUAL`，旧 pass 名称和顺序不变。
- `AUTO + ToneMappingMode.NONE`、非法上下限、非有限数值和非正速度分别失败。
- 暗场提高 target exposure，亮场降低 target exposure，结果始终位于上下限内。
- 指数适应在不同帧率下对相同总时间得到近似结果，brighten/darken 使用各自速度。
- 架构守卫禁止自动曝光生产包调用 GPU readback API 或 `CommandBuffer.custom()`。

### 真实 GL

- `R16F` target 可写、可采样，并保留大于 1 和小于 1 的有限曝光值；`RG32F` 使用正确双通道浮点元数据。
- 9×1 非均匀亮度完整链末端为 `log(highlight)/9`；1280×1 左右边缘单像素权重一致。
- graph 以 1×1 构建后 resize 到 47×33，末端权重为完整的 1551，而不是只测量 texel `(0,0)`。
- 暗场→亮场时曝光单调下降，亮场→暗场时单调上升，均不越过配置边界。
- history 只在成功帧交换；故意令后续 pass 失败后，下一帧仍从上一张有效 history 继续。
- NONE/MSAA/FXAA/TAA 四条 HDR 路径以及 Bloom enabled/disabled 均产生有限、非空最终像素。
- resize、最小化恢复、重复 build/close 均无 GL error、资源泄漏或错误历史复用。
- 手动模式最终像素与 v0.9 基线逐像素一致；自动模式稳定后不发生可见的逐帧振荡。

### 发布门槛

- `compileJava demoClasses test` 通过，现有 182 个测试不得回退。
- `localGlVerification --rerun-tasks` 完整通过，无 GL error、线程悬挂或同步 readback。
- 提交 1080p 与 4K 的五轮正式基准，分别记录自动曝光关闭/开启时的 CPU、各 pass GPU 和总 GPU
  median；性能用于发现异常，不作为跨机器 CI 硬阈值。
- 更新 capability matrix、testing guide 和 changelog，版本进入 `0.10.0-rc.1` 后再做稳定发布验收。

## 实施顺序

1. 完成设置契约、`R16F`、`RG32F` 和 delta 输入。
2. 完成 log luminance、reduction 和 1×1 history ping-pong。
3. 接入 Tone Mapping、Bloom 分支依赖和异常安全交换。
4. 补齐 GL 测试、确定性 Demo 集成和正式性能报告。
5. v0.10 稳定后再选择最小 PBR 闭环或 GPU culling；默认优先 PBR 资源与材质语义准备。

## 验收结果

- `glSmoke --rerun-tasks`：182 个测试全部通过，无跳过或失败。
- `clean compileJava demoClasses test localGlVerification --rerun-tasks`：23 个任务全部重新执行并通过。
- `runAutoExposureIntegration --rerun-tasks`：确定性明暗切换、Bloom 和 FXAA 链路通过。
- 四种 HDR AA × Bloom enabled/disabled 的真实 GL 最终像素均有限且非空。
- `R16F` 保留大于 1 和小于 1 的曝光值；`RG32F` 显式累计 sum/weight；9×1、1280×1
  边缘权重和 1×1 resize 到 47×33 的全图归约均与预期一致。
- `Scene.setLight()` 同结构更新成功，类型和 `castShadows` 结构变化均以含 index/字段的异常拒绝。
- 失败帧不交换 history；恢复帧继续从上一张有效 history 适应。
- 1080p 自动曝光 GPU median 增量 `0.215 ms`，4K 增量 `0.435 ms`；未设置跨机器硬阈值。
