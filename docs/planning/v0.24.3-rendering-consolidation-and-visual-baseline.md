# v0.24.3 渲染收尾与视觉基线执行指南

编写日期：2026-09-22。基于当前工作树、桌面 `render.md` 修订路线及 v0.24.2 第三次验收。

**版本目标：让已经实现的 Clustered、Outdoor、TAA 和夜间小镇成为可测、可维护、可重复调色的渲染基线。** 本版不新增 Froxel、DOF、空间 PostProcessVolume 或通用 RenderFeature 框架。

本文是实施要求，不表示以下工作已经完成。标为“拟新增”的类型、配置字段与 Gradle 任务需要工程师实际实现；现有入口应复用，不能只在文档中写一个新名字。

## 0. 范围与交付物

### 0.1 必须完成

1. 修复 GPU benchmark 跨轮归档与最后一轮回收；分离正常运行和 CPU 隔离归因。
2. 补同灯数 full-scan、零灯 CPU 基线、小场景增量及候选指纹证据。
3. 从 PostProcessPassBuilder 提取 Outdoor 内部模块，保持现有算法和成功帧/代次事务。
4. 建立全局视觉预设、可靠保存/加载和有限参数热更新。
5. 冻结林间晨雾、黄昏林缘、夜间小镇三个视觉场景，提供固定路径、对照图和质量记录。
6. 将新增验证接入真实 Gradle 汇总和发布证据链。

### 0.2 不进入本版

- 重写 TAA、重建 Scene Buffers、改 Deferred 或扩大 MAX_LIGHTS 常量。
- 通用公开 RenderFeature/FrameResources 插件框架。
- DOF、Contact Shadow、SSR、Reflection/GI Probe、水、空间视觉区域混合。
- 新建资源编辑器、自由材质图、贴图导入系统或更换图形 API。

出现效果需求时先记录到后续清单，不能以“顺手完善”为由扩展本版主线。

### 4.2 样本身份与窗口映射

唯一键至少为 `(runId, generationId, passName, sampleFrameSequence)`。同一 graph 的序号可以从 0 起，重建后不能与旧 graph 合并。

每次实际提交时，保存 `sequence → round/phase/measuredIndex` 映射。不能假定 CPU 循环 frame 永远等于 graph sequence；失败帧、预热前构建和 generation 替换都可能打破假设。

```text
提交一帧 → 登记 frame ticket：generation、sequence、轮次、warmup/measured
收到 GPU sample → 查它自己的 ticket
  无 ticket → 记录为未知样本，正式运行失败
  warmup ticket → 不进入 measured 分布
  measured ticket → 按唯一键插入对应轮次
同键同值 → 去重并记录数量
同键不同值 → 数据冲突，正式运行失败
```

样本在下一轮 warmup 才到达，仍属于上一轮 measured。禁止继续使用当前 CPU 轮次的 windowStart/windowEnd 做回收过滤。

### 4.3 最后一轮回收

1. 完成最后一帧提交后停止测量，不新增补帧来凑样本。
2. 在正确 GL context/thread 中 flush 已提交命令，然后重复调用现有 drainGpuSamples。当前 GpuTimer.drainCompletedSamples 已主动检查可用 query，不必新增第二套“查询轮询器”。
3. 以期望提交 ticket、已回收样本和明确的 skipped/failed 状态判断完成；设置可配置 deadline，默认建议 10 秒，时间记录在报告中。
4. 到期退出，报告 pending/skipped/failed 和逐 pass 覆盖率。收尾不会把缺失样本变成 0，也不能把最近一次值复制到末尾。
5. 清理 query/resource 必须在 finally 中，即使窗口关闭、GL 错误、测量失败或收尾超时。

正式正常路径不逐帧 glFinish。单独隔离任务可以在计时开始前等待，但必须写 `cpuIsolation=true`；隔离和正常结果不合并成一份“passed”。不要用无截止的 glFinish 冒充有界收尾。

coverage 的正式下限沿用 95%，逐必需 pass、逐轮判断；另外报告所有配对 pass 齐全的帧覆盖率。原则上正常收尾应收全已经成功提交的 query；达 95% 不代表可忽略可复现的回收错误。可选/无工作 pass 用执行掩码标为 N/A，不把缺失强行记成零。

### 4.4 GPU 统计定义

- 每个 pass 输出帧序号、轮次、原始 ns、status；JSON 派生毫秒只做显示。
- 同一帧有 Bounds、Assign、Stats、Geometry 等必要样本后才能求该帧组合耗时，再取组合 p50/p95。
- 不相加 pass p95，不把 p50(A)+p50(B) 当 p50(A+B)。
- `gpuPassSum` 明确是已测且互不重叠 pass 的 GPU 耗时之和，不能命名为含空隙/交换的真实 frame latency。
- 若增加整帧 GPU 时间，使用兼容的 timestamp 范围或独立计时运行；不能在现有 elapsed query 外嵌套另一个 GL_TIME_ELAPSED 查询。
- Bounds 未 dispatch 时，不用它的空 pass 时间推断重建成本。稳定相机测试与 grid/camera 更新场景分别报告。

### 4.5 CPU 统计定义

当前 `execute wall - sum(pass record)` 包含准备、上传和提交等剩余工作，不能继续直接标成 device submit。

本版最低要求：

| 指标 | 含义 |
| --- | --- |
| executeWall | RenderPipeline.execute 调用耗时，包含其中的驱动反压 |
| framePreparation | 实际帧冻结/灯表构造等边界内耗时 |
| lightPackAndRecord | 打包及相关命令录制；与其他区段不得重复计入 |
| graphRecord | 图命令录制区段，不能冒充整个准备成本 |
| deviceSubmit | 仅在实际执行/提交边界单独计时，有阻塞也如实记录 |
| presentWall | 仅窗口交换存在时记录；隐藏 FBO 测试标 N/A |

新增计时可作为 benchmark 专用 opt-in，避免正常帧分配大量对象。尚未分离的部分命名为 `unattributedCpu`，不伪造精细归因。隔离 CPU 数据是解释补充，正常 wall/submit 仍需保留。

### 4.6 必测用例

拟新增 `BenchmarkSampleCollectorTest`：上一轮末帧延迟到下一轮、尾帧、乱序、重复、重复冲突、未知序号、失败/跳过、generation 序号重置、N/A pass、配对集合不足、95% 边界、超时不能通过。

真实 GL 用例覆盖完整提交—回收链和 ring 饱和状态；不要只模拟 List 就宣称 GL query 正确。复用现有数值统计测试，不写“expected 调用生产函数”的自证测试。

## 5. M2：补齐同场景性能和光照对照

### 5.1 full-scan 参考的边界

已有 `src/test/resources/shaders/clustered/full-scan-reference.frag` 可作起点，但不得默认它与现行 PBR 永远一致。

- 灯表、BRDF、材质、IBL、衰减、阴影槽、曝光、几何和相机相同，主要差异只能是局部灯遍历方式。
- correctness 对照在线性 HDR、关闭 TAA/Bloom/自动曝光条件下进行；误差门槛沿用规划的 `abs <= 1e-3 + 1e-3*abs(reference)`。阴影边缘另有明确规则，不能放宽整张图掩盖差异。
- 参考 shader 仅属于 test/benchmark 资源，不能作为正式生产模式暴露给用户。给基准配置明确 classpath 或生成资源目录，不把整个测试目录混入正式 jar。
- 性能 reference 应保留灯表上传、真实 Forward 工作和相同阴影；移除对照侧不需要的 cluster bounds/assign/stats。若仍执行这些 pass，不能拿它作为 full-scan 总成本基线。
- 不通过“强制每个 cluster overflow”构造性能参考，这会额外承担分簇成本。
- 在已有独立 CPU/oracle 测试之外增加 shader 共同行为同步检查。共享代码能避免 BRDF 漂移，但共享代码本身不构成算法独立性证明。

基准接入应尽量留在 demo/test 构建与内部 seam，不为测量引入公开的第二套长期生产 renderer。

### 5.2 矩阵与运行顺序

| 场景 | 分辨率 | 模式 | 要求 |
| --- | --- | --- | --- |
| sparse 8 | 1080p | clustered / full-scan | 小场景总 GPU 增量 |
| sparse 128 | 1080p | clustered | Assign 预算、0 overflow |
| sparse 256 | 1080p、4K | clustered / full-scan / 同几何零局部灯 | 灯循环收益、CPU 增量、0 overflow |
| sparse 512、1024 | 1080p | clustered | 容量/覆盖/退化记录，不要求任意场景 60 FPS |
| overlap 256 | 1080p | clustered / correctness reference | 真实触发 fallback、不漏灯、不越界 |
| coverage 256 | 1080p | clustered | 大范围灯混合，报告真实 fallback 占比 |
| town 修订版 | 1080p、4K | 固定配置、静态/街道路径 | 完整画面成本，和旧 town 分开 |

每正式配置至少 3 轮、每轮 120 warmup + 300 measured。A/B 成对交替，按固定 seed 和相机帧号匹配；不能全部先跑 A 再全部跑 B，忽视热状态漂移。零灯与 256 灯保持相同几何/材质/IBL/相机，不能顺便删灯笼模型。

正确性截图和 GPU 读回移出测量窗口。比较运行无截图、无每帧同步诊断、vsync 关闭。GPU 基准串行运行，不与别的 GL demo 并发争抢 GPU。

### 5.3 沿用预算及更完整的成本记录

| 指标 | 门槛/处理 |
| --- | --- |
| sparse 128/1080p Assign GPU p95 | <=0.75 ms |
| sparse 256/4K Assign GPU p95 | <=1.50 ms |
| sparse 256 的 snapshot+pack+record CPU 增量 | 相对同场景零局部灯 p95 <=0.50 ms；逐帧匹配求差后取分位数，原始双方分布另存 |
| sparse 256/1080p、4K 的 Assign+Forward | 同帧相加后取 p50，再与 reference Forward p50 比，<=75% |
| sparse 128/256 overflow | 0 |
| 4K 默认 cluster 自有资源 | <=64 MiB，列清所有实际分配 |
| 8 灯/1080p 总 GPU 增量 | 相对同灯数参考 <=0.30 ms；冻结 p50 口径并另报 p95 |
| GPU 覆盖率 | 每轮必需 pass 与组合配对集合 >=95% |

上述预算继承 0.24.2 规划，不因新版报告不好看而改松。Assign+Forward 历史指标继续报告，但必须额外列出 Upload/Bounds/Assign/Stats/Geometry 完整配对总和及其参考差值，不能通过把工作移进 Stats 宣称整体加速。

小镇整帧 GPU/CPU 和峰值资源在 M0 采集并冻结验收阈值；本指南不捏造未测的 FPS。若某项仍未达标，先定位算法/驱动/环境原因，再记录接受范围或继续优化，不能用硬件豁免覆盖漏灯、越界、资源泄漏或统计错误。

### 5.4 报告 schema

报告目录建议：`build/reports/render3d-v0243/<candidate>/<runId>/`，至少包含：

```text
manifest.json       源码/profile/场景指纹、参数、硬件、时间、正式/隔离标记
raw-samples.jsonl   generation、sequence、round、phase、pass、status、nanos
metrics.json        每轮/汇总分布、配对集合大小、coverage、gate 实测值和门槛
failures.json       无数据/超时/冲突/预算失败及原因，不能只有 passed 布尔值
captures/           非计时阶段的图像和误差图（按需）
```

比较 raw 保留完整 frame identity；按 pass 各写一串浮点数而无序号，不足以证明相同帧配对。报告应失败时仍落盘，异常退出不能留下旧的 passed 文件假装本轮结果。

## 6. M3：Outdoor 行为等价拆分

### 6.1 边界与拟新增模块

| 类型 | 职责 | 不负责 |
| --- | --- | --- |
| OutdoorPassBuilder（内部） | volume / temporal / depth-history / upsample 的图声明与录制 | 全局设置解析、TAA/Bloom、另建 RenderGraph |
| OutdoorFrameState（内部） | 当前候选/上一成功相机、历史权重/有效性、失效原因 | 分配 GL 资源 |
| OutdoorResources（内部，确有必要时） | 现有 pass 对象、颜色/深度历史、resize candidate 的唯一所有权 | 独立决定代次替换 |
| PostProcessPassBuilder（保留） | 通用 HDR 颜色链、TAA、曝光、Bloom、tone/LUT；调用 Outdoor 构图并接回输出 | 同时保存第二份 Outdoor 相机/历史 |
| PipelineGeneration（保留） | 唯一代次所有者，协调 graph/Outdoor/TAA/cluster 候选 | 跨代次借用旧可写历史 |
| RenderPipeline（保留） | 设置应用、帧事务、scene/camera 更新和诊断发布 | 在各模块间复制原始 texture ID 作长期缓存 |

所有拟新增类型先 package-private。一个 generation 只能有一个 OutdoorResources owner；如通过 PostProcessPassBuilder 间接拥有，就不能再由 PipelineGeneration 重复 close。

### 6.2 迁移顺序

1. 列出 PostProcessPassBuilder 中 outdoor* 字段、工厂/构造参数、build、相机更新、历史失效、成功发布、resize 与 close 的调用点。
2. 先移动纯 CPU OutdoorFrameState，保持旧调用顺序和失效判定；运行前后图像与失败注入。
3. 移动 Outdoor 图声明，返回类型化的“输出颜色句柄/producer”，继续接在同一个 graph。保留 pass 名称和依赖，便于前后比较。
4. 最后移动资源与 ResizeCandidate；旧方法暂时只委托，不同时保留两个 owner。
5. 更新 PipelineGeneration/RenderPipeline 调用，删除委托、重复字段与旧构造参数。

本阶段不同时修改积分、shadow sample、downsample、权重、深度阈值、天空或 TAA 顺序。行为优化放到后续独立提交，避免重构差异无法归因。

### 6.3 不可破坏的事务

- 帧开始仅 prepare 当前候选。所有可失败的结束工作先完成，再统一发布 history-valid、上一成功矩阵、sequence；publish 阶段不能再做可能抛异常的 GL 分配。
- 部分历史已被写入但帧失败时，不能伪装为仍有效的上一帧历史；使用现有写侧隔离或失效策略，证明不会再次采样半成品。
- resize 先准备 graph、TAA、Outdoor 颜色/深度历史、cluster 资源；任何一步失败关闭所有新候选，旧 generation 保持可用。
- 不在某个子模块 prepare 成功后提前提交其尺寸/句柄；整组 commit 后才交换并释放旧资源。
- scene replace、切镜、质量切换、启停、shader reload 的失效语义保持；两台相机/两条 pipeline 不共享 mutable history。
- SceneBufferView 仍是当帧借用，不能 close/保存到下帧；设备深度、线性深度、previous surface depth 不互换。

### 6.4 验收

重构前后相同输入、相同硬件同帧输出应一致；若由于执行细节出现非零误差，定位原因后冻结窄阈值，不能先用宽容差盖住变化。

用例至少包含 Outdoor reference、3600 帧稳定性、100 次设置/尺寸切换、颜色历史和深度历史分配失败、执行失败后恢复、NONE/FXAA/TAA/MSAA、GTAO+CSM+Bloom、宿主状态恢复。现有测试应迁移复用，不用几项新 mock 测试代替原真实 GL 矩阵。

## 7. M4：全局视觉预设与有限热更新

### 7.1 数据与分层

本版不做空间 volume，只处理一个当帧全局 profile。

- demo 层拟新增 VisualProfile/VisualProfileCodec：带 schemaVersion、id、说明、作者参数；读取文件不创建 GL 对象。
- renderer 层按需要增加最小不可变 VisualSettings：只包含引擎实际消费的数值，不知道文件路径、demo 名称或按钮。
- demo adapter 将 profile 转换为受校验的设置；相机路径/seed/抓图帧单独放 SceneCaptureSpec，避免调色文件悄悄修改测试几何或运动。
- 复用 Outdoor Demo 现有 saveEnvironmentConfig/loadEnvironmentConfig 的字段经验，将公共解析抽取后让旧入口委托；不要长期维护两套含义不同的字段。

首版字段：schemaVersion、profileId、manualExposure、IBL intensity/rotation、主方向光方向/颜色/强度、Bloom enabled/intensity/threshold/softKnee、已有 FogSettings、Outdoor 设置与现有 quality 枚举。LUT 若支持只引用已加载的受控资源 ID，不在 render 线程任意读文件。

用 properties 或项目现有 JSON 风格选一种正式序列化；建议本版沿用 properties，避免迁移格式成为前置工程。保存增加 schemaVersion；读旧配置走明确的兼容函数，不通过捕获所有异常静默回默认值。

### 7.2 校验与保存

解析阶段校验版本、未知字段策略、NaN/Infinity、非负强度、颜色范围、方向非零、合法 quality、局部体积数量和尺度。错误包含文件/字段/原因，当前有效 profile 保持不变。

先在目标目录写临时文件，完整校验后原子替换；不支持原子移动的平台使用明确回退并报告失败。单次加载先得到完整 immutable candidate，再入渲染线程应用；不边读字段边改画面。

资源引用只能来自既有资产解析和生命周期机制；关闭 profile 不等于关闭借用 environment/LUT。保存/加载 round-trip 不改变参数含义，不要求保留无意义的文本字段顺序。

### 7.3 参数、历史与拓扑分类

| 变化 | graph 重建 | 历史处理 |
| --- | --- | --- |
| 手动曝光、已启用 Bloom 的 intensity/threshold/softKnee | 不应重建；更新实际录制输入 | 曝光位于 TAA 后时不因纯输出曝光强制清全部历史 |
| 已有雾颜色/密度、太阳或局部介质内容 | 不应因标量变化重建 | 保守失效 Outdoor 历史；按实际 TAA 输入变化处理，不把表面 velocity 当雾运动 |
| IBL 强度/旋转、直接照明剧变 | 不应重建资源 | 采用明确的 temporal lighting invalidation，避免保留旧光照 |
| Bloom 启停/层数、AA、体积分辨率/启停、附件需求 | 候选 generation 或现有专用事务 | 依变化失效相关历史，失败恢复旧设置 |
| 相同 profile 再次 apply | no-op | 不增加 revision、不清历史、不重建 |

不能假定现在的 RenderSettings 和 build-only setter 已支持这些热更新。本版需要最小 typed update seam，让 PostProcessPassBuilder 的录制读取冻结值。不能偷偷修改 RenderSettings 全局对象或绕过 topologySettingsRevision。

一次 apply 对太阳、IBL、后期和 Outdoor 是原子操作。现有 PbrEnvironment 有可变 intensity/rotation，不要在 candidate 成功前先改它；如必须修改借用对象，保存旧值并在失败时恢复。更优先使用 per-frame override，避免两个 pipeline 共用同一 environment 时互相污染。

普通数值调节由下一帧生效；GPU 资源型切换允许较高成本，但 UI 要明确区分。暂不引入异步全图编译、任意 smooth blending 或多 profile 空间混合。

### 7.4 验收

- codec round-trip、旧版本迁移、未知/损坏配置、NaN、超量雾体、缺资产引用。
- 连续 300 帧调整曝光/Bloom intensity，generationBuildCount 不增加，参数有真实图像效果。
- 重复 apply 同值不增长 revision；切换 topology 后效果正确、资源不泄漏。
- 注入资源分配失败时，太阳/IBL/后期全部保留旧值。
- 两条 pipeline 借用同一 environment 的参数隔离。
- 保存后重启同配置、同帧得到相同图像；证明不依赖上次手调残留。

## 8. M5：三个视觉基线与 Demo 设计

### 8.1 固定场景

| profile | 场景 | 主检查点 | 不允许的替代 |
| --- | --- | --- | --- |
| forest_morning | 现有 Outdoor 林地 | 树冠遮挡、晨雾层次、太阳光束、曝光后叶片层次 | 提高全局 Bloom 掩盖体积错误 |
| forest_dusk | 同一林地和相机基线 | 冷暖关系、轮廓、远景雾和暗部 | 更换素材后称调色提升 |
| town_night | 新 ClusteredTownModel | 建筑/门窗辨识、街道深度、暖灯与冷月光、喷泉不过曝 | 回退旧大方块或把灯数减少后称性能优化 |

本版只做静态湿润感的 roughness 调节作为可选变体，不加入雨、水或 SSR。无新增外部素材需求时优先保留程序化模型；确有新素材才补授权与 manifest。

### 8.2 冻结顺序

1. 灰模和中性材质检查几何尺寸、法线、遮挡和轮廓。
2. 固定曝光、IBL、主光、灯强度/范围，确认暗部可读而无全屏泛白。
3. 固定粗糙度/金属度，再调雾和冷暖色；最后加 Bloom 和 LUT。
4. 保存 profile，重新加载后抓图，不以未保存的手调状态作验收。
5. 固定静态全景和 480 帧路径，声明 60/240/420 抓图；UI 不进入正式图像门禁。

小镇主立面灯位继续由模型 Anchors 生成；后立面装饰窗没有独立点灯的限制保留在说明中。几何/灯数/路径变化需更新 sceneRevision，不能覆盖旧报告。

### 8.3 对照和诊断

每场景保存 final、fog off、Bloom off、固定曝光灰模；Outdoor 另外有高采样 history-off 参考、transmittance/scattering/history rejection；小镇有 cluster occupancy/overflow/shadow slot。

线性 HDR 数值验证与 tone-mapped PNG 美术复核分别输出。TAA 使用静止收敛、相机移动、灯变化、切镜/遮挡恢复序列，测量误差随时间与残影恢复，不拿单帧 sharpness 推断所有时域质量。

继承已有 Outdoor/TAA 数值阈值；新场景阈值在 M0 的参考图和人工复核基础上确定并写配置，正式候选不能临时放松。若当前图像工具只支持 RGBA8，则先补 HDR 读回测试能力，不能换名声称已经验证线性 HDR。

### 8.4 UI 最小范围

在已有 demo/overlay 中提供 profile 选择、Save/Reload、固定曝光、fog/Bloom 对照、路径暂停与截图。图形诊断继续放高级面板；profile 切换不创建第二套控制器或编辑器。

关闭窗口、resize、切换 profile 和退出时关闭顺序仍由现有 demo Bundle/pipeline 管理，不能把新资源交给 UI 持有到进程退出。

## 10. 删旧代码与迁移边界

本版允许移除内部重复实现，不要求为未发布内部 API 保留兼容层；已有公开 API 的调整仍更新 migrations/allowlist，不能静默删掉用户入口。

应删除：

- BenchmarkSuite 中基于当前轮次的样本过滤与误命名 submit 统计。
- 正式任务默认 --cpu-isolation；原归因能力移至独立任务。
- PostProcessPassBuilder 中已迁移的 Outdoor 字段、分配/释放、resize、矩阵与重复历史状态。
- profile codec 抽取后 demo 内重复解析；原入口改成委托或明确迁移。
- 新旧参数更新路径产生相同效果但绕过不同生命周期的重复分支。

不得删除：

- 现有 Outdoor 高采样参考、Beer–Lambert/HG 等数值证明。
- TAA/GTAO/Scene Buffers 的独立历史、Reactive 和成功帧契约。
- 灯表/阴影 stable ID 和 frameLightIndex 映射、overflow 正确回退。
- 新小镇模型和确定性动画、正常性能路径及原始失败报告。

修改 shader/资源路径后同步 manifest、许可证记录、测试资源合同与 Gradle 输入；不能把旧性能报告修改成新版本通过报告。
