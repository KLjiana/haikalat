## 1. 目标与范围

本版本交付一个能够通过生产入口启停、调参、处理历史与资源事务的 GTAO 内部模块，同时减少 `RenderPipeline` 和 `PostProcessPassBuilder` 对 GTAO 实现细节的了解。保持现有 AO 算法、材质作用范围及画面合同；必要的已有缺陷修复单独记录。

```text
0.27.1
├── 必须交付
│   ├── GTAO 生产依赖、资源与历史合同
│   ├── MSAA resolve → GTAO 的正确生产者顺序
│   ├── 狭窄的运行时启停／调参入口
│   ├── GTAO 私有资源与渲染装配边界
│   ├── 候选提交、失败恢复及无关资源复用
│   ├── GTAO × 体积雾组合回归
│   └── 两个模块的共性评估与中心职责变化记录
├── 按变化触发的验收
│   ├── RenderGraph／附件所有权回归
│   ├── 宿主回调与借用目标复验
│   └── 单场景性能观察
└── 不纳入本版本
    ├── 通用插件发现、独立模块版本解析、后台常驻线程
    ├── 全部 Subsystems 迁移或公共 FeatureModule 框架
    ├── GTAO 算法升级、全新 AO 算法和画质档扩张
    ├── 全面 UI／编辑器／风格预设系统
    └── Minecraft 地形／光照统一整合与完整发布工程
```

成功标准不是目录调整或类行数变少，而是：GTAO 的内部变化通常只涉及其自身边界和必要装配；启停不无故重建无关 owner；参数更新与失败语义能通过真实绘制证明；新增第二模块没有在中心类再复制一套资源管理分支。

## 3. 当前代码切口

以下文件位于 `src/main/java/com/kaleblangley/haikalat/`；描述依据制定本计划时的源码，开工需刷新。

| 入口 | 当前职责／问题 | 本版本处理 |
|---|---|---|
| `subsystems/render3d/GtaoPasses.java` | 已拥有程序、ScreenQuad、可选历史及 estimate/temporal/denoise/upsample Pass；配置为 final，输入通过 sharedSurface 布尔和固定名称选择 | 保留算法实现；明确配置更新、输入与输出、资源所有权，避免再套空壳模块 |
| `subsystems/render3d/GtaoHistory.java` | 双缓冲历史、成功提交与 resize candidate | 保留并补全跨候选、失败、停用及内容失效合同 |
| `subsystems/render3d/PostProcessPassBuilder.java` | 创建／关闭 GTAO，转发帧回调、深度预通道统计、诊断、历史 import 和 resize；同时负责 TAA/Bloom/曝光等 | 将 GTAO 的专属生命周期和装配归回其边界；避免形成同量转发的第二层管理器 |
| `subsystems/render3d/RenderPipeline.java` | 构造 GTAO 深度 Shader、决定 shared surface、执行深度预通道、材质采样、失败／成功协调；已有 postProcessSettings 构建前入口 | 保留公共兼容入口和全帧协调，增加必要的运行时 GTAO 更新能力，减少直接操纵私有资源 |
| `subsystems/render3d/PipelineGeneration.java` | Graph、私有 owner、借用转交与 resize 事务 | 接入 GTAO 局部替换，明确图资源、GTAO 和后处理 owner 的独立所有权 |
| `subsystems/render3d/PipelineTopology.java`、`ForwardPassBuilder.java` | 表面通道需求、MSAA resolve、Geometry 依赖 AO 输出 | 将实际 producer 与输入规格传给 GTAO；不得让模块猜测注册次序 |
| `subsystems/postprocess/GtaoSettings.java`、`GtaoQuality.java` | 不可变参数；质量档由方向数／步数定义 | 保留公开配置含义，区分数值、算法采样参数和资源拓扑变化 |

**先处理已观察到的生产者依赖缺口：** `GtaoPasses.addPreGeometryPasses` 在共享表面路径中仅依赖 `SceneSurfacePass`；MSAA 时读取的单采样深度／法线由 `SceneSurfaceResolvePass` 产生。不能依靠注册顺序保证 resolve 先执行。M1 必须添加生产回归并修正该连接，再冻结相应组合的重构参考画面。

历史 MASK 顶点 alpha 一致性等问题先复核影响：若触及本次 GTAO 深度／表面验收，作为独立正确性修复处理；不把原有错误输出冻结成正确答案，也不顺带承诺修完全部高级功能审计事项。

## 4. 目标边界与运行合同

### 4.1 装配与所有权

```text
RenderPipeline：公共入口、帧级协调
└── 装配与候选事务（优先复用已有机制）
    ├── 场景表面生产者
    │   ├── 单采样表面／兼容的独立深度路径
    │   └── MSAA 表面 → resolve
    ├── GTAO 内部边界
    │   ├── 配置分类、帧输入与历史有效性
    │   ├── 专属程序、历史、按需深度绘制资源
    │   └── estimate → temporal → denoise → upsample
    ├── Geometry／PBR：消费 AO 输出
    ├── 体积雾：独立私有资源与历史
    └── 后处理：TAA、曝光、Bloom 等既有职责
```

此树表达职责，不要求逐层增加类型。M2 必须给出具体迁移清单：哪些 GTAO 构造、释放、resize、import、诊断和回调职责从中心对象移出，哪些装配连接保留，为什么。

| 对象 | 所有者与权限 |
|---|---|
| 场景深度／法线及其 resolve 附件 | 原 Graph／表面生产者拥有；GTAO 借用，说明格式、坐标、尺寸、采样数、实际 producer 和代次 |
| GTAO 中间和最终图附件 | Graph 拥有；模块声明输出，不能重复释放 |
| GTAO 历史附件 | GTAO 历史 owner 拥有；Graph import 仅借用，帧内 read/write 身份明确 |
| GTAO 程序、quad、专属深度绘制资源 | 各自唯一 owner，归入 GTAO 生命周期边界；复用失败不得释放活动对象 |
| Camera、光照、阴影、TAA、体积雾资源 | 各自原 owner；GTAO 不能关闭；复用需要兼容性和代次证据 |
| 宿主 framebuffer／texture | 宿主拥有，任何模块和候选都不可释放 |

输入合同不得只记录纹理名字。构图时验证生产者存在、顺序、格式与样本数；执行时拒绝失效代次和不合法的历史目标。Graph 仍使用显式依赖，不在本版本建设通用资源读写推导系统。

AO 输出维持现有作用范围：PBR 间接光及材质 opt-out 合同。关闭时使用正确的无 AO 语义，不残留旧纹理绑定，不乘黑，也不把 AO 擅自扩展到直接光、透明或全部材质。

### 4.2 运行时参数

交付一个狭窄的生产更新入口，建议形态为 `applyGtao(GtaoSettings)`；最终命名与公开级别在 M2 审查，本文不是已存在 API 的说明。不通过重建整个 Pipeline 的 Demo 旁路冒充运行时更新，也不扩大现有所有后处理参数的可变范围。

| 参数变化 | 目标行为 |
|---|---|
| radius／strength／thickness | 更新数值，不重建图或无关 GPU 对象；按实际历史内容定义失效原因 |
| historyWeight／depthRejectionThreshold | 更新时域参数，不重建图；是否丢弃历史需说明理由 |
| quality | 当前表示方向数／步数，默认按采样参数更新；没有实际规格变化时不得仅因枚举改变重建资源 |
| enabled | 改变 Pass 纳入范围及必要的表面需求；完整候选成功后发布；停用释放专属资源 |
| temporal | 影响历史分配和外部目标／内部附件路径，需要明确候选事务 |
| 尺寸／AA／世界／资源重载 | 根据实际规格和代次进行重建、复用或失效，不混用旧输入 |

保持同步渲染线程入口语义：返回成功表示已经在安全边界生效。拒绝执行中、错误线程／Context 和关闭后调用。不为了第二模块新增异步队列；未来有真实异步准备需求时另行设计请求合同。

### 4.3 提交、失败与历史

1. CPU 校验和预算先于 GPU 候选分配；峰值包含活动、候选和待退役资源，使用实际 AO 格式／尺寸核算，不能照搬雾预算。
2. 创建和编译候选时不得修改活动回调捕获的状态、历史 read/write 或 donor 所有权。
3. 完整输入与图校验成功后，在帧边界提交；旧资源按已有 fence／在途使用规则退役。
4. 发布前失败保留旧设置、旧图及真实可绘制结果，释放候选；发布后清理失败保持新状态并单独报告。
5. 帧执行失败不提交 GTAO 成功历史；部分 GPU 写入不可回滚，必须使受影响历史失效并验证恢复。
6. 停用清除后续 AO 绘制、专属历史与程序驻留；若有缓存，必须显式定义上限和回收策略，默认不保留专属缓存。

区分存储复用与像素历史有效性。GTAO 开关可能改变最终颜色，因此可以让 TAA 内容失效而保留存储；不能仅因 GTAO 开关就重建体积雾 owner、重置无关灯表或清除阴影缓存。反向切换雾时，也必须验证 GTAO owner 与历史是否真的需要变化。

保留稳定相机下 GTAO 采样相位及 TAA jitter 的现有约定；不把每帧 jitter 当成相机移动。相机突变、resize、配置和失败的失效原因须可诊断，不用无理由全局 reset 掩盖错误。

## 5. 两个模块的共性评估

M4 输出对照表，分别列出体积雾与 GTAO 的参数分类、输入验证、候选预算、所有权转交、Pass 贡献、历史提交、退役和错误路径。

只有两处生产代码确实重复、且提炼后减少中心对象实现知识时，才引入小型内部机制。允许复用既有 Graph/manager 事务，也允许部分差异保持具体实现；不要为了统一方法签名制造空实现或强迫 GTAO 和雾共享历史策略。

公共 `FeatureModule` 不是本版本完成条件。若认为必须公开，需额外说明两个生产消费者、被替代的重复、稳定语义、失败模式和迁移成本，遵守抽象密度准入规则。

**架构退出条件：** `PostProcessPassBuilder` 不再作为 GTAO 的完整资源与帧生命周期代理；`RenderPipeline` 保留必要的 AO 装配／材质连接，但不再新增平行的一整套 GTAO 私有资源构造、借用、清理分支。若中心细节反而增长，先调整切口，不能仅凭测试通过宣布架构目标完成。

## 8. 执行与证据预算

优先扩展现有 `GtaoSettingsTest`、`GtaoAnalyticReferenceTest`、`GtaoPassesTest`、`GtaoShaderGlTest`、`GtaoReconstructionGlTest`、`GtaoHistoryResizeGlTest`、`PipelineTopologyTest` 与 `RenderPipelineGlTest`。体积雾邻接验证优先使用现有 Modularity／Composite GL 中与 owner 复用、历史及表面输入相关用例。

现有入口可复用，但实施前须核对所选类的属性与执行条件：`glSmoke` 不自动保证所有 readback 用例执行；有需要时显式启用对应属性或使用合适叶子 task，跳过不算通过。`runRender3dGtaoIntegration` 可作为生产 Demo 入口；不直接运行携带 benchmark 的 `localGtaoVerification` 代替选测。

- 日常与普通功能签收：定向 JVM、受影响 GL、一个必要主场景，默认总时限 5 分钟；超时列未完成项，不循环重跑。
- 同一未变输入的证据可复用，保留原指纹与 `REUSED_PASS` 标记；修改 Shader／绑定／历史后重新验证直接受影响链路。
- API／架构守卫在相应变更后新鲜执行，记录实际执行数、跳过数和退出码。
- benchmark 非本版本普通功能验收前置条件；有性能承诺或有效回退迹象时单独安排固定配置。未测记 `NOT_EVALUATED`，不沿用体积雾预算宣称 GTAO 达标。
- 不默认再次跑全部 0.27.0 画质、4K、3600 帧与完整 Minecraft 17 步；只有共享资源或对应行为变化才扩展所需范围。
- G13 若只复用未变宿主协议，可用有效宿主证据加新鲜嵌入式 GL 签收协议范围。若声称实际客户端中的 GTAO 可见，必须使用含可见几何／接触面的 Scene 真实运行；空场景抓图不足以证明 AO 效果，更不能证明 Minecraft 地形整合。
