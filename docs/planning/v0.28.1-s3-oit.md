| resolve | 全屏 resolve 读取两个附件：`average = Σ(c·α·w) / max(Σ(α·w), 1e-6)`，`coverage = 1 - Π(1-α)`，输出 `(average, coverage)`；调用方目标上以 `SRC_ALPHA / ONE_MINUS_SRC_ALPHA` + `FUNC_ADD` 合成，即 `average·coverage + dst·revealage`。空白像素 coverage=0，目标逐位保持不变。若 `accum`/`weightSum` 为 NaN/Inf、`weightSum<0`、`weightSum>6.5e4`、任一 `accum.rgb>6.5e4` 或 `accum.a∉[0,1]`，视为溢出/损坏，输出 coverage=0（目标保持不变）；否则 `average` clamp 到 `65504`，保证写入 half-float target 的通道有限。 |
| 权重公式 | `w(z) = clamp(depthScale / (1 + (|z| / referenceDepth)^2), minimumWeight, maximumWeight)`，`z` 为插值后的正视图深度（`-viewPosition.z`）。`depthWeighting=false` 时精确返回 1.0。默认 `depthScale=10`、`referenceDepth=20 m`、`minimumWeight=1e-2`、`maximumWeight=300`。 |
| 参数校验 | `depthScale ∈ [0.001,1000]`；`referenceDepth ∈ [0.01,1e6]`；`minimumWeight ∈ [0,1000]`；`maximumWeight ∈ (0,1000]` 且 `≥ minimumWeight`；`alphaThreshold ∈ [0,0.999]`；`maximumSurfaces ∈ [1,65536]`。全部要求有限；非法值在 record 之前拒绝，不静默夹取。**`alphaThreshold` 是逐层 `discard` 阈值（`α <= threshold` 的层完全不累积），不是把 alpha clamp 到下限。** |

## 与主透明队列、#26 的关系

- 本 Pass 只处理**显式传入的集合**。同一帧不得让同一批表面既走主透明 alpha 队列又走 OIT 累积，否则会双重合成；
  是否切换由 Integrator 按集合（粒子/烟雾/独立透明网格）决定，并在图描述与文档中标注。
- 与 #26 是同一透明集合的两条互斥路线：需要精确前后顺序的 alpha 粒子可走 #26 排序；可接受近似加权平均的烟雾/粒子走 #28。
  两条路线共享同一份 `OitSurface` 展开结果即可做 A/B 对照，但不得共享累积附件或同帧混用。
- #37 随机透明是第三条独立路线；本卡不宣称 OIT 等同于精确排序或随机透明。

## 权重公式与误差

权重（与 shader、`WeightedOitSettings.weightForViewDepth` 一致）：

```text
z = |view-space depth|                       // 米
w(z) = depthWeighting ? clamp(depthScale / (1 + (z/referenceDepth)^2),
                              minimumWeight, maximumWeight) : 1
```

- `w(0) = depthScale`（被 `maximumWeight` 限制）；`w(referenceDepth) = depthScale/2`；随 `|z|` 单调递减。
- 权重整体缩放会在 resolve 的除法中抵消，只影响相对权重与 float16 动态范围；因此默认把 `maximumWeight` 限制在 300。
- 结果始终位于 `[minimumWeight, maximumWeight]`，`z=0` 不产生除零；depth weighting 关闭时精确为 1。
- shader 对 `NaN/Inf` 的视图深度或权重回退到 `minimumWeight`，并把单层权重硬 clamp 到 `3.0e4`（在 settings 上限之上再留一层保护）。

### 有限输出保护（复审反例）

`OitSurface` 是合法的不可变值，但合法的极值仍可能让 half-float 附件溢出，例如
`color=7000, α=1`、默认 `w(1 m)≈9.975` 时单层贡献约 `69,825 > 65,504`；多层 `α=1,color=1` 也可让
`Σ(α·w)` 超过 half-float 上限。生产 shader 采用两层保护：

| 阶段 | 保护 | 数值 |
|---|---|---|
| surface fragment | 单层权重 clamp | `w ≤ 3.0e4` |
| surface fragment | 单层贡献 `color·α·w` 逐通道 clamp | `≤ 3.0e4` |
| surface fragment | NaN/Inf 输入回退 | 非有限视图深度/权重/颜色 ⇒ 有限值（`minimumWeight` 或 0） |
| resolve fragment | 附件有限性与上限检查 | `isnan/isinf`、`weightSum<0`、`weightSum>6.5e4`、`accum.rgb>6.5e4`、`accum.a∉[0,1]` |
| resolve fragment | 非法累积回退 | 输出 coverage=0，target 保持原值（不写 Inf/NaN，不伪造颜色） |
| resolve fragment | 合法平均颜色上限 | `min(average, 65504)` |

保证：在调用方 target 本身有限的正常前提下，对任意合法 `OitSurface` 列表，最终 target 的 RGB 通道都是有限值且
`∈ [0, 65504]`（alpha 由 coverage 与 target 原有 alpha 的 over 合成决定）。超过附件容量的极端叠加会
**整像素丢失 OIT 贡献并保留背景**（有界、可解释的降级），而不是输出 Inf/NaN；这可从 target 读回与
GL 极端用例观察到。默认权重下正常烟雾/粒子的累积远低于 `6.5e4` 上限，不受影响。

**误差说明（两层）**。设近层 `(a₁,c₁)`、远层 `(a₂,c₂)`，权重同为 1，背景 `b`，`t=(1-a₁)(1-a₂)`：

```text
精确 sorted over:  a₁c₁ + (1-a₁)a₂c₂ + t·b
WBOIT resolve:     (a₁c₁ + a₂c₂)/(a₁+a₂) · (1-t) + t·b
WBOIT - 精确排序 = (a₁²·a₂/(a₁+a₂)) · (c₂ - c₁) = -(a₁²·a₂/(a₁+a₂)) · (c₁ - c₂)
|WBOIT - 精确排序| = (a₁²·a₂/(a₁+a₂)) · |c₁ - c₂|
```

- 透射 `t` 与背景项精确一致；误差只来自不同颜色的加权平均，且随 `|c₁-c₂|` 与 alpha 增大。
- 当所有层颜色相同、或某层 alpha 为 0 时 WBOIT 与精确排序一致。GL 排序参考用例因此同时覆盖：同色两层（与精确
  sorted over 在 2e-3 内一致）和异色两层（断言 `|实际 - 精确排序| ≤ 上述解析界 + 2e-3`，并以独立加权模型做 2e-3 的
  更严格断言）；不把 WBOIT 宣称为精确排序。
- 三层及以上没有同形式的简单界；本版不承诺精确透明交错，误差随层数与颜色分散增大。多批次表面在同一像素上合成时同样适用该近似。

## 共享命令扩展（集成时必须一起合并）

既有 typed 命令路径的 `blendFunc` 只能为 RGB 和 alpha 设置相同因子，无法表达
`GL_ONE, GL_ONE, GL_ZERO, GL_ONE_MINUS_SRC_ALPHA`。本包补充了受控、通用于其它效果的：

- `CommandBuffer.blendFuncSeparate(int,int,int,int)`；
- `PendingPipelineState` 保存四因子并按“alpha == rgb 时仍走 `blendFunc`”编码；
- `PipelineStateSink.blendFuncSeparate` 与 `StateCache` 的四因子缓存（后续 `blendFunc` 会像 `glBlendFunc` 一样重置 alpha 因子）；
- `PendingPipelineStateTest` 新增：命令计数/对象 payload 检查、**直接解码 4 个 blend 整数**的状态包测试、以及 alpha == RGB
  时回退为 `glBlendFunc` 的双因子往返测试。

没有引入 `custom(Runnable)`；`architectureGuard` 的
`productionCodeDoesNotUseCustomCommandEscapeHatch` 仍通过。该扩展是共享文件改动，Integrator 合并本包时必须一并保留。

## API/README 描述校正

由于公共 API 叙述段落由 Integrator 在集成分支维护，本 Worker 按原任务禁令未直接修改
`docs/architecture/public-api/README.md`；集成分支若已有 OIT 段落，请使用以下校正文本：

- 附件 0 `RGBA16F`：RGB = `Σ(c·α·w)`，A = `Π(1-α)`（revealage/transmittance）。
- 附件 1 `R16F`：`Σ(α·w)`（权重和），**不是 revealage**；revealage 只在附件 0 的 alpha。
- `alphaThreshold` 是逐层 `discard` 阈值（`α <= threshold` 的层不累积），**不是 alpha 下限 clamp**。
- `OitSurface.color` 的合法上限是 `65504`，但单层贡献与权重在 shader 内 clamp 到 `3.0e4`；resolve 对溢出/非有限
  附件回退为 coverage=0（target 不变）并把平均颜色 clamp 到 `65504`，因此最终 target 有限。
- 关闭（`enabled=false` / `settings.active()==false`）时不创建 Pass、附件或绘制。

## 接线合同（Integrator）

1. `RenderFeatureSettings`/`RenderPipeline` 增加 `WeightedOitSettings` 字段与 `weightedOit(...)`/`applyWeightedOit(...)`，
   默认 `WeightedOitSettings.disabled()`；只在 `active()` 时创建 `WeightedOitPass(width,height,settings)`。
   `maximumSurfaces` 改变需要新建 Pass（Pass 会拒绝不匹配的 settings）。
2. 图节点：按上文推荐顺序插入 `record` 与 `resolve` 两个节点/执行点；`record` 的附件是模块私有资源，不由 RenderGraph 声明；
   `resolve` 必须画在已绑定 HDR 目标的节点内。
3. 选中的粒子集合从主透明队列移除；同一集合不得再交给 #26/alpha 队列。OIT 集合与主透明队列的**不同**表面可以在
   同一帧共存（OIT 先 resolve 到 HDR，再画主队列），但先后关系与深度交错不在本版承诺内。
4. 场景目标：要求单采样 HDR 目标（或在 MSAA resolve 之后）。本版不做 MSAA 逐样本累积；不得把 `resolve` 指向
   多重采样附件。
5. 共享深度：Pass 不绑定也不写共享深度；遮挡剔除由调用方完成。若后续需要逐片段遮挡，应另开任务并明确 MSAA 语义。
6. `docs/architecture/public-api/README.md` 按任务约束未修改；本包已把三个新类型登记到
   `docs/architecture/public-api/render3d.allowlist`，README 的叙述由 Integrator 统一补充。

## 明确限制与未验证项

1. 不是精确透明排序：解析使用单一加权平均色，二层以上/多颜色层存在本卡推导的近似误差；不承诺任意透明交错、逐像素正确前后关系或精确折射/透射。
2. 不做场景深度遮挡：Pass 无深度附件、不采样共享深度；被不透明体遮挡的表面若进入集合仍会贡献。调用方必须预裁剪，或另立任务扩展（含 MSAA 深度语义）。
3. 只接受世界空间平行四边形列表（`halfRight`/`halfUp` 可表达旋转/倾斜，但仍是四边形）；任意透明 mesh、纹理/逐顶点颜色/法线、骨骼/形变与粒子软边深度不支持。
4. half-float 边界：单层权重与贡献被 clamp 到 `3.0e4`，resolve 在 `>6.5e4`/非有限时整像素回退为背景（target 不变）；因此极端亮度或极多层叠加不会输出 Inf/NaN，但会**有界地丢失该像素的 OIT 贡献**。正常默认权重下的烟雾/粒子远低于上限。`alphaThreshold` 会改变能量（被丢弃的表面不产生透射）。
5. 单采样限制：MSAA 路径需要先 resolve 再接入；本版没有逐样本覆盖/深度。
6. 时域/后处理组合未验证：OIT 表面没有 velocity/reactive 通道，接入 TAA 时移动粒子可能拖影；与雾、DOF、Bloom 的顺序只给出建议，未做真实组合验收。
7. 与 #26 的 A/B 对照、#27 粒子真实集合、`VfxRenderer` 消费均未接线（本 Worker 禁止修改 `RenderPipeline` 等指定文件）；`README.md` 公共 API 叙述由 Integrator 补，校正文本见上文「API/README 描述校正」。
8. 未做 GPU 性能/显存测量；质量档只是有界配置，成本状态 `NOT_EVALUATED`。
