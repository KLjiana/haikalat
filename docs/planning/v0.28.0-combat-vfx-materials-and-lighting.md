# 0.28 战斗特效材质与动态光照实施计划

计划日期：2026-11-11。目标版本：0.28.0。状态：已实施并通过复审聚焦验收；本文冻结建议交付范围与验收合同。实现与聚焦验收结果见 [0.28.0 验收](../releases/v0.28.0-review.md)，使用说明见 [战斗 VFX 指南](../guides/render3d-combat-vfx.md)。

依据：[实时渲染技术未来计划大纲](realtime-rendering-roadmap.md) A 组。用户指定本次计划版本为 **0.28**，承接大纲原先暂标为 0.27.6 的技术主线；不要求先实施全部 [0.27.6 候选方案](v0.27.6-candidate-tasks.md)。规划时实际 `build.gradle` 仍为 0.27.5；实施时已按第 13 节升级到 0.28.0。

## 1. 版本目标

让作者通过已有场景与 UI，组合出“蓄力 → 释放 → 命中 → 消退”的完整战斗特效：网格能量边缘随视角变化，纹理随时间流动并局部扭曲，效果按曲线溶解，短暂动态光实际照亮周边场景。

本版交付四项相互组合的技术，以及完成配置、预览、保存、加载和重放所需的最小工具流程。新增效果必须进入正式 VFX／RenderPipeline 调用链，不能仅在独立 Demo shader 中实现。

### 1.1 必做与排除范围

| 类别 | 0.28 范围 |
|---|---|
| #1 轮廓光 | 有可靠法线的网格 VFX，支持颜色、强度、指数和遮罩；不改写 PBR 现有 Fresnel |
| #2 UV Flow / Distortion | VFX 材质内 UV 流动和局部噪声扭曲；不是采样场景颜色的屏幕扭曲 |
| #3 Dissolve / Erosion | VFX 噪声阈值、可控发光边缘、生命周期曲线；不扩展至所有不透明场景材质 |
| #7 VFX Dynamic Lighting | 少量、有限生命周期、无阴影点光；使用现有灯表与 Clustered 光照 |
| 组合与控制 | 不可变材质／帧数据、确定性时间与种子、容量规则、已有总暂停／HDR VFX 门控接线 |
| 作者工具 | 当前四项的参数面板、固定条件 A/B、限定范围的配置保存／加载、重放和失败提示 |
| 联合消费者 | 一个已有 Render3D 场景中的完整技能过程，包含真实受光物体和带法线的网格 VFX |
| 不纳入 | 通用顶点位移、投射式贴花、屏幕空间折射、GPU 粒子生产化、特效投影灯／阴影、场景材质通用溶解、空间参数混合、完整编辑器 |

0.28 不因版本号跨到 0.28 就扩大为 A–H 全路线交付。聚光特效灯、通用材质推广可以后续增加，不以扩充本版技术数量为验收目标。

### 1.2 完成标准

- 同一套参数可在 API 与工具入口使用；参数最终驱动真实 shader 和场景灯表。
- 三种材质效果可以在同一个网格上同时使用；可以与同一效果时间线的点光组合。
- 关闭、取消、停止生成、暂停、重放和加载失败有明确且不同的行为。
- 非法输入在发布前拒绝；合法标量调整不重建 RenderGraph、不重复分配纹理。
- 代表性组合、资源所有权、失败恢复和旧入口兼容通过下文验收。
- 性能、人工视觉、真实 Minecraft 与发布就绪分别报告，不由功能 PASS 自动推导。

## 3. 架构与生产数据流

### 3.1 职责分配

```text
作者参数／效果资产／明确的时间输入
  └─ subsystems.vfx
       ├─ 材质定义、曲线、种子、效果生命周期
       └─ 不可变帧快照：primitive 参数 + 有界灯描述
            └─ render3d 装配入口：一次冻结同一特效帧
                 ├─ render3d.vfx：GPU 资源与颜色／reactive 录制
                 └─ 纯值灯适配 → 帧光照输入 → FrameLightTable
                                              └─ lighting / Clustered / PBR

demo 作者面板
  └─ 草稿校验 → 资源准备 → 帧边界发布 → 实际状态展示
```

| 位置 | 允许承担 | 不应承担 |
|---|---|---|
| `subsystems.vfx` | GL-free 定义、时间采样、灯的效果空间／世界空间数据 | 导入 `RenderPipeline`、`SceneLight`、GL 类型或创建 GPU 资源 |
| `render3d.vfx` | shader／纹理／网格 owner、值到光照合同的适配 | 依赖 `render3d.pipeline` 或反向操纵整个 RenderPipeline |
| `render3d.pipeline`／入口 | 借用特效输入、同帧冻结、装配与候选事务 | UV、溶解和轮廓算法、完整特效实例状态 |
| `render3d.scene / lighting` | 消费普通冻结灯条目、容量与上传 | 知道 EffectAsset、技能阶段或 UI 字段 |
| `demo` | 面板、预设文件、固定场景与重放驱动 | 作为正式算法、灯桥接或资源 owner 的唯一实现 |

新增值类型以真实需要为准。下文“特效帧输入”“灯桥接”“作者配置”等是职责名称，不要求机械创建同名 manager／factory／controller。新增 public 类型同步 [API 清单与迁移记录](../architecture/public-api/README.md)，新增包同步架构门禁名单。

### 3.2 冻结与线程顺序

1. 逻辑侧推进效果时间并生成深度不可变快照；相机相关排序与灯身份分开。
2. 外部线程通过已有受控交接方式把完整快照送到 GPU owner，不逐字段修改活动数据。
3. 帧入口先处理统一控制请求；按实际 effective 状态选择本帧特效输入。
4. 灯适配、容量选择和普通灯合并发生在 `RenderFrameContext`／灯表冻结前。
5. VFX 颜色录制和 reactive 重录制只消费同一已冻结快照；录制期间不能推进时间或修改 Scene。
6. 后到快照下一帧处理；多个视图可有独立排序，但不能各自推进同一效果年龄。

本版给正式调用方提供完成上述接线的最小受控入口。不能要求调用方在 HDR 后处理回调内临时修改灯来补救时序，也不能只在 Demo 更新循环里实现桥接。

## 4. 四项技术卡与算法合同

### 4.1 #1 网格轮廓光

- **输入**：位置、UV、有效法线、模型矩阵、相机位置，线性 RGB 颜色、非负强度、正指数；首版只支持有明确法线的网格 VFX。
- **计算**：以单位世界法线 `N`、单位指向相机向量 `V` 计算艺术权重 `r = pow(1 - clamp(dot(N, V), 0, 1), exponent)`。双面网格先按约定将背面法线翻向可见面，再计算。它是艺术轮廓项，不宣称是新的物理 Fresnel BRDF。
- **法线合同**：非均匀缩放使用逆转置；镜像变换的朝向需覆盖；奇异变换必须明确拒绝或跳过，不产生 NaN。NORMAL 位置在 M0 结合 `MeshData` 布局冻结，不能全局改变旧 UV location。
- **输出**：增加线性 HDR 发光颜色，受材质遮罩、溶解可见性和最终透明覆盖限制；不无条件增加 alpha，也不在完全消失的像素上保留亮边。
- **资源**：复用网格／shader owner。旧不含法线的 quad、Ribbon、平面贴花继续走旧路径；不在未绑定法线属性时依赖默认 attribute 值。
- **参考**：独立标量算例：指数 2 时，`N·V=1/0.5/0` 对应 `r=0/0.25/1`；旋转物体／相机、非均匀缩放和背面像素对照。
- **成本／回退**：参数关闭走基线；不需要独立全屏 Pass；正式 GPU 成本 `NOT_EVALUATED`。缺法线时拒绝启用轮廓功能，不能伪报生效。

### 4.2 #2 UV 流动与局部扭曲

- **输入**：primitive 局部 UV、固定定义的效果时间、速度、噪声资源／缩放／幅度／种子、UV region 和可选 Flipbook。
- **顺序**：局部 UV → 速度乘时间偏移 → 局部噪声扭曲 → 局部 wrap／clamp → 映射当前／下一 Flipbook cell → 两次纹理采样并混合。噪声坐标和基色坐标分开，避免无意递归采样。
- **图集**：wrap 在 cell 内发生；采样足迹不能进入邻 cell。首版可对无 padding 图集限制 mip／过滤方式，M0 冻结明确策略及半 texel 边界，不能把 `CLAMP_TO_EDGE` 当成所有图集边界的保证。
- **时间**：使用传入的确定性时间与固定噪声，禁止 shader 自行读取墙钟；速度为 UV 单位／秒，改变速度不改变纹理缓存身份。
- **资源**：噪声／控制纹理是线性数据，颜色纹理遵循已有 sRGB 解码；缓存键体现用途／颜色空间和资源版本，不把强度／时间作为纹理键。
- **参考**：手工 UV 位移算例、常量／棋盘／双色 cell 输入；零速度／零幅度基线、正负速度、边界、Flipbook 插值与固定时刻对照。
- **成本／回退**：关闭不采样新增噪声；无场景颜色／深度新附件。当前不承诺所有采样组合无代价。

### 4.3 #3 溶解与侵蚀

- **输入**：线性噪声 `n∈[0,1]`、溶解进度 `d∈[0,1]`、边缘宽度／颜色／强度和生命周期采样结果。
- **首版语义**：`d=0` 完整恢复原材质，`d=1` 完全消失，端点显式处理；中间以固定噪声阈值决定可见性，在可见侧计算有界发光边缘。边缘宽度为 0 时无边缘发光，不除以零。
- **组合**：基础颜色采样与轮廓／溶解边缘在 HDR 中组合，统一受原 alpha／遮罩及溶解覆盖限制，最后按现有 alpha 或 additive 合同输出；雾变体维持已有预乘约定，不能重复乘 alpha。
- **生命周期**：默认以 primitive 归一化年龄驱动，也允许显式效果阶段参数；在配置中区分这两种来源，不由 shader 猜测。
- **时域**：颜色与 reactive 使用同一噪声、阈值、时间和覆盖；TAA 下检查快速消失、镜头移动和前景遮挡。首版不制造不存在的 VFX velocity，利用已有 reactive／拒绝策略并明确剩余限制。
- **资源／参考**：复用新噪声资源 owner；常量噪声和手写阈值集合证明覆盖与端点，用像素数／边缘值验证，不只检查 shader 编译。
- **回退**：功能关闭与零进度回到旧材质；非法／缺失资源在发布前失败，保持旧效果配置。

### 4.4 #7 无阴影特效点光

- **输入**：效果实例身份、局部灯序号、世界位置、线性颜色、强度／范围曲线、优先级和有限生命周期；不把每个粒子默认变成灯。
- **范围**：首版点光、`castShadows=false`，默认 `LightVolumeHints.DISABLED`，只承担表面照明；不隐式启用体积注光或创建阴影槽位。
- **身份**：效果灯键由实例身份与灯序号确定；映射到与 Scene 灯不冲突的正数 stable ID，复用／共享现有身份分配规则。不能用数组索引、帧序号或未经验证的负数区间代替。
- **合并方案**：优先在帧输入层合并冻结的普通灯与临时特效灯，不向用户 Scene 灯列表反复增删。灯适配输出普通光照值；如需扩展 `RenderFrameContext.capture`，保持旧重载和原场景变更检测，并独立跟踪特效灯输入 revision。
- **容量**：普通场景灯保留既有容量语义。特效可用容量为配置上限与剩余 local light 容量的较小值；按显式优先级、稳定身份确定性选择。场景自身超限继续报错，不能通过裁掉用户灯掩盖错误。
- **动态变化**：位置、颜色、强度和生灭在既有容量内不重建图；容量规格变化才走候选事务。特效灯变化不无条件清空 TAA／体积历史；同时检查不要因无阴影灯更新而使所有静态阴影缓存失效。
- **参考**：同位置／颜色／强度／范围的手工 Scene 点光作为等价生产对照，辅以独立容量／身份算例；看周边 PBR 接收面的 HDR 差异，不能只看 VFX 自发光亮不亮。
- **诊断**：请求数、选中数、裁减数及门控原因有界记录；性能未评估前不承诺某个灯数能在所有场景稳定运行。

## 5. 时间、实例与控制合同

### 5.1 三层数据分离

| 数据 | 存放位置 | 更新规则 |
|---|---|---|
| 材质／效果定义 | `VfxMaterial`／`EffectAsset` 及必要配置值 | 不可变；纹理逻辑引用、参数范围、曲线定义 |
| 运行状态 | `EffectInstance` 或已有实例拥有者 | 时间、随机状态、粒子、网格、灯实例；有界且可关闭 |
| 帧值 | `EffectSnapshot` 及必要组合值 | 每帧固定；录制／reactive／灯适配只读 |

材质相同但年龄不同的两个实例必须独立表现；不得为了上传每帧时间而复制整套纹理资源或把时间加入共享材质缓存键。

### 5.2 行为语义

| 操作 | 必须发生 |
|---|---|
| 停止生成 | 不再发射新 primitive；已有内容按其生命周期继续消退，保持 `emitting(false)` 旧语义 |
| 效果暂停 | 所属更新驱动停止推进效果时钟；同一快照可重复绘制，不重新采样随机数 |
| 立即取消 | 后续帧不含该实例的 primitive 和灯；清除其运行状态，不关闭共享材质资源 |
| 重放 | 从定义与种子重新建立实例；固定采样／更新序列可重复，不恢复过期 GPU 句柄 |
| 管线总暂停 | 遵守现有渲染暂停与资源保留合同；作者工具同时暂停其拥有的效果时钟，UI 继续响应 |
| HDR VFX 关闭 | 本版受控特效帧的视觉录制和关联灯同时不参与；其他普通场景灯不变 |
| 直接光关闭 | 点光可以仍在输入诊断中，但不贡献表面光照；明确原因，不误报桥接失败 |

`RenderPipeline` 不能自动暂停任意外部调用方的 CPU 模拟。工具中的暂停联动属于明确的更新驱动行为，不改变现有总开关 API 含义。

精确可重复承诺限定为：相同初始定义、种子、事件和更新序列得到相同结果；解析材质／灯曲线在相同显式时间一致。现有粒子积分不因此被宣称对任意不同 dt 划分产生逐位相同轨迹。大 dt、过期和越界行为单独测试。

### 5.3 统一控制与兼容

- 本版正式受控输入使用现有 `hdrVfx` 能力门，完整配置仍通过 `RenderFeaturesControl` 提交；不为 UV 速度、溶解阈值或轮廓颜色分别新增全局开关。
- 在活动诊断中区分未挂载输入、门关闭、无活动实例、灯容量裁减和直接光关闭。扩展 HDR VFX 对关联灯的含义时同步控制合同，不静默改变旧纯 recorder 的所有权。
- 旧 `VfxRenderer.record`、`VfxMaterial` 默认值、已有 EffectAsset 构建、无新字段的快照构造保持源兼容入口；公共 record 若变更组件，列出旧构造兼容及二进制兼容影响，不能只以源码编译通过宣称二进制兼容。
- 旧 recorder 仍由调用方拥有；新输入和 renderer 的 borrowed／owned 必须独立声明。控制器不创建 shader、不关闭调用方 renderer。

## 6. 资源准备、加载失败与所有权

| 资源／数据 | owner | 借用者与释放要求 |
|---|---|---|
| 特效定义／CPU 实例 | 调用方的效果拥有者 | renderer 借用帧快照；取消实例不释放共享资产 |
| VFX 程序、GPU 网格、颜色／噪声纹理 | `VfxRenderer` 及其私有资源 owner | 管线借用；关闭／资源替换只由 owner 处理 |
| 场景深度、HDR 颜色与 reactive 目标 | 既有 Graph／宿主协议 | VFX 借用，不保存跨代帧租约 |
| 灯身份映射与冻结临时灯 | 本版受控输入的装配 owner | 容量有界；取消／场景解绑／关闭时清理映射，不删除用户灯 |
| 预设文件与 UI 草稿 | demo 作者工具 | 不持有 GL ID、callback 或 pipeline 私有状态 |

作者路径的资源切换必须执行：解析 CPU 候选 → 校验定义与资源引用 → owner 线程准备全部新增 GPU 资源 → 帧边界发布 → 安全退役旧资源。失败关闭候选自有资源，保持旧配置、旧 renderer 可用和一致的灯描述。

这是本版需要补齐的能力，不能假定现有 `VfxTextureCache.get` 的首次同步加载已经提供该保证。允许明确同步的“加载”操作，不需要为此增加常驻线程；热路径只使用准备好的资源。标量编辑不触发解码／上传。

反复加载不同资源必须有释放／有界缓存策略，不能让资源键永久积累到 renderer 关闭。被多个活动实例借用的旧纹理不得提前释放；CPU 原始资产和 GPU owner 的生命周期分开说明。

发布后退役异常保留已发布的活动配置并报告，不能伪报回滚。单帧 GPU 执行失败也不意味着画面像素已恢复；配置事务与 GPU 帧成功语义分别记录。

## 7. 作者流程与联合场景

### 7.1 一个正式联合入口

扩展 `HaikalatShowcaseDemo` 现有 HDR VFX 接线，提供固定相机、带法线网格、受光 PBR 接收面和遮挡物。沿用已有 UI 组件／诊断面板，不把 UI 通用层绑定到 Render3D。

场景过程：

1. 蓄力：网格轮廓光与 UV 流动，点光强度按曲线上升。
2. 释放：产生网格／粒子内容，点光按世界位置移动；不要求新增战斗玩法系统。
3. 命中：接收面出现可比较的照明响应，HDR／Bloom 可观察。
4. 消退：溶解进度和灯强度独立按定义下降，最终无残留 primitive 和灯。

固定场景承担四项技术的组合证明；`VfxDemo` 可用于局部调试，不新增四个 Demo 或四个 Gradle 任务。

### 7.2 最小面板

- 实例选择、时间／重放／取消、效果暂停与管线暂停状态。
- 轮廓颜色／强度／指数，UV 速度／幅度，溶解进度／边缘，灯颜色／强度／范围／优先级。
- 资源逻辑 ID、requested／effective／失败原因，以及活动实例／灯裁减计数。
- 保存、加载、基线 A/B；A/B 锁定相机、采样时间、种子和曝光条件。

草稿编辑不直接覆盖生效配置；非法草稿保留在 UI 并显示原因。加载失败保留旧有效效果。一次操作提交完整候选，禁止 UI 分字段跨线程修改活动资源。

### 7.3 限定范围的作者配置

首版保存当前联合场景支持的材质参数、曲线／时间规则、种子、点光定义和资源逻辑引用。网格／纹理通过场景支持的资源目录解析；不序列化任意 Java 对象、GL ID、完整 Scene 或任意 callback。

为该配置定义独立 schema 标识及版本，复用 [VisualProfileCodec](../../src/demo/java/com/kaleblangley/haikalat/demo/pbr/VisualProfileCodec.java) 的严格解析／原子保存经验，但不把视觉 profile schema 2 当作新的 VFX 文件解释。首版不宣称可以导出任意 EffectAsset。

CPU codec 可以先留在 demo 工具层；正式 API 仍直接接收生产定义。缺字段、未知版本、非有限数、越界值和资源缺失的处理明确，损坏文件不得覆盖已保存的有效文件。只有出现真实库消费需求才迁移 codec 到 main。

## 9. 验收合同

下列 C01–C18 是本计划新增的验收 ID，不是现有测试方法名。实施时映射到已有合同／必要新用例；一个用例可以覆盖多项，不按行机械新建测试类。

| ID | 必需合同 | 主要证据 |
|---|---|---|
| C01 | 旧材质默认值与新功能关闭保持旧行为 | JVM 兼容构建＋冻结基线像素／命令行为 |
| C02 | 非有限数、越界进度、非法曲线和缺失必要属性明确拒绝 | 独立参数边界用例；不借助 GL 才发现纯数据错误 |
| C03 | 相同显式时间的解析参数一致；暂停、停止生成、取消、重放互不混淆 | 固定种子／事件的小序列；不要求任意积分 dt 划分逐位一致 |
| C04 | NORMAL、非均匀／镜像变换、双面与观察方向正确 | 轮廓解析值＋旋转／变换 GL 像素；缺法线拒绝 |
| C05 | UV 顺序、零幅度与图集／Flipbook 边界正确 | 棋盘、双色相邻帧、固定时间采样，不串 cell |
| C06 | 溶解完整／消失端点、阈值与边缘可解释 | 常量噪声、覆盖像素数、独立边缘数值 |
| C07 | 三项材质效果同网格组合，不互相覆盖参数 | 分项／组合 HDR 像素对照；alpha／additive 各代表一例 |
| C08 | 特效灯与手工同参点光对接收面产生相符结果 | 真实 RenderPipeline／Clustered／PBR 读回，不只检查灯列表 |
| C09 | 身份不冲突，裁减稳定，用户灯不被修改，输入冻结后不能混帧 | JVM 容量／身份＋生产多帧变更；场景自身超限仍明确失败 |
| C10 | HDR VFX 关闭同时停止受控视觉与关联灯；直接光门控可解释 | RenderFeaturesControl 真实执行与接收面 A/B |
| C11 | 取消／结束／场景解绑／关闭不留下灯，暂停资源语义正确 | 生命周期序列、计数及像素；外部 renderer 不被 pipeline 越权关闭 |
| C12 | 标量／灯生灭不重建图，容量／资源变化走候选；不无故失效其他历史 | generation／资源计数及必要 TAA／阴影缓存直接消费者 |
| C13 | 雾变体与 reactive 使用一致覆盖；快速溶解在 TAA 下无未说明残影 | 固定时间序列、颜色／reactive 读回、遮挡变化；保留算法限制 |
| C14 | 资源加载失败保留旧有效配置，候选无泄漏，成功替换可回收 | 资源错误／分配失败注入、owner／句柄证据；重复加载有界 |
| C15 | resize、目标借用、执行失败与恢复遵守现有事务 | 新路径的实际受影响 GL 消费者；不改宿主附件所有权 |
| C16 | 实际 UI 输入驱动材质／灯，非法编辑不覆盖有效状态 | 输入派发 → 草稿 → 提交 → 快照 → 像素／状态链路；人工体验另外记录 |
| C17 | 保存／加载／重放可恢复所承诺的配置，损坏文件不破坏旧状态 | 严格 codec＋实际消费者重载，不仅 round-trip |
| C18 | 实例、灯、缓存、shader 变体与诊断有界，组合流程结束回到约定基线 | 代表负载、资源／计数记录；成本未正式验证时标 NOT_EVALUATED |

### 9.1 最小组合矩阵

- 旧 quad／Ribbon／网格各保留代表性兼容；轮廓只对有法线网格启用。
- 单实例：三项效果分别开／关及同网格全开；多实例：共享材质但不同年龄／种子。
- AA：NONE 基线与 TAA 时域为必需；MSAA 覆盖新深度／resolve 消费路径；未改动的 FXAA 可按输入与合同说明复用旧证据。
- 透明：alpha 与 additive；深度遮挡、soft particle、HDR／Bloom；体积雾开／关时颜色与 reactive 消费。
- 灯：0、容量以内、特效超限、场景已满；普通灯与特效灯混合，取消／重放，直接光门与 HDR VFX 门。
- 事件：总暂停／恢复、取消、坏文件／坏资源、resize、目标替换与 owner 关闭。

非法组合应被明确拒绝，不能依靠自动改设置让所有测试都运行到成功分支。不存在消费者的组合不为凑矩阵添加。

## 10. 验证入口与证据组织

遵循[测试指南](../guides/testing.md)、[合同索引](../guides/test-contracts.md)及[有侧重验收规范](../guides/focused-acceptance-policy.md)。优先扩展当前存在的 `VfxMaterialTest`、`EffectInstanceTest`、`VfxRendererMathTest`、`VfxRendererGlTest`、`VfxTextureCacheGlTest`、`RenderFeatureControlTest`／`GlTest`。

灯表冻结、控制与 PBR 接收的联合回归如现有 fixture 不适合，可增加一组围绕该行为的集成测试；必须写明现有便宜覆盖为何不足。新 codec、UI 输入的测试接到实际新消费者，不能借用现有 VisualProfileCodec 测试结果冒充完成。

当前可用的定向入口示例，实施后按实际受影响方法调整：

```powershell
# 纯逻辑：选定受影响领域，不创建 GL
.\gradlew.bat test --tests "*VfxMaterialTest" --tests "*EffectInstanceTest" --tests "*VfxRendererMathTest"

# 材质与纹理的真实 GL 消费者
.\gradlew.bat glSmoke --tests "*VfxRendererGlTest" --tests "*VfxTextureCacheGlTest"

# 控制面接线改动时的直接消费者
.\gradlew.bat glSmoke --tests "*RenderFeatureControlGlTest"
```

这些不是完整 C01–C18 清单，不能只跑三个命令就签收本版。M0/M5 将灯合并、雾／TAA、UI 和加载合同映射到实际 case 与入口；新必需 case 未加入固定 focused 列表时，原 `verify.ps1` 不会自动覆盖它。

- 普通聚焦签收默认总时限 300 秒、零自动重试；按修改选取组合，不依次叠加全量 `check`、无过滤 `glSmoke`、GL 全集和发布矩阵。
- 新增 public 类型／迁移时运行相关 API 与架构门禁；构建配置确需修改才阅读构建指引并调整任务，不预设新增任务。
- GPU 结果核对实际执行、readback、XML 与候选身份。`UP-TO-DATE`、历史复用、新执行分别报告；未执行／空选择／必需 skip／超时不记 PASS。
- 失败保留 case、候选、日志、耗时；正确性失败先修复，不进行无依据重试。修复后只重跑受影响合同和直接消费者。
- 产出建议放在 `build/reports/v028-acceptance/<runId>/`，包含候选身份、合同映射、必要像素／资源证据和失败记录。该目录是建议归档约定，不是当前已经存在的自动化任务。

## 11. 成本、资源与视觉评价

目标档位为 RTX 3050 Laptop；代表场景建议 1920×1080，具体硬件、驱动、功耗、电源模式、显存、AA、内部尺寸、灯数和覆盖率随记录保存。

本版首先证明正确性与有界资源，不预先承诺固定毫秒或帧率。普通开发可记录代表负载计时；只有开展明确的正式性能任务并通过冻结门槛后，才将性能从 `NOT_EVALUATED` 改为已验证。

至少记录：基线／分项／组合的 CPU 与 GPU 可用计时、draw 次数、材质切换、实例数、灯请求／选中／裁减数、纹理／网格缓存以及加载候选峰值。不能只用粒子总数代表透明 overdraw，也不能只看无阴影灯数推断总成本。

功能关闭、实例取消和总暂停的资源曲线分别解释。第一版如果缓存保留已准备资源，必须注明缓存政策和上限，不声称“关闭后显存归零”。

人工视觉评价使用固定曝光、相机、时间、种子和对照开关，检查战斗目标可读性、过曝、残影、突变及边缘闪烁。自动像素通过与人工表现通过分开记录；Minecraft 客户端不在本版默认验收范围。

## 12. 风险与处理顺序

| 风险 | 必须采取的处理 |
|---|---|
| 轮廓只在 Demo 特殊网格有效 | M0 冻结生产 NORMAL 布局与旧网格兼容；M2 在真实 renderer 验证 |
| 材质参数爆炸／shader 变体指数增长 | 小型组合值与受控分支；按真实布局／雾需求选变体，不为每个数值生成程序 |
| UV 图集串帧、溶解噪声颜色空间错误 | 独立图案 fixture、用途明确的线性资源、发布前校验 |
| 特效灯晚一帧／与视觉不一致 | 在帧冻结前处理统一输入与门控，颜色和灯使用相同 revision |
| 动态灯让整帧不断重建／清空历史 | 容量与数值变化分离；独立 revision；检测 generation、阴影缓存和时域消费者 |
| 缓存只增不减，加载失败污染活动状态 | 明确候选 owner 与替换回收，反复资源切换测试；不靠全局 clean 掩盖 |
| UI 扩展变成完整编辑器 | 仅做四项技术必要参数与限定 schema；空间区域混合和通用资产编辑后置 |
| 只测试局部 shader，缺生产光照 | M3/C08/C10 强制经过 RenderPipeline、灯表、Clustered 和真实 PBR 接收面 |

遇到风险时先收窄明确不承诺的内容或修正合同，不能降低独立正确性阈值来完成签收。
