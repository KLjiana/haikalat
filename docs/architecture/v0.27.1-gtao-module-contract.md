# v0.27.1 GTAO 模块合同

日期：2026-11-07。生产实现合同；候选身份和验收结果见[复核记录](../releases/v0.27.1-review.md)，修复前/后的身份与零容差参考见[基线](../releases/v0.27.1-baseline.md)。

## 具体边界与迁移清单

`GtaoPasses` 是实际 GPU owner 和 Pass 贡献者，不再套一层空壳 FeatureModule。`PipelineGeneration` 直接拥有 GTAO，与体积雾及后处理并列。`RenderPipeline` 保留公共入口、完整帧提交和 AO→PBR 的材质连接。

| 原责任 | 目标位置 | 保留在中心的连接 |
|---|---|---|
| PostProcess 创建/关闭 GTAO | Generation 拥有 GtaoPasses，后者关闭程序、quad、history、专属深度绘制资源 | 只选取当前 GTAO 配置及输入来源 |
| PostProcess 代理 begin/success/failure/history import | GtaoPasses 持有历史与待提交帧 | 完整帧成功/失败时与其他 owner 协调 |
| PostProcess 代理 resize/诊断 | GTAO 自己的 candidate；Generation 聚合 resize 事务 | 完整 resize 提交及现有 Render3dDiagnostics 值快照 |
| Pipeline 构造三种 GTAO depth Shader 并实现整段深度绘制 | GtaoDepthPass，包含 opaque/MASK/deformation/实例绘制与唯一程序所有权 | 传入冻结 SceneFrame、CameraUniforms 与实例消费者，只借用 |
| sharedSurface 布尔与模块猜测 producer | 每个 Graph 的 GtaoSurfaceInputs 租约 | 装配处选择实际单采样 producer，MSAA 明确为 resolve |
| Pipeline 直接操纵 GTAO 私有资源 | GtaoPasses 的参数、历史和候选合同 | 狭窄 applyGtao 入口；不增加通用后处理可变 API |

`PostProcessPassBuilder` 不应再持有 GtaoPasses 字段，也不保留对应生命周期/历史/诊断转发方法。GTAO 深度 Shader 路径和专用 draw loop 不应再出现在 RenderPipeline/Generation。不是把 RenderPipeline 整体搬进另一个管理器。

## 输入、输出与代次

GtaoSurfaceInputs 为包内具体值合同，包含所属 Graph/代次、实际 producer、深度/法线逻辑附件、AA、temporal 和输入模式。它不拥有 Graph 或纹理。

- shared 单采样：SceneSurfacePass 生产 D24 device-depth texture、RG16F signed-oct 世界法线。
- shared MSAA：SceneSurfacePass 生产多采样附件；SceneSurfaceResolvePass 选择同一覆盖样本，产出 R32F device depth、RG16F 法线及对应运动数据。GTAO estimate 显式依赖 resolve。
- 兼容独立深度：GtaoDepthPass 写单采样 D24，仅由 GTAO 拥有程序；场景 mesh、材质、CameraUniforms、实例及变形绑定均借用，保持相同 MASK/绕序/剔除合同。
- shared temporal 同时要求 RG16F velocity、R32F previous surface depth、R8 validity，不能只记录纹理名字。

构图校验 producer 存在、Graph 尺寸、单采样、附件类型/格式及实际依赖顺序。Graph 的深度描述为 DEPTH_COMPONENT，实际 canonical descriptor 为 DEPTH_COMPONENT24；R32F resolve 作为颜色附件校验。Graph 只用显式依赖，本版本不增加通用读写推导。

执行前校验帧尺寸与 Graph；每个 Pass 捕获其输入租约，只有该租约已在当前帧 prepare 后才能执行。旧 Graph 的 callback 不能消费另一代刚准备的帧。resize 保持 Graph/租约代次，尺寸从已提交 Graph 与历史实际目标核对，避免冻结旧宽高。

AO 中间/最终附件归 Graph；temporal 双缓冲 RG16F 归 GtaoHistory，Graph import 只借用本帧 write target。历史 target 必须是本 owner 的候选且尺寸为 ceil-half；read/write 只在成功帧交换。GTAO normal cache 为 unsigned-oct，不能与共享世界法线的 signed-oct 混用。

## 参数与历史

运行入口为 advanced RenderPipeline 上的 `applyGtao(GtaoSettings)`，保持同步渲染线程语义；返回成功表示配置已在安全帧边界生效。拒绝执行中、错误线程/Context、关闭后调用，不引入后台准备队列。

| 变化 | 存储/Graph | 内容失效 |
|---|---|---|
| radius/strength/thickness | 保留 Graph、程序、history storage 与无关 owner | AO 估计值变化，拒绝旧 GTAO 像素历史；最终颜色改变使 TAA 内容失效 |
| quality | 方向数/步数更新，不因枚举变化分配新存储 | 采样结果变化，GTAO/TAA 内容失效 |
| historyWeight | 无 Graph/存储变化 | 原 AO history 含义不变，可使用新混合权重 |
| depthRejectionThreshold | 无 Graph/存储变化 | 更新后续拒绝/过滤策略，理由可诊断；不以全局 reset 隐藏错误 |
| enabled/temporal | 先完整构建候选，再发布；停用不保留专属缓存 | 按实际颜色/历史形状失效，TAA storage 可保留 |
| 相机突变/投影/resize/世界/失败 | 按真实依赖失效或重建 | 原因进入成功帧诊断；失败帧不消费待报告原因 |

稳定相机的 GTAO phase 保持不动，只有真实视图移动推进既有序列；TAA jitter 不视为相机移动。部分 GPU 写入不能撤销；失败不提交 read/write 或成功帧相机，恢复时拒绝受影响历史。

## 候选与资源

CPU 规格校验及 AO 专属分配预算必须先于候选 GPU 分配。AO 使用自己的 R8/RG16F/D24 及 ceil-half 尺寸核算，活动、候选、待退役余额均计入；不得套用体积雾预算或把格式估算称为实测显存。

当前 `GtaoAllocationPlan` 的活动上限为 128 MiB，事务峰值上限为 256 MiB，仅覆盖 AO 专属附件、history 与 quad 的格式估算。共享场景表面、程序驱动开销和其他模块不在此计数内，不代表整个 Pipeline 或进程的显存上限。令 `F=w*h`、`H=ceil(w/2)*ceil(h/2)`，quad 为 96 字节：

| 路径 | Graph 附件 | 私有资源 |
|---|---|---|
| shared + temporal | `F + 6H` | `96 + 8H` |
| shared + 非 temporal | `F + 10H` | `96` |
| 独立深度 | 在上述 Graph 计数加 `4F` | 与对应 temporal 设置相同 |

3840×2160 的 shared/temporal 为 37,324,896 字节，独立深度/temporal 为 70,502,496 字节；这些是公式校验，不能当作本机 4K 运行或性能证明。新代预算汇总活动和退役代余额，复用项保守计入 retained。公开 resize 先等待并回收退役队列，再准备活动代与 resize 候选，所以不遗漏仍驻留的旧代。硬件最大纹理尺寸在 owner 初始化时读取并缓存，规格检查在附件分配前拒绝超限。

构建候选不得修改活动回调捕获的状态、历史或 donor 所有权。Graph 编译及输入校验后才能发布；借用转交沿用 Generation/Graph/RenderTargetManager 的现有机制，已提交旧代沿用有界 fence 退役。发布前故障保留旧配置/真实像素并清理候选；发布后退役故障保持新配置，单独报告清理失败。

旧代在尝试建立 fence **之前**进入同一退役队列。若 fence 创建失败，owner 仍在队列中，后续合法收集/关闭可重新建立覆盖此前提交的 fence；不能因插入失败丢弃旧 owner，也不能把 0 handle 当作有效 fence。原生故障回归覆盖重复插入失败、恢复收集、关闭失败后重试，检查新代不回滚、旧 history/owner 仍可达及最后 live=0。

GTAO 与体积雾分别持有历史。GTAO 启停不应重建灯表、阴影、Camera、TAA storage 或无变化的雾资源；雾启停/规格变化也不应重建不相关 GTAO owner 或清空其 AO history。共享表面附件只按所有实际消费者的并集保留，descriptor 不兼容时由 Graph 更换，借用期与所有权不混淆。

AO 仅作用于既有 PBR 间接光与材质 opt-out 范围，不乘直接光或扩展到所有透明材质。停用时明确关 uniform 并解绑 texture/sampler，后续消费者使用无 AO 语义。每个 GTAO 输入显式使用纹理自身 sampling 参数，不继承材质 sampler。

## 共享表面绘制输入

`SceneSurfacePass` 在激活普通网格的表面程序前先绑定首个网格 VAO。诊断控制将通用顶点法线设为 `(9,8,7)`，异常 MSAA 首帧读到的长度与该值相符，而缓冲内网格法线仍是 `(0,0,1)`；调整程序与 VAO 的顺序后，两轮各 96 次冷启动探针通过。保持原 Shader、法线编码和 AO 算法，实例程序路径也保持原合同。不以这些本机证据推断所有驱动的内部原因。

变形 Shader 的五个活跃 SSBO（7–11）需要有效存储。[OpenGL 4.6 §7.8](https://registry.khronos.org/OpenGL/specs/gl/glspec46.core.withchanges.pdf)规定，活跃 storage block 没有足够 backing 时，执行结果可未定义或被修改。`SceneDeformationDefaults` 用既有 typed buffer 命令绑定 identity palette（64 B）与 zero morph（16 B），真实 draw binding 覆盖实际使用项。原生反射的最小范围为 64/16/4/64/4 B，glTF morph weight 的合法 4 B 步长保持原样。单独补齐存储的 JAR 仍捕获过首帧反证，两项修复分别保留各自证据。

这 80 B 是 Generation 共享资源，由现有 borrow/adopt/close 管理，不计入 AO 专属附件预算。在 surface/reactive、三类 shadow、PBR 和兼容 GTAO depth 录制前提供有效默认绑定。宿主状态恢复包含既有的 SSBO 0–15，新增嵌入式 GL 用例明确检查 7–11 的宿主绑定与存活。

## 两模块共性与职责复核

M4 以真实调用点审计配置分类、输入租约、预算、Graph 贡献、成功历史、借用转交和退役。优先让 GTAO 与雾共同消费已有 Generation.borrow / Graph replacement / 有界 fence；是否新增小型机制由实际重复决定，不以对齐方法签名为目标。

| 职责 | GTAO 的实际调用 | 体积雾的实际调用 | 共用或保留差异 |
|---|---|---|---|
| 同步配置 | `RenderPipeline.applyGtao` → `GtaoPasses.applySettings`，enabled/temporal 走代候选 | `applyVolumetricFog`，quality/emission 走代候选，其余在帧准备读取 | 共用线程、Context、执行中和关闭检查；保留具体配置分类 |
| 输入合同 | `GtaoSurfaceInputs` 捕获 Graph、代次、实际 producer；`prepareFrame/requireFrame` 校验租约 | `VolumetricLightingInputs` 借用灯表，`VolumetricSurfaceInputs` 校验表面；`compatibleScene` 限制 variant 复用 | 各自验证坐标、格式和所有权；不强迫共享一个万能输入类型 |
| CPU 预算 | `GtaoAllocationPlan.prepare` | `VolumetricAllocationPlan.prepare` | 都在候选分配前校验；分别使用 AO 与 froxel/颜色链的真实格式公式 |
| 贡献 Pass | `PipelineGeneration.assembleGtao` → `GtaoPasses.addPreGeometryPasses` | `assembleVolumetric` → `VolumetricPassBuilder.addPasses/addColorPasses` | Graph 仍拥有图内附件；实际执行器在模块内 |
| 私有复用 | compatible 的 `GtaoPasses` 及其 history | compatible 的 fog owner、history 和 material variants | 两个真实消费者都使用现有 `PipelineGeneration.borrow/adoptBorrowedResources`；失败候选不关闭 donor |
| Graph 复用 | 两者均经 `RenderGraph.replacementOf/commitReplacement` 与 `RenderTargetManager.borrowCompatible/commitBorrowed` | 同左 | 以 descriptor 和共享附件来源检查兼容性，不仅比较名字 |
| 历史提交 | `GtaoHistory.stageRendered/commit/discard`；GTAO phase、相机与失效原因 | fog 的 `prepareFrameSuccess/frameSucceeded/frameFailed` 及体积历史 | 仅全帧成功共同提交；两者的重投影与历史策略保持独立 |
| 退役与关闭 | Generation 直接关闭 GTAO owner | Generation 直接关闭 fog owner | 共用 Pipeline 已有的有界 fence 队列与关闭重试协议；没有再复制一套 GTAO 退役队列 |

结论是继续使用以上已有的具体事务机制，不新增公共 FeatureModule 或通用模块管理器。两个模块的内存结构、表面合同和历史策略不同，把它们强行改成相同回调接口不会减少实现知识。

一次半径更新的实际路径为：调用方构造新的 `GtaoSettings` → `applyGtao` 检查 render owner/Context/帧边界 → topology 不变时只调用 `GtaoPasses.applySettings` → 拒绝旧 AO 像素历史并保留 storage → 下一帧 `recordEstimate` 上传新半径 → 全帧成功后确认上传状态与失效原因。TAA 可以拒绝旧颜色内容而保留原目标；此路径不创建 Graph、程序、history 或 fog owner。enabled/temporal 变化则经过 `createGeneration` → 两模块具体 assembly → Graph 编译和租约校验 → 一次借用转交及发布 → 原 fence 退役路径。

从开工 `2e37724` 到阶段提交 `7b0b0c9`，`RenderPipeline` 为 2860→2809 行、`PostProcessPassBuilder` 为 1003→949 行、`PipelineGeneration` 为 313→357 行、`GtaoPasses` 为 645→763 行。行数只用于定位迁移，不能作为架构验收结论。实质变化是 PostProcess 的整套 GTAO 代理消失，三种 depth Shader 的构造与专用 draw loop 进入 `GtaoDepthPass`，Graph 输入及候选组装进入具体 GTAO 边界。Pipeline 仍连接 AO 到 PBR、协调全帧提交及管理整个 Generation，因此仍承担重要装配与事务职责。

最终相对开工的行数为 RenderPipeline 2860→2834、PostProcessPassBuilder 1003→949、PipelineGeneration 313→361、GtaoPasses 645→766。最终增加的默认输入装配和 fence 重试属于共享资源正确性职责，GTAO 专有构造、历史及释放仍在模块边界内。

默认生产路径使用 shared surface；保留的独立深度由内部测试选择器 `haikalat.test.gtaoDedicatedDepth` 经真实 Pipeline 验证，不是新增对外产品模式。公开 API 分类继续使用已有 advanced `RenderPipeline`，新增具体内部类型均不进入公共 allowlist。

最终报告必须列出中心移出的责任、保留的连接和一次参数变化路径。G01–G14 没有证据的项保持未完成；不能把编译成功、纯拓扑或截图当作全部资源事务/宿主整合完成。完整发布与 Minecraft 地形/光照整合不在本合同范围，`releaseReady=false`。
