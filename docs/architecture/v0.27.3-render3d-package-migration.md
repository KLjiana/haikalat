# v0.27.3 Render3D 包迁移清单

> 状态：M0–M3 已完成机械迁移；阶段结论与未完成项见
> [v0.27.3 review](../releases/v0.27.3-review.md)。
>
> 基线：HEAD `c8c8969`（会话开始时工作树干净）。候选：当前工作树（203 个改动
> 入口，含 docs/tests/demo）。本文件中的“旧类型”指基线 FQCN，“新类型”指候选
> FQCN。

## 1. 分类与兼容结论

- **stable 类型未删除**：`render3d.ExternalCamera`、`render3d.gltf.GltfRuntimeLibrary`、
  `render3d.gltf.GltfSceneAsset`、`render3d.pbr.PbrEnvironment*` 等仍保持原 FQCN、
  原构造器与公开方法签名。`publicApiGuard` 的 stable 签名与迁移记录检查通过。
- **advanced 类型**：后处理效果类、`ScreenQuad`、`TaaSettings`/`TaaResolveInputs`、
  阴影贴图／图集／诊断、`InstancedRenderer`、`MeshRenderer`、`SceneDrawBinding`、
  `TemporalDrawBinding`、`SceneBuffer*`、体积雾只读与诊断类型移入职责子包，类名与
  公开签名不变，调用方只需更新 import；迁移记录追加在
  `docs/architecture/public-api/migrations.md`。
- **internal 类型**：子包之间需要 public 的实现入口全部登记为 `internal`，只允许
  `render3d` 子系统内或 Demo 证明调用；它们在 `render3d.allowlist` 尾部集中列出。
- **新增 public 类型**：`PostProcessPipeline`、`SurfaceInputs`、`LateSurfaceProducer`、
  `TemporalFramePose`、`TaaInvalidationReason` 为 advanced 合同；各效果的
  `BloomChain`/`AutoExposureChain`/`ToneMappingChain`/`TemporalChain`/`FogChain`/
  `FxaaChain`/`TaaHistory` 为 internal。`PostProcessPassBuilder`（包内）由
  `PostProcessPipeline` 取代，兼容层不保留第二份状态。

## 5. 可见性提升

机械迁移需要跨子包访问的实现入口提升了可见性；全部为 `internal` 或新增的
advanced 合同，不做兼容承诺。提升发生在三处：

1. 迁移后的实现类本身（由包内可见改为 `public`）。
2. 模块间读取的快照／布局成员（如 `SceneFrame.renderer`、`FrameLightTable.record`、
   `SceneSurfaceLayout.Storage`、`ShadowFramePlan.DirectionalPlan`）。
3. 装配层需要的构造函数与候选类型（如 `GtaoPasses.ResizeCandidate`、
   `VolumetricResources.ResizeCandidate`、`TemporalFrameState.FrameParameters`）。

`SceneFrame` 的数组、计数和统计由构建器发布，消费者通过索引和标量访问。
`copyModel` 写入调用方的矩阵。`WorldBounds.Scratch` 是 `WorldBounds` 下的
internal 写入能力，只有持有该槽的构建器或实例批次能修改视图。

跨包可见性最小化仍按类型职责判定：根包入口保持原签名；新增 public 成员集中在
`internal` 实现类，`publicApiGuard` 只把它们登记在子系统域内。测试仍调用真实装配
入口（`RenderPipeline`/`Runtime`/真实 GL 用例），没有为了通过编译而改用反射。

## 6. 测试与 Demo 更新

- `RenderPipelineTest` 改为通过 `PostProcessPipeline` 与 `TemporalChain`/
  `AutoExposureChain` 的公开常量验证拓扑；新增 `SurfaceInputs` 桩仅用于无表面
  的纯拓扑用例。
- GL 用例继续直接构造 `TaaHistory`、`TaaResolveInputs`、`TaaSettings`，只更新 import。
- Demo 与运行时入口更新类型和查询方式。`ShadowPlannerEvidence` 用 planner 的
  `reset()` 触发完整重建，沿用场景装配顺序和 shader 路径。

## 7. 职责迁移结果与未迁移项

已完成：

- 后处理：`PostProcessPipeline` 只负责颜色链顺序与帧事务；Bloom／曝光／色调映射／
  TAA／FXAA／Fog 各自拥有程序与历史，`PostProcessPassBuilder` 不再持有全部效果状态。
- `ShadowCasterRecorder` 承接三类阴影的命令录制、遮罩材质绑定与图集清除。
  `ShadowPrograms` 负责普通、MASK 和实例程序的创建、复用判断与关闭，代次只转交程序组。
- 光照：`FrameLightBinder` 承接逐帧相机／阴影采样／cluster／AO 纹理绑定顺序。

- 几何：`SceneRenderer` 承接 forward／透明／instanced 的绘制顺序、材质与
  front-face 状态跟踪；`RenderPipeline` 只提供 `Host` 协作输入（帧快照、背景、
  frame state、PBR 绑定、透明 shader 变体）。

未完成：

- `RenderPipeline.sceneFrame()` 仍编排逐帧快照／灯表／cluster／阴影计划的生成
  （帧级协调职责）。`lighting` ↔ `shadow` 循环已通过把 `FrameLightTable` 上移到
  根包消除；现仅剩 `scene` ↔ `geometry` 的不可变快照／绘制值双向引用，见合同
  第 6 节。
- `render3d.gltf`、`pbr`、`preview`、`vfx` 为既有扩展包，本版本只随依赖更新
  import，不做内部重组。
