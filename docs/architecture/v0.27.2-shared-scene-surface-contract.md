# v0.27.2 共享场景表面合同

基础实现已接入生产装配。原生写入、像素和资源事务已完成定向 GPU 验证。[验收记录](../releases/v0.27.2-review.md)

## 需求与实体布局

`PipelineTopology` 合并已有 `SceneBufferRequirements`，用有效 AA 样本数调用 `SceneSurfaceLayout.plan`。原始请求的样本数必须等于光栅样本数，单采样请求必须为 1。`SceneBufferRequirements` 的公开 `merge` 和 `samples()` 保持原有聚合语义。生产装配先分别合并两类请求，再规划实体。

| 消费者 | 请求 | 执行时读取 |
|---|---|---|
| GTAO | 单采样深度、法线。开启 temporal 时增加运动组 | estimate、history、denoise 和 upsample 从本代输入取纹理。专属深度兼容路径保留独立 owner |
| TAA | 单采样深度、运动组。有实际晚期生产者时再要求 reactive | 颜色和全部表面生产者完成后写入 TAA 自有 history |
| 体积雾 | 光栅深度及单采样深度 | guide 用单采样深度，复合、透明和自身深度 VFX 保持原始样本。非 MSAA 软粒子在既有复制路径使用 R32F |
| 解析雾 | 单采样深度 | 雾后处理显式依赖实际深度生产者 |

| 通道 | 语义与格式 |
|---|---|
| DEPTH | 光栅 D24 device depth。MSAA 的单采样读视图使用 R32F |
| NORMAL | RG16F，世界空间几何法线的 signed oct 编码 |
| VELOCITY | RG16F，从当前表面指向上一成功帧的 UV 偏移，剔除 jitter |
| PREVIOUS_SURFACE_DEPTH | R32F，当前可见表面在上一帧视空间的线性深度 |
| VALIDITY | R8，可靠上一帧对应标志 |
| REACTIVE | R8，晚期历史拒绝强度。体积雾参与 TAA 时别名借用 composite 的 opaque mask |
| LINEAR_DEPTH | 必需请求直接拒绝。当前生产链没有该通道的独立生产者 |

请求 velocity 会补齐 previous-depth 和 validity。有早期表面输出时需要光栅深度以建立覆盖。仅深度、深度加法线、运动组三类都只创建实际需要的纹理。表面片元 Shader 的输出位置由布局提供。没有附件的输出映射到实际 color slot 之外。Resolve 的 Shader 与绑定只包含实际需要的单采样输出。

多采样 resolve 按样本编号升序选取最近深度。同深度保持先遇到的样本，所有同伴通道使用同一个编号。原先仅深度的体积雾 guide 保留精确 clear-depth 规则，其余保留 `0.999999` 的覆盖判定。单采样图的读视图直接借用光栅附件。

## 生产、借用与过期

`SceneSurfaceLayout` 提供实际逻辑名、格式、样本、槽位和 producer。Forward 装配根据它创建 surface 和必要 resolve。`SceneSurfaceInputs` 在候选发布前校验完整图的实际附件以及消费边。Reactive 校验区分 pass 自有 R8 和体积雾借用的 R8，并核对借用源 pass 和槽位。GTAO、TAA、解析雾和体积雾从同一租约绑定数据。体积雾的 graph callback 捕获各自候选的租约，复用 fog owner 时无需写回输入引用。

每帧的租约持有该帧的 extent 和 sequence。`PassResources.recordingPass(expectedGraph)` 在当前 Graph 的录制线程和回调内提供真实 pass 名。Raster、resolve 和 reactive 只能由各自的回调登记。Graph 按依赖录制并提交整帧命令流，正常返回或抛错都会结束回调范围。标记用于约束录制时序，GPU 执行结果沿用全帧成功与失败合同。绑定时核对帧对象、Graph、通道、producer 就绪及 framebuffer 的尺寸和样本数。帧结束清掉租约，退役和关闭同时撤销后续取用。换世界或 resize 后的新帧建立独立租约，GL ID 重用不影响有效性。

公开 `SceneBufferView` 仍是兼容值对象。构造器、单一 `samples()` 和可选查询保持原语义。它没有生产绑定入口，执行校验由包内租约承担。

## 资源与事务

Graph 继续拥有实体附件，Geometry 和晚期 reactive 仅借用相关 storage。GTAO、TAA 和体积雾的历史沿用各自 owner。Generation 根据实际布局兼容性借用表面程序和 resolve 程序，提交与回退沿用既有 Graph／Generation 和 fence 路径。

Graph 的 resize 候选与替换候选记录来源的目标版本。Pass 声明、Graph 尺寸、独立目标尺寸或资源转交发生变化时，旧候选在发布前被拒绝。公开的拓扑修订号仍用于描述 pass 拓扑。

当前实体复用单位是 Graph 的完整 target descriptor 与借用来源。布局改变时重建受影响的 target 组，同一个 FBO 内不做逐平面转移。场景深度、raw／resolved 组和 reactive 的格式账目归在共享表面。与体积雾 composite 共用的 reactive 按体积雾 owner 计一次。预算在分配前估算活动、候选和待退役字节，所有权转交后从 donor 扣减转移的组。该账目使用格式字节数和尺寸，不是实测 VRAM。设备尺寸上限及原有 GTAO／雾预算仍生效。

## 迁移点

- `PipelineTopology` 保留需求合并与拓扑快照。`ForwardPassBuilder` 用布局完成表面和 Geometry 的借用连接。
- `SceneSurfacePass` 和 `SceneSurfaceResolvePass` 使用布局槽位。普通网格仍先绑定 VAO 再激活表面 Shader。
- `GtaoSurfaceInputs` 保留专属深度区别。`VolumetricSurfaceInputs` 保留 RGBA16F 颜色约束。`PostProcessPassBuilder` 把 TAA 和 reactive 接到实际生产者。
- `PipelineGeneration` 持有布局对应的程序和租约，`RenderPipeline` 负责候选与帧协调。
