# v0.27.3 Render3D 模块边界合同

> 状态：M0–M3 结构迁移已落地并通过 JVM／架构门禁；联合验收见
> [v0.27.3 review](../releases/v0.27.3-review.md)。计划见
> [v0.27.3 planning](../planning/v0.27.3-render3d-module-boundaries-and-packages.md)。

本文件描述 0.27.3 之后的实际模块归属、允许依赖、帧／线程／资源合同，以及中心对象
仍然保留的职责。类型到包的完整映射见
[包迁移清单](v0.27.3-render3d-package-migration.md)。

## 1. 包与职责

`render3d` 根包只保留稳定入口、现有配置值和跨包值对象；实现进入职责子包。
`postprocess` 按效果拆分子包，并拥有颜色链所需的全部输入合同。

| 包 | 职责 | 拥有的资源 | 输入 |
|---|---|---|---|
| `render3d` | 公共入口 `RenderPipeline`、`Scene`/`Camera`/`SceneObject`、配置值、`PipelineTopology`/`PipelineFeaturePolicy` 值策略 | 仅值对象；无 GPU 资源 | 调用方配置、模块候选 |
| `render3d.pipeline` | 候选代装配、代次借用／转交、帧级协调、reactive 与后处理适配 | `PipelineGeneration` 的 owner 集合与转交记录 | 模块候选、`RenderFrameContext` |
| `render3d.scene` | 帧只读视图、可见性、队列、revision、帧上下文、运动历史 | `SceneFrameBuilder` 的矩阵、bounds 与队列 arena | `Scene`、相机事实 |
| `render3d.geometry` | 普通／实例绘制、材质绑定协作、相机 uniform、变形默认值、**forward/透明/instanced 命令录制** | `CameraUniforms` UBO、`SceneDeformationDefaults`、`SceneRenderer` | `SceneFrame`、材质、`Host` 协作输入 |
| `render3d.surface` | 共享深度／法线／运动／reactive 布局与生产、表面租约 | 表面／resolve 程序 | 消费者请求、图附件 |
| `render3d.lighting` | 帧灯表、clustered 存储与 assignment、绑定、光照诊断、**逐帧光照绑定** | cluster SSBO、计数器、绑定状态、`FrameLightBinder` | `SceneLightEntry` 快照、阴影槽位计划 |
| `render3d.shadow` | 调度、图集、缓存、caster 规划、采样块、程序生命周期和阴影命令录制 | 图集分配器、采样 UBO、`ShadowPrograms` | 灯表快照、`SceneFrame`、caster 计划 |
| `render3d.ao` | GTAO 程序、历史、专属深度兼容路径 | GTAO shader、双缓冲历史 | 共享表面或专属深度 |
| `render3d.volumetric` | 体积雾资源、历史、介质／注光、合成与只读输出 | 3D 纹理、历史、程序 | 表面输入、光照只读合同 |
| `render3d.environment` | 室外天空装配 | `ScreenQuad`、天空程序 | 环境设置 |
| `render3d.pbr` / `gltf` / `preview` / `vfx` | 既有扩展包：IBL/PBR 资源、glTF 运行时、图预览、GPU VFX | 各自持有 | 各自公开合同 |
| `postprocess` | 颜色链合同与装配、颜色链顺序、TAA 事务边界 | `PostProcessPipeline`（效果 owner 集合） | `SurfaceInputs`、`LateSurfaceProducer`、`TemporalFramePose` |
| `postprocess.bloom` / `exposure` / `tonemapping` / `color` / `temporal` / `fxaa` / `fog` | 单个效果的程序、历史与 Pass 声明 | 各自程序、LUT、TAA 历史、1×1 曝光历史 | 颜色链输入、颜色链提供的帧位姿 |

后处理效果 owner 只在对应子包内创建；颜色链只负责顺序和帧事务，不再持有
Bloom 层级、Bloom 阈值、TAA 历史或其他效果的内部状态。

## 2. 依赖方向

```text
调用方 ──► render3d（RenderPipeline / Scene / 配置）
             │
             ├──► render3d.pipeline ──► 各功能子包
             ├──► render3d.scene / geometry / surface / shadow / lighting
             │        / ao / volumetric / environment / pbr / gltf / preview / vfx
             │                 │
             │                 └──► render3d 根包值类型（Camera、SceneFrame 等稳定值）
             │
             └──► postprocess 合同（PostProcessPipeline、SurfaceInputs、
                          LateSurfaceProducer、TemporalFramePose、TaaInvalidationReason、ScreenQuad）

postprocess ──✗──► render3d（门禁禁止；由 pipeline 适配器注入）
功能子包   ──✗──► render3d.pipeline（门禁禁止；子包不得依赖装配实现）
```

- `pipeline` 组合各功能；功能子包不引用 `RenderPipeline`、`PipelineGeneration` 或
  `ForwardPassBuilder`。
- 子包可以依赖根包中的稳定值类型（`Camera`、`SceneLightEntry`、`PipelineTopology`、
  配置 record 等）；根包仍可作为公共入口被装配层依赖。
- `render3d` 单向使用 `postprocess` 的合同类型；`postprocess` 不导入任何
  `render3d` 类型（含全限定名与静态导入）。门禁见
  `ArchitectureBoundaryTest.postProcessDoesNotDependOnRender3d`。
- `surface` 提供通道事实；AO、体积雾、后处理消费它，`surface` 不依赖这些效果的
  实现类。reactive 与后处理之间的别名适配位于 `render3d.pipeline`，因为它是装配职责。
- `FrameLightTable` 是跨模块帧值（根包），`shadow` 只接收该快照；`lighting` 单向
  消费 `shadow` 的槽位计划与采样块，不再形成 lighting↔shadow 循环。唯一的双向
  包引用是 `scene` ↔ `geometry`（不可变快照与绘制值），见第 6 节。
- `postprocess` 内部：根包合同 ← 各效果子包；效果子包不互相依赖，`fog`→`temporal`
  只为读取帧位姿，`tonemapping`→`color` 只为 LUT。

## 3. 帧、线程与失败合同

- **GPU owner 线程**：`RenderPipeline` 的构造、`build()`、`execute()`、`resize()`、
  `close()` 与所有模块 GL 资源创建／销毁都在同一 GPU owner 线程与 current context
  内执行；`requireGpuOwner` / `requireOwnerContext` 在入口校验。本版本没有新增常驻
  线程，也没有引入全局 `glFinish` 或任意线程 GL 操作。
- **候选准备**：模块先创建候选（程序、历史、目标），`graph.compile()` 后由
  `SceneSurfaceInputs.validate()`、`PostProcessPipeline.validateSurfaceInputs()`、
  GTAO／体积雾输入校验检查附件、依赖边和租约，最后 `activateGeneration` 原子发布。
  失败保留旧代，候选资源按 `closeCollecting` 顺序回收。
- **图拥有附件**：`RenderGraph` 拥有所有附件；`surface`/`shadow`/`lighting`/`volumetric`
  只借用 storage 并贡献 Pass 声明。外部导入（宿主颜色／深度、TAA history）用
  `ExternalAttachment.borrowedColor` 显式声明借用。
- **帧边界发布**：TAA 历史、自动曝光 1×1 历史、GTAO/体积雾历史只在
  `frameSucceeded` 后交换读写槽；`frameFailed` 保留上一成功状态。部分 GPU 写入不
  被解释为像素回滚。候选发布前失败保留旧代，发布后 fence 退役失败保留可重试的
  旧 owner。
- **resize**：`PipelineGeneration.prepareResize` 同时准备图、TAA、GTAO、clustered、
  volumetric 候选；提交只交换已分配句柄，失败关闭全部候选。块尺寸或样本数变化会
  重建受影响的 target 组，不复活旧帧输入。
- **诊断**：`Render3dDiagnostics`、`ClusteredLightingDiagnostics`、体积雾诊断来自
  实际生产帧，区分当前／复用／过期数据；关闭或失败不伪报新 GPU 测量。

## 4. 资源所有权

| owner | 资源 | 释放点 |
|---|---|---|
| `RenderGraph` | 全部 Pass 附件、外部导入、resize 候选 | 代次关闭 |
| `PipelineGeneration` | owner 集合、借用集合、转交记录、fence 退役 | `close()`/`retire()` |
| `postprocess.PostProcessPipeline` | 效果 owner 集合与帧事务；不拥有图附件 | `close()`（转移后仅新 owner 释放） |
| `postprocess.temporal.TemporalChain` | `TaaHistory` 双缓冲、resolve 程序 | `close()` |
| `postprocess.exposure.AutoExposureChain` | 1×1 曝光历史、归约程序 | `close()` |
| `postprocess.bloom/tonemapping/fog/fxaa` | 各自程序、LUT、`ScreenQuad` | 各自 `close()` |
| `shadow.ShadowPrograms` | 普通、MASK 和按需实例阴影程序，供方向光、点光和聚光 Pass 共享 | 部分创建失败时回收已建程序，完整 owner 随候选关闭或 fence 退役 |
| `shadow.ShadowSamplingBlock` | 阴影采样 UBO | 候选关闭或 fence 退役 |
| `lighting` | cluster SSBO、计数器、绑定器 | `ClusteredLightingResources.close()` |
| `surface` | 表面／resolve 程序与租约 | 代次关闭；Graph 释放附件 |
| `ao` | GTAO 程序与历史 | `GtaoPasses.close()` |
| `volumetric` | 3D 纹理、历史、程序 | `VolumetricPassBuilder.close()` |
| `environment`/`pbr` | 天空程序、IBL 环境 | 各自 owner |

借用规则：借用者不销毁；`PipelineGeneration.borrow` 记录借用集合，关闭时跳过
`borrowed` 成员；`adoptBorrowedResources` 在候选发布时把借用转为新代所有权，同时
从 donor 扣减转交的表面存储。后处理逐效果判断兼容性，候选失败只关闭自己创建的
效果，发布时由新代接管借用的效果。Bloom 开关和层数变化保留兼容的 TAA 历史存储
及内容；世界或上游光照发生变化时单独失效历史内容。
环境替换按 IBL 身份更新 PBR 绑定，沿用其他兼容的 owner。转交时从旧代的保留估算
扣除兼容的 GTAO 存储和雾存储。GTAO 时间模式变化时，公共图附件与重新分配的历史
存储分别计账。
阴影候选由 `ShadowPrograms.prepare` 判断程序组兼容性。代次转交以程序组为单位，
`ShadowCasterRecorder` 借用组内程序录制。Graph 持有阴影图集附件。

## 5. 中心对象保留职责

`RenderPipeline` 可以保留：公共配置入口、`applyVisualSettings`/`applyGtao`/
`applyVolumetricFog`/`applyOutdoorEnvironment` 候选事务、整帧顺序、候选合法性与原子
发布、宿主导入、诊断读取入口、以及各模块候选的创建／借用调用。

`PipelineGeneration` 可以保留：私有 owner 字段、装配入口、借用／转交记录、resize
事务、关闭顺序和 fence 退役。跨包装配只读取所需 owner，不公开可写字段或 owner 集合。

明确**不**保留：Bloom 层级与阈值、曝光归约细节、TAA 历史存储与 resolve 参数打包、
clustered 存储布局与 assignment 细节、阴影逐灯更新细节、各效果 shader 参数打包。
这些已经位于对应效果子包（后处理）或模块包（阴影／光照／表面等）。

| 职责 | 迁移前 | 现在 |
|---|---|---|
| Bloom／曝光／TAA／FXAA／Fog 的资源与 Pass 拓扑 | `Render3D.PostProcessPassBuilder` 单类持有 | `postprocess.*` 各效果 owner + `PostProcessPipeline` 顺序 |
| TAA 历史与失效原因 | `PostProcessPassBuilder` + `render3d.TaaHistory` | `postprocess.temporal.TemporalChain` |
| 阴影命令录制（图集清除、caster、遮罩材质、instanced） | `RenderPipeline` 私有方法 | `shadow.ShadowCasterRecorder` |
| 阴影程序创建、兼容性与释放 | `PipelineGeneration` 逐程序管理 | `shadow.ShadowPrograms`，代次负责组级借用与转交 |
| 逐帧光照／阴影采样／cluster／AO 绑定 | `RenderPipeline.bindFrameState` | `lighting.FrameLightBinder` |
| forward／透明／instanced 绘制循环与材质状态跟踪 | `RenderPipeline.renderScene` | `geometry.SceneRenderer` |
| 帧灯表快照 | `lighting.FrameLightTable` | 根包值（供 scene/shadow/lighting 只读） |
| 帧快照、可见性、队列、revision | 已部分在根包 | `scene.*` |
| 候选代装配、发布、关闭、fence 退役 | `RenderPipeline`/`PipelineGeneration` | 保留（`pipeline`） |
| 整帧顺序、公开配置入口、原子发布、诊断读取 | `RenderPipeline` | 保留（根包） |

## 6. 已知残留与后续

1. **`scene` ↔ `geometry` 的帧内借用**。构建器从场景借用 renderer，几何、表面、
   GTAO 和阴影按索引读取帧视图，视图在下一次构建开始时失效。模型矩阵复制到调用方
   的复用暂存对象，`WorldBounds` 只提供坐标查询。边界写入能力 `WorldBounds.Scratch`
   由场景 arena 与实例批次各自持有。绘制对象仍按原有场景生命周期借用。
   曾经的 `lighting` ↔ `shadow` 循环已消除：`FrameLightTable` 作为跨模块帧值
   上移到根包，`shadow` 只读取根值快照，`lighting` 单向消费 `shadow` 的槽位计划
   与采样块。
2. **中心仍编排逐帧快照与计划生成**：`SceneFrame` 构建、帧灯表、cluster 网格、阴影
   调度／caster 计划／缓存准备仍在 `RenderPipeline.sceneFrame()` 中按帧编排（属于
   “帧级协调”允许保留的职责），具体布局、缓存、录制与绑定已归模块包。已移出的
   职责：后处理效果 owner、阴影程序与命令录制（`ShadowPrograms` 和
   `ShadowCasterRecorder`）、逐帧
   光照绑定（`lighting.FrameLightBinder`）、forward/透明/instanced 绘制录制
   （`geometry.SceneRenderer`）。
3. `PipelineTopology`/`PipelineFeaturePolicy` 留在根包：它们是组合值与策略，
   被多个模块作为输入读取，迁入 `pipeline` 会形成反向依赖。
