# v0.23 Render3D M1 revision 与 frame context 合同

每帧由 `SceneRevisionSnapshot` 捕获 scene generation 以及 membership、transform/model、lighting、
material/render-state、camera、topology/settings 六个 revision 域。`FrameInvalidation.between(...)`
生成无分配位掩码；只有显式 diagnostics 才把原因展开为列表。

`RenderFrameContext` 是一次 execute 的不可变输入。pass callback 从该 snapshot 读取 camera、extent、
frame index、revision 与 scene frame，不在执行途中重新读取可变 `Scene`/`Camera`。scene generation
变化使所有 scene 派生域失效；camera 或 topology 可独立失效。

合同：相同 revision 的连续帧复用 queue/矩阵/bounds 缓存；transform 只失效模型/bounds/排序，材质
revision 触发重新分类，lighting 只刷新光照/shadow，camera 只影响可见性/透明排序/CSM 矩阵，topology
变化才允许构建新 pipeline generation。失败帧不发布半完成 snapshot，下一帧可重新构建。

Transform 与 MaterialInstance 的有效变更分别推进进程级单调 mutation epoch。scene snapshot 以 O(1)
读取 epoch；跨 scene 变更最多造成一次保守 cache miss。任意非 `RevisionedModelSource` updater 仍把
frame index 混入 transform revision，不能被误判为静态。`SceneFrameBuilder` 只有在 material epoch
变化时才扫描本 scene 的 instance revision，稳定 10k scene 不再承担三次 O(N) revision 扫描。

证明入口：`RenderFrameContextTest`、`RenderPipelineTest`、`ScenePipelineTest`、
`SceneVisibilityGlTest` 和 `runRender3dV023Integration`。
