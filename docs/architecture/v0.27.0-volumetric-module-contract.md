# v0.27.0 体积雾内部模块合同

本文件是第一阶段实施合同；验收状态见 [阶段报告](../releases/v0.27.0-phase1-review.md)，不能由本合同存在推断实现完成。

## 切口与真实消费者

保留具体的包内 `VolumetricPassBuilder`，它已独占雾存储、程序、参数上传、Pass、透明变体与成功帧历史。收敛其对光照实现和装配细节的依赖，不再套一层只转发方法的 `FeatureModule`。

`RenderPipeline` 保留公共配置入口、全帧协调和装配；`PipelineGeneration` 负责候选与活动代所有权。光照、阴影、后处理继续由各自 owner 实现。新的内部输入合同只描述读取光源快照、绑定 compute/fine shader 和 shadow 输入所需能力，禁止关闭生产者或访问任意字段。生产连接点是管线装配，独立 shader/无光照测试可以明确使用无光照降级。

```text
场景快照 → 光照 binder → 只读帧表 / compute+fine 绑定
阴影帧计划 + Graph atlas → shadow 绑定
场景表面 + geometry → depth/color（样本数、格式、尺寸、坐标）
                    ↓
               体积雾内部 owner
  medium → lighting → temporal → integrate → surface guide
                    ↓
            opaque composite → transparency/VFX → reactive
                    ↓
                  TAA/HDR 后处理
```

光照生产 Pass 名称由装配方传入并在候选 compile 前验证。场景深度的 single/MSAA resolve、color producer、shared attachments 必须保留显式依赖；`borrowsExternalStorage` 只记录借用，不推导自动冲突排序。

## 请求与事务

同步入口必须位于创建资源的渲染 owner thread，持有同一当前 GL Context，且处于帧边界。无后台 CPU 工作时不强行异步；因此同步返回表示已生效，不存在请求队列或尚未投递的结果。任何未来跨线程入口需单独提供有界队列、每请求结果、序号与世界代次，不能直接把同步 `HaikalatRuntime.execute` 当作投递。

参数分类：

| 变化 | 行为 |
|---|---|
| 密度、颜色、风、history 权重等数值 | 保留 graph/私有存储；下一帧参数更新；必要历史按实际依赖失效 |
| enabled、quality、emission shape | 完整雾候选 + 新 graph 计划；复用不受影响 owner；成功后发布 |
| resize | 保留跨 graph/TAA/GTAO/cluster/雾事务；不混用新旧尺寸 |
| 世界/场景替换、环境或其他拓扑变化 | 以实际 owner 兼容性选择范围，禁止跨世界帧引用 |
| close | 拒绝后续 GPU 操作；正确线程/context 清理；重复合法关闭安全 |

候选借用资源只在准备期间借用旧代，失败清理只释放候选独占对象。所有权转交必须在可执行计划 compile/输入验证成功之后、发布与旧代退役之前完成。转交后旧代不再释放这些对象；无引用计数全局服务。

Graph 附件仅当名字、完整 descriptor 和共享源的实际对象身份兼容时复用；共享源改变就必须重建借用 framebuffer。兼容判断不依赖“名字相同”或“尺寸相同”单一条件。候选不能执行、resize 或修改 donor。全部转交先验证，再进行不可失败的所有权移动。

后处理的 GPU 存储可以复用，装配参数在候选私有记录中准备，不能修改活动 Pass 回调捕获的状态。发布后因雾颜色改变失效 TAA 像素，但不重建 TAA 存储。光照/阴影 owner 保持身份；shadow cache 若随 graph 重建失效需有明确原因。

## 失败语义

| 边界 | 结果 |
|---|---|
| CPU 校验/预算/GPU 分配/Shader/Graph 编译失败 | 旧设置、旧代和旧像素保持可用；候选资源余额归零；保留原始 cause |
| 记录阶段失败，未执行命令 | 不发布成功历史；丢弃暂存 |
| 设备已执行部分/全部命令后失败 | 不声称像素回滚；失效受影响历史，下一帧恢复 |
| 发布后旧代清理失败 | 新代仍为活动状态；不得恢复旧设置；记录独立清理失败 |
| 错误 thread/context | 在第一次 GL 操作及所有权修改之前拒绝 |

已提交 GPU 工作的旧代使用 fence 退役；帧边界非阻塞回收已完成项，队列上限为 4，达到上限或关闭/resize 时仅等待相关 fence（每项上限 5 秒），不调用全局 `glFinish`。超时保留 owner 供后续合法关闭重试，关闭开始后拒绝新请求。候选峰值预算包含活动、候选和尚未释放的旧雾；停用不保留雾缓存。Graph 和宿主借用附件只有各自 owner 可释放。

零局部光源是输入合同的一部分：光照生产者跳过 cluster assignment，此时 header 内容没有有效性保证，消费者必须先检查 light table 的局部光源数量。循环测试暴露旧雾 Shader 违反此约束并造成 GPU 超时；本次增加零数量保护，保留有光源时的算法。光照/Camera owner 跨雾代复用后，其绑定能力缓存以 ShaderProgram 对象身份为键，不能按可回收的 GL program ID 复用旧结论。

`RenderPipeline.volumetricAllocationDiagnostics()` 是 advanced CPU 诊断入口，只能在 owner 线程查询，无 GL 调用或 fence 等待；关闭后仍可查询零余额。`activePrivateBytes` 为雾私有存储估算，`activeColorUpperBoundBytes` 为图附件保守上界，`retiringUpperBoundBytes/retiringGenerations` 为待退役余额，`lastCandidatePeakBytes` 为最近成功 CPU 预算准备（或成功 resize）的峰值，GPU 候选失败不会抹去已准备的估算；CPU 预算自身失败时仍保留上一次值，异常提供被拒绝的 active/peak。兼容附件可能复用，因此峰值不是实际分配之和，更不是驱动实测显存；关闭后的历史峰值保留。

`lastRender3dDiagnostics().invalidationReasons` 在成功帧中附加实际 TAA 失效原因：`TAA_FIRST_FRAME`、`TAA_VOLUMETRIC_SETTINGS`、`TAA_VOLUMETRIC_TOPOLOGY`、`TAA_RESIZE`、`TAA_EXPLICIT_RESET`。原因在成功提交后发布；失败不会消费待发布原因，下一稳定帧不重复旧原因。无 TAA 时不报告这些标签。雾自身的拒绝原因仍由 `volumetricFogDiagnostics().rejectionReason` 描述。

## 后续缓存的所有权与有效性（2026-11-07）

`ClusteredLightingBinder` 仅在同一 storage、完整稳定投影/视图/网格参数以及打包光照表逐字节相等时复用 cluster 结果。缓存命中省去上传、assignment、counter reset/reduction 与新 fence；光照表、相机、尺寸或 storage 变化走原生产路径。只有整个帧成功后才提交缓存键，失败清空有效性。已完成的 counter 快照保留实际 GPU 来源帧号，不把复用值标成新一帧的测量；resize 后旧 storage 的 fence/快照不能验证新 storage。

`VolumetricResources` 独占有界 FP32 介质缓存：每列三个 `vec4`，合计 `nx*ny*48` 字节，没有跨代共享或无上限增长。SurfaceGuide 在本帧重写前几个受支持区间的 scattering 与 z 标签，未填槽置为无效；SSBO barrier 后由 opaque/透明/VFX 的 fine 查询只读借用。命中使用原 FP32 值，未命中沿用直接计算；诊断计数帧沿用直接路径。停用/关闭、候选失败与 resize 的清理归同一 Storage owner，覆盖全部十五个纹理/缓冲分配故障位置。

该缓存新增 SSBO binding 15；生产反射与绘制测试、绑定清单共同覆盖 PBR/VFX、single/MSAA composite 和 SurfaceGuide，HostGlState 按设备实际 indexed storage binding 数量保存/恢复该槽。资源模型也计入缓存：BALANCED 4K 的保守私有存储加参数为 126,295,568 字节，加原生颜色/reactive 后为 200,945,168 字节，两代峰值 401,890,336 字节，继续遵守原预算。均为按格式/尺寸核算的估算，不是驱动显存测量。

## Shader 与输出合同

compute 使用 VolumeParameters UBO 与 light table/cluster、hint/volume/diagnostic SSBO；fine fragment 由现有 `VolumetricFogView` 改写符号和绑定。具体绑定保持原算法，新增验证必须包含真实 shader 反射/运行，而非只验证源码字符串。fine fragment 共享 shadow sampler/UBO，light table 使用独立绑定；透明与 VFX 停用时使用原无雾路径。

`VolumetricFogView` 是帧内借用，带 generation/frame identity，过期绑定、关闭后绑定必须拒绝。散射/透射、scene color、reactive 的消费者分别为透明/VFX、后处理、TAA；Graph 只拥有自己创建的附件，雾 owner 只拥有私有 3D/storage/program。失败不提交 `VolumetricFrameState` 或 `VolumetricHistoryPlan`，resize、拓扑/设置和执行失败应保留可诊断的历史失效原因。

新增边界的验收必须穿过 `RenderPipeline.applyVolumetricFog/applyVisualSettings → execute → RenderDevice`，包括旧配置故障后继续真实绘制、无关对象身份、200 次启停及已初始化两线程/context 关闭测试。M5 必须使用实际 Minecraft 回调和借用目标，不能用此文档代替游戏证据。

## A14 变更局部性与第二模块决策

密度调整的真实链为 `FogMediumSettings.extinction → applyVolumetricFog → prepareFrame → VolumetricPassBuilder` 的 VolumeParameters offset 544 → medium Shader。规格不变时不经过 candidate/Graph 编译或光照、阴影 owner 构造；仅更新当前雾参数与依赖它的 TAA 内容有效性。16 次连续调参的真实像素、revision 和 native 创建计数由 Modularity GL 覆盖，Minecraft 也重复该入口。零局部光源策略修复只改雾 Shader 的读取条件及对应生产测试，没有修改光照分配策略；这是本次实际策略变更的局部性样本。

| 新增或跨域修改 | 必要性与实际消费者 |
|---|---|
| `VolumetricLightingInputs` | 包内只读帧表与 compute/fine 绑定能力；光照 binder 生产，雾 owner 消费，验证帧序号 |
| `VolumetricSurfaceInputs` | 包内 producer/depth 值合同；管线连接，雾验证格式、尺寸、采样和顺序 |
| `VolumetricAllocationPlan` | 包内纯 CPU 预算；创建候选和 resize 在任何候选 GL 分配前使用 |
| `VolumetricAllocationDiagnostics` | advanced 值快照；实际宿主事件记录候选峰值与待退役余额，不暴露内部 owner/native ID |
| Graph / RenderTargetManager | descriptor 与共享源身份兼容的借用、提交转交、失败清理；由真实雾候选调用，不是新的全局共享服务 |
| 后处理 / Camera / lighting binder | 复用后处理 owner 时分离装配与所有权；正确记录 TAA 失效；跨代 shader 缓存改用对象身份 |
| RenderPipeline / PipelineGeneration | 保留兼容入口、全帧协调、装配和所有权事务；没有把中心类整体搬进新管理器 |

RenderPipeline 仍直接承担多类 owner 的复用选择、装配、候选发布与退役事务，本次也增加了相应代码。体积雾边界与局部替换的改善不能证明中心对象过重的问题已全面解决；第二试点需要验证事务逻辑能否保持局部，不能机械增加更多分支并称为全面模块化完成。

第一阶段只形成体积雾试点合同。下一模块建议选择现有 GTAO：它已有私有资源、表面输入和时域提交，并与 resize/TAA 存在真实协作压力，适合检验哪些资源转交与历史诊断可共用。当前决定是**先另立 GTAO 小范围计划，再决定提炼共性**；本阶段不新增 FeatureModule、插件发现、独立版本解析或第二套调度器，也不声称所有 Subsystems 已模块化。
