# v0.20 API 与包边界清单

状态：M1 已完成，后续重构以本清单为边界合同。

本清单记录 v0.20 重构开始时 `src/main/java` 的 public 顶层类型分类和包依赖规则。
它不扩大 v0.19.4 的兼容面；新增 public 类型必须同时更新对应域的 allowlist、测试和迁移说明。

## 依赖边界

- `backend` 可以依赖 `core`，但不能依赖 `runtime` 或任何 `subsystems.*`。
- `core` 和 `runtime` 不依赖 `subsystems.*`；`core` 不反向依赖 `runtime`。
- `animation`、`resources` 和 `vfx` 保持 GL-free，不能直接引用 backend 或 OpenGL。
- `ui` 只能依赖允许的 `core`、事件和 backend 抽象，不能依赖 `render3d` 或
  `postprocess` 的具体实现。
- GPU 适配只放在 `render3d`、`postprocess` 等渲染域；跨域实现若暂时需要 public，
  必须标为 `internal`。
- 生产路径不调用 `CommandBuffer.custom()`；该入口仅保留给诊断 Demo 和合同测试。
- 异步场景/UI 加载只能在 owner/render thread 创建或销毁 GL 资源，候选失败时不得替换
  当前有效代次。

## 现有验证入口

- `PublicApiCatalog`：检查 public 顶层类型是否未分类、重复、陈旧或错域，并检查
  stable 第三方签名泄漏。
- `ArchitectureBoundaryTest`：检查域间依赖、GL-free 约束、`custom()` 生产调用和 GPU
  readback 限制。
- `UiPublicApiSurfaceTest`、`PbrPublicApiSurfaceTest`、`GltfArchitectureTest`：
  对 UI、PBR 和 glTF 的入口及包边界做专项校验。
- 各域 allowlist 与本清单必须保持同步；若类型降为 package-private，则应从 allowlist
  删除，并保留对应迁移说明。

M1 只完成清点和合同固化，不在没有迁移记录的情况下删除或改名 public API。M2 之后的
内部拆分应优先使用 package-private 组件，同时保持 facade 和 stable 入口不变。
