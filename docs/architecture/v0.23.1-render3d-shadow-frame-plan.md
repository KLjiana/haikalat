# v0.23.1 Render3D 阴影帧计划与缓存合同

本文记录 v0.23.1 多局部光阴影的正式架构边界。目标不是建立通用 `ShadowManager`，而是在既有
Forward/PBR 管线中让选择、atlas、深度绘制、采样和诊断消费同一份确定性结果。

## 单一帧计划

`Scene` 为每盏灯分配进程内单调 stable ID。`setLight(index, light)` 和
`setShadowLightHints(index, hints)` 只提升该 entry revision，不更换身份；shader index 仍只是本帧
2/8/4 灯光数组中的位置，不能作为缓存键。

`ShadowLightScheduler` 每帧最多生成一份不可变 `ShadowFramePlan`：

1. 收集可投影且位于 shader 上限内的 directional/point/spot candidate。
2. 先按 `ShadowLightHints.priority`，再按选择策略评分；完全平局以 stable ID 收口。
3. 通过 replacement threshold 保留仍有竞争力的 owner，并由 `ShadowAtlasAllocator` 复用槽位。
4. 固定预算为一盏方向光、最多两盏点光和四盏聚光；未入选项保留明确拒绝原因。
5. `ForwardPassBuilder`、深度 pass、`ShadowSamplingBlock` 和 `Render3dDiagnostics` 只读取该计划，
   不再各自扫描“第一盏阴影灯”。

point slot 独占一个 3×2 六面 block；两个 slot 组成 3×4 atlas。spot slot 使用固定 2×2 atlas。
方向光继续使用最多四级的固定 2×2 CSM atlas。布局坐标由 atlas 类型唯一生成，viewport、scissor、
sampling rect 和诊断不得复制第二套计算。

## Topology 与帧级失效

以下变化属于 topology，必须 candidate-first 创建新的 `PipelineGeneration`：

- point/spot 容量或单 tile 分辨率；
- directional cascade 数或固定 atlas 尺寸；
- 阴影光型从无到有/从有到无，以及既有 RenderGraph/target topology 输入。

新 atlas、framebuffer 或 UBO 任一步失败时，旧 generation 继续可用，candidate 已创建的资源全部逆序
释放。重复 `close()` 不得重复释放。容量为零时不创建对应 atlas；精确 legacy 1+1 配置继续使用
`pbr-forward.frag` 的旧 uniform 合同，不分配新增 sampling UBO。balanced 路径由
`GltfRuntimeLibrary.createShadowBudget()` 显式选择 `pbr-forward-shadow-budget.frag`，避免默认 shader
承担新增 UBO、分支或采样成本。

选择模式、priority、replacement threshold、filter、base/normal bias、灯光参数、caster/material/
deformation revision 和相机矩阵只使 frame plan 或 depth cache 失效，不改变 RenderGraph topology。
同宽高比 resize 只替换窗口相关 target，fixed shadow atlas 内容和身份保持。

## Depth 内容缓存

`ShadowCacheKey` 显式记录 scene generation、stable light ID/revision、caster membership、
transform/model、material、deformation、camera/cascade 和 settings。比较结果只产生一种首要 miss reason：
`NEW_ALLOCATION`、`LIGHT`、`CASTER_MEMBERSHIP`、`TRANSFORM_MODEL`、`MATERIAL`、`DEFORMATION`、
`CAMERA_CASCADE`、`SETTINGS` 或 `GENERATION`。

- point 以六面 block 为失效单位，dirty 时只清理并重画该 slot 的六个 face。
- spot 以 tile 为失效单位。
- directional 以 cascade tile 为失效单位；world-texel snapping 同时量化 light-space X/Y/Z，
  子 texel 相机移动可精确复用矩阵与 depth。
- generation 首帧全清；后续只对 dirty tile 启用 scissor clear。绘制成功后才提交新 key。
- `castShadows=false` 与 BLEND 不进入 caster key；MASK 的材质/UV/cutoff 和 skin/morph deformation
  会使相关 slot 失效。
- 非 revisioned model updater 保守地每帧失效。glTF instance 暴露事务式 model revision，使冻结的
  skin/morph 内容可以命中缓存，实际姿态更新仍使所有受影响的投影失效。

静态 balanced 帧应报告 `tilesRendered=0`、`tilesReused=20`。移动一盏 point 只重画 6 face，
移动一盏 spot 只重画 1 tile；相机移动只重画四个 directional cascade。

## Shader 数据与质量

高级路径使用 binding 5、`std140` 大小 1,392 bytes 的 `ShadowSamplingBlock`：两组 point metadata、
12 个 point matrix/rect、四组 spot metadata/matrix/rect，以及 filter radius、normal bias 和两类
base bias。Java offset、GL 反射大小与 GLSL 容量由 JVM/真实 GL 测试共同锁定；同一签名不重复打包上传。

`HARD`、`PCF_3X3`、`PCF_5X5` 的 kernel radius 分别为 0/1/2。directional、point face 与 spot tile
均使用 `radius + 0.5` atlas texel 的 guard，并逐 tap clamp 到当前 tile；任何档位都不能采到相邻槽。
base bias 沿用 `LocalShadowSettings.bias()`，共享 slope 公式；normal bias 是沿世界空间接收面法线的
偏移，默认 legacy 为 0，balanced 为 0.002 world units。质量设置不能通过放大 bias 掩盖矩阵或 atlas
边界错误。

## 可观察性与验证

`Render3dDiagnostics.ShadowSummary` 保持有界，只记录 candidate/selected/capacity、stable ID、shader
index、slot、priority/score、拒绝原因、tile rendered/reused、cache hit/miss/miss reason、filter、
atlas 尺寸和估算 depth bytes，不保存对象列表或逐帧打印。

核心证据入口：

```powershell
.\gradlew.bat test --tests "*ShadowLightSchedulerTest" --tests "*ScenePipelineTest"
.\gradlew.bat glSmoke --tests "*LocalShadowsGlTest" --rerun-tasks
.\gradlew.bat runRender3dShadowBudgetIntegration --rerun-tasks
```

窗口化人工入口为 `runRender3dShadowBudgetDemo`。它固定展示 1 directional + 2 point + 4 spot、预算
拒绝、MASK、skin/morph caster、局部灯/相机/变形失效、resize 和最终完全缓存复用。
