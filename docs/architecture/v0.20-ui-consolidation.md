# v0.20 UI 内部收敛

状态：M2、M3 与 M7 已完成；公共 UI facade 与 v0.19.4 保持兼容。

## 职责结构

```text
UiSystem
├─ UiUpdateCoordinator       viewport、input、IME 顺序
├─ UiSnapshotPublisher       snapshot 序号、发布和 exchange 生命周期
├─ UiAttachmentController    RenderGraph 校验、挂接和 compositor 选择
└─ UiDiagnostics             update/render 线程统计合并

UiNode
├─ UiTreeLinks               parent、children、稳定顺序、cycle 和 document 归属
├─ UiDirtyState              dirty flag 存储
└─ UiEventRegistry           capture/bubble listener 与 dispatch snapshot

UiDisplayList
└─ UiDisplayListValidator    freeze、栈平衡、资源和索引合同

UiRenderer
├─ UiSdfRenderer             SDF uniform 编码与复用 scratch
└─ UiRenderResourceOwner     shader、sampler、ring、atlas 与逆序 close

UiCompositor
└─ UiCompositorPlan          layer 拓扑、预算、pass 名称与预校验
```

`UiSystem` 仍是公共生命周期入口；`UiNode` 和 `UiDisplayList` 的 public 方法没有删除或改名。
新增组件全部为 package-private，因此不扩大 allowlist 或兼容面。

## 实施决策

- `UiSnapshotExchange` 的 slot-owned `UiDisplayList` 继续作为 snapshot arena。现有实现已经避免
  acquire 中的槽被 producer 覆盖，无需再套一层等价的 public arena 类型。
- `UiDisplayList` 继续使用结构化数组作为 primitive command store。将数组机械搬到另一个对象
  会增加一次间接访问，却不会改善生命周期，因此 M2 只抽出集中验证策略。
- 输入统计保存在 `UiUpdateCoordinator` 的可复用标量字段中；每帧 route 不创建结果对象。
- child 的公开快照只在树变更时重建。关闭子树会清空当前快照，但已返回的旧快照仍保持不可变。
- RenderGraph topology 的校验与 seal 顺序集中在 `UiAttachmentController`，overlay callback 和
  pass 名称保持不变。
- `UiSdfRenderer` 复用 render-thread vector scratch；普通 quad 路径不会构造 SDF 参数对象。
- `UiCompositorPlan` 在修改 RenderGraph 前完成 layer tree、预算和 pass 名称验证；
  `UiRenderResourceOwner` 采用 candidate-first 初始化，失败时逆序清理部分资源。

## 静态热路径

- `UiSystem.update()` 只在首帧、可见 paint dirty、glyph upload 完成、活动 effect 或
  effect 结束清场时重新 paint 和发布 snapshot。
- 没有变化时 renderer 继续持有上一张 immutable lease；统计使用缓存标量，不为
  “没有更新”构造诊断结果或空 effect 集合。
- snapshot 发布失败会重新标记根节点 paint dirty，下一帧重试，不会把失败候选当作
  当前有效画面。
- `UiInputRouter` 缓存 hit target、cursor、focus 和 inside 状态；只有输入位置/焦点变化
  或树上存在 `HIT_TEST` dirty 时才重建命中结果。
- `ListView.refreshViewport()` 在 materialized range 与 item height 都不变时直接返回，
  不复制列表、不重新挂接 cell，也不传播无意义 dirty。

五轮静态 UI 容量基准中，十个测量窗口的 snapshot publication、layout、shape、paint
和 atlas upload 均为零；draw 数与既有语义一致。10,000 quad 仍约
`255 KiB/frame`，证据显示它位于 render/GL submission 一侧，作为后续预算保留。
完整口径见 `docs/performance/v0.20-m7-2026-07-28.md`。

## 生命周期与线程

- update、树、input、layout 和 snapshot publication 仍由 `UiSystem` 创建线程约束。
- render pass 只通过 lease 消费不可变 `UiRenderSnapshot`，不会回读可变 `UiNode`。
- `UiSystem.close()` 先关闭 snapshot publisher，再释放 render lease/GPU owner，随后停用 IME 并
  逆序关闭 CPU 组件；重复 close 仍幂等。
- resource owner 的 candidate 只有全部创建成功后才成为 active；package-private 拆分没有新增
  跨 context 创建或销毁路径。
