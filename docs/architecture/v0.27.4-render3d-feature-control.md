# 0.27.4 Render3D 统一功能控制合同

记录日期：2026-11-09，对应 v0.27.4 候选。本文补充
[0.27.3 模块边界合同](v0.27.3-render3d-module-contracts.md)，只描述新增的控制面、
开关映射、依赖校验和暂停／恢复生命周期。

## 1. 控制对象

`RenderPipeline.features()` 返回 `RenderFeaturesControl`。控制器不持有 GL 资源、
不构造 Pass、不决定借用关系，只保存：

- `requested`／`requestedRevision`：最近一次完整 `RenderFeatureSettings` 快照；
- `effective`／`effectiveRevision`：最后一个成功发布的快照；
- `status`：`PENDING`、`PREPARING`、`APPLIED` 或 `FAILED`；
- `failureReason`：静态校验或候选准备失败原因；
- `activities`：每个 `RenderFeature` 是否参与输出及原因。

控制器在 GPU owner 线程接收 `submit`。请求在下一帧 `executeFrame` 入口处理；
暂停期间只保留快照，不分配候选。旧 `apply*` 入口仍同步工作，成功后刷新控制器
观察值（`requested == effective`，revision 递增）。失败语义以发布边界区分：

- 校验或候选准备失败：保留旧活动代与 effective，状态为 `FAILED`；后续普通帧不隐式重试，也不清除失败，只有新提交才重新进入 `PENDING`。
- 候选已发布后的旧代退役失败：保留新活动代与已发布的 effective/revision，统一请求保持 `APPLIED`；退役异常通过 `retirement-after-publication` 诊断暴露，不能回滚配置冒充旧图仍在使用。

实现和故障注入回归见[复审修复记录](../releases/v0.27.4-review-fixes-2026-11-09.md)。

## 2. 快照与开关映射

| 字段 | 来源 | 消费者／所有者 |
|---|---|---|
| `enabled` | 新增 | `executeFrame` 暂停门；不改变子字段 |
| `directLighting` | 新增 | `FrameLightBinder` 覆盖 PBR shader `uEnableDirect` |
| `imageBasedLighting` | 新增 | `FrameLightBinder` 覆盖 `uEnableDiffuseIbl`／`uEnableSpecularIbl`；`PbrEnvironment` 仍由调用方所有 |
| `directionalShadows`／`pointShadows`／`spotShadows` | 新增 | `PipelineTopology.capture` 与场景投影灯、容量共同求有效阴影；`ShadowPrograms`／图集 owner |
| `render` | `RenderSettings` | AA、Tone mapping、Bloom、曝光；`PostProcessPipeline` |
| `postProcess.gtao` | `GtaoSettings` | `GtaoPasses`／history owner |
| `volumetricFog` | `VolumetricFogSettings` | `VolumetricPassBuilder`／`VolumetricResources` |
| `outdoorEnvironment` | `OutdoorEnvironmentSettings` | 天空绘制；不改变 IBL |
| `postProcess.fog`／`colorGrading` | `PostProcessSettings` | `FogChain`／`ColorGradingLut` |
| `hdrVfx` | 新增 | `PostProcessPipeline` 的 VFX recorder 注入；recorder 属于调用方 |
| `preview` | 新增 | `PipelineGeneration.finishAssembly` 的 `GraphPreviewRenderer` 创建与帧回调 |
| 阴影／聚簇配置 | `DirectionalShadowMap`、`DirectionalCascadeSettings`、`LocalShadowPipelineSettings`、`ClusteredLightingSettings` | 随快照进入候选；不再只允许 build 前设置 |

不存在“postprocess 假字段”：后处理子树由上述现有配置字段表达，各效果仍可独立
关闭；AO、体积雾和天空由各自现有 `enabled` 字段表达，不复制第二套布尔。

## 3. 依赖与互斥

`RenderFeaturePolicy` 是唯一纯策略边界，在候选分配前执行：

- HDR：调色、解析雾、体积雾、Bloom、HDR VFX 和 PBR 材质继续要求
  `ToneMappingMode != NONE`；PBR 材质还必须有借用的 `PbrEnvironment`。
- GTAO：要求至少一个 `MaterialModel.METALLIC_ROUGHNESS` 消费者。
- 雾：解析雾与体积雾互斥，整份请求拒绝。
- VFX：体积雾开启且配置了非 fog-aware 的自定义 recorder 时，必须显式
  `hdrVfxFogOptOut(true)`，否则整份请求拒绝。
- 阴影：请求 + 场景投影灯 + 容量共同决定有效类型；无灯或零容量报告
  `NO_ELIGIBLE_LIGHT`，不分配空图集，也不使整份请求失败。
- IBL：无 PBR 消费者报告 `NO_PBR_MATERIAL`，无借用环境报告 `NO_ENVIRONMENT`；
  但 PBR 场景缺环境是校验失败（既有合同）。
- 直接光关闭不改变体积雾／阴影的光照输入；体积雾作为光照消费者时仍读取灯表，
  该语义由本文件固定，不由管线猜测。

## 4. 暂停与恢复

- `enabled=false` 在 `executeFrame` 的目标可渲染检查之后、resize／host import／
  绘制之前返回 `PresentationResult.SKIPPED_PAUSED`；不绑定、清除或释放宿主附件。
- 暂停保留活动代、子配置、requested／effective revision 和所有资源；不会触发
  `createGeneration` 或退役。
- 暂停期间的子配置请求保持 `PENDING`，直到恢复请求（`enabled=true`）在同一帧
  边界一次性应用；发布前失败时仍暂停并保留旧 effective；发布后退役异常遵循上一节的已发布状态规则。
- 恢复前调用现有 `resetTemporalHistory()`：TAA、GTAO、体积雾及场景／实例历史
  全部失效，不从暂停前历史继续累积。
- `close()` 是唯一销毁路径；暂停不释放资源，关闭后不允许隐式恢复。

## 5. 所有权

| 资源 | 所有者 | 开关作用 |
|---|---|---|
| PBR material binder／environment background | generation（借用环境） | IBL 只覆盖 uniform；不关闭借用对象 |
| ShadowPrograms、方向／点／聚光图集 | shadow owner | 关闭类型时不创建／不使用对应 Pass；最终随代关闭 |
| GTAO passes／history | `GtaoPasses` | 关闭时移除 AO Pass，共享 surface 仍按 TAA／雾消费者保留 |
| Volumetric passes／history | `VolumetricPassBuilder`／`VolumetricResources` | 关闭时移除雾 owner；其他消费者共享附件保留 |
| PostProcess owners | `PostProcessPipeline` 各效果链 | 逐效果移除 Pass，未变 owner 复用 |
| HDR VFX recorder | 调用方 | 开关只控制调用；不释放 recorder |
| Preview renderer | generation | 关闭时不创建 renderer／不执行帧回调；生产图附件不变 |
| `RenderFeaturesControl` | `RenderPipeline` | 无 GPU 资源 |

## 6. 共享表面

`PipelineTopology.sceneSurface` 仍按活跃消费者求并集：

- GTAO 请求 depth／normal（及 temporal 时的额外通道）；
- 解析雾／体积雾请求 fog view；
- TAA 请求 history／velocity（reactive 只在真实 producer 存在时）；
- MSAA + 雾继续经过 `DepthResolveDescriptor`。

关闭某一消费者只重算需求并移除其专属 Pass；其他消费者仍请求的附件不会因该
消费者关闭而释放。批量切换后由同一候选代发布新 topology，避免逐字段中间态。

## 7. 公共 API 分类

新增 `RenderFeature`、`RenderFeatureActivity`、`RenderFeatureReason`、
`RenderFeatureSettings`、`RenderFeatureState`、`RenderFeatureStatus`、
`RenderFeaturesControl` 分类为 **advanced**（与 `RenderPipeline` 同级），
`RenderFeaturePolicy` 保持包内 internal。它们不暴露 GL 句柄、Pass builder 或
模块私有 owner；旧 `apply*` 签名不变，作为兼容入口继续刷新同一状态。

## 8. 0.28 战斗 VFX 与动态光照扩展

0.28 不新增 UV 速度、溶解阈值或轮廓颜色等逐参数全局开关；受控视觉仍由
`RenderFeatureSettings.hdrVfx()` 统一门控。扩展语义：

- `RenderPipeline.vfxLights(List<VfxLight>)` 提交完整不可变特效灯输入，
  `maxVfxLights(int)` 设置每帧上限。输入在 `RenderFrameContext.capture` 前与
  Scene 灯合并；视觉 recorder 与 Clustered/PBR 光照消费同一冻结帧。
- `hdrVfx=false` 时受控视觉与关联特效灯同时不参与，`VfxLightDiagnostics.reason`
  为 `hdr-vfx-disabled`；`directLighting=false` 时灯仍在输入诊断中，reason 为
  `direct-lighting-disabled`，但不贡献表面光照。容量裁减为 `capacity-culled`，
  无活动灯为 `no-active-light`。
- 特效灯不改变 `RenderFeatureSettings` 的拓扑或阴影请求；固定无阴影点光，
  `LightVolumeHints.DISABLED`。位置/颜色/强度/范围/生灭变化不重建 RenderGraph，
  不无条件清空 TAA/体积历史，也不使静态阴影缓存失效。
- 特效灯 stable ID 与 Scene 灯共用 `LightIdAllocator`，因此不会冲突；用户 Scene
  灯不会被增删。场景自身超过 `maxLocalLights` 仍由 `FrameLightTable` 明确失败。
- `Render3dDiagnostics` 新增 `vfxLights` 组件；旧构造入口保留并填入
  `VfxLightDiagnostics.UNAVAILABLE`。诊断只保留 requested/selected/culled/
  capacity/reason/inputRevision，不保留逐帧灯列表。
- 新 public 类型 `VfxRimLight`、`VfxUvFlow`、`VfxDissolve`、`EffectLight`、
  `VfxLight`、`VfxLightDiagnostics` 均为 advanced；`LightIdAllocator` 与
  `VfxLightBridge` 保持包内 internal。
