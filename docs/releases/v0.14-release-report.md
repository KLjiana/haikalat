# v0.14 发布验收报告

状态：`0.14.0` 已发布
日期：2026-07-19
环境：Windows，Java 21，LWJGL 3.3.3，OpenGL 4.6

## 收口结果

- 正式模型路径只保留 OBJ 与静态 glTF 2.0；Assimp Java 入口、module 与 native 已删除。
- 262 个 public 顶层类型全部分类：stable 34、advanced 189、internal 39。
- glTF loader 拆为 document/URI/buffer/accessor/material/node/mesh 阶段；公开 facade 未改变。
- Scene 配置拆为语法 parser、值转换和单次引用 validator，两种语法保持等价。
- glTF owner 使用包内逆序回滚，RenderGraph 使用不可变 compiled topology plan。
- CommandBuffer 已有 primitive SoA `CommandStream`、`CommandExecutor` 和 pending state，审计后保留，
  没有为满足类名清单重复引入 encoder/arena 包装。
- runtime dependency report 不含 Assimp；全部 main/demo resources 具有八字段记录和 SHA-256 门禁。
- 静态 UI 不再逐帧解析整棵样式树或创建逐节点 bounds/children 临时对象；10,000 quads 三轮均为
  254.5 KiB/frame，2,000 glyphs 中位低于 5 KiB/frame。

## 既有实现审查

上一个实现中可以保留的方向包括：删除 Assimp 入口和依赖、启用 dependency locking、把 glTF 与
Scene 配置拆向包内阶段、复用小型 `CloseStack`，以及建立 quick/local 两级验证任务。以下部分经过
修正或补完：

- 单一全项目 allowlist 无法表达域边界，改为 backend/core/runtime/render3d/postprocess/ui/windowing
  七域清单，并加入完整性、重复、错域、第三方签名泄漏和 stable migration 守卫；
- glTF/Scene 拆分原先只移动了部分代码，现已让 facade 只负责编排，错误 phase/location、sparse、
  selected-scene 与两种 scene 语法均由回归测试锁定；
- `localReleaseVerification` 原先只是粗粒度依赖集合，现按共享 GLFW/OpenGL context 风险串行覆盖
  headless、真实 GL、resize、PBR、glTF、UI、IME 与 native soak；
- CommandBuffer 已经具备 typed SoA stream、executor 和 pending state，不再为了路线图类名制造一层
  空包装；RenderGraph 则补上确实缺失的 package-private compiler 与不可变 compiled plan；
- 初始 UI 路径仍约 600 KiB/frame，不符合路线图门槛，修复静态样式遍历和临时对象后才稳定降到
  254.5 KiB/frame。

## 基线与兼容判断

v0.13 已归档的 glTF decode/upload、1080p/4K PBR 和 UI/stress 数据作为重构前基线，见
`docs/performance/`。v0.14 不改变 shader、资产坐标、色彩空间或 Demo 画面合同。glTF decode 中位
仅变化 +1.4%，upload 中位变化 -6.6%；类拆分没有在 frame
loop 中增加对象化命令；RenderGraph topology 只在首次执行或 topology 变化后编译。
