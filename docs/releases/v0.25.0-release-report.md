## 资源与兼容性

仅需 depth 的 fog 共享 surface 分支不分配 normal/velocity/validity。Fog disabled 不分配卷、不注入/上传参数。
32 KiB 参数预留覆盖正式 1024+8 灯 hints；独立资源测试的 256 灯容量仍为 15 KiB。
M5 增加 R8 reactive-prefix，避免 full-resolution 每像素遍历全部 Z 层。M6 在已有 RGBA16F prefix
的 Nz+1 物理边界之外增加一层 opaque-depth guide，额外 8 bytes/column，不新增 texture owner。
Balanced 4K、含 emission 的保守自有 storage 为 104,263,568 bytes，颜色/Reactive 后单采样
178,913,168 bytes，resize 峰值 357,826,336 bytes，4× 为 377,978,768 bytes。128/192/384 MiB 等预算与性能阈值未放宽；
storage 声明不包含驱动额外开销，不能作为性能数据。8 个纹理+5 个缓冲的 13 个分配失败位置均已验证。

单采样合成使用 MRT 同时计算颜色与 opaque reactive。后续响应 pass 直接借用该 R8 附件，
透明/VFX 用 MAX 合并；不新增第二张 R8 或再次执行全屏复制。NONE/TAA 的别名、resize 和零泄漏已有真实 GL 回归。
关闭诊断时不再上传清零缓冲或执行 GPU 原子计数；有限性保护照常生效。

灯 hints、局部雾体和脏域字节未变时复用上一成功帧已上传数据，减少常驻参数更新和命令快照分配。
缓存包含实际 buffer 身份及有效字节；只在成功帧提交，失败或 resize 强制失效。参数 UBO 仍逐帧更新。
新增真实 GL 回归先执行会改写 GPU 雾体数据的部分失败帧，再恢复与旧成功帧相同的输入，并验证热修改和 resize 首次上传。

体积历史比较在相同索引处先核对 stableId，再回退到原 ID 查询；删除、排序移动与失败帧不改变比较身份。
新增回归覆盖删除首灯后的存活灯索引移动、失败值恢复和新方向灯引起的排序变化。积分、GPU storage 与 UBO 更新方式未改变。
局部比较探针约 3.05→1.87 µs，两边稳态分配均为 0；该微小收益不能替代正式性能，上一渲染候选的 1080p CPU 仍失败。
逐帧重建 UBO 存储的实验没有显示收益，已撤回；JVM 性能记录只用于归因，单独标为带 profiler 的非正式结果。

单采样 HDRVFX 的独立 soft depth copy 另计 4 bytes/pixel。4K balanced、emission+单采样 HDRVFX
超出 192 MiB 时在候选阶段明确拒绝，保留旧代次；不自动降低画质。
自定义透明 shader 必须声明 fog 合同或显式 opt-out；自定义 HDR recorder 同理。
新三维雾与旧 analytic/Outdoor 体积雾不能叠加。旧 Outdoor 当前保留作参考，advanced VolumetricLight 未删除。
