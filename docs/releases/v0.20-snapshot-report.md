## M8 发现并修复的回归

### 固定尺寸 target 被 resize 重建

首轮 `glSmoke` 在
`RenderPipelineGlTest.graphResizePreservesFixedSizeShadowTarget` 发现固定 64×64 shadow
target 的 native id 从 1 变为 2。本轮 candidate generation 原先重建了全部 managed
target，违反“resize 只重建尺寸相关资源”的既有合同。

修复后 `RenderGraph` 分别持有 fixed-size 与 window/relative-size 内部 owner：

- 固定 target 在窗口 resize 时继续存活；
- 可变 target 仍先完整创建 candidate，再原子切换并退休旧 generation；
- attachment lookup 在新 generation 激活后、旧 generation close 前刷新；
- 回归测试同时断言 fixed depth id 不变、window color id 必须变化。

针对性真实 GL 测试和完整 `glSmoke` 都已通过。

### async UI 发布数依赖计时文本偶然变化

首轮 `runUiAsyncIntegration` 得到 35 次 publication，而旧合同要求 36 次。产品逻辑没有
丢失 dirty：集成测试原先依赖三位小数的 timing label “碰巧不同”来触发每次 publication；
当相邻耗时四舍五入相同时，v0.20 的静态 snapshot 复用会正确跳过一次。

集成入口现在为每次 producer update 写入确定性递增的视觉 revision，明确制造三次真实
dirty publication。重跑结果为：

```text
12 render frames
36 published snapshots
24 dropped snapshots
898 glyphs
1 atlas page
77 draws
```

这既保留 latest-wins 压力合同，也不要求产品为静态内容发布冗余 snapshot。

instance buffer/sprite atlas/compute。v0.20 不以扩大这些能力为目标。
