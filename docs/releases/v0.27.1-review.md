## 冷启动反证与修复

- 阶段推送的白图在共享 MSAA 法线原生附件中已是 NaN；深度有限，不能通过重排 GTAO resolve 后的 Pass 或放宽误差掩盖。`prepush-gtao-accepted.log` 与 `cold-*` 记录真实失败。
- 五个变形 SSBO 的缺省未绑定是独立的接口缺陷。补齐有效默认存储后，47 项开发 GL 一度通过，18 份参考相同；但 `artifact-recheck-initial-failed/` 从 JAR 再现首帧白图（48 项，1 失败）。静态顶点试验与仅法线片元简化也各自失败并撤回，见 `static-vertex-disproven/`、`geometric-fragment-disproven/`。
- `constant-surface-probe/` 的常量法线输出跨 64 次冷启动有限，读原始法线属性仍可失败，`flat`、`centroid`、`sample` 试验均有反证。对通用属性 `(9,8,7)` 的污染控制捕获 5143 个异常覆盖像素，输出长度约 13.92，同时 VBO 中的法线为 `(0,0,1)`、GL error=0；这把故障定位到该路径使用了通用属性值。
- 只重绑 VAO、重设 layout 及查询 enable 均没有消除反证；先绑定网格 VAO 再激活程序的两个诊断执行各通过 96 次冷启动。生产修复只改变普通 SceneSurfacePass 首次绑定顺序；Shader 不改动，没有留诊断旁路。默认存储按 [OpenGL 4.6 §7.8](https://registry.khronos.org/OpenGL/specs/gl/glspec46.core.withchanges.pdf) 保留。上述诊断用于定位；最终像素与运行合同使用无覆写的生产代码复验。

主场景 `runRender3dGtaoModuleIntegration` 为隐藏 640×400、16 帧、test IBL。帧 2/4/6/8/10/12 经真实 `applyGtao` 完成停用、启用/质量、strength、temporal 和恢复；帧 4/12 移动和恢复相机。左侧 ON/OFF 有 10434 个 RGB 像素变化，右侧 opt-out 差异为零。已查看实际截图；左侧墙面条纹在从 M1 重建的同输入静止序列中也存在，属于既有画质问题。最终 JAR 静止序列与该 M1 对照的 256000 个 RGB 像素完全一致；经过切换和移动的恢复帧与静止序列差 2 像素、最大通道差 1，两个历史序列不同，不作为零容差迁移对照。M1 重建核对 1518 个 main/demo 文件，诊断驱动只补有效 SSBO，不改场景或算法；见 `m1-visual-replay-metadata/` 和 `main-pixel-comparison.json`。演示 FPS 不是性能样本。

宿主协议复用 [0.27.0 实际 Minecraft 证据](v0.27.0-current-candidate-review-2026-11-07.md#本轮实际-minecraft)。`host-protocol-reuse.json` 核对原归档 manifest SHA 及 HostGlState／FrameDriver／RenderWindow／PresentationTarget 等 5 份源码的字节身份。新鲜嵌入式 GL 覆盖受影响的借用目标和 binding；本轮未重启客户端，也没有证明 Minecraft 中 GTAO 可见、地形深度或光照统一。
