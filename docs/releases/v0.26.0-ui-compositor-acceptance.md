## 生产链路与逐项合同复核

```text
WindowInputCollector → UiSystem.update → UiDocument/layout/input/animation
  → UiPainter（节点 ID、矩阵、layer begin/end）→ 不可变 UiRenderSnapshot
  → UiLayerFrame（平衡区间与原 paint order）→ UiCompositor 准备实际尺寸/预算/缓存 key
  → UiRenderer.prepare（一次 ring 写入）→ 分段 primitive / 子层 composite
  → 两遍 Gaussian 或有效缓存 → 父层 / UiOverlay
  → 最后消费者后的 typed fence → RenderGraph submit → frame observer 发布缓存或失效
```

## 数值参考与限制

核参考在测试中独立计算 Gaussian/双线性/逐阶段量化，不调用生产 `UiBlurKernel`。奇数 97×65、radius8、downsample2/4 的透明边缘比较在线性 RGBA16F 阶段，R 绝对误差 0.001、透背景 B 0.002；基础解析 ROI 为 0.002，8-bit sRGB 来源/输出为 0.003，窗口原生编码为 0.006。容差保持首次参考值，不通过替换金图或放宽阈值修复失败。

RGBA16F 存储舍入通过单独的常量着色器测量为 nearest-even 或 toward-zero，再计入 H、V 和最终目标；该步骤只校准存储格式，不读取 blur 输出作为 golden。此前无限精度参考遗漏 per-pass 量化的失败原样保留。sRGB 来源参考显式包含 8-bit encode→quantize→decode，不把理想 0.5 当成编码纹理的精确存储值。

关键失败及修复证据仍保留于历史 UUID：`b847b195-eda7-44a5-906a-efcbfed6852c` 暴露 candidate FBO 创建污染旧 graph 绑定，随后修复构造绑定恢复与 state epoch；`269e7322-ef60-4c93-aa2d-972731c9989e` 暴露既有 VLS policy 第 38 行与旧固定计数不符，未放宽其他 GL 错误；`f428eee7-80f3-4856-bec0-53bd31ed3bd1` 为 Demo 编译失败，finalizer 输出 FAIL/NOT_RUN。失败没有被历史成功覆盖。

最终组合复核 run `7c4baee8-5665-4025-aa53-51452ce869f6` 暴露 sRGB MSAA resolve 的 read-side 解码遗漏：关闭 FRAMEBUFFER_SRGB 时，编码值被当成线性值参与滤波。修复为开启 blit 的 sRGB 转换、保持 RGBA16F 目的地线性；六种格式/采样组合沿用同一 0.003 容差，不修改参考值。该失败及修复后的最终报告在索引中分别保留。

本机 NVIDIA GeForce RTX 3050 Laptop GPU / OpenGL 4.6 / driver 576.88；Java 测试与 Demo 使用 21 toolchain，Gradle daemon Java 可能为 17，分开记录。没有正式 4K、多硬件、精确旋转/任意 mask、全层 Glow/shadow/color filter 验收。GL 日志仅沿用已有窄范围例外，VLS 的 131154 单次最终 PNG readback 不构成通用豁免。

已实际查看四例最终 PNG 和 VLS 交互截图。原生可见窗口 probe 在 `visible-20261105/probe-status.json` 记录 computer-use helper 两次初始化失败（os error 3），按工具规则停止；没有发生原生鼠标/键盘动作。因此功能完成与人工体验 `NOT_EVALUATED` 同时成立，不能把自动回放改称人工验收。
