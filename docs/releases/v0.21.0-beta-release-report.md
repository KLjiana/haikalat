# v0.21.0-beta 发布报告

> 版本：`0.21.0-beta`  
> 状态：Beta 发布 - 功能完整，已知性能回退  
> 发布日期：2026-08-06  
> 基线：v0.20.2  
> 主题：序列化游戏场景与角色内容管线

## 执行摘要

v0.21.0-beta 完成了从"渲染框架"到"内容驱动运行时"的关键演进。本版本实现了完整的场景序列化、角色动画管线、事务式热重载和 UI 诊断系统，使得游戏场景可以通过 JSON 文件定义而非硬编码。

**Beta 标记原因**：在 10,000 对象极限场景下观察到 27% CPU 性能回退。该回退源于新增的诊断收集、拓扑签名计算和 generation 管理系统。实际游戏场景（100-1000 对象）性能影响可接受。计划在 v0.22 进行专门性能优化。

## 版本定位达成

### 已完成目标 ✅

1. **场景序列化系统** - 完整实现
   - `haikalat.scene/1` 格式支持可选 `characters` 字段
   - 严格的 JSON 解析器，完整的字段、数量和引用校验
   - `player_wild` 通过 SerializedSceneDemo 加载，无需手工装配

2. **Animation Graph Sidecar** - 完整实现
   - `haikalat.animation-graph/1` 独立格式
   - `AnimationGraphParser` + `AnimationGraphDocument` + `AnimationGraphCompiler`
   - 支持参数、状态、transition、condition、loop、interruption
   - Clip 名称绑定到 `GltfSceneInstance`

3. **依赖管理与热重载** - 完整实现
   - 外部动画库、Graph、模型、texture 和 scene 全部纳入 generation
   - `SceneReloadCoordinator` 合并重复变更为一次确定性决策
   - Candidate 失败时保留 active scene/Graph/UI snapshot

4. **M4 同拓扑快速路径** - 完整实现
   - `SceneTopologySignature` 比较阴影拓扑（方向光/点光/聚光）
   - 拓扑相同时只替换 scene/lighting binding，复用 RenderGraph
   - 拓扑改变时才构建 candidate pipeline

5. **M5 UI Diagnostics** - 完整实现
   - `DiagnosticsPanel` 新增 `SCENE` 视图
   - `SerializedSceneDiagnostics`：场景 ID、generation、角色、Graph 状态数
   - `SceneCharacterRuntimeDiagnostics`：当前状态、时间、transition、active windows

6. **M7 稳定性验证** - 完整实现
   - `SerializedSceneStabilityTest`：3,600 帧 + 100 次 reload soak
   - Close 竞争和重复 close 测试
   - Handle 状态管理、资源清理、异步操作竞争覆盖

7. **Embedded 集成** - 完整实现
   - `HaikalatRuntime.createEmbedded()` 使用同一 scene plan
   - Borrowed FBO、外部相机、宿主线程契约验证

### 明确不做（按计划）

- ❌ ECS、全局 AssetRegistry、Service Locator
- ❌ GeckoLib 原始 Molang、声音、粒子
- ❌ 可视化动画编辑器、曲线编辑器
- ❌ GPU-driven scene、MDI、Hi-Z occlusion
- ❌ Motion matching、GPU animation sampling
- ❌ 第二渲染后端

### 测试环境

- **OS**: Windows 11 amd64

- **LWJGL**: 3.3.3

### 性能回退分析

**主要影响区域**：
1. **场景提交路径** - 新增拓扑签名计算
2. **诊断收集** - 每帧状态快照和序列化
3. **Generation 管理** - 依赖图追踪和失效传播

**不受影响区域**：
- ✅ 动画运行时（Graph evaluation）
- ✅ 动画约束（IK、FABRIK）
- ✅ GPU 渲染性能
- ✅ 资源上传速度

**优化路径（v0.22 计划）**：
1. 诊断收集改为按需触发，而非每帧
2. 拓扑签名计算缓存和增量更新
3. Generation tracker 使用更高效的数据结构
4. Scene reload 路径 profiling 和热点优化

## 已知问题与限制

### 性能 ⚠️

1. **极限场景性能回退**
   - 10,000 对象场景 CPU 时间增加 27%
   - 主要来自诊断收集和拓扑管理开销
   - 计划在 v0.22 专门优化

### 功能限制 ℹ️

1. **Animation Graph 表达式**
   - 不支持脚本表达式（Molang、Lua）
   - Condition 使用 typed predicate
   - 宿主逻辑需外部注入参数

2. **序列化格式**
   - 仅支持 `haikalat.scene/1` 和 `haikalat.animation-graph/1`
   - 不直接解析 GeckoLib 格式
   - 需要通过 animation library 桥接

3. **Reload 粒度**
   - Graph-only 变更已优化
   - Texture/material 单独变更仍触发 scene generation
   - 更细粒度 invalidation 留待未来优化

## 升级指南

### 从 v0.20.x 升级

**无破坏性变更**。v0.21 是纯功能增量，所有 v0.20 代码继续有效。

**新增能力**：

1. **场景序列化**（可选）
```java
// 旧方式仍然有效
Scene scene = new Scene();
scene.addObject(new SceneObject(...));

// 新方式：从文件加载
SceneAssetService service = new SceneAssetService(catalog);
SceneBuildPlan plan = service.loadPlan(sceneId).join();
```

2. **Animation Graph 文件**（可选）
```java
// 旧方式：Java Builder
AnimationGraph graph = AnimationGraph.builder()
    .addState("idle", idleClip)
    .addTransition("idle", "run", condition)
    .build();

// 新方式：从 JSON 加载
AnimationGraphDocument doc = AnimationGraphParser.parse(json);
AnimationGraph graph = AnimationGraphCompiler.compile(doc, skeleton, clips);
```

3. **UI Diagnostics**（推荐）
```java
DiagnosticsPanel panel = new DiagnosticsPanel(diagnostics, exportPath, clipboard, preview);
panel.setSceneDiagnostics(
    () -> new SerializedSceneDiagnostics(...),
    () -> new SceneCharacterRuntimeDiagnostics(...)
);
// F2 切换 SCENE 视图
```

### API 稳定性

**Public API 变更**：
- ✅ 新增：`AnimationGraphParser`、`AnimationGraphCompiler`
- ✅ 新增：`SceneAssetService.invalidateAll(...)`
- ✅ 新增：`GltfSceneInstance.attachAnimationGraph(...)`
- ✅ 新增：`RenderPipeline.replaceScene(...)`
- ⚠️ 内部：`SceneBuildPlan` 新增 `characters()` 字段
- ⚠️ 内部：`SceneDefinition` 新增可选 `characters` 列表

所有新增 API 已进入 allowlist 和 changelog。
