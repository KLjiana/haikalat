## 3. 失败与独立修复

### 3.1 已修复的既有集成缺陷（基线失败）

`OutdoorEnvironmentGlTest.uiRebindsAfterQualityAndEnvironmentChangesAndKeepsFailedCandidate`
在基线 `focusedRender3dGlTest`、`glSmoke` 与候选早期 `runRender3dVisualProfileIntegration`
中失败，位置为该用例第 211 行：`applyOutdoorEnvironment(...)` 之后的 rebind。
旧 `RenderGraph` 已退役但 `isClosed()` 尚未为真（带 fence 的延迟退役），而
`UiAttachmentController.rebind` 要求旧图已关闭。

这是 0.27.x fence 退役与 UI attachment 生命周期的既有冲突，不是包迁移引入的回归。
候选在独立修复中把 UI attachment 的 rebind 改为“允许退役中的旧图，compositor 延迟到
旧图实际关闭时释放”：

- `UiAttachmentController.rebind` 不再要求旧图 `isClosed()`，仍拒绝 executing 图；
- 旧 binding 进入 `retiring`，`pruneRetired()` 在图关闭时释放 compositor；
- `prepareAttachment` 提交同样改为延迟释放旧 compositor。

证据：`OutdoorEnvironmentGlTest` 9/9、`focusedRender3dGlTest` 40/40、
`runRender3dVisualProfileIntegration` 22/22、`uiCompositorJvmVerification` 34、
`uiCompositorGlVerification` 33 全部通过。基线在修复前确实失败，修复不改变包迁移
结论；该改动不属于 0.27.3 的机械迁移，单独列在此处。

### 3.2 任务选择差异

`glSmoke` 单独运行 `VolumetricCompositeGlTest` 时 2 个诊断用例需要
`haikalat.internal.volume.diagnostics=true`；在 `runRender3dVolumetricFogIntegration`
（专用属性）中该 suite 的 15 个用例全部通过，不是行为回归。

### 3.3 资产清单同步（独立元数据修复）

基线 `assetManifestGuard` 失败：`docs/licenses/assets.tsv` 对 0.27.2 修改过的 10 个
shader 仍保留旧哈希。已核对工作树字节与 `HEAD` blob 完全一致、且为 LF，
`git diff -- src/main/resources` 为空；即 shader 未被本候选修改，清单是既有未同步
元数据。

候选只更新这 10 行的 hash 并在说明列追加 `hash sync 0.27.3 2026-11-09`，未改
shader 字节、许可或来源字段：`gtao-estimate.frag`、`gtao-masked-depth.{frag,vert}`、
`scene-surface-resolve.frag`、`scene-surface-instanced.vert`、`scene-surface.{frag,vert}`、
`surface-guide.comp`、`volume-fine.glsl`、`volume-lighting.glsl`。同步后
`assetManifestGuard` 通过，`render3dLogicVerification` 全绿。该修复与包迁移无关，
单独列于此。
