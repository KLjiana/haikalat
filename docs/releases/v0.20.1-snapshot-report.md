# v0.20.1-SNAPSHOT 可嵌入渲染验收报告

日期：2026-07-29

状态：引擎侧实现与本地 JVM/真实 GL 验收通过；未转正式版。

## 结论

Haikalat 已具备宿主无关的显式渲染入口。Host 可以提供非零 FBO、color/depth/stencil
texture、输出尺寸、外部相机与帧时序；Haikalat 负责场景、后处理、VFX 和 UI 的渲染，
但不创建窗口/context/线程，不控制主循环，也不调用 present 或 `swapBuffers`。

`BORROWED` FBO/texture 在 graph、pipeline 和 runtime 的正常关闭与异常路径中均不被删除、
重分配或修改采样参数。目标 resize/重建只需提交新 generation；`0×0` 目标安全跳过。

## 实现范围

- `PresentationTarget`、`ExternalAttachment`、`AttachmentRole`、`PresentationResult` 和
  `ResourceOwnership`；
- `OwnedPresentationTarget` 的单 owner、同线程、幂等释放；
- RenderGraph external color/depth/stencil/presentation target 导入、replacement 与命名输出；
- `ExternalCamera` 的 defensive copy、exact projection/view/viewProjection、inverse 与 revision；
- `RenderPipeline.execute/render(RenderDevice, ExternalCamera, PresentationTarget, deltaSeconds)`；
- LDR/HDR、Bloom、tone mapping、FXAA、HDR VFX 与 UI 的显式目标输出；
- `HaikalatRuntime.createEmbedded(RenderDevice)` 的 borrowed device 与 render-thread guard；
- embedded build/resize/render/close 的宿主 GL 状态隔离；
- 原有窗口、framebuffer `0` 和 Demo 路径保持兼容。

策略；定向门禁与完整 `glSmoke` 重跑后不再出现该 API error。

## 已证明的宿主契约

1. 最终输出进入 Host 提供的非零 draw FBO，默认 framebuffer 不被覆盖；
2. Host color texture 接收真实几何、HDR 后处理和 UI 像素；
3. Host depth-stencil texture 的 depth 值真实参与几何遮挡；
4. FBO/texture/尺寸变化后，同一 runtime 和 pipeline 可接收新 target；
5. 旧、新 borrowed FBO/texture 在 close/failure 后仍由 `glIs*` 证明有效；
6. 最小化的 `0×0` 帧在 graph 录制和提交前跳过；
7. owned presentation owner 只释放一次；
8. 外部 camera 驱动 visibility、uniform、lighting/shadow/fog 和 camera-aware HDR VFX；
9. 成功与故意抛异常的 pipeline 路径都恢复宿主 GL state；
10. 静态架构门禁证明 embedded runtime/pipeline 不依赖 Minecraft、NeoForge、
    `ResourceLocation` 或 swap 调用。
