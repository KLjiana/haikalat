# v0.15 发布验收报告

状态：`0.15.0`，已验收
日期：2026-07-19  
环境：Windows、Java 21、LWJGL 3.3.3、OpenGL 4.6

## 结果

- GPU timer 保持 8-slot 非阻塞 ring，并新增 submission/result identity、pending/available/skipped/failed、
  sample age 和完整 GPU 总和语义；未知值不再显示成零。
- `FrameDriver` 拥有 OFF/BASIC/DETAILED 诊断 session、默认 240 帧有界历史、epoch、freeze、clear 和
  incomplete failure frame 恢复。
- RenderGraph 发布来自 compiled plan/descriptor 的不可变描述，并通过 typed command 为每个 pass 建立
  异常安全的 OpenGL debug group。
- backend 结构化 256 项 GL message ring，并按 context 跟踪主要 wrapper 资源；正常主 Demo 关闭后
  tracked live count 回到零。
- 主 Demo 在原 `UiSystem/UiOverlayPass` 中加入五页诊断面板，F2 切换；支持 live/freeze/clear/filter/export。
- schema v1 JSON 两次导出字节相同，临时文件关闭后原子替换；integration 验证 graph、pass、resource、
  message、resize、failure/recovery 和 cleanup。
- active GPU query 在命令异常时显式中止；真实 pass callback 与 query 后 command failure 均生成当前
  frame sequence 的 FAILED 帧，debug group/query 状态恢复后下一帧继续渲染。
- 资源跟踪采用 context-scoped 引用计数 lease；runtime 公共 capture 不再暴露 backend DTO，面板资源和
  消息页与 Overview 共用同一 `FrameDiagnostics` 发布边界。
- exporter 在写入前校验 capture，写出构建和 OpenGL 元数据，默认省略 native id；Demo 导出只允许
  `build/diagnostics/` 下的安全路径。

## 当前限制

资源字节数是框架 storage 估值；裸 GL 对象不在完整性承诺内。面板不预览 texture 像素，不编辑 graph，
不启动 Nsight/RenderDoc，不提供网络 telemetry。

发布人已接受本地完整验证、人工诊断面板检查和外部工具合同，批准版本进入 `0.15.0`。性能报告没有
声称完成独立 v0.14 checkout 的精确 1% 对照；远端 Windows/Linux CI 仍由正式发布流水线复验，
不在本地报告中伪造结果。
