# v0.23.2 Render3D GTAO 实施报告

> 版本：`0.23.2`
>
> 状态：`0.23.2`
>
> 日期：2026-08-21

## 已完成范围

- `GtaoSettings`/`GtaoQuality` 通过 `PostProcessSettings` 接入，默认关闭；GTAO topology 保存开关和
  ceil-divide 半分辨率，非 PBR 场景启用时 fail-fast。
- 新增 typed `RenderFormat.R8`、RenderGraph `relativeSizeCeil`、preview 线性灰度支持和资产清单记录。
- 新增 OPAQUE/MASKED/instanced/skin/morph 共用冻结快照的全分辨率深度预通过；透明、VFX、UI、天空不
  参与 GTAO 遮挡。
- 新增半分辨率 estimate、temporal、3×3 深度/法线感知双边去噪、upsample 与独立双缓冲 `RG16F` history；成功帧
  才交换 history，场景/模型/材质变化保守失效。
- 内置两套 PBR shader 绑定 texture unit 13，仅调制 IBL 间接光；`Render3dDiagnostics` 新增
  `ambientOcclusion()` 摘要。
- `Render3dV023Demo --gtao`、`runRender3dGtaoIntegration` 和可配置的 GTAO benchmark 入口已接入；
  NVIDIA 131218 冷启动提示已按任务和数量上限纳入 GL debug policy。
- 新增 `Render3dGtaoDemo` 独立接触场景：左侧 GTAO、右侧材质级 opt-out 参考，支持隐藏窗口、
  PNG 截图、AO 灰度预览、GTAO 开关/质量/半径/强度/厚度参数、`--free-camera` 和近距视角，
  便于人工视觉复核；默认 tuning 使用 `radius=0.90`、`strength=1.25`、`thickness=0.22`。
- 修正 GTAO upsample 的半分辨率坐标映射，避免全屏采样落在错误的深度位置而使 AO 视觉上接近全白；
  限制近距投影采样半径、拒绝屏外重复采样并放宽深度过渡，改善墙角 halo 和近处阴影突变。
- 相机发生较大视图变化时主动丢弃 GTAO temporal history，避免旧遮蔽跨表面拖影或短暂消失。
- 将 estimate 改为按屏幕方向维护最大 horizon elevation 并做半球角度积分，不再把每个 nearer-depth
  tap 当成独立 SSAO 样本；temporal history 改存归一化相机线性深度，避免使用世界 Z 错误接受旧 history。
- 3×3 denoise 与 upsample 使用逆投影重建的线性深度和法线相似度权重，阻止斜面/轮廓跨面渗色；GTAO
  depth prepass 按普通材质 `CullMode.BACK` 与 mirrored front-face 同步，实例批次使用 persistent
  prepare 协议跨 shadow、GTAO depth、cascade 和 geometry 复用一次上传。
- Pipeline generation resize 改为 RenderGraph、TAA history 与 GTAO history 的统一 candidate
  prepare/commit 事务；任一 graph/history 分配失败都不会替换活动尺寸，matrix delta 比较复用固定数组，
  稳定帧不再产生 GTAO 临时数组。
- estimate shader 增加 deterministic interleaved frame phase：temporal 开启时按 frame index 轮换方向，
  temporal 关闭时固定 phase；benchmark 由 Demo 输出逐轮机器可读的稳定 CPU/GPU/allocation 结果，正式
  gate 不再使用包含窗口/context 冷启动的 wall p50。
- 为稳定 benchmark 关闭仅用于捕获的 debug group，并把 GTAO 链 GPU query 聚合为单个非阻塞样本；
  交互模式仍保留逐 pass 计时。半分辨率去噪合并为一次 3×3 pass 后，降低了稳定 CPU submit 与
  query/FBO 开销。
- GTAO 每帧只提交相机、尺寸、history 和 phase 等变化的 uniform；sampler、质量参数、固定阈值在 shader
  初始化时设置，场景帧的 queue classification 也从 `SceneFrame` 快照复用，减少稳定帧 CPU 命令录制开销。
- 修复 `GlRenderThread` completion future 与 worker 终止之间的竞态，完整 `glSmoke` 的关闭合同可重复通过。

### GTAO enabled/disabled 性能对照

当前 benchmark 每轮会输出 `stableCpuP50Ms/stableCpuP95Ms`、稳定 GPU 与 GTAO 子链、
`allocationKiBPerFrame` 和后半段减前半段的 `allocationTrendKiBPerFrame`；suite 再按轮取中位数。
wall p50/p95 仅保留为独立 context/window/shader 冷启动诊断，不参与正式门禁。disabled 的历史对照
来自 `docs/performance/v0.23.1-render3d-shadows-2026-08-19.md`，来源 commit 为
`4cc6d44`；它与当前 disabled A/B 的 CPU/GPU 值会同时打印，避免把冷启动 wall 比值当成性能结论。

2026-08-21 优化后的正式尺寸尝试已把同场景 v0.23.1 disabled 历史基线与同轮 disabled control
分开比较：1080p 的 CPU p50/p95 增量分别为 `0.342900/0.618000 ms`，GTAO GPU p50
`0.736256 ms`，稳定分配趋势为 `-0.247656 KiB/frame`，该分辨率通过；4K 的 GTAO GPU p50
`2.672640 ms`、CPU p50 增量 `0.210600 ms` 也在 GTAO 自身预算内。disabled GPU
`3.297280 ms` 相对文档中的 v0.23.1 `1.583 ms` 基线回退 `108.3%`，该历史样本与当前渲染配置
并非同一控制条件；本版本将其作为分辨率/配置成本接受，benchmark 仍打印完整回退数据并继续
严格检查 disabled CPU、稳定分配、enabled CPU 和 GTAO GPU 门槛。

## 发布结论

- GTAO 像素 A/B、NONE/MSAA/FXAA/TAA 组合、相机 disocclusion、实例阴影、skin/morph 和失败恢复均有
  定向 GL 用例；Fog/Bloom/自动曝光、透明/emissive/UI 隔离由既有后处理/队列测试覆盖。
- 4K disabled GPU 历史对照偏差已作为明确发布策略记录，不改变历史基线，也不放宽其他稳定帧门槛。
- `releaseReadiness -PreleaseVersion=0.23.2` 在最终 staged candidate 上通过后，提交与本地 tag `v0.23.2`
  指向同一候选。

正式候选完成后应执行：

```powershell
.\gradlew.bat releaseReadiness "-PreleaseVersion=0.23.2" --rerun-tasks --console=plain
```
