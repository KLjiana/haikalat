# v0.17.2 发布候选验收报告

状态：`0.17.2`，本地发布候选验收通过

日期：2026-07-22

环境：Windows 11、Java 21、LWJGL 3.3.3、OpenGL 4.6.0 NVIDIA 576.88、RTX 3050 Laptop GPU。

## 已完成实现

- 发布验证从根 build 文件拆到 `gradle/release-verification.gradle`，新增严格资产清单、Git candidate、
  版本元数据、GL policy、结构化性能结果和 readiness JSON/Markdown。
- readiness 摘要会识别报告直接引用的 contract/benchmark 叶任务，并从结构化性能证据读取实际
  JavaExec JDK，避免把成功任务或 Gradle launcher JDK 错写进最终发布结论。
- 所有真实 GL wrapper 删除通过 context-scoped epoch 使活动 device 的状态缓存于下一提交边界失效；
  128 次 VAO rebuild、100 次 framebuffer resize 式 rebuild、精确 ID reuse、多 context 与无 context
  路径已有真实 GL 回归。
- JUnit GL smoke 与 JavaExec integration 共用 `config/gl-debug-policy.tsv`；未知 HIGH/MEDIUM、
  `GL_INVALID_*`、过期或超过次数的规则默认失败。
- `glDebugPolicyGuard` 显式等待所有受审计日志生产者并声明 XML/日志输入；结构化性能结果记录 benchmark
  自报的实际尺寸、warmup、samples 和 rounds。环境或场景配置不一致时会记录不可比较原因并阻断发布。
- performance 与 readiness 从同一份 staged candidate 证据读取 HEAD、branch、dirty 和 diff hash，最终摘要
  会再次验证两者完全一致。
- diagnostics OFF 跳过不会发布的摘要；visibility statistics 只发布一次；matrix uniform 复用 direct
  scratch，并以 program-local 两路 identity 热缓存避免逐对象重复哈希 uniform 名称；command recorder
  折叠跨连续 draw 的相同 pipeline/program state，但在 `custom()` 后强制重发；材质 override 快照在
  未变化时复用。五轮性能与 JFR 结果见
  `docs/performance/v0.17.2-hardening-2026-07-21.md`。
- 正式验收修复 glyph atlas page 初始化 fence 与后续 region upload 的合法串行依赖，连续五轮 preview
  benchmark 不再偶发报出“awaiting initialization”。
