# v0.26 UI Compositor 独立复验

日期：2026-11-05。源码 HEAD：`28b7b474f46f01618174e11705a8fc091aa7bb32`；构建版本仍为 `0.25.0`，这与本阶段不改版本的合同一致。

结论：核心合成功能的定向自动检查通过，但暂不签收“全部完成”。发现一项异步 GPU 资源关闭路径遗漏，以及一项标准验收入口重复运行失败。未修改实现；既有未提交文档保持原样。

## 发现

### P1：异步关闭没有覆盖新增 Compositor GPU owner

`UiSystem.closeRenderResources()`（UiSystem.java:416）按公开协议在 render 线程释放 GPU 资源，但仅关闭 renderer，没有关闭 attachment 中的 compositor。

后续 `UiSystem.close()`（同文件 :426、:449）要求 update owner，并调用 attachments.close；它经 UiAttachmentController.close（:145）进入 UiCompositor.close（:367），最终 UiCompositeGpu.close（:65）删除 shader、sampler、VAO。对于已绘制过离屏层、GL context 只在 render 线程的正常异步宿主，这些删除会落到没有相应 context 的 update 线程，存在关闭异常与泄漏问题。

这是源码调用链确认的遗漏，本轮未执行该双线程故障复现。现有 UiSystemTest.asyncLifecycleCanReleaseUninitializedRendererBeforeOwnerClose 只关闭未初始化 renderer，没有创建实际 compositor GPU 资源，因此它通过不能覆盖本问题。

修复建议：把 compositor GPU 释放纳入 render-thread 关闭阶段，update-thread 关闭仅处理 CPU/attachment 状态；保持重复关闭安全，不关闭宿主拥有的 graph。补真实双线程/current-context 测试：渲染至少一帧带模糊层，render 线程 closeRenderResources，然后无 GL context 的 update owner close，核对资源回到基线。

### P2：标准 UiConsumers 命令因可缓存 guard 被复用而失败

实际执行 `./verify.ps1 -Mode UiConsumers -TimeoutSeconds 300`，退出码 1，汇总 FAIL。34 项 JVM、30 项 GL、四个 Demo、VLS 和 Modern UI 均为 FRESH/PASS，零失败零 skip；候选指纹前后相同。

失败原因：publicApiGuard 和 architectureGuard 为 UP-TO-DATE，taskOutcome 将其标记为 REUSED_TASK_OUTPUT。gradle/focused-verification.gradle:363 只约束 guard 的执行顺序，没有强制 fresh；:422 附近汇总又要求所有 entry.status 都等于 PASS。因此正常重复执行会被拒绝。

修复建议：若合同要求所有 guard 本轮执行，应对选中的 UI guard 禁用 up-to-date/cache；或在明确更新证据合同后接受输入验证成立的 guard 复用。不要把未执行的任务直接标成 FRESH。验收应连续两次运行文档原命令，均得到符合合同的结果，无需用户手动清理 Gradle 状态。
