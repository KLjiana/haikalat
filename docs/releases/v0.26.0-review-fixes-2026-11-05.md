# v0.26 独立复核缺口修复与补验

日期：2026-11-05。针对异步 Compositor GPU 关闭遗漏与标准 UiConsumers 命令重复运行失败两项问题。核心渲染能力保留原有结论；原先“全部完成”撤回，整版签收待复核。用户提供的独立复验文档和其他并行改动保持原样。

## 修复范围

| 问题 | 修复与证明 |
| --- | --- |
| render 关闭只释放 renderer，update close 才删除 Compositor | `UiSystem.closeRenderResources` 与同步 `close` 共用关闭路径：先验证 render owner，再释放 snapshot lease、关闭全部 attachments/Compositor，最后关闭 renderer/ring。update owner 漏掉 render 关闭时，在任何生命周期状态改变前拒绝，可按正确顺序恢复。已关闭的 GPU owner 在 update close 中只走幂等返回，不删除 native 资源；graph 始终属于调用方 |
| API/架构 guard 被 Gradle 复用，汇总拒绝 REUSED_TASK_OUTPUT | UI capture 被选中时，五项 UI guard 禁用 up-to-date/build-cache；其他非 UI 入口保留原策略。汇总仍要求本次 FRESH/PASS，不把 UP-TO-DATE 改写成 fresh，也不以旧报告补证 |

新增真实 GL 检查为 `UiCompositorLifecycleGlTest.asynchronousCompositorClosesGpuOnRenderThreadBeforeContextFreeUpdateOwnerClose`。启动阶段在 update owner/current context 下注册离屏图层，然后将同一 context 与 capabilities 交给独立 render 线程：

1. update owner 发布实际包含文字与模糊层的 snapshot，render 线程至少绘制两帧；解析像素正确，首帧两次滤波，至少三套 UI/blur/composite program 确实存活。
2. update owner 没有 GL context；过早 `close()` 明确拒绝，`isClosed` 仍为 false，GPU 资源清单不变。
3. render owner 连续调用两次 `closeRenderResources()`；所有 UI GPU 对象消失，扣除仍属 graph 的 timer query 后，资源清单精确回到 graph/宿主目标基线。graph 与目标仍可存活。
4. update owner 的 `glfwGetCurrentContext()==0`，且无 LWJGL capabilities，此时两次 `close()` 均成功。
5. 调用方在各 owner/current context 下关闭 graph 与宿主目标后，总资源清单和字节数回到最初基线。

该测试是实际双线程/current-context 证明，不是关闭尚未初始化 renderer 的 JVM 替代测试。初始化需 current context，`OwnedPresentationTarget` wrapper 仍遵守其创建线程所有权；跨线程仅传不可变 `PresentationTarget` 描述。测试搭建期间的编译与所有权错误保留为失败记录，不冒充产品缺口的复现。

## 标准命令重复验收

原样串行执行以下命令两次，期间不修改任何输入：

```powershell
.\verify.ps1 -Mode UiConsumers -TimeoutSeconds 300
.\verify.ps1 -Mode UiConsumers -TimeoutSeconds 300
```

每轮独立总时限 300 秒、零自动重试。没有 `--rerun-tasks`、clean 或人工清理 Gradle 状态。必须同时满足：两次 bounded/summary 均 PASS；34 项 JVM、31 项 GL 全通过且零 skip；四例各 96 帧、VLS 100 帧、Modern UI 90 帧与 GL 日志门禁通过；五项 guard 均 FRESH/PASS；两轮 candidate 身份完全一致。
