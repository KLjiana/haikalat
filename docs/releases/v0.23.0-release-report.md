# v0.23.0 Render3D 框架加固与能力扩展正式版验收报告

> 版本：`0.23.0`
> 状态：`0.23.0`
> 日期：2026-08-18
> 发布日期：2026-08-18
> 基线：v0.22.2
> 主题：Render3D frame/generation 合同、透明材质、Fog + MSAA 与级联阴影

## 执行摘要

v0.23.0 完成 Render3D M0～M8。pipeline 以六域 revision、不可变 frame context 和 candidate-first
generation 管理帧状态与资源；普通 draw 明确分为 OPAQUE/MASKED/ALPHA/ADDITIVE；glTF BLEND 与
MASK shadow、Fog + 4x MSAA depth resolve、2～4 级 CSM 和有界 diagnostics 均进入正式路径。

专项窗口 `runRender3dV023Demo` 在同一场景展示四类 queue、MASK shadow、Fog + 4x MSAA、4 级
CSM、resize 与 diagnostics。方向光 atlas 提升到 4096x4096，四级布局的单 tile 为 2048x2048；
PBR 3x3 PCF tap 被限制在当前 tile 的半 texel 内边界。

## 性能与架构决定

专项数据见 [`docs/performance/v0.23-render3d-visibility-index-decision-2026-08-18.md`](../performance/v0.23-render3d-visibility-index-decision-2026-08-18.md)。
100/1,000/10,000 对象代表场景没有让 O(N) culling + queue scan 持续超过 2 ms，10,000 全静态
场景的 queue cache 把 queue build 降到 0.08 ms 以下。因此 CPU spatial index 的准入条件不成立，
本版本不引入 BVH/AABB tree；既有静态 submission 性能门禁继续作为发布基线。

## 专项验证

- 全量 JVM、shader generation、Demo 编译和测试通过。
- 真实 GL 覆盖四类 queue、透明稳定排序、MASK 最终像素与 shadow cutoff、BLEND 默认不写 shadow、
  Fog + resolved depth、2/3/4 级 CSM、atlas tile PCF、resize、embedded 和失败回滚。
- `runRender3dV023Integration` 固定 12 帧并中途从 640x360 resize 到 800x450，断言四类 queue、
  MASK caster、4x depth resolve、4 级 cascade、固定 atlas、cache 与 diagnostics。
- `runGltfSceneScalabilityIntegration` 验证 schema-v1 的 `maskedDraws` 计数恒等式。
- GL debug policy 只接受 vendor/entry/id/source/type/message/expiry/maximum 全部精确匹配的规则；
  未授权 HIGH/MEDIUM 与任何 `GL_INVALID_*` 都会使发布门禁失败。

## 兼容性与明确限制

`Scene.add/remove`、既有 `BlendMode`、默认 opaque material、单级方向光阴影、无 MSAA fast path 和
borrowed embedded target 所有权保持兼容。调用方不需要创建内部 `PipelineGeneration` 或 frame state。

ALPHA 排序仍是对象级，不能保证 mesh 内部自相交；ALPHA/ADDITIVE 默认不投射阴影。本版本不提供
透明阴影、OIT、transmission/refraction、per-cascade caster spatial index、occlusion/GPU culling、
MDI 或 clustered lighting。4096 shadow atlas 提高专项 Demo 的采样质量，也会增加显存和 fill 成本；
应用应按目标硬件选择配置。
