## 3. 依赖与所有权快照

基线依赖：`render3d` 根包包含 111 个实现类（含后来迁出的 lighting/shadow/surface/
ao/volumetric 类），`postprocess` 15 个类；`postprocess` 导入 `render3d.ScreenQuad`
与 `render3d.TaaResolveInputs`，形成包级双向依赖。

候选依赖（按包，去除自引用）：

```text
render3d ──► pipeline / scene / geometry / surface / lighting / shadow / ao
              / volumetric / environment / pbr / gltf / preview / vfx
render3d ──► postprocess（合同：PostProcessPipeline、SurfaceInputs、
              LateSurfaceProducer、TemporalFramePose、TaaInvalidationReason、ScreenQuad）
pipeline ──► scene / geometry / surface / lighting / shadow / ao / volumetric
              / environment / pbr / preview / postprocess
geometry ──► scene
surface  ──► scene / geometry
scene    ──► geometry
shadow   ──► scene / geometry
lighting ──► shadow（单向；灯表值 `FrameLightTable` 在根包，shadow 只读快照）
volumetric ──► scene / geometry / surface / lighting / shadow
postprocess ──► bloom / exposure / tonemapping / color / temporal / fxaa / fog
postprocess.* ──✗──► render3d
render3d.<module> ──✗──► pipeline
```

`scene` ↔ `geometry` 是唯一保留的双向包引用：帧快照持有绘制值，绘制录制读取快照；
不共享可变 GPU owner。`lighting` ↔ `shadow` 循环已在候选末期消除（`FrameLightTable`
上移根包）。

`render3d` 根包不再持有实现；29 个文件全部是入口、配置与跨包值对象
（`ArchitectureBoundaryTest.render3dRootKeepsOnlyDocumentedEntriesAndValues`）。

所有权表：

| owner | 主要资源 | 迁移点 |
|---|---|---|
| `RenderGraph` | 图附件、外部导入、resize 候选 | 未改 |
| `render3d` 根包 | `FrameLightTable` 帧灯表快照值（无 GPU 资源） | 从 `lighting` 上移到根包以消除 lighting↔shadow 循环 |
| `PipelineGeneration` | 借用／转交集合、fence 退役 | 迁入 `render3d.pipeline` |
| 后处理效果 owner | 程序、LUT、TAA 历史、1×1 曝光历史 | 拆入 `postprocess.*` 子包 |
| `shadow` | 图集分配器、采样块、阴影程序、`ShadowCasterRecorder` | 迁入 `render3d.shadow` |
| `lighting` | cluster SSBO、计数器、`FrameLightBinder` | 迁入 `render3d.lighting` |
| `geometry` | 相机 UBO、变形默认值、`SceneRenderer` | 迁入 `render3d.geometry` |
| `surface` | 表面／resolve 程序与租约 | 迁入 `render3d.surface` |
| `ao` / `volumetric` | GTAO 历史、3D 纹理与体积历史 | 迁入 `render3d.ao` / `volumetric` |
| `environment` / `pbr` | 天空程序、IBL 环境 | `environment` 新建，`pbr` 原样 |

## 4. 继承与失效

- 0.27.2 的共享表面合同、GTAO 合同与体积雾合同继续有效；具体实现只改变包路径与
  可见性，资源生命周期与帧边界语义未改。
- 0.27.2 的 18 张浮点图与 64 次冷启动结果只在“输入未变”的用例上复用：包移动
  不改变 shader 资源路径、采样与算法；但任何导入了被移动 advanced 类型的 GL 用例
  都重新执行，避免仅凭算法文本未变复用。
- 本版本没有新的像素金图；既有金图未更新。出现视觉差异必须按独立问题处理。

## 5. 基线环境限制与修复状态

以下问题在基线上已存在；候选对其中两项做了独立修复，基线事实保持 FAIL，不因修复
改写：

1. `assetManifestGuard` 在基线 worktree 失败：`docs/licenses/assets.tsv` 对 0.27.2
   修改过的 10 个 shader 保留旧哈希。候选在独立元数据同步中按 HEAD 字节更新 hash 并
   追加 `hash sync 0.27.3` 注记（shader 字节未改），修复后 guard 通过。
2. 以 `glSmoke --tests` 单独运行 `VolumetricCompositeGlTest` 的 2 个诊断用例时，
   基线同样抛 `enable haikalat.internal.volume.diagnostics before the captured frame`；
   这些用例需要专用任务的 JVM 启动参数。在 `runRender3dVolumetricFogIntegration`
   中该 suite 的 15 个用例全部通过，属于任务选择差异，不是行为回归。
3. `OutdoorEnvironmentGlTest.uiRebindsAfterQualityAndEnvironmentChangesAndKeepsFailedCandidate`
   在基线 `focusedRender3dGlTest` 与 `glSmoke` 中失败（`UI rebind requires a retired
   previous RenderGraph`，环境替换后的 rebind）；候选在独立修复中改为允许退役中的
   旧图并延迟释放 compositor，修复后 9/9 通过，详见
   [review §3.1](v0.27.3-review.md)。

历史遗留（0.27.2 已记录、本版本不处理）：旧墙面条纹、性能欠账、宿主协议视觉统一。
