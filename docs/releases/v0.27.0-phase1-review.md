## 本轮实现

体积雾继续由具体内部 owner `VolumetricPassBuilder` 持有私有资源、参数上传、Pass 与历史。新增只借用的光照能力和场景表面值合同，装配方传入生产者名称；候选发布前编译图并验证尺寸、采样与 HDR/depth 约定。

雾启停/quality/emission shape 改变使用候选事务：不相关 Camera、clustered lighting、shadow、PBR/sky、后处理私有 GPU owner 可复用。Graph 附件按完整 descriptor、逻辑附件及共享源对象身份复用；失败候选不关闭旧 owner，成功后明确转交所有权。TAA 存储复用与像素历史失效分别处理；标量调参不改变 Graph revision。

新增纯 CPU 活动/候选/待退役雾预算，旧代按 fence 有界退役；同步入口检查 owner thread、GL capabilities 及已捕获的 GLFW 原生 Context。关闭为终态。实际异步请求队列未引入：本阶段没有需要异步执行的 CPU 准备工作，现有同步成功语义保持。

循环测试另外发现并修复零局部光源合同问题：光照生产者不分配有效 header 内容，而旧雾 Shader 仍读取 header。故意残留 header 的生产测试与 200 次启停覆盖此修复。跨代长期存活的光照/Camera 绑定缓存也改用 ShaderProgram 对象身份，避免 GL program ID 回收后命中旧能力结论。

- 结构与功能：M0–M4/A01–A12、A14 在体积雾试点范围通过，真实生产消费者已迁移。RenderPipeline 仍承担较多装配、owner 复用选择及事务协调职责，不能称为全面模块化完成。
- 性能：当前候选和冻结开工基线的同条件比较处于事先确定的噪声容差内；原 2.0 ms GPU / 0.35 ms CPU 绝对预算仍 FAIL，作为明确欠账保留。没有做其他分辨率/硬件/完整性能矩阵，不宣称提升 FPS。
- 宿主：M5/A13 的既有证据支持实际 Minecraft 回调、目标借用与生命周期接入；与地形、深度遮挡、光照和阴影的统一视觉整合未验收，人工手感、多人与斜投影也未验收。本轮没有重新启动客户端。
- 阶段整体：第一阶段完成。完整版本发布、构建号升级和 release readiness 另走发布流程；本次 releaseReady=false。

下一模块选择建议为 GTAO，理由与边界见[试点合同](../architecture/v0.27.0-volumetric-module-contract.md#a14-变更局部性与第二模块决策)。先另立第二试点计划验证共性，本阶段不自动迁移 GTAO、不公开通用 FeatureModule，也不扩展作者风格配置或全部 UI 特效。
