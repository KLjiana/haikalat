## 尚未关闭的 P2：运行期间候选变化仍可 PASS

位置：[verify.ps1](../../verify.ps1) 第 177 行及 finally 中的结果写入逻辑。

`Get-WorkingTreeFingerprint` 只在启动前调用一次。结束时不重新计算，也不比较前后内容。脚本因此能将运行期间变化的候选，与开始时的内容摘要关联后报告 PASS。`FRESH` 当前仅反映归档 XML 的时间，不能证明候选稳定；已有内容指纹测试只证明“两次调用能区分文件内容”，没有覆盖“同一次验收运行期间内容变化”。

本轮用完整、未修改的 `verify.ps1` 副本在 `build/v0275-recheck-20261111/candidate-change-fixture/` 做隔离探针：

1. 临时 Git 仓库中放置候选文件；包装脚本计算开始指纹。
2. 替身 `gradlew.bat` 在子进程运行期间把候选文件从 BEFORE 改为 AFTER，生成一份新鲜的成功 JUnit XML，再以 0 退出。
3. 包装脚本报告 **PASS／FRESH**。随后使用同一指纹函数重算，前后摘要不同：
   - 报告开始摘要：`ea5d47d1f83bb1536c6bbdde010d47a72d16820d6a61662a5576ddce5d0da9d7`
   - 结束后摘要：`0b2c077d06e2420d528484fec8169cc2e87ee51a9d9ff44b3c2e19df7aa9facb`

探针是包装脚本控制流验证，不是真实 Gradle／GPU 验收；没有修改项目源码。摘要保存在 `build/v0275-recheck-20261111/candidate-change-summary.json`。首次探针的 Windows PowerShell 脚本执行被环境策略拒绝；改用当前 pwsh 后定向运行一次，得到上述结果。

最小修正：在运行前后采集内容摘要并随报告保留；不同则标记 `SOURCE_CHANGED` 或等效失败，不能为 PASS。若身份采集失败，也不能在需要候选绑定的 GL 验收中静默通过。增加同一次运行期间改变输入的负例即可，无需新增一批生产类对应测试或重跑性能矩阵。
