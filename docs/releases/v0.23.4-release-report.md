# v0.23.4 Render3D 动态阴影发布报告

> 版本：`0.23.4`
>
> 状态：`0.23.4`
>
> 日期：2026-08-22

## 发布范围

v0.23.4 将 Render3D 阴影提交从全场/全局失效收紧为固定 20 个 shadow view 的保守逐 view
caster slice 与 cache key：

- directional cascade、point cube face、spot tile 分别裁剪、清理和失效；point cache 细化到
  六个 face，caster 移动使用 old/new membership 并集；
- 空 view 的局部 depth clear 与失败帧 `FRAME_FAILURE` 恢复合同；clean view 不因相邻 dirty view
  重画；同宽高比 resize 保留 fixed atlas 与 planner arena；
- 实例 batch 提供 aggregate bounds 与精确矩阵 revision，directional/point/spot shadow
  复用同一帧实例准备；
- 新增 `RenderPipeline.lastShadowCullingStatistics()` 与 bounded `ShadowCullingStatistics`，以及
  动态 integration/benchmark 入口。
- dynamic integration 使用 revisioned glTF caster 穿过 point face/spot range，并在已提交 tile
  上注入一次 partial shadow failure；恢复帧以 `FRAME_FAILURE` 重新构建 dirty view。

## 发布门禁

- 必须通过默认 JVM `check`、GL smoke、动态 integration、shadow benchmark、public API、architecture、
  asset/license 和 GL debug policy 门禁；
- 业务路径不得出现 HIGH、`GL_INVALID_*`、资源泄漏或线程悬挂；NVIDIA `131218` MEDIUM 仅允许按
  `config/gl-debug-policy.tsv` 登记的冷启动 specialization；
- 最终版本为 `0.23.4`，完整候选暂存后执行：

```powershell
.\gradlew.bat releaseReadiness "-PreleaseVersion=0.23.4" --rerun-tasks --console=plain
```

- 最终 release commit 与本地 tag `v0.23.4` 必须指向同一通过门禁的 staged candidate。

## 已知限制

本版本仍停留在 batch-level instance culling，不提供 BVH、GPU-driven/indirect shadow submission、
逐实例 compact 或新的 shadow quality 算法；无可靠 bounds 的 caster 采用保守回退，密集 unknown-bounds
场景可能接近全量 view 提交。

## 发布结论

所有发布门禁均已通过；正式提交为 `release: v0.23.4`，本地 tag 为 `v0.23.4`。
