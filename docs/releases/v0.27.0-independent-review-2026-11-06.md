## 合同核对

| 合同 | 本轮判断 |
|---|---|
| 关闭无专属绘制、开启按需分配 | 生产 Generation／Composite GL 和循环测试通过；停用资源可能先进入 fence 退役队列，不能要求 GPU 尚在使用时立即删除 |
| 标量不重建、规格局部替换 | Modularity GL 验证真实像素、图 revision、对象身份与 native 分配；光照、Camera、阴影附件、TAA 存储按兼容条件复用 |
| 候选失败与发布后清理失败 | CPU／分配／Shader／Graph 注入和 retirement failure 通过；发布前保留旧状态，发布后保持新状态，两者没有混为像素回滚 |
| 输入与所有权 | 光照能力和表面输入由装配连接；图附件按 descriptor 与共享源身份检查；未提交候选禁止执行／resize，失败不释放 donor |
| 正确线程与 Context | 已初始化资源的第二线程、detach 与不同 Context 测试通过；保留同步入口，不把不存在的异步队列测试算为通过 |
| 历史与资源复用 | TAA 存储与内容有效性分别处理；失败不提交成功历史；拓扑、设置、resize 有诊断原因 |
| 持续启停与关闭 | 200 次启停、3600 帧等现有长测本轮重新通过；这是对象与分配估算证据，不是驱动显存测量 |

职责内聚确有改善：体积雾保留具体内部 owner，输入合同由真实生产路径消费，没有另建万能模块管理器。不过 `RenderPipeline` 仍直接承载较多各类 owner 的复用选择与事务装配，本次增加了相应代码。因此只能签收“体积雾边界和局部替换试点”，不能宣称中心对象过重的问题已经全面解决。下一试点应检验该事务逻辑是否能够保持局部，而不是机械复制更多分支。

必须进一步限定这项宿主证据：验收消费者创建独立的空几何 `Scene` 和方向光，并非接入 Minecraft 地形、光源和阴影数据。它证明真实客户端回调、目标借用、雾启停、重载、世界切换与释放链可以运行；截图不能证明与 Minecraft 世界深度／遮挡／光照的统一视觉表现。实际标准旁观者投影范围可以接受，人工游玩、多人、受伤／摇晃斜投影及世界视觉整合均未签收。
